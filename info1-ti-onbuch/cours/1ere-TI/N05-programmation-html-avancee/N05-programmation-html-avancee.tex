\coursec{Site web, HTML et structure d'une page}

Au lycée de Nkongsamba, le proviseur a une idée ambitieuse : publier sur Internet les résultats du probatoire et proposer un formulaire d'inscription en ligne pour les nouveaux élèves. Fini les longues files d'attente devant le tableau d'affichage ! Il confie la mission à un élève de Première TI. Celui-ci, plein d'enthousiasme, ouvre Microsoft Word, tape le texte, insère un tableau... et envoie le fichier. Résultat : impossible à afficher correctement dans un navigateur, aucun lien ne fonctionne, le formulaire n'existe pas. Il découvre alors une vérité fondamentale : le Web possède son propre langage, le \cle{HTML}, et c'est lui seul que les navigateurs comprennent. Comment structurer une page web ? Comment y insérer des images, des tableaux de résultats et un formulaire d'inscription ? C'est toute la problématique de cette leçon : \textbf{créer un site web statique en HTML}. Commençons par le commencement : comprendre ce qu'est un site web et comment une page HTML est construite.

\courssub{Site web, page web, navigateur et serveur}

\courssub{Les acteurs du Web : définitions}

Avant d'écrire la moindre ligne de code, il faut comprendre le décor dans lequel notre page va vivre. Quand tu tapes une adresse dans ton téléphone au cybercafé, que se passe-t-il exactement ?

\begin{definition}[Site web et page web]
Une \cle{page web} est un document informatique, écrit dans un langage de description (le HTML), consultable à l'aide d'un navigateur. Un \cle{site web} est un ensemble cohérent de pages web reliées entre elles par des liens hypertextes, hébergées sur un serveur et accessibles via une même adresse (nom de domaine).
\end{definition}

\begin{definition}[Navigateur et serveur web]
Le \cle{navigateur} (ou \emph{browser}) est le logiciel client qui demande, reçoit et \emph{interprète} les pages web pour les afficher à l'écran : Google Chrome, Mozilla Firefox, Microsoft Edge, Opera... Le \cle{serveur web} est un ordinateur (et le logiciel qui y tourne, comme Apache ou Nginx) qui stocke les fichiers du site et les envoie aux navigateurs qui les réclament, selon le protocole HTTP.
\end{definition}

Le dialogue est donc toujours le même : le navigateur \emph{demande} une page au serveur, le serveur \emph{envoie} le fichier HTML, le navigateur \emph{interprète} le code et affiche le résultat. Ce mécanisme s'appelle le modèle \cle{client-serveur}.

\begin{definition}[Site statique et site dynamique]
Un site \cle{statique} est un site dont le contenu des pages est fixe : le fichier HTML envoyé par le serveur est identique pour tous les visiteurs et ne change que si le concepteur modifie le code à la main. Un site \cle{dynamique} génère ses pages à la volée, souvent à partir d'une base de données (exemples : Facebook, un site d'actualités, les résultats du Probatoire en ligne). En Première TI, nous créons des sites \textbf{statiques} : le dynamique côté serveur viendra en Terminale.
\end{definition}

\begin{exemplebox}[Statique ou dynamique ?]
\begin{itemize}
\item La page de présentation du lycée de Nkongsamba (historique, photos, contact) : site \textbf{statique}, car le contenu change rarement.
\item La consultation des notes en ligne, où chaque élève voit \emph{ses propres} résultats : site \textbf{dynamique}, car la page affichée dépend du visiteur.
\end{itemize}
\end{exemplebox}

\courssub{Le langage HTML : un langage à balises interprété}

HTML signifie \emph{HyperText Markup Language}, c'est-à-dire « langage de balisage hypertexte ». Ce n'est \textbf{pas} un langage de programmation comme le C : il ne contient ni variables, ni boucles, ni calculs. C'est un langage de \emph{description} : il indique au navigateur \emph{la structure} du document (« ceci est un titre, ceci est un paragraphe, ceci est une image »).

\begin{propriete}[HTML est interprété, pas compilé]
Contrairement au langage C qui est \emph{compilé} (traduit une fois pour toutes en langage machine par un compilateur), le code HTML est \cle{interprété} : le navigateur lit le fichier texte ligne par ligne et affiche le résultat au fur et à mesure. Conséquences pratiques :
\begin{itemize}
\item aucun outil spécial n'est nécessaire : un simple éditeur de texte (Bloc-notes, Notepad++) suffit ;
\item une erreur dans le code ne « plante » pas la page : le navigateur ignore la balise inconnue et continue l'affichage ;
\item le code source de n'importe quelle page est visible (clic droit $\to$ « Afficher le code source »).
\end{itemize}
\end{propriete}

\courssub{Balises et attributs : les briques du HTML}

\courssub{La balise : ouvrante, fermante, orpheline}

Pour marquer un contenu, on l'entoure de \cle{balises}. Une balise est un mot-clé écrit entre les signes \texttt{<} et \texttt{>}.

\begin{definition}[Balise]
Une \cle{balise} est un marqueur encadré par les chevrons \texttt{<} et \texttt{>} qui indique au navigateur la nature d'un contenu. La plupart des balises fonctionnent par paire :
\begin{itemize}
\item la \textbf{balise ouvrante} : \texttt{<p>} marque le début ;
\item la \textbf{balise fermante} : \texttt{</p>} (avec un slash \texttt{/}) marque la fin.
\end{itemize}
Certaines balises, dites \cle{orphelines} (ou auto-fermantes), n'ont pas de contenu à encadrer et s'écrivent seules : \texttt{<br>} (retour à la ligne), \texttt{<hr>} (ligne horizontale), \texttt{<img>} (image), \texttt{<meta>} (métadonnée).
\end{definition}

\begin{exemplebox}[Balise paire et balises orphelines]
\begin{lstlisting}[language=HTML]
<p>Le lycée de Nkongsamba est situé au pied du Mont Manengouba.</p>
<hr>
<p>Deuxième ligne après un retour :<br>voici la suite.</p>
\end{lstlisting}
Ici, \texttt{<p>} encadre un paragraphe, \texttt{<hr>} trace une ligne horizontale et \texttt{<br>} force un retour à la ligne \emph{à l'intérieur} du paragraphe.
\end{exemplebox}

\begin{attention}[Pièges classiques avec les balises]
\begin{itemize}
\item \textbf{Oublier la balise fermante} : \texttt{<b>Important} sans \texttt{</b>} met \emph{toute la suite de la page} en gras.
\item \textbf{Mal imbriquer} : \texttt{<b><i>texte</b></i>} est incorrect ; la dernière balise ouverte doit être la première fermée : \texttt{<b><i>texte</i></b>}.
\item \textbf{Majuscules/minuscules} : HTML est insensible à la casse (\texttt{<P>} fonctionne), mais la convention professionnelle est d'écrire en \textbf{minuscules}.
\end{itemize}
\end{attention}

\courssub{L'attribut de balise}

Une balise seule donne une information générale ; un \cle{attribut} la précise. Par exemple, \texttt{<img>} ne suffit pas : il faut dire \emph{quelle} image afficher.

\begin{definition}[Attribut de balise]
Un \cle{attribut} est une information complémentaire placée \emph{dans la balise ouvrante}, sous la forme \texttt{nom="valeur"}. La valeur est toujours écrite entre guillemets. Certains attributs sont \textbf{obligatoires} (la balise ne fonctionne pas sans eux), d'autres sont \textbf{facultatifs}.
\end{definition}

\begin{propriete}[Syntaxe générale d'une balise avec attributs]
\begin{lstlisting}[language=HTML]
<balise attribut1="valeur1" attribut2="valeur2"> contenu </balise>
\end{lstlisting}
Exemples d'attributs obligatoires : \texttt{src} et \texttt{alt} pour \texttt{<img>}, \texttt{href} pour le lien \texttt{<a>}. Exemples d'attributs facultatifs : \texttt{width}, \texttt{height}, \texttt{align}, \texttt{title} (infobulle), \texttt{id}.
\end{propriete}

\begin{exemplebox}[Attributs obligatoires et facultatifs]
\begin{lstlisting}[language=HTML]
<img src="logo.png" alt="Logo du lycée" width="150">
\end{lstlisting}
\texttt{src} (chemin de l'image) et \texttt{alt} (texte alternatif affiché si l'image ne se charge pas) sont obligatoires ; \texttt{width} (largeur en pixels) est facultatif.
\end{exemplebox}

\courssub{La structure minimale d'une page HTML}

Toute page HTML bien formée possède un squelette immuable. Apprends-le par cœur : c'est la charpente de ta maison.

\begin{propriete}[Structure obligatoire d'un document HTML]
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <title>Titre de la page</title>
</head>
<body>
    <!-- Contenu visible de la page -->
</body>
</html>
\end{lstlisting}
\begin{itemize}
\item \texttt{<!DOCTYPE html>} : déclaration placée en toute première ligne, indiquant au navigateur qu'il s'agit d'un document HTML5 ;
\item \texttt{<html>} : élément racine qui englobe tout le document ;
\item \texttt{<head>} : en-tête, contient les informations \emph{invisibles} sur la page (encodage, titre, liens vers les fichiers CSS) ;
\item \texttt{<title>} : titre affiché dans l'onglet du navigateur (obligatoire, placé dans \texttt{<head>}) ;
\item \texttt{<body>} : corps de la page, contient tout ce qui sera \emph{affiché} à l'écran.
\end{itemize}
\end{propriete}

\texttt{<h1>} à \texttt{<h6>} & Titres, du plus important (\texttt{h1}, gros) au moins important (\texttt{h6}, petit) \\
\hline
\texttt{<p>} & Paragraphe (avec un espacement automatique avant et après) \\
\hline
\texttt{<br>} & Retour à la ligne simple, sans nouveau paragraphe (orpheline) \\
\hline
\texttt{<hr>} & Ligne horizontale de séparation (orpheline) \\
\hline
\texttt{<b>} & Texte en gras (\emph{bold}) \\
\hline
\texttt{<i>} & Texte en italique \\
\hline
\end{tabularx}
\end{center}

\begin{attention}[Titre n'est pas gras]
\texttt{<h1>} n'est pas un « gros texte décoratif » : c'est un \emph{titre structurant}. Une page ne devrait contenir qu'un seul \texttt{<h1>} (le titre principal), puis des \texttt{<h2>} pour les grandes parties, etc. Et pour un simple retour à la ligne dans une adresse, utilise \texttt{<br>}, pas \texttt{<p>}, qui crée un nouveau paragraphe avec un espacement.
\end{attention}

\end{methode}

\coursec{Listes, hyperliens et URL}

Dans la section précédente, nous avons posé les fondations d'une page HTML~: la structure globale (\texttt{<!DOCTYPE html>}, \texttt{<html>}, \texttt{<head>}, \texttt{<body>}), les balises de titre (\texttt{<h1>} à \texttt{<h6>}), les paragraphes (\texttt{<p>}) et l'importance cruciale de la balise \texttt{<meta charset="utf-8">} pour afficher correctement nos accents camerounais (É, È, À, Ô, etc.). Une page web ne vit cependant pas isolée~: elle doit structurer l'information sous forme de listes, et surtout, elle doit permettre à l'utilisateur de naviguer vers d'autres ressources. C'est précisément le rôle des \textbf{listes} et des \textbf{hyperliens}, que nous allons maîtriser maintenant.

\courssub{Les listes en HTML~: structurer l'information}

Une page web présente souvent des ensembles d'éléments~: un menu de navigation, les filières d'un lycée, les articles d'un panier d'achat, les étapes d'une recette de \emph{ndolé} ou de \emph{poulet DG}. HTML propose deux types principaux de listes, distinguées par la sémantique (le sens) que l'on veut donner à l'ordre des éléments.

\begin{definition}[Liste non ordonnée et liste ordonnée]
Une \textbf{liste non ordonnée} (\texttt{<ul>} pour \emph{Unordered List}) regroupe des éléments dont l'ordre n'a pas d'importance sémantique (ex.~: ingrédients d'une recette, liens d'un menu). Chaque élément est balisé \texttt{<li>} (\emph{List Item}). Le navigateur affiche par défaut une puce (disque, cercle, carré) devant chaque \texttt{<li>}.

Une \textbf{liste ordonnée} (\texttt{<ol>} pour \emph{Ordered List}) regroupe des éléments dont la séquence est significative (ex.~: étapes d'un montage PC, classement des élèves, chapitres d'un cours). Chaque élément est aussi balisé \texttt{<li>}. Le navigateur affiche par défaut une numérotation (1, 2, 3... ou a, b, c... selon l'attribut \texttt{type}).
\end{definition}

\begin{propriete}[Syntaxe de base des listes]
\begin{itemize}
    \item \textbf{Non ordonnée~:} \texttt{<ul><li>Élément 1</li><li>Élément 2</li></ul>}
    \item \textbf{Ordonnée~:} \texttt{<ol><li>Étape 1</li><li>Étape 2</li></ol>}
    \item Attributs utiles sur \texttt{<ol>}~: \texttt{type="1|A|a|I|i"} (style de numérotation), \texttt{start="n"} (démarrer à n), \texttt{reversed} (ordre décroissant).
    \item Attribut \texttt{value="n"} sur un \texttt{<li>} spécifique pour forcer son numéro.
\end{itemize}
\end{propriete}

\begin{exemplebox}[Liste des filières du lycée technique de Bafoussam]
Voici une liste non ordonnée pour des filières (l'ordre alphabétique est arbitraire) et une liste ordonnée pour la procédure d'inscription.
\begin{lstlisting}[language=HTML]

    <li>Électrotechnique (ET)</li>
    <li>Mécanique de Construction (MC)</li>

    <li>Remplir les informations (nom, date de naissance, série).</li>
    <li>Joindre l'acte de naissance et le certificat de scolarité.</li>
    <li>Déposer le dossier complet avant la date limite.</li>
</ol>
\end{lstlisting}
\end{exemplebox}

\textbf{Imbrication des listes (listes imbriquées).}\par
C'est une compétence clé du programme~: une liste peut contenir d'autres listes. Pour ce faire, on place une balise \texttt{<ul>} ou \texttt{<ol>} \emph{à l'intérieur} d'un \texttt{<li>} parent, au même niveau que le texte de cet item. L'indentation du code (décalage vers la droite) devient alors indispensable pour la lisibilité et la maintenance.

\begin{methode}[Construire une liste imbriquée proprement]
\begin{enumerate}
    \item Ouvrir la liste parente (\texttt{<ul>} ou \texttt{<ol>}).
    \item Pour chaque item parent~: ouvrir \texttt{<li>}, écrire le texte de l'item.
    \item Si l'item a des sous-items~: ouvrir la liste enfant (\texttt{<ul>} ou \texttt{<ol>}) \textbf{avant de fermer le \texttt{</li>} parent}.
    \item Remplir la liste enfant avec ses propres \texttt{<li>}.
    \item Fermer la liste enfant (\texttt{</ul>} ou \texttt{</ol>}).
    \item Fermer le \texttt{</li>} parent.
    \item Répéter pour les autres items parents.
    \item Fermer la liste parente.
    \item \textbf{Indenter} chaque niveau de 2 ou 4 espaces (ou une tabulation) pour visualiser la hiérarchie.
\end{enumerate}
\end{methode}

\begin{attention}[Piège classique : mauvaise fermeture des balises imbriquées]
L'erreur n°1 chez les débutants est de fermer le \texttt{</li>} parent \textbf{avant} d'avoir ouvert la liste enfant. Le code suivant est \textbf{invalide} (mal formé)~:
\begin{lstlisting}[language=HTML]
<!-- MAUVAIS : le </li> coupe la branche avant la sous-liste -->
<ul>
    <li>Filière Scientifique</li>     <!-- FERMETURE PRÉMATURÉE ! -->
    <ul>                              <!-- Orpheline, hors d'un <li> -->
        <li>Série C</li>
    </ul>
</li>                                 <!-- </li> en trop, déséquilibre -->
</ul>
\end{lstlisting}
Le validateur W3C (validator.w3.org) vous signalera une erreur de type « \texttt{Element ul not allowed as child of element ul in this context} » ou « \texttt{Unclosed element li} ». Respectez toujours la règle~: \textbf{la liste enfant est \emph{contenue} dans le \texttt{<li>} parent}.
\end{attention}

\courssub{L'URL~: adresse unique d'une ressource sur le Web}

Avant de créer des liens, il faut comprendre \emph{où} ils pointent. Chaque ressource sur le Web (page HTML, image, vidéo, fichier PDF, script, API) possède une adresse unique normalisée~: l'\textbf{URL} (\emph{Uniform Resource Locator}).

\begin{definition}[URL (Uniform Resource Locator)]
Une \textbf{URL} est une chaîne de caractères standardisée qui identifie l'emplacement d'une ressource sur Internet et le protocole pour y accéder. Elle se décompose en plusieurs parties obligatoires ou optionnelles~:
\begin{itemize}
    \item \textbf{Le protocole (scheme)}~: \texttt{http://}, \texttt{https://}, \texttt{ftp://}, \texttt{mailto:}, \texttt{file://}... Indique \emph{comment} communiquer.
    \item \textbf{L'autorité (authority)}~: souvent un \textbf{nom de domaine} (ex. \texttt{www.minesec.gov.cm}) ou une adresse IP. Peut inclure un port (\texttt{:80}, \texttt{:443}) et des identifiants (\texttt{user:pass@} — déconseillé).
    \item \textbf{Le chemin (path)}~: chemin hiérarchique vers la ressource sur le serveur (ex. \texttt{/resultats/probatoire/2024.pdf}). Sensible à la casse sur les serveurs Linux/Unix (majorité du Web).
    \item \textbf{La requête (query string)}~: commence par \texttt{?}, paires \texttt{clé=valeur} séparées par \texttt{\&} (ex. \texttt{?annee=2024\&session=juin}).
    \item \textbf{Le fragment (anchor)}~: commence par \texttt{\#}, pointe vers une ancre \texttt{id} dans la page (ex. \texttt{\#inscription}).
\end{itemize}
\end{definition}

\begin{propriete}[Règles de syntaxe d'une URL]
\begin{itemize}
    \item Les caractères non-ASCII (espaces, accents, \texttt{é}, \texttt{à}, \texttt{ç}) doivent être \textbf{encodés en pourcent} (\emph{percent-encoding})~: espace $\to$ \texttt{\%20} ou \texttt{+}, \texttt{é} $\to$ \texttt{\%C3\%A9}.
    \item Les caractères réservés (\texttt{: / ? \# [ ] @ ! \$ \& ' ( ) * + , ; =}) ont un sens spécial ; s'ils font partie d'une valeur de données, ils doivent être encodés.
    \item La longueur maximale pratique est d'environ \num{2000}~caractères (limite navigateurs/serveurs).
    \item \textbf{HTTPS} (port 443) est la norme actuelle~: chiffre la communication (TLS/SSL). Tout site professionnel (banque, administration, école) doit l'utiliser. HTTP (port 80) transmet en clair (risque d'écoute).
\end{itemize}
\end{propriete}

\courssub{Les hyperliens~: la navigation avec \texttt{<a>}}

L'hyperlien (ou simplement \emph{lien}) est l'âme du Web. C'est lui qui transforme un ensemble de documents isolés en un \emph{hypertexte} navigable.

\begin{definition}[Hyperlien (balise \texttt{<a>})]
Un \textbf{hyperlien} est un élément interactif (texte, image, bloc) qui, au clic (ou activation clavier), demande au navigateur de charger la ressource désignée par son attribut \texttt{href} (\emph{Hypertext REFerence}). La balise est \texttt{<a>} (ancre). Elle est \textbf{inline} par défaut (ne force pas de saut de ligne).
\begin{itemize}
    \item Attribut obligatoire~: \texttt{href="URL"} (absolue ou relative).
    \item Attribut \texttt{title="Texte"}~: \textbf{infobulle} (tooltip) affichée au survol souris ; utile pour l'accessibilité et l'UX.
    \item Attribut \texttt{target="\_blank"}~: ouvre dans un nouvel onglet/fenêtre. \textbf{Obligatoire d'ajouter \texttt{rel="noopener noreferrer"} pour la sécurité} (empêche la page ouverte d'accéder à \texttt{window.opener}).
    \item Attribut \texttt{download}~: force le téléchargement au lieu de l'affichage (pour PDF, ZIP, images).
\end{itemize}
\end{definition}

\textbf{Lien absolu vs lien relatif.}\par
C'est une distinction fondamentale pour l'organisation d'un site (dossiers locaux vs ressources externes).

\begin{propriete}[Lien absolu]
Contient l'URL complète (protocole + domaine + chemin). Pointe vers \textbf{n'importe quelle ressource sur le Web}, y compris sur le même domaine mais de façon explicite.
\begin{lstlisting}[language=HTML]
<a href="https://www.minesec.gov.cm/examens/probatoire">Résultats Probatoire MINESEC</a>
<a href="https://www.camtelecom.cm/fibre-optique">CAMTEL Fibre Optique</a>
\end{lstlisting}
\end{propriete}

\begin{propriete}[Lien relatif]
Ne contient \textbf{que le chemin relatif à la page courante}. Ne fonctionne qu'à l'intérieur du \textbf{même site} (même domaine). Indispensable pour la portabilité : si vous déplacez le site sur un autre domaine (ex. de \texttt{localhost} vers \texttt{monlycee.cm}), les liens relatifs fonctionnent sans modification.
\begin{itemize}
    \item \texttt{href="page.html"}~: même dossier.
    \item \texttt{href="dossier/page.html"}~: sous-dossier (descendre).
    \item \texttt{href="../page.html"}~: dossier parent (remonter d'un niveau). \texttt{..} = parent.
    \item \texttt{href="../../autre/page.html"}~: remonter de deux niveaux puis descendre.
    \item \texttt{href="/"} ou \texttt{href="/index.html"}~: \textbf{relatif à la racine du site} (démarre par \texttt{/}). Très robuste.
\end{itemize}
\end{propriete}

\begin{methode}[Choisir entre lien absolu et lien relatif]
\begin{enumerate}
    \item \textbf{La ressource est-elle sur un autre domaine (site externe) ?}
        \begin{itemize}
            \item \textbf{OUI} $\to$ \textbf{Lien absolu obligatoire} (ex. lien vers Wikipedia, CAMTEL, Facebook, Google Fonts).
        \end{itemize}
    \item \textbf{La ressource est-elle sur le même site (même domaine) ?}
        \begin{itemize}
            \item \textbf{OUI} $\to$ \textbf{Privilégier le lien relatif}.
            \item Si la structure de dossiers est stable et simple~: relatif au fichier courant (\texttt{page.html}, \texttt{dossier/page.html}, \texttt{../page.html}).
            \item Si la structure peut changer ou pour les liens de navigation globale (menu, logo, pied de page) $\to$ \textbf{relatif à la racine} (\texttt{/index.html}, \texttt{/contact.html}, \texttt{/assets/css/style.css}). C'est la meilleure pratique professionnelle.
        \end{itemize}
    \item \textbf{Testez toujours} en cliquant sur le lien dans le navigateur (local \texttt{file://} ou serveur \texttt{http://localhost}). Vérifiez la barre d'adresse et la console (F12) pour les erreurs 404.
\end{enumerate}
\end{methode}

\textbf{Lien vers une ancre interne (fragment d'URL).}\par
Permet de sauter à une section précise \emph{dans la même page} ou \emph{dans une autre page}. On utilise l'attribut universel \texttt{id} sur l'élément cible.

\begin{exemplebox}[Navigation interne avec ancres (sommaire de page)]
\begin{lstlisting}[language=HTML]
<!-- Dans la même page : sommaire en haut -->
<nav>
    <ul>
        <li><a href="#presentation">Présentation du lycée</a></li>
        <li><a href="#filieres">Nos filières</a></li>
        <li><a href="#inscription">Inscription 2024-2025</a></li>
        <li><a href="#contact">Contact \& Accès</a></li>
    </ul>
</nav>

<!-- Plus bas dans la page : sections cibles -->
<section id="presentation">
    <h2>Présentation du Lycée Technique de Douala</h2>
    <p>...</p>
</section>

<section id="filieres">
    <h2>Filières proposées</h2>
    <!-- Liste imbriquée vue plus haut -->
</section>

<section id="inscription">
    <h2>Modalités d'inscription</h2>
    <ol>...</ol>
</section>

<footer id="contact">
    <address>BP 1234 Douala - Tél : +237 2XX XX XX XX</address>
</footer>
\end{lstlisting}
\end{exemplebox}

\begin{propriete}[Lien vers ancre dans une \emph{autre} page]
Combine chemin relatif/absolu + \texttt{\#id}.
\begin{lstlisting}[language=HTML]
<!-- Depuis index.html vers la section "inscription" de infos.html -->
<a href="infos.html#inscription">Voir les modalités d'inscription</a>

<!-- Lien absolu vers ancre externe -->
<a href="https://www.minesec.gov.cm/resultats#probatoire">Résultats Probatoire sur le site MINESEC</a>
\end{lstlisting}
\end{propriete}

\textbf{Lien \texttt{mailto:~:} ouvrir le client de messagerie.}\par
Utile pour les pages « Contact ». Ouvre le logiciel de messagerie par défaut (Outlook, Thunderbird, Gmail web, Mail iOS/Android) avec des champs pré-remplis.

\begin{propriete}[Syntaxe \texttt{mailto:}]
\begin{lstlisting}[language=HTML]
<!-- Simple -->
<a href="mailto:secretariat@lyceebilingue.cm">Écrire au secrétariat</a>

<!-- Avec sujet, corps, copies (encodage URL requis pour espaces et accents) -->

    Contacter la direction (pré-rempli)
</a>
\end{lstlisting}
\textbf{Attention~:} \texttt{mailto:} dépend de la configuration poste client (pas de client mail $\to$ ne fait rien ou propose webmail). Ne pas l'utiliser pour des actions critiques serveur (utilisez un formulaire \texttt{<form action="...">} traité par un script côté serveur — en Terminale).
\end{propriete}

\begin{attention}[Erreur n°1 : le lien relatif cassé après déplacement de fichier]
C'est \textbf{la} cause numéro un de liens brisés (erreur 404) en développement local.
\begin{quote}
\textbf{Scénario~:} Vous créez \texttt{index.html} et \texttt{apropos.html} à la racine. Dans \texttt{index.html}, vous mettez \texttt{<a href="apropos.html">À propos</a>}. Ça marche. Puis vous créez un dossier \texttt{pages/} et vous y déplacez \texttt{apropos.html} pour ranger. \textbf{Vous oubliez de mettre à jour le lien dans \texttt{index.html}}. Le navigateur cherche \texttt{apropos.html} à la racine $\to$ \textbf{404 Not Found}.
\end{quote}
\begin{methode}[Éviter les liens relatifs cassés]
\begin{enumerate}
    \item \textbf{Planifiez l'arborescence} avant de coder (dossiers \texttt{css/}, \texttt{js/}, \texttt{images/}, \texttt{pages/}).
    \item \textbf{Utilisez des liens relatifs à la racine} (\texttt{/pages/apropos.html}) pour la navigation principale. Ils ne cassent \textbf{jamais} quand on déplace le fichier \emph{source} du lien.
    \item \textbf{Utilisez un éditeur avec renommage/refactoring} (VS Code : clic droit $\to$ Rename Symbol / Move File met à jour les imports/liens automatiquement dans tout le projet).
    \item \textbf{Testez systématiquement} après tout déplacement de fichier (raccourci Ctrl+Click sur le \texttt{href} dans VS Code pour sauter à la cible).
    \item \textbf{Vérifiez la console réseau (F12 $\to$ Network)} : les requêtes en rouge (statut 404) révèlent les ressources introuvables (CSS, JS, images, liens).
\end{enumerate}
\end{methode}
\end{attention}

\courssub{Bonnes pratiques, accessibilité et limites du HTML statique}

Au-delà de la syntaxe, un développeur web professionnel (même en Première TI) doit adopter des réflexes de qualité.

\begin{aretenir}[Check-list « Liens de qualité » pour le Probatoire et au-delà]
\begin{itemize}
    \item \textbf{Texte de lien explicite~:} Évitez « Cliquez ici », « Lien », « Ici ». Préférez « \emph{Consulter les résultats du Probatoire 2024} », « \emph{Télécharger le programme de 1ère TI (PDF)} ». Le texte seul doit indiquer la destination (accessibilité lecteurs d'écran, SEO, UX).
    \item \textbf{Infobulle \texttt{title}~:} Ajoutez une information \emph{supplémentaire} (pas une répétition du texte). Ex.~: \texttt{<a href="/inscription" title="Frais : 15\,000 FCFA - Date limite : 30 sept.">Inscription</a>}.
    \item \textbf{Liens externes~:} \texttt{target="\_blank" rel="noopener noreferrer"} systématique. Indiquez visuellement (icône \texttt{<span aria-hidden="true">$\Box$\textsuperscript{$\nearrow$}</span>} ou texte « (nouvel onglet) ») que le lien sort du site.
    \item \textbf{Encodage des URLs~:} Dans \texttt{href}, les espaces deviennent \texttt{\%20}, les accents s'encodent (UTF-8 $\to$ \%XX). En HTML5, le navigateur gère souvent l'affichage, mais le code source doit être valide.
    \item \textbf{Validation~:} Passez vos pages au \textbf{validateur W3C} (validator.w3.org) : « Validate by direct input » ou « Validate by file upload ». Corrigez \textbf{toutes} les erreurs (balises non fermées, attributs invalides, \texttt{<a>} sans \texttt{href}, \texttt{id} dupliqués).
\end{itemize}
\end{aretenir}

\begin{savaistu}[Le premier lien de l'histoire du Web]
Le 6 août 1991, Tim Berners-Lee a mis en ligne la première page web au CERN (Suisse). Elle expliquait le projet « WorldWideWeb » et contenait... des hyperliens vers d'autres documents du CERN. L'URL était \texttt{http://info.cern.ch/hypertext/WWW/TheProject.html}. Elle existe toujours (archivée). Au Cameroun, la première connexion Internet opérationnelle date de 1996 (via le projet NICI et CAMTEL). Aujourd'hui, la fibre optique nationale (backbone CAMTEL, projet \emph{Patriot}) relie les 10 régions, permettant aux lycées techniques d'accéder aux ressources pédagogiques en ligne et de publier leurs propres sites d'établissement.
\end{savaistu}

\begin{exoresolu}[Corriger des liens relatifs cassés]
\textbf{Énoncé.}
L'arborescence d'un site de gestion de notes est la suivante~:
\begin{lstlisting}
/ (racine)
├── index.html
├── css/
│   └── style.css
├── pages/
│   ├── eleves.html
│   └── notes/
│       └── saisie.html
└── assets/
    └── logo.png
\end{lstlisting}
Dans \texttt{pages/notes/saisie.html}, on trouve ces liens (certains sont erronés)~:
\begin{enumerate}
    \item \texttt{<a href="../../index.html">Accueil</a>}
    \item \texttt{<a href="eleves.html">Liste élèves</a>}
    \item \texttt{<a href="/css/style.css">Feuille de style</a>} (dans une balise \texttt{<link>})
    \item \texttt{<a href="../assets/logo.png">Logo</a>} (dans une balise \texttt{<img>})
\end{enumerate}
Identifiez les erreurs et corrigez-les.

\textbf{Solution détaillée.}
Analysons la position de \texttt{saisie.html}~: \texttt{/pages/notes/saisie.html}. Profondeur~: 3 niveaux (pages $\to$ notes $\to$ saisie.html).

\begin{enumerate}
    \item \texttt{href="../../index.html"}~: \texttt{../} remonte à \texttt{/pages/}, second \texttt{../} remonte à \texttt{/} (racine). \textbf{Correct}. Atteint \texttt{/index.html}.
    \item \texttt{href="eleves.html"}~: chemin relatif \textbf{sans préfixe}, donc cherche dans le \textbf{même dossier} que la page courante, soit \texttt{/pages/notes/eleves.html}. \textbf{ERREUR} : \texttt{eleves.html} est dans \texttt{/pages/} (un niveau au-dessus).
        \begin{itemize}
            \item Correction~: \texttt{href="../eleves.html"} (remonter d'un niveau vers \texttt{/pages/}) \textbf{OU} \texttt{href="/pages/eleves.html"} (relatif à la racine, recommandé).
        \end{itemize}
    \item \texttt{href="/css/style.css"} (dans \texttt{<link rel="stylesheet" href="...">})~: commence par \texttt{/}, donc \textbf{relatif à la racine}. Chemin résolu~: \texttt{/css/style.css}. \textbf{Correct}. C'est la meilleure pratique pour les ressources partagées (CSS, JS, images communes).
    \item \texttt{href="../assets/logo.png"} (dans \texttt{<img src="...">})~: \texttt{../} remonte à \texttt{/pages/}. Cherche \texttt{/pages/assets/logo.png}. \textbf{ERREUR} : le dossier \texttt{assets/} est à la \textbf{racine}, pas dans \texttt{/pages/}.
        \begin{itemize}
            \item Correction~: \texttt{href="../../assets/logo.png"} (remonter deux niveaux : notes $\to$ pages $\to$ racine) \textbf{OU} \texttt{href="/assets/logo.png"} (relatif à la racine, \textbf{fortement recommandé}).
        \end{itemize}
\end{enumerate}

\textbf{Règle d'or~:} Pour les ressources globales (CSS, JS, logo, favicon, polices), \textbf{utilisez toujours le chemin relatif à la racine (\texttt{/...})}. Cela évite tout calcul de \texttt{../} selon la profondeur de la page courante.
\end{exoresolu}

\coursec{Insertion de médias : images, sons, vidéos}

Dans la section précédente, tu as appris à structurer le texte d'une page avec les listes et à relier les pages entre elles grâce aux hyperliens et aux URL. Mais un site composé uniquement de texte ressemblerait à un vieux document tapé à la machine ! Imagine le site web du lycée sans le logo de l'établissement, sans la photo de la cérémonie de remise des prix, sans l'hymne national en fond sonore : il serait terne et peu attractif. Les \cle{médias} (images, sons, vidéos) transforment une simple page en une véritable vitrine. C'est exactement ce que fait un cybercafé de Douala qui crée le site d'une agence de tourisme : il y insère des photos du Mont Cameroun, une vidéo des chutes de la Lobé et des chants traditionnels. Dans cette section, tu vas apprendre à insérer chacun de ces médias avec la syntaxe HTML exacte, à choisir le bon chemin de fichier, et à éviter les pièges classiques.

\courssub{Insertion d'une image : la balise \texttt{<img>}}

\textbf{Intuition.} Une page HTML ne « contient » pas réellement les images : elle contient seulement une \emph{référence} vers le fichier image, comme une affiche publicitaire indique où trouver un produit. Le navigateur lit cette référence, va chercher le fichier image (sur le même ordinateur ou sur un serveur distant), puis l'affiche à l'endroit prévu.

\begin{definition}[Balise \texttt{<img>}]
La balise \texttt{<img>} (de l'anglais \emph{image}) permet d'insérer une image dans une page web. C'est une \cle{balise orpheline} (ou \emph{balise vide}) : elle ne possède \textbf{pas de balise fermante}. Sa syntaxe générale en HTML5 est :
\begin{lstlisting}[language=HTML]
<img src="URL_de_l_image" alt="texte alternatif" width="largeur" height="hauteur">
\end{lstlisting}
\end{definition}

\begin{propriete}[Attributs de la balise \texttt{<img>}]
\begin{itemize}
  \item \texttt{src} (\emph{source}) : \textbf{obligatoire}. Indique l'URL de l'image, c'est-à-dire l'adresse du fichier image à afficher.
  \item \texttt{alt} (\emph{alternative}) : \textbf{fortement recommandé} (obligatoire pour la validité HTML5). Texte alternatif affiché si l'image ne peut pas être chargée, et lu à voix haute par les logiciels d'accessibilité.
  \item \texttt{width} et \texttt{height} : largeur et hauteur d'affichage, exprimées en \cle{pixels} (valeurs numériques entières, sans unité \texttt{px} dans l'attribut). Si l'on n'indique qu'une seule dimension, le navigateur calcule l'autre en conservant les proportions.
\end{itemize}
\end{propriete}

\begin{attention}[\texttt{<img>} est une balise orpheline]
Contrairement à \texttt{<p>...</p>} ou \texttt{<h1>...</h1>}, la balise \texttt{<img>} \textbf{ne se ferme jamais} avec \texttt{</img>}. Écrire \texttt{</img>} est une erreur fréquente au Probatoire. Toute l'information se trouve dans les attributs, à l'intérieur de la balise unique :
\begin{lstlisting}[language=HTML]
<img src="images/logo.png" alt="Logo du lycee">
\end{lstlisting}
Même remarque pour \texttt{<br>}, \texttt{<hr>}, \texttt{<meta>}, \texttt{<input>} : ce sont aussi des balises orphelines.
\end{attention}

\courssub{Image locale (chemin relatif) ou image distante (URL absolue) ?}

L'attribut \texttt{src} accepte deux types d'adresses, que tu connais déjà depuis la section sur les hyperliens :

\begin{itemize}
  \item \textbf{Image locale (chemin relatif)} : le fichier image est rangé dans les dossiers du site, par exemple dans un sous-dossier \texttt{images/}. On écrit alors \texttt{src="images/logo.png"}. C'est la méthode recommandée pour un site sérieux : l'image voyage avec le site.
  \item \textbf{Image distante (URL absolue)} : l'image est hébergée sur un autre serveur. On écrit alors l'adresse complète : \texttt{src="https://www.exemple.cm/photo.jpg"}. Pratique pour tester, mais risqué : si le site distant supprime l'image, elle disparaît de ta page (lien brisé) !
\end{itemize}

\begin{methode}[Insérer une image avec le bon chemin relatif]
Pour insérer proprement une image locale dans ta page, suis ces étapes :
\begin{enumerate}
  \item Dans le dossier de ton site (par exemple \texttt{mon\_site/}), crée un sous-dossier nommé \texttt{images}.
  \item Copie ton fichier image (par exemple \texttt{logo.png}) dans ce sous-dossier.
  \item Vérifie l'orthographe exacte du nom de fichier : \texttt{logo.png} et \texttt{Logo.PNG} sont deux noms différents pour de nombreux serveurs (respecte les majuscules et l'extension).
  \item Dans ta page HTML, écris la balise avec le chemin relatif : \texttt{<img src="images/logo.png" alt="Logo">}.
  \item Ouvre la page dans le navigateur : si l'image s'affiche, le chemin est correct ; sinon, vérifie le nom du dossier, le nom du fichier et l'extension.
\end{enumerate}
\end{methode}

\courssub{Le texte alternatif \texttt{alt} : bien plus qu'une option}

\begin{definition}[Texte alternatif]
Le \cle{texte alternatif} (attribut \texttt{alt}) est une courte description de l'image. Il remplit deux rôles essentiels :
\begin{itemize}
  \item il s'\textbf{affiche à la place de l'image} si celle-ci ne peut pas être chargée (fichier supprimé, chemin erroné, connexion lente) ;
  \item il est \textbf{lu à voix haute} par les lecteurs d'écran utilisés par les personnes malvoyantes, rendant la page accessible à tous.
\end{itemize}
\end{definition}

\begin{savaistu}[L'attribut \texttt{alt} et l'accessibilité]
Les personnes aveugles ou malvoyantes naviguent sur le web grâce à des logiciels appelés \cle{lecteurs d'écran}, qui lisent à voix haute le contenu des pages. Quand le logiciel rencontre une image, il lit le contenu de l'attribut \texttt{alt}. Une image sans \texttt{alt} est donc « invisible » pour ces utilisateurs. C'est pourquoi les normes internationales du web (W3C) exigent que toute image informative possède un texte alternatif. Rédiger un bon \texttt{alt}, c'est rendre ton site ouvert à tous, y compris aux élèves malvoyants de ton lycée.
\end{savaistu}

\courssub{L'image cliquable}

\textbf{Intuition.} Sur de nombreux sites, cliquer sur le logo en haut de la page ramène à l'accueil. Comment faire ? Il suffit de combiner deux balises que tu connais déjà : le lien \texttt{<a>} et l'image \texttt{<img>}.

\begin{propriete}[Image cliquable]
Pour rendre une image cliquable, on \textbf{imbrique} la balise \texttt{<img>} à l'intérieur d'une balise de lien \texttt{<a href="...">...</a>}. L'image remplace alors le texte du lien :
\begin{lstlisting}[language=HTML]
<a href="destination.html"><img src="images/logo.png" alt="Logo"></a>
\end{lstlisting}
\end{propriete}

\begin{exemplebox}[Logo du lycée cliquable renvoyant vers l'accueil]
Sur le site du Lycée de Nkol-Eton, le logo affiché en haut de chaque page renvoie vers la page d'accueil \texttt{index.html} :
\begin{lstlisting}[language=HTML]
<!-- Logo cliquable : un clic ramene a la page d'accueil -->
<a href="index.html" title="Retour à l'accueil">
  <img src="images/logo_lycee.png" alt="Logo du Lycee de Nkol-Eton"
       width="120" height="120">
</a>
\end{lstlisting}
L'attribut \texttt{title} du lien ajoute une \cle{infobulle} : le texte « Retour à l'accueil » apparaît quand la souris survole le logo.
\end{exemplebox}

\begin{attention}[Ne pas confondre \texttt{src} et \texttt{href}]
C'est l'une des erreurs les plus fréquentes :
\begin{itemize}
  \item \texttt{src} (\emph{source}) indique \textbf{où se trouve le média à afficher} : il s'utilise avec \texttt{<img>}, \texttt{<audio>}, \texttt{<video>}, \texttt{<source>}.
  \item \texttt{href} (\emph{hypertext reference}) indique \textbf{la destination d'un lien} : il s'utilise avec \texttt{<a>}, \texttt{<link>}.
\end{itemize}
Écrire \texttt{<img href="...">} ou \texttt{<a src="...">} ne fonctionne pas. Retiens : \textbf{src = Source du média ; href = Hyperlien}.
\end{attention}

\courssub{Insertion d'un son : la balise \texttt{<audio>}}

\textbf{Intuition.} Un site culturel présentant les danses traditionnelles du Cameroun gagne à proposer un extrait musical. Avant HTML5, il fallait des logiciels externes (plugins) ; aujourd'hui, une seule balise suffit.

\begin{definition}[Balise \texttt{<audio>}]
La balise \texttt{<audio>} insère un lecteur sonore dans la page. L'attribut \texttt{src} indique l'URL du fichier audio, et l'attribut \texttt{controls} (booléen, sans valeur) fait apparaître les boutons de lecture (lecture, pause, volume) :
\begin{lstlisting}[language=HTML]
<audio src="sons/hymne.mp3" controls></audio>
\end{lstlisting}
Si le navigateur ne supporte pas le format, le contenu placé entre les balises (texte de secours) s'affiche.
\end{definition}

\begin{attention}[Toujours mettre \texttt{controls}]
Sans l'attribut \texttt{controls}, le lecteur audio est \textbf{invisible} : le son ne peut pas être déclenché par le visiteur (sauf lecture automatique déconseillée). Sauf cas particulier, ajoute toujours \texttt{controls}. Le format audio le plus courant et le mieux supporté est le \cle{MP3}.
\end{attention}

\courssub{Insertion d'une vidéo : la balise \texttt{<video>}}

\begin{definition}[Balise \texttt{<video>}]
La balise \texttt{<video>} insère un lecteur vidéo dans la page. On utilise \texttt{src} pour l'URL du fichier, \texttt{controls} pour afficher les commandes de lecture, \texttt{width} (éventuellement \texttt{height}) pour régler la taille du lecteur en pixels, et \texttt{poster} pour une image d'aperçu avant lecture :
\begin{lstlisting}[language=HTML]
<video src="videos/chutes_lobe.mp4" controls width="480" poster="images/apercu.jpg"></video>
\end{lstlisting}
Le format vidéo le plus répandu sur le web est le \cle{MP4} (codec H.264).
\end{definition}

\textbf{Poids des fichiers et temps de chargement.} Au Cameroun, de nombreux visiteurs naviguent avec une connexion mobile limitée. Il faut donc \cle{optimiser} les médias : redimensionner les photos à la taille réellement affichée (inutile d'envoyer une photo de 4000 pixels de large pour l'afficher en 400), choisir le format adapté (JPG pour les photos, PNG pour les logos) et compresser les fichiers. Une image de page web devrait idéalement peser moins de \SI{200}{Ko}.

\begin{itemize}

\coursec{Les tableaux en HTML}

Dans la section précédente, tu as appris à insérer des médias (images, sons, vidéos) pour rendre tes pages vivantes. Mais une page web ne contient pas que du texte et des images : il arrive très souvent qu'on doive présenter des \cle{données organisées en lignes et en colonnes}. Pense à l'emploi du temps affiché au tableau du lycée, au bulletin de notes que le proviseur fait imprimer en fin de trimestre, ou au tableau des prix dans une boutique de Douala. Comment représenter proprement ces grilles d'informations dans une page web ? C'est exactement le rôle des \cle{tableaux HTML}.

\courssub{Structure d'un tableau : \texttt{<table>}, \texttt{<tr>}, \texttt{<td>}, \texttt{<th>}}

\begin{definition}[Tableau HTML]
Un \cle{tableau} HTML est un élément de page web qui organise des données en \textbf{lignes} et en \textbf{colonnes}, formant des \textbf{cellules} à leur intersection. Il se construit avec quatre balises essentielles :
\begin{itemize}
\item \texttt{<table>} \texttt{</table>} : délimite le tableau complet ;
\item \texttt{<tr>} \texttt{</tr>} (\emph{table row}) : délimite une \textbf{ligne} du tableau ;
\item \texttt{<td>} \texttt{</td>} (\emph{table data}) : délimite une \textbf{cellule} ordinaire contenant des données ;
\item \texttt{<th>} \texttt{</th>} (\emph{table header}) : délimite une cellule d'\textbf{en-tête} (affichée en gras et centrée par défaut).
\end{itemize}
\end{definition}

L'idée directrice est simple : un tableau se décrit \textbf{ligne par ligne}, et chaque ligne se décrit \textbf{cellule par cellule}, de gauche à droite. On n'écrit jamais les colonnes directement : ce sont les cellules des différentes lignes qui, empilées, forment les colonnes.

\begin{propriete}[Règles d'imbrication]
\begin{enumerate}
\item Toute cellule (\texttt{<td>} ou \texttt{<th>}) doit se trouver \textbf{à l'intérieur} d'une ligne \texttt{<tr>}.
\item Toute ligne \texttt{<tr>} doit se trouver à l'intérieur de \texttt{<table>}.
\item Le nombre de colonnes du tableau est déterminé par la ligne qui contient le \textbf{plus} de cellules.
\end{enumerate}
\end{propriete}

\begin{exemplebox}[Premier tableau : les notes de deux élèves]
\begin{lstlisting}[language=HTML]
<table border="1">
  <tr>
    <th>Nom</th>
    <th>Maths</th>
    <th>Informatique</th>
  </tr>
  <tr>
    <td>Etoundi</td>
    <td>14</td>
    <td>17</td>
  </tr>
  <tr>
    <td>Kamga</td>
    <td>11</td>
    <td>15</td>
  </tr>
</table>
\end{lstlisting}
Ce code produit un tableau de 3 lignes et 3 colonnes : la première ligne est une ligne d'en-têtes (\texttt{<th>}), les deux suivantes contiennent les données (\texttt{<td>}).
\end{exemplebox}

\begin{attention}[Balise fermante oubliée]
L'erreur la plus fréquente du débutant est d'oublier un \texttt{</td>} ou un \texttt{</tr>}. Le navigateur tente alors de « deviner » la structure, et le tableau s'affiche déformé ou décalé. Indente ton code comme dans l'exemple : chaque niveau d'imbrication décalé vers la droite rend les oublis visibles immédiatement.
\end{attention}

\courssub{Les attributs du tableau : \texttt{border}, \texttt{id}, \texttt{width}, \texttt{height}, \texttt{align}, \texttt{cellpadding}, \texttt{cellspacing}}

Sans attribut, un tableau s'affiche \textbf{sans bordures} et avec une taille automatique. Les attributs de la balise \texttt{<table>} permettent de contrôler son apparence.

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Attribut} & \textbf{Rôle} \\
\hline
\texttt{border="1"} & Affiche une bordure d'épaisseur 1 pixel autour du tableau et des cellules. \texttt{border="0"} (ou absence) : pas de bordure. \\
\hline
\texttt{id="notes"} & Donne un identifiant unique au tableau (utile pour le CSS et le JavaScript). \\
\hline
\texttt{width="80\%"} & Largeur du tableau : en pixels (\texttt{width="500"}) ou en pourcentage de la page. \\
\hline
\texttt{height="200"} & Hauteur du tableau en pixels ou en pourcentage. \\
\hline
\texttt{align="center"} & Positionne le tableau dans la page : \texttt{left}, \texttt{center} ou \texttt{right}. \\
\hline
\texttt{cellpadding="5"} & Marge \textbf{intérieure} de chaque cellule : espace entre le bord de la cellule et son contenu (en pixels). \\
\hline
\texttt{cellspacing="3"} & Espace \textbf{entre} les cellules voisines (en pixels). \\
\hline
\end{tabularx}
\end{center}

\begin{definition}[\texttt{cellpadding} et \texttt{cellspacing}]
\begin{itemize}
\item \cle{cellpadding} : espace \textbf{à l'intérieur} de chaque cellule, entre sa bordure et le texte qu'elle contient. C'est le « rembourrage » de la cellule.
\item \cle{cellspacing} : espace \textbf{entre} les cellules, c'est-à-dire l'épaisseur du vide qui sépare deux cellules voisines.
\end{itemize}
\end{definition}

\texttt{border}, \texttt{align}, \texttt{width}, \texttt{cellpadding} et \texttt{cellspacing} sont des attributs HTML \textbf{historiques} : dans la pratique professionnelle actuelle, on préfère les définir en CSS. Cependant, ils figurent \textbf{explicitement au programme de Première TI} et sont donc exigibles au Probatoire : tu dois connaître leur nom, leur rôle et leur syntaxe exacte.
\end{attention}

\courssub{La légende du tableau : \texttt{<caption>}}

\begin{definition}[Balise \texttt{<caption>}]
La balise \texttt{<caption>} \texttt{</caption>} définit la \cle{légende} (le titre) d'un tableau. Elle doit être placée \textbf{juste après} la balise ouvrante \texttt{<table>}, avant la première ligne \texttt{<tr>}. Par défaut, la légende s'affiche centrée au-dessus du tableau.
\end{definition}

\begin{lstlisting}[language=HTML]
<table border="1">
  <caption>Moyennes du premier trimestre - Premiere TI</caption>
  <tr><th>Eleve</th><th>Moyenne</th></tr>
  <tr><td>Ngo Bell</td><td>15,5</td></tr>
</table>
\end{lstlisting}

\courssub{Fusion de cellules : \texttt{colspan} et \texttt{rowspan}}

\textbf{Intuition.} Regarde un emploi du temps : le créneau « Informatique » occupe souvent \textbf{deux heures consécutives} (deux lignes), et la case « Pause » s'étend parfois sur \textbf{plusieurs colonnes}. Un tableau réel n'est donc pas toujours une grille régulière : certaines cellules « mangent » leurs voisines. HTML offre deux attributs pour cela.

\begin{definition}[Fusion de cellules]
\begin{itemize}
\item \cle{colspan} (appliqué à \texttt{<td>} ou \texttt{<th>}) : fusion \textbf{horizontale}. \texttt{colspan="n"} signifie que la cellule s'étend sur $n$ colonnes vers la droite.
\item \cle{rowspan} (appliqué à \texttt{<td>} ou \texttt{<th>}) : fusion \textbf{verticale}. \texttt{rowspan="n"} signifie que la cellule s'étend sur $n$ lignes vers le bas.
\end{itemize}
Après une fusion, les cellules « absorbées » \textbf{ne s'écrivent plus} dans le code.
\end{definition}

\begin{popfigure}
\begin{tikzpicture}[scale=0.9, every node/.style={font=\small}]
% Grille 4 lignes x 3 colonnes, cellules de 2.4 x 1.1
% Ligne 1 : titre fusionne colspan=3

\node at (3.6,3.85) {1 (\texttt{colspan="3"})};
% Ligne 2 : cellule 2 (rowspan 2), cellule 3, cellule 4
\draw[fill=popblueL, thick, popdark] (0,1.1) rectangle (2.4,3.3);
\node at (1.2,2.2) {2 (\texttt{rowspan="2"})};
\draw[fill=white, thick, popdark] (2.4,2.2) rectangle (4.8,3.3);
\node at (3.6,2.75) {3};
\draw[fill=white, thick, popdark] (4.8,2.2) rectangle (7.2,3.3);
\node at (6.0,2.75) {4};
% Ligne 3 : cellules 5 et 6 (la colonne 1 est absorbée par rowspan)
\draw[fill=white, thick, popdark] (2.4,1.1) rectangle (4.8,2.2);
\node at (3.6,1.65) {5};
\draw[fill=white, thick, popdark] (4.8,1.1) rectangle (7.2,2.2);
\node at (6.0,1.65) {6};
% Ligne 4 : trois cellules normales
\draw[fill=white, thick, popdark] (0,0) rectangle (2.4,1.1);

\begin{methode}[Construire un tableau avec fusions]
\begin{enumerate}
\item \textbf{Dessiner} le tableau sur papier, avec ses bordures et ses fusions.
\item \textbf{Compter les colonnes} de la ligne la plus large (celle sans fusion horizontale) : c'est le nombre de colonnes du tableau.
\item \textbf{Repérer les fusions} : pour chaque cellule élargie, noter son \texttt{colspan} ; pour chaque cellule étirée vers le bas, noter son \texttt{rowspan}.
\item \textbf{Coder ligne par ligne}, de haut en bas, et dans chaque ligne de gauche à droite, en n'écrivant \textbf{que} les cellules qui \emph{commencent} dans cette ligne.
\item \textbf{Vérifier} : pour chaque ligne, la somme (nombre de cellules écrites + colonnes absorbées par les \texttt{colspan} de la ligne + colonnes occupées par les \texttt{rowspan} venus d'en haut) doit égaler le nombre total de colonnes.
\end{enumerate}
\end{methode}

Appliquons cette méthode à la figure ci-dessus (4 lignes, 3 colonnes) :

\begin{lstlisting}[language=HTML]
<table border="1" cellpadding="6">
  <tr>
    <th colspan="3">1 - Titre general</th>
  </tr>
  <tr>
    <td rowspan="2">2</td>
    <td>3</td>
    <td>4</td>
  </tr>
  <tr>
    <!-- la cellule 2 occupe deja la 1re colonne -->
    <td>5</td>
    <td>6</td>
  </tr>
  <tr>
    <td>7</td>
    <td>8</td>
    <td>9</td>
  </tr>
</table>
\end{lstlisting}

\begin{attention}[Erreur classique de comptage après un \texttt{colspan} ou un \texttt{rowspan}]
Après un \texttt{colspan="3"}, la ligne contient \textbf{moins} de balises \texttt{<td>} : une seule cellule en remplace trois. De même, sous une cellule en \texttt{rowspan="2"}, la ligne suivante « saute » la colonne occupée. Si tu écris quand même toutes les cellules, le navigateur décale tout le tableau et crée une colonne fantôme à droite. Compte toujours en \textbf{colonnes}, jamais en nombre de balises.
\end{attention}

\coursec{Les formulaires}

Dans la section précédente, nous avons appris à présenter des données sous forme de tableaux : l'information circulait dans un seul sens, du concepteur de la page vers le visiteur. Mais sur le Web réel, le visiteur n'est pas qu'un lecteur : il remplit des formulaires d'inscription à l'examen du Probatoire sur une plateforme en ligne, il saisit son numéro de téléphone pour recharger son compte mobile, il répond à un sondage. Comment une page web peut-elle \emph{recueillir} des informations auprès de l'utilisateur ? C'est exactement le rôle des \cle{formulaires} HTML, dernier grand mécanisme d'interaction que nous étudions cette année.

\courssub{Définition et rôle d'un formulaire}

Imagine le secrétariat de ton lycée au moment des inscriptions : on te remet une fiche papier comportant des cases à remplir (nom, date de naissance), des cases à cocher (sexe : M ou F), une liste de classes parmi lesquelles choisir, puis tu déposes la fiche remplie au secrétariat qui la traite. Un formulaire HTML fonctionne exactement pareil : la page joue le rôle de la fiche, les champs jouent le rôle des cases, et le bouton d'envoi joue le rôle du dépôt au secrétariat.

\begin{definition}[Formulaire]
Un \cle{formulaire} est une zone d'une page web permettant de \textbf{collecter des données saisies ou choisies par l'utilisateur} (texte, mot de passe, choix unique ou multiple, etc.) en vue de les transmettre pour traitement. En HTML, un formulaire est délimité par la balise \texttt{<form>} ... \texttt{</form>}, qui contient les différents \textbf{champs} (zones de saisie, boutons, listes) et les boutons d'envoi.
\end{definition}

\begin{definition}[La balise \texttt{<form>} et ses attributs]
La balise \texttt{<form>} admet deux attributs essentiels :
\begin{itemize}
\item \cle{action} : indique l'\textbf{URL de la page} vers laquelle les données saisies seront envoyées lorsque l'utilisateur valide le formulaire ;
\item \cle{method} : indique \textbf{comment} les données sont transmises. La valeur \texttt{get} place les données dans l'URL (visible, adaptée aux petites quantités de données non confidentielles) ; la valeur \texttt{post} les envoie dans le corps de la requête (invisible dans l'URL, adaptée aux données confidentielles comme un mot de passe).
\end{itemize}
Syntaxe générale : \texttt{<form action="page\_cible" method="get">} ou \texttt{method="post"}.
\end{definition}

\begin{attention}[Notion admise à ce niveau]
En Première TI, on ne programme pas encore le traitement des données côté serveur : ce sera l'objet de la classe de Terminale (PHP). Les attributs \texttt{action} et \texttt{method} sont donc \textbf{admis} : tu dois savoir les écrire et expliquer leur rôle, sans savoir encore construire la page de traitement.
\end{attention}

\courssub{Les champs de saisie : la balise \texttt{<input>}}

La balise \texttt{<input>} est une balise \textbf{orpheline} (sans balise fermante) dont le comportement dépend entièrement de son attribut \cle{type}. C'est le couteau suisse du formulaire.

\begin{propriete}[Attributs communs de \texttt{<input>}]
\begin{itemize}
\item \texttt{type} : nature du champ (\texttt{text}, \texttt{password}, \texttt{radio}, \texttt{checkbox}, \texttt{submit}, \texttt{reset}, ...) ;
\item \cle{name} : \textbf{nom du champ}, indispensable : c'est sous ce nom que la donnée sera transmise à la page cible ;
\item \texttt{placeholder} : texte grisé affiché dans le champ vide pour guider l'utilisateur (il disparaît dès la saisie) ;
\item \texttt{size} : largeur visible du champ, exprimée en nombre de caractères ;
\item \texttt{value} : valeur initiale du champ, ou libellé d'un bouton.
\end{itemize}
\end{propriete}

Les deux champs de saisie les plus simples sont :

\begin{lstlisting}[language=HTML]
<!-- Champ texte ordinaire : ce qui est tape reste visible -->
Nom : <input type="text" name="nom" placeholder="Ex : MBALLA" size="30">

<!-- Champ mot de passe : les caracteres sont masques par des points -->
Mot de passe : <input type="password" name="mdp" size="20">
\end{lstlisting}

La seule différence entre \texttt{text} et \texttt{password} est l'\textbf{affichage} : avec \texttt{password}, chaque caractère tapé est remplacé à l'écran par un point ou une étoile, pour qu'un voisin indiscret ne lise pas le mot de passe. Les données elles-mêmes sont transmises de la même façon.

\courssub{Boutons radio et cases à cocher}

Très souvent, on ne veut pas que l'utilisateur tape une réponse libre, mais qu'il \textbf{choisisse} parmi des propositions. Deux situations se présentent.

\textbf{Choix unique : les boutons radio.} Pour le sexe (M ou F), une seule réponse est possible. On utilise \texttt{<input type="radio">} et l'on \textbf{regroupe} les boutons en leur donnant \emph{le même attribut} \texttt{name} : le navigateur comprend alors qu'ils s'excluent mutuellement — cocher l'un décoche automatiquement l'autre. L'attribut \texttt{value} précise la valeur transmise pour le bouton choisi.

\begin{lstlisting}[language=HTML]
Sexe :
<input type="radio" name="sexe" value="M"> Masculin
<input type="radio" name="sexe" value="F"> Feminin
\end{lstlisting}

\begin{attention}[Le piège classique des boutons radio]
Si tu oublies de donner le \textbf{même} \texttt{name} à tous les boutons radio d'un groupe (par exemple \texttt{name="sexe1"} et \texttt{name="sexe2"}), le navigateur les considère comme indépendants : l'utilisateur pourra cocher \textbf{plusieurs} réponses, ce qui est absurde pour un choix unique. Vérifie toujours l'orthographe exacte du \texttt{name}, y compris les majuscules.
\end{attention}

\textbf{Choix multiples : les cases à cocher.} Pour les options choisies par un élève (Informatique, Sport, Musique...), plusieurs réponses sont possibles simultanément. On utilise \texttt{<input type="checkbox">} ; chaque case est indépendante et possède son propre \texttt{name}.

\begin{lstlisting}[language=HTML]
Options :
<input type="checkbox" name="info" value="oui"> Informatique
<input type="checkbox" name="sport" value="oui"> Sport
<input type="checkbox" name="musique" value="oui"> Musique
\end{lstlisting}

\begin{aretenir}[Radio ou case à cocher ?]
Choix \textbf{unique} parmi plusieurs propositions $\Rightarrow$ \texttt{radio} avec le \textbf{même} \texttt{name}. Choix \textbf{multiples} autorisés $\Rightarrow$ \texttt{checkbox} avec des \texttt{name} \textbf{différents}.
\end{aretenir}

\courssub{La liste déroulante : \texttt{<select>} et \texttt{<option>}}

Quand les propositions sont nombreuses (les 10 régions du Cameroun, les classes d'un lycée), aligner des boutons radio prendrait trop de place. On utilise alors une \cle{liste déroulante}, construite avec la balise \texttt{<select>} (qui porte le \texttt{name}) contenant une balise \texttt{<option>} par choix possible. L'attribut \cle{selected}, placé dans une \texttt{<option>}, désigne le choix présélectionné par défaut.

\begin{lstlisting}[language=HTML]
Classe :
<select name="classe">
  <option value="2nde">Seconde</option>
  <option value="1ereTI" selected>Premiere TI</option>
  <option value="TleTI">Terminale TI</option>
</select>
\end{lstlisting}

À l'affichage, seule l'option sélectionnée est visible ; un clic déroule la liste complète. Ici, « Première TI » apparaîtra choisie par défaut grâce à \texttt{selected}.

\courssub{Étiquettes \texttt{<label>} et zone de texte multiligne}

\begin{definition}[La balise \texttt{<label>}]
Une \cle{étiquette} \texttt{<label>} associe un texte descriptif à un champ. On la lie au champ grâce à son attribut \texttt{for}, qui doit reprendre la valeur de l'attribut \texttt{id} du champ. Avantage pratique : cliquer sur le texte de l'étiquette active le champ (ou coche la case), ce qui améliore le confort de l'utilisateur.
\end{definition}

\begin{lstlisting}[language=HTML]
<label for="nom">Nom du candidat :</label>
<input type="text" id="nom" name="nom" size="30">
\end{lstlisting}

Pour les réponses longues (adresse, motivation, commentaire), un champ \texttt{text} d'une seule ligne ne suffit pas : on utilise la zone de texte multiligne \cle{<textarea>}, dont on fixe les dimensions avec les attributs \texttt{rows} (nombre de lignes) et \texttt{cols} (largeur en caractères). Attention : contrairement à \texttt{<input>}, \texttt{<textarea>} possède une balise fermante.

\begin{lstlisting}[language=HTML]
<label for="motiv">Vos motivations :</label><br>
<textarea id="motiv" name="motivations" rows="4" cols="40"></textarea>
\end{lstlisting}

\courssub{Les boutons cliquables}

Un formulaire sans bouton est une fiche qu'on ne peut pas déposer. Trois boutons sont à connaître :

\begin{propriete}[Boutons d'un formulaire]
\begin{itemize}
\item \texttt{<input type="submit" value="Envoyer">} : \textbf{valide} le formulaire et transmet les données vers la page indiquée par l'attribut \texttt{action} du \texttt{<form>} ;
\item \texttt{<input type="reset" value="Annuler">} : \textbf{efface} toutes les saisies et ramène le formulaire à son état initial ;
\item \texttt{<button type="submit">Envoyer</button>} : variante à balise fermante, dont le libellé est le contenu de la balise (elle peut contenir du texte enrichi ou une image).
\end{itemize}
\end{propriete}

\begin{methode}[Construire un formulaire propre et lisible]
\begin{enumerate}
\item Ouvrir la balise \texttt{<form>} avec ses attributs \texttt{action} et \texttt{method}.
\item Pour chaque information à collecter, écrire \textbf{un label (ou un texte) + un champ par ligne}, en séparant les lignes par \texttt{<br>} ou en les plaçant dans des paragraphes.
\item Choisir le bon type de champ : \texttt{text}/\texttt{password} pour une saisie libre, \texttt{radio} pour un choix unique (même \texttt{name} pour tout le groupe !), \texttt{checkbox} pour des choix multiples, \texttt{select} pour une longue liste.
\item Donner à chaque champ un \texttt{name} explicite et unique (sauf groupe radio).
\item Terminer par les boutons \texttt{submit} et \texttt{reset}, puis fermer \texttt{</form>}.
\item Tester dans le navigateur : remplir, vérifier que les radios s'excluent, que le bouton Annuler efface tout.
\end{enumerate}
\end{methode}

\begin{attention}[Limite fondamentale du HTML seul]
En HTML seul, les données d'un formulaire ne sont \textbf{ni vérifiées} (on peut saisir un nom vide ou une date impossible) \textbf{ni enregistrées} (aucune base de données n'est interrogée). Le HTML ne fait que \emph{présenter} le formulaire et \emph{transmettre} les données. Le contrôle des saisies se fera en JavaScript (côté client) et leur traitement définitif (enregistrement, réponse personnalisée) exigera un \textbf{langage serveur} comme PHP, étudié en Terminale TI. Ne dis donc jamais qu'un formulaire HTML « enregistre » des informations : il les \emph{envoie}.
\end{attention}

\begin{exoresolu}[Corriger un formulaire défectueux]
Énoncé. Un élève de Première TI écrit le fragment suivant pour demander le sexe du visiteur, mais on constate qu'on peut cocher les deux réponses à la fois. De plus, rien ne se passe au clic sur « Envoyer ». Identifier les deux erreurs et corriger le code.
\begin{lstlisting}[language=HTML]
<form>
  Sexe :
  <input type="radio" name="sexe1" value="M"> Masculin
  <input type="radio" name="sexe2" value="F"> Feminin
  <input type="submit" value="Envoyer">
</form>
\end{lstlisting}
\tcblower
Solution détaillée.
\textbf{Erreur 1 :} les deux boutons radio portent des \texttt{name} différents (\texttt{sexe1} et \texttt{sexe2}). Le navigateur les traite donc comme deux groupes indépendants et autorise deux coches simultanées. Il faut le \textbf{même} \texttt{name} pour tout le groupe.
\textbf{Erreur 2 :} la balise \texttt{<form>} n'a pas d'attribut \texttt{action} : le navigateur ne sait pas vers quelle page envoyer les données. On ajoute \texttt{action} (et \texttt{method} par bonne pratique).
Code corrigé :
\begin{lstlisting}[language=HTML]
<form action="traitement.html" method="post">
  Sexe :
  <input type="radio" name="sexe" value="M"> Masculin
  <input type="radio" name="sexe" value="F"> Feminin
  <input type="submit" value="Envoyer">
</form>
\end{lstlisting}
Désormais, les deux boutons s'excluent mutuellement et le clic sur « Envoyer » transmet le couple \texttt{sexe=M} (ou \texttt{sexe=F}) vers \texttt{traitement.html}.
\end{exoresolu}

\begin{aretenir}[L'essentiel sur les formulaires]
\begin{itemize}
\item Un formulaire (\texttt{<form action="..." method="get|post">}) \textbf{collecte} des données saisies par l'utilisateur et les \textbf{transmet} à une page cible.
\item \texttt{<input>} change de rôle selon \texttt{type} : \texttt{text}, \texttt{password} (saisie masquée), \texttt{radio} (choix unique, même \texttt{name}), \texttt{checkbox} (choix multiples), \texttt{submit} (envoyer), \texttt{reset} (effacer).
\item Liste déroulante : \texttt{<select>} + \texttt{<option>}, avec \texttt{selected} pour le choix par défaut ; texte long : \texttt{<textarea rows cols>}.
\item \texttt{<label for="id">} relie un texte à son champ ; \texttt{name} nomme la donnée transmise.
\item HTML seul ne vérifie ni n'enregistre rien : le traitement relève d'un langage serveur (Terminale).
\end{itemize}
\end{aretenir}

\coursec{Organisation d'un site, balises de section et limites du HTML}

Dans la section précédente, nous avons appris à insérer des \cle{formulaires} dans une page web : champs de saisie, boutons radio, cases à cocher, listes déroulantes. Nous savons donc désormais construire des pages riches. Mais un vrai site web, comme celui de ton lycée ou d'une boutique en ligne, ne tient pas dans un seul fichier : il contient des dizaines de pages, des centaines d'images, des fichiers de style. Comment ranger tout cela proprement ? Comment regrouper les zones d'une page (en-tête, menu, contenu, pied de page) ? Et surtout : jusqu'où le HTML peut-il aller seul ? C'est l'objet de cette dernière section.

\courssub{Organiser les dossiers d'un site web}

\textbf{Pourquoi organiser ?}\par
Imagine un élève qui range tous ses cahiers, ses stylos, ses brouillons et ses manuels en vrac dans un seul sac : le jour de l'interrogation, il ne retrouve rien. C'est exactement ce qui arrive à un développeur qui place tous ses fichiers (pages HTML, images, feuilles de style) dans un seul dossier. Dès que le site dépasse cinq ou six fichiers, il devient introuvable et impossible à maintenir. La solution est une \cle{arborescence} : une organisation hiérarchique en dossiers et sous-dossiers.

\begin{definition}[Dossier racine et index.html]
Le \cle{dossier racine} est le dossier principal qui contient tous les fichiers et sous-dossiers du site. Le fichier \texttt{index.html}, placé dans la racine, est la \cle{page d'accueil} : c'est le fichier que le serveur web affiche automatiquement lorsqu'un visiteur tape l'adresse du site sans préciser de page.
\end{definition}

\begin{methode}[Organiser les dossiers d'un site web avant de coder]
Avant d'écrire la moindre ligne de HTML, suis ces étapes :
\begin{enumerate}
  \item Crée le \textbf{dossier racine} du site, par exemple \texttt{monsite/}.
  \item À l'intérieur, crée les sous-dossiers : \texttt{images/} pour les photos et logos, \texttt{css/} pour les feuilles de style, \texttt{pages/} pour les pages secondaires.
  \item Place le fichier \texttt{index.html} (page d'accueil) directement dans la racine.
  \item Place chaque fichier dans le dossier qui correspond à son rôle : une photo dans \texttt{images/}, une page secondaire dans \texttt{pages/}.
  \item Nomme les fichiers en \textbf{minuscules, sans espaces ni accents} : \texttt{photo\_classe.jpg} et non \texttt{Photo de la classe.JPG}.
\end{enumerate}
\end{methode}

\courssub{Les chemins relatifs dans une arborescence}

Une fois les fichiers rangés dans des dossiers différents, il faut pouvoir les désigner les uns depuis les autres. On utilise pour cela des \cle{chemins relatifs}, c'est-à-dire des adresses exprimées \emph{par rapport au fichier courant}.

\begin{definition}[Chemin relatif]
Un \cle{chemin relatif} indique la position d'un fichier par rapport au dossier contenant la page en cours. On utilise :
\begin{itemize}
  \item \texttt{nomfichier} pour un fichier du \textbf{dossier courant} ;
  \item \texttt{dossier/nomfichier} pour descendre dans un \textbf{sous-dossier} ;
  \item \texttt{../nomfichier} pour remonter vers le \textbf{dossier parent} (\texttt{../} signifie « dossier au-dessus »).
\end{itemize}
\end{definition}

\begin{exemplebox}[Chemins relatifs en pratique]
Avec l'arborescence de la figure précédente :
\begin{itemize}
  \item Depuis \texttt{index.html}, afficher le logo : \texttt{images/logo.png} (on descend dans \texttt{images/}).
  \item Depuis \texttt{pages/contact.html}, afficher le logo : \texttt{../images/logo.png} (on remonte à la racine, puis on descend dans \texttt{images/}).
  \item Depuis \texttt{pages/contact.html}, revenir à l'accueil : \texttt{../index.html}.
\end{itemize}
\begin{lstlisting}[language=HTML]
<!-- Dans pages/contact.html : retour vers l'accueil -->
<a href="../index.html" title="Retour a l'accueil">Accueil</a>

<!-- Dans pages/contact.html : image situee dans images/ -->
<img src="../images/logo.png" alt="Logo du lycee" width="120">
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Le piège du dossier parent oublié]
L'erreur la plus fréquente : une image s'affiche bien depuis \texttt{index.html} mais devient « cassée » (icône d'image brisée) dans une page du dossier \texttt{pages/}. La cause est presque toujours l'oubli du \texttt{../}. Vérifie toujours : « où suis-je ? où est le fichier visé ? ». Autre piège : les espaces et accents dans les noms de fichiers, qui cassent les liens sur certains serveurs.
\end{attention}

\courssub{Les balises de section : DIV, SECTION et SPAN}

Regarde une page de journal : il y a un titre principal, des colonnes, un encadré publicité, un pied de page. Une page web est organisée de la même façon en \textbf{zones} : en-tête, menu, contenu principal, pied de page. Pour délimiter ces zones, le HTML propose des \cle{balises de section}.

\begin{definition}[Balises de section]
\begin{itemize}
  \item \texttt{<DIV>} : \cle{conteneur de type bloc} générique. Il regroupe plusieurs éléments (titres, paragraphes, images) dans une zone rectangulaire, sans signification particulière. C'est la balise de structuration la plus utilisée.
  \item \texttt{<SECTION>} : conteneur de type bloc qui regroupe des éléments formant un \textbf{ensemble thématique} cohérent (un chapitre, une rubrique « Actualités », une fiche produit). Contrairement à \texttt{<DIV>}, elle a une signification sémantique.
  \item \texttt{<SPAN>} : \cle{conteneur en ligne}. Il encadre un petit morceau de contenu \emph{à l'intérieur} d'un texte (un mot, une phrase) sans provoquer de retour à la ligne, par exemple pour colorer un seul mot.
\end{itemize}
\end{definition}

\textbf{Élément bloc ou élément en ligne ?}\par
C'est une distinction fondamentale en HTML. Un \cle{élément bloc} (\texttt{<div>}, \texttt{<p>}, \texttt{<h1>}, \texttt{<section>}, \texttt{<table>}) occupe toute la largeur disponible et provoque un retour à la ligne avant et après lui : il forme un « bloc » empilé verticalement. Un \cle{élément en ligne} (\texttt{<span>}, \texttt{<a>}, \texttt{<img>}, \texttt{<b>}) s'insère dans le flux du texte, comme un mot dans une phrase, sans retour à la ligne.

\begin{exemplebox}[Structurer une page avec DIV, SECTION et SPAN]
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <title>Site du Lycee de Bafoussam</title>
</head>
<body>
  <!-- En-tete du site : bloc generique -->
  <div id="entete">
    <h1>Lycee de Bafoussam</h1>
    <p>Bienvenue sur le site officiel de notre etablissement.</p>
  </div>

  <!-- Rubrique thematique : balise SECTION -->
  <section id="actualites">
    <h2>Actualites</h2>
    <p>La rentree scolaire aura lieu le
       <span class="important">8 septembre</span>.</p>
  </section>

  <!-- Pied de page -->
  <div id="pied">
    <p>Contact : lycee.bafoussam@education.cm</p>
  </div>
</body>
</html>
\end{lstlisting}
Ici, \texttt{<span class="important">} encadre uniquement la date, à l'intérieur de la phrase : c'est un conteneur en ligne. Les \texttt{<div>} et \texttt{<section>} découpent la page en grandes zones.
\end{exemplebox}

\begin{savaistu}[HTML5 et les balises sémantiques]
HTML5 a introduit des balises de section plus précises : \texttt{<header>} (en-tête), \texttt{<footer>} (pied de page), \texttt{<nav>} (navigation), \texttt{<main>} (contenu principal), \texttt{<article>} (contenu autonome), \texttt{<aside>} (contenu annexe). Elles remplacent avantageusement \texttt{<div>} quand leur sens correspond, car elles améliorent le référencement (SEO) et l'accessibilité. Le programme de Première TI exige la maîtrise de \texttt{<DIV>}, \texttt{<SECTION>} et \texttt{<SPAN>} ; ces nouvelles balises seront approfondies en Terminale.
\end{savaistu}

\courssub{Repérer les sections : les attributs id et class}

Pour identifier les zones d'une page (afin de les styliser en CSS ou de les manipuler en JavaScript), on utilise deux attributs universels, valables sur presque toutes les balises.

\begin{definition}[Attributs id et class]
\begin{itemize}
  \item L'attribut \cle{id} donne un \textbf{identifiant unique} à un élément : deux éléments d'une même page ne peuvent jamais porter le même \texttt{id}. Exemple : \texttt{<div id="entete">}.
  \item L'attribut \cle{class} attribue une \textbf{étiquette réutilisable} : plusieurs éléments peuvent partager la même classe, et un élément peut avoir plusieurs classes (séparées par des espaces). Exemple : \texttt{<p class="important">} ou \texttt{<div class="carte produit">}.
\end{itemize}
\end{definition}

\begin{attention}[id unique, class réutilisable]
Écrire deux fois \texttt{id="menu"} dans la même page est une \textbf{erreur} : le navigateur ne saura plus quel élément viser, et le JavaScript ou le CSS associé se comportera de façon imprévisible. Règle simple : un \texttt{id} est comme un numéro de CNI (unique), une \texttt{class} est comme un uniforme (porté par plusieurs élèves).
\end{attention}

\hline
\rowcolor{popblueL} \textbf{Critère} & \textbf{id} & \textbf{class} \\
\hline
Unicité & Unique dans toute la page & Réutilisable à volonté \\
\hline

\courssub{Les limites du HTML}

Nous avons vu que le HTML permet de structurer le contenu : titres, paragraphes, listes, liens, médias, tableaux, formulaires, sections. Mais essaie de réaliser avec le seul HTML un site aux couleurs de ton lycée, avec un menu animé et un calcul automatique de moyenne : tu n'y arriveras pas. Ce n'est pas un oubli des concepteurs, c'est un choix.

\begin{propriete}[Limites du HTML (admise)]
Le HTML est un langage de \textbf{description de contenu}, pas un langage de programmation. À lui seul, il ne permet :
\begin{itemize}
  \item \textbf{ni mise en forme évoluée} (couleurs, polices, mise en page précise, animations visuelles) : c'est le rôle du \cle{CSS} ;
  \item \textbf{ni interactivité} (réagir à un clic, vérifier une saisie, animer un menu, calculer dans la page) : c'est le rôle du \cle{JavaScript} ;
  \item \textbf{ni traitement ni stockage de données} (enregistrer un client, gérer des comptes, interroger une base de données) : c'est le rôle des \textbf{langages serveur} (comme PHP) associés à une \textbf{base de données}.
\end{itemize}
\end{propriete}

\courssub{Site statique et site dynamique : bilan}

\begin{definition}[Site statique et site dynamique]
Un \cle{site statique} est constitué de pages HTML écrites une fois pour toutes : \textbf{tous les visiteurs voient exactement le même contenu}, qui ne change que si le webmestre modifie les fichiers. Un \cle{site dynamique} génère ses pages à la demande, à partir d'une base de données : le contenu s'adapte au visiteur (son compte, son panier, l'heure, ses recherches).
\end{definition}

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}
\hline
\rowcolor{popblueL} \textbf{Critère} & \textbf{Site statique} & \textbf{Site dynamique} \\
\hline
Technologies & HTML + CSS (+ JavaScript côté client) & HTML + CSS + JS + langage serveur + base de données \\
\hline
Contenu & Identique pour tous, figé & Personnalisé, généré à la demande \\
\hline
Mise à jour & Modification manuelle des fichiers & Via une interface d'administration \\
\hline
Exemples & Site vitrine d'un lycée, CV en ligne & Jumia, Facebook, site de notes en ligne \\
\hline
\end{tabularx}
\end{center}

\begin{savaistu}[Les grands sites sont dynamiques]
Les sites que tu utilises chaque jour — Jumia, Facebook, WhatsApp Web, les plateformes de paiement mobile — sont des sites \textbf{dynamiques} : quand tu ouvres Facebook, la page affiche \emph{ton} fil d'actualité, différent de celui de ton voisin. Un site statique, lui, affiche le même contenu à tous les visiteurs, comme un panneau d'affichage. C'est parfait pour présenter un lycée, une entreprise ou un événement, et c'est exactement ce que tu sais maintenant construire !
\end{savaistu}

\begin{exoresolu}[Organiser le site d'une bibliothèque scolaire]
Énoncé. La bibliothèque du lycée veut un site statique de trois pages : un accueil, une page « Catalogue » et une page « Contact ». Les images (logo, photo de la salle) et la feuille de style doivent être rangées séparément. Propose une arborescence, puis écris le code du lien et de l'image à placer dans la page \texttt{catalogue.html} pour revenir à l'accueil et afficher le logo.
\tcblower
Solution détaillée.
\textbf{1. Arborescence.} On crée la racine \texttt{bibliotheque/} contenant \texttt{index.html} et trois sous-dossiers : \texttt{images/} (logo.png, salle.jpg), \texttt{pages/} (catalogue.html, contact.html), \texttt{css/} (style.css).

\textbf{2. Chemins relatifs.} Le fichier \texttt{catalogue.html} se trouve dans \texttt{pages/}. Pour atteindre la racine, on remonte avec \texttt{../} ; pour atteindre le logo, on remonte puis on descend dans \texttt{images/} :
\begin{lstlisting}[language=HTML]
<!-- Dans pages/catalogue.html -->
<a href="../index.html" title="Retour a l'accueil">Accueil</a>
<img src="../images/logo.png" alt="Logo de la bibliotheque" width="100">
\end{lstlisting}
\textbf{3. Vérification.} Sans le \texttt{../}, le navigateur chercherait \texttt{pages/index.html} et \texttt{pages/images/logo.png}, qui n'existent pas : lien mort et image cassée.
\end{exoresolu}

\begin{experience}[TP : construire l'arborescence d'un mini-site]
\textbf{Objectif :} créer l'arborescence complète d'un site statique et vérifier les chemins relatifs.
\textbf{Matériel :} un PC avec un éditeur de texte (Bloc-notes, Notepad++) et un navigateur.
\textbf{Manipulation :}
\begin{enumerate}
  \item Crée le dossier \texttt{monsite/} puis les sous-dossiers \texttt{images/}, \texttt{pages/} et \texttt{css/}.
  \item Place une image quelconque dans \texttt{images/} sous le nom \texttt{photo.jpg}.
  \item Crée \texttt{index.html} à la racine avec un lien vers \texttt{pages/page2.html} et l'image \texttt{images/photo.jpg}.
  \item Crée \texttt{pages/page2.html} contenant un lien de retour \texttt{../index.html} et l'image \texttt{../images/photo.jpg}.
  \item Ouvre \texttt{index.html} dans le navigateur, clique le lien, vérifie que l'image s'affiche sur les deux pages.
\end{enumerate}
\textbf{Observations :} si l'image n'apparaît pas sur la page 2, c'est que le \texttt{../} manque. Corrige et recharge (touche F5).
\textbf{Interprétation :} un chemin relatif se lit toujours \emph{depuis le fichier qui le contient}, jamais depuis la racine.
\end{experience}

\begin{exercice}[À toi de jouer]
\begin{enumerate}
  \item Un site contient \texttt{index.html} à la racine et \texttt{pages/infos.html}. Quel chemin relatif faut-il écrire dans \texttt{infos.html} pour afficher \texttt{css/style.css} ?
  \item Pourquoi est-il interdit d'avoir deux \texttt{<div id="menu">} dans la même page ?
  \item Cite les trois limites du HTML et le langage qui compense chacune d'elles.
  \item Le site des résultats du Probatoire, où chaque candidat consulte \emph{sa} note, est-il statique ou dynamique ? Justifie.
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice]
\begin{enumerate}
  \item \texttt{../css/style.css} : on remonte de \texttt{pages/} vers la racine avec \texttt{../}, puis on descend dans \texttt{css/}.
  \item Un \texttt{id} doit être unique dans une page : avec deux identifiants identiques, le navigateur ne sait plus quel élément cibler, et le CSS ou le JavaScript associé devient imprévisible. Pour repérer plusieurs éléments semblables, on utilise \texttt{class}.
  \item Pas de mise en forme évoluée $\rightarrow$ CSS ; pas d'interactivité $\rightarrow$ JavaScript ; pas de traitement ni stockage de données $\rightarrow$ langages serveur (PHP) et bases de données.
  \item C'est un site \textbf{dynamique} : le contenu affiché dépend du candidat connecté et provient d'une base de données. Un site statique afficherait la même page à tous.
\end{enumerate}
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
  \item Un site s'organise en \textbf{arborescence} : racine contenant \texttt{index.html} et des sous-dossiers (\texttt{images/}, \texttt{css/}, \texttt{pages/}).
  \item Les \textbf{chemins relatifs} désignent un fichier depuis la page courante : \texttt{dossier/fichier} pour descendre, \texttt{../} pour remonter au dossier parent.
  \item \texttt{<DIV>} et \texttt{<SECTION>} sont des conteneurs \textbf{bloc} (zones de page) ; \texttt{<SPAN>} est un conteneur \textbf{en ligne} (morceau de texte).
  \item \texttt{id} est \textbf{unique} dans la page ; \texttt{class} est \textbf{réutilisable}.
  \item Le HTML seul ne fait que structurer : la forme revient au CSS, l'interactivité au JavaScript, le traitement des données aux langages serveur et aux bases de données. Un site \textbf{statique} affiche le même contenu à tous ; un site \textbf{dynamique} le génère à la demande.
\end{itemize}
\end{aretenir}

Tu sais désormais construire un site statique complet et bien organisé. La prochaine étape de ton parcours ? Donner du style à tes pages avec le CSS, puis les faire réagir avec JavaScript : c'est la séparation fond / forme / comportement, la règle d'or du web moderne.

\coursec{Leçon N05 : Programmation Web statique en HTML}

\courssub{Site web, HTML et structure d'une page}

\begin{definition}[Site web et page web]
Un \cle{site web} est un ensemble de fichiers (pages HTML, images, styles, scripts) liés entre eux par des hyperliens, hébergés sur un serveur web et accessibles via une \cle{URL} (Uniform Resource Locator). Une \cle{page web} est un document unique, rédigé en \cle{HTML} (HyperText Markup Language), que le navigateur interprète pour l'afficher à l'écran.
\end{definition}

\begin{propriete}[Structure minimale d'un document HTML5]
Tout document HTML5 valide respecte la structure suivante~:
\begin{lstlisting}
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="utf-8">
    <title>Titre de la page</title>
</head>
<body>
    <!-- Contenu visible de la page -->
</body>
</html>
\end{lstlisting}
\begin{itemize}
\item \texttt{<!DOCTYPE html>}~: déclare la version HTML5 (obligatoire en première ligne).
\item \texttt{<html lang="fr">}~: racine du document, langue principale française.
\item \texttt{<head>}~: métadonnées (titre, encodage, styles, scripts) non affichées directement.
\item \texttt{<meta charset="utf-8">}~: \textbf{indispensable} pour afficher correctement les caractères accentués (é, è, à, ç, ô…) et spéciaux. Sans elle, le navigateur peut utiliser un encodage par défaut (ISO-8859-1) et afficher des caractères illisibles (�).
\item \texttt{<title>}~: titre affiché dans l'onglet du navigateur et les favoris.
\item \texttt{<body>}~: contient tout le contenu visible (textes, images, tableaux, formulaires…).
\end{itemize}
\end{propriete}

\begin{methode}[Créer une page HTML valide]
\begin{enumerate}
\item Ouvrir un éditeur de texte simple (Notepad++, VS Code, Gedit…).
\item Écrire la structure minimale ci-dessus.
\item Enregistrer le fichier avec l'extension \texttt{.html} (ex. \texttt{index.html}), \textbf{sans accents, sans espaces, en minuscules} (ex. \texttt{page\_accueil.html}).
\item Ouvrir le fichier dans un navigateur (double-clic ou \texttt{Fichier > Ouvrir}).
\end{enumerate}
\end{methode}

\courssub{Listes, hyperliens et URL}

\begin{definition}[URL (Uniform Resource Locator)]
Une \cle{URL} est l'adresse unique d'une ressource sur le web. Elle se compose~: \texttt{protocole://domaine/chemin/fichier?paramètres\#ancre}.
En travail local, on utilise des \cle{chemins relatifs}~:
\begin{itemize}
\item \texttt{fichier.html}~: même dossier.
\item \texttt{dossier/fichier.html}~: descendre dans un sous-dossier.
\item \texttt{../fichier.html}~: remonter d'un niveau (dossier parent).
\end{itemize}
\end{definition}

\begin{propriete}[Hyperlien -- Balise \texttt{<a>}]
La balise \texttt{<a>} (ancre) crée un lien hypertexte.
\begin{lstlisting}
<a href="URL" title="Infobulle au survol" target="_blank">Texte ou image cliquable</a>
\end{lstlisting}
\begin{itemize}
\item \texttt{href}~: destination (URL absolue \texttt{https://...} ou relative \texttt{pages/contact.html}).
\item \texttt{title}~: texte de l'\cle{infobulle} affichée au survol de la souris (accessibilité, UX).
\item \texttt{target="\_blank"}~: ouvre le lien dans un nouvel onglet (optionnel).
\end{itemize}
\end{propriete}

\begin{propriete}[Listes -- \texttt{<ul>}, \texttt{<ol>}, \texttt{<li>}]
\begin{itemize}
\item \texttt{<ul>} (unordered list)~: liste à puces (ordre non important).
\item \texttt{<ol>} (ordered list)~: liste numérotée (ordre important).
\item \texttt{<li>} (list item) : chaque élément.
\item \textbf{Imbrication}~: une liste complète (\texttt{<ul>} ou \texttt{<ol>}) se place \emph{à l'intérieur} d'un \texttt{<li>} de la liste parente.
\end{itemize}
\begin{lstlisting}
<ul>
    <li>Série Scientifique
        <ul>
            <li>C</li>
            <li>D</li>
        </ul>
    </li>
    <li>Série Technique
        <ul><li>TI</li></ul>
    </li>
</ul>
\end{lstlisting}
\end{propriete}

\courssub{Insertion de médias : images, sons, vidéos}

\begin{propriete}[Image -- Balise \texttt{<img>} (balise orpheline / auto-fermante)]
\begin{lstlisting}
<img src="chemin/vers/image.png" alt="Description alternative" width="300" height="200">
\end{lstlisting}
\begin{itemize}
\item \texttt{src} (source)~: chemin relatif ou absolu vers le fichier image (PNG, JPG, GIF, SVG, WebP).
\item \texttt{alt} (alternative)~: \textbf{obligatoire} pour l'accessibilité (lecteurs d'écran) et le référencement ; affiché si l'image ne charge pas.
\item \texttt{width}, \texttt{height}~: dimensions en pixels (réserve l'espace, évite le « saut » de mise en page).
\end{itemize}
\end{propriete}

\begin{propriete}[Image cliquable]
On imbrique la balise \texttt{<img>} \emph{à l'intérieur} de la balise \texttt{<a>}~:
\begin{lstlisting}
<a href="index.html" title="Retour à l'accueil">
    <img src="images/logo.png" alt="Logo du lycée" width="120" height="120">
</a>
\end{lstlisting}
\end{propriete}

\begin{propriete}[Son et Vidéo -- Balises \texttt{<audio>} et \texttt{<video>} (HTML5)]
Ces balises permettent l'insertion native sans plugin externe (Flash obsolète).
\begin{lstlisting}
<!-- Audio -->
<audio controls>
    <source src="media/son.mp3" type="audio/mpeg">
    <source src="media/son.ogg" type="audio/ogg">
    Votre navigateur ne supporte pas l'audio HTML5.
</audio>

<!-- Vidéo -->
<video controls width="640" height="360" poster="images/vignette.jpg">
    <source src="media/video.mp4" type="video/mp4">
    <source src="media/video.webm" type="video/webm">
    Votre navigateur ne supporte pas la vidéo HTML5.
</video>
\end{lstlisting}
\begin{itemize}
\item \texttt{controls}~: affiche les boutons lecture/pause, volume, barre de progression.
\item \texttt{<source>}~: permet de proposer plusieurs formats (compatibilité navigateurs).
\item \texttt{type}~: type MIME (ex. \texttt{video/mp4}, \texttt{audio/mpeg}).
\item \texttt{poster} (vidéo)~: image d'attente avant lecture.
\end{itemize}
\end{propriete}

\courssub{Les tableaux en HTML}

\begin{attention}[Attributs de présentation vs CSS]
Le programme officiel impose la connaissance des attributs \texttt{border}, \texttt{width}, \texttt{height}, \texttt{align}, \texttt{cellpadding}, \texttt{cellspacing} sur \texttt{<table>}. \textbf{Notez que ces attributs sont obsolètes (dépréciés) en HTML5} : le style (bordures, espacement, alignement, largeur) se gère normalement en CSS. Pour le Probatoire, vous devez savoir les utiliser en HTML pur.
\end{attention}

\begin{propriete}[Structure de base d'un tableau]
\begin{lstlisting}
<table border="1" width="60%" align="center" cellpadding="5" cellspacing="0" id="tab-resultats">
    <caption>Titre du tableau (optionnel)</caption>
    <tr>          <!-- Table Row : ligne -->
        <th>En-tête 1</th>  <!-- Table Header : cellule d'en-tête (gras, centré) -->
        <th>En-tête 2</th>
    </tr>
    <tr>
        <td>Donnée 1</td>   <!-- Table Data : cellule standard -->
        <td>Donnée 2</td>
    </tr>
</table>
\end{lstlisting}
\begin{itemize}
\item \texttt{border="1"}~: épaisseur de la bordure en pixels.
\item \texttt{width="60\%"}~: largeur relative à la fenêtre ou au conteneur parent.
\item \texttt{align="center"}~: centre le tableau horizontalement (\texttt{left}, \texttt{right} possibles).
\item \texttt{cellpadding="5"}~: espace \emph{interne} entre le bord de la cellule et son contenu (en pixels).
\item \texttt{cellspacing="0"}~: espace \emph{externe} entre les cellules (bordures collées si 0).
\item \texttt{id}~: identifiant unique pour cibler le tableau en CSS/JS.
\end{itemize}
\end{propriete}

\begin{propriete}[Fusion de cellules -- \texttt{colspan} et \texttt{rowspan}]
\begin{itemize}
\item \texttt{colspan="n"}~: fusionne \texttt{n} cellules \emph{horizontalement} (sur une même ligne).
\item \texttt{rowspan="n"}~: fusionne \texttt{n} cellules \emph{verticalement} (sur une même colonne).
\end{itemize}
\textbf{Règle d'or}~: une cellule fusionnée \emph{disparaît} des lignes/colonnes suivantes. Il faut \textbf{retirer} les balises \texttt{<td>} ou \texttt{<th>} correspondantes dans le code des lignes concernées.
\end{propriete}

\begin{exemplebox}[Tableau avec fusions (extrait de l'activité)]
Ligne de titre sur 3 colonnes (\texttt{colspan="3"}), cellule « 2024 » sur 3 lignes (\texttt{rowspan="3"}).
\begin{lstlisting}[language=HTML]
<table border="1" width="60%" align="center" cellpadding="5" cellspacing="0">
    <tr>
        <th colspan="3">Résultats du Probatoire 2024</th>
    </tr>
    <tr>
        <th>Année</th><th>Série</th><th>Taux de réussite</th>
    </tr>
    <tr>
        <td rowspan="3">2024</td><td>C</td><td>78 %</td>
    </tr>
    <tr>
        <td>D</td><td>71 %</td>
    </tr>
    <tr>
        <td>TI</td><td>85 %</td>
    </tr>
</table>
\end{lstlisting}
\end{exemplebox}

\courssub{Les formulaires}

\begin{definition}[Formulaire HTML]
Un \cle{formulaire} (\texttt{<form>}) est une zone de la page permettant à l'utilisateur de saisir des données pour les envoyer à un serveur (traitement côté serveur : PHP, Python, Node.js… vu en Terminale). En HTML statique, le formulaire s'affiche et se remplit, mais l'envoi (\texttt{submit}) ne produit aucun traitement visible sans script serveur.
\end{definition}

\begin{propriete}[Balise \texttt{<form>} et attributs principaux]
\begin{lstlisting}
<form action="traitement.php" method="post">
    <!-- Contrôles de saisie -->
</form>
\end{lstlisting}
\begin{itemize}
\item \texttt{action}~: URL du script serveur qui traitera les données (ex. \texttt{inscription.php}, \texttt{mailto:email@domaine.com} pour test).
\item \texttt{method}~: \texttt{get} (données dans l'URL, visible, limité) ou \texttt{post} (données dans le corps HTTP, invisible, sans limite de taille, \textbf{recommandé} pour les mots de passe et formulaires longs).
\end{itemize}
\end{propriete}

\begin{propriete}[Contrôles de saisie courants -- \texttt{<input>}, \texttt{<select>}, \texttt{<textarea>}]
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}
\hline
\textbf{Type / Balise} & \textbf{Code exemple} & \textbf{Rôle / Attributs clés} \\ \hline
\texttt{<input type="text">} & \texttt{<input type="text" name="nom" id="nom" size="30" placeholder="Votre nom">} & Champ texte une ligne. \texttt{name} (clé envoyée au serveur), \texttt{id} (lien \texttt{<label>}), \texttt{placeholder} (indice). \\ \hline
\texttt{<input type="date">} & \texttt{<input type="date" name="naissance">} & Sélecteur de date natif (calendrier). Format envoyé : \texttt{AAAA-MM-JJ}. \\ \hline
\texttt{<input type="radio">} & \texttt{<input type="radio" name="sexe" value="M" id="m"> <label for="m">Masculin</label>} & Bouton radio : \textbf{choix unique} dans un groupe. \textbf{Même \texttt{name} pour tous les boutons du groupe}. \texttt{value} = valeur envoyée. \\ \hline
\texttt{<input type="checkbox">} & \texttt{<input type="checkbox" name="club" value="info" id="club"> <label for="club">Club info</label>} & Case à cocher : \textbf{choix multiple} (0, 1 ou plusieurs). \texttt{name} \textbf{différent} pour chaque case. \\ \hline
\texttt{<select> + <option>} & \texttt{<select name="serie" id="serie"> <option value="C">C</option> <option value="TI" selected>TI</option> </select>} & Liste déroulante. \texttt{selected} = choix par défaut. \texttt{multiple} autorise plusieurs choix (avec \texttt{Ctrl}). \\ \hline
\texttt{<textarea>} & \texttt{<textarea name="msg" rows="5" cols="40"></textarea>} & Zone de texte multi-lignes. \\ \hline
\texttt{<input type="submit">} & \texttt{<input type="submit" value="Envoyer">} & Bouton d'envoi du formulaire vers \texttt{action}. \\ \hline
\texttt{<input type="reset">} & \texttt{<input type="reset" value="Effacer">} & Bouton de remise à zéro des champs. \\ \hline
\end{tabularx}
\end{center}
\end{propriete}

\begin{methode}[Bonnes pratiques d'accessibilité pour les formulaires]
\begin{enumerate}
\item Associer \textbf{chaque} champ à un \texttt{<label>} via \texttt{for="id\_du\_champ"} (clic sur le label = focus sur le champ).
\item Regrouper les champs logiquement avec \texttt{<fieldset>} et \texttt{<legend>} (ex. « Coordonnées », « Choix de série »).
\item Utiliser \texttt{required} sur les champs obligatoires (validation HTML5 navigateur).
\item Prévoir un \texttt{name} explicite pour chaque contrôle (clé côté serveur).
\end{enumerate}
\end{methode}

\courssub{Organisation d'un site, balises de section et limites du HTML}

\begin{methode}[Organiser l'arborescence d'un site web statique]
\begin{enumerate}
\item Créer un dossier racine (ex. \texttt{site\_lycee\_\_}).
\item Placer \texttt{index.html} (page d'accueil obligatoire) à la racine.
\item Créer des sous-dossiers thématiques~: \texttt{images/}, \texttt{pages/}, \texttt{styles/} (pour CSS plus tard), \texttt{scripts/} (pour JS plus tard), \texttt{media/}.
\item \textbf{Nommage strict}~: minuscules, pas d'espaces, pas d'accents, tirets bas \texttt{\_} ou tirets \texttt{-} seulement (ex. \texttt{photo\_classe.jpg}, \texttt{mentions-legales.html}).
\item Utiliser des chemins relatifs dans tous les liens (\texttt{href}, \texttt{src}).
\end{enumerate}
\end{methode}

\begin{propriete}[Balises de structure sémantique (HTML5)]
Ces balises n'ont pas d'affectation visuelle par défaut mais structurent le document pour le référencement (SEO), l'accessibilité et la maintenance.
\begin{itemize}
\item \texttt{<div>}~: conteneur \textbf{bloc} générique (pas de sens sémantique). Utilisé pour le layout CSS.
\item \texttt{<span>}~: conteneur \textbf{en ligne} (inline) générique. Pour styliser une portion de texte.
\item \texttt{<header>}~: en-tête de page ou de section (logo, titre, navigation principale).
\item \texttt{<nav>}~: zone de navigation principale (menus).
\item \texttt{<main>}~: contenu principal unique de la page.
\item \texttt{<section>}~: section thématique du contenu (généralement avec un titre \texttt{<h1>}-\texttt{<h6>}).
\item \texttt{<article>}~: contenu autonome, syndiquable (article de blog, fiche produit).
\item \texttt{<aside>}~: contenu annexe (barre latérale, publicité, liens connexes).
\item \texttt{<footer>}~: pied de page (copyright, mentions légales, contacts).
\end{itemize}
\textbf{Au programme de Première TI}~: \texttt{<div>}, \texttt{<section>}, \texttt{<span>} sont explicitement demandés. L'usage de \texttt{<header>}, \texttt{<nav>}, \texttt{<footer>} est une bonne pratique professionnelle fortement encouragée.
\end{propriete}

\begin{aretenir}[Limites du HTML (statique)]
\begin{itemize}
\item \textbf{Pas de traitement de données}~: un formulaire HTML seul ne peut pas enregistrer en base, envoyer un email, calculer une moyenne. Il faut un langage côté serveur (PHP, Python, Node.js) ou client (JavaScript) pour traiter l'événement \texttt{submit}.
\item \textbf{Pas de mise en page avancée}~: HTML décrit la structure, pas l'apparence (couleurs, polices, grille responsive, animations). C'est le rôle du \textbf{CSS} (leçon suivante).
\item \textbf{Pas d'interactivité dynamique}~: pas de modification du DOM sans rechargement, pas de validation instantanée, pas de carrousel, pas de carte interactive. C'est le rôle du \textbf{JavaScript} (leçon suivante).
\item \textbf{Contenu dupliqué}~: le menu, le pied de page, l'en-tête sont copiés-collés dans chaque page. Maintenance difficile. Les \emph{includes} côté serveur (PHP \texttt{include}) ou les \emph{components} (JS frameworks) résolvent cela en Terminale.
\end{itemize}
\end{aretenir}

\courssub{Activité d'intégration guidée : Mini-site du Lycée Bilingue de Nkol-Eton}

\begin{experience}[Réalisation d'un site vitrine statique (3 pages)]
\textbf{Durée estimée~:} 4 h (2 séances de 2 h). \textbf{Matériel~:} Postes de travail (salle multimédia), navigateur (Firefox/Chrome), éditeur de code (VS Code / Notepad++), image \texttt{logo.png} fournie.

\textbf{Objectifs~:} Mobiliser l'ensemble des savoir-faire de la leçon dans un projet concret~: arborescence, structure HTML5, encodage, liens relatifs + infobulles, image cliquable, tableau avec attributs et fusions, listes imbriquées, balises de section, formulaire complet, test navigateur.

\textbf{Situation~:}
Le \textbf{Lycée Bilingue de Nkol-Eton} (région du Centre) prépare la rentrée. Le proviseur, M. Essomba, commande un site vitrine de 3 pages pour informer parents et nouveaux élèves. Chaque binôme de Première TI livre le site complet, testé, et présente son arborescence.

\textbf{Données fournies~:}
\begin{itemize}
\item \textbf{Page d'accueil} (\texttt{index.html})~: Titre principal (nom du lycée), paragraphe avec accents (« établissement créé en 1992, situé à Nkol-Eton, accueillant 1 250 élèves »), logo \texttt{logo.png} \textbf{cliquable} (retour accueil), menu navigation 3 liens \textbf{relatifs} avec \textbf{infobulles}.
\item \textbf{Page « Résultats »} (\texttt{pages/resultats.html})~: Tableau taux de réussite Probatoire TI 2024 (C: 78\%, D: 71\%, TI: 85\%). Ligne titre fusionnée (\texttt{colspan}), cellule « 2024 » fusionnée verticalement (\texttt{rowspan=3}). Liste imbriquée des filières (Littéraire: A4 ; Scientifique: C, D ; Technique: TI, F4).
\item \textbf{Page « Inscription »} (\texttt{pages/inscription.html})~: Formulaire pré-inscription~: Nom (texte), Date naissance (date), Sexe (radio M/F), Série (liste déroulante A4, C, D, TI), Activités (checkbox Football, Chorale, Club info), Boutons Envoyer / Effacer. Champs regroupés dans \texttt{<div>} ou \texttt{<section>}.
\end{itemize}

\textbf{Consignes pas à pas~:}
\begin{enumerate}
\item \textbf{Arborescence~:} Créer \texttt{site\_lycee/} sur le Bureau. Y placer \texttt{index.html}. Créer \texttt{pages/} (\texttt{resultats.html}, \texttt{inscription.html}) et \texttt{images/} (\texttt{logo.png}). Dessiner l'arborescence sur papier.
\item \textbf{Structure de base~:} Écrire le squelette HTML5 (\texttt{<!DOCTYPE html>}, \texttt{<html lang="fr">}, \texttt{<head>} avec \texttt{<meta charset="utf-8">} et \texttt{<title>}, \texttt{<body>}) dans les 3 fichiers. \emph{Pourquoi \texttt{meta charset} est-il vital ici ?}
\item \textbf{Page Accueil~:} Insérer \texttt{<h1>}, paragraphe \texttt{<p>}, logo cliquable (\texttt{<a><img></a>}), menu \texttt{<nav>} avec 3 liens \texttt{<a href="...">} + \texttt{title}. Chemins vers \texttt{pages/resultats.html} et \texttt{pages/inscription.html}.
\item \textbf{Page Résultats~:} Construire le \texttt{<table>} avec attributs \texttt{border}, \texttt{width}, \texttt{align}, \texttt{cellpadding}, \texttt{cellspacing}, \texttt{id}. Gérer \texttt{colspan="3"} sur \texttt{<th>} titre, \texttt{rowspan="3"} sur premier \texttt{<td>} de la 1ère ligne de données. Écrire la liste imbriquée \texttt{<ul><li>...<ul><li>...</li></ul></li></ul>}. Liens retour : \texttt{../index.html} et \texttt{inscription.html}.
\item \textbf{Page Inscription~:} Construire \texttt{<form action="traitement.html" method="post">}. Un \texttt{<div>} par groupe de champs. \texttt{<label for="id">} + \texttt{<input id="id" name="...">}. Radios : même \texttt{name="sexe"}. Checkboxes : \texttt{name} distincts. \texttt{<select>} avec \texttt{<option value="TI" selected>}. Boutons \texttt{type="submit"} et \texttt{type="reset"}. Lien retour \texttt{../index.html}.
\item \textbf{Test \& Débogage~:} Ouvrir \texttt{index.html}. Vérifier~: accents, logo cliquable, menu (infobulles, liens), tableau (fusions, alignement), formulaire (radio exclusif, checkbox multiples, liste, boutons). Corriger erreurs 404 (chemins), tableaux cassés (mauvais \texttt{rowspan}), radios non groupés.
\item \textbf{Présentation~:} Montrer l'arborescence et le site fonctionnel. Citer une limite du HTML observée.
\end{enumerate}

\textbf{Compétences évaluées~:} Organiser, Coder (HTML), Tester, Communiquer (arborescence, limites).
\end{experience}

\begin{attention}[Erreurs fréquentes au Probatoire et en TP -- Check-list de révision]
\begin{itemize}
\item \textbf{Chemins relatifs~:} Oublier \texttt{../} pour remonter depuis \texttt{pages/} vers \texttt{index.html} ou \texttt{images/}. $\rightarrow$ Erreur 404 « Fichier introuvable ».
\item \textbf{Encodage~:} Absence de \texttt{<meta charset="utf-8">} $\rightarrow$ « �tablissement », « �lèves ».
\item \textbf{Nommage fichiers~:} Espaces (\texttt{Page Résultats.html}), accents (\texttt{inscription.html}), majuscules $\rightarrow$ Liens cassés sur serveur Linux.
\item \textbf{Tableau \& fusions~:} Compter les cellules \emph{après} fusion. Ex~: \texttt{rowspan="3"} sur 3 lignes $\rightarrow$ les 2 lignes suivantes ont \textbf{une cellule de moins}. Ne pas écrire le \texttt{<td>} fantôme.
\item \textbf{Radios~:} \texttt{name} différents $\rightarrow$ on peut cocher Masculin \textbf{ET} Féminin en même temps.
\item \textbf{Checkboxes~:} \texttt{name} identiques $\rightarrow$ un seul choix possible (comportement radio).
\item \textbf{Formulaire~:} Oublier \texttt{name} sur un champ $\rightarrow$ donnée non envoyée au serveur.
\item \textbf{Accessibilité~:} \texttt{alt} manquant sur image, \texttt{<label>} non lié (\texttt{for}/\texttt{id}).
\item \textbf{Imbrication~:} Fermer les balises dans l'ordre inverse (LIFO) : \texttt{<ul><li><ul><li></li></ul></li></ul>}. Ne pas croiser : \texttt{<a><b></a></b>} (invalide).
\end{itemize}
\end{attention}

\textbf{Bilan de la leçon.}
Cette leçon a couvert l'intégralité du module « Programmation Web statique en HTML » du programme officiel de Première TI. Tu sais maintenant~:
\begin{enumerate}
\item Structurer une page HTML5 valide avec \texttt{<!DOCTYPE html>}, \texttt{<meta charset="utf-8">}, \texttt{<head>}, \texttt{<body>}.
\item Organiser une \cle{arborescence} de site propre (dossiers \texttt{images/}, \texttt{pages/}, noms normalisés).
\item Maîtriser les \cle{liens relatifs} (\texttt{dossier/}, \texttt{../}) et les \cle{infobulles} (\texttt{title}).
\item Insérer des \cle{médias} : images (\texttt{<img>}), images cliquables (\texttt{<a><img></a>}), sons (\texttt{<audio>}), vidéos (\texttt{<video>}).
\item Construire des \cle{tableaux} complexes avec attributs de présentation (\texttt{border}, \texttt{width}, \texttt{align}, \texttt{cellpadding}, \texttt{cellspacing}) et \cle{fusions de cellules} (\texttt{colspan}, \texttt{rowspan}).
\item Imbriquer des \cle{listes} (\texttt{<ul>}/\texttt{<ol>} dans \texttt{<li>}).
\item Réaliser des \cle{formulaires} accessibles et complets : \texttt{<form>}, \texttt{<input>} (text, date, radio, checkbox, submit, reset), \texttt{<select>}/\texttt{<option>}, \texttt{<label>}, \texttt{<fieldset>}.
\item Structurer le contenu avec les balises de \cle{section} (\texttt{<div>}, \texttt{<section>}, \texttt{<span>}, \texttt{<header>}, \texttt{<nav>}, \texttt{<footer>}).
\item Identifier les \cle{limites du HTML} : langage de \textbf{balisage} (structure + contenu), \textbf{statique}, sans traitement de données, sans mise en page avancée, sans interactivité dynamique $\rightarrow$ nécessite \textbf{CSS} (style) et \textbf{JavaScript} (comportement) côté client, puis langages serveur (PHP, Python...) côté serveur (Terminale).
\end{enumerate}

\begin{methode}[Afficher correctement les caractères accentués]
Pour que les accents (é, è, à, ç, ô...) s'affichent correctement dans tous les navigateurs, deux conditions \textbf{indissociables} doivent être respectées :
\begin{enumerate}
  \item \textbf{Encodage du fichier :} Enregistrer le fichier \textbf{impérativement en UTF-8} (menu \emph{Encodage} $\to$ \emph{Convertir en UTF-8} dans Notepad++ ou VS Code). C'est l'encodage universel du web.
  \item \textbf{Déclaration dans le code :} Placer \textbf{en tout premier} dans la balise \texttt{<head>} la balise méta : \texttt{<meta charset="utf-8">}.
\end{enumerate}
\textbf{Réflexe Bac :} La balise \texttt{<meta charset="utf-8">} est \emph{orpheline} (pas de balise fermante). Elle doit être la \textbf{première enfant de \texttt{<head>}}, avant \texttt{<title>}, pour que le navigateur lise le titre lui-même avec le bon encodage. Si des symboles type \texttt{Ã©} ou \texttt{�} apparaissent : l'encodage du fichier (disque) ne correspond pas au \texttt{charset} déclaré (navigateur).
\end{methode}

\begin{exoresolu}[Une page qui affiche mal les accents]
Le site du lycée de Bafoussam affiche « Bienvenue au LycÃ©e » au lieu de « Bienvenue au Lycée ». Le code source commence ainsi :
\begin{lstlisting}[language=HTML]
<html>
<head>
<title>Lycee de Bafoussam</title>
</head>
<body>Bienvenue au Lycee</body>
</html>
\end{lstlisting}
1) Identifier la cause du problème. 2) Corriger le code en respectant la structure HTML5 complète.
\tcblower
\textbf{1) Cause.} L'affichage « LycÃ©e » est le symptôme classique d'un fichier enregistré en UTF-8 mais interprété par le navigateur en ISO-8859-1 (Latin-1), car \textbf{aucun \texttt{charset} n'est déclaré} dans le \texttt{<head>}. Le navigateur « devine » mal. De plus, la déclaration de type de document (\texttt{<!DOCTYPE html>}) est absente.

\textbf{2) Correction.} On ajoute le \texttt{DOCTYPE} HTML5, la balise méta \texttt{charset} en \textbf{première position} dans \texttt{<head>}, et on s'assure que le fichier est bien enregistré en UTF-8 (sans BOM de préférence) :
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="utf-8">
    <title>Lycée de Bafoussam</title>
</head>
<body>
    <p>Bienvenue au Lycée</p>
</body>
</html>
\end{lstlisting}
\textbf{Conclusion :} La déclaration \texttt{<meta charset="utf-8">} dans \texttt{<head>}, associée à un enregistrement du fichier en UTF-8, garantit l'affichage correct des caractères accentués. L'attribut \texttt{lang="fr"} sur \texttt{<html>} aide aussi l'accessibilité et le référencement.
\end{exoresolu}

\begin{methode}[Imbriquer des listes et insérer un hyperlien avec infobulle]
\textbf{Listes imbriquées (règle d'or : l'imbrication se fait \emph{dans} un \texttt{<li>}) :}
\begin{enumerate}
  \item Une liste non ordonnée \texttt{<ul>} (puces) ou ordonnée \texttt{<ol>} (numéros) contient des items \texttt{<li>}.
  \item Pour créer une sous-liste, on ouvre la nouvelle liste (\texttt{<ul>} ou \texttt{<ol>}) \textbf{à l'intérieur d'un \texttt{<li>} parent}, avant de fermer ce \texttt{<li>}.
  \item On ferme les balises dans l'ordre inverse de l'ouverture (LIFO) : \texttt{</ol>} puis \texttt{</li>} puis \texttt{</ul>}.
\end{enumerate}

\textbf{Hyperlien (\texttt{<a>}) avec infobulle :}
\begin{enumerate}
  \item Syntaxe : \texttt{<a href="URL" title="Texte de l'infobulle">Contenu cliquable</a>}.
  \item L'attribut \texttt{href} (Hypertext REFerence) reçoit une \cle{URL} :
        \begin{itemize}
          \item \textbf{Absolue :} Adresse complète avec protocole (\texttt{https://www.minesec.gov.cm}, \texttt{mailto:contact@ecole.cm}).
          \item \textbf{Relative :} Chemin depuis la page courante (\texttt{contact.html}, \texttt{../images/logo.png}, \texttt{/pages/accueil.html}).
        \end{itemize}
  \item L'attribut \texttt{title} affiche une \cle{infobulle} (tooltip) au survol de la souris (accessibilité).
  \item Le contenu cliquable peut être du texte, une image, ou un bloc (HTML5).
\end{enumerate}
\end{methode}

\begin{methode}[Insérer un média : image, image cliquable, son, vidéo]
\begin{enumerate}
  \item \textbf{Image (\texttt{<img>}) :} \texttt{<img src="URL" alt="Description textuelle" width="..." height="...">}.
        \begin{itemize}
          \item \texttt{src} (source) : URL relative ou absolue du fichier image (JPG, PNG, WebP, SVG, GIF).
          \item \texttt{alt} (alternative) : \textbf{Obligatoire} (accessibilité lecteurs d'écran, référencement, affichage si image absente).
          \item \texttt{width}/\texttt{height} : Dimensions en pixels (réserve l'espace, évite le « saut » de mise en page au chargement).
        \end{itemize}
        \texttt{<img>} est une \cle{balise orpheline} (auto-fermante en HTML5 : \texttt{<img ...>}).
  \item \textbf{Image cliquable :} On imbrique \texttt{<img>} \emph{à l'intérieur} d'un lien \texttt{<a href="...">...</a>}.
  \item \textbf{Son (\texttt{<audio>}) :} \texttt{<audio src="URL" controls></audio>}.
        \begin{itemize}
          \item \texttt{controls} : Affiche les boutons lecture/pause/volume (interface navigateur).
          \item Formats courants : MP3, OGG, WAV. Préférer \texttt{<source>} multiples pour compatibilité.
        \end{itemize}
  \item \textbf{Vidéo (\texttt{<video>}) :} \texttt{<video src="URL" controls width="..."></video>}.
        \begin{itemize}
          \item \texttt{controls}, \texttt{width}, \texttt{height}, \texttt{poster} (image d'attente).
          \item Formats : MP4 (H.264) universel, WebM. Utiliser \texttt{<source>} pour alternatives.
        \end{itemize}
  \item \textbf{Vérification cruciale :} Le chemin (URL) du média doit être correct \emph{relativement à l'emplacement du fichier HTML} (pas relativement au dossier racine du serveur).
\end{enumerate}
\textbf{Rappel :} \texttt{<img>} orpheline ; \texttt{<audio>} et \texttt{<video>} ont une balise fermante (permettent du contenu de repli entre les balises).
\end{methode}

\begin{exoresolu}[Page d'accueil d'un cybercafé]
La page d'accueil (\texttt{index.html} à la racine) du cybercafé « NetExpress » de Douala doit afficher : le logo \texttt{logo.png} (dans \texttt{images/}) qui, cliqué, renvoie vers \texttt{services.html} ; puis une vidéo de présentation \texttt{promo.mp4} (dans \texttt{video/}) avec contrôles. Rédiger le code HTML5 complet.

\textbf{Raisonnement.} Page à la racine $\Rightarrow$ URL relatives : \texttt{images/logo.png} et \texttt{video/promo.mp4} (descente dans sous-dossiers). Image cliquable = \texttt{<a>} autour de \texttt{<img>}. Vidéo = \texttt{<video controls>}.

\begin{methode}[Construire un tableau et fusionner des cellules]
\begin{enumerate}
  \item \textbf{Structure de base :} \texttt{<table>} $\to$ lignes \texttt{<tr>} $\to$ cellules \texttt{<td>} (données) ou \texttt{<th>} (en-têtes, gras + centrées par défaut).
  \item \textbf{Attributs de \texttt{<table>} (HTML4/transitionnel, encore au programme) :}
        \texttt{border="1"} (bordure), \texttt{width="80\%"} (largeur), \texttt{cellpadding="5"} (marge intérieure), \texttt{cellspacing="2"} (espace entre cellules), \texttt{align="center"} (centrage tableau), \texttt{id="identifiant"} (unique pour CSS/JS).
        \emph{Note :} En HTML5 moderne, on privilégie CSS pour la présentation (\texttt{border-collapse}, \texttt{padding}, \texttt{margin}).
  \item \textbf{Fusion horizontale (\texttt{colspan}) :} Dans un \texttt{<td>} ou \texttt{<th>}, \texttt{colspan="n"} fusionne $n$ cellules sur la \emph{même ligne}. \textbf{On supprime alors les $n-1$ cellules \texttt{<td>} suivantes de cette ligne.}
  \item \textbf{Fusion verticale (\texttt{rowspan}) :} \texttt{rowspan="n"} fusionne $n$ cellules sur la \emph{même colonne}. \textbf{On supprime la cellule correspondante dans chacune des $n-1$ lignes suivantes.}
  \item \textbf{Vérification systématique (règle de cohérence) :} Chaque ligne \texttt{<tr>} doit occuper le \textbf{même nombre total de colonnes} en comptant : cellules normales + valeurs \texttt{colspan} + cellules « retenues » par un \texttt{rowspan} venu du dessus.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Tableau des notes d'une classe de Première TI]
Créer un tableau HTML5 (avec bordure visible, largeur 80\%, centré) comportant :
\begin{itemize}
  \item Une ligne d'en-tête : « Matière | Note | Appréciation ».
  \item Une ligne de données : « Algorithmique | 17 | Très bien ».
  \item Une ligne de données : « Web Statique | 15 | Bien ».
  \item Une dernière ligne fusionnant les 3 colonnes : « Moyenne générale : 15,5 ».
\end{itemize}
Utiliser \texttt{cellpadding="5"} et \texttt{cellspacing="0"}.
\tcblower
\textbf{Raisonnement.} Trois colonnes $\Rightarrow$ 3 cellules par ligne (sauf fusion). Dernière ligne : fusion horizontale des 3 colonnes $\Rightarrow$ un seul \texttt{<td colspan="3">}, \textbf{aucune autre cellule} sur cette ligne.
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="utf-8">
    <title>Bulletin de notes - 1ère TI</title>
</head>
<body>
    <table border="1" width="80%" cellpadding="5" cellspacing="0" align="center" id="bulletin">
        <caption>Résultats du 1er trimestre - Élève : Mbarga Jean</caption>
        <tr>
            <th>Matière</th>
            <th>Note</th>
            <th>Appréciation</th>
        </tr>
        <tr>
            <td>Algorithmique</td>
            <td>17</td>
            <td>Très bien</td>
        </tr>
        <tr>
            <td>Web Statique</td>
            <td>15</td>
            <td>Bien</td>
        </tr>
        <tr>
            <td colspan="3" style="text-align:center; font-weight:bold;">Moyenne générale : 15,5</td>
        </tr>
    </table>
</body>
</html>
\end{lstlisting}
\textbf{Vérification :}
Ligne 1 (en-têtes) : 3 \texttt{<th>} = 3 colonnes.
Ligne 2 : 3 \texttt{<td>} = 3 colonnes.
Ligne 3 : 3 \texttt{<td>} = 3 colonnes.
Ligne 4 : 1 \texttt{<td colspan="3">} = 3 colonnes. \textbf{Tableau équilibré.}

\textbf{Conclusion :} L'attribut \texttt{colspan} permet la fusion horizontale ; on retire scrupuleusement les cellules absorbées pour conserver un tableau régulier. L'ajout de \texttt{<caption>} (légende) et d'un peu de CSS \texttt{inline} (\texttt{style}) améliore la lisibilité.
\end{exoresolu}

\begin{methode}[Créer un formulaire HTML]
\begin{enumerate}
  \item \textbf{Conteneur :} \texttt{<form action="URL\_traitement" method="get|post">...</form>}.
        \begin{itemize}
          \item \texttt{action} : URL du script serveur qui traitera les données (PHP, Python, Node.js... vu en Terminale). En attendant, on met souvent \texttt{action="\#"} ou \texttt{action=""} (page courante) pour tester la structure.
          \item \texttt{method} : \texttt{get} (données dans l'URL, pour recherche/filtrage) ou \texttt{post} (données dans le corps HTTP, pour inscription/modification, plus sécurisé).
        \end{itemize}
  \item \textbf{Champ de saisie texte :} \texttt{<input type="text" name="identifiant" id="identifiant" placeholder="Votre nom">}.
        \texttt{type="password"} masque la saisie. \texttt{name} est \textbf{indispensable} pour l'envoi des données.
  \item \textbf{Boutons radio (choix unique) :} \texttt{<input type="radio" name="groupe" value="valeur" id="id1">}.
        \textbf{Règle stricte :} Tous les boutons d'un même choix exclusif portent le \textbf{même \texttt{name}}.
  \item \textbf{Cases à cocher (choix multiples) :} \texttt{<input type="checkbox" name="choix[]" value="val" id="id2">}.
        \texttt{name} peut être identique (tableau côté serveur) ou différent. \texttt{value} = valeur envoyée si cochée.
  \item \textbf{Liste déroulante :} \texttt{<select name="ville" id="ville">} contenant \texttt{<option value="code">Libellé</option>}.
  \item \textbf{Boutons d'action :}
        \texttt{<input type="submit" value="Envoyer">} (envoie le formulaire),
        \texttt{<input type="reset" value="Annuler">} (remet à zéro),
        \texttt{<button type="button">Action JS</button>} (bouton neutre pour JavaScript).
  \item \textbf{Accessibilité (Obligatoire au Bac) :} Associer \textbf{explicitement} chaque champ à son étiquette via \texttt{<label for="id\_du\_champ">Libellé</label>} et \texttt{id="id\_du\_champ"} sur le \texttt{<input>/<select>/<textarea>}. Cela agrandit la zone cliquable et aide les lecteurs d'écran.
\end{enumerate}
\end{methode}

\begin{methode}[Organiser les dossiers d'un site et structurer avec les balises de section]
\begin{enumerate}
  \item \textbf{Arborescence type (racine du site) :}
\begin{verbatim}
mon_site/
├── index.html          (page d'accueil, point d'entrée)
├── css/
│   └── style.css
├── js/
│   └── script.js
├── images/
│   ├── logo.png
│   └── banniere.jpg
└── pages/
    ├── contact.html
    └── services.html
\end{verbatim}
  \item \textbf{URL relatives (navigation dans l'arborescence) :}
        \begin{itemize}
          \item Descendre : \texttt{images/logo.png}, \texttt{pages/contact.html}.
          \item Remonter : \texttt{../index.html} (depuis \texttt{pages/}), \texttt{../../fichier} (deux niveaux).
          \item Racine du site (absolu depuis racine) : \texttt{/images/logo.png} (débute par \texttt{/}).
        \end{itemize}
  \item \textbf{Balises de structure sémantique (HTML5) :}
        \begin{itemize}
          \item \texttt{<header>} : En-tête de page ou de section (logo, titre, nav principal).
          \item \texttt{<nav>} : Navigation principale (menus).
          \item \texttt{<main>} : Contenu principal unique de la page.
          \item \texttt{<section>} : Regroupement thématique \emph{avec un titre} (ex: « Actualités », « Services »).
          \item \texttt{<article>} : Contenu autonome, syndiquable (ex: article de blog, fiche produit).
          \item \texttt{<aside>} : Contenu annexe (barre latérale, pub, liens connexes).
          \item \texttt{<footer>} : Pied de page (copyright, mentions légales, contacts).
          \item \texttt{<div>} : Conteneur \textbf{générique} de bloc (sans sens sémantique), pour mise en page CSS (grilles, flexbox).
          \item \texttt{<span>} : Conteneur \textbf{générique en ligne} (pas de retour à la ligne), pour styliser un morceau de phrase.
        \end{itemize}
  \item \textbf{Identification pour CSS/JS :} Attribut \texttt{id} (unique dans la page, ex: \texttt{id="menu-principal"}) ou \texttt{class} (réutilisable, ex: \texttt{class="carte-service"}).
  \item \textbf{Limites du HTML (à connaître et énoncer) :}
        \begin{enumerate}
          \item HTML est un langage de \textbf{balisage} (structure/contenu), \textbf{pas un langage de programmation} : pas de variables, boucles, conditions, calculs, fonctions.
          \item HTML produit des pages \textbf{statiques} : même contenu pour tous, pas d'interaction avec une base de données, pas de session utilisateur, pas de traitement de formulaire (nécessite JS côté client + langage serveur côté serveur).
          \item Le rendu visuel \textbf{dépend du navigateur} (styles par défaut différents) $\Rightarrow$ nécessité du CSS.
          \item Accessibilité et SEO limités sans attributs sémantiques (\texttt{alt}, \texttt{label}, structure \texttt{<h1>}-\texttt{<h6>}, balises HTML5).
        \end{enumerate}
\end{enumerate}
\end{methode}

\begin{exoresolu}[Structurer la page d'accueil du site du lycée]
Le site du lycée possède l'arborescence : racine (\texttt{index.html}), \texttt{images/}, \texttt{css/}, \texttt{pages/}.
On demande :
1) Depuis \texttt{pages/contact.html}, écrire la balise pour afficher \texttt{images/batiment.jpg}.
2) Structurer \texttt{index.html} en zones sémantiques : en-tête (logo + titre), navigation (menu), contenu principal (section « Bienvenue » + section « Actualités »), pied de page. Mettre en évidence le mot « excellence » dans une phrase.
3) Citer deux limites majeures du HTML.
\tcblower
\textbf{1) Image depuis un sous-dossier \texttt{pages/}.}
Il faut \emph{remonter} d'un niveau (\texttt{../}) pour atteindre la racine, puis \emph{redescendre} dans \texttt{images/} :
\begin{lstlisting}[language=HTML]
<!-- Dans pages/contact.html -->
<img src="../images/batiment.jpg" alt="Bâtiment principal du lycée" width="400" height="300">
\end{lstlisting}

\textbf{2) Structuration sémantique de \texttt{index.html}.}
On utilise les balises HTML5 (\texttt{<header>}, \texttt{<nav>}, \texttt{<main>}, \texttt{<section>}, \texttt{<footer>}) pour le sens, et \texttt{<div>} uniquement si besoin de conteneur neutre pour le CSS. \texttt{<span>} pour le mot en ligne.
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="utf-8">
    <title>Lycée de Bafoussam - Accueil</title>
    <link rel="stylesheet" href="css/style.css">
</head>
<body>
    <header id="entete">
        <img src="images/logo.png" alt="Logo du Lycée" width="100" height="100">
        <h1>Lycée de Bafoussam</h1>
    </header>

    <nav id="menu-principal">
        <ul>
            <li><a href="index.html">Accueil</a></li>
            <li><a href="pages/presentation.html">Présentation</a></li>
            <li><a href="pages/contact.html">Contact</a></li>
        </ul>
    </nav>

    <main id="contenu-principal">
        <section id="bienvenue">
            <h2>Bienvenue</h2>
            <p>Un établissement d'<span class="mot-cle">excellence</span> au service de la réussite de tous.</p>
        </section>

        <section id="actualites">
            <h2>Actualités</h2>
            <article>
                <h3>Rentrée 2024-2025</h3>
                <p>Les inscriptions sont ouvertes...</p>
            </article>
        </section>
    </main>

    <footer id="pied-page">
        <p>Contact : <a href="mailto:lycee.bafoussam@education.cm">lycee.bafoussam@education.cm</a></p>
        <p>&copy; 2025 Lycée de Bafoussam - Tous droits réservés.</p>
    </footer>
</body>
</html>
\end{lstlisting}
\textbf{Note :} \texttt{<span class="mot-cle">} n'introduit \textbf{pas} de rupture de ligne (élément \emph{inline}), contrairement à \texttt{<div>} (bloc). C'est le bon choix pour styliser un mot dans une phrase. Les \texttt{id} uniques (\texttt{entete}, \texttt{menu-principal}...) et \texttt{class} réutilisables (\texttt{mot-cle}) préparent le ciblage CSS.

\textbf{3) Limites majeures du HTML.}
\begin{enumerate}
  \item \textbf{Statisme \& Absence de logique :} HTML ne permet ni calculs, ni conditions (\texttt{if/else}), ni boucles, ni stockage de données. Une page HTML est un document figé servi tel quel.
  \item \textbf{Aucune interaction serveur / Base de données :} HTML seul ne peut pas traiter un formulaire (enregistrer un élève), afficher des notes depuis une BDD, ni gérer une session utilisateur (connexion). Cela nécessite JavaScript (côté client) et un langage serveur (PHP, Python, Node.js) + SGBD (vus en Terminale).
\end{enumerate}

\textbf{Conclusion :} Une arborescence claire, la maîtrise des URL relatives (\texttt{../}) et l'usage des balises sémantiques HTML5 (\texttt{<header>}, \texttt{<nav>}, \texttt{<main>}, \texttt{<section>}, \texttt{<footer>}, \texttt{<span>}) donnent un site bien organisé, accessible et maintenable, tout en gardant à l'esprit que HTML seul reste limité à la structure et au contenu statique.
\end{exoresolu}

\begin{attention}[Les 5 erreurs qui coûtent des points au Probatoire]
\begin{enumerate}
  \item \textbf{Oublier \texttt{<meta charset="utf-8">}} ou le placer hors du \texttt{<head>} (ex: dans \texttt{<body>}) : les accents s'affichent mal (\texttt{Ã©}, \texttt{�}) $\Rightarrow$ sanction systématique. \emph{Astuce :} Le taper en tout premier dans le \texttt{<head>}.
  \item \textbf{Fusionner des cellules sans supprimer les cellules absorbées :} Avec \texttt{colspan="3"}, on n'écrit \textbf{qu'une seule} cellule \texttt{<td>} sur la ligne ; avec \texttt{rowspan="2"}, on \textbf{supprime} la cellule correspondante dans la ligne suivante. Sinon : colonnes décalées, tableau « cassé ».
  \item \textbf{Donner des \texttt{name} différents aux boutons radio d'un même groupe :} L'utilisateur peut alors tout cocher (choix multiple au lieu d'unique). \textbf{Même groupe $\Rightarrow$ Même \texttt{name}.}
  \item \textbf{Erreur d'URL relative (chemin cassé) :} Depuis \texttt{pages/contact.html}, écrire \texttt{src="images/logo.png"} au lieu de \texttt{src="../images/logo.png"}. Le navigateur cherche \texttt{pages/images/logo.png} (inexistant) $\Rightarrow$ image cassée (icône déchirée). \emph{Réflexe :} « Suis-je dans un sous-dossier ? $\Rightarrow$ \texttt{../} pour sortir. »
  \item \textbf{Confondre balises de structure et leurs rôles :}
        \begin{itemize}
          \item Utiliser \texttt{<div>} pour un mot dans une phrase (crée un bloc, retour à la ligne) au lieu de \texttt{<span>} (en ligne).
          \item Oublier l'attribut \texttt{alt} sur \texttt{<img>} (accessibilité, SEO, validation W3C).
          \item Écrire \texttt{<img>...</img>} ou \texttt{<br></br>} : ce sont des \textbf{balises orphelines} (void elements), syntaxe correcte : \texttt{<img ...>}, \texttt{<br>}.
          \item Imbriquer une liste \texttt{<ul>} \emph{entre} deux \texttt{<li>} au lieu de \emph{dans} le \texttt{<li>} parent.
        \end{itemize}
\end{enumerate}
\end{attention}

\begin{savaistu}[Le saviez-vous ? : Le premier site web au monde]
Le tout premier site web de l'histoire a été mis en ligne le \textbf{20 décembre 1990} par \textbf{Tim Berners-Lee} au CERN (Suisse). Il tournait sur un ordinateur NeXT et expliquait le projet « WorldWideWeb » : comment créer des pages, des liens, et configurer un serveur. L'adresse originale \texttt{http://info.cern.ch/} est toujours accessible (restaurée en 2013). Il ne contenait \textbf{que du HTML} (pas de CSS, pas d'images, pas de JS) : du texte structuré avec des titres, des listes et des hyperliens. C'est la preuve que le cœur du web, c'est d'abord \textbf{la structure de l'information et le lien hypertexte} — exactement ce que vous apprenez en ce moment en Première TI !
\end{savaistu}

\coursec{Leçon 05 : Programmation Web statique en HTML — Exercices corrigés}

\begin{corrige}[Exercice 1 — QCM : à chaque question, une seule bonne réponse]
\begin{enumerate}
\item \textbf{Réponse a.} La déclaration correcte de l'encodage est \texttt{<meta charset="utf-8">}, placée dans l'en-tête \texttt{<head>}. L'encodage \cle{UTF-8} permet l'affichage correct des caractères accentués (é, è, à, ç\ldots). Les autres propositions n'existent pas en HTML : il n'y a ni balise \texttt{<charset>}, ni attribut \texttt{encoding} sur \texttt{<meta>}, ni attribut \texttt{charset} sur \texttt{<html>}.
\item \textbf{Réponse c.} L'attribut \texttt{href} (\emph{hypertext reference}) de la balise \texttt{<a>} contient l'adresse (URL) de la destination du lien. L'attribut \texttt{src} sert, lui, à indiquer la source d'un média (image, son, vidéo).
\item \textbf{Réponse b.} L'attribut \texttt{colspan} fusionne des cellules \emph{horizontalement} (sur plusieurs colonnes, donc sur une même ligne). \texttt{rowspan} fusionne verticalement (sur plusieurs lignes), et \texttt{cellpadding} définit l'espacement intérieur des cellules. L'attribut \texttt{merge} n'existe pas en HTML.
\item \textbf{Réponse b.} Des boutons radio forment un groupe mutuellement exclusif lorsqu'ils partagent le \textbf{même attribut \texttt{name}} : le navigateur n'autorise alors qu'une seule case cochée dans le groupe. L'attribut \texttt{id} doit au contraire être unique pour chaque élément, et \texttt{value} sert à définir la valeur envoyée au serveur.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 2 — Vrai ou faux — justifier]
\begin{enumerate}
\item \textbf{Faux.} La plupart des balises vont par paire (\texttt{<p>}\ldots\texttt{</p>}), mais il existe des balises \emph{orphelines} (ou \cle{auto-fermantes} / \emph{void elements}) qui n'ont pas de balise fermante : \texttt{<img>}, \texttt{<br>}, \texttt{<hr>}, \texttt{<input>}, \texttt{<meta>}.
\item \textbf{Vrai.} L'attribut \texttt{title} d'un lien (et de nombreuses autres balises) affiche une \cle{infobulle} (tooltip) contenant son texte lorsque le pointeur de la souris survole l'élément.
\item \textbf{Faux.} \texttt{<img>} est une balise orpheline : elle ne possède pas de balise fermante \texttt{</img>}. Toute l'information est portée par ses attributs (\texttt{src}, \texttt{alt}, \texttt{width}\ldots).
\item \textbf{Faux.} Le chemin \texttt{pages/contact.html} signifie que \texttt{contact.html} se trouve dans le \textbf{sous-dossier \texttt{pages}} du dossier contenant la page courante. S'il était dans le même dossier, on écrirait simplement \texttt{href="contact.html"}.
\item \textbf{Vrai.} \texttt{<span>} est un conteneur \emph{en ligne} (\emph{inline}) : il n'occupe que la largeur de son contenu et ne provoque pas de retour à la ligne ; il sert à marquer une portion de texte. \texttt{<div>} est un conteneur de type \emph{bloc} : il occupe toute la largeur disponible et crée un nouveau bloc.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 3 — Question de cours type Probatoire]
\begin{itemize}
\item \textbf{\cle{Balise}} : marqueur de structuration du langage HTML, écrit entre chevrons (\texttt{<} et \texttt{>}), qui indique au navigateur la nature et le rôle d'un contenu. \emph{Exemple :} \texttt{<h1>} ouvre un titre de niveau 1, fermé par \texttt{</h1>}.
\item \textbf{\cle{Attribut de balise}} : information complémentaire placée dans la balise ouvrante, sous la forme \texttt{nom="valeur"}, qui précise le comportement ou les propriétés de l'élément. \emph{Exemple :} dans \texttt{<img src="logo.png" alt="Logo">}, \texttt{src} et \texttt{alt} sont des attributs.
\item \textbf{\cle{Hyperlien}} : élément cliquable d'une page web qui renvoie vers une autre page, un autre site ou un emplacement précis ; il est créé par la balise \texttt{<a>} et son attribut \texttt{href}. \emph{Exemple :} \texttt{<a href="tarifs.html">Voir les tarifs</a>}.
\item \textbf{\cle{URL}} (\emph{Uniform Resource Locator}) : adresse normalisée permettant de localiser une ressource sur le Web. \emph{Exemple :} \texttt{https://www.minesec.gov.cm} (URL absolue) ; \texttt{pages/contact.html} (URL relative).
\item \textbf{\cle{Site web}} : ensemble cohérent de pages web reliées entre elles par des hyperliens, hébergé sur un serveur et accessible via une adresse. \emph{Exemple :} le site vitrine du cybercafé « Net Express » composé de \texttt{index.html} et \texttt{tarifs.html}.
\end{itemize}
\textbf{Points de vigilance (type Probatoire) :} chaque définition doit être accompagnée d'un exemple \emph{précis et syntaxiquement correct} ; confondre balise et attribut est une erreur éliminatoire fréquente.
\end{corrige}

\begin{corrige}[Exercice 4 — Lecture de code]
\begin{enumerate}
\item \texttt{<ul>} (\emph{unordered list}) crée une \textbf{liste à puces} (non numérotée) ; \texttt{<ol>} (\emph{ordered list}) crée une \textbf{liste numérotée} (ordonnée : 1, 2, 3\ldots).
\item Il s'agit d'une \textbf{liste imbriquée} : la liste numérotée \texttt{<ol>} est placée à l'intérieur d'un élément \texttt{<li>} de la liste à puces \texttt{<ul>}. On parle d'\emph{imbrication de listes}.
\item Le texte cliquable est \textbf{« MINESEC »} (contenu de la balise \texttt{<a>}). Au survol de la souris, une \textbf{infobulle} affichant « Site du MINESEC » apparaît, grâce à l'attribut \texttt{title}.
\item Le lien est \textbf{absolu}, car l'attribut \texttt{href} contient une URL complète avec le protocole (\texttt{https://}) et le nom de domaine (\texttt{www.minesec.gov.cm}) : il désigne une ressource externe au site, localisée de manière indépendante de la position de la page courante.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 5 — Chasse aux erreurs]
Les cinq erreurs sont les suivantes :
\begin{enumerate}
\item \textbf{Balise \texttt{<h1>} non fermée} : le titre « Bienvenue au Lycée de Nkolbisson » doit être refermé par \texttt{</h1>}, sinon tout le reste de la page serait affiché comme un titre de niveau 1.
\item \textbf{Attribut mal orthographié} : \texttt{scr} doit être corrigé en \texttt{src} (\emph{source}) ; sans cela, l'image ne s'affiche pas.
\item \textbf{Chemin incorrect} : le fichier se trouvant dans le dossier \texttt{pages}, le lien doit être \texttt{href="pages/contact.html"} et non \texttt{page/contact.html} (erreur 404 garantie).
\item \textbf{Attribut \texttt{name} manquant sur les boutons radio} : sans \texttt{name} commun, les deux boutons peuvent être cochés simultanément. Il faut ajouter \texttt{name="sexe"} aux deux \texttt{<input>}.
\item \textbf{Absence de la déclaration d'encodage} : il manque \texttt{<meta charset="utf-8">} dans le \texttt{<head>}, ce qui risque de provoquer l'affichage de caractères illisibles à la place des accents.
\end{enumerate}
Code corrigé (avec accents désormais pris en charge grâce à l'UTF-8) :
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <title>Mon lycée</title>
</head>
<body>
  <h1>Bienvenue au Lycée de Nkolbisson</h1>
  <img src="images/logo.png" alt="Logo du lycée">
  <a href="pages/contact.html">Nous contacter</a>
  <form>
    <input type="radio" name="sexe" value="M"> Garçon
    <input type="radio" name="sexe" value="F"> Fille
  </form>
</body>
</html>
\end{lstlisting}
\textbf{Point de vigilance :} en production réelle, on écrirait « Lycée », « Garçon » avec leurs accents, justement rendus possibles par la déclaration UTF-8 ajoutée.
\end{corrige}

\begin{corrige}[Exercice 6 — Tableau d'emploi du temps]
\begin{lstlisting}[language=HTML]
<table border="1" width="80%" cellpadding="5" cellspacing="2" align="center">
  <tr>
    <th>Heures</th><th>Lundi</th><th>Mardi</th>
    <th>Mercredi</th><th>Jeudi</th><th>Vendredi</th>
  </tr>
  <tr>
    <td>7h30 - 9h30</td><td>Maths</td><td>Physique</td>
    <td>Français</td><td>Anglais</td><td rowspan="2">EPS</td>
  </tr>
  <tr>
    <td>9h30 - 10h00</td><td colspan="4" align="center">Pause</td>
  </tr>
  <tr>
    <td>10h00 - 12h00</td><td>Informatique</td><td>Histoire</td>
    <td>Maths</td><td>SVT</td>
  </tr>
</table>
\end{lstlisting}
Explications :
\begin{itemize}
\item Les en-têtes de colonnes utilisent la balise \texttt{<th>} (\emph{table header}), qui centre et met en gras automatiquement ; une colonne « Heures » a été ajoutée pour libeller les créneaux.
\item La cellule « Pause » porte \texttt{colspan="4"} : elle fusionne les 4 colonnes de jours \emph{disponibles} (Lundi à Jeudi) sur la ligne concernée. La colonne Vendredi est occupée par la fusion verticale \texttt{rowspan="2"} de la cellule « EPS » démarrée sur la ligne précédente.
\item La cellule « EPS » porte \texttt{rowspan="2"} : elle occupe deux lignes dans la colonne Vendredi ; la ligne suivante (Pause) ne contient donc \textbf{pas} de cellule Vendredi (4 cellules de données + 1 cellule Heures = 5 cellules au total sur cette ligne, au lieu de 6).
\item \texttt{border="1"} rend la bordure visible, \texttt{width="80\%"} fixe la largeur relative, \texttt{cellpadding="5"} l'espacement intérieur et \texttt{cellspacing="2"} l'espacement entre cellules.
\end{itemize}
\textbf{Point de vigilance :} après une fusion par \texttt{rowspan}, la ligne suivante doit contenir une cellule de \emph{moins} pour la colonne concernée ; l'oublier (ou utiliser un \texttt{colspan} trop large) décale tout le tableau et produit un rendu imprévisible.
\end{corrige}

\begin{corrige}[Exercice 9 — Site vitrine d'un cybercafé de Bafoussam]
\begin{enumerate}
\item \textbf{Site web} : ensemble cohérent de pages web reliées par des hyperliens, hébergé sur un serveur et accessible via une adresse. \textbf{URL} : adresse normalisée permettant de localiser une ressource sur le Web (ex. \texttt{https://www.camtel.cm}). Un site \textbf{statique} affiche un contenu figé, identique pour tous les visiteurs, écrit uniquement en HTML/CSS : les pages ne changent que si l'on modifie le code source. Un site \textbf{dynamique} génère ses pages à la demande, à partir d'une base de données et d'un traitement côté serveur (contenu personnalisé, formulaires traités, comptes utilisateurs).
\item Squelette de \texttt{index.html} :
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <title>Net Express - Cybercafé de Bafoussam</title>
</head>
<body>
  <h1>Bienvenue chez Net Express</h1>
</body>
</html>
\end{lstlisting}
La balise \texttt{<meta charset="utf-8">}, placée dans le \texttt{<head>}, garantit l'affichage correct des caractères accentués (é, è, à).
\item Logo inséré puis rendu cliquable en l'entourant d'une balise \texttt{<a>} :
\begin{lstlisting}[language=HTML]
<a href="pages/tarifs.html">
  <img src="images/logo.png" alt="Logo du cybercafé Net Express">
</a>
\end{lstlisting}
\item Liste imbriquée des services :
\begin{lstlisting}[language=HTML]
<ul>
  <li>Navigation Internet</li>
  <li>Impression</li>
  <li>Formation bureautique
    <ol>
      <li>Word</li>
      <li>Excel</li>
    </ol>
  </li>
</ul>
\end{lstlisting}
\item Tableau de tarifs (dans \texttt{tarifs.html}) :
\begin{lstlisting}[language=HTML]
<table border="1" cellpadding="5" cellspacing="2">
  <tr><th>Service</th><th>Durée</th><th>Prix en FCFA</th></tr>
  <tr><td>Navigation</td><td>1 heure</td><td>200</td></tr>

\end{corrige}

\begin{corrige}[Exercice 10 — Formulaire d'inscription à la bibliothèque scolaire]
\begin{enumerate}
\item \textbf{\cle{Formulaire}} : zone d'une page web, délimitée par la balise \texttt{<form>}, permettant à l'utilisateur de saisir et d'envoyer des informations (champs de texte, boutons radio, cases à cocher, listes déroulantes, boutons). \textbf{\cle{Attribut de balise}} : information complémentaire écrite dans la balise ouvrante sous la forme \texttt{nom="valeur"}, qui précise les propriétés de l'élément (ex. \texttt{type="text"} dans \texttt{<input>}).
\item Code complet du formulaire :
\begin{lstlisting}[language=HTML]
<form action="inscription.html" method="post">
  <p>
    <label for="nom">Nom complet :</label>
    <input type="text" id="nom" name="nom">
  </p>
  <p>
    <label for="classe">Classe :</label>
    <select id="classe" name="classe">
      <option value="2nde">Seconde</option>
      <option value="1ere">Première</option>
      <option value="Tle">Terminale</option>
    </select>
  </p>
  <p>
    Sexe :
    <input type="radio" id="sxM" name="sexe" value="M">
    <label for="sxM">Masculin</label>
    <input type="radio" id="sxF" name="sexe" value="F">
    <label for="sxF">Féminin</label>
  </p>
  <p>
    Ouvrages souhaités :
    <input type="checkbox" id="rom" name="romans" value="oui">
    <label for="rom">Romans</label>
    <input type="checkbox" id="sci" name="sciences" value="oui">
    <label for="sci">Sciences</label>
    <input type="checkbox" id="his" name="histoire" value="oui">
    <label for="his">Histoire</label>
  </p>
  <p>
    <label for="com">Commentaire :</label><br>
    <textarea id="com" name="commentaire" rows="4" cols="40"></textarea>
  </p>
  <p>
    <input type="submit" value="Valider">
    <input type="reset" value="Effacer">
  </p>
</form>
\end{lstlisting}
\item Les deux boutons radio portent le même \texttt{name="sexe"} pour former un \textbf{groupe} : le navigateur applique alors l'exclusivité mutuelle (cocher l'un décoche l'autre), ce qui correspond à la réalité — un élève ne peut être que d'un seul sexe. Sans \texttt{name} commun, les deux boutons seraient indépendants et l'utilisateur pourrait cocher les deux simultanément, ce qui produirait une donnée incohérente.
\item Un bouton \texttt{submit} \textbf{envoie} les données du formulaire vers la page indiquée par l'attribut \texttt{action} ; un bouton \texttt{reset} \textbf{réinitialise} tous les champs à leurs valeurs initiales, sans rien envoyer.
\item Le HTML seul ne sait que \emph{décrire} l'interface du formulaire ; il ne peut ni recevoir, ni traiter, ni enregistrer les données dans une base de données : cela exige un \textbf{traitement côté serveur}. La technologie étudiée en Terminale pour cela est le \textbf{PHP} (couplé à un SGBD comme MySQL).
\item Deux autres limites du HTML :
\begin{itemize}
\item \textbf{Pas de mise en forme avancée} (couleurs, polices, positionnement fin) : palliée par le \textbf{CSS} (\emph{Cascading Style Sheets}) ;
\item \textbf{Pas d'interactivité côté client} (calculs, vérification de saisie, réaction aux clics sans recharger la page) : palliée par le \textbf{JavaScript}.
\end{itemize}
\end{enumerate}
\textbf{Barème indicatif (sur 10) :} définitions (1 pt) ; code complet et correct (4 pts) ; rôle du \texttt{name} commun (1,5 pt) ; distinction submit/reset (1 pt) ; limite et PHP (1,5 pt) ; deux autres limites (1 pt).
\textbf{Points de vigilance :} la zone multiligne s'écrit \texttt{<textarea>} (et non \texttt{<input type="textarea">}) ; citer explicitement que le traitement se fait \emph{côté serveur} ; ne pas confondre CSS (présentation) et JavaScript (comportement).
\end{corrige}

\begin{corrige}[Exercice 11 — Correction et enrichissement d'une page web]
\begin{enumerate}
\item Les quatre erreurs corrigées :
\begin{itemize}
\item \texttt{<h1>} fermée par \texttt{</h2>} : incohérence de balises, on ferme par \texttt{</h1>} ;
\item chemin \texttt{images\textbackslash{}classe.jpg} : sur le Web, le séparateur est le slash \texttt{/}, soit \texttt{images/classe.jpg} ;
\item attribut \texttt{alt} manquant sur \texttt{<img>} : il est obligatoire pour l'accessibilité et la validité ;
\item la dernière ligne du tableau \texttt{<tr>} n'est pas fermée : il manque \texttt{</tr>} avant \texttt{</table>}.
\end{itemize}
Code corrigé (incluant la déclaration d'encodage) :
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <title>Classe de Première TI</title>
</head>
<body>
  <h1>Notre classe</h1>
  <p>Bienvenue sur la page de la classe de Première TI.</p>
  <img src="images/classe.jpg" alt="Photo de la classe de Première TI">
  <table border="1">
    <tr><th>Jour</th><th>Matière</th></tr>
    <tr><td>Lundi</td><td>Informatique</td></tr>
  </table>
  <a href="https://www.minesec.gov.cm">Site officiel</a>
</body>
</html>
\end{lstlisting}
\item L'attribut \texttt{alt} fournit un \textbf{texte alternatif} affiché si l'image ne peut pas être chargée (chemin erroné, connexion lente, navigateur texte) ; il est aussi lu par les lecteurs d'écran pour les malvoyants et utilisé par les moteurs de recherche pour l'indexation. Il est donc indispensable pour l'accessibilité (\cle{accessibilité}) et la robustesse de la page.
\item On ajoute dans le \texttt{<head>}, idéalement juste après son ouverture (avant le \texttt{<title>}) :
\begin{lstlisting}[language=HTML]
<meta charset="utf-8">
\end{lstlisting}
\item Lien avec infobulle :
\begin{lstlisting}[language=HTML]
<a href="https://www.minesec.gov.cm"
   title="Ministère des Enseignements Secondaires">Site officiel</a>
\end{lstlisting}
\item Page structurée en sections sémantiques :
\begin{lstlisting}[language=HTML]
<body>
  <section>
    <h2>Présentation</h2>
    <p>Bienvenue sur la page de la classe de Première TI.</p>
    <img src="images/classe.jpg" alt="Photo de la classe de Première TI">
  </section>
  <section>
    <h2>Emploi du temps</h2>
    <table border="1">
      <tr><th>Jour</th><th>Matière</th></tr>
      <tr><td>Lundi</td><td>Informatique</td></tr>
    </table>
  </section>
  <a href="https://www.minesec.gov.cm"
     title="Ministère des Enseignements Secondaires">Site officiel</a>
</body>
\end{lstlisting}
\item Le HTML est un langage de \textbf{structuration du contenu} : il décrit la nature des éléments (titre, paragraphe, tableau) mais pas leur présentation. La couleur bleue et le centrage relèvent de la \textbf{mise en forme}, qui est du ressort du \textbf{CSS} (\emph{Cascading Style Sheets}), langage de style complémentaire du HTML.
\end{enumerate}
\textbf{Barème indicatif (sur 10) :} quatre erreurs corrigées (4 pts) ; rôle de \texttt{alt} (1,5 pt) ; \texttt{meta charset} bien placée (1 pt) ; infobulle (1 pt) ; sections (1,5 pt) ; limite du HTML et CSS (1 pt).
\textbf{Points de vigilance :} le titre de niveau 2 à l'intérieur de chaque \texttt{<section>} est bien un \texttt{<h2>} (le \texttt{<h1>} reste unique en tête de page) ; exiger la justification « HTML = structure, CSS = présentation » pour la dernière question.
\end{corrige}

\begin{bilan}
\textbf{Définitions clés}
\begin{itemize}
  \item \cle{Site web} : ensemble de pages web reliées par des hyperliens, hébergé sur un serveur et consultable via un navigateur.
  \item \cle{Balise} : marqueur encadré par \texttt{<} et \texttt{>} qui structure le contenu ; la plupart vont par paires (\texttt{<p>...</p>}), certaines sont orphelines (\texttt{<br>}, \texttt{<img>}, \texttt{<input>}).
  \item \cle{Attribut} : précision placée dans la balise ouvrante sous la forme \texttt{nom="valeur"} (ex. \texttt{src}, \texttt{href}, \texttt{width}).
  \item \cle{Hyperlien} : zone cliquable créée par \texttt{<a href="URL">} qui mène vers une autre page, un fichier ou une ancre.
  \item \cle{URL} : adresse d'une ressource sur le Web ; \emph{absolue} (complète, avec \texttt{http://}) ou \emph{relative} (par rapport au dossier du site).
  \item \cle{Formulaire} : zone de saisie (\texttt{<form>}) permettant à l'utilisateur d'entrer des données envoyées à un serveur.
\end{itemize}

\textbf{Syntaxes à connaître par c\oe ur}
\begin{center}

\hline

\hline

\hline

\hline

\textbf{Méthodes express}
\begin{itemize}
  \item \emph{Créer une page} : ouvrir le Bloc-notes ou un éditeur, écrire le squelette (\texttt{<!DOCTYPE html>}, \texttt{<html>}, \texttt{<head>} avec le charset, \texttt{<body>}), enregistrer en \texttt{.html}, ouvrir dans le navigateur.
  \item \emph{Organiser un site} : un dossier racine contenant \texttt{index.html} et des sous-dossiers (\texttt{images/}, \texttt{css/}, \texttt{pages/}) ; les liens internes utilisent des URL relatives.
  \item \emph{Construire un tableau} : d'abord les lignes \texttt{<tr>}, puis les cellules \texttt{<td>} ; vérifier que chaque ligne a le même nombre de colonnes en comptant les fusions.
  \item \emph{Limites du HTML} : pas de mise en forme élaborée (rôle du CSS), pas d'interactivité (rôle de JavaScript), pas de traitement côté serveur ; HTML décrit uniquement la \emph{structure} du contenu.
\end{itemize}
\end{bilan}

\begin{aretenir}[Checklist avant le Bac]

  \item $\square$ Je distingue balise ouvrante, balise fermante et balise orpheline.
  \item $\square$ Je sais imbriquer une liste dans une autre liste (\texttt{<ul>} dans un \texttt{<li>}).
  \item $\square$ Je différencie une URL absolue d'une URL relative et j'ajoute une infobulle avec \texttt{title}.
  \item $\square$ Je sais insérer une image avec \texttt{src} et \texttt{alt}, et la rendre cliquable.
  \item $\square$ Je sais insérer un son et une vidéo avec l'attribut \texttt{controls}.
  \item $\square$ Je construis un tableau avec \texttt{border}, \texttt{width}, \texttt{align}, \texttt{cellpadding}, \texttt{cellspacing}.
