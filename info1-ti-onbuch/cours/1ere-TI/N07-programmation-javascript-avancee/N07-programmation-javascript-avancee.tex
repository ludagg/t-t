\coursec{Scripts, évènements et insertion de JavaScript dans HTML}

Aminatou tient une boutique en ligne à Douala. Ses clientes remplissent un formulaire de commande, mais certaines oublient leur numéro de téléphone ou saisissent « abc » à la place de la quantité. Le site envoie alors des commandes incomplètes au serveur, ce qui fait perdre du temps et de l'argent : il faut rappeler les clientes, corriger les bons de livraison, annuler des envois. Un ami développeur lui explique qu'un petit programme exécuté \emph{directement dans le navigateur} peut vérifier la saisie avant l'envoi, calculer le total automatiquement et réagir aux clics des visiteurs. Ce programme, c'est un \cle{script} JavaScript.

\textbf{Problématique :} comment écrire un tel programme et comment l'insérer correctement dans les pages web d'Aminatou ? C'est toute l'ambition de cette première section : comprendre ce qu'est un script, ce qu'est un évènement, connaître les forces et les faiblesses de JavaScript, puis maîtriser les trois façons d'insérer un script dans un document HTML.

\courssub{Notion de script}

\courssub{Intuition : pourquoi un programme dans le navigateur ?}

Jusqu'ici, avec HTML et CSS, tu as construit des pages \emph{statiques} : belles, bien présentées, mais figées. Une page HTML seule ne peut ni calculer, ni vérifier une saisie, ni réagir à un clic. Or, dans la boutique d'Aminatou, on a besoin de \emph{logique} : « si le champ téléphone est vide, afficher un avertissement ; sinon, envoyer la commande ». Cette logique, on l'écrit dans un langage de programmation. Mais où ce programme va-t-il s'exécuter ?

Deux réponses sont possibles. Soit le programme s'exécute sur le \cle{serveur} (la machine distante qui héberge le site) : c'est la programmation \emph{côté serveur}, que tu étudieras en Terminale. Soit il s'exécute sur la machine du visiteur, dans son \cle{navigateur} : c'est la programmation \emph{côté client}, et c'est précisément le rôle de \cle{JavaScript}. L'intérêt est immense : la vérification se fait \emph{avant} l'envoi, instantanément, sans aller-retour avec le serveur — un vrai soulagement quand la connexion est lente ou coûteuse.

\begin{definition}[Script]
Un \cle{script} est un programme écrit dans un \cle{langage interprété}, c'est-à-dire une suite d'instructions exécutées directement par un logiciel (ici, le navigateur web) \textbf{sans compilation préalable}. Contrairement à un programme en langage C, qui doit d'abord être traduit en langage machine par un compilateur, le script est lu et exécuté ligne par ligne, au moment où le navigateur le rencontre.
\end{definition}

\begin{attention}[Interprété ne veut pas dire « sans règles »]
Parce qu'il n'y a pas d'étape de compilation, une erreur de syntaxe dans un script n'est détectée qu'\emph{à l'exécution}, et souvent elle bloque silencieusement tout le reste du script. Il faut donc tester ses scripts dans le navigateur (la console de développement, touche F12, affiche les erreurs). Ne confonds pas non plus « interprété » et « lent » : les navigateurs modernes exécutent JavaScript très rapidement.
\end{attention}

\courssub{Notion d'évènement}

Un script ne s'exécute pas toujours d'un seul coup au chargement de la page. Très souvent, il \emph{attend} que quelque chose se passe : l'utilisateur clique sur un bouton, survole une image avec la souris, modifie un champ, ou la page finit de se charger. Chacune de ces actions est un \cle{évènement}.

\begin{definition}[Évènement]
Un \cle{évènement} est une action de l'utilisateur ou du navigateur (clic, survol de la souris, saisie dans un champ, chargement de la page, etc.) qui peut être \textbf{détectée} par le script et qui \textbf{déclenche} l'exécution d'un code JavaScript associé. On dit que le script « réagit » à l'évènement.
\end{definition}

\begin{exemplebox}[Évènements dans la boutique d'Aminatou]
\begin{itemize}
\item Clic sur le bouton « Commander » $\rightarrow$ évènement \texttt{onClick} : le script vérifie les champs.
\item La cliente quitte le champ « quantité » après l'avoir modifié $\rightarrow$ évènement \texttt{onChange} : le script recalcule le total.
\item La page vient de s'afficher $\rightarrow$ évènement \texttt{onLoad} : le script affiche un message de bienvenue.
\item La cliente survole une image de produit $\rightarrow$ évènement \texttt{onMouseOver} : le script agrandit l'image.
\item La cliente place le curseur dans le champ « email » $\rightarrow$ évènement \texttt{onFocus} : le script affiche une aide contextuelle.
\end{itemize}
Nous étudierons ces évènements en détail dans la dernière section de la leçon ; retiens pour l'instant l'idée générale : \textbf{évènement détecté $\Rightarrow$ code exécuté}.
\end{exemplebox}

\courssub{Caractéristiques, avantages et limites de JavaScript}

\courssub{Caractéristiques}

\begin{propriete}[Caractéristiques du langage JavaScript]
JavaScript est un langage :
\begin{itemize}
\item \textbf{interprété} : exécuté ligne par ligne par le navigateur, sans compilation préalable ;
\item \textbf{côté client} : exécuté sur la machine du visiteur, dans son navigateur, et non sur le serveur ;
\item \textbf{orienté objet} : il manipule des objets (la page, les balises, les champs de formulaire) dotés de propriétés et de méthodes ;
\item \textbf{faiblement typé} : on ne déclare pas le type d'une variable ; le type est déterminé automatiquement à l'affectation et peut changer en cours d'exécution ;
\item \textbf{indépendant du serveur} : il fonctionne même sans connexion au serveur, une fois la page chargée.
\end{itemize}
\end{propriete}

\courssub{Avantages}

\begin{itemize}
\item \textbf{Interactivité immédiate} : la page réagit instantanément aux actions de l'utilisateur (calcul du total, message d'erreur, changement de couleur), sans attendre une réponse du serveur.
\item \textbf{Allègement du serveur} : les traitements simples sont faits chez le client ; le serveur n'est sollicité que pour l'essentiel, ce qui est précieux quand des centaines de clientes commandent en même temps.
\item \textbf{Contrôle de saisie avant envoi} : on vérifie les formulaires (champ vide, quantité non numérique) \emph{avant} de transmettre les données — c'est exactement le problème d'Aminatou.
\item \textbf{Amélioration de l'IHM} : menus déroulants, messages de confirmation, effets visuels rendent l'interface homme-machine plus agréable et plus claire.
\end{itemize}

\courssub{Limites}

\begin{attention}[Limites à connaître]
\begin{itemize}
\item JavaScript \textbf{dépend du navigateur} : un script peut se comporter légèrement différemment selon le navigateur ou sa version.
\item Le code est \textbf{visible par l'utilisateur} (affichage du code source) : on n'y place donc jamais de secret (mot de passe, clé) ; la sécurité est limitée.
\item JavaScript \textbf{peut être désactivé} par l'utilisateur dans les réglages du navigateur : le site doit rester utilisable, ou prévoir un message d'avertissement.
\item Pour des raisons de sécurité, JavaScript \textbf{n'a pas accès aux fichiers} de la machine du client : il ne peut ni lire ni écrire librement sur le disque dur du visiteur.
\end{itemize}
Conséquence pratique : le contrôle JavaScript est un \emph{confort}, jamais une garantie absolue ; les vérifications critiques seront refaites côté serveur (en Terminale).
\end{attention}

\begin{savaistu}[JavaScript n'a rien à voir avec Java]
Malgré son nom, JavaScript n'a \textbf{aucun lien} avec le langage Java. Créé en 1995 par Brendan Eich chez Netscape, il s'appelait d'abord \emph{Mocha}, puis \emph{LiveScript}. Le nom « JavaScript » fut choisi pour profiter de l'énorme popularité de Java à l'époque — un coup de marketing qui seme la confusion chez les débutants depuis près de trente ans ! Son nom officiel standardisé est d'ailleurs \emph{ECMAScript}.
\end{savaistu}

\courssub{Insertion d'un script dans un document HTML}

Tout script JavaScript placé dans une page HTML est délimité par la balise \texttt{<script>} et sa balise fermante \texttt{</script>}. Reste à savoir \emph{où} la placer : il existe trois emplacements possibles, chacun avec son usage.

\begin{propriete}[Syntaxe générale de la balise script]
Script interne (code écrit dans la page) :
\begin{lstlisting}[language=HTML]
<script>
    // instructions JavaScript
</script>
\end{lstlisting}
Script externe (code dans un fichier séparé) :
\begin{lstlisting}[language=HTML]
<script src="monscript.js"></script>
\end{lstlisting}
L'attribut \texttt{src} (source) indique le chemin du fichier externe, de la même façon que pour une image.
\end{propriete}

\courssub{Insertion dans l'en-tête}

Le script est placé entre \texttt{<head>} et \texttt{</head>}. Il est chargé \emph{avant} le contenu de la page. C'est l'emplacement idéal pour les \textbf{fonctions réutilisables} qui seront appelées plus tard, par exemple au clic sur un bouton : elles sont déjà en mémoire quand l'utilisateur agit.

\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <title>Boutique d'Aminatou</title>
    <script>
        // Fonction définie dans l'en-tête, prête à l'emploi
        function saluer() {
            alert("Bienvenue dans ma boutique !");
        }
    </script>
</head>
<body>
    <h1>Boutique d'Aminatou</h1>
</body>
</html>
\end{lstlisting}

\courssub{Insertion dans le corps}

Le script est placé dans \texttt{<body>}, à l'endroit exact où l'on veut qu'il s'exécute. Il est exécuté \textbf{immédiatement}, au moment où le navigateur le rencontre pendant l'affichage de la page. C'est l'emplacement adapté à une exécution immédiate, par exemple écrire du texte dans la page.

\begin{lstlisting}[language=HTML]
<body>
    <h1>Nos produits</h1>
    <script>
        // Exécute pendant l'affichage de la page
        document.write("<p>Promotions du jour !</p>");
    </script>
    <p>Livraison partout à Douala.</p>
</body>
</html>
\end{lstlisting}

\courssub{Insertion d'un fichier externe}

Le code est écrit dans un fichier séparé, par exemple \texttt{boutique.js}, et la page y fait référence grâce à l'attribut \texttt{src}. C'est la méthode \textbf{professionnelle} : le même script peut servir dans dix pages (réutilisabilité), et le code JavaScript reste séparé du code HTML, ce qui rend le site plus facile à maintenir.

Fichier \texttt{boutique.js} :
\begin{lstlisting}[language=JavaScript]
// Fichier externe : pas de balise <script> ici !
function verifierQuantite() {
    alert("Vérification de la quantité...");
}
\end{lstlisting}

Page HTML qui l'utilise :
\begin{lstlisting}[language=HTML]
<head>
    <meta charset="utf-8">
    <title>Commande</title>
    <script src="boutique.js"></script>
</head>
\end{lstlisting}

\begin{methode}[Choisir l'emplacement du script]
\begin{enumerate}
\item Le script contient des \textbf{fonctions} appelées par des évènements (clics, survols) ? $\rightarrow$ place-le dans l'\textbf{en-tête} (\texttt{<head>}), afin qu'elles soient chargées avant toute action de l'utilisateur.
\item Le script doit s'exécuter \textbf{au moment de l'affichage} (écrire dans la page, message de bienvenue) ? $\rightarrow$ place-le dans le \textbf{corps} (\texttt{<body>}), à l'endroit voulu.
\item Le même script sert dans \textbf{plusieurs pages} ? $\rightarrow$ crée un \textbf{fichier externe} \texttt{.js} et lie-le avec \texttt{src} dans chaque page.
\end{enumerate}
\end{methode}

\begin{attention}[Erreurs fréquentes avec la balise script]
\begin{itemize}
\item \textbf{Oublier la balise fermante} \texttt{</script>} : tout le contenu qui suit est alors considéré comme du JavaScript et la page ne s'affiche plus correctement.
\item \textbf{Écrire \texttt{scr} au lieu de \texttt{src}} dans \texttt{<script src="...">} : le fichier externe n'est jamais chargé, et aucune erreur visible ne s'affiche — le script semble « ignoré ».
\item Mettre des balises \texttt{<script>} \emph{à l'intérieur} du fichier \texttt{.js} : le fichier externe ne contient que du code JavaScript pur.
\item Oublier que JavaScript est \textbf{sensible à la casse} : \texttt{Alert} n'existe pas, seul \texttt{alert} fonctionne.
\item Utiliser \texttt{document.write()} \textbf{après le chargement de la page} (dans un gestionnaire d'évènement par exemple) : cela efface tout le contenu de la page pour la réécrire. Réserve \texttt{document.write()} aux scripts s'exécutant \emph{pendant} l'analyse initiale du HTML.
\end{itemize}
\end{attention}

\courssub{Premier script : alert() et document.write()}

Deux instructions de sortie suffisent pour débuter :
\begin{itemize}
\item \texttt{alert("message")} affiche une \textbf{boîte de dialogue} avec un bouton OK ; elle bloque la page jusqu'au clic de l'utilisateur. Idéale pour les avertissements (« Champ téléphone vide ! »).
\item \texttt{document.write("texte")} \textbf{écrit directement dans la page HTML}, à l'endroit où se trouve le script (uniquement pendant le chargement initial).
\end{itemize}

\begin{experience}[TP guidé : mon premier script]
\textbf{Objectif :} afficher un message de bienvenue et écrire une ligne dans la page d'accueil de la boutique.

\textbf{Matériel :} un ordinateur avec un éditeur de texte (Notepad++, VS Code) et un navigateur (Chrome, Firefox).

\textbf{Manipulation :}
\begin{enumerate}
\item Ouvre l'éditeur et saisis le code suivant :
\end{enumerate}
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html>
<head>
    <meta charset="utf-8">
    <title>Premier script</title>
    <script>
        // Boîte de dialogue affichée au chargement
        alert("Bienvenue chez Aminatou !");
    </script>
</head>
<body>
    <h1>Ma boutique en ligne</h1>
    <script>
        // Écriture directe dans la page
        document.write("<p>Ouvert du lundi au samedi.</p>");
    </script>
</body>
</html>
\end{lstlisting}
\begin{enumerate}
\item[2.] Enregistre le fichier sous le nom \texttt{index.html} (type « Tous les fichiers », encodage UTF-8).
\item[3.] Double-clique sur le fichier : il s'ouvre dans le navigateur.
\end{enumerate}

\textbf{Observations :} une boîte de dialogue « Bienvenue chez Aminatou ! » apparaît d'abord (script de l'en-tête) ; après le clic sur OK, la page s'affiche avec le titre et la ligne « Ouvert du lundi au samedi. » (script du corps).

\textbf{Interprétation :} le navigateur a exécuté les deux scripts localement, dans l'ordre où il les a rencontrés, sans aucun serveur — la preuve : le fichier fonctionne même hors connexion.

\begin{exoresolu}[Insertion correcte d'un fichier externe]
Énoncé : Aminatou a écrit le code ci-dessous, mais le message ne s'affiche jamais. Trouve les deux erreurs et corrige-les.
\begin{lstlisting}[language=HTML]
<head>
    <script scr="accueil.js">
</head>
\end{lstlisting}
\tcblower
Solution détaillée :
\begin{enumerate}
\item \textbf{Première erreur :} l'attribut est mal orthographié : \texttt{scr} au lieu de \texttt{src}. Le navigateur ne trouve donc aucun fichier à charger.
\item \textbf{Deuxième erreur :} la balise fermante \texttt{</script>} est absente. Même pour un fichier externe (dont le corps est vide), la balise fermante est \emph{obligatoire}.
\end{enumerate}
Code corrigé :
\begin{lstlisting}[language=HTML]
<head>
    <script src="accueil.js"></script>
</head>
\end{lstlisting}
Le fichier \texttt{accueil.js} doit se trouver dans le même dossier que la page HTML, sinon il faut indiquer le chemin complet (par exemple \texttt{src="js/accueil.js"}).
\end{exoresolu}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Un \cle{script} est un programme en langage interprété, exécuté directement par le navigateur sans compilation.
\item Un \cle{évènement} (clic, survol, chargement...) déclenche l'exécution d'un code JavaScript.
\item JavaScript est interprété, côté client, orienté objet, faiblement typé et indépendant du serveur ; il rend les pages interactives mais reste visible, désactivable et sans accès aux fichiers du client.
\item Trois insertions possibles : en-tête (fonctions réutilisables), corps (exécution immédiate), fichier externe via \texttt{<script src="fichier.js"></script>} (mutualisation).
\item \texttt{alert()} affiche une boîte de dialogue ; \texttt{document.write()} écrit dans la page (pendant le chargement).
\end{itemize}
\end{aretenir}

\coursec{Variables, constantes, types et opérateurs}

Dans la section précédente, nous avons appris à insérer un script JavaScript dans une page HTML et à le déclencher grâce à un évènement comme \texttt{onClick}. Mais un script qui ne fait qu'afficher un message fixe reste limité. Un vrai programme doit pouvoir \emph{mémoriser} des informations : le prix d'un article dans la boutique en ligne, la note d'un élève, le nom du visiteur. C'est précisément le rôle des \cle{variables}. Et pour transformer ces informations (calculer une moyenne, comparer deux montants, décider si un élève est admis), il faut des \cle{opérateurs}. Cette section pose donc les fondations de tout programme JavaScript.

\courssub{Variables et constantes}

\textbf{Intuition.} Imagine une étagère de boîtes étiquetées dans un magasin de Douala : chaque boîte porte un nom (son étiquette) et contient une valeur (son contenu). Tu peux ouvrir la boîte pour lire le contenu ou le remplacer. En informatique, ces boîtes sont des cases de la mémoire vive de l'ordinateur.

\begin{definition}[Variable et constante]
Une \cle{variable} est une \textbf{zone de la mémoire nommée} (on lui donne un identificateur) dont le \textbf{contenu peut varier} au cours de l'exécution du programme. Une \cle{constante} est une zone de la mémoire nommée dont le contenu est \textbf{fixé une fois pour toutes à la déclaration} : toute tentative de modification ultérieure provoque une erreur.
\end{definition}

\textbf{Déclaration.} En JavaScript, on déclare une variable avec le mot-clé \texttt{var} (programme officiel), suivi du nom, puis on lui affecte une valeur avec \texttt{=}. On peut déclarer et initialiser en une seule instruction. Le mot-clé \texttt{let}, introduit plus tard dans le langage, joue le même rôle que \texttt{var} avec une portée plus fine (complément utile pour le Bac). Les constantes se déclarent avec \texttt{const} et doivent être initialisées immédiatement.

\begin{lstlisting}[language=JavaScript]
var nom = "Amina";        // variable chaine de caracteres
var age = 16;             // variable numerique
var note;                 // declaree mais pas encore initialisee
note = 14.5;              // affectation ulterieure
let ville = "Yaounde";    // equivalent moderne de var
const PI = 3.14159;       // constante : valeur definitive
const TAUX_TVA = 0.1925;  // TVA du Cameroun : 19,25 %
// PI = 3.14;             // ERREUR : une constante ne se modifie pas
\end{lstlisting}

\begin{propriete}[Règles de nommage des identificateurs]
Le nom d'une variable ou d'une constante en JavaScript obéit aux règles suivantes :
\begin{itemize}
\item il est composé uniquement de \textbf{lettres} (a--z, A--Z), de \textbf{chiffres} (0--9) et du caractère \textbf{souligné} \texttt{\_} ;
\item il ne doit \textbf{jamais commencer par un chiffre} ;
\item JavaScript est \textbf{sensible à la casse} : \texttt{note}, \texttt{Note} et \texttt{NOTE} sont trois variables \emph{différentes} ;
\item les mots réservés du langage (\texttt{var}, \texttt{if}, \texttt{for}, \texttt{function}\ldots) sont interdits.
\end{itemize}
Par convention, on écrit les noms en minuscules avec une majuscule à chaque nouveau mot : \texttt{prixUnitaire}, \texttt{nombreEleves}.
\end{propriete}

\begin{attention}[Noms invalides]
\texttt{2note} est refusé (commence par un chiffre), \texttt{prix-unitaire} est refusé (le tiret est interprété comme une soustraction), \texttt{ma note} est refusé (espace interdit). Et surtout : si tu déclares \texttt{Moyenne} puis écris \texttt{moyenne} plus loin, JavaScript ne signalera pas toujours l'erreur clairement et ton programme se comportera bizarrement. Vérifie l'orthographe exacte de tes identificateurs !
\end{attention}

\courssub{Les types de base en JavaScript}

Chaque valeur manipulée possède un \cle{type}. Le programme officiel en retient trois :

\begin{itemize}
\item \cle{number} : les nombres, entiers (\texttt{42}, \texttt{-7}) ou réels (\texttt{14,5}, \texttt{0,1925}). Attention : le séparateur décimal est le \textbf{point}, jamais la virgule ;
\item \cle{string} : les chaînes de caractères, délimitées par des guillemets doubles ou simples : \texttt{"Bonjour"}, \texttt{'Cameroun'} ;
\item \cle{boolean} : les valeurs logiques, qui ne peuvent être que \texttt{true} (vrai) ou \texttt{false} (faux).
\end{itemize}

\begin{propriete}[Typage faible et dynamique (admise)]
JavaScript est un langage \textbf{faiblement typé} : on ne déclare jamais le type d'une variable. Le type est \textbf{déterminé automatiquement au moment de l'affectation}, et il \textbf{peut changer} au cours du programme. Ainsi, après \texttt{var x = 5;} la variable \texttt{x} est un \texttt{number} ; après \texttt{x = "cinq";} elle devient une \texttt{string}. C'est souple, mais source d'erreurs : il faut toujours savoir ce que contient une variable avant de l'utiliser.
\end{propriete}

\begin{lstlisting}[language=JavaScript]
var x = 5;        // x est de type number
x = "cinq";       // x devient de type string (autorise !)
var admis = true; // admis est de type boolean
\end{lstlisting}

\courssub{Les opérateurs arithmétiques}

Les opérateurs arithmétiques réalisent les calculs sur les nombres. Ce sont : \texttt{+} (addition), \texttt{-} (soustraction), \texttt{*} (multiplication), \texttt{/} (division) et \texttt{\%} (\cle{modulo} : reste de la division entière).

\begin{exemplebox}[Le modulo, l'opérateur méconnu]
Le modulo \texttt{a \% b} donne le \textbf{reste} de la division entière de \texttt{a} par \texttt{b}. Il est très utilisé, par exemple pour tester la parité d'un nombre.
\begin{lstlisting}[language=JavaScript]
var a = 5, b = 2;
var q = a / b;   // q vaut 2.5 (division reelle)
var r = a % b;   // r vaut 1 (reste de 5 divise par 2)
var p = 14 % 2;  // p vaut 0 : 14 est pair
var i = 15 % 2;  // i vaut 1 : 15 est impair
\end{lstlisting}
\end{exemplebox}

\courssub{L'opérateur d'assignation et ses formes combinées}

L'opérateur \texttt{=} ne signifie pas « est égal à » mais « \textbf{reçoit} » : l'instruction \texttt{x = x + 1;} se lit « \texttt{x} reçoit l'ancienne valeur de \texttt{x} augmentée de 1 ». Le membre de droite est évalué d'abord, puis rangé dans la variable de gauche.

Comme on modifie très souvent une variable à partir de sa propre valeur, JavaScript offre des formes combinées : \texttt{+=}, \texttt{-=}, \texttt{*=}, \texttt{/=}, ainsi que \texttt{++} (incrémentation : ajouter 1) et \texttt{--} (décrémentation : retirer 1).

\begin{methode}[Accumuler une valeur]
Pour accumuler des montants (total d'une facture, somme de notes), la démarche est toujours la même :
\begin{enumerate}
\item initialiser l'accumulateur à zéro : \texttt{var total = 0;}
\item à chaque nouvelle valeur, écrire \texttt{total += prix;} qui est \textbf{strictement équivalent} à \texttt{total = total + prix;}
\item lire \texttt{total} à la fin.
\end{enumerate}
\begin{lstlisting}[language=JavaScript]
var total = 0;
total += 1500;  // total vaut 1500 (savon)
total += 2500;  // total vaut 4000 (huile)
total += 1000;  // total vaut 5000 (riz)
var compteur = 0;
compteur++;     // compteur vaut 1
compteur++;     // compteur vaut 2
\end{lstlisting}
\end{methode}

\courssub{Les opérateurs de comparaison}

Les opérateurs de comparaison comparent deux valeurs et produisent un \textbf{booléen} (\texttt{true} ou \texttt{false}) : \texttt{==} (égal), \texttt{!=} (différent), \texttt{<} (strictement inférieur), \texttt{>} (strictement supérieur), \texttt{<=} (inférieur ou égal), \texttt{>=} (supérieur ou égal). On mentionne aussi \texttt{===} (égalité stricte, qui compare en plus le type) : \texttt{5 == "5"} vaut \texttt{true} (conversion automatique) alors que \texttt{5 === "5"} vaut \texttt{false} (complément utile pour le Bac).

\begin{attention}[Le piège classique : = contre ==]
Dans un test, confondre \texttt{=} (affectation) et \texttt{==} (comparaison) est l'erreur la plus fréquente du débutant. Écrire \texttt{if (note = 10)} ne compare pas : cela \emph{affecte} 10 à \texttt{note}, et le test est alors toujours vrai ! Pour comparer, il faut impérativement le double égal : \texttt{if (note == 10)}.
\end{attention}

\courssub{Les opérateurs logiques}

Les opérateurs logiques combinent des conditions booléennes : \texttt{\&\&} (ET logique), \texttt{||} (OU logique), \texttt{!} (NON logique). Par exemple, un élève est admis au Probatoire si sa moyenne est supérieure ou égale à 10 \emph{et} sa conduite jugée satisfaisante : \texttt{(moyenne >= 10) \&\& (conduite == true)}.

\courssub{La concaténation et le piège de l'opérateur +}

L'opérateur \texttt{+} a un comportement double : avec deux nombres, il \textbf{additionne} ; dès que l'un des deux opérandes est une chaîne, il \textbf{concatène} (colle les textes bout à bout).

\begin{exemplebox}[Addition ou concaténation ?]
\begin{lstlisting}[language=JavaScript]
var nom = "Amina";
var message = "Bonjour " + nom;   // "Bonjour Amina" (concatenation)
var x = 5 + 2;                    // 7 (addition : deux nombres)
var y = "5" + 2;                  // "52" (concatenation : "5" est une chaine)
var z = "5" + 2 + 3;              // "523" (de gauche a droite)
var w = 5 + 2 + "3";              // "73" (5+2=7 d'abord, puis collage)
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Le piège du + avec les saisies]

Nous verrons dans la section suivante comment convertir avec \texttt{parseInt()} et \texttt{parseFloat()} avant tout calcul.
\end{attention}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Une variable se déclare avec \texttt{var} (ou \texttt{let}), une constante avec \texttt{const} ; les noms respectent des règles strictes et la casse compte.
\item Les trois types de base sont \texttt{number}, \texttt{string} et \texttt{boolean} ; JavaScript est faiblement typé : le type suit la valeur affectée.
\item \texttt{\%} donne le reste de la division entière ; \texttt{==} compare, \texttt{=} affecte ; \texttt{\&\&}, \texttt{||}, \texttt{!} combinent les conditions.
\item \texttt{total += prix;} est la forme courte de \texttt{total = total + prix;}.
\item \texttt{+} additionne deux nombres mais concatène dès qu'une chaîne est présente : \texttt{"5" + 2} donne \texttt{"52"}.
\end{itemize}
\end{aretenir}

\begin{exoresolu}[Facture d'une boutique scolaire]
Énoncé. Une librairie de Bafoussam vend 3 cahiers à 500 FCFA l'unité et 2 stylos à 150 FCFA l'unité. Écrire les instructions JavaScript qui calculent le montant total, puis déterminent si l'achat dépasse 2000 FCFA (booléen \texttt{depassement}), et affichent un message du type « Total : 1800 FCFA ». Que vaut \texttt{total \% 1000} ?
\tcblower
Solution détaillée. On déclare les quantités et prix unitaires, on calcule le total par accumulation, puis on compare.
\begin{lstlisting}[language=JavaScript]
var nbCahiers = 3, prixCahier = 500;
var nbStylos = 2, prixStylo = 150;
var total = 0;
total += nbCahiers * prixCahier;  // total = 1500
total += nbStylos * prixStylo;    // total = 1800
var depassement = total > 2000;   // false : 1800 n'excede pas 2000
var message = "Total : " + total + " FCFA";
// message vaut "Total : 1800 FCFA" (concatenation)
var reste = total % 1000;         // reste de 1800 / 1000 : 800
\end{lstlisting}
Vérifications : $3 \times 500 = 1500$, $2 \times 150 = 300$, $1500 + 300 = 1800$. La comparaison \texttt{1800 > 2000} est fausse, donc \texttt{depassement} vaut \texttt{false}. Enfin, $1800 = 1 \times 1000 + 800$, donc \texttt{total \% 1000} vaut $800$. Remarque le mélange dans \texttt{message} : \texttt{"Total : "} étant une chaîne, le \texttt{+} concatène le nombre 1800 au lieu de l'additionner.
\end{exoresolu}

\coursec{Instructions simples : entrées, sorties et conversions}

Dans la section précédente, tu as appris à déclarer des variables et des constantes, à choisir leur type et à manipuler les opérateurs. Mais un programme qui ne fait que calculer en silence, avec des valeurs écrites « en dur » dans le code, ne sert à rien. Imagine le site d'une boutique de Douala : le client doit pouvoir \emph{saisir} la quantité d'articles qu'il commande, et la page doit lui \emph{afficher} le montant total. Toute application interactive repose donc sur trois gestes fondamentaux : \textbf{lire} une donnée (entrée), la \textbf{transformer} (calcul), puis la \textbf{restituer} (sortie). Cette section t'apprend à réaliser ces trois gestes en JavaScript, et surtout à éviter le piège le plus célèbre du débutant : la confusion entre chaîne de caractères et nombre.

\courssub{L'affectation : stocker le résultat d'une expression}

\begin{definition}[Affectation]
L'\cle{affectation} est l'instruction qui consiste à \textbf{évaluer une expression} (à droite du signe \texttt{=}) puis à \textbf{stocker le résultat dans une variable} (à gauche du signe \texttt{=}). En JavaScript, sa syntaxe est :
\begin{lstlisting}[language=JavaScript]
variable = expression ;
\end{lstlisting}
\end{definition}

L'ordre des opérations est capital et toujours le même, dans \emph{tous} les langages de programmation :

\begin{enumerate}
\item le moteur JavaScript \textbf{évalue} d'abord l'expression située à droite du \texttt{=} (calculs, appels de fonctions, concaténations...) ;
\item le résultat obtenu est ensuite \textbf{rangé} dans la variable située à gauche, en écrasant son ancienne valeur.
\end{enumerate}

\begin{exemplebox}[Lecture d'affectations]
\begin{lstlisting}[language=JavaScript]
let prixUnitaire = 1500;          // on stocke 1500
let quantite = 3;                 // on stocke 3
let total = prixUnitaire * quantite; // on évalue 1500*3, puis on stocke 4500
total = total + 500;              // on évalue 4500+500, puis on stocke 5000
\end{lstlisting}
La dernière ligne n'est \textbf{pas} une équation mathématique : elle signifie « prends la valeur actuelle de \texttt{total}, ajoute 500, et remets le résultat dans \texttt{total} ». Après exécution, \texttt{total} vaut 5000.
\end{exemplebox}

\begin{attention}[Le signe = n'est pas une égalité mathématique]
En JavaScript, \texttt{=} est l'opérateur d'\textbf{affectation}, pas de comparaison. Écrire \texttt{total = 500} modifie la variable ; pour \emph{tester} une égalité, on utilise \texttt{==} ou \texttt{===} (vu dans la section précédente). Écrire \texttt{if (total = 500)} au lieu de \texttt{if (total === 500)} est un bug classique : la condition sera toujours vraie et la variable sera écrasée !
\end{attention}

\courssub{Les sorties : communiquer un résultat à l'utilisateur}

Un programme qui calcule sans rien montrer est inutile. JavaScript côté client offre trois moyens principaux de sortie, chacun ayant son usage propre.

\textbf{1. La boîte de dialogue \texttt{alert()}.}

\begin{propriete}[Syntaxe de alert()]
\begin{lstlisting}[language=JavaScript]
alert(message);
\end{lstlisting}
\texttt{alert()} ouvre une \textbf{boîte de dialogue modale} (qui bloque la page tant que l'utilisateur n'a pas cliqué sur « OK ») affichant le \texttt{message}. Le message peut être une chaîne littérale, une variable, ou une concaténation des deux.
\end{propriete}

\begin{lstlisting}[language=JavaScript]
let nom = "Amina";
alert("Bonjour " + nom + ", bienvenue sur notre site !");
// Affiche : Bonjour Amina, bienvenue sur notre site !
\end{lstlisting}

\textbf{2. L'écriture dans la page avec \texttt{document.write()}.}

\begin{propriete}[Syntaxe de document.write()]
\begin{lstlisting}[language=JavaScript]
document.write(texte);
\end{lstlisting}
\texttt{document.write()} écrit le \texttt{texte} \textbf{directement dans le corps du document HTML}, à l'endroit où le script est exécuté. Le texte peut contenir des balises HTML, qui seront interprétées par le navigateur.
\end{propriete}

\begin{lstlisting}[language=JavaScript]
let moyenne = 14,5;
document.write("Votre moyenne est : " + moyenne + " / 20");
document.write("<br>"); // <br> : saut de ligne HTML
document.write("<strong>Admis(e) !</strong>"); // balises interprétées
\end{lstlisting}

\begin{attention}[document.write() après le chargement de la page]
Si \texttt{document.write()} est appelé \emph{après} que la page a fini de se charger (par exemple dans une fonction déclenchée par un clic), il \textbf{efface tout le contenu existant} de la page avant d'écrire. On l'utilisera donc uniquement pendant le chargement initial, ou à des fins de test. Pour modifier une page déjà affichée, on préférera \texttt{getElementById()} (vu en section 6).
\end{attention}

\textbf{3. Le débogage avec \texttt{console.log()}.}

\begin{propriete}[Syntaxe de console.log()]
\begin{lstlisting}[language=JavaScript]
console.log(valeur);
\end{lstlisting}
\texttt{console.log()} affiche la \texttt{valeur} dans la \textbf{console du navigateur} (touche F12, onglet « Console »), invisible pour le visiteur. C'est l'outil préféré du programmeur pour \textbf{vérifier le contenu d'une variable} en cours d'exécution et traquer les bugs.
\end{propriete}

\begin{lstlisting}[language=JavaScript]
let a = 7, b = 3;
console.log("a =", a, " b =", b, " a/b =", a / b);
// Dans la console : a = 7  b = 3  a/b = 2,3333333333333335
\end{lstlisting}

\courssub{L'entrée : lire une donnée avec prompt()}

\begin{definition}[La fonction prompt()]
\cle{prompt()} ouvre une boîte de dialogue contenant un message et un champ de saisie, puis attend que l'utilisateur tape une valeur et valide. Sa syntaxe est :
\begin{lstlisting}[language=JavaScript]
variable = prompt(message, valeurParDefaut);
\end{lstlisting}
\begin{itemize}
\item \texttt{message} : le texte affiché pour guider l'utilisateur ;
\item \texttt{valeurParDefaut} (facultatif) : le texte pré-rempli dans le champ de saisie ;
\item la fonction \textbf{retourne} ce que l'utilisateur a tapé, que l'on stocke dans la \texttt{variable}.
\end{itemize}
\end{definition}

\begin{exemplebox}[Première saisie]
\begin{lstlisting}[language=JavaScript]
let ville = prompt("Dans quelle ville habites-tu ?", "Yaoundé");
alert("Tu habites à " + ville + ".");
\end{lstlisting}
Si l'utilisateur valide sans rien changer, \texttt{ville} contient \texttt{"Yaoundé"}. S'il tape « Bafoussam », \texttt{ville} contient \texttt{"Bafoussam"}.
\end{exemplebox}

\begin{aretenir}[La règle d'or de prompt()]
\texttt{prompt()} retourne \textbf{toujours une chaîne de caractères} (type \texttt{string}), même si l'utilisateur tape des chiffres. Taper \texttt{2000} dans la boîte de dialogue produit la \emph{chaîne} \texttt{"2000"}, pas le \emph{nombre} 2000. Si l'utilisateur clique sur « Annuler », \texttt{prompt()} retourne la valeur spéciale \texttt{null}.
\end{aretenir}

\courssub{La conversion : parseInt() et parseFloat()}

Voici le problème central de cette section. Puisque \texttt{prompt()} renvoie une chaîne, l'opérateur \texttt{+} appliqué à deux saisies réalise une \textbf{concaténation} et non une addition :

\begin{lstlisting}[language=JavaScript]
let a = prompt("Premier nombre :");   // l'utilisateur tape 2000
let b = prompt("Deuxième nombre :");  // l'utilisateur tape 500
alert(a + b); // Affiche "2000500" et NON 2500 !
\end{lstlisting}

Pour faire de vrais calculs, il faut donc \textbf{convertir} la chaîne saisie en nombre. JavaScript fournit deux fonctions prédéfinies pour cela.

\begin{propriete}[Syntaxe de parseInt() et parseFloat()]
\begin{lstlisting}[language=JavaScript]
nombreEntier = parseInt(chaine);   // conversion en entier
nombreReel   = parseFloat(chaine); // conversion en nombre réel
\end{lstlisting}
\begin{itemize}
\item \texttt{parseInt(chaine)} lit les chiffres au début de la chaîne et retourne un \textbf{nombre entier} : la partie décimale est ignorée (tronquée, pas arrondie) ;
\item \texttt{parseFloat(chaine)} lit les chiffres \textbf{et le point décimal} et retourne un \textbf{nombre réel} ;
\item si la chaîne ne commence par aucun chiffre valide, les deux fonctions retournent la valeur spéciale \cle{NaN} (\emph{Not a Number}).
\end{itemize}
\end{propriete}

\begin{exemplebox}[Exemples chiffrés de conversion]
\begin{lstlisting}[language=JavaScript]
parseInt("12.7");     // vaut 12     (partie décimale tronquée)
parseFloat("12.7");   // vaut 12,7   (réel conservé)
parseInt("abc");      // vaut NaN    (aucun chiffre au début)
parseInt("2500 FCFA");// vaut 2500   (lecture stoppée au premier espace)
parseFloat("3.14abc");// vaut 3,14   (lecture stoppée au premier caractère invalide)
parseInt("");         // vaut NaN    (chaîne vide)
\end{lstlisting}
Remarque bien le premier exemple : \texttt{parseInt("12.7")} donne 12 et non 13. Il n'y a \textbf{pas d'arrondi}, seulement une suppression de la partie décimale.
\end{exemplebox}

\begin{attention}[Erreur fréquente : additionner deux résultats de prompt()]
Le bug le plus classique du débutant est d'écrire directement :
\begin{lstlisting}[language=JavaScript]
let total = prompt("Prix 1 :") + prompt("Prix 2 :");
\end{lstlisting}
Avec les saisies 2000 et 500, \texttt{total} contient la chaîne \texttt{"2000500"} et non le nombre 2500, car \texttt{+} concatène deux chaînes. \textbf{Toute saisie numérique via prompt() doit passer par parseInt() ou parseFloat() avant tout calcul.}
\end{attention}

\begin{methode}[Lire correctement un nombre saisi par l'utilisateur]
Pour lire un nombre et pouvoir calculer avec, applique systématiquement cette démarche en trois étapes :
\begin{enumerate}
\item \textbf{Saisir} : récupère la réponse de \texttt{prompt()} dans une variable (c'est une chaîne) ;
\item \textbf{Convertir} : applique \texttt{parseInt()} (entier) ou \texttt{parseFloat()} (réel) à cette chaîne et stocke le résultat ;
\item \textbf{Calculer et afficher} : utilise le nombre obtenu dans tes expressions, puis affiche avec \texttt{alert()} ou \texttt{document.write()}.
\end{enumerate}
On peut condenser les étapes 1 et 2 en une seule ligne :
\begin{lstlisting}[language=JavaScript]
let age = parseInt(prompt("Quel est ton âge ?"));
\end{lstlisting}
\end{methode}

\begin{savaistu}[NaN est... un nombre !]
Voici une curiosité qui surprend tous les débutants : en JavaScript, la valeur \texttt{NaN} (\emph{Not a Number}) est elle-même de type \texttt{number} ! L'instruction \texttt{typeof NaN} retourne \texttt{"number"}. Autre bizarrerie : \texttt{NaN} n'est égal à rien, pas même à lui-même (\texttt{NaN === NaN} vaut \texttt{false}). Pour tester si une conversion a échoué, on utilise donc la fonction prédéfinie \texttt{isNaN(valeur)}, qui retourne \texttt{true} si la valeur n'est pas un nombre exploitable. C'est un outil précieux pour le contrôle de saisie que tu étudieras en section 6.
\end{savaistu}

\begin{exoresolu}[Somme de deux nombres saisis]
\textbf{Énoncé.} Le gérant d'un cybercafé de Bafoussam veut une petite page qui demande le prix de deux services (impression, connexion), calcule le total à payer et l'affiche. Écris le script JavaScript complet.
\tcblower
\textbf{Solution détaillée.} On applique la méthode en trois étapes : saisie, conversion, puis calcul et affichage.
\begin{lstlisting}[language=JavaScript]
// Étape 1 et 2 : saisie + conversion immédiate
let prixImpression = parseInt(prompt("Prix de l'impression (FCFA) :", "0"));

\end{lstlisting}
\textbf{Trace d'exécution} : si l'utilisateur saisit 2000 puis 500, \texttt{parseInt} produit les nombres 2000 et 500 ; l'addition donne 2500 ; la boîte de dialogue affiche « Total à payer : 2500 FCFA ». Sans \texttt{parseInt()}, on aurait obtenu « 2000500 FCFA ».
\end{exoresolu}

\end{corrige}

Tu maîtrises désormais le trio fondamental de tout programme interactif : \textbf{saisir}, \textbf{convertir}, \textbf{afficher}. La section suivante te montrera comment faire \emph{prendre des décisions} à ton script avec les structures alternatives (\texttt{if}, \texttt{if...else}) et comment \emph{répéter} des traitements avec les boucles (\texttt{for}, \texttt{while}, \texttt{do...while}) — de quoi rendre tes pages vraiment intelligentes.

\coursec{Structures alternatives et boucles}

Dans la section précédente, nous avons appris à réaliser des \cle{instructions simples} : affectation, saisie avec \texttt{prompt()}, affichage avec \texttt{alert()} ou \texttt{document.write()}, et conversions avec \texttt{parseInt()} et \texttt{parseFloat()}. Mais un programme qui ne fait qu'exécuter des instructions les unes après les autres, dans l'ordre, reste très limité. Imagine le site de notes de ton lycée : il doit afficher « Admis » si la moyenne est supérieure ou égale à 10, et « Ajourné » sinon. Ou encore un cybercafé de Bonabéri qui doit calculer le montant dû par 50 clients : on ne va pas écrire 50 fois le même calcul ! Il faut donc des instructions capables de \cle{choisir} (les structures alternatives) et de \cle{répéter} (les boucles). C'est l'objet de cette section.

\courssub{La structure alternative simple : \texttt{if}}

\begin{definition}[Structure alternative simple]
La structure alternative simple \cle{if} permet d'exécuter un bloc d'instructions \emph{uniquement si} une condition est vraie. Si la condition est fausse, le bloc est simplement ignoré et le programme continue après l'accolade fermante.
\end{definition}

\begin{propriete}[Syntaxe du \texttt{if} simple]
\begin{lstlisting}[language=JavaScript]
if (condition) {
    // instructions executees si condition est vraie
}
\end{lstlisting}
La \texttt{condition} est une expression booléenne (utilisant les opérateurs de comparaison \texttt{==}, \texttt{!=}, \texttt{<}, \texttt{<=}, \texttt{>}, \texttt{>=} et les opérateurs logiques \texttt{\&\&}, \texttt{||}, \texttt{!}). Les parenthèses autour de la condition sont \textbf{obligatoires}. Si le bloc ne contient qu'une seule instruction, les accolades peuvent être omises, mais il est fortement conseillé de les mettre toujours pour la lisibilité et la prévention d'erreurs.
\end{propriete}

\begin{exemplebox}[Majorité d'un client]
\begin{lstlisting}[language=JavaScript]
let age = parseInt(prompt("Quel est votre age ?"));
if (age >= 18) {
    alert("Vous etes majeur.");
}
alert("Merci de votre visite !");
\end{lstlisting}
Si l'utilisateur saisit 20, les deux messages s'affichent. S'il saisit 15, seul le second message apparaît : le bloc du \texttt{if} est sauté.
\end{exemplebox}

\begin{attention}[Valeur \texttt{NaN} et comparaisons]
Si l'utilisateur annule la boîte de dialogue ou saisit du texte, \texttt{parseInt} renvoie \texttt{NaN} (Not a Number). Toute comparaison avec \texttt{NaN} (\texttt{NaN >= 18}, \texttt{NaN == NaN}) renvoie \texttt{false}. Le bloc \texttt{if} ne s'exécute pas, ce qui peut masquer une erreur de saisie. En pratique, on teste souvent \texttt{isNaN(age)} avant de comparer.
\end{attention}

\courssub{La structure alternative complète : \texttt{if...else}}

Très souvent, on ne veut pas seulement faire quelque chose « si c'est vrai », mais aussi faire \emph{autre chose} « si c'est faux ». C'est le cas du couple Admis/Ajourné évoqué plus haut.

\begin{definition}[Structure alternative complète]
La structure \cle{if...else} exécute un premier bloc si la condition est vraie, et un second bloc (exclusif du premier) si elle est fausse. \textbf{Un seul des deux blocs est toujours exécuté.}
\end{definition}

\begin{propriete}[Syntaxe du \texttt{if...else}]
\begin{lstlisting}[language=JavaScript]
if (condition) {
    // instructions si condition VRAIE
} else {
    // instructions si condition FAUSSE
}
\end{lstlisting}
Le mot-clé \texttt{else} ne porte jamais de condition : il signifie « dans tous les autres cas ».
\end{propriete}

\begin{exemplebox}[Décision du jury]
\begin{lstlisting}[language=JavaScript]
let moyenne = parseFloat(prompt("Entrez la moyenne :"));
if (moyenne >= 10) {
    alert("Admis(e) ! Felicitations.");
} else {
    alert("Ajourne(e). Courage pour la prochaine fois.");
}
\end{lstlisting}
\end{exemplebox}

\courssub{Tests imbriqués et enchaînement \texttt{else if}}

Que faire quand il y a \emph{plus de deux cas} ? Par exemple, la mention au Probatoire : Ajourné, Passable, Assez Bien, Bien, Très Bien. On peut imbriquer des \texttt{if} dans des \texttt{else}, mais l'enchaînement \texttt{else if} est plus lisible : les conditions sont testées \textbf{dans l'ordre}, et dès qu'une condition est vraie, son bloc est exécuté et tout le reste est ignoré.

\begin{exemplebox}[Mentions au Probatoire]
\begin{lstlisting}[language=JavaScript]
let moy = parseFloat(prompt("Moyenne generale :"));
if (moy < 10) {
    alert("Ajourne");
} else if (moy < 12) {
    alert("Mention Passable");
} else if (moy < 14) {
    alert("Mention Assez Bien");
} else if (moy < 16) {
    alert("Mention Bien");
} else {
    alert("Mention Tres Bien");
}
\end{lstlisting}
L'ordre des tests est crucial : comme on teste d'abord \texttt{moy < 10}, dans le premier \texttt{else if} on sait déjà que \texttt{moy >= 10}, il suffit donc de vérifier \texttt{moy < 12}.
\end{exemplebox}

\begin{attention}[Le point-virgule assassin]
Ne place \textbf{jamais} de point-virgule juste après la parenthèse d'un \texttt{if} ou d'un \texttt{while} :
\begin{lstlisting}[language=JavaScript]
if (moy >= 10);   // ERREUR : le ; termine le if !
{
    alert("Admis"); // s'execute TOUJOURS, meme si moy < 10
}
\end{lstlisting}
Le point-virgule est interprété comme une instruction vide : le \texttt{if} ne contrôle plus rien, et le bloc entre accolades s'exécute dans tous les cas. C'est l'un des bugs les plus fréquents et les plus difficiles à repérer, car le code ne produit aucun message d'erreur syntaxique.
\end{attention}

\courssub{La boucle \texttt{for} : un nombre de tours connu}

Pour afficher la table de multiplication de 7, on pourrait écrire dix lignes presque identiques. La boucle \cle{for} permet d'écrire le calcul \emph{une seule fois} et de le répéter un nombre de fois déterminé à l'avance.

\begin{propriete}[Syntaxe de la boucle \texttt{for}]
\begin{lstlisting}[language=JavaScript]
for (initialisation ; condition ; increment) {
    // instructions repetees
}
\end{lstlisting}
Le déroulement est précisément le suivant :
\begin{enumerate}
\item l'\textbf{initialisation} est exécutée \emph{une seule fois}, au départ (ex. \texttt{let i = 1}) ;
\item la \textbf{condition} est testée : si elle est fausse, la boucle s'arrête immédiatement ;
\item si la condition est vraie, le \textbf{corps} de la boucle s'exécute ;
\item l'\textbf{incrément} est exécuté (ex. \texttt{i++}), puis on retourne à l'étape 2.
\end{enumerate}
L'utilisation de \texttt{let} pour le compteur (au lieu de \texttt{var}) limite sa portée au bloc de la boucle, ce qui évite des effets de bord indésirables.
\end{propriete}

\begin{exemplebox}[Table de multiplication de 7]
\begin{lstlisting}[language=JavaScript]
for (let i = 1; i <= 10; i++) {
    document.write("7 x " + i + " = " + (7 * i) + "<br>");
}
\end{lstlisting}
Ce script affiche les dix lignes \texttt{7 x 1 = 7} jusqu'à \texttt{7 x 10 = 70}. La variable \texttt{i} est appelée \cle{compteur} de la boucle ; \texttt{i++} est un raccourci pour \texttt{i = i + 1}.
\end{exemplebox}

\courssub{La boucle \texttt{while} : répéter tant qu'une condition est vraie}

Parfois, on ne sait pas à l'avance combien de tours seront nécessaires : on veut simplement continuer \emph{tant qu'}une condition reste vraie. Par exemple, redemander un mot de passe tant que la saisie est incorrecte.

\begin{propriete}[Syntaxe de la boucle \texttt{while}]
\begin{lstlisting}[language=JavaScript]
while (condition) {
    // instructions repetees tant que condition est vraie
}
\end{lstlisting}
La condition est testée \textbf{avant} chaque tour. Si elle est fausse dès le départ, le corps n'est exécuté \textbf{aucune fois}. Il est indispensable que le corps contienne une instruction qui fasse évoluer la condition, sinon la boucle ne s'arrêtera jamais.
\end{propriete}

\begin{exemplebox}[Saisie contrôlée d'un mot de passe]
\begin{lstlisting}[language=JavaScript]
let mdp = prompt("Entrez le mot de passe :");
while (mdp != "ti2024") {
    mdp = prompt("Incorrect. Reessayez :");
}
alert("Acces autorise !");
\end{lstlisting}
Ici, le nombre de tentatives est inconnu à l'avance : c'est exactement le domaine de la boucle \texttt{while}. Remarque la nouvelle affectation de \texttt{mdp} dans le corps : c'est elle qui permet à la condition d'évoluer.
\end{exemplebox}

\courssub{La boucle \texttt{do...while} : exécuter au moins une fois}

La boucle \cle{do...while} est une variante de \texttt{while} dans laquelle le test est effectué \textbf{après} le corps. Conséquence fondamentale : le corps s'exécute \textbf{au moins une fois}, même si la condition est fausse dès le départ.

\begin{propriete}[Syntaxe de la boucle \texttt{do...while}]
\begin{lstlisting}[language=JavaScript]
do {
    // instructions executees au moins une fois
} while (condition);
\end{lstlisting}
Attention au point-virgule \textbf{obligatoire} après \texttt{while (condition)} : c'est la seule boucle qui se termine ainsi.
\end{propriete}

\begin{exemplebox}[Saisie d'une note valide]
\begin{lstlisting}[language=JavaScript]
let note;
do {
    note = parseFloat(prompt("Note entre 0 et 20 :"));
} while (note < 0 || note > 20 || isNaN(note));
alert("Note enregistree : " + note);
\end{lstlisting}
On doit demander la note au moins une fois avant de pouvoir la tester : le \texttt{do...while} est le choix naturel. L'ajout de \texttt{isNaN(note)} protège contre une saisie non numérique (annulation ou texte).
\end{exemplebox}

\courssub{Choisir sa boucle et éviter la boucle infinie}

\begin{methode}[Quelle boucle choisir ?]
\begin{enumerate}
\item \textbf{Le nombre de tours est connu à l'avance} (afficher 10 lignes, traiter 30 élèves, somme des $n$ premiers entiers) : utilise la boucle \cle{for}, qui regroupe initialisation, test et incrément sur une seule ligne.
\item \textbf{L'arrêt dépend d'une condition et le corps peut ne jamais s'exécuter} (tant que le mot de passe est faux, tant que le stock n'est pas épuisé) : utilise la boucle \cle{while}.
\item \textbf{Le corps doit s'exécuter au moins une fois avant tout test} (saisir une valeur puis la valider) : utilise la boucle \cle{do...while}.
\end{enumerate}
En cas de doute entre \texttt{for} et \texttt{while}, pose-toi la question : « puis-je compter les tours avant de commencer ? ». Si oui : \texttt{for}. Si non : \texttt{while}.
\end{methode}

\begin{attention}[La boucle infinie]
Une boucle \texttt{while} (ou \texttt{for}) dont la condition n'est \textbf{jamais modifiée} dans le corps est une \cle{boucle infinie} : elle tourne sans fin et bloque l'onglet du navigateur, qui finit par proposer de « tuer » la page.
\begin{lstlisting}[language=JavaScript]
let i = 1;
while (i <= 5) {
    document.write(i + "<br>");
    // OUBLI de i++ : i reste a 1, boucle infinie !
}
\end{lstlisting}
Avant de tester ton script, vérifie toujours que chaque boucle contient une instruction qui rapproche la condition de la sortie (incrémentation, nouvelle saisie, modification d'un drapeau booléen, etc.).
\end{attention}

\courssub{Trace d'exécution : la somme des $n$ premiers entiers}

Pour être sûr qu'une boucle est correcte, les informaticiens réalisent une \cle{trace d'exécution} : ils déroulent le programme « à la main », en notant dans un tableau la valeur de chaque variable à chaque tour. C'est une compétence exigée au Probatoire.

\begin{propriete}[Somme des $n$ premiers entiers]
La boucle suivante calcule la somme $1 + 2 + \dots + n$ :
\begin{lstlisting}[language=JavaScript]
const n = 5;
let s = 0;
for (let i = 1; i <= n; i++) {
    s = s + i;
}
alert("La somme vaut " + s);
\end{lstlisting}
Vérifions par déroulement pour $n = 5$ que l'on obtient bien $s = 15$ (voir la trace ci-dessous). Ce résultat est conforme à la formule mathématique $\dfrac{n(n+1)}{2} = \dfrac{5 \times 6}{2} = 15$.
\end{propriete}

\begin{exoresolu}[Parité des nombres de 1 à 10]
Énoncé. Écris un script JavaScript qui affiche, pour chaque entier de 1 à 10, s'il est pair ou impair. On rappelle que \texttt{a \% b} donne le reste de la division de \texttt{a} par \texttt{b}.
\tcblower
Solution. Le nombre de tours est connu (10) : on choisit la boucle \texttt{for}. À l'intérieur, une structure alternative teste la parité grâce au reste de la division par 2.
\begin{lstlisting}[language=JavaScript]
for (let i = 1; i <= 10; i++) {
    if (i % 2 == 0) {
        document.write(i + " est pair<br>");
    } else {
        document.write(i + " est impair<br>");
    }
}
\end{lstlisting}
Trace partielle : pour \texttt{i = 1}, \texttt{1 \% 2} vaut 1, donc « 1 est impair » ; pour \texttt{i = 2}, \texttt{2 \% 2} vaut 0, donc « 2 est pair » ; et ainsi de suite jusqu'à \texttt{i = 10}. Ce script illustre l'\textbf{imbrication} d'une structure alternative dans une boucle, une combinaison très fréquente dans les programmes réels.
\end{exoresolu}

\begin{exercice}[Somme des pairs]
Écris un script qui calcule et affiche la somme des nombres pairs compris entre 1 et 100, puis vérifie ton résultat par la formule $2 + 4 + \dots + 100 = 2 \times (1 + 2 + \dots + 50) = 50 \times 51 = 2550$.
\end{exercice}

\begin{exercice}[Devinette]
Écris un script qui demande à l'utilisateur de deviner un nombre secret fixé (par exemple 7) en utilisant une boucle \texttt{do...while}, et qui affiche « Bravo ! » lorsque le nombre est trouvé. Pourquoi le \texttt{do...while} est-il ici préférable au \texttt{while} ?
\end{exercice}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item \texttt{if} exécute un bloc seulement si la condition est vraie ; \texttt{if...else} choisit entre deux blocs ; \texttt{else if} enchaîne plusieurs cas testés dans l'ordre.
\item \texttt{for (init ; condition ; incrément)} s'emploie quand le nombre de tours est connu ; \texttt{while} répète tant qu'une condition est vraie (corps éventuellement jamais exécuté) ; \texttt{do...while} exécute le corps au moins une fois.
\item Jamais de point-virgule juste après \texttt{if (...)} ou \texttt{while (...)} ; toujours une instruction qui fait évoluer la condition dans le corps d'une boucle, sous peine de boucle infinie.
\item La trace d'exécution (tableau des valeurs des variables tour par tour) est l'outil de vérification indispensable d'une boucle.
\item Privilégier \texttt{let} et \texttt{const} (portée de bloc) plutôt que \texttt{var} (portée de fonction) pour déclarer les variables et constantes modernes.
\end{itemize}
\end{aretenir}

\coursec{Tableaux, objets et fonctions}

Dans la section précédente, tu as appris à répéter des instructions avec les boucles \texttt{for}, \texttt{while} et \texttt{do...while}. Une question se pose alors naturellement : comment stocker les \cle{notes des 25 élèves} d'une classe de Première TI ? Créer 25 variables \texttt{note1}, \texttt{note2}, \ldots, \texttt{note25} serait absurde : impossible de les parcourir avec une boucle, puisque chaque nom est différent. Il nous faut une structure capable de regrouper plusieurs valeurs sous un \emph{seul} nom, repérées par un \emph{numéro}. Cette structure existe : c'est le \cle{tableau}. Et pour éviter de recopier dix fois le même calcul dans une page, JavaScript nous offre un second outil : la \cle{fonction}, un bloc d'instructions réutilisable à volonté. Cette section te donne ces deux piliers de la programmation, plus une introduction à la création d'objets avec l'opérateur \texttt{new}.

\courssub{Les tableaux en JavaScript}

\textbf{Le problème à résoudre.}\par
Le proviseur du lycée veut afficher sur le site de l'établissement la moyenne des notes de TI de la classe. Avec des variables ordinaires, il faudrait écrire \texttt{somme = n1 + n2 + n3 + ...} jusqu'à la dernière note : un cauchemar dès que la classe compte 40 élèves. Le tableau résout ce problème en donnant un \emph{nom unique} à l'ensemble et un \emph{indice numérique} à chaque valeur : la boucle \texttt{for} peut alors tout parcourir automatiquement.

\begin{definition}[Tableau]
Un \cle{tableau} est une structure de données qui regroupe plusieurs valeurs sous un même nom de variable. Chaque valeur est rangée dans une \cle{case} repérée par un \cle{indice} (un numéro de position). En JavaScript, \textbf{le premier élément porte toujours l'indice 0} : un tableau de $n$ éléments a des indices allant de $0$ à $n-1$.
\end{definition}

\begin{propriete}[Déclaration et initialisation d'un tableau]
Deux syntaxes équivalentes permettent de créer un tableau en JavaScript :
\begin{itemize}
  \item avec des \cle{crochets} (syntaxe la plus courante, dite \emph{littérale}) : \texttt{var notes = [12, 15, 9];}
  \item avec l'opérateur \texttt{new} et le constructeur \texttt{Array} : \texttt{var notes = new Array(12, 15, 9);}
\end{itemize}
On accède ensuite à un élément en écrivant le nom du tableau suivi de l'indice entre crochets : \texttt{notes[0]} vaut 12, \texttt{notes[1]} vaut 15, \texttt{notes[2]} vaut 9. On peut aussi \emph{modifier} une case : \texttt{notes[1] = 17;} remplace 15 par 17.
\end{propriete}

\begin{attention}[Piège du constructeur \texttt{Array} avec un seul argument numérique]
\texttt{new Array(5)} ne crée \textbf{pas} un tableau contenant le nombre 5, mais un tableau \emph{vide} de longueur 5 (5 cases \texttt{undefined}). Pour créer un tableau à un seul élément numérique, utilise obligatoirement la syntaxe à crochets : \texttt{[5]}.
\end{attention}

\begin{propriete}[La propriété length]
Tout tableau JavaScript possède la propriété \cle{length}, qui donne le \textbf{nombre d'éléments} du tableau. Si \texttt{notes} contient 5 notes, alors \texttt{notes.length} vaut 5. Comme les indices commencent à 0, le \textbf{dernier indice valide est} \texttt{notes.length - 1}.
\end{propriete}

\begin{attention}[L'erreur classique : dépasser le dernier indice]
L'erreur la plus fréquente des débutants est d'écrire \texttt{notes[notes.length]}. Si le tableau contient 5 éléments, les indices valides sont 0, 1, 2, 3, 4 : la case d'indice 5 \textbf{n'existe pas}. JavaScript ne signale pas d'erreur, il retourne silencieusement \texttt{undefined}, ce qui fausse tous les calculs (une somme devient \texttt{NaN}). Retiens : \textbf{le dernier indice valide est toujours \texttt{length - 1}}. Dans une boucle, écris \texttt{i < notes.length} et jamais \texttt{i <= notes.length}.
\end{attention}

\textbf{Parcours d'un tableau avec une boucle for.}\par
C'est le mariage parfait entre cette section et la précédente : la boucle \texttt{for} fait varier l'indice \texttt{i} de 0 à \texttt{length - 1}, et chaque tour traite la case \texttt{notes[i]}.

\begin{exemplebox}[Afficher toutes les notes d'un tableau]
\begin{lstlisting}[language=JavaScript]
var notes = [12, 15, 9, 14, 11];

// i prend successivement les valeurs 0, 1, 2, 3, 4
for (var i = 0; i < notes.length; i++) {
    document.write("Note n" + (i + 1) + " : " + notes[i] + "<br>");
}
\end{lstlisting}
Ce script affiche les cinq notes, numérotées de 1 à 5 pour l'utilisateur (on écrit \texttt{i + 1} car l'être humain compte à partir de 1, la machine à partir de 0).
\end{exemplebox}

\textbf{Recherche d'un élément dans un tableau.}\par
Autre besoin concret : la secrétaire du lycée veut savoir si un élève a obtenu la note 20 quelque part dans le tableau, et à quelle position. Il faut parcourir le tableau en comparant chaque case à la valeur cherchée, tout en mémorisant si on l'a rencontrée.

\begin{methode}[Rechercher un élément x dans un tableau (première occurrence)]
\begin{enumerate}
  \item Initialiser un indicateur booléen \texttt{trouve} à \texttt{false} et une variable \texttt{position} à $-1$ (valeur conventionnelle signifiant « pas trouvé »).
  \item Parcourir le tableau avec une boucle \texttt{for} (indice \texttt{i} de 0 à \texttt{length - 1}).
  \item À chaque tour, comparer la case courante à \texttt{x} : si \texttt{t[i] == x}, alors mettre \texttt{trouve} à \texttt{true}, mémoriser \texttt{position = i} et \textbf{quitter la boucle} avec \texttt{break}.
  \item Après la boucle, tester \texttt{trouve} : s'il vaut \texttt{true}, afficher \texttt{position} ; sinon annoncer que l'élément est absent.
\end{enumerate}
\end{methode}

\begin{exemplebox}[Recherche de la note 20 dans le tableau]
\begin{lstlisting}[language=JavaScript]
var notes = [12, 15, 20, 9, 14];
var x = 20;            // valeur recherchée
var trouve = false;    // indicateur
var position = -1;     // -1 signifie "pas trouvé"

for (var i = 0; i < notes.length; i++) {
    if (notes[i] == x) {
        trouve = true;
        position = i;  // on mémorise l'indice
        break;         // on stoppe la boucle : première occurrence trouvée
    }
}

if (trouve) {
    alert("La note " + x + " existe à l'indice " + position);
} else {
    alert("La note " + x + " n'existe pas dans le tableau.");
}
\end{lstlisting}
Ici, la recherche s'arrête sur l'indice 2 : le script affiche « La note 20 existe à l'indice 2 ».
\end{exemplebox}

\courssub{Création d'objets avec l'opérateur new}

JavaScript fournit des \cle{objets} prédéfinis, c'est-à-dire des structures riches dotées de propriétés (des données) et de méthodes (des actions). On les crée avec l'opérateur \cle{new} suivi du nom du \emph{constructeur} :

\begin{lstlisting}[language=JavaScript]
var d = new Date();       // objet Date : date et heure actuelles
var t = new Array();      // tableau vide (on ajoutera les cases ensuite)
var s = new String("TI"); // objet chaîne de caractères
\end{lstlisting}

L'objet \texttt{Date} est très utile pour un site dynamique : il capture la date et l'heure du moment où la page s'exécute, et ses méthodes permettent d'en extraire les composantes.

\begin{exemplebox}[Afficher la date du jour sur la page d'accueil du lycée]
\begin{lstlisting}[language=JavaScript]
var d = new Date();           // création de l'objet Date
var jour  = d.getDate();      // numéro du jour du mois (1 à 31)
var mois  = d.getMonth() + 1; // mois : attention, 0 = janvier !
var annee = d.getFullYear();  // année sur 4 chiffres

document.write("Nous sommes le " + jour + "/" + mois + "/" + annee);
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Le piège de getMonth()]
La méthode \texttt{getMonth()} retourne les mois numérotés \textbf{de 0 à 11} (0 pour janvier, 11 pour décembre), comme les indices d'un tableau. Oublier le \texttt{+ 1} affiche un mois de retard : en mars, ta page annoncerait « mois 2 ». Pense toujours à ajouter 1.
\end{attention}

\courssub{Les fonctions}

\textbf{Le problème à résoudre.}\par
Sur le site du lycée, on calcule la moyenne des notes de la classe de Première, puis celle de Terminale, puis celle de Seconde. Faut-il recopier trois fois la même boucle de somme ? Non : on écrit le calcul \emph{une seule fois} dans une \cle{fonction}, puis on l'\emph{appelle} autant de fois que nécessaire avec des données différentes. La fonction est une machine : on lui donne des ingrédients (les \cle{paramètres}), elle effectue un traitement, et elle peut rendre un résultat (la \cle{valeur de retour}).

\begin{propriete}[Déclaration et appel d'une fonction]
La syntaxe générale de déclaration est :
\begin{lstlisting}[language=JavaScript]
function nomFonction(parametre1, parametre2) {
    // instructions du traitement
    return expression;   // seulement si la fonction retourne une valeur
}
\end{lstlisting}
\begin{itemize}
  \item Le mot-clé \texttt{function} est suivi du \textbf{nom} de la fonction, puis des \textbf{paramètres} entre parenthèses (séparés par des virgules ; les parenthèses restent obligatoires même vides), puis du corps entre accolades.
  \item \textbf{Fonction sans retour} (appelée aussi \emph{procédure}) : elle exécute des actions (affichage, modification de la page) mais ne rend rien ; elle ne contient pas de \texttt{return} (ou un \texttt{return} seul sans expression).
  \item \textbf{Fonction avec retour} : l'instruction \texttt{return expression;} calcule l'expression, renvoie sa valeur à l'appelant et \textbf{termine immédiatement} la fonction.
  \item Pour \textbf{appeler} la fonction, on écrit son nom suivi des valeurs concrètes (les \emph{arguments}) : \texttt{var m = moyenne(notes);} récupère la valeur retournée dans la variable \texttt{m}.
\end{itemize}
\end{propriete}

\begin{methode}[Écrire une fonction en trois questions]
\begin{enumerate}
  \item \textbf{Quelles sont les entrées ?} Identifie les données dont le traitement a besoin : ce seront les paramètres, placés entre parenthèses.
  \item \textbf{Quel est le traitement ?} Écris les instructions qui transforment les entrées en résultat (boucles, calculs, tests).
  \item \textbf{Faut-il rendre un résultat ?} Si l'appelant doit récupérer une valeur (une moyenne, un total, un vrai/faux), termine par \texttt{return} suivi de cette valeur. Si la fonction ne fait qu'afficher ou modifier la page, aucun \texttt{return} n'est nécessaire.
\end{enumerate}
\end{methode}

\begin{exemplebox}[Fonction sans retour : afficher un message de bienvenue]
\begin{lstlisting}[language=JavaScript]
// Procédure : elle affiche, mais ne retourne rien
function bienvenue(nom) {
    alert("Bienvenue " + nom + " sur le site du lycée !");
}

bienvenue("Amina");   // appel : affiche "Bienvenue Amina ..."
bienvenue("Biya");    // on réutilise la même fonction
\end{lstlisting}
\end{exemplebox}

\begin{exoresolu}[Calculer la moyenne d'un tableau de notes]
Énoncé. Écrire une fonction \texttt{moyenne(t)} qui reçoit un tableau de notes, parcourt toutes ses cases, calcule la somme des éléments et retourne la moyenne. Vérifier que \texttt{moyenne([10, 12, 14])} retourne 12.
\tcblower
Solution détaillée. On applique la méthode en trois questions : l'entrée est le tableau \texttt{t} (un seul paramètre) ; le traitement est une boucle de somme ; le résultat doit être rendu, donc on utilise \texttt{return}. On prévoit le cas d'un tableau vide pour éviter une division par zéro.
\begin{lstlisting}[language=JavaScript]
function moyenne(t) {
    if (t.length === 0) return 0;      // garde-fou : tableau vide
    var somme = 0;                       // accumulateur initialisé à 0
    for (var i = 0; i < t.length; i++) { // parcours des indices 0 à length-1
        somme = somme + t[i];            // on ajoute chaque case
    }
    return somme / t.length;             // valeur retournée
}

// Appel de la fonction et récupération du résultat
var m = moyenne([10, 12, 14]);
alert("La moyenne est : " + m);   // affiche 12
\end{lstlisting}
Vérification pas à pas : \texttt{somme} vaut successivement $0$, puis $0 + 10 = 10$, puis $10 + 12 = 22$, puis $22 + 14 = 36$. Le tableau contient 3 éléments, donc la fonction retourne $36 / 3 = 12$. L'appel stocke 12 dans \texttt{m}, que l'on affiche. Remarque que la même fonction fonctionne pour \emph{n'importe quel} tableau : \texttt{moyenne([8, 9])} retourne 8,5.
\end{exoresolu}

\textbf{Portée des variables.}\par
Une variable déclarée avec \texttt{var} \emph{à l'intérieur} d'une fonction est dite \cle{locale} : elle n'existe que pendant l'exécution de cette fonction et est invisible à l'extérieur. Dans l'exemple précédent, \texttt{somme} et \texttt{i} sont locales à \texttt{moyenne} : après l'appel, elles ont disparu de la mémoire. C'est une protection précieuse : deux fonctions peuvent utiliser chacune une variable \texttt{i} sans se gêner. À l'inverse, une variable déclarée hors de toute fonction est \cle{globale} : elle est accessible partout dans le script.

\begin{attention}[Confondre paramètre et variable globale]
Un piège fréquent consiste à utiliser dans une fonction une variable globale au lieu d'un paramètre : la fonction « marche » tant que la globale porte le bon nom, puis casse dès qu'on la réutilise ailleurs. Règle d'or : \textbf{tout ce dont une fonction a besoin doit entrer par ses paramètres}, et tout ce qu'elle produit doit sortir par \texttt{return}. Ainsi, \texttt{moyenne(t)} fonctionne avec n'importe quel tableau, pas seulement avec celui qui s'appelle \texttt{notes}.
\end{attention}

\begin{experience}[TP guidé : statistiques des notes d'une classe]
\textbf{Objectif} : écrire une page qui affiche la moyenne, la note maximale et le nombre d'admis (note $\geq 10$) d'une classe.\par
\textbf{Logiciels} : un éditeur de texte (Notepad++) et un navigateur (Firefox ou Chrome).\par
\textbf{Manipulation} :

Chaque fonction applique un algorithme classique de parcours : accumulation (somme), comparaison mémorisée (maximum) et comptage conditionnel (admis). \begin{aretenir}[L'essentiel de la section]
\begin{itemize}
  \item Un \cle{tableau} regroupe plusieurs valeurs sous un même nom ; chaque case est repérée par un \cle{indice} qui commence à \textbf{0}. On le crée avec \texttt{var t = [12, 15, 9];} ou \texttt{new Array(12, 15, 9)} (attention : \texttt{new Array(5)} crée un tableau vide de longueur 5).
  \item \texttt{t.length} donne le nombre d'éléments ; le dernier indice valide est \texttt{t.length - 1}. On parcourt un tableau avec \texttt{for (var i = 0; i < t.length; i++)}.
  \item L'opérateur \texttt{new} crée des objets prédéfinis : \texttt{new Date()}, \texttt{new Array()}.
  \item Une \cle{fonction} se déclare avec \texttt{function nom(parametres) \{ ... \}} et s'appelle par son nom suivi des arguments. \texttt{return} renvoie une valeur et termine la fonction ; sans \texttt{return}, c'est une procédure qui agit sans rien rendre.
  \item Une variable déclarée dans une fonction est \cle{locale} : elle n'existe qu'à l'intérieur de celle-ci.
\end{itemize}
\end{aretenir}

\coursec{Évènements et contrôle des formulaires}

Dans la section précédente, nous avons appris à structurer des données complexes avec les \emph{tableaux} et les \emph{objets}, et à factoriser nos traitements grâce aux \emph{fonctions}. Nous possédons désormais la « boîte à outils » algorithmique de JavaScript. Il nous reste à brancher ces outils sur l'interface utilisateur : comment faire en sorte qu'un clic sur un bouton déclenche un calcul, qu'une saisie dans un champ soit vérifiée instantanément, ou que la page s'initialise correctement au chargement ? C'est tout l'objet de la \textbf{programmation évènementielle}, cœur de l'interactivité côté client.

\courssub{Programmation évènementielle : concepts et insertion}

\begin{definition}[Évènement et gestionnaire d'évènement]
Un \cle{évènement} est une action détectée par le navigateur : un clic de souris, l'appui sur une touche, le chargement d'une image, la modification d'un champ de formulaire, etc. Un \cle{gestionnaire d'évènement} (ou \emph{écouteur}) est une fonction JavaScript qui sera exécutée automatiquement lorsque l'évènement se produit sur un élément HTML précis.
\end{definition}

En JavaScript côté client (niveau Première TI), la méthode historique et pédagogique pour associer un évènement à une fonction consiste à utiliser un \textbf{attribut HTML} directement dans la balise de l'élément concerné. La syntaxe générale est :
\begin{center}
\texttt{<balise onevent="nomFonction();">}
\end{center}
où \texttt{onevent} est le nom de l'attribut (ex. \texttt{onclick}, \texttt{onchange}) et \texttt{nomFonction} le nom de la fonction JavaScript définie dans un bloc \texttt{<script>}.

\courssub{Accès aux éléments HTML : \texttt{document.getElementById} et propriété \texttt{.value}}

Pour contrôler une saisie ou modifier le contenu d'une page, le script doit « attraper » l'élément HTML. La méthode standard au programme est \texttt{document.getElementById("identifiant")}.

\begin{propriete}[Accès à un élément par son \texttt{id}]
\begin{itemize}
    \item \textbf{Syntaxe :} \texttt{var element = document.getElementById("id\_de\_l\_element");}
    \item \textbf{Condition :} L'élément HTML doit posséder un attribut \texttt{id="id\_de\_l\_element"} \textbf{unique} dans la page.
    \item \textbf{Retour :} Un objet \texttt{HTMLElement} (ou \texttt{null} si introuvable).
    \item \textbf{Propriété clé :} \texttt{element.value} renvoie la \textbf{valeur courante} d'un champ de formulaire (\texttt{<input>}, \texttt{<select>}, \texttt{<textarea>}).
\end{itemize}
\end{propriete}

\begin{attention}[Erreurs fréquentes — \textbf{À lire avant tout TP}]
\begin{enumerate}
    \item \textbf{Guillemets obligatoires :} \texttt{getElementById("champ")} (chaîne de caractères). \texttt{getElementById(champ)} cherche une variable JS nommée \texttt{champ} $\rightarrow$ \texttt{ReferenceError}.
    \item \textbf{\texttt{id} vs \texttt{name} :} \texttt{getElementById} ne cherche que l'attribut \texttt{id}. L'attribut \texttt{name} sert à l'envoi des données au serveur (PHP en Terminale), pas à la sélection JS côté client.
    \item \textbf{\texttt{.value} est \emph{toujours} une chaîne :} Même pour \texttt{<input type="number">}, \texttt{element.value} renvoie \texttt{"12"} (string), pas \texttt{12} (number). \textbf{Conversion impérative} avec \texttt{parseInt()} ou \texttt{parseFloat()} avant tout calcul ou comparaison numérique.
    \item \textbf{Exécution trop tôt :} Si le script dans \texttt{<head>} appelle \texttt{getElementById} avant que le \texttt{<body>} ne soit lu, l'élément n'existe pas encore $\rightarrow$ retourne \texttt{null}. \textbf{Solution :} placer le script à la fin du \texttt{<body>} ou utiliser \texttt{window.onload} / \texttt{<body onload="...">}.
\end{enumerate}
\end{attention}

\begin{exemplebox}[Lecture, conversion et calcul]
\begin{lstlisting}[language=JavaScript]
function calculerMontant() {
    // 1. Récupérer les éléments
    const inputQte = document.getElementById("qte");
    const inputPU  = document.getElementById("pu");
    const spanTotal = document.getElementById("total");

    // 2. Lire les valeurs (chaînes)
    const strQte = inputQte.value; // ex: "5"
    const strPU  = inputPU.value;  // ex: "1200"

    // 3. CONVERSION IMPÉRATIVE
    const qte = parseInt(strQte, 10); // base 10 recommandée
    const pu  = parseFloat(strPU);    // gère les décimales

    // 4. Vérification basique (NaN = Not a Number)
    if (isNaN(qte) || isNaN(pu) || qte <= 0 || pu < 0) {
        spanTotal.textContent = "Erreur de saisie";
        spanTotal.style.color = "red";
        return; // stoppe la fonction
    }

    // 5. Calcul et affichage
    const montant = qte * pu;
    spanTotal.textContent = montant.toLocaleString() + " FCFA"; // formatage FR
    spanTotal.style.color = "green";
}
\end{lstlisting}
\end{exemplebox}

\courssub{Contrôle de saisie et validation de formulaire}

Le contrôle de saisie (\emph{validation côté client}) vise à donner un retour \textbf{immédiat} à l'utilisateur avant d'envoyer les données au serveur. Cela économise de la bande passante et améliore l'expérience utilisateur (UX).

\begin{methode}[Contrôler une saisie en 4 étapes]
\begin{enumerate}
    \item \textbf{Récupérer l'élément} avec \texttt{document.getElementById("idChamp")}.
    \item \textbf{Lire la valeur} via la propriété \texttt{.value} (rappel : c'est une \texttt{String}).
    \item \textbf{Tester la valeur} :
        \begin{itemize}
            \item Non vide : \texttt{val.trim() !== ""}
            \item Entier positif strict : \texttt{!isNaN(val) \&\& parseInt(val, 10) > 0 \&\& val === String(parseInt(val, 10))}
            \item Format complexe (email, téléphone CM) : \emph{Expressions régulières} (voir Terminale) ou logique \texttt{if} simple (longueur, préfixe \texttt{"6"} ou \texttt{"2"} pour le Cameroun).
        \end{itemize}
    \item \textbf{Réagir} :
        \begin{itemize}
            \item Afficher un message : \texttt{alert("Message")} (modal, bloquant) ou injection dans un \texttt{<span>} (non bloquant, pro).
            \item \textbf{Bloquer l'envoi} : la fonction de validation appelée par \texttt{onsubmit} doit retourner \texttt{false} si erreur.
        \end{itemize}
\end{enumerate}
\end{methode}

\begin{propriete}[Validation globale : l'attribut \texttt{onsubmit} sur \texttt{<form>}]
Pour interdire l'envoi du formulaire si les données sont invalides, on place un gestionnaire sur la balise \texttt{<form>} :
\begin{center}
\texttt{<form action="traitement.php" method="post" onsubmit="return verifierFormulaire();">}
\end{center}
\begin{itemize}
    \item La fonction \texttt{verifierFormulaire()} doit retourner \texttt{true} (envoi autorisé) ou \texttt{false} (envoi annulé).
    \item Le \texttt{return} \textbf{devant l'appel} dans l'attribut est crucial : \texttt{onsubmit="return verifierFormulaire()"}.
\end{itemize}
\end{propriete}

\begin{exemplebox}[Vérification quantité entière positive — Exemple chiffré]
\begin{lstlisting}[language=JavaScript]
function verifierQuantite() {
    const champ = document.getElementById("qteCmd");
    const val = champ.value.trim(); // "  12  " -> "12"

    // 1. Non vide
    if (val === "") {
        alert("La quantité est obligatoire.");
        champ.focus(); // replace le curseur
        return false;
    }

    // 2. Conversion et test entier positif
    const qte = parseInt(val, 10);
    if (isNaN(qte) || qte <= 0 || val !== String(qte)) {
        // val !== String(qte) détecte "12.5" ou "12abc" -> parseInt donne 12 mais val != "12"
        alert("Quantité invalide : veuillez entrer un entier strictement positif (ex: 5).");
        champ.select(); // sélectionne le texte pour correction facile
        return false;
    }

    return true; // OK
}
\end{lstlisting}
\end{exemplebox}

\begin{savaistu}[Contrôle côté client vs côté serveur]
Le JavaScript s'exécute dans le navigateur de l'utilisateur (\emph{côté client}). L'utilisateur peut \textbf{désactiver JavaScript} dans les paramètres de son navigateur, ou un développeur malveillant peut modifier votre code via les outils de développement (F12) pour contourner vos contrôles. \textbf{Jamais} vous ne devez faire confiance aux données reçues du client sans les revérifier côté serveur (PHP, Node.js, Python, Java — programme de Terminale TI). Le contrôle côté client est un \emph{confort} (réactivité, économie de requêtes), le contrôle côté serveur est une \emph{nécessité de sécurité} (intégrité des données, protection contre injections SQL/XSS).
\end{savaistu}

\textbf{Étape 2 — Le script externe (\texttt{script.js}).} Les constantes (\texttt{const}) protègent les valeurs de référence (seuil, taux) contre toute réaffectation accidentelle ; \texttt{let} est utilisé pour le tableau \texttt{factures} car sa \emph{contenu} change (ajout d'éléments) mais pas sa référence, et pour les variables locales des fonctions. \begin{lstlisting}[language=JavaScript]
// Constantes de l'application (valeurs fixes, lisibles, maintenables)
const SEUIL_REMISE = 5;      // seuil en heures (nombre entier)
const TAUX_REMISE = 0.10;    // remise de 10 % (nombre décimal)

// Tableau des montants de la journée : let car on y ajoute des éléments (push)
let factures = [];

// Fonction SANS retour : message au chargement (évènement onload)
function bienvenue() {
    alert("Bienvenue au cyber-café Njangui Net !");
}

// Fonction SANS retour : calcule, affiche et mémorise une facture
function calculerFacture() {
    // 1. Lecture des champs (retourne des chaînes de caractères)
    let nom = document.getElementById("nom").value;
    let heures = parseFloat(document.getElementById("heures").value);
    let tarif = parseFloat(document.getElementById("tarif").value);

    // 2. Contrôle de saisie rigoureux
    if (nom === "") {
        alert("Erreur : veuillez saisir le nom du client.");
    } else if (isNaN(heures) || heures <= 0) {
        alert("Erreur : le nombre d'heures doit être un nombre positif.");
    } else if (isNaN(tarif) || tarif <= 0) {
        alert("Erreur : le tarif horaire doit être un nombre positif.");
    } else {
        // 3. Calcul du montant
        let montant = heures * tarif;
        let message = "Client : " + nom + "\n";
        
        // Application de la remise conditionnelle
        if (heures > SEUIL_REMISE) {
            montant = montant * (1 - TAUX_REMISE);
            message = message + "Remise de 10 % appliquée.\n";
        }
        
        // 4. Mémorisation et affichage
        factures.push(montant); // Ajout au tableau de la journée
        message = message + "Montant à payer : " + montant.toFixed(0) + " FCFA";
        
        // Remplacement des retours à la ligne par <br> pour l'affichage HTML
        document.getElementById("resultat").innerHTML =
            "<p>" + message.replace(/\n/g, "<br>") + "</p>";
    }
}

// Fonction AVEC retour : calcule la recette totale (parcours tableau)
function calculerBilan() {
    let total = 0;
    for (let i = 0; i < factures.length; i++) {
        total = total + factures[i];
    }
    return total; // Retourne la somme pour réutilisation
}

// Fonction SANS retour : affiche le bilan complet (nb, total, max)
function afficherBilan() {
    if (factures.length === 0) {
        alert("Aucune facture enregistrée aujourd'hui.");
    } else {
        let total = calculerBilan(); // Réutilisation de la fonction
        let max = factures[0];       // Initialisation du maximum
        
        // Recherche du maximum (parcours à partir du 2e élément)
        for (let i = 1; i < factures.length; i++) {
            if (factures[i] > max) {
                max = factures[i];
            }
        }
        
        document.getElementById("resultat").innerHTML =
            "<p>Bilan du jour :<br>" +
            "Nombre de factures : " + factures.length + "<br>" +
            "Recette totale : " + total.toFixed(0) + " FCFA<br>" +
            "Plus grande facture : " + max.toFixed(0) + " FCFA</p>";
    }
}

\begin{attention}[Pièges fréquents rencontrés pendant l'activité]
\begin{itemize}
\item \textbf{Oublier \texttt{parseFloat()} / \texttt{parseInt()}} : la valeur lue par \texttt{.value} est une \emph{chaîne} ; \texttt{"3" + "500"} donne \texttt{"3500"} (concaténation) et non $3500$ (addition).
\item \textbf{Virgule décimale} : \texttt{parseFloat("2,5")} renvoie $2$ (arrêt au premier caractère invalide) ! Saisir les durées avec un point (\texttt{2.5}) ou remplacer la virgule avant conversion : \texttt{parseFloat(valeur.replace(",", "."))}.
\item \textbf{Mauvaise casse} : \texttt{getElementById} est sensible à la casse ; \texttt{getElementByID} (D majuscule) provoque une erreur \texttt{Uncaught TypeError}.
\item \textbf{Script chargé trop tôt} : si la balise \texttt{<script src="...">} est placée dans \texttt{<head>} sans attribut \texttt{defer}, les éléments HTML n'existent pas encore au moment de l'exécution ; placer la balise en fin de \texttt{<body>} (comme ici) ou utiliser \texttt{defer}.
\item \textbf{Confondre \texttt{=} et \texttt{===}} dans les tests : \texttt{if (nom = "")} \emph{affecte} la chaîne vide à \texttt{nom} et retourne \texttt{""} (faux), au lieu de comparer. Toujours écrire \texttt{===} (égalité stricte) ou \texttt{==}.
\item \textbf{Variable \texttt{max} mal initialisée} : initialiser \texttt{let max = 0} échoue si toutes les factures sont négatives (impossible ici) ou si le tableau est vide (géré par le \texttt{if} précédent). La méthode robuste est \texttt{let max = factures[0];} puis boucle à partir de l'indice 1.
\end{itemize}
\end{attention}

\coursec{Programmation JavaScript côté client}

\begin{definition}[Script JavaScript --- Côté client]
Un \textbf{script} est une suite d'instructions écrites dans un langage de script (ici JavaScript) et destinées à être exécutées par un interpréteur intégré au navigateur web. En \emph{côté client} (client-side), le code est téléchargé avec la page HTML et s'exécute sur la machine de l'utilisateur (ordinateur, téléphone), sans aller-retour vers le serveur. Cela permet de rendre l'interface homme-machine (IHM) réactive : validation instantanée de formulaires, animations, mise à jour partielle de la page (DOM), calculs locaux.
\end{definition}

\begin{aretenir}[Avantages et limites de JavaScript côté client]
\begin{itemize}
\item \textbf{Avantages :} Réactivité immédiate (pas de latence réseau) ; allègement du serveur (traitement local) ; enrichissement de l'IHM (drag-and-drop, carrousels, cartes interactives) ; langage universel (tous navigateurs modernes).
\item \textbf{Limites :} \textbf{Sécurité :} le code est visible et modifiable par l'utilisateur (outils développeur) \rightarrow \textbf{jamais} de confiance aveugle pour des opérations critiques (paiement, droits d'accès, BDD) ; \textbf{Dépendance navigateur :} différences mineures d'API (rares aujourd'hui) ; \textbf{Accès restreint :} pas d'accès direct au système de fichiers local, à la base de données du serveur, ni aux périphériques sans autorisation explicite (Webcam, GPS via API sécurisées).
\end{itemize}
\end{aretenir}

\courssub{Scripts, évènements et insertion de JavaScript dans HTML}

\begin{definition}[Évènement]
Un \textbf{évènement} est une action détectée par le navigateur sur un élément HTML : clic de souris (\texttt{click}), survol (\texttt{mouseover}), frappe clavier (\texttt{keydown}), chargement de la page (\texttt{load}), modification d'un champ (\texttt{change}), prise de focus (\texttt{focus}). JavaScript permet d'associer une \emph{fonction gestionnaire} (handler) à cet évènement pour y réagir.
\end{definition}

\begin{methode}[Bien insérer un script : les trois méthodes]
Pour intégrer du JavaScript dans une page HTML, procède ainsi :
\begin{enumerate}
\item \textbf{Choisir l'emplacement} :
      \begin{itemize}
      \item Dans l'en-tête \texttt{<head>} : idéal pour déclarer des \emph{fonctions} qui seront appelées plus tard (évènements, \texttt{onload}). Le script est lu avant l'affichage du \texttt{<body>}.
      \item Dans le corps \texttt{<body>} : le script s'exécute \emph{au moment où le navigateur le rencontre} lors du parsing HTML. Utile pour écrire du contenu dynamique au chargement (\texttt{document.write}), mais bloque l'affichage.
      \item Dans un \textbf{fichier externe} (extension \texttt{.js}) : \textbf{méthode recommandée} (propre, réutilisable, mise en cache navigateur).
      \end{itemize}
\item \textbf{Script interne} : encadrer le code par les balises \texttt{<script>} et \texttt{</script>}.
      \begin{lstlisting}[language=HTML]
<script>
    // Code JavaScript ici
    console.log("Script interne chargé");
</script>
      \end{lstlisting}
\item \textbf{Script externe} : utiliser l'attribut \texttt{src} sur une balise \texttt{<script>} \textbf{non auto-fermante}.
      \begin{lstlisting}[language=HTML]
<script src="mesScripts/fonctions.js"></script>
      \end{lstlisting}
      \textbf{Interdiction} : on ne met \emph{jamais} de code JavaScript \emph{entre} les balises d'un \texttt{<script src="...">} (il serait ignoré).
\item \textbf{Attribut \texttt{defer} / \texttt{async} (bonus)} : dans le \texttt{<head>}, \texttt{<script src="..." defer></script>} attend la construction du DOM avant d'exécuter (équivalent à placer le script en fin de \texttt{<body>}). \texttt{async} exécute dès que possible (ordre non garanti).
\end{enumerate}
\textbf{Réflexe Probatoire} : si l'énoncé demande « un script réutilisable sur plusieurs pages » ou « séparation structure/comportement », c'est le fichier externe (\texttt{.js}) qu'il faut citer.
\end{methode}

\begin{exoresolu}[Insertion d'un script dans une page]
\textbf{Énoncé.} La boutique « Chez Manga » de Douala veut afficher un message de bienvenue à l'ouverture de sa page d'accueil.
\begin{enumerate}
\item Écrire le code HTML complet d'une page contenant, dans l'en-tête, un script qui affiche la boîte de dialogue « Bienvenue chez Manga ! ».
\item Réécrire uniquement la ligne d'insertion si le script est placé dans un fichier externe nommé \texttt{bienvenue.js}.
\end{enumerate}
\tcblower
\textbf{Solution.}
\begin{enumerate}
\item Le script est placé entre \texttt{<head>} et \texttt{</head>}, encadré par la balise \texttt{<script>}. La fonction \texttt{alert()} affiche une boîte de dialogue modale.
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Boutique Chez Manga</title>
    <script>
        // Script interne place dans l'en-tete
        alert("Bienvenue chez Manga !");
    </script>
</head>
<body>
    <h1>Boutique Chez Manga</h1>
    <p>Vos articles scolaires au meilleur prix.</p>
</body>
</html>
\end{lstlisting}
\item Pour un fichier externe, on utilise l'attribut \texttt{src} et on laisse le corps de la balise vide :
\begin{lstlisting}[language=HTML]
<script src="bienvenue.js"></script>
\end{lstlisting}
Le fichier \texttt{bienvenue.js} contient alors uniquement la ligne \texttt{alert("Bienvenue chez Manga !");}, \textbf{sans} balise \texttt{<script>}.
\end{enumerate}
\textbf{Conclusion} : un script interne s'écrit entre \texttt{<script>} et \texttt{</script>}, un script externe se lie avec \texttt{<script src="fichier.js"></script>}.
\end{exoresolu}

\courssub{Variables, constantes, types et opérateurs}

\begin{methode}[Déclarer et calculer sans se tromper]
\begin{enumerate}
\item \textbf{Déclarer} : \texttt{const} pour une valeur qui ne change pas (référence constante), \texttt{let} pour une variable réaffectable. \textbf{Éviter \texttt{var}} (portée fonction, hoisting source de bugs).
      \begin{lstlisting}
const TVA = 19.25;      // Constante : separateur DECIMAL = POINT
let quantite = 10;      // Variable modifiable
let nomClient;          // Declaration sans initialisation (undefined)
      \end{lstlisting}
\item \textbf{Types de base (primitifs)} : \texttt{number} (entiers, flottants, \texttt{NaN}, \texttt{Infinity}), \texttt{string} (chaîne : guillemets simples \texttt{'...'}, doubles \texttt{"..."} ou backticks \texttt{`...`}), \texttt{boolean} (\texttt{true}/\texttt{false}), \texttt{undefined}, \texttt{null}. JavaScript est à \emph{typage dynamique} : le type suit la valeur.
\item \textbf{Opérateurs} :
      \begin{itemize}
      \item Arithmétiques : \texttt{+}, \texttt{-}, \texttt{*}, \texttt{/}, \texttt{\%} (modulo, reste), \texttt{**} (puissance).
      \item Comparaison : \texttt{===} (égalité stricte : valeur \textbf{ET} type), \texttt{!==} (différence stricte), \texttt{>}, \texttt{>=}, \texttt{<}, \texttt{<=}. \textbf{Proscrivez \texttt{==} et \texttt{!=}} (coercition de type imprévisible : \texttt{0 == "0" // true}).
      \item Logiques : \texttt{\&\&} (ET), \texttt{||} (OU), \texttt{!} (NON). Court-circuit : \texttt{expr1 \&\& expr2} évalue \texttt{expr2} seulement si \texttt{expr1} est truthy.
      \item Assignation : \texttt{=}, \texttt{+=}, \texttt{-=}, \texttt{*=}, \texttt{/=}, \texttt{\%=}.
      \item Concaténation : \texttt{+} entre chaînes. \textbf{Piège} : \texttt{"5" + 3 $\to$ "53"} (chaîne), \texttt{5 + 3 $\to$ 8} (nombre). Si un opérande est chaîne, \texttt{+} concatène.
      \end{itemize}
\item \textbf{Tester} mentalement chaque ligne avec des valeurs concrètes avant de conclure.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Trace d'exécution et opérateurs]
\textbf{Énoncé.} On donne le script suivant :
\begin{lstlisting}[language=JavaScript]
let a = 10, b = 4, c = "10";
let r1 = a % b;
let r2 = a / b;
let r3 = c + b;
let r4 = (a > b) && (b > 0);
a += 5;
\end{lstlisting}
Donner la valeur et le type de \texttt{r1}, \texttt{r2}, \texttt{r3}, \texttt{r4}, puis la valeur finale de \texttt{a}.
\tcblower
\textbf{Solution.} On exécute le script ligne par ligne :
\begin{itemize}
\item \texttt{r1 = a \% b} : l'opérateur \texttt{\%} donne le \textbf{reste} de la division entière. Or $10 = 4 \times 2 + 2$, donc \texttt{r1 = 2} (type \texttt{number}).
\item \texttt{r2 = a / b} : division réelle : $10 / 4 = 2,5$, donc \texttt{r2 = 2.5} (type \texttt{number}).
\item \texttt{r3 = c + b} : \texttt{c} est la \textbf{chaîne} \texttt{"10"} (guillemets !). L'opérateur \texttt{+} concatène : \texttt{r3 = "104"} (type \texttt{string}).
\item \texttt{r4 = (a > b) \&\& (b > 0)} : $10 > 4$ est vrai, $4 > 0$ est vrai, donc \texttt{vrai ET vrai = vrai} : \texttt{r4 = true} (type \texttt{boolean}).
\item \texttt{a += 5} équivaut à \texttt{a = a + 5}, donc \texttt{a = 10 + 5 = 15}.
\end{itemize}
\textbf{Conclusion} : \texttt{r1 = 2}, \texttt{r2 = 2.5}, \texttt{r3 = "104"}, \texttt{r4 = true} et \texttt{a = 15}. La présence de guillemets transforme un nombre en chaîne et change totalement le sens de \texttt{+}.
\end{exoresolu}

\courssub{Instructions simples : entrées, sorties et conversions}

\begin{methode}[Lire, convertir, afficher]
\begin{enumerate}
\item \textbf{Entrée (boîte de dialogue)} : \texttt{let saisie = prompt("Message :");} renvoie \emph{toujours} une \texttt{string} (ou \texttt{null} si Annuler). Même si l'utilisateur tape \texttt{12}, \texttt{saisie} vaut \texttt{"12"}.
\item \textbf{Conversion OBLIGATOIRE avant tout calcul} :
      \begin{itemize}
      \item \texttt{parseInt(chaine [, base])} : convertit en \textbf{entier} (base 10 par défaut). \texttt{parseInt("12.5") $\to$ 12}. \texttt{parseInt("abc") $\to$ NaN}.
      \item \texttt{parseFloat(chaine)} : convertit en \textbf{flottant}. \texttt{parseFloat("12.5") $\to$ 12.5}.
      \item \texttt{Number(chaine)} : conversion stricte (\texttt{Number("12.5") $\to$ 12.5}, \texttt{Number("abc") $\to$ NaN}).
      \end{itemize}
      \textbf{Usage type} : \texttt{let age = parseInt(prompt("Age ?"));}.
\item \textbf{Sorties} :
      \begin{itemize}
      \item \texttt{alert(message)} : boîte modale (bloquante). Débogage simple / utilisateur.
      \item \texttt{document.write(texte)} : écrit \emph{dans le flux HTML} au chargement. \textbf{Attention} : après chargement complet (\texttt{onload}), écrase toute la page. Réservé aux exercices simples.
      \item \texttt{console.log(valeur)} : console développeur (F12). Outil pro n°1 pour déboguer (objets, tableaux, traces non bloquantes).
      \item \texttt{element.textContent = ...} / \texttt{innerHTML = ...} : écriture dans le DOM (vrai dynamisme, vu plus loin).
      \end{itemize}
\item \textbf{Construire le message} par concaténation (+) ou template literals (ES6) : \texttt{`Total : \${total} FCFA`}.
\item \textbf{Vérifier} : si le résultat d'un calcul donne des chiffres collés (ex. \texttt{53} au lieu de $8$), c'est qu'une conversion \texttt{parseInt}/\texttt{parseFloat} a été oubliée.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Calcul d'une moyenne de notes]
\textbf{Énoncé.} Un enseignant du lycée de Nkongsamba veut un script qui demande les notes de deux épreuves de TI (sur 20) et affiche la moyenne. Écrire ce script en JavaScript.
\tcblower
\textbf{Solution.} Les valeurs saisies via \texttt{prompt} sont des chaînes : on les convertit avec \texttt{parseFloat} car une note peut être décimale (ex. $12,5$). La moyenne est $m = \dfrac{n_1 + n_2}{2}$.
\begin{lstlisting}[language=JavaScript]
// Saisie des deux notes avec conversion immediate
const note1 = parseFloat(prompt("Entrez la note 1 :"));
const note2 = parseFloat(prompt("Entrez la note 2 :"));

// Calcul de la moyenne : parentheses OBLIGATOIRES !
const moyenne = (note1 + note2) / 2;

// Affichage du resultat (template literal ES6)
alert(`La moyenne est : ${moyenne} / 20`);
\end{lstlisting}
\textbf{Vérification} : pour \texttt{note1 = 12} et \texttt{note2 = 15}, on obtient $m = \dfrac{12 + 15}{2} = \dfrac{27}{2} = 13,5$. Le message affiché est « La moyenne est : 13.5 / 20 ».

Sans \texttt{parseFloat}, \texttt{note1 + note2} vaudrait la chaîne \texttt{"1215"} et le résultat serait absurde. Sans parenthèses, \texttt{note1 + note2 / 2} calculerait $12 + 7,5 = 19,5$ (priorité de la division).

\textbf{Conclusion} : toute donnée issue de \texttt{prompt} (ou \texttt{.value}) doit être convertie avant calcul, et la formule de moyenne exige des parenthèses autour de la somme.
\end{exoresolu}

\courssub{Structures alternatives et boucles}

\begin{methode}[Choisir et rédiger une structure de contrôle]
\begin{enumerate}
\item \textbf{Alternative simple} : \texttt{if (condition) \{ ... \}} ; avec deux cas : \texttt{if (condition) \{ ... \} else \{ ... \}}. La condition est une expression \texttt{boolean}. \textbf{Jamais \texttt{=} seul dans un test} (affectation) ; on utilise \texttt{===} (strict) ou \texttt{==} (toléré mais déconseillé).
\item \textbf{Cas multiples} : enchaîner \texttt{if ... else if ... else}.
\item \textbf{Boucle \texttt{for}} : quand le nombre de répétitions est connu ou pour parcourir un tableau (indices).
      \texttt{for (let i = 0; i < n; i++) \{ ... \}} \quad (initialisation ; condition ; incrément).
\item \textbf{Boucle \texttt{while}} : tant qu'une condition est vraie (test en entrée, corps peut ne jamais s'exécuter).
      \texttt{while (condition) \{ ... \}}.
\item \textbf{Boucle \texttt{do...while}} : le corps s'exécute \emph{au moins une fois} (test en sortie). \textbf{Point-virgule final obligatoire}.
      \texttt{do \{ ... \} while (condition);}.
\item \textbf{Garantir l'arrêt} : vérifier que la variable de contrôle est modifiée dans le corps vers la condition d'arrêt, sinon \textbf{boucle infinie} (gel navigateur).
\item \textbf{\texttt{break} / \texttt{continue}} : \texttt{break} sort de la boucle ; \texttt{continue} passe à l'itération suivante.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Mention d'un élève et table de multiplication]
\textbf{Énoncé.}
\begin{enumerate}
\item Écrire un script qui demande la moyenne d'un élève et affiche « Admis » si elle est supérieure ou égale à 10, « Ajourné » sinon.
\item Écrire une boucle \texttt{for} qui affiche la table de multiplication de 7 (de $7 \times 1$ à $7 \times 10$) dans la page.
\end{enumerate}
\tcblower
\textbf{Solution.}
\begin{enumerate}
\item La condition porte sur la moyenne convertie en nombre :
\begin{lstlisting}[language=JavaScript]
const moy = parseFloat(prompt("Entrez la moyenne :"));
if (moy >= 10) {
    alert("Admis");
} else {
    alert("Ajourné");
}
\end{lstlisting}
Le test \texttt{moy >= 10} couvre le cas limite $10/20$ : l'élève est Admis, conformément à la règle.
\item Le nombre de tours est connu (10) : la boucle \texttt{for} est adaptée.
\begin{lstlisting}[language=JavaScript]
for (let i = 1; i <= 10; i++) {
    document.write(`7 x ${i} = ${7 * i}<br>`);
}
\end{lstlisting}
\textbf{Trace} : \texttt{i} vaut successivement $1, 2, \dots, 10$ ; à \texttt{i = 11}, la condition \texttt{i <= 10} devient fausse et la boucle s'arrête. La page affiche « 7 x 1 = 7 » jusqu'à « 7 x 10 = 70 ». La balise \texttt{<br>} provoque le retour à la ligne HTML.
\end{enumerate}
\textbf{Conclusion} : \texttt{if...else} traite une décision à deux branches ; la boucle \texttt{for (init ; cond ; inc)} est idéale pour un nombre d'itérations connu.
\end{exoresolu}

\courssub{Tableaux, objets et fonctions}

\begin{methode}[Manipuler tableaux et fonctions]
\begin{enumerate}
\item \textbf{Déclarer un tableau} : littéral \texttt{const notes = [12, 15, 9];} (recommandé) ou \texttt{new Array(12, 15, 9);}. \texttt{new Array(3)} crée un tableau \emph{vide} de longueur 3 (piège !).
\item \textbf{Indices} : base \textbf{0}. Premier : \texttt{tab[0]}, dernier : \texttt{tab[tab.length - 1]}. \texttt{length} = nombre d'éléments (propriété, pas méthode).
\item \textbf{Parcours standard} :
      \begin{lstlisting}[language=JavaScript]
for (let i = 0; i < tab.length; i++) {
    console.log(tab[i]);
}
      \end{lstlisting}
      Parcours \texttt{for...of} (ES6, valeurs) : \texttt{for (const val of tab) \{ ... \}}.
\item \textbf{Recherche} : parcourir en comparant chaque élément à la valeur cherchée (retourner \texttt{true}/\texttt{false} ou l'indice).
\item \textbf{Objets} : collection de paires \texttt{clé: valeur}.
      \begin{itemize}
      \item Littéral : \texttt{const eleve = \{nom: "Amina", age: 16\};} (accès \texttt{eleve.nom} ou \texttt{eleve["nom"]}).
      \item Constructeur natif : \texttt{const d = new Date();} (méthodes \texttt{getFullYear()}, \texttt{getTime()}, etc.).
      \end{itemize}
\item \textbf{Fonction} : bloc réutilisable.
      \begin{lstlisting}[language=JavaScript]
function nom(param1, param2) {
    // instructions
    return resultat; // optionnel
}
      \end{lstlisting}
      \textbf{Return} : termine la fonction et renvoie une valeur. Sans \texttt{return} (ou \texttt{return;}), la fonction renvoie \texttt{undefined}.
\item \textbf{Appel} : \texttt{const res = nom(arg1, arg2);}.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Maximum d'un tableau de notes]
\textbf{Énoncé.} Les notes de TI d'une classe sont stockées dans un tableau. Écrire une fonction \texttt{noteMax(tab)} qui reçoit un tableau de nombres et retourne la plus grande note, puis un appel avec le tableau \texttt{[8, 14, 11, 17, 10]}.
\tcblower
\textbf{Solution.} On applique l'algorithme classique de recherche de maximum : on initialise le maximum au premier élément, puis on parcourt le reste du tableau en mettant à jour le maximum dès qu'on trouve plus grand.
\begin{lstlisting}[language=JavaScript]
function noteMax(tab) {
    if (tab.length === 0) return undefined; // Garde-fou
    let max = tab[0];              // maximum provisoire
    for (let i = 1; i < tab.length; i++) {
        if (tab[i] > max) {
            max = tab[i];          // nouveau maximum trouve
        }
    }
    return max;                    // la fonction retourne une valeur
}

// Appel de la fonction
const notes = [8, 14, 11, 17, 10];
alert(`La meilleure note est : ${noteMax(notes)}`);
\end{lstlisting}
\textbf{Trace détaillée} : \texttt{max = 8} ; \texttt{i=1} : $14 > 8 \to$ \texttt{max = 14} ; \texttt{i=2} : $11 < 14$ (inchangé) ; \texttt{i=3} : $17 > 14 \to$ \texttt{max = 17} ; \texttt{i=4} : $10 < 17$ (inchangé). Boucle finie (\texttt{i = 5 = tab.length}).

\textbf{Conclusion} : la fonction retourne $17$, et le message « La meilleure note est : 17 » s'affiche. Sans \texttt{return}, l'appelant ne pourrait pas récupérer le résultat.
\end{exoresolu}

\courssub{Évènements et contrôle des formulaires}

\begin{methode}[Réagir aux évènements et valider une saisie]
\begin{enumerate}
\item \textbf{Associer un évènement} (niveau Probatoire : attribut HTML \emph{inline}) :
      \begin{itemize}
      \item \texttt{onClick} (clic souris) sur bouton, lien, div...
      \item \texttt{onMouseOver} / \texttt{onMouseOut} (survol / sortie souris).
      \item \texttt{onChange} (perte de focus \textbf{après} modification) sur \texttt{<input>}, \texttt{<select>}.
      \item \texttt{onFocus} / \texttt{onBlur} (prise / perte de focus) sur champ.
      \item \texttt{onLoad} sur \texttt{<body>} (page + ressources chargées).
      \item \texttt{onSubmit} sur \texttt{<form>} (validation formulaire, \texttt{return false} pour bloquer).
      \end{itemize}
      Valeur = appel de fonction : \texttt{onClick="verifier()"}.
\item \textbf{Accéder à un élément HTML} par son \texttt{id} unique : \texttt{const elt = document.getElementById("id");}.
      \begin{itemize}
      \item Valeur d'un champ (\texttt{input}, \texttt{select}, \texttt{textarea}) : \texttt{elt.value} (toujours \texttt{string}).
      \item Contenu HTML : \texttt{elt.innerHTML} ou \texttt{elt.textContent}.
      \item Modifier style : \texttt{elt.style.color = "red";}.
      \end{itemize}
\item \textbf{Convertir} la valeur lue (\texttt{string}) avec \texttt{parseInt} / \texttt{parseFloat} / \texttt{Number} si calcul.
\item \textbf{Contrôler (Validation)} :
      \begin{itemize}
      \item Champ vide : \texttt{if (valeur === "")} ou \texttt{if (!valeur.trim())}.
      \item Intervalle : \texttt{if (age < 0 || age > 120)}.
      \item Format (email, téléphone) : expressions régulières (aperçu) ou \texttt{input type="email"} (HTML5).
      \end{itemize}
      Afficher erreur : \texttt{alert(...)} ou injection DOM (\texttt{span} erreur).
\item \textbf{Tester} avec valeurs limites : vide, 0, borne min, borne max, texte au lieu de nombre, espaces.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Validation d'un formulaire d'inscription]
\textbf{Énoncé.} Un cybercafé de Yaoundé propose un formulaire avec un champ de saisie d'identifiant \texttt{"age"} et un bouton « Valider ». Écrire le code HTML et JavaScript complet : au clic sur le bouton (évènement \texttt{onClick}), une fonction \texttt{verifier()} lit l'âge saisi et affiche « Inscription acceptée » si l'âge est supérieur ou égal à 15 ans, « Âge insuffisant » sinon, et « Veuillez saisir votre âge » si le champ est vide.
\tcblower
\textbf{Solution.} On suit la démarche : champ avec \texttt{id}, bouton avec \texttt{onClick}, fonction de contrôle utilisant \texttt{document.getElementById}.
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Inscription cybercafe</title>
    <script>
        function verifier() {
            // 1. Recuperation de l'element et de sa valeur (string)
            const champ = document.getElementById("age");
            const saisie = champ.value.trim(); // trim() supprime espaces debut/fin

            // 2. Controle saisie vide
            if (saisie === "") {
                alert("Veuillez saisir votre age");
                return; // Arrete la fonction ici
            }

            // 3. Conversion en nombre (entier)
            const age = parseInt(saisie, 10); // Base 10 explicite

            // 4. Controle logique (NaN si saisie non numerique)
            if (isNaN(age)) {
                alert("Veuillez entrer un nombre valide");
            } else if (age >= 15) {
                alert("Inscription acceptée");
            } else {
                alert("Âge insuffisant");
            }
        }
    </script>
</head>
<body>
    <h1>Formulaire d'inscription</h1>
    <form action="#" onsubmit="return false;"> <!-- Empeche envoi reel pour l'exercice -->
        <label for="age">Age : </label>
        <input type="text" id="age" name="age">
        <input type="button" value="Valider" onclick="verifier()">
    </form>
</body>
</html>
\end{lstlisting}
\textbf{Justification} :
\begin{itemize}
\item \texttt{document.getElementById("age")} sélectionne l'unique élément \texttt{id="age"}.
\item \texttt{.value} récupère le texte saisi (\texttt{string}). \texttt{.trim()} nettoie les espaces.
\item Test \texttt{saisie === ""} \textbf{avant} conversion (sinon \texttt{parseInt("") $\to$ NaN}).
\item \texttt{parseInt(saisie, 10)} : base 10 forcée (évite octal sur vieux navigateurs si \texttt{"010"}).
\item \texttt{isNaN(age)} détecte si la conversion a échoué (ex. saisie "abc").
\item \texttt{onclick="verifier()"} (minuscules recommandées en HTML5) lie l'évènement clic.
\end{itemize}
\textbf{Vérification} : champ vide $\to$ « Veuillez saisir votre âge » ; saisie \texttt{"abc"} $\to$ « Veuillez entrer un nombre valide » ; saisie \texttt{17} $\to$ « Inscription acceptée » ; saisie \texttt{12} $\to$ « Âge insuffisant ».

\textbf{Conclusion} : le contrôle de saisie côté client repose sur trois réflexes : \textbf{récupérer} (\texttt{getElementById(...).value}), \textbf{tester} (vide, \texttt{NaN}, bornes), \textbf{convertir} (\texttt{parseInt}/\texttt{parseFloat}) \textbf{avant} tout calcul ou comparaison numérique.
\end{exoresolu}

\begin{attention}[Les 5 erreurs qui coûtent des points au Probatoire]
\begin{enumerate}
\item \textbf{Confondre \texttt{=} et \texttt{===}} : \texttt{if (moy = 10)} \emph{affecte} 10 à \texttt{moy} (valeur 10, truthy) au lieu de tester ; la condition est alors toujours vraie. Dans un test, on écrit \textbf{\texttt{===}} (strict) ou \texttt{==} (toléré).
\item \textbf{Oublier \texttt{parseInt}/\texttt{parseFloat}/\texttt{Number}} après \texttt{prompt} ou \texttt{.value} : \texttt{"12" + "15"} donne \texttt{"1215"} (concaténation) et non $27$. Toute saisie utilisateur est une \texttt{string} tant qu'elle n'est pas convertie.
\item \textbf{Mal indexer les tableaux} : le premier élément est \texttt{tab[0]}, le dernier \texttt{tab[tab.length - 1]}. Écrire \texttt{i <= tab.length} dans la condition de boucle provoque un accès \texttt{undefined} (débordement).
\item \textbf{Oublier le \texttt{return}} dans une fonction censée retourner une valeur : l'appelant reçoit \texttt{undefined}. Distinguer clairement fonction « action » (effet de bord : affichage, modification DOM, sans \texttt{return}) et fonction « calcul » (valeur de retour, \textbf{avec \texttt{return}}).
\item \textbf{Mal écrire l'insertion du script} : oublier le \texttt{</script>} de fermeture, écrire \texttt{<script src="fichier.js" />} (auto-fermante interdite), ou mettre du code interne dans une balise qui possède déjà un \texttt{src}. Autre piège classique : écrire les décimaux avec une virgule (\texttt{13,5}) au lieu du point (\texttt{13.5}) dans le code JS.
\end{enumerate}
\end{attention}

\begin{corrige}[Exercice 1 — QCM : premiers pas en JavaScript]
\begin{enumerate}
\item \textbf{Réponse c.} La balise standard d'insertion d'un script dans un document HTML est \texttt{<script>}. Les balises \texttt{<js>}, \texttt{<javascript>} et \texttt{<code>} n'existent pas dans le langage HTML.
\item \textbf{Réponse b.} \texttt{alert()} affiche une boîte de dialogue modale contenant un message. \texttt{prompt()} affiche une boîte de \emph{saisie} (elle retourne une chaîne), \texttt{print()} n'existe pas en JavaScript côté client (pour la console, on utilise \texttt{console.log()}), et \texttt{echo()} appartient au langage PHP.
\item \textbf{Réponse b.} \texttt{==} est l'opérateur de comparaison d'égalité (égalité faible, avec conversion de type implicite). Attention : \texttt{=} est l'opérateur d'\emph{affectation}, et \texttt{===} teste l'égalité stricte (valeur \emph{et} type).
\item \textbf{Réponse b.} En JavaScript, les tableaux sont indexés à partir de \cle{0} : \texttt{t[0]} vaut 5, \texttt{t[1]} vaut \textbf{9}, \texttt{t[2]} vaut 2.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 2 — Vrai ou faux]
\begin{enumerate}
\item \textbf{Vrai.} JavaScript est un langage interprété par le moteur JavaScript du navigateur de l'internaute (V8 pour Chrome, SpiderMonkey pour Firefox). Le code s'exécute donc sur la machine du client, et non sur le serveur web.
\item \textbf{Faux.} La fonction \texttt{prompt()} retourne \emph{toujours} une chaîne de caractères (type \texttt{string}), même si l'utilisateur tape des chiffres. Sans conversion, l'opérateur \texttt{+} provoquerait une concaténation au lieu d'une addition. Il faut convertir la saisie avec \texttt{parseInt()}, \texttt{parseFloat()} ou \texttt{Number()}.
\item \textbf{Vrai.} Dans une boucle \texttt{do...while}, le test de la condition est effectué \emph{après} l'exécution du corps de la boucle : le bloc d'instructions est donc exécuté au moins une fois, même si la condition est fausse dès le départ.
\item \textbf{Faux.} L'évènement \texttt{onLoad} se déclenche lorsque la page web a fini de se charger dans le navigateur. Le clic sur un bouton correspond à l'évènement \texttt{onClick}.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 3 — Définitions et question de cours]
\begin{enumerate}
\item \textbf{Script :} un \cle{script} est une suite d'instructions écrites dans un langage de script (ici JavaScript), insérée dans une page HTML (balise \texttt{<script>} ou fichier externe \texttt{.js}) et exécutée par le navigateur pour rendre la page dynamique et interactive.\\
\textbf{Évènement :} un \cle{évènement} est une action détectable par le navigateur (clic de souris, survol d'un élément, saisie au clavier, fin de chargement de la page, modification d'un champ de formulaire...) susceptible de déclencher l'exécution d'une fonction JavaScript appelée \emph{gestionnaire d'évènement}.
\item \textbf{Avantages de JavaScript côté client} (deux parmi) :
\begin{itemize}
\item interactivité immédiate : le traitement est local, sans aller-retour vers le serveur, d'où une grande réactivité de la page ;
\item allègement du serveur : les contrôles et calculs simples sont réalisés sur le poste client, ce qui réduit la charge du serveur et la consommation de bande passante (atout précieux pour les connexions lentes).
\end{itemize}
\textbf{Limites} (deux parmi) :
\begin{itemize}
\item sécurité limitée : le code source est visible et modifiable par l'utilisateur ; un contrôle critique ne doit jamais reposer \emph{uniquement} sur JavaScript ;
\item dépendance au navigateur : JavaScript peut être désactivé par l'utilisateur, et le comportement peut varier légèrement d'un navigateur à l'autre. De plus, l'accès au disque dur et aux bases de données est interdit au script (bac à sable).
\end{itemize}
\item \texttt{parseInt("7.9")} analyse la chaîne et s'arrête au premier caractère qui ne peut pas faire partie d'un entier (ici le point) : elle retourne l'entier \textbf{7}.\\
\texttt{parseFloat("7.9")} analyse la chaîne comme un nombre décimal : elle retourne le nombre flottant \textbf{7,9} (noté \texttt{7.9} en JavaScript).
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 4 — Évaluation d'expressions]
On rappelle : \texttt{a = 10} (nombre), \texttt{b = "3"} (chaîne), \texttt{c = 4} (nombre).
\begin{enumerate}
\item \texttt{a + c} $= 10 + 4 =$ \textbf{14} (type \texttt{number}) : addition arithmétique entre deux nombres.
\item \texttt{a + b} $=$ \textbf{"103"} (type \texttt{string}) : l'un des opérandes est une chaîne, donc l'opérateur \texttt{+} réalise une \emph{concaténation} ; le nombre 10 est converti en \texttt{"10"}.
\item \texttt{a + parseInt(b)} $= 10 + 3 =$ \textbf{13} (type \texttt{number}) : \texttt{parseInt("3")} convertit la chaîne en entier, l'addition redevient arithmétique.
\item \texttt{a \% c} $= 10 \bmod 4 =$ \textbf{2} (type \texttt{number}) : reste de la division euclidienne de 10 par 4 ($10 = 4 \times 2 + 2$).
\item \texttt{(a > c) \&\& (c < 5)} $=$ \textbf{true} (type \texttt{boolean}) : \texttt{10 > 4} est vrai et \texttt{4 < 5} est vrai ; le ET logique de deux valeurs vraies est vrai.
\item \texttt{parseFloat("12,5".replace(",", "."))} $=$ \textbf{12,5} (type \texttt{number}) : la méthode \texttt{replace} transforme la virgule française en point décimal, puis \texttt{parseFloat} convertit correctement la chaîne \texttt{"12.5"} en nombre.
\end{enumerate}
\textbf{Point de vigilance :} la confusion entre addition et concaténation (questions 1 et 2) est l'erreur la plus fréquente au Probatoire : dès qu'un opérande de \texttt{+} est une chaîne, JavaScript concatène.
\end{corrige}

\begin{corrige}[Exercice 6 — Gestion des ventes d'une boutique]
\begin{enumerate}
\item Fonction de calcul du total :
\begin{lstlisting}[language=JavaScript]

  var somme = 0;                    // accumulateur initialise a 0
  for (var i = 0; i < t.length; i++) {
    somme += t[i];                  // somme = somme + t[i]
  }
  return somme;                     // la fonction RETOURNE la somme
}
\end{lstlisting}
La propriété \texttt{t.length} donne le nombre d'éléments du tableau (ici 4) : la boucle parcourt donc les indices 0 à 3.\\

\item Fonction de recherche du maximum :
\begin{lstlisting}[language=JavaScript]
function plusGrandeVente(t) {
  var max = t[0];                   // on suppose le 1er element maximal
  for (var i = 1; i < t.length; i++) {
    if (t[i] > max) {
      max = t[i];                   // nouveau maximum trouve
    }
  }
  return max;
}
\end{lstlisting}
\textbf{Trace d'exécution :} \texttt{max = 15000} ; $8000 < 15000$ (inchangé) ; $22000 > 15000$ donc \texttt{max = 22000} ; $12000 < 22000$ (inchangé). La fonction retourne \textbf{22000}.
\item Instruction d'affichage :
\begin{lstlisting}[language=JavaScript]

\end{lstlisting}
Le message affiché est : « Total : 57000 FCFA - Meilleure vente : 22000 FCFA ».
\end{enumerate}
\textbf{Point de vigilance :} les deux fonctions utilisent \texttt{return} et non \texttt{alert()} : une fonction qui \emph{retourne} une valeur peut être réutilisée dans un calcul ou une concaténation, ce qui est exactement ce que fait la question 3. \begin{corrige}[Exercice 7 — Parité d'un nombre]
Un entier est \cle{pair} si le reste de sa division par 2 vaut 0, c'est-à-dire si \texttt{n \% 2 === 0}.

\begin{corrige}[Exercice 9 — Chasse aux erreurs]
\begin{enumerate}
\item \textbf{Les cinq erreurs et leurs corrections :}
\begin{enumerate}
\item \textbf{\texttt{var age = saisie;} — erreur de conversion.} \texttt{prompt()} retourne une chaîne de caractères ; les comparaisons et calculs ultérieurs seront faussés. \emph{Correction :} \texttt{var age = parseInt(saisie);}
\item \textbf{\texttt{if (age = 18)} — erreur de logique (et de syntaxe algorithmique).} \texttt{=} est une affectation : la variable \texttt{age} reçoit 18 et la condition est toujours vraie. \emph{Correction :} \texttt{if (age === 18)} (égalité stricte) ou \texttt{if (age == 18)}.
\item \textbf{\texttt{ages[3]} — erreur d'accès au tableau.} Le tableau \texttt{ages} contient 3 éléments, d'indices 0, 1 et 2 ; l'indice 3 est hors limites et vaut \texttt{undefined}. Pour afficher le \emph{premier} âge : \emph{correction :} \texttt{ages[0]} (valeur 15).
\item \textbf{\texttt{document.getElementById(resultat)} — erreur d'accès à un élément HTML.} Sans guillemets, \texttt{resultat} est interprété comme une variable JavaScript inexistante ; de plus aucun élément de la page ne porte l'identifiant \texttt{resultat}. \emph{Correction :} écrire \texttt{document.getElementById("resultat")} et ajouter dans le corps de la page un élément \texttt{<p id="resultat"></p>}, ou supprimer cette ligne si elle est inutile.
\item \textbf{La balise fermante \texttt{<script>} en fin de script — erreur de syntaxe HTML.} Une balise fermante porte une barre oblique. \emph{Correction :} \texttt{</script>}.
\end{enumerate}
\item \textbf{Pourquoi la comparaison reste risquée sans conversion :} tant que \texttt{age} est une chaîne (par exemple \texttt{"20"}), JavaScript effectue une conversion implicite lors de la comparaison avec un nombre. Cela peut donner un résultat juste par chance pour \texttt{"20"}, mais toute saisie non numérique (par exemple \texttt{"abc"}) est convertie en \texttt{NaN}, et toute comparaison avec \texttt{NaN} est fausse : un élève majeur serait alors déclaré mineur. \emph{Correction définitive :} convertir dès la saisie, \texttt{var age = parseInt(saisie);}, et contrôler la validité avec \texttt{isNaN(age)}.
\item \textbf{Affichage pour la saisie \texttt{20} (script corrigé) :} \texttt{age} vaut 20. Le test \texttt{age === 18} est faux : pas de premier message. Le test \texttt{age >= 18} est vrai : la boîte de dialogue affiche « Vous etes majeur. Premier age du tableau : 15 ». Le bloc \texttt{else} n'est pas exécuté.
\end{enumerate}
\textbf{Barème indicatif (10 pts) :} identification et correction des 5 erreurs : $5 \times 1$ pt $= 5$ pts ; explication du problème de conversion : 2 pts ; correction définitive proposée : 1 pt ; affichage exact pour la saisie 20 (avec la valeur 15 du tableau) : 2 pts.\\
\textbf{Points de vigilance :} le correcteur attend pour chaque erreur la \emph{nature} (conversion, logique, indice de tableau, accès DOM, syntaxe HTML) et la \emph{correction exacte}, pas seulement la ligne fautive. Pour la question 3, la valeur affichée doit être \texttt{ages[0] = 15}, pas 3 ni \texttt{undefined}.
\end{corrige}

  }
}
\end{lstlisting}
On pouvait aussi écrire les conditions en extension avec des opérateurs logiques, par exemple \texttt{else if (n >= 10 \&\& n < 12)}.
\item Le script principal :
\begin{lstlisting}[language=JavaScript]
var saisie = prompt("Entrez la note sur 20 :");
var note = parseFloat(saisie);   // note eventuellement decimale
if (isNaN(note)) {
  alert("Erreur : veuillez entrer un nombre valide.");
} else {
  var m = mention(note);
  alert("Note : " + note + " - Mention : " + m);
}
\end{lstlisting}
Pour la saisie \texttt{13.5}, on obtient : « Note : 13.5 - Mention : Bien » ($12 \leq 13{,}5 < 16$).
\item Saisie et affichage des 5 notes avec un tableau créé par \texttt{new Array()} :
\begin{lstlisting}[language=JavaScript]
var notes = new Array(5);        // tableau de 5 cases
// Remplissage du tableau
for (var i = 0; i < 5; i++) {
  var s = prompt("Note de l'eleve " + (i + 1) + " :");
  notes[i] = parseFloat(s);
}
// Affichage des mentions
for (var i = 0; i < 5; i++) {
  if (isNaN(notes[i])) {
    alert("Eleve " + (i + 1) + " : note invalide");
  } else {
    alert("Eleve " + (i + 1) + " : Note " + notes[i] +
          " - Mention : " + mention(notes[i]));
  }
}
\end{lstlisting}
\item \textbf{Cas de la saisie \texttt{"abc"} :} \texttt{parseFloat("abc")} retourne \texttt{NaN}. Or toute comparaison impliquant \texttt{NaN} est fausse : \texttt{NaN < 10}, \texttt{NaN < 12} et \texttt{NaN < 16} sont toutes fausses. L'exécution tombe donc dans le \texttt{else} final et l'élève obtient abusivement la mention \textbf{« Très bien »}. \emph{Test à ajouter} en tête de la fonction : \texttt{if (isNaN(n)) \{ return "Note invalide"; \}}.
\end{enumerate}
\textbf{Barème indicatif (10 pts) :} fonction \texttt{mention} correcte (structure \texttt{if...else if...else}, quatre cas, \texttt{return}) : 3 pts ; script principal (prompt, parseFloat, appel, affichage) : 2,5 pts ; tableau \texttt{new Array(5)} et deux boucles : 3 pts ; réponse \texttt{NaN} $\to$ « Très bien » justifiée + test \texttt{isNaN} : 1,5 pt.\\
\textbf{Points de vigilance :} le barème impose des structures alternatives \emph{emboîtées} ; l'ordre des tests doit respecter les intervalles croissants. Citer explicitement que \texttt{parseFloat} est utilisé (et non \texttt{parseInt}) car une note peut être décimale (13,5).
\end{corrige}

\begin{corrige}[Exercice 11 — Formulaire d'inscription à un concours]
\begin{enumerate}
\item La fonction \texttt{verifier()} :
\begin{lstlisting}[language=JavaScript]
function verifier() {
  // Recuperation des elements HTML par leur identifiant
  var nom = document.getElementById("nom").value;
  var ageSaisi = document.getElementById("age").value;
  var zone = document.getElementById("erreur");

  // Controle 1 : le nom est obligatoire
  if (nom == "") {
    zone.textContent = "Erreur : le nom est obligatoire.";
    return;                       // on arrete la fonction
  }
  // Controle 2 : l'age doit etre un nombre entier
  var age = parseInt(ageSaisi);
  if (isNaN(age)) {
    zone.textContent = "Erreur : l'age doit etre un nombre.";
    return;
  }
  // Controle 3 : l'age doit etre dans l'intervalle [17 ; 25]
  if (age < 17 || age > 25) {
    zone.textContent =
      "Erreur : l'age doit etre compris entre 17 et 25 ans.";
    return;
  }
  // Tous les controles sont passes
  zone.textContent = "Inscription validee. Bienvenue !";
}
\end{lstlisting}
La condition « hors intervalle » s'écrit \texttt{age < 17 || age > 25} (opérateur OU) ; de façon équivalente, la condition de validité est \texttt{age >= 17 \&\& age <= 25} (opérateur ET). \textbf{Vérification :} âge 17 $\to$ accepté (borne incluse) ; âge 25 $\to$ accepté ; âge 16 ou 26 $\to$ refusé.
\item \textbf{Rôle de \texttt{onClick} :} placé sur le bouton « Valider », l'évènement \texttt{onClick} déclenche l'exécution de la fonction \texttt{verifier()} au moment où l'utilisateur clique : c'est le lien entre l'action de l'utilisateur et le script de contrôle.\\
\textbf{Deux autres évènements pour améliorer l'ergonomie :}
\begin{itemize}
\item \texttt{onChange} sur le champ âge : le contrôle se déclenche dès que l'utilisateur quitte le champ après l'avoir modifié, sans attendre le clic sur « Valider » ;
\item \texttt{onFocus} sur un champ : il se déclenche quand le champ reçoit le curseur ; on peut par exemple effacer le message d'erreur ou colorer le champ pour guider la saisie.
\end{itemize}
\item \textbf{Liaison du fichier externe :}
\begin{lstlisting}[language=HTML]
<script src="controle.js"></script>
\end{lstlisting}
\textbf{Avantage :} le script est séparé du document HTML, ce qui rend la page plus lisible, permet de réutiliser le même fichier \texttt{controle.js} dans plusieurs pages, et facilite la maintenance (une seule modification profite à tout le site).
\end{enumerate}
\textbf{Barème indicatif (10 pts) :} récupération correcte des champs avec \texttt{getElementById(...).value} : 2 pts ; contrôle du nom vide : 1,5 pt ; conversion \texttt{parseInt} + test \texttt{isNaN} : 2 pts ; test d'intervalle avec opérateur logique : 1,5 pt ; message de succès : 0,5 pt ; rôle de \texttt{onClick} et deux évènements justifiés : 1,5 pt ; balise \texttt{src} et avantage : 1 pt.\\
\textbf{Points de vigilance :} ne pas oublier la propriété \texttt{.value} après \texttt{getElementById(...)} (sans elle, on récupère l'\emph{élément} et non son contenu) ; les bornes 17 et 25 sont \emph{incluses}, d'où les comparaisons strictes \texttt{< 17} et \texttt{> 25} pour le rejet ; l'identifiant passé à \texttt{getElementById} doit être entre guillemets.
\end{corrige}

\begin{bilan}
\textbf{1. Définitions clés}
\begin{itemize}
  \item \cle{Script} : petit programme inséré dans une page web et \textbf{exécuté par le navigateur} (côté client), sans compilation.
  \item \cle{JavaScript} : langage de script \emph{interprété}, \emph{non typé à la déclaration}, qui rend les pages HTML \textbf{dynamiques} (réaction aux actions de l'utilisateur).
  \item \cle{Évènement} : action détectée par le navigateur (clic, survol, chargement, saisie\ldots) à laquelle on associe du code JavaScript.
  \item \cle{Variable} : zone mémoire nommée dont la valeur peut changer ; \cle{constante} : zone mémoire dont la valeur est fixée une fois pour toutes.
\end{itemize}

\textbf{2. Syntaxes à connaître par c\oe ur}
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Notion} & \textbf{Syntaxe JavaScript} \\
\hline
Insertion dans HTML & \texttt{<script type="text/javascript"> ... </script>} (dans \texttt{<head>} ou \texttt{<body>}) ; fichier externe : \texttt{<script src="fichier.js"></script>} \\
\hline
Déclaration & \texttt{var age = 17 ;} \quad \texttt{const PI = 3.14 ;} \\
\hline
Types de base & \texttt{number} (entier ou réel), \texttt{string} (chaîne), \texttt{boolean} (\texttt{true}/\texttt{false}) \\
\hline
Entrée / sortie & \texttt{prompt("message")}, \texttt{alert("message")}, \texttt{document.write("texte")} \\
\hline
Conversions & \texttt{parseInt("25")} $\to$ 25 ; \texttt{parseFloat("2,5")} $\to$ 2.5 \\
\hline
Alternative & \texttt{if (cond) \{ ... \} else \{ ... \}} \\
\hline
Boucles & \texttt{for (i=0; i<n; i++)}, \texttt{while (cond)}, \texttt{do \{ ... \} while (cond);} \\
\hline
Tableau & \texttt{var t = new Array(3);} ou \texttt{var t = [10, 20, 30];} ; accès : \texttt{t[0]} ; taille : \texttt{t.length} \\
\hline
Fonction & \texttt{function nom(p1, p2) \{ ... return r; \}} \\
\hline
Évènements & \texttt{onClick}, \texttt{onMouseOver}, \texttt{onChange}, \texttt{onFocus}, \texttt{onLoad} (attributs des balises HTML) \\
\hline

\hline

\end{center}

\textbf{3. Opérateurs}
\begin{itemize}
  \item Arithmétiques : \texttt{+ - * / \%} (reste de la division entière).
  \item Comparaison : \texttt{==}, \texttt{!=}, \texttt{<}, \texttt{>}, \texttt{<=}, \texttt{>=}.
  \item Logiques : \texttt{\&\&} (ET), \texttt{||} (OU), \texttt{!} (NON).
  \item Assignation : \texttt{=}, \texttt{+=}, \texttt{-=}, \texttt{++}, \texttt{-{}-}.
  \item Concaténation de chaînes : \texttt{+} (ex. \texttt{"Bonjour " + nom}).
\end{itemize}

\textbf{4. Méthodes express}
\begin{itemize}
  \item \emph{Contrôler un formulaire} : récupérer la valeur avec \texttt{getElementById(...).value}, tester avec \texttt{if}, afficher un message avec \texttt{alert}, renvoyer \texttt{false} pour bloquer l'envoi.
  \item \emph{Parcourir un tableau} : \texttt{for (i=0; i<t.length; i++)} puis tester chaque \texttt{t[i]} pour une recherche.
  \item \emph{Saisie numérique} : toujours appliquer \texttt{parseInt} ou \texttt{parseFloat} au résultat de \texttt{prompt}, qui renvoie une chaîne.
\end{itemize}
\end{bilan}
