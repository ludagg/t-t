\begin{exercice}[Gestion d'un stock de pièces détachées -- Structures et fichiers]
Une entreprise gère un stock de pièces détachées. Chaque pièce est caractérisée par : un code entier (4 chiffres), une désignation (chaîne de 30 caractères max), un prix unitaire (réel), et une quantité en stock (entier). On souhaite développer un module de gestion en langage C.

\begin{enumerate}
    \item Définir un type \texttt{Piece} à l'aide d'une structure (\texttt{struct}) adaptée. Déclarer un tableau \texttt{stock} pouvant contenir au maximum 500 pièces et une variable \texttt{nbPieces} pour le nombre effectif.
    \item Écrire la fonction \texttt{void saisirPiece(Piece *p)} qui lit les informations d'une pièce depuis l'entrée standard. Préciser les précautions à prendre pour la lecture de la désignation (espaces autorisés) après une lecture numérique.
    \item Écrire la fonction \texttt{int rechercherCode(const Piece stock[], int n, int code)} qui retourne l'indice de la pièce de code \texttt{code} dans les \texttt{n} premières cases du tableau, ou \texttt{-1} si absent. Justifier le choix du qualificatif \texttt{const} pour le paramètre tableau.
    \item Proposer un algorithme (en C ou pseudo-code structuré) pour la fonction \texttt{void approvisionner(Piece stock[], int *n, int code, int qte)} qui augmente la quantité de la pièce \texttt{code} de \texttt{qte}. Si le code n'existe pas et que le stock n'est pas plein, la pièce est créée (saisie des autres champs) et ajoutée. Gérer le cas stock plein.
    \item On souhaite sauvegarder le stock dans un fichier binaire \texttt{stock.dat}. Écrire la fonction \texttt{int sauvegarder(const Piece stock[], int n)} qui retourne le nombre d'éléments effectivement écrits. Expliquer pourquoi l'écriture binaire (\texttt{fwrite}) est préférable à l'écriture formatée (\texttt{fprintf}) ici, et citer un risque majeur lié à la portabilité des fichiers binaires de structures.
\end{enumerate}
\end{exercice}

\begin{exercice}[Analyse et correction d'un tri -- Pointeurs et tableaux]
Un élève a écrit le programme suivant pour trier un tableau d'entiers par ordre croissant selon l'algorithme du tri à bulles optimisé (arrêt si aucun échange).

\begin{verbatim}
#include <stdio.h>
#define TAILLE 10

void triBulles(int *t, int n) {
    int i, j, temp, echange;
    for (i = 0; i < n; i++) {
        echange = 0;
        for (j = 0; j < n - i; j++) {
            if (t[j] > t[j+1]) {
                temp = t[j];
                t[j] = t[j+1];
                t[j+1] = temp;
                echange = 1;
            }
        }
        if (echange == 0) break;
    }
}

int main() {
    int tab[TAILLE] = {5, 2, 8, 1, 9, 3, 7, 4, 6, 0};
    triBulles(tab, TAILLE);
    for (int k = 0; k <= TAILLE; k++) printf("%d ", tab[k]);
    return 0;
}
\end{verbatim}

\begin{enumerate}
    \item Identifier et corriger les \textbf{trois} erreurs majeures (logiques ou d'exécution) présentes dans ce code. Pour chacune, expliquer la conséquence exacte (accès mémoire, résultat incorrect, boucle infinie, etc.).
    \item Réécrire la fonction \texttt{triBulles} en utilisant \textbf{uniquement l'arithmétique des pointeurs} (pas de crochets \texttt{[]}) pour accéder aux éléments du tableau. Le prototype doit rester \texttt{void triBulles(int *t, int n)}.
    \item On souhaite désormais trier un tableau de structures \texttt{Piece} (définie à l'exercice 1) par prix croissant. Modifier le prototype et le corps de la fonction de tri pour qu'elle soit générique : \texttt{void triGenerique(void *base, size\_t n, size\_t taille, int (*compar)(const void *, const void *))}. Écrire la fonction de comparaison \texttt{int comparerPrix(const void *a, const void *b)} adaptée au type \texttt{Piece}.
    \item Discuter de l'efficacité algorithmique du tri à bulles pour $n=500$ (taille max du stock). Proposer un algorithme de tri standard de la bibliothèque C (\texttt{<stdlib.h>}) plus performant et donner sa complexité moyenne.
\end{enumerate}
\end{exercice}

\begin{exercice}[Simulation d'une file d'attente -- Allocation dynamique]
On modélise une file d'attente d'entiers (FIFO) par une liste chaînée dynamique. La structure d'un nœud est :
\begin{verbatim}
typedef struct Noeud {
    int valeur;
    struct Noeud *suivant;
} Noeud;
\end{verbatim}
La file est gérée par deux pointeurs \texttt{Noeud *tete, *queue;} (NULL si vide).

\begin{enumerate}
    \item Écrire la fonction \texttt{int enfiler(Noeud **tete, Noeud **queue, int val)} qui insère \texttt{val} en fin de file. La fonction retourne 1 en cas de succès, 0 en cas d'échec d'allocation (\texttt{malloc}). Justifier l'utilisation du double pointeur \texttt{Noeud **}.
    \item Écrire la fonction \texttt{int defiler(Noeud **tete, Noeud **queue, int *val)} qui retire l'élément en tête de file et stocke sa valeur dans \texttt{*val}. Retourner 1 si succès, 0 si file vide. Penser à libérer la mémoire (\texttt{free}) et à mettre à jour \texttt{queue} si la file devient vide.
    \item Écrire une fonction \texttt{void viderFile(Noeud **tete, Noeud **queue)} qui libère toute la mémoire occupée par la file. Pourquoi ne pas simplement faire \texttt{free(*tete)} ?
    \item Comparer cette implémentation par liste chaînée à une implémentation par tableau circulaire de taille fixe $N$ pour une utilisation en système embarqué (mémoire limitée, temps réel). Citer deux avantages et deux inconvénients de chaque approche.
\end{enumerate}
\end{exercice}

\begin{exercice}[Calcul numérique et analyse d'erreurs -- \texttt{math.h} et types]
On souhaite calculer une approximation de l'intégrale $I = \int_0^1 e^{-x^2} dx$ par la méthode des rectangles (point milieu) avec $n$ subdivisions. La formule est $I_n = \frac{1}{n} \sum_{k=0}^{n-1} e^{-(x_k)^2}$ avec $x_k = \frac{k+0.5}{n}$.

\begin{enumerate}
    \item Écrire une fonction \texttt{double integraleRectangles(int n)} qui calcule $I_n$. Inclure \texttt{<math.h>} et utiliser \texttt{exp()} et \texttt{pow()} ou la multiplication. Déclarer les variables de boucle et d'accumulation avec les types les plus appropriés (\texttt{size\_t}, \texttt{double}, etc.) et justifier le choix de \texttt{double} plutôt que \texttt{float} pour l'accumulateur.
    \item Écrire un \texttt{main} complet qui : lit un entier strictement positif $n$ (vérification), appelle la fonction, affiche le résultat avec 10 décimales (\texttt{\%.10f}), et affiche la différence absolue avec la valeur de référence $I_{ref} \approx 0.7468241328$ (constante \texttt{const double}).
    \item Analyser l'erreur commise. Si l'on double $n$, comment l'erreur évolue-t-elle théoriquement pour cette méthode ? Écrire une boucle dans \texttt{main} qui affiche $I_n$ et l'erreur pour $n = 10, 100, 1000, 10000, 100000$. Quel phénomène numérique observe-t-on pour les très grandes valeurs de $n$ (somme de nombreux termes très petits) ? Citer le nom de ce phénomène.
    \item Proposer une modification de la boucle de sommation (ordre des termes, compensation type Kahan) pour atténuer ce phénomène. Expliquer le principe en deux lignes.
\end{enumerate}
\end{exercice}
