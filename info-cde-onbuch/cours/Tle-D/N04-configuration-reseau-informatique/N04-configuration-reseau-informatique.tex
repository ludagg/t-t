\coursec{Notion de réseau et types de réseaux}

Le lycée bilingue de Nkongsamba vient de recevoir 20 ordinateurs offerts par un partenaire. Le proviseur veut les connecter entre eux et à Internet, mais le technicien consulté parle de « switch », de « classe C » et d'« adresses 192.168 » que personne ne comprend. Pendant ce temps, au cybercafé voisin, les clients se plaignent : quand un poste tombe en panne, tout le réseau s'arrête. Comment concevoir un réseau fiable, choisir les bons équipements et attribuer correctement les adresses ? C'est tout l'objet de cette leçon.

Avant de brancher le moindre câble, il faut d'abord répondre à une question plus simple : \emph{qu'est-ce qu'un réseau, et pourquoi en vouloir un ?} C'est par là que nous commençons.

\courssub{Qu'est-ce qu'un réseau informatique ?}

\textbf{Une situation de la vie quotidienne.} Dans le secrétariat du lycée, la secrétaire tape les bulletins sur son ordinateur, mais l'imprimante est branchée sur la machine du proviseur. Chaque fois qu'elle veut imprimer, elle copie son fichier sur une clé USB, traverse le couloir, branche la clé, imprime, revient. Si le fichier change, elle recommence. Ce va-et-vient est exactement le problème que le réseau résout : au lieu de déplacer physiquement l'information, on \cle{relie} les machines pour qu'elles échangent directement.

\begin{definition}[Réseau informatique]
Un \cle{réseau informatique} est un ensemble d'équipements informatiques (ordinateurs, imprimantes, serveurs, téléphones, équipements d'interconnexion) \textbf{reliés entre eux} par des supports de transmission, afin d'\textbf{échanger des informations} et de \textbf{partager des ressources}.
\end{definition}

Les ressources partagées sont de trois natures :
\begin{itemize}
\item les \textbf{ressources matérielles} : une imprimante unique pour tout le laboratoire, un scanner, un disque dur de grande capacité ;
\item les \textbf{ressources logicielles et données} : fichiers partagés (les bulletins de la secrétaire), bases de données, applications installées sur un serveur ;
\item la \textbf{connexion Internet} : une seule ligne CAMTEL ou une seule box peut servir les 20 postes du lycée.
\end{itemize}

\begin{aretenir}[Pourquoi créer un réseau ?]
Les trois grands intérêts d'un réseau sont :
\begin{enumerate}
\item le \cle{partage de ressources} : une imprimante, un fichier ou une connexion Internet pour tous les postes ;
\item la \cle{communication} : messagerie, courrier électronique, visioconférence entre utilisateurs du réseau ;
\item la \cle{mutualisation des coûts} : au lieu d'acheter 20 imprimantes et 20 abonnements Internet, on achète une imprimante réseau et un seul abonnement partagé.
\end{enumerate}
\end{aretenir}

\begin{attention}[Un réseau n'est pas qu'une question de câbles]
Relier physiquement des machines ne suffit pas : il faut aussi qu'elles \emph{parlent la même langue}. Cette langue commune s'appelle un \cle{protocole} de communication (nous y reviendrons en section 4). Un réseau = du matériel relié \textbf{+} des règles de communication respectées par tous.
\end{attention}

\courssub{Classification des réseaux selon l'étendue géographique}

\textbf{Intuition.} Connecter ton téléphone à ton enceinte Bluetooth sur ta table, connecter 20 ordinateurs dans une salle, connecter toutes les agences bancaires de Douala, connecter le Cameroun au reste du monde : ce sont quatre problèmes de tailles très différentes, qui n'utilisent ni les mêmes technologies ni les mêmes équipements. On classe donc les réseaux selon leur \cle{étendue géographique} (leur portée). On distingue les réseaux \textbf{filaires} (à câbles) et leurs équivalents \textbf{sans fil}.

\begin{definition}[Réseaux filaires : PAN, LAN, MAN, WAN]
\begin{itemize}
\item \cle{PAN} (\emph{Personal Area Network}) : réseau personnel, de quelques mètres de portée. Il relie les appareils d'une seule personne (téléphone, montre connectée, ordinateur portable).
\item \cle{LAN} (\emph{Local Area Network}) : réseau local, limité à un bâtiment ou un site : la salle informatique du lycée, un cybercafé, les bureaux d'une entreprise. Portée : quelques dizaines à quelques centaines de mètres.
\item \cle{MAN} (\emph{Metropolitan Area Network}) : réseau à l'échelle d'une ville, reliant plusieurs sites distants de quelques kilomètres (les différents campus d'une université, les agences d'une banque dans Douala).
\item \cle{WAN} (\emph{Wide Area Network}) : réseau étendu couvrant un pays, un continent ou le monde entier. Internet est le plus grand WAN existant.
\end{itemize}
\end{definition}

\begin{definition}[Réseaux sans fil : WPAN, WLAN, WMAN, WWAN]
Chaque catégorie filaire possède un équivalent sans fil (le préfixe \textbf{W} signifie \emph{Wireless}) :
\begin{itemize}
\item \cle{WPAN} (\emph{Wireless PAN}) : réseau personnel sans fil, technologie typique : \textbf{Bluetooth} (quelques mètres, ex. téléphone $\to$ enceinte ou écouteurs).
\item \cle{WLAN} (\emph{Wireless LAN}) : réseau local sans fil, technologie typique : le \textbf{Wi-Fi} (un bâtiment, une salle, un domicile).
\item \cle{WMAN} (\emph{Wireless MAN}) : réseau métropolitain sans fil, technologie typique : \textbf{WiMAX} (couverture d'une ville).
\item \cle{WWAN} (\emph{Wireless WAN}) : réseau étendu sans fil, technologies typiques : les réseaux \textbf{cellulaires 2G/3G/4G} des opérateurs (MTN, Orange), couvrant des régions entières.
\end{itemize}
\end{definition}

\begin{propriete}[Règle de classification]
Pour classer un réseau, on se pose une seule question : \emph{quelle distance sépare les équipements les plus éloignés ?}
\begin{itemize}
\item quelques mètres $\Rightarrow$ PAN / WPAN ;
\item un bâtiment ou un site $\Rightarrow$ LAN / WLAN ;
\item une ville $\Rightarrow$ MAN / WMAN ;
\item un pays ou plus $\Rightarrow$ WAN / WWAN.
\end{itemize}
La nature filaire ou sans fil du support détermine ensuite si l'on ajoute le préfixe \textbf{W}.
\end{propriete}

\begin{exemplebox}[Classer des réseaux du quotidien]
Classons trois situations :
\begin{itemize}
\item Le \textbf{Wi-Fi du lycée} couvre la salle informatique et la bibliothèque : c'est un réseau local sans fil $\Rightarrow$ \textbf{WLAN}.
\item La connexion \textbf{Bluetooth} entre ton téléphone et ton enceinte portative (2 ou 3 mètres) $\Rightarrow$ \textbf{WPAN}.
\item Le \textbf{réseau national de CAMTEL}, qui relie Douala, Yaoundé, Garoua par fibre optique $\Rightarrow$ \textbf{WAN} (filaire, à l'échelle du pays).
\end{itemize}
\end{exemplebox}

\begin{exoresolu}[Identifier le type de réseau]
\textbf{Énoncé.} Pour chacune des situations suivantes, indique le type de réseau (PAN, LAN, MAN, WAN ou version sans fil) en justifiant par la portée :
\begin{enumerate}
\item la montre connectée d'un élève synchronisée avec son téléphone ;
\item les 20 ordinateurs du lycée bilingue de Nkongsamba reliés par câbles ;
\item le réseau 4G d'Orange couvrant tout le Cameroun ;
\item les trois agences d'une microfinance réparties dans la ville de Bafoussam.
\end{enumerate}
\tcblower
\textbf{Solution détaillée.} On applique la règle : quelle distance sépare les équipements les plus éloignés ?
\begin{enumerate}
\item Téléphone et montre sont portés par la même personne, à moins d'un mètre, sans fil (Bluetooth) $\Rightarrow$ \textbf{WPAN}.
\item 20 postes dans un même bâtiment, reliés par câbles $\Rightarrow$ \textbf{LAN}.
\item Couverture nationale, sans fil, technologie cellulaire 4G $\Rightarrow$ \textbf{WWAN}.
\item Plusieurs sites distants de quelques kilomètres dans une même ville $\Rightarrow$ \textbf{MAN}.
\end{enumerate}
\end{exoresolu}

\courssub{Intranet, extranet et Internet}

\textbf{Intuition.} La classification précédente repose sur la \emph{géographie}. Mais on peut aussi classer les réseaux selon \emph{qui a le droit de s'y connecter}. Le réseau du lycée n'est pas ouvert à n'importe qui ; le site des résultats du baccalauréat, lui, est consultable par tous les candidats du pays. Trois notions distinguent ces situations.

\begin{definition}[Intranet, extranet, Internet]
\begin{itemize}
\item Un \cle{intranet} est un réseau \textbf{privé}, réservé aux membres d'une organisation (lycée, entreprise, ministère). Il utilise les mêmes technologies qu'Internet, mais son accès est protégé (comptes, mots de passe). Exemple : le réseau interne du lycée où les enseignants saisissent les notes.
\item Un \cle{extranet} est la partie d'un intranet \textbf{volontairement ouverte} à des partenaires extérieurs autorisés (fournisseurs, clients, établissements partenaires). Exemple : le lycée donne aux parents d'élèves un accès limité pour consulter les bulletins en ligne.
\item \cle{Internet} (avec un I majuscule) est le \textbf{réseau mondial public}, l'interconnexion de millions de réseaux à travers le monde, accessible à tous. C'est un WAN planétaire.
\end{itemize}
\end{definition}

\begin{aretenir}[Privé, semi-ouvert, public]
Retiens la gradation : \textbf{intranet} = réservé aux membres de l'organisation ; \textbf{extranet} = ouvert à quelques partenaires extérieurs autorisés ; \textbf{Internet} = ouvert au monde entier.
\end{aretenir}

\begin{attention}[Internet n'est pas le Web !]
Erreur très fréquente au Baccalauréat : confondre \textbf{Internet} et le \textbf{Web}.
\begin{itemize}
\item \textbf{Internet} est le \emph{réseau} lui-même : l'infrastructure de câbles, de routeurs et d'équipements qui relie les machines du monde entier.
\item Le \textbf{Web} (World Wide Web) est un \emph{service} qui fonctionne \emph{au-dessus} d'Internet, grâce au protocole HTTP : ce sont les pages et sites web consultés avec un navigateur.
\end{itemize}
Internet héberge d'autres services que le Web : le courrier électronique (SMTP, POP3), le transfert de fichiers (FTP), etc. Dire « je vais sur Internet » pour dire « je consulte un site web » est un abus de langage : tu utilises le Web \emph{grâce à} Internet.
\end{attention}

\begin{savaistu}[Le Cameroun branché au monde : le câble WACS]
Le câble sous-marin \textbf{WACS} (\emph{West Africa Cable System}), long d'environ \num{14000} km, relie l'Afrique du Sud à l'Europe (Royaume-Uni) en longeant la côte ouest africaine. Il arrive à \textbf{Douala}, où il est amarré depuis 2012. Grâce à ce câble en fibre optique, le Cameroun dispose d'une connexion internationale à haut débit : c'est par là que transite l'essentiel du trafic Internet du pays. D'autres câbles (SAT-3, ACE, SAIL) complètent ce dispositif, et la fibre nationale de CAMTEL achemine ensuite la connexion vers l'intérieur du pays : un véritable WAN à l'échelle continentale !
\end{savaistu}

\begin{exercice}[À toi de jouer]
\begin{enumerate}
\item Donne trois ressources que les 20 postes du lycée de Nkongsamba pourraient partager une fois mis en réseau.
\item Le proviseur consulte ses e-mails depuis son téléphone en 4G. À quels types de réseaux fait-il appel, du téléphone jusqu'au serveur de messagerie ?
\item Le lycée ouvre un espace en ligne où les parents consultent les notes de leurs enfants avec un mot de passe. S'agit-il d'un intranet, d'un extranet ou d'Internet ? Justifie.
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice n° 1]
\begin{enumerate}
\item Ressources partageables : une imprimante réseau, des dossiers de fichiers (cours, bulletins), la connexion Internet unique du lycée (on pouvait aussi citer un serveur d'applications ou un scanner).
\item Du téléphone à l'antenne de l'opérateur : réseau cellulaire $\Rightarrow$ \textbf{WWAN} ; de l'opérateur au serveur de messagerie, les données transitent par l'infrastructure mondiale $\Rightarrow$ \textbf{WAN} (Internet). Le service utilisé est le courrier électronique, \emph{au-dessus} d'Internet.
\item C'est un \textbf{extranet} : il s'agit d'une partie du réseau privé du lycée (intranet) ouverte de façon contrôlée à des partenaires extérieurs autorisés (les parents), grâce à un mot de passe. Ce n'est ni l'intranet complet (réservé au personnel) ni un accès public libre comme sur Internet.
\end{enumerate}
\end{corrige}

Maintenant que tu sais ce qu'est un réseau et comment on le classe, une question se pose naturellement pour nos 20 ordinateurs de Nkongsamba : \emph{comment les disposer et les relier concrètement ?} Faut-il les brancher en chaîne, en cercle, autour d'un point central ? C'est la question des \textbf{topologies}, objet de la section suivante — et c'est elle qui expliquera pourquoi, au cybercafé voisin, la panne d'un seul poste paralyse tout le réseau.

\coursec{Topologies physiques et logiques}

Dans la section précédente, nous avons découvert ce qu'est un réseau informatique et nous l'avons classé selon son étendue géographique : PAN, LAN, MAN, WAN. Mais savoir qu'un réseau couvre une salle informatique ou tout un pays ne suffit pas. Imagine le cybercafé de notre accroche : ses dix ordinateurs sont reliés entre eux, d'accord, mais \emph{comment} ? Tous branchés sur un seul câble qui traverse la salle ? Chacun relié à une boîte centrale ? En cercle ? La réponse à cette question n'est pas un détail technique : elle détermine le coût de l'installation, la vitesse du réseau et, surtout, ce qui se passe quand quelque chose tombe en panne. C'est exactement l'objet de cette section : décrire la \emph{forme} d'un réseau, c'est-à-dire sa \cle{topologie}.

\courssub{Topologie physique et topologie logique : deux points de vue}

Reprenons une image simple. Pour décrire le réseau routier du Cameroun, on peut donner la carte des routes telles qu'elles sont tracées sur le terrain (Douala--Yaoundé, Yaoundé--Bafoussam, etc.) : c'est la description \emph{physique}. Mais on peut aussi décrire comment circulent les camions de marchandises : passent-ils tous par un carrefour central ? Suivent-ils un itinéraire en boucle ? C'est la description \emph{logique}. Les deux descriptions concernent le même pays, mais ne disent pas la même chose. Un réseau informatique se décrit exactement de la même manière, à deux niveaux.

\begin{definition}[Topologie physique]
La \cle{topologie physique} d'un réseau décrit la \textbf{disposition réelle et matérielle} des câbles, des ordinateurs et des équipements d'interconnexion : quelle machine est reliée à quelle autre, et par quel câble. On la représente par un schéma où les ordinateurs sont des \emph{nœuds} et les câbles des \emph{liaisons} (arêtes).
\end{definition}

\begin{definition}[Topologie logique]
La \cle{topologie logique} d'un réseau décrit la \textbf{manière dont les données circulent} entre les machines, indépendamment de la disposition des câbles : qui a le droit d'émettre, à quel moment, et selon quelle règle d'accès au support de transmission.
\end{definition}

\begin{aretenir}[L'idée fondamentale]
Physique = ce que l'on \emph{voit} (les câbles). Logique = ce qui se \emph{passe} (la circulation des données). Un même câblage peut donner lieu à des modes de circulation différents : les deux notions sont indépendantes, et c'est un piège classique de l'examen que de les confondre.
\end{aretenir}

\courssub{Les quatre topologies physiques}

\textbf{La topologie en bus}\par
Tous les ordinateurs sont branchés sur \textbf{un seul câble unique}, appelé \emph{bus} ou \emph{tronc commun}, terminé à ses deux extrémités par des \textbf{résistances de terminaison} (souvent appelées \emph{bouchons}) qui absorbent le signal et évitent les réflexions. Quand un poste émet, le message se propage dans les deux sens et \emph{tous} les postes le reçoivent ; seul le destinataire indiqué dans la trame l'exploite, les autres l'ignorent. C'est la topologie historique d'Ethernet 10BASE2 (câble coaxial fin) et 10BASE5 (câble coaxial épais), normalisée IEEE 802.3.

\begin{itemize}
\item \textbf{Avantages} : très peu de câble nécessaire, donc coût faible ; installation simple ; facile d'ajouter un poste en se branchant sur le bus (prise vampire ou connecteur T).
\item \textbf{Inconvénients} : le câble est un \emph{point unique de défaillance} (SPOF) ; si deux postes émettent en même temps, leurs signaux se mélangent : c'est une \cle{collision} (gérée par CSMA/CD) ; plus il y a de postes, plus le support est encombré et les performances chutent.
\end{itemize}

\textbf{La topologie en étoile}\par
Chaque ordinateur est relié par \textbf{son propre câble} (généralement paires torsadées RJ45) à un équipement central : un \cle{hub} (concentrateur, demi-duplex, domaine de collision unique) ou, aujourd'hui presque toujours, un \cle{switch} (commutateur, plein duplex, un domaine de collision par port). Toute communication entre deux postes transite par ce centre.

\begin{itemize}
\item \textbf{Avantages} : si le câble d'un poste est coupé ou si un poste tombe en panne, \emph{les autres continuent de fonctionner} ; les pannes sont faciles à localiser (le port du switch clignote ou pas) ; on ajoute un poste en le branchant sur un port libre du switch.
\item \textbf{Inconvénients} : il faut beaucoup plus de câble (un par poste) ; et surtout, si l'équipement central tombe en panne, \emph{tout} le réseau s'arrête : la fiabilité du réseau repose entièrement sur ce point central.
\end{itemize}

\textbf{La topologie en anneau}\par
Chaque poste est relié à \textbf{exactement deux voisins}, de sorte que l'ensemble forme une boucle fermée. Les messages circulent de proche en proche, dans un seul sens (uni-directionnel) : chaque poste reçoit la trame, vérifie s'il en est le destinataire, et la retransmet au voisin suivant sinon. La trame finit par revenir à l'émetteur, qui la retire de l'anneau. C'est la topologie physique des réseaux Token Ring (IEEE 802.5) et FDDI (fibre optique, double anneau pour la redondance).

\begin{itemize}
\item \textbf{Avantages} : circulation ordonnée, pas de collision, performances prévisibles et déterministes même avec beaucoup de postes.
\item \textbf{Inconvénients} : la coupure d'une liaison ou la panne d'un poste peut interrompre toute la boucle (sauf double anneau FDDI) ; l'ajout d'un poste impose d'ouvrir momentanément l'anneau.
\end{itemize}

\textbf{La topologie maillée}\par
Chaque poste est relié à \textbf{plusieurs autres postes} ; dans le maillage \emph{complet}, chaque poste est relié à \emph{tous} les autres. S'il existe $n$ postes, le maillage complet exige
\[ \frac{n(n-1)}{2} \]
liaisons : pour $n = 5$ postes, il faut déjà $\frac{5 \times 4}{2} = 10$ câbles, et pour $n = 10$, on atteint $45$ câbles !

\begin{itemize}
\item \textbf{Avantages} : fiabilité maximale, car il existe toujours plusieurs chemins entre deux postes ; si une liaison tombe, les données empruntent un autre itinéraire (routage dynamique).
\item \textbf{Inconvénients} : coût de câblage et de matériel prohibitif, complexité d'installation et de gestion. C'est pourquoi le maillage complet est réservé aux \emph{dorsales} (backbones) d'Internet et aux liaisons entre grands routeurs, où la panne est inacceptable.
\end{itemize}

\begin{propriete}[Comportement en cas de panne (admis, justifié par analyse)]
Analysons le chemin que doit parcourir un message dans chaque cas :
\begin{itemize}
\item En topologie \textbf{bus}, tout message transite par le câble tronc commun. Si ce câble est coupé en un point, le réseau est scindé en deux morceaux qui ne peuvent plus communiquer : \textbf{la rupture du câble principal interrompt tout le réseau}.
\item En topologie \textbf{étoile}, chaque poste possède sa propre liaison vers le centre. Si le câble d'un poste est coupé, \textbf{seule la branche coupée est hors service} ; les autres postes continuent d'échanger normalement à travers l'équipement central. En revanche, la panne de l'équipement central (switch) paralyse l'ensemble du réseau.
\item En topologie \textbf{anneau} simple, la panne d'un poste ou la coupure d'un brin rompt la boucle : \textbf{toute la circulation s'arrête}. (Le double anneau FDDI contourne ce défaut par un second chemin).
\end{itemize}
\end{propriete}

\begin{exemplebox}[Le cybercafé de l'accroche câblé en bus]
Le cybercafé « Espace Jeunesse » de notre accroche a été câblé il y a des années avec un unique câble coaxial courant le long du mur, auquel les dix postes sont raccordés : c'est une topologie en \textbf{bus}. Un matin, un client arrache le câble en déplaçant une table : le tronc est sectionné. Résultat, \emph{les dix postes perdent simultanément la connexion}, même ceux situés loin de la coupure, car le bus est le seul chemin de circulation. Le gérant perd une journée de recette.

\textbf{Solution} : recâbler le cybercafé en \textbf{étoile} autour d'un switch à 16 ports (environ 15 000 FCFA) : chaque poste reçoit son propre câble UTP Cat 6. Désormais, si un client arrache un câble, seul son poste est déconnecté ; les neuf autres continuent de fonctionner, et la réparation se limite à remplacer un câble de branche.
\end{exemplebox}

\courssub{Les topologies logiques : Ethernet et Token Ring}

La topologie physique dit \emph{où} sont les câbles ; reste à régler un problème : \emph{qui parle, et quand ?} Si tous les postes émettent n'importe quand sur un support partagé, les signaux se mélangent et plus rien n'est compréhensible. La topologie logique est précisément la \textbf{règle d'accès au support} (couche MAC). Deux règles historiques dominent.

\textbf{Ethernet : l'accès par contention (CSMA/CD)}\par
\cle{Ethernet} (norme IEEE 802.3) est la topologie logique utilisée aujourd'hui par l'immense majorité des réseaux locaux. Son principe est celui d'une conversation courtoise dans une salle : chacun parle quand il veut, mais \emph{écoute d'abord} si personne ne parle déjà. La méthode historique sur support partagé (bus ou hub) s'appelle \textbf{CSMA/CD} (\emph{Carrier Sense Multiple Access with Collision Detection}) :

\begin{enumerate}
\item un poste qui veut émettre \textbf{écoute} le support : s'il est occupé (porteuse détectée), il attend ;
\item s'il est libre, le poste émet tout en continuant d'écouter (détection de collision) ;
\item si deux postes ont émis en même temps, ils \textbf{détectent la collision}, cessent immédiatement d'émettre, envoient un signal de bourrage (jam), attendent chacun une durée \emph{aléatoire} (algorithme d'attente exponentielle tronquée), puis réessaient.
\end{enumerate}

C'est un accès dit \emph{par contention} : les postes sont en compétition pour le support. Nous admettrons ce principe : il est simple et efficace, mais les performances se dégradent quand le nombre de postes augmente, car les collisions se multiplient. \textbf{Notons qu'avec les switchs modernes (liaisons point à point en plein duplex), les collisions ont pratiquement disparu} : chaque port est un domaine de collision isolé, ce qui explique le succès durable d'Ethernet.

\textbf{Token Ring : le jeton qui circule}\par
\cle{Token Ring} (« anneau à jeton »), normalisé IEEE 802.5, développé par IBM, applique une règle radicalement différente, celle du bâton de parole dans une palabre : un petit message spécial appelé \cle{jeton} (\emph{token}, 3 octets) circule en permanence dans l'anneau, de poste en poste. \textbf{Seul le poste qui détient le jeton a le droit d'émettre.}

\begin{enumerate}
\item un poste qui veut émettre attend l'arrivée du jeton libre (bit \texttt{Monitor} = 0) ;
\item il le « capture », le marque occupé (bit \texttt{Monitor} = 1), y attache sa trame de données et l'adresse destinataire, puis l'envoie au voisin ;
\item la trame circule de proche en proche jusqu'au destinataire, qui la copie, met à jour les bits d'accusé de réception (A/C) et la laisse repartir ;
\item revenue à l'émetteur, celui-ci vérifie l'accusé de réception, retire sa trame de l'anneau et \textbf{libère un nouveau jeton libre}, qui repart vers le poste suivant.
\end{enumerate}

Grâce au jeton, il ne peut jamais y avoir deux émissions simultanées : \emph{aucune collision n'est possible}, et chaque poste est sûr de pouvoir émettre dans un délai borné (déterministe). En contrepartie, la gestion du jeton (perte, duplication, poste moniteur) complique le protocole, et le matériel était plus coûteux qu'Ethernet, ce qui explique sa disparition progressive.

\begin{attention}[Physique en étoile, logique en anneau !]
Erreur fréquente à l'examen : croire qu'un câblage en étoile implique forcément une circulation « en étoile ». Historiquement, les réseaux \textbf{Token Ring} étaient câblés \emph{physiquement en étoile} autour d'une armoire centrale appelée \textbf{MAU} (\emph{Multistation Access Unit}), mais à l'intérieur de cette armoire, les câbles étaient bouclés de sorte que le jeton circulait \emph{logiquement en anneau}. Retiens bien : la topologie physique se voit sur les câbles, la topologie logique se déduit de la règle de circulation des données (protocole MAC). Ce sont deux questions indépendantes.
\end{attention}

\begin{methode}[Choisir une topologie physique pour un LAN]
Pour choisir la topologie d'un réseau local à installer, procède par étapes :
\begin{enumerate}
\item \textbf{Évalue le budget et la durée de vie.} Budget très serré et réseau provisoire (quelques mois) : le bus (si matériel dispo) est le moins cher, mais accepte sa fragilité et son obsolescence.
\item \textbf{Évalue la taille et la croissance.} S'il faut ajouter régulièrement des postes (salle informatique de lycée, entreprise qui recrute), l'étoile est imbattable : un port libre suffit, voire l'ajout d'un second switch en cascade.
\item \textbf{Évalue la fiabilité exigée.} Si une panne de quelques heures est acceptable, l'étoile simple suffit. Si le service ne doit \emph{jamais} s'arrêter (serveurs critiques, liaisons inter-sites), prévois de la redondance : double liaison vers le switch cœur, switchs empilables (stack) ou maillage partiel entre équipements de distribution.
\item \textbf{Conclus.} Dans la pratique, pour tout réseau local moderne (LAN), le choix standard est : \textbf{topologie physique en étoile autour d'un switch (ou stack de switchs), topologie logique Ethernet (IEEE 802.3, plein duplex)}. Le maillage est réservé aux cœurs de réseaux des opérateurs (backbone).
\end{enumerate}
\end{methode}

\begin{exoresolu}[Quelle topologie pour le lycée ?]
Énoncé. Un lycée de Yaoundé veut équiper sa salle multimédia de 20 ordinateurs reliés entre eux et à un serveur pédagogique. Le proviseur hésite entre un câblage en bus (devis : 60 000 FCFA) et un câblage en étoile autour d'un switch 24 ports Gigabit (devis : 180 000 FCFA). Le réseau devra accueillir 10 postes supplémentaires l'an prochain, et les enseignants exigent que la panne d'un poste ne perturbe pas les séances des autres classes. Quelle topologie conseilles-tu ? Justifie.
\tcblower
Solution détaillée. Analysons les trois contraintes de l'énoncé.
\begin{enumerate}
\item \emph{Évolution prévue} (+10 postes) : en bus, chaque ajout dégrade les performances (support unique partagé, collisions croissantes, limite de 30 postes sur segment 10BASE2) ; en étoile, il suffit de brancher les nouveaux postes sur les 4 ports libres du switch 24 ports, quitte à ajouter un second switch plus tard sans perturber l'existant.
\item \emph{Fiabilité exigée} : en bus, la rupture du câble tronc interrompt \emph{tout} le réseau, ce qui contredit directement l'exigence des enseignants ; en étoile, la panne ou la coupure d'une branche n'affecte que le poste concerné (domaine de collision isolé par le switch).
\item \emph{Budget} : l'étoile coûte trois fois plus cher à l'installation, mais le bus ferait courir un risque d'arrêt total des séances et imposerait un recâblage complet à moyen terme (coût caché).
\end{enumerate}
\textbf{Conclusion} : on conseille la topologie en \textbf{étoile} autour du switch 24 ports Gigabit, avec la topologie logique \textbf{Ethernet} (plein duplex, sans collision). Le surcoût initial est amorti par la fiabilité (une panne de poste ne perturbe personne), la performance (1 Gbit/s dédié par poste) et l'évolutivité (ajout simple des 10 futurs postes). Le seul point fragile reste le switch lui-même : on prévoira un onduleur (protection secteur) et un switch de rechange à froid.
\end{exoresolu}

\begin{savaistu}[L'étoile, norme universelle]
Aujourd'hui, la quasi-totalité des réseaux locaux du monde — entreprises, administrations, campus, lycées et cybercafés camerounais — est câblée en \textbf{étoile} autour de switchs, avec la topologie logique \textbf{Ethernet}. Le bus (coaxial) et l'anneau (Token Ring) ont disparu des installations neuves. Quant à la topologie maillée, elle règne là où tu ne la vois pas : entre les grands routeurs des dorsales Internet, comme les liaisons fibrées qui relient Douala et Yaoundé aux câbles sous-marins (WACS, ACE, SAIL), où chaque nœud possède plusieurs chemins de secours (protocoles OSPF, BGP) pour que jamais le trafic ne s'arrête.
\end{savaistu}

\begin{exercice}[Topologies et pannes]
Un réseau de 6 postes est câblé en anneau physique simple (unidirectionnel).
\begin{enumerate}
\item Combien de voisins possède chaque poste ? Quel est le nombre total de liaisons ?
\item Le poste P3 tombe en panne (carte réseau HS, ne retransmet plus). Que devient la circulation des messages entre P1 et P4 ?
\item Combien de liaisons faudrait-il pour câbler ces 6 postes en maillage complet ? Conclus sur le coût relatif.
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice 1]
\begin{enumerate}
\item En anneau, chaque poste est relié à \textbf{deux voisins} : un voisin amont (dont il reçoit) et un voisin aval (vers qui il émet). Nombre total de liaisons = nombre de postes = \textbf{6}.
\item P3 ne retransmet plus les trames : la boucle est rompue physiquement. \textbf{Toute la circulation s'arrête} : P1 ne peut plus joindre P4, ni aucun autre poste. (D'où l'intérêt du double anneau FDDI ou du MAU Token Ring qui bypasse le port défaillant).
\item En maillage complet, il faut $\dfrac{n(n-1)}{2} = \dfrac{6 \times 5}{2} = 15$ liaisons, contre 6 pour l'anneau : le maillage complet est donc ici $2,5$ fois plus câblé, ce qui illustre son coût prohibitif dès que le nombre de postes grandit.
\end{enumerate}
\end{corrige}

Nous savons désormais \emph{comment} disposer les machines et \emph{comment} les données circulent. Mais de quoi sont faits ces câbles (paires torsadées, fibre), et quels équipements — cartes réseau (NIC), hubs, switchs, routeurs, box — font vivre ces topologies ? C'est l'objet de la section suivante.

\coursec{Supports de transmission et équipements réseau}

Dans la section précédente, nous avons appris à \emph{dessiner} un réseau : topologie en bus, en étoile, en anneau. Mais un schéma ne suffit pas pour faire communiquer réellement des machines. Il reste deux questions concrètes : \textbf{par quel support physique} l'information va-t-elle voyager (un câble ? une onde ? de la lumière ?), et \textbf{grâce à quels équipements} les ordinateurs vont-ils être reliés entre eux ? C'est exactement la situation du lycée bilingue de Bafoussam qui veut câbler sa salle multimédia : avant d'acheter quoi que ce soit, il faut connaître les supports de transmission et le rôle de chaque boîtier que le fournisseur propose. C'est l'objet de cette section.

\courssub{Les supports de transmission filaires}

\begin{definition}[Support de transmission]
Un \cle{support de transmission} est le \textbf{médium physique} par lequel circulent les signaux porteurs de l'information entre deux équipements d'un réseau. On distingue les supports \textbf{filaires} (câbles : paires torsadées, coaxial, fibre optique) et les supports \textbf{sans fil} (ondes radio, infrarouge). Dans cette section, nous étudions les supports filaires.
\end{definition}

\textbf{Pourquoi plusieurs supports ?} Parce qu'aucun câble n'est parfait sur tous les critères : débit, distance, coût, résistance aux perturbations. Le bon choix dépend du besoin. Étudions les trois supports filaires au programme.

\courssub{Les paires torsadées (câble RJ45)}

C'est le câble que tu vois partout : dans les salles informatiques, derrière les box Internet, dans les cybercafés de quartier. Il est constitué de \textbf{quatre paires de fils de cuivre torsadés} (enroulés en hélice deux par deux). La torsion n'est pas décorative : elle réduit les interférences électromagnétiques entre les paires (diachronie) et les perturbations extérieures. Le câble se termine par un connecteur appelé \cle{RJ45} (Registered Jack 45), qui ressemble à une grosse prise téléphonique (RJ11) mais avec 8 contacts au lieu de 4.

\begin{aretenir}[Paires torsadées : l'essentiel]
\begin{itemize}
\item Support le plus \textbf{courant dans les réseaux locaux (LAN)} et le \textbf{moins cher} ;
\item Débit courant : \SI{100}{Mbit/s} (Cat 5e), \SI{1}{Gbit/s} (Cat 5e/6), voire \SI{10}{Gbit/s} (Cat 6a/7) sur de courtes distances ;
\item \textbf{Portée limitée à \SI{100}{m}} par segment (norme IEEE 802.3) : au-delà, le signal s'affaiblit trop (atténuation) et il faut un équipement intermédiaire (switch) pour le régénérer ;
\item Sensibilité moyenne aux perturbations électromagnétiques (éviter de le faire passer le long de câbles électriques puissants, de néons ou de moteurs) ;
\item Existe en \textbf{UTP} (non blindé, le plus courant), \textbf{F/UTP} (blindage global) ou \textbf{S/FTP} (blindage par paire + global) pour les environnements bruités.
\end{itemize}
\end{aretenir}

\courssub{Le câble coaxial}

Le câble coaxial est constitué d'un \textbf{conducteur central en cuivre} entouré d'un isolant diélectrique, puis d'une \textbf{tresse métallique de blindage} (et parfois un feuillard), le tout protégé par une gaine plastique. C'est le même type de câble qui amène historiquement le signal de la télévision par câble ou l'Internet par câble (DOCSIS).

\begin{aretenir}[Câble coaxial : l'essentiel]
\begin{itemize}
\item Support \textbf{historique} : c'était le câble des premiers réseaux Ethernet en topologie bus (standards 10BASE5 « thicknet » et 10BASE2 « thinnet », années 1980-1990) ;
\item Grâce à son \textbf{blindage}, il résiste mieux aux perturbations que les paires torsadées non blindées ;
\item Portée : \SI{185}{m} (10BASE2) à \SI{500}{m} (10BASE5) sans répéteur ; débit : \SI{10}{Mbit/s} ;
\item Aujourd'hui \textbf{quasiment abandonné} dans les LAN au profit des paires torsadées (coût, encombrement, connectique BNC fragile, topologie bus obsolète), mais encore utilisé pour la télévision par câble et certains raccordements opérateurs (derniers mètres).
\end{itemize}
\end{aretenir}

\courssub{La fibre optique}

La fibre optique est un fil de verre (silice) ou de plastique très fin (cœur de \SI{9}{\micro m} pour la monomode, \SI{50}{\micro m} ou \SI{62.5}{\micro m} pour la multimode, gaine \SI{125}{\micro m}) dans lequel on envoie des \textbf{impulsions lumineuses} produites par un laser (monomode) ou une LED/VCSEL (multimode). La lumière se propage par \textbf{réflexion totale} sur l'interface cœur/gaine, sans jamais en sortir.

\begin{aretenir}[Fibre optique : l'essentiel]
\begin{itemize}
\item \textbf{Très haut débit} : de \SI{1}{Gbit/s} à plusieurs \SI{100}{Gbit/s} (voire Tbit/s sur dorsales avec multiplexage DWDM) ;
\item \textbf{Très longue portée} : plusieurs kilomètres (multimode) à plusieurs dizaines/centaines de kilomètres (monomode) sans amplification ;
\item \textbf{Totalement insensible aux interférences électromagnétiques} (elle transporte de la lumière, pas de l'électricité) : idéale en milieu industriel, pour les liaisons inter-bâtiments ou les dorsales ;
\item Inconvénients : \textbf{coût élevé} (câble, jarretières, modules SFP/SFP+, soudeuse à arc pour la pose), fragilité mécanique (rayon de courbure minimal à respecter), connectique délicate (polissage des ferrules).
\end{itemize}
\end{aretenir}

\begin{savaistu}[La fibre optique au Cameroun]
La fibre optique transmet l'information par des \textbf{impulsions lumineuses} et peut atteindre plusieurs Tbit/s sur les dorsales internationales grâce au multiplexage en longueur d'onde (DWDM). Le Cameroun dispose d'un réseau national de fibre optique de plusieurs milliers de kilomètres (backbone national), exploité notamment par \textbf{CAMTEL}, et relié aux câbles sous-marins (comme le câble \textbf{WACS} — West Africa Cable System — arrivant à Douala, ou \textbf{ACE} — Africa Coast to Europe). C'est cette infrastructure qui permet l'Internet haut débit dans les grandes villes (Yaoundé, Douala, Bafoussam, Garoua...) et qui connecte de plus en plus d'administrations (MINPOSTEL, universités, hôpitaux) via le projet \textbf{Cameroun Digital}.
\end{savaistu}

\begin{exemplebox}[Quel support pour quel besoin ?]
\begin{itemize}
\item Relier 20 ordinateurs dans la salle multimédia d'un lycée (distances $<$ \SI{30}{m}) : \textbf{paires torsadées Cat 6 UTP RJ45} (distances courtes, coût faible, débit \SI{1}{Gbit/s} garanti).
\item Relier deux bâtiments du campus distants de \SI{2}{km} : \textbf{fibre optique monomode} (portée \textgreater{} \SI{100}{m}, immunité aux orages/parasites inter-bâtiments, débit \SI{10}{Gbit/s}+).
\item Câble coaxial : on ne le choisit plus pour un nouveau réseau local ; on le rencontre seulement dans d'anciennes installations ou pour la prise TV/Box opérateur.
\end{itemize}
\end{exemplebox}

\courssub{La carte réseau (NIC)}

Avant tout équipement externe, un ordinateur ne peut pas se connecter à un réseau sans un composant interne indispensable.

\begin{definition}[Carte réseau — NIC]
La \cle{carte réseau} (en anglais \emph{Network Interface Card}, \cle{NIC}) est le composant matériel qui sert d'\textbf{interface entre l'ordinateur et le réseau} : c'est elle qui émet et reçoit les signaux sur le câble (via un contrôleur PHY/MAC) ou les ondes (carte WIFI). Chaque carte réseau possède une \textbf{adresse physique unique au monde}, appelée \cle{adresse MAC} (Media Access Control), gravée en usine dans une mémoire EEPROM (exemple : \texttt{5C:26:0A:4B:91:2E} ou \texttt{5C-26-0A-4B-91-2E}). Les 3 premiers octets identifient le constructeur (OUI), les 3 suivants le numéro de série.
\end{definition}

Retiens la distinction fondamentale : l'\textbf{adresse MAC} (couche 2, liaison de données) identifie \emph{physiquement} l'interface (elle ne change pas, sauf usurpation logicielle), tandis que l'\textbf{adresse IP} (couche 3, réseau) identifie \emph{logiquement} la machine \emph{dans un réseau donné} (elle peut changer selon le réseau). La commande \texttt{ipconfig /all} sous Windows (ou \texttt{ip link} / \texttt{ifconfig -a} sous Linux) affiche d'ailleurs les deux pour chaque interface.

\courssub{Le hub (concentrateur)}

\begin{definition}[Hub]
Un \cle{hub} (ou \textbf{concentrateur}) est un équipement de \textbf{couche 1 (physique)} qui reçoit les signaux sur un port et les \textbf{répète (régénère) vers tous ses autres ports}, sans aucune analyse du destinataire (adresse MAC). Il ne gère qu'un seul domaine de collision pour tous ses ports.
\end{definition}

Conséquence : si l'ordinateur A envoie une trame à l'ordinateur B, les ordinateurs C et D la reçoivent aussi (diffusion broadcast). Pire, si deux machines émettent en même temps, leurs signaux se mélangent sur le médium partagé : c'est une \cle{collision} (domaine de collision unique), et les données doivent être retransmises (algorithme CSMA/CD). Plus il y a de machines, plus il y a de collisions, et plus le débit utile chute. C'est pourquoi le hub est aujourd'hui \textbf{obsolète} : on ne l'achète plus, on le remplace par un switch.

\courssub{Le switch (commutateur)}

\begin{definition}[Switch]
Un \cle{switch} (ou \textbf{commutateur}) est un équipement de \textbf{couche 2 (liaison de données)} qui relie les machines d'un même réseau local et qui \textbf{transmet les trames uniquement vers le port du destinataire}, grâce à l'adresse MAC de destination lue dans chaque trame.
\end{definition}

Le switch \textbf{apprend} dynamiquement : à la réception d'une trame, il note l'adresse MAC source et le port d'arrivée dans sa \textbf{table d'adresses MAC} (table de commutation). S'il connaît le port de destination, il transmet uniquement sur ce port (unicast) ; sinon, il inonde (flooding) sur tous les ports sauf l'émetteur.

\begin{propriete}[Switch et domaines de collision — admis]
Contrairement au hub, le switch \textbf{crée un domaine de collision par port}. En mode \textbf{full-duplex} (standard aujourd'hui : émission et réception simultanées sur deux paires distinctes), les collisions sont \textbf{éliminées} : chaque paire émetteur--récepteur dispose de sa propre « voie » de communication dédiée. C'est pour cette raison que le switch est l'\textbf{équipement central des LAN modernes} (commutation à vitesse filaire, non-bloquante).
\end{propriete}

\courssub{Le modem}

\begin{definition}[Modem]
Un \cle{modem} (contraction de \emph{MOdulateur--DÉModulateur}) est un équipement de \textbf{couche 1 (physique)} qui \textbf{adapte le signal numérique de l'ordinateur (ou du routeur) à la ligne de transmission analogique ou spécifique} du fournisseur d'accès (FAI), et inversement. Il transforme les bits (0/1) en signaux compatibles avec le support (modulation) et réciproquement (démodulation).
\end{definition}

Exemples concrets selon la technologie d'accès :
\begin{itemize}
\item \textbf{Modem ADSL/VDSL} (ligne téléphonique cuivre) : module sur porteuses hautes fréquences (DMT) ; fourni par CAMTEL.
\item \textbf{Modem Câble (DOCSIS)} : module sur canaux TV (QAM) ; réseau coaxial opérateur.
\item \textbf{Modem Fibre (ONT -- Optical Network Terminal)} : convertit signal optique $\leftrightarrow$ électrique Ethernet ; terme « modem » souvent utilisé abusivement pour l'ONT.
\item \textbf{Modem 4G/5G (Clé USB, Box 4G, Routeur 4G)} : module sur ondes radio (OFDMA) ; réseaux MTN, Orange, Nexttel.
\end{itemize}
Sans modem, ton équipement réseau « parle » Ethernet (signaux différentiels sur paires torsadées), un langage que la ligne téléphonique, le câble coaxial opérateur ou l'onde radio ne comprennent pas nativement.

\courssub{Le routeur}

\begin{definition}[Routeur]
Un \cle{routeur} est un équipement de \textbf{couche 3 (réseau)} qui \textbf{interconnecte des réseaux différents} (chacun avec son propre préfixe d'adressage IP) et qui \textbf{choisit le meilleur chemin} (routage) pour acheminer les paquets de données d'un réseau à l'autre, en se basant sur leurs \textbf{adresses IP de destination} et sa \textbf{table de routage}.
\end{definition}

L'image à retenir : le routeur est le \textbf{carrefour intelligent} d'Internet. Quand un élève du lycée consulte un site hébergé en Europe, le paquet traverse plusieurs routeurs successifs (passerelles), chacun consultant sa table de routage pour rediriger le paquet vers le prochain saut (\emph{next hop}) le plus approprié. À la maison ou au bureau, ta « box » Internet est en réalité une \textbf{passerelle résidentielle (Residential Gateway)} qui \textbf{cumule plusieurs fonctions} dans un seul boîtier :
\begin{itemize}
\item \textbf{Modem} (ONT, ADSL, 4G...) : interface ligne WAN.
\item \textbf{Routeur} : NAT (translation d'adresses), pare-feu, DHCP serveur, DNS relay, routage LAN $\leftrightarrow$ WAN.
\item \textbf{Switch} (généralement 4 ports RJ45 Gigabit) : interconnexion LAN filaire.
\item \textbf{Point d'accès WIFI (AP)} : interconnexion LAN sans fil (802.11ac/ax).
\end{itemize}

\begin{attention}[Erreur fréquente : confondre switch et routeur]
C'est la confusion classique au Baccalauréat :
\begin{itemize}
\item Le \textbf{switch} relie des machines \textbf{à l'intérieur d'un même réseau local (LAN)} — même préfixe IP — et travaille avec les \textbf{adresses MAC} (couche 2).
\item Le \textbf{routeur} relie \textbf{des réseaux différents entre eux} (préfixes IP distincts : ex. LAN $192.168.1.0/24$ et WAN Internet) et travaille avec les \textbf{adresses IP} (couche 3).
\end{itemize}
Phrase-clé à retenir : \emph{« Le switch commute \textbf{dans} le LAN (MAC), le routeur route \textbf{entre} les réseaux (IP) »}. Dire « le switch relie le réseau du lycée à Internet » est une erreur technique majeure.
\end{attention}

\courssub{Choisir le bon équipement selon le besoin}

\begin{methode}[Identifier l'équipement adapté à un besoin décrit dans un énoncé]
Face à une question du type « quel équipement faut-il pour... ? », applique la démarche suivante :
\begin{enumerate}
\item \textbf{Repérer le périmètre} : s'agit-il de relier des machines \emph{entre elles, dans un même local / même réseau IP} (LAN), ou de relier le réseau \emph{à l'extérieur / à un autre réseau IP} (WAN/Internet) ?
\item \textbf{Besoin interne au LAN} (partage fichiers, imprimante, serveur local) : c'est un \textbf{Switch} (jamais un hub, obsolète ; jamais un routeur, qui sert entre réseaux). Précise que chaque machine doit avoir une \textbf{carte réseau} (NIC) et un câble \textbf{RJ45} (ou liaison WIFI via un Point d'Accès).
\item \textbf{Besoin d'interconnexion entre réseaux} (ex. LAN $\to$ Internet, LAN Siège $\leftrightarrow$ LAN Agence) : c'est un \textbf{Routeur}.
\item \textbf{Besoin d'adaptation à la ligne du fournisseur} (ligne téléphonique, câble coaxial opérateur, fibre FTTH, réseau mobile 4G/5G) : c'est un \textbf{Modem} (ou ONT pour la fibre).
\item \textbf{Vérifier si les deux sont nécessaires} : pour un accès Internet complet, il faut souvent Modem \emph{et} Routeur (ou une Box / Passerelle résidentielle qui les combine).
\end{enumerate}
\end{methode}

\begin{exemplebox}[Relier le réseau du lycée à Internet via CAMTEL Fibre]
Le lycée veut connecter son réseau local à Internet par une liaison \textbf{FTTH (Fiber To The Home)} de CAMTEL. Il faut \textbf{un ONT (Modem optique) ET un Routeur} :
\begin{itemize}
\item L'\textbf{ONT} (fournis par CAMTEL) est indispensable : il termine la fibre optique, convertit le signal lumineux en signal électrique Ethernet (couche 1). Sans lui, le routeur ne peut pas se brancher sur la fibre (pas de port SFP standard sur les routeurs grand public).
\item Le \textbf{Routeur} (souvent fourni ou géré par l'établissement) est indispensable car le LAN du lycée ($192.168.10.0/24$ par ex.) et le réseau de CAMTEL (adresses publiques) sont \textbf{deux réseaux IP différents} : seul un routeur sait diriger les paquets de l'un vers l'autre (NAT, routage, pare-feu).
\end{itemize}
En pratique, CAMTEL fournit souvent une \textbf{Box} (Passerelle résidentielle) qui intègre ONT + Routeur + Switch 4 ports + WIFI dans un seul boîtier. Le switch du lycée se branche alors sur un port LAN de la Box.
\end{exemplebox}

\begin{exoresolu}[Équiper la salle informatique d'un collège]
Énoncé. Un collège de Yaoundé dispose de 12 ordinateurs dans une salle informatique. Le proviseur veut : (a) permettre aux 12 postes d'échanger des fichiers entre eux ; (b) partager une imprimante réseau ; (c) donner à toute la salle un accès Internet via une ligne Fibre FTTH CAMTEL. Un fournisseur propose : un hub 16 ports, un switch 16 ports, un ONT Fibre, un routeur. Pour chaque besoin, indique l'équipement adapté en justifiant, et précise si le hub proposé est un bon choix.
\tcblower
Solution détaillée.
\begin{enumerate}
\item \textbf{Échanges entre les 12 postes (a) et partage de l'imprimante (b)} : c'est un besoin \emph{interne au LAN}. L'équipement adapté est le \textbf{Switch 16 ports} (Gigabit de préférence) : il relie toutes les machines (et l'imprimante réseau) en étoile et envoie les trames uniquement au port du destinataire (apprentissage MAC), ce qui élimine les collisions (full-duplex) et garantit le débit \SI{1}{Gbit/s} par poste. Chaque poste doit bien sûr posséder une \textbf{carte réseau} (NIC) \SI{1}{Gbit/s} et être relié au switch par un câble à \textbf{paires torsadées Cat 6 RJ45} (distance $<$ \SI{100}{m}, coût faible).
\item \textbf{Le hub est un mauvais choix} : il répète les signaux vers tous les ports (half-duplex imposé), créant un unique domaine de collision. Avec 12 postes actifs, le taux de collision rendrait le réseau inutilisable (débit utile effondré). Le hub est obsolète depuis 15+ ans : on choisit le switch.
\item \textbf{Accès Internet (c)} : il faut d'abord l'\textbf{ONT Fibre} (fourni par CAMTEL), qui convertit le signal optique de la fibre en Ethernet ; puis le \textbf{Routeur}, qui interconnecte le LAN du collège (réseau privé) avec le réseau de CAMTEL (réseau public, adresses IP publiques) et choisit le chemin des paquets vers Internet (NAT, pare-feu, DHCP serveur pour le LAN). Le routeur sera relié d'un côté au switch (port LAN), de l'autre à l'ONT (port WAN).
\end{enumerate}
Schéma final : 12 PC + Imprimante $\xrightarrow{\text{RJ45}}$ Switch $\xrightarrow{\text{RJ45}}$ Routeur $\xrightarrow{\text{RJ45}}$ ONT Fibre $\xrightarrow{\text{Fibre}}$ Internet CAMTEL.
\end{exoresolu}

\begin{exercice}[À toi de jouer]
Une ONG installe un bureau à Maroua avec 5 ordinateurs portables. Elle veut : (1) que les postes partagent des documents entre eux via un serveur de fichiers local ; (2) que tout le bureau accède à Internet grâce au réseau 4G de l'opérateur Orange. 
\begin{enumerate}
\item Quels équipements faut-il acheter au minimum ? Justifie chaque choix en précisant la couche OSI concernée.
\item La distance entre le bureau et l'antenne relais 4G (quelques km) pose-t-elle un problème de câblage ? Quel support de transmission est ici utilisé entre le modem et l'opérateur ?
\item Si l'ONG déménage dans un local plus grand où les câbles RJ45 dépasseraient \SI{100}{m}, quelle solution technique préconises-tu ?
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice — ONG de Maroua]
\begin{enumerate}
\item Équipements minimaux :
\begin{itemize}
\item Un \textbf{Switch} (8 ports Gigabit) — Couche 2 : pour interconnecter les 5 PC + le serveur de fichiers en étoile (LAN filaire stable et rapide). Chaque poste a sa carte réseau (NIC).
\item Un \textbf{Routeur 4G} (ou Box 4G) — Couche 3 : pour faire le routage entre le LAN privé de l'ONG et le réseau WAN de l'opérateur Orange (adressage IP public dynamique, NAT).
\item Un \textbf{Modem 4G} — Couche 1 : intégré dans la Box 4G / Routeur 4G (slot carte SIM), il module/démodule les signaux sur les ondes radio (bandes 4G Orange Cameroun).
\end{itemize}
\textit{Note :} Un seul boîtier « Routeur 4G WIFI » (Box 4G) combine Modem + Routeur + Switch (4 ports) + Point d'accès WIFI. Si les 5 portables ont du WIFI, le switch filaire devient optionnel (mais le filaire reste préférable pour le serveur).
\item \textbf{Non, aucun problème de câblage} : entre le modem 4G (intégré à la box) et l'antenne relais de l'opérateur, le support de transmission est \textbf{sans fil} (ondes radioélectriques, couche 1 physique). Il n'y a donc aucun câble à tirer sur des kilomètres. Seules les liaisons internes au bureau (PC $\leftrightarrow$ Switch/Box) utilisent des câbles RJ45 (ou le WIFI).
\item Pour dépasser \SI{100}{m} en filaire : déployer de la \textbf{fibre optique multimode} (portée \SI{550}{m} en 10G, \SI{2}{km} en 1G) entre le switch principal et un second switch distant (liaison uplink fibre via modules SFP), ou utiliser des \textbf{répéteurs/extenders Ethernet} (peu recommandés au-delà de 2-3 sauts), ou passer en \textbf{WIFI} (borne d'accès) si le débit le permet. La fibre est la solution professionnelle standard.
\end{enumerate}
\end{corrige}

\begin{aretenir}[Bilan de la section]
\begin{itemize}
\item Trois supports filaires : \textbf{Paires torsadées RJ45} (LAN, $\le$ \SI{100}{m}, Cat 5e/6/6a, coût faible), \textbf{Coaxial} (historique LAN, TV/Box opérateur, blindé), \textbf{Fibre optique} (Très haut débit, km, immunité EMI, coût élevé, monomode/multimode).
\item \textbf{Carte réseau (NIC)} : interface machine/réseau, possède \textbf{adresse MAC} unique (couche 2, physique).
\item \textbf{Hub} (Couche 1) : répète vers tous $\to$ 1 domaine de collision $\to$ \textbf{obsolète}.
\item \textbf{Switch} (Couche 2) : commute vers destinataire (table MAC) $\to$ 1 domaine de collision par port, full-duplex $\to$ \textbf{cœur du LAN}.
\item \textbf{Modem/ONT} (Couche 1) : adaptation signal ligne FAI (ADSL, Câble, Fibre, 4G/5G).
\item \textbf{Routeur} (Couche 3) : interconnexion réseaux IP distincts, routage table IP, NAT, pare-feu.
\item Règle d'or : \textbf{Switch \emph{dans} le LAN (MAC), Routeur \emph{entre} les réseaux (IP)} ; Accès Internet = Modem + Routeur (souvent Box tout-en-un).
\end{itemize}
\end{aretenir}

Maintenant que nos machines sont physiquement reliées par les bons câbles et les bons équipements, il reste à comprendre \emph{le langage} qu'elles utilisent pour se parler : ce seront les \textbf{protocoles de communication}, objet de la section suivante.

\coursec{Protocoles de communication et protocoles Internet}

Dans la section précédente, nous avons vu comment interconnecter physiquement des machines : câbles à paires torsadées, fibre optique, cartes réseau, switch, routeur... Le réseau du cybercafé de quartier est désormais \emph{matériellement} câblé. Mais un câble qui relie deux ordinateurs ne suffit pas : il faut encore que les machines se \emph{comprennent}. Quand ton navigateur demande une page Web, comment le serveur sait-il ce qu'on lui demande ? Comment le message est-il découpé, adressé, acheminé ? C'est exactement le rôle des \cle{protocoles}. Cette section répond à la question : \textbf{quelles règles régissent le dialogue entre les machines d'un réseau ?}

\courssub{Notion de protocole}

\courssub{Une analogie pour comprendre : la conversation humaine}

Imagine deux personnes qui se rencontrent à Yaoundé. Pour que la conversation réussisse, elles doivent respecter des règles implicites : parler une \textbf{langue commune} (le français, l'anglais, l'ewondo...), ne pas parler en même temps, saluer avant de demander quelque chose, attendre une réponse avant de continuer. Si l'une parle français et l'autre japonais, ou si les deux parlent en même temps, la communication échoue, même si les deux voix se portent parfaitement dans l'air.

Les ordinateurs sont dans la même situation : le câble ou les ondes Wi-Fi transportent bien les signaux (c'est le « son de la voix »), mais il faut des \textbf{règles de dialogue} pour que les données échangées aient un sens : qui parle en premier ? Sous quelle forme sont envoyées les données ? Comment l'autre machine accuse-t-elle réception ?

\begin{definition}[Protocole de communication]
Un \cle{protocole} de communication est un \textbf{ensemble de règles et de conventions} qui régissent l'échange de données entre des équipements d'un réseau : format des messages, ordre des échanges, gestion des erreurs, accusés de réception. Deux machines ne peuvent communiquer que si elles utilisent le \textbf{même protocole}.
\end{definition}

\begin{aretenir}[L'idée essentielle]
Le support physique (câble, fibre, onde radio) est la \emph{route} ; le protocole est le \emph{code de la route et la langue} des véhicules qui y circulent. Sans protocole commun, pas de communication possible, même avec le meilleur câble du monde.
\end{aretenir}

Il existe des centaines de protocoles, chacun spécialisé dans un service précis : transporter une page Web, envoyer un courriel, attribuer une adresse IP... Nous étudions maintenant les six protocoles exigibles au programme.

\courssub{IP : le protocole fondamental de l'Internet}

\courssub{À quoi ça sert ?}

Quand tu envoies une lettre par CAMPOST, tu écris l'adresse du destinataire sur l'enveloppe, et le service postal se charge de l'acheminer de bureau en bureau. Sur Internet, les données sont découpées en petits morceaux appelés \cle{paquets}, et chaque paquet doit porter l'adresse de son expéditeur et de son destinataire pour traverser les réseaux. C'est le travail du protocole IP.

\begin{definition}[IP (Internet Protocol)]
Le protocole \cle{IP} (\emph{Internet Protocol}) est le protocole fondamental de l'Internet. Il assure deux fonctions :
\begin{itemize}
\item l'\textbf{adressage} : chaque machine connectée possède une adresse IP unique qui l'identifie (nous étudierons les adresses IPv4 en détail dans la section suivante) ;
\item l'\textbf{acheminement} (ou \emph{routage}) : les paquets sont transportés de réseau en réseau, de routeur en routeur, jusqu'à la machine destinataire.
\end{itemize}
\end{definition}

\begin{attention}[IP ne garantit pas tout !]
Le protocole IP achemine les paquets \emph{au mieux}, mais il ne garantit ni leur arrivée, ni leur ordre d'arrivée. D'autres protocoles (comme TCP, qui accompagne souvent IP) se chargent de vérifier que rien ne s'est perdu. Retiens simplement : \textbf{IP = adressage + acheminement des paquets}.
\end{attention}

\courssub{HTTP : le protocole du Web}

\courssub{À quoi ça sert ?}

Tu ouvres ton navigateur et tu tapes \texttt{www.camertech.cm}. Quelques fractions de seconde plus tard, la page s'affiche. Que s'est-il passé ? Ton navigateur (le \emph{client}) a envoyé une \textbf{requête} au serveur Web qui héberge le site, et ce serveur a renvoyé la page en \textbf{réponse}. Ce dialogue requête/réponse obéit à un protocole précis : HTTP.

\begin{definition}[HTTP (HyperText Transfer Protocol)]
Le protocole \cle{HTTP} (\emph{HyperText Transfer Protocol}) est le protocole de \textbf{transfert des pages Web} entre un serveur Web et un navigateur (client). Il fonctionne selon le modèle \textbf{requête/réponse} :
\begin{enumerate}
\item le navigateur envoie une requête HTTP demandant une ressource (une page, une image...) ;
\item le serveur Web traite la demande et renvoie une réponse HTTP contenant la ressource demandée (ou un message d'erreur, comme le célèbre code 404 « page non trouvée »).
\end{enumerate}
Sa version sécurisée, \cle{HTTPS}, chiffre les échanges (cadenas visible dans la barre d'adresse).
\end{definition}

\begin{exemplebox}[Ce qui se passe quand tu visites www.camertech.cm]
\begin{enumerate}
\item Tu tapes l'adresse dans le navigateur ;
\item le navigateur envoie une \textbf{requête HTTP} au serveur du site : « donne-moi la page d'accueil » ;
\item les paquets de cette requête sont \textbf{acheminés par le protocole IP} à travers les réseaux (ton fournisseur d'accès, la dorsale nationale, etc.) ;
\item le serveur reçoit la requête et renvoie la page dans une \textbf{réponse HTTP}, elle aussi transportée grâce à IP ;
\item le navigateur affiche la page.
\end{enumerate}
Retiens la distinction : \textbf{HTTP transporte le contenu de la page, IP achemine les paquets}. Les deux protocoles travaillent ensemble, chacun à son niveau.
\end{exemplebox}

\courssub{FTP : le transfert de fichiers}

\courssub{À quoi ça sert ?}

Le webmaster du lycée veut déposer les nouvelles pages du site de l'établissement sur le serveur d'hébergement. Ou un élève veut télécharger un logiciel depuis un serveur de fichiers. On n'utilise pas HTTP (pensé pour les pages Web) mais un protocole spécialisé dans le transfert de fichiers de machine à machine.

\begin{definition}[FTP (File Transfer Protocol)]
Le protocole \cle{FTP} (\emph{File Transfer Protocol}) permet le \textbf{transfert de fichiers} entre deux machines d'un réseau : envoyer (\emph{upload}) ou récupérer (\emph{download}/télécharger) des fichiers entre un client FTP et un serveur FTP. Il est très utilisé pour mettre à jour un site Web ou partager de gros fichiers.
\end{definition}

\courssub{SMTP et POP3 : les protocoles du courrier électronique}

\courssub{À quoi ça sert ?}

Tu envoies un e-mail à ton professeur depuis ta boîte Gmail. Deux étapes distinctes se déroulent, avec deux protocoles différents :
\begin{itemize}
\item ton message doit d'abord être \textbf{envoyé} de ton appareil vers le serveur de messagerie, puis acheminé jusqu'au serveur du destinataire ;
\item ensuite, ton professeur doit \textbf{recevoir} ce message, c'est-à-dire le récupérer sur son serveur de messagerie pour le consulter.
\end{itemize}
Envoyer et recevoir sont deux services différents, donc deux protocoles différents.

\begin{definition}[SMTP (Simple Mail Transfer Protocol)]
Le protocole \cle{SMTP} (\emph{Simple Mail Transfer Protocol}) est le protocole d'\textbf{envoi} du courrier électronique : il transporte le message du poste de l'expéditeur vers son serveur de messagerie, puis de serveur en serveur jusqu'au serveur du destinataire.
\end{definition}

\begin{definition}[POP3 (Post Office Protocol version 3)]
Le protocole \cle{POP3} (\emph{Post Office Protocol, version 3}) est le protocole de \textbf{réception} du courrier électronique : il permet à un utilisateur de \textbf{récupérer et consulter} sur son poste les messages stockés sur son serveur de messagerie (comme on retire son courrier dans une boîte postale — d'où son nom, « protocole du bureau de poste »).
\end{definition}

\begin{attention}[L'erreur classique du Bac : ne pas inverser SMTP et POP3 !]
\textbf{SMTP sert à ENVOYER le courrier, POP3 sert à le RECEVOIR.} C'est l'une des confusions les plus fréquentes dans les copies. Moyen mnémotechnique :
\begin{itemize}
\item \textbf{S}MTP = \textbf{S}end (envoyer) ;
\item \textbf{P}OP3 = \textbf{P}oste (retirer son courrier à la poste, donc recevoir).
\end{itemize}
Dans une question « quel protocole permet de recevoir ses e-mails ? », la réponse est POP3, jamais SMTP.
\end{attention}

\courssub{DHCP : l'attribution automatique des adresses IP}

\courssub{À quoi ça sert ?}

Nous verrons dans la section suivante que chaque machine d'un réseau doit posséder une adresse IP, un masque de sous-réseau, une passerelle... Configurer tout cela \emph{à la main} sur chacun des 30 postes de la salle informatique serait long et source d'erreurs (deux machines avec la même adresse = conflit !). Le protocole DHCP automatise entièrement cette tâche.

\begin{definition}[DHCP (Dynamic Host Configuration Protocol)]
Le protocole \cle{DHCP} (\emph{Dynamic Host Configuration Protocol}) permet l'\textbf{attribution automatique} des paramètres réseau (adresse IP, masque de sous-réseau, passerelle par défaut, serveurs DNS) aux machines qui se connectent à un réseau. Un serveur DHCP (souvent intégré au routeur ou à la box Internet) distribue ces paramètres à la demande, ce qui évite toute configuration manuelle.
\end{definition}

\begin{methode}[Comment une machine obtient-elle son adresse via DHCP ?]
\begin{enumerate}
\item La machine se connecte au réseau (câble branché ou Wi-Fi activé) et diffuse une \textbf{demande} : « y a-t-il un serveur DHCP ? » (DISCOVER) ;
\item le serveur DHCP répond en \textbf{proposant} une adresse IP disponible (OFFER) ;
\item la machine \textbf{accepte} l'offre (REQUEST) ;
\item le serveur \textbf{confirme} l'attribution (ACK) : la machine peut communiquer.
\end{enumerate}
\end{methode}

\begin{savaistu}[Le Wi-Fi et DHCP dans ta poche]
Grâce à DHCP, ton téléphone reçoit automatiquement une adresse IP dès qu'il se connecte au réseau Wi-Fi du lycée, du cybercafé ou de la maison : tu n'as rien à configurer ! C'est aussi DHCP qui permet à des dizaines d'appareils de se connecter successivement à la même box sans jamais entrer en conflit d'adresses.
\end{savaistu}

\begin{methode}[Associer un protocole à un service décrit dans une situation (question classique du Bac)]
Face à une question du type « Quel protocole permet... ? », procède en trois étapes :
\begin{enumerate}
\item \textbf{Repère le service} décrit dans l'énoncé : page Web ? fichier ? e-mail ? adresse IP ? Souligne le verbe d'action (consulter, envoyer, recevoir, transférer, attribuer).
\item \textbf{Associe le service au protocole} à l'aide du tableau récapitulatif ci-dessus.
\item \textbf{Vérifie le sens de l'opération} pour les cas piégeux : pour le courrier, « envoyer » $\to$ SMTP, « recevoir/consulter » $\to$ POP3 ; pour le Web, c'est toujours HTTP, et IP intervient dans \emph{tous} les échanges.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Identifier les protocoles mis en jeu]
Énoncé. Dans le cybercafé de Mme Etoundi, une cliente effectue les opérations suivantes : (a) son ordinateur reçoit automatiquement une adresse IP en se connectant au réseau ; (b) elle consulte le site de son université ; (c) elle envoie un e-mail à sa sœur ; (d) sa sœur relève le message reçu ; (e) elle télécharge un dossier de fichiers depuis un serveur. Pour chaque opération, indique le protocole utilisé.
\tcblower
Solution détaillée. On applique la méthode : repérage du service, puis association.
\begin{enumerate}
\item[(a)] Attribution \textbf{automatique} d'une adresse IP $\to$ \textbf{DHCP}.
\item[(b)] Consultation d'un \textbf{site Web} : la page est transférée par \textbf{HTTP} (et les paquets sont acheminés par \textbf{IP}).
\item[(c)] \textbf{Envoi} d'un e-mail $\to$ \textbf{SMTP}.
\item[(d)] \textbf{Réception} (consultation) du message sur le serveur $\to$ \textbf{POP3}.
\item[(e)] \textbf{Transfert de fichiers} $\to$ \textbf{FTP}.
\end{enumerate}
Remarque : le protocole IP est présent dans \emph{toutes} ces opérations, car il achemine les paquets sur le réseau ; mais le protocole caractéristique du service demandé est celui du tableau.
\end{exoresolu}

\begin{exercice}[À toi de jouer]
Le lycée bilingue de Bafoussam met en place sa messagerie scolaire et son site Web.
\begin{enumerate}
\item Quel protocole permettra aux enseignants d'\emph{envoyer} des e-mails aux parents d'élèves ?
\item Quel protocole leur permettra de \emph{consulter} les réponses reçues ?
\item Quel protocole est utilisé lorsqu'un parent consulte le site du lycée ?
\item Le technicien veut que les 25 postes de la salle multimédia reçoivent leur adresse IP sans configuration manuelle : quel protocole doit-il activer ?
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice : messagerie et site Web du lycée]
\begin{enumerate}
\item \textbf{SMTP} : c'est le protocole d'envoi du courrier électronique.
\item \textbf{POP3} : c'est le protocole de réception/consultation du courrier sur le serveur.
\item \textbf{HTTP} : c'est le protocole de transfert des pages Web entre le serveur et le navigateur (IP acheminant les paquets).
\item \textbf{DHCP} : il attribue automatiquement les adresses IP et les paramètres réseau aux 25 postes.
\end{enumerate}
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Un \cle{protocole} est un ensemble de règles régissant l'échange de données entre équipements : pas de protocole commun, pas de communication.
\item \cle{IP} : adressage et acheminement des paquets — le protocole fondamental.
\item \cle{HTTP} : pages Web ; \cle{FTP} : fichiers ; \cle{SMTP} : envoi du courrier ; \cle{POP3} : réception du courrier ; \cle{DHCP} : attribution automatique des adresses IP.
\item Piège n°1 : SMTP envoie, POP3 reçoit. Ne les inverse jamais.
\end{itemize}
Dans la section suivante, nous étudierons en détail les \textbf{adresses IPv4} que le protocole IP manipule : leur structure, leurs classes et le calcul des adresses réseau et de diffusion.
\end{aretenir}


\coursec{Adressage IPv4}

Dans la section précédente, nous avons vu que les protocoles (HTTP, FTP, SMTP, IP\ldots) sont les \emph{règles de langue} qui permettent aux machines de se comprendre sur un réseau. Mais une question demeure : quand le protocole IP transporte un paquet, comment sait-il \emph{à qui} l'adresser ? Sur le réseau du lycée, comment distinguer le poste du secrétariat de celui de la salle informatique ? Il faut donner à chaque machine une \cle{adresse} unique, exactement comme chaque maison d'un quartier de Yaoundé possède une adresse postale. C'est le rôle de l'\cle{adresse IP}. Cette section est capitale pour le Baccalauréat : déterminer une classe, une adresse réseau et une adresse de diffusion est un savoir-faire exigé.

\courssub{Structure d'une adresse IPv4}

\begin{definition}[Adresse IP (version 4)]
Une \cle{adresse IPv4} est un identifiant numérique unique attribué à chaque machine (ordinateur, imprimante, routeur, téléphone) connectée à un réseau utilisant le protocole IP. Elle est codée sur \cle{32 bits} (4 octets) et s'écrit en \cle{notation décimale pointée} sous la forme :
\[ a.b.c.d \quad \text{où } a, b, c, d \text{ sont quatre entiers compris entre } 0 \text{ et } 255. \]
Exemple : \texttt{192.168.1.10}.
\end{definition}

Pourquoi 32 bits ? Parce que les ordinateurs ne manipulent que du binaire (des 0 et des 1). L'adresse \texttt{192.168.1.10} est en réalité, pour la machine, la suite de 32 bits :
\[ 11000000.10101000.00000001.00001010 \]
La notation décimale pointée n'est qu'une \emph{traduction confortable} pour les humains : on regroupe les 32 bits en 4 paquets de 8 bits (4 octets) et on convertit chaque octet en décimal.

\begin{propriete}[Plage de valeurs d'un octet]
Un octet est une suite de 8 bits. Le nombre de valeurs différentes qu'il peut représenter est :
\[ \underbrace{2 \times 2 \times \cdots \times 2}_{8 \text{ facteurs}} = 2^8 = 256 \text{ valeurs.} \]
En comptant à partir de 0, un octet prend donc ses valeurs dans l'intervalle $[0\,;\,255]$. Par conséquent, \textbf{chaque nombre d'une adresse IPv4 est compris entre 0 et 255}.
\end{propriete}

\textbf{Démonstration guidée (dénombrement).} Un bit a 2 valeurs possibles : 0 ou 1.
\begin{itemize}
  \item Avec 1 bit : $2^1 = 2$ valeurs (0, 1).
  \item Avec 2 bits : $2^2 = 4$ valeurs (00, 01, 10, 11), soit de 0 à 3.
  \item Avec 3 bits : $2^3 = 8$ valeurs, soit de 0 à 7.
  \item \ldots{} à chaque bit ajouté, le nombre de combinaisons \emph{double}.
  \item Avec 8 bits : $2^8 = 256$ valeurs, de $00000000$ (qui vaut 0) à $11111111$ (qui vaut $128+64+32+16+8+4+2+1 = 255$).
\end{itemize}

\begin{exemplebox}[Conversion d'un octet : 192 en binaire]
Pour convertir 192 en binaire, on utilise les puissances de 2 (poids des bits) :
\[ 192 = 128 + 64 = 1\times 2^7 + 1\times 2^6 + 0\times 2^5 + 0\times 2^4 + 0\times 2^3 + 0\times 2^2 + 0\times 2^1 + 0\times 2^0 \]
Donc $192 = (11000000)_2$. De même : $168 = 128 + 32 + 8 = (10101000)_2$, $1 = (00000001)_2$ et $10 = 8 + 2 = (00001010)_2$.
\end{exemplebox}

\begin{attention}[Octet supérieur à 255 : adresse invalide]
Une erreur très fréquente au Baccalauréat consiste à accepter (ou à écrire) une adresse comme \texttt{192.168.300.1}. Cette adresse est \textbf{invalide}, car l'octet 300 dépasse 255 : il faudrait 9 bits pour le coder. Avant tout calcul, vérifie toujours que chacun des quatre nombres est compris entre 0 et 255.
\end{attention}

\courssub{Les classes d'adresses IPv4}

Pour organiser l'attribution des adresses à l'échelle mondiale, on a découpé l'ensemble des adresses IPv4 en \cle{classes}. La classe d'une adresse se détermine \textbf{uniquement à partir de la valeur du premier octet}.

\begin{aretenir}[Les classes A, B et C]
\begin{itemize}
  \item \cle{Classe A} : premier octet de \textbf{1 à 126}. Masque par défaut : \texttt{255.0.0.0}. Réservée aux très grands réseaux : $2^{24} - 2 = 16\,777\,214$ machines adressables par réseau.
  \item \cle{Classe B} : premier octet de \textbf{128 à 191}. Masque par défaut : \texttt{255.255.0.0}. Réseaux moyens : $2^{16} - 2 = 65\,534$ machines.
  \item \cle{Classe C} : premier octet de \textbf{192 à 223}. Masque par défaut : \texttt{255.255.255.0}. Petits réseaux : $2^8 - 2 = 254$ machines. C'est la classe typique d'un LAN de lycée ou de cybercafé.
\end{itemize}
On retire 2 adresses par réseau : l'adresse réseau et l'adresse de diffusion, qui ne peuvent pas être attribuées à une machine.
\end{aretenir}

\begin{attention}[La classe se lit sur le premier octet, pas sur le masque]
Piège classique : on te donne l'adresse \texttt{10.0.0.5} avec le masque \texttt{255.255.255.0} et on te demande sa classe. Beaucoup d'élèves répondent « classe C » en regardant le masque. \textbf{Faux !} C'est le \emph{premier octet} qui donne la classe : 10 est entre 1 et 126, donc l'adresse est de \textbf{classe A}. Le masque peut être modifié par l'administrateur (sous-réseaux), il ne définit pas la classe.
\end{attention}

\courssub{Le masque de sous-réseau}

Une adresse IP contient deux informations : \emph{quel réseau ?} et \emph{quelle machine dans ce réseau ?}. C'est comme une adresse postale : le nom du quartier (partie réseau) puis le numéro de la maison (partie machine). Mais comment l'ordinateur sait-il où s'arrête la partie réseau ? Grâce au \cle{masque de sous-réseau}.

\begin{definition}[Masque de sous-réseau]
Le \cle{masque de sous-réseau} est une suite de 32 bits, notée comme une adresse IP (ex. \texttt{255.255.255.0}), qui sert à séparer dans une adresse IP :
\begin{itemize}
  \item la \cle{partie réseau} : les bits de l'adresse correspondant aux bits à \textbf{1} du masque ;
  \item la \cle{partie machine} (hôte) : les bits correspondant aux bits à \textbf{0} du masque.
\end{itemize}
En binaire, le masque est toujours une suite de 1 suivie d'une suite de 0. Exemple : \texttt{255.255.255.0} s'écrit $11111111.11111111.11111111.00000000$ : les 24 premiers bits désignent le réseau, les 8 derniers la machine.
\end{definition}

Deux machines appartiennent au \emph{même réseau} si elles ont la même partie réseau. C'est ce qui permet à ton poste de savoir si le destinataire d'un paquet est dans la salle informatique (même réseau : envoi direct) ou à l'autre bout du pays (réseau différent : on confie le paquet au routeur).

\courssub{Adresse réseau et adresse de diffusion}

\begin{definition}[Adresses spéciales d'un réseau]
\begin{itemize}
  \item L'\cle{adresse réseau} identifie le réseau lui-même. Elle s'obtient par le \textbf{ET logique bit à bit} entre l'adresse IP et le masque de sous-réseau.
  \item L'\cle{adresse de diffusion} (ou \emph{broadcast}) permet d'envoyer un message à \textbf{toutes} les machines du réseau. Elle s'obtient en mettant à 1 tous les bits de la partie machine de l'adresse réseau.
\end{itemize}
Ces deux adresses ne peuvent jamais être attribuées à une machine.
\end{definition}

Rappelons la table du \cle{ET logique} (AND) : $1 \text{ ET } 1 = 1$ ; dans tous les autres cas, le résultat est 0 ($1 \text{ ET } 0 = 0$, $0 \text{ ET } 1 = 0$, $0 \text{ ET } 0 = 0$). Astuce : faire un ET avec un bit à 1 \emph{recopie} le bit ; faire un ET avec un bit à 0 \emph{force à 0}. Le masque agit donc comme un pochoir : il conserve la partie réseau et efface la partie machine.

\begin{methode}[Déterminer classe, adresse réseau et adresse de diffusion]
Pour une adresse IP et un masque donnés :
\begin{enumerate}
  \item \textbf{Classe} : lire le premier octet et le situer dans les plages 1--126 (A), 128--191 (B), 192--223 (C).
  \item \textbf{Adresse réseau} : convertir l'IP et le masque en binaire, appliquer le ET logique bit à bit, puis reconvertir en décimal pointé. (Raccourci : octet ET 255 = octet inchangé ; octet ET 0 = 0.)
  \item \textbf{Adresse de diffusion} : repartir de l'adresse réseau et remplacer par des 1 tous les bits de la partie machine (les octets correspondant à des 0 du masque deviennent 255).
\end{enumerate}
\end{methode}

\begin{exoresolu}[Étude complète de l'adresse 192.168.1.10 / 255.255.255.0]
Énoncé. On donne l'adresse IP \texttt{192.168.1.10} et le masque \texttt{255.255.255.0}. Déterminer la classe, l'adresse réseau et l'adresse de diffusion.
\tcblower
\textbf{Étape 1 : la classe.} Le premier octet est 192, compris entre 192 et 223 : c'est une adresse de \textbf{classe C}. Le masque par défaut de la classe C est bien \texttt{255.255.255.0} : cohérent.

\textbf{Étape 2 : l'adresse réseau (ET logique bit à bit).}
\begin{align*}
\text{IP : }     & 11000000.10101000.00000001.00001010 \quad (192.168.1.10)\\
\text{Masque : } & 11111111.11111111.11111111.00000000 \quad (255.255.255.0)\\
\text{ET : }     & 11000000.10101000.00000001.00000000 \quad (192.168.1.0)
\end{align*}
Détail du dernier octet : $00001010 \text{ ET } 00000000 = 00000000 = 0$. Les trois premiers octets sont recopiés car $x \text{ ET } 255 = x$.
L'adresse réseau est donc \texttt{192.168.1.0}.

\textbf{Étape 3 : l'adresse de diffusion.} Le masque a 8 bits à 0 (le dernier octet) : la partie machine occupe le dernier octet. On met tous ces bits à 1 : $11111111 = 255$. L'adresse de diffusion est \texttt{192.168.1.255}.

\textbf{Conclusion.} Classe C ; réseau \texttt{192.168.1.0} ; diffusion \texttt{192.168.1.255} ; les machines du réseau peuvent prendre les adresses de \texttt{192.168.1.1} à \texttt{192.168.1.254} (soit 254 postes).
\end{exoresolu}

\courssub{Adresses particulières à connaître}

Certaines adresses ont un rôle spécial et ne sont jamais attribuées à une machine ordinaire :

\begin{itemize}
  \item \texttt{127.0.0.1} : la \cle{boucle locale} (\emph{localhost}). Elle désigne la machine elle-même. Exécuter \texttt{ping 127.0.0.1} permet de tester que la carte réseau et la pile TCP/IP de ton propre poste fonctionnent, sans aucun câble. Toute la plage \texttt{127.x.x.x} est réservée à cet usage (c'est pourquoi la classe A s'arrête à 126).
  \item Les \cle{adresses privées} : plages réservées aux réseaux locaux, non routables sur Internet. Les plus utilisées sont \texttt{192.168.0.0} à \texttt{192.168.255.255} (les fameuses \texttt{192.168.x.x}), mais aussi \texttt{10.x.x.x} et \texttt{172.16.x.x} à \texttt{172.31.x.x}. Le réseau de ton lycée ou de ton cybercafé utilise presque toujours \texttt{192.168.1.x} ; c'est le routeur (la box) qui fait la traduction vers une adresse publique pour sortir sur Internet.
  \item L'adresse réseau (partie machine à 0) et l'adresse de diffusion (partie machine à 1), vues plus haut.
\end{itemize}

\begin{savaistu}[Et quand il n'y aura plus d'adresses ?]
Avec 32 bits, IPv4 offre environ $2^{32} \approx 4,3$ milliards d'adresses : c'est devenu insuffisant face à l'explosion des téléphones et objets connectés, y compris en Afrique où l'Internet mobile croît très vite. C'est pourquoi une nouvelle version, \cle{IPv6} (adresses sur 128 bits), se déploie progressivement. Au programme de Terminale, seule IPv4 est exigée : retiens bien ses 4 octets et ses classes.
\end{savaistu}

On donne l'adresse \texttt{172.16.5.20} et le masque \texttt{255.255.0.0}. Détermine la classe, l'adresse réseau et l'adresse de diffusion, puis le nombre de machines adressables dans ce réseau.
\end{exercice}

\begin{corrige}[Exercice]
\textbf{Classe} : premier octet 172, compris entre 128 et 191 $\Rightarrow$ \textbf{classe B} (masque par défaut cohérent : \texttt{255.255.0.0}).

\textbf{Adresse réseau} : le ET logique avec \texttt{255.255.0.0} conserve les deux premiers octets et annule les deux derniers :
\[ 172.16.5.20 \text{ ET } 255.255.0.0 = \texttt{172.16.0.0} \]

\textbf{Adresse de diffusion} : la partie machine occupe les deux derniers octets (16 bits) ; on les met à 1 : \texttt{172.16.255.255}.

\textbf{Nombre de machines} : $2^{16} - 2 = 65\,534$ machines (de \texttt{172.16.0.1} à \texttt{172.16.255.254}).
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
  \item Une adresse IPv4 : 32 bits, notée $a.b.c.d$ avec chaque octet entre 0 et 255 ($2^8 = 256$ valeurs).
  \item La classe se lit sur le \textbf{premier octet} : A (1--126), B (128--191), C (192--223).
  \item Le masque sépare partie réseau (bits à 1) et partie machine (bits à 0).
  \item Adresse réseau $=$ IP \textbf{ET} masque ; adresse de diffusion $=$ adresse réseau avec tous les bits machine à 1.
  \item \texttt{127.0.0.1} $=$ boucle locale ; \texttt{192.168.x.x} $=$ adresses privées des réseaux locaux.
\end{itemize}
\end{aretenir}

\coursec{Création et configuration d'un réseau local de 3 postes}

Dans la section précédente, tu as appris à décoder une adresse IPv4 : sa classe, son masque, son adresse réseau et son adresse de diffusion. Ces connaissances ne sont pas de simples exercices de calcul : elles sont exactement ce qu'il faut pour \cle{construire un vrai réseau}. C'est ce que nous allons faire maintenant, pas à pas, comme le ferait l'informaticien d'un lycée de Yaoundé qui doit interconnecter les trois ordinateurs de la salle multimédia pour que le proviseur, le censeur et le secrétariat partagent une même imprimante et échangent des fichiers.

Objectif de la section : monter physiquement un réseau local de trois postes, leur attribuer des adresses IP cohérentes, puis \emph{prouver} qu'ils communiquent grâce à deux commandes incontournables : \texttt{IPCONFIG} et \texttt{PING}.

\courssub{Le matériel nécessaire}

Avant toute chose, faisons l'inventaire. Pour créer un petit réseau local filaire en \cle{topologie en étoile}, il faut :

\begin{itemize}
\item \textbf{3 ordinateurs}, chacun équipé d'une \cle{carte réseau} (NIC) avec un port RJ45 — c'est le cas de pratiquement tous les ordinateurs modernes ;
\item \textbf{1 switch} (commutateur) disposant d'au moins 3 ports libres : c'est lui qui joue le rôle de \emph{centre de l'étoile} et qui aiguille les trames vers le bon destinataire ;
\item \textbf{3 câbles réseau à paires torsadées}, droits, terminés par des connecteurs RJ45 (un câble par poste).
\end{itemize}

\begin{attention}[Câble droit ou câble croisé ?]
Pour relier un ordinateur à un switch, on utilise un câble \cle{droit} (les fils sont dans le même ordre aux deux extrémités). Le câble \cle{croisé} servait historiquement à relier deux ordinateurs directement entre eux, sans switch. Les cartes réseau récentes (norme Auto-MDI/MDIX) s'adaptent automatiquement, mais au Baccalauréat, retiens : \textbf{poste $\rightarrow$ switch = câble droit}.
\end{attention}

\courssub{Les quatre étapes de la méthode}

\begin{methode}[Créer un réseau local en 4 étapes]
\begin{enumerate}
\item \textbf{Câbler} : relier physiquement chaque poste à un port du switch avec un câble RJ45 droit (topologie en étoile), puis mettre le switch et les postes sous tension.
\item \textbf{Planifier les adresses} : choisir un plan d'adressage cohérent (même adresse réseau, adresses IP distinctes) et le consigner dans un tableau.
\item \textbf{Configurer} : saisir sur chaque poste son adresse IP et le masque de sous-réseau dans les propriétés TCP/IPv4.
\item \textbf{Tester} : vérifier la configuration avec \texttt{IPCONFIG} puis la connectivité entre les postes avec \texttt{PING}.
\end{enumerate}
\end{methode}

\courssub{Étape 1 : le câblage physique}

Un petit « clic » confirme le verrouillage du connecteur, et une diode lumineuse s'allume sur le port du switch dès que la liaison est active.

\begin{aretenir}[Pourquoi un switch et pas un hub ?]
Le \cle{hub} (concentrateur) répète chaque message vers \emph{tous} les postes : c'est du gaspillage et une source de collisions. Le \cle{switch} (commutateur) est intelligent : il apprend quelle machine est branchée sur quel port et n'envoie la trame qu'au destinataire. C'est l'équipement standard des réseaux locaux modernes.
\end{aretenir}

\courssub{Étape 2 : le plan d'adressage}

C'est ici que la section « Adressage IPv4 » prend tout son sens. Les postes doivent pouvoir se joindre \emph{directement}, sans routeur : il faut donc qu'ils appartiennent au \textbf{même réseau logique}.

\begin{propriete}[Condition de communication directe (admise, vérifiée en TP)]
Deux postes peuvent communiquer directement dans un réseau local si et seulement si ils ont la \cle{même adresse réseau}, c'est-à-dire si le ET logique bit à bit entre leur adresse IP et leur masque donne le même résultat. Si les adresses réseau diffèrent, la communication exige un \cle{routeur} (passerelle).
\end{propriete}

Nous choisissons le réseau privé de classe C \textbf{192.168.1.0} avec le masque \textbf{255.255.255.0} (c'est-à-dire /24 : les 24 premiers bits identifient le réseau, les 8 derniers identifient les machines). Le plan d'adressage se consigne dans un tableau :

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}
\hline
\rowcolor{popblueL} \textbf{Poste} & \textbf{Adresse IP} & \textbf{Masque de sous-réseau} \\
\hline
PC1 & 192.168.1.1 & 255.255.255.0 \\
\hline
PC2 & 192.168.1.2 & 255.255.255.0 \\
\hline
PC3 & 192.168.1.3 & 255.255.255.0 \\
\hline
\end{tabularx}
\end{center}

\begin{exemplebox}[Vérification : PC2 et PC3 sont-ils sur le même réseau ?]
Appliquons le ET logique bit à bit entre chaque adresse et le masque 255.255.255.0. Le masque vaut 255 sur les trois premiers octets (qui sont donc recopiés) et 0 sur le dernier (qui est mis à zéro) :
\begin{align*}
\text{PC2 : } & 192.168.1.2 \;\&\; 255.255.255.0 = 192.168.1.0 \\
\text{PC3 : } & 192.168.1.3 \;\&\; 255.255.255.0 = 192.168.1.0
\end{align*}
Les deux adresses réseau sont identiques ($192.168.1.0$) : PC2 et PC3 appartiennent au même réseau et peuvent communiquer directement via le switch. L'adresse de diffusion de ce réseau est 192.168.1.255 (tous les bits de la partie machine à 1).
\end{exemplebox}

\begin{attention}[Erreur fréquente n°1 : le conflit d'adresses]
Attribuer la \textbf{même adresse IP} à deux postes (par exemple 192.168.1.2 à PC2 \emph{et} à PC3) provoque un \cle{conflit d'adresses} : Windows affiche un avertissement et les communications des deux machines deviennent erratiques. Règle d'or : dans un même réseau, \textbf{même adresse réseau, mais adresses IP toutes distinctes}. De même, des \textbf{masques différents} sur les postes (l'un en 255.255.255.0, l'autre en 255.255.0.0) faussent le calcul de l'adresse réseau et bloquent la communication.
\end{attention}

\begin{attention}[Erreur fréquente n°2 : les adresses réservées]
Deux adresses du réseau ne doivent \textbf{jamais} être attribuées à un poste :
\begin{itemize}
\item l'\cle{adresse réseau} 192.168.1.0 (partie machine à 0), qui désigne le réseau lui-même ;
\item l'\cle{adresse de diffusion} 192.168.1.255 (partie machine à 255), qui sert à envoyer un message à \emph{tous} les postes du réseau.
\end{itemize}
Avec le masque 255.255.255.0, les adresses utilisables vont donc de 192.168.1.1 à 192.168.1.254, soit 254 postes possibles.
\end{attention}

\courssub{Étape 3 : la configuration sous Windows}

Sur chaque poste, on saisit manuellement l'adresse IP prévue au plan (on parle d'adressage \cle{statique}, par opposition à l'attribution automatique par un serveur DHCP).

\begin{methode}[Configurer l'adresse IP d'un poste sous Windows]
\begin{enumerate}
\item Ouvrir le \textbf{Panneau de configuration}, puis cliquer sur \textbf{Réseau et Internet}, puis \textbf{Centre Réseau et partage}.
\item Dans le menu de gauche, cliquer sur \textbf{Modifier les paramètres de la carte}.
\item Clic droit sur la connexion \textbf{Ethernet} (ou « Connexion au réseau local »), puis \textbf{Propriétés}.
\item Dans la liste, sélectionner \textbf{Protocole Internet version 4 (TCP/IPv4)}, puis cliquer sur \textbf{Propriétés}.
\item Cocher \textbf{Utiliser l'adresse IP suivante}, puis saisir :
\begin{itemize}
\item \textbf{Adresse IP} : celle du plan (ex. 192.168.1.1 pour PC1) ;
\item \textbf{Masque de sous-réseau} : 255.255.255.0 (souvent rempli automatiquement) ;
\item \textbf{Passerelle par défaut} : laisser vide pour l'instant (voir le complément plus bas).
\end{itemize}
\item Valider par \textbf{OK}, fermer les fenêtres, et répéter l'opération sur PC2 et PC3 avec leurs propres adresses.
\end{enumerate}
\end{methode}

\courssub{Étape 4 : la vérification avec IPCONFIG et PING}

Un réseau n'est déclaré « terminé » que lorsqu'on l'a \emph{testé}. Deux commandes, tapées dans l'invite de commandes (touche Windows, taper \texttt{cmd}, puis Entrée), suffisent.

\textbf{La commande IPCONFIG.} Elle affiche la configuration IP de la machine : adresse IP, masque de sous-réseau et passerelle par défaut de chaque carte réseau. C'est la commande du \emph{diagnostic} : « quelle est ma configuration actuelle ? ».

\textbf{La commande PING.} Suivie d'une adresse IP (\texttt{ping 192.168.1.2}), elle envoie de petits paquets de test à la machine cible et attend sa réponse. C'est la commande du \emph{test} : « est-ce que je parviens à joindre l'autre poste ? ».

\begin{propriete}[Interprétation des réponses de PING]
\begin{itemize}
\item \textbf{« Réponse de 192.168.1.2 : octets=32 temps<1ms TTL=128 »} : \emph{succès}. Le poste cible est joignable, le câble, le switch et les adresses sont corrects. La ligne de statistiques indique 0~\% de perte.
\item \textbf{« Délai d'attente de la demande dépassé »} : \emph{échec}. Les paquets partent mais aucune réponse ne revient.
\item \textbf{« Hôte de destination inaccessible »} : \emph{échec}. Le poste émetteur sait déjà qu'il ne peut pas router le paquet (souvent un problème d'adresse réseau).
\end{itemize}
\end{propriete}

\begin{methode}[Dépannage quand le PING échoue]
Vérifier dans l'ordre :
\begin{enumerate}
\item \textbf{Le câble} : est-il bien enfoncé des deux côtés ? La diode du port du switch est-elle allumée ?
\item \textbf{L'adressage} : relancer \texttt{IPCONFIG} sur les deux postes. Ont-ils la même adresse réseau (mêmes trois premiers octets avec un masque /24) ? Des adresses IP distinctes ? Le même masque ?
\item \textbf{Le pare-feu} : le pare-feu Windows peut bloquer les requêtes PING ; le désactiver temporairement (ou autoriser le partage de fichiers et d'imprimantes) permet de vérifier.
\end{enumerate}
\end{methode}

\begin{savaistu}[D'où vient le PING ?]
La commande \texttt{PING} envoie de petits paquets de test (protocole ICMP) et mesure le \cle{temps de réponse} en millisecondes : c'est le « temps<1ms » affiché dans chaque réponse. Son nom vient du sonar des sous-marins, qui émettent un « ping » sonore et écoutent l'écho pour détecter les obstacles. Sur un réseau local, le temps de réponse est inférieur à 1 ms ; vers un serveur en Europe via la fibre CAMTEL, il est plutôt de l'ordre de 100 à 200 ms. Les techniciens réseau du monde entier commencent presque toujours un diagnostic par un PING !
\end{savaistu}

\courssub{TP guidé : monter et tester le réseau de la salle multimédia}

\begin{experience}[Création d'un réseau local de 3 postes]
\textbf{Objectif} : interconnecter trois ordinateurs et démontrer qu'ils communiquent.

\textbf{Matériel et logiciels} : 3 PC sous Windows avec carte réseau, 1 switch, 3 câbles RJ45 droits.

\textbf{Manipulation} :
\begin{enumerate}
\item Postes éteints, relier chaque PC au switch par un câble RJ45 droit. Mettre le switch sous tension, puis allumer les trois PC.
\item Sur PC1, ouvrir les propriétés TCP/IPv4 et saisir l'adresse 192.168.1.1 avec le masque 255.255.255.0. Faire de même sur PC2 (192.168.1.2) et PC3 (192.168.1.3).
\item Sur PC1, ouvrir l'invite de commandes et taper \texttt{ipconfig}. Noter l'adresse affichée.
\item Toujours sur PC1, taper \texttt{ping 192.168.1.2} puis \texttt{ping 192.168.1.3}. Observer les réponses.
\item Modifier volontairement l'adresse de PC3 en 192.168.2.3, puis refaire \texttt{ping 192.168.1.3} depuis PC1. Observer.
\end{enumerate}

\textbf{Observations} : aux étapes 3 et 4, \texttt{IPCONFIG} confirme la configuration et les PING aboutissent (« Réponse de ... », 0~\% de perte). À l'étape 5, le PING échoue : PC3 a changé d'adresse réseau (192.168.2.0 au lieu de 192.168.1.0) et n'est plus joignable directement.

\textbf{Interprétation} : le TP vérifie expérimentalement la propriété fondamentale — deux postes ne communiquent directement que s'ils partagent la même adresse réseau. Le câblage physique ne suffit pas : il faut une cohérence \emph{logique} des adresses.
\end{experience}

\begin{exoresolu}[Un réseau qui refuse de parler]
\textbf{Énoncé.} Dans le réseau d'un cybercafé, le poste A a l'adresse 192.168.1.10 et le poste B l'adresse 192.168.1.20, tous deux avec le masque 255.255.255.0. Le gérant, voulant « réparer » une panne, a changé l'adresse de B en 192.168.1.10. Depuis, les deux postes affichent des erreurs et le PING échoue. (1) Identifier l'erreur commise. (2) Proposer une correction et donner la commande permettant de vérifier la réparation.
\tcblower
\textbf{Solution.} (1) Le gérant a attribué à B la \textbf{même adresse IP} que A (192.168.1.10) : c'est un \cle{conflit d'adresses}. Deux machines d'un même réseau doivent avoir la même adresse réseau mais des adresses IP \emph{distinctes}.

(2) On remet à B une adresse libre du même réseau, par exemple 192.168.1.20, avec le masque 255.255.255.0. Vérification du plan :
\begin{align*}
\text{A : } & 192.168.1.10 \;\&\; 255.255.255.0 = 192.168.1.0 \\
\text{B : } & 192.168.1.20 \;\&\; 255.255.255.0 = 192.168.1.0
\end{align*}
Même adresse réseau, adresses distinctes : la configuration est correcte. Pour vérifier la réparation, on tape depuis A la commande \texttt{ping 192.168.1.20} : l'affichage « Réponse de 192.168.1.20 » avec 0~\% de perte confirme que le réseau fonctionne.
\end{exoresolu}

\courssub{Complément utile au Bac : la passerelle par défaut}

Notre réseau de trois postes est autonome : les machines se parlent entre elles, mais elles ne peuvent pas \emph{sortir} vers d'autres réseaux, notamment Internet. Pour cela, il faut un \cle{routeur} (par exemple la box de l'abonnement Internet) relié au switch.

\begin{definition}[Passerelle par défaut]
La \cle{passerelle par défaut} est l'adresse IP du routeur par lequel un poste envoie tous les paquets destinés à un réseau \emph{autre} que le sien. Elle se configure dans les propriétés TCP/IPv4, dans le champ « Passerelle par défaut ».
\end{definition}

Concrètement : quand PC1 (192.168.1.1) veut joindre 192.168.1.2, le calcul du ET logique lui montre que la cible est sur \emph{son} réseau : il envoie la trame directement via le switch. Mais s'il veut joindre un serveur Web à l'adresse 196.201.214.5, la cible est \emph{hors} de son réseau : il confie le paquet à la passerelle, par exemple 192.168.1.254 (l'adresse du routeur dans le réseau local), qui se charge de l'acheminer vers Internet. La passerelle doit donc toujours appartenir au \textbf{même réseau} que le poste — une passerelle en 192.168.5.1 pour un poste en 192.168.1.1 serait injoignable et donc inutile.

\begin{exercice}[À toi de jouer]
On veut créer un réseau de 3 postes dans le réseau 192.168.10.0 avec le masque 255.255.255.0, plus un routeur d'accès à Internet.
\begin{enumerate}
\item Proposer un plan d'adressage complet (3 postes + passerelle) sous forme de tableau.
\item Quelles sont les deux adresses de ce réseau qu'aucun poste ne peut utiliser ?
\item Depuis le premier poste, quelles commandes permettent de vérifier la configuration puis la communication avec le deuxième poste ?
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice 1]
\begin{enumerate}
\item Plan d'adressage possible : PC1 : 192.168.10.1 ; PC2 : 192.168.10.2 ; PC3 : 192.168.10.3 ; passerelle (routeur) : 192.168.10.254 ; masque partout : 255.255.255.0.
\item L'adresse réseau 192.168.10.0 et l'adresse de diffusion 192.168.10.255 sont réservées et ne peuvent être attribuées à aucun poste.
\item \texttt{ipconfig} pour afficher l'adresse IP, le masque et la passerelle du poste, puis \texttt{ping 192.168.10.2} pour tester la connectivité avec le deuxième poste (« Réponse de ... » = succès).
\end{enumerate}
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Un petit réseau local se construit en \textbf{4 étapes} : câbler (étoile autour d'un switch, câbles RJ45 droits), planifier les adresses, configurer (propriétés TCP/IPv4), tester.
\item Règle d'or de l'adressage : \textbf{même adresse réseau, adresses IP distinctes, même masque}. Jamais l'adresse réseau ni l'adresse de diffusion sur un poste.
\item \texttt{IPCONFIG} affiche la configuration (IP, masque, passerelle) ; \texttt{PING} teste la connectivité (« Réponse de ... » = succès ; « Délai d'attente dépassé » = échec).
\item La \textbf{passerelle par défaut} (adresse du routeur) est indispensable dès qu'on veut sortir du réseau local vers Internet.
\end{itemize}
\end{aretenir}

\coursec{Leçon 4 : Configuration d'un réseau informatique}

\courssub{Objectifs de l'activité}

À l'issue de cette activité d'intégration, tu seras capable de mobiliser l'ensemble des savoirs et savoir-faire de la leçon pour résoudre une situation-problème complète et authentique. Concrètement, tu devras :

\begin{itemize}
\item choisir et justifier une \cle{topologie physique} adaptée à un petit réseau local ;
\item identifier les \cle{équipements réseau} nécessaires (cartes réseau, switch, câbles) et les \cle{supports de transmission} appropriés ;
\item élaborer un \cle{plan d'adressage IPv4} cohérent en classe C ;
\item calculer l'\cle{adresse réseau} et l'\cle{adresse de diffusion} par le \cle{ET logique} entre une adresse IP et son masque ;
\item vérifier que plusieurs postes appartiennent au même réseau ;
\item configurer réellement des postes et valider la connectivité avec les commandes \texttt{IPCONFIG} et \texttt{PING} ;
\item expliquer le rôle du protocole \cle{DHCP} dans l'attribution automatique des adresses.
\end{itemize}

\courssub{Situation}

Le Lycée de Nkongsamba (région du Littoral) vient de recevoir, dans le cadre d'un projet de dotation en matériel informatique, trois ordinateurs de bureau destinés à sa salle multimédia. Le proviseur souhaite que les enseignants puissent \textbf{partager des fichiers} (épreuves, progressions pédagogiques, bulletins) et une \textbf{imprimante} entre ces trois postes, sans passer par des clés USB, sources fréquentes de virus.

Le proviseur te confie, à toi élève de Terminale, la mission de concevoir et de mettre en place ce petit réseau. Il te remet le cahier des charges suivant :

\begin{itemize}
\item les trois postes, nommés \textbf{PC1}, \textbf{PC2} et \textbf{PC3}, sont disposés dans la même salle, à moins de \SI{15}{\meter} les uns des autres ;
\item chaque poste possède une \textbf{carte réseau Ethernet} (NIC) avec un port RJ45 ;
\item le lycée dispose d'un \textbf{switch} à 8 ports et de câbles à \textbf{paires torsadées} (catégorie 5e) ;
\item l'adressage doit être réalisé dans le réseau privé de classe C \textbf{192.168.10.0} avec le masque \textbf{255.255.255.0} ;
\item PC1 recevra la première adresse disponible, PC2 la deuxième, PC3 la troisième ;
\item la connectivité devra être validée par les commandes \texttt{IPCONFIG} et \texttt{PING} ;
\item un rapport écrit devra expliquer comment le protocole \textbf{DHCP} aurait simplifié la tâche.
\end{itemize}

\courssub{Consignes}

Par groupes de quatre élèves, répondez aux questions suivantes, d'abord sur le papier, puis en salle informatique.

\begin{enumerate}
\item À quel type de réseau (PAN, LAN, MAN ou WAN) appartient le réseau à créer ? Justifier.
\item Quelle topologie physique préconisez-vous ? Dessiner le schéma du réseau et donner deux avantages de cette topologie par rapport à la topologie en bus.
\item Compléter la liste du matériel nécessaire : quels équipements et quels supports de transmission faut-il prévoir ? Préciser le rôle du switch.
\item Proposer le plan d'adressage complet sous forme d'un tableau : nom du poste, adresse IPv4, masque de sous-réseau.
\item En posant le ET logique bit à bit entre l'adresse de PC1 et le masque, déterminer l'adresse réseau. En déduire l'adresse de diffusion.
\item Vérifier, par le même calcul, que PC2 et PC3 appartiennent bien au même réseau que PC1.
\item Combien de machines peut-on adresser au maximum dans ce réseau ? Le switch à 8 ports est-il suffisant pour une extension future de la salle ?
\item En salle informatique : configurer les trois postes avec les adresses du plan, puis vérifier la configuration avec \texttt{IPCONFIG} et tester la connectivité avec \texttt{PING}. Noter les résultats observés.
\item Rédiger un court paragraphe expliquant le rôle du protocole DHCP et ce qu'il aurait changé dans cette activité.
\end{enumerate}

\courssub{Ressources à mobiliser}

\begin{aretenir}[Formulaire de l'activité]
\begin{itemize}
\item Un réseau limité à une salle ou un bâtiment est un \cle{LAN} (\emph{Local Area Network}) ; la topologie de référence avec un switch est la topologie en \cle{étoile}.
\item Une adresse IPv4 est codée sur 32 bits (4 octets). En \cle{classe C}, le premier octet est compris entre 192 et 223 et le masque par défaut est 255.255.255.0 (notation CIDR /24).
\item \textbf{Adresse réseau} = adresse IP \textbf{ET} masque (ET logique bit à bit : $1 \text{ ET } 1 = 1$, sinon $0$).
\item \textbf{Adresse de diffusion} (broadcast) : adresse réseau dont on met à 1 tous les bits de la partie machine.
\item Deux postes communiquent directement (sans routeur) s'ils ont la \textbf{même adresse réseau}.
\item Avec un masque /24, le nombre d'adresses machine utilisables est $2^{8} - 2 = 254$.
\item \texttt{IPCONFIG} (Windows) ou \texttt{ifconfig} / \texttt{ip a} (Linux) affiche la configuration IP d'un poste ; \texttt{PING} teste la connectivité avec un autre poste.
\item \cle{DHCP} (\emph{Dynamic Host Configuration Protocol}) attribue automatiquement adresse IP, masque, passerelle par défaut et serveur(s) DNS.
\end{itemize}
\end{aretenir}

\courssub{Démarche et corrigé commenté}

\begin{exoresolu}[Le réseau du Lycée de Nkongsamba]
Énoncé : concevoir, adresser et valider le réseau local de 3 postes de la salle multimédia, selon le cahier des charges du proviseur.
\tcblower
\textbf{Question 1 — Type de réseau.} Les trois postes sont situés dans une même salle du lycée : l'étendue géographique est de quelques mètres, inférieure à un bâtiment. Il s'agit donc d'un \cle{LAN} (\emph{Local Area Network}), réseau local filaire. Ce n'est pas un PAN (périmètre personnel, \SI{10}{\meter} max, souvent sans fil), ni un MAN (ville), ni un WAN (inter-villes, opérateur télécom).

\textbf{Question 2 — Topologie.} On choisit la topologie en \cle{étoile} : chaque poste est relié par son propre câble au switch, qui occupe le centre.

Avantages par rapport au bus : (a) la panne d'un câble ou d'un poste n'affecte pas les autres communications ; (b) l'ajout d'un poste est immédiat sur un port libre du switch ; (c) le switch commute les trames (commutation) vers le seul destinataire (adresse MAC), évitant les collisions inhérentes au bus partagé (CSMA/CD).

\textbf{Question 3 — Matériel.} Il faut : 3 cartes réseau Ethernet (intégrées aux cartes mères, ports RJ45), 1 switch 8 ports (équipement d'interconnexion de niveau 2 : il apprend les adresses MAC sources et distribue les trames au bon port destinataire), 3 câbles à paires torsadées \textbf{droits} (straight-through) RJ45 catégorie 5e (support adapté : débit jusqu'à \SI{1}{Gbit/s}, portée \SI{100}{\meter}, largement suffisante pour \SI{15}{\meter}).

\textbf{Question 4 — Plan d'adressage.} La première adresse utilisable du réseau 192.168.10.0/24 est 192.168.10.1 (l'adresse .0 étant l'adresse réseau) :

\hline

\hline
\end{tabular}
\end{center}
\textit{Note : la passerelle par défaut reste vide (aucun routeur vers l'extérieur), les serveurs DNS ne sont pas requis pour une communication locale pure.}

\textbf{Question 5 — Adresse réseau et adresse de diffusion.} On convertit le dernier octet en binaire (les trois premiers octets du masque valent 255, soit 8 bits à 1 : ils recopient l'adresse inchangée) :
\begin{align*}
\text{PC1 : }      & 192.168.10.1 \rightarrow 11000000.10101000.00001010.\mathbf{00000001} \\
\text{Masque : }   & 255.255.255.0 \rightarrow 11111111.11111111.11111111.\mathbf{00000000} \\
\text{ET logique : } & 11000000.10101000.00001010.\mathbf{00000000} = \textbf{192.168.10.0}
\end{align*}
L'\textbf{adresse réseau} (identifiant du réseau) est donc \textbf{192.168.10.0}.
L'\textbf{adresse de diffusion} (broadcast) s'obtient en mettant à 1 les 8 bits de la partie machine (hôte) : \textbf{192.168.10.255}.

\textbf{Question 6 — Vérification d'appartenance.} Pour PC2 : $192.168.10.2 \text{ ET } 255.255.255.0 = 192.168.10.0$. Pour PC3 : $192.168.10.3 \text{ ET } 255.255.255.0 = 192.168.10.0$. Les trois postes ont la même adresse réseau (\textbf{192.168.10.0}) : ils appartiennent au même réseau logique et peuvent communiquer directement à travers le switch, sans passer par un routeur.

\textbf{Question 7 — Capacité et extensibilité.} La partie machine compte 8 bits (masque /24), soit $2^{8} = 256$ adresses au total. En retirant l'adresse réseau (192.168.10.0) et l'adresse de diffusion (192.168.10.255), on obtient \textbf{254 adresses attribuables} aux machines. Le switch à 8 ports a 3 ports utilisés, il reste \textbf{5 ports libres} : il permet d'ajouter 5 postes supplémentaires sans nouvel équipement, ce qui est suffisant pour une extension raisonnable de la salle.

\textbf{Question 8 — Configuration et tests pratiques.} Sur chaque poste (Panneau de configuration $\rightarrow$ Réseau et Internet $\rightarrow$ Centre Réseau et partage $\rightarrow$ Modifier les paramètres de la carte $\rightarrow$ Propriétés $\rightarrow$ Protocole Internet version 4 (TCP/IPv4) $\rightarrow$ Propriétés), on sélectionne « Utiliser l'adresse IP suivante » et on saisit l'adresse et le masque du plan. \textbf{Question 9 — Rôle de DHCP.} Le protocole \cle{DHCP} (\emph{Dynamic Host Configuration Protocol}) fonctionne selon le processus DORA (Discover, Offer, Request, Acknowledge) : un serveur DHCP (souvent intégré au routeur/box) attribue automatiquement à chaque poste son adresse IP, son masque, sa passerelle par défaut et ses serveurs DNS dès la mise sous tension (bail). Avec DHCP, la saisie manuelle de la question 8 devient inutile : on évite les erreurs de frappe (faute de frappe dans l'IP ou le masque), les conflits d'adresses (deux postes configurés avec la même IP), et l'ajout d'un nouveau poste ne demande aucune configuration manuelle (branchement \emph{plug-and-play}). C'est la solution standard dans les cybercafés, les entreprises et les administrations camerounaises connectées au réseau national (CAMTEL, MTN, Orange).
\end{exoresolu}

\begin{attention}[Erreurs fréquentes rencontrées pendant l'activité]
\begin{itemize}
\item Attribuer l'adresse \textbf{192.168.10.0} (adresse réseau) ou \textbf{192.168.10.255} (adresse de diffusion) à un poste : ces deux adresses sont \textbf{réservées} et ne peuvent pas être assignées à une interface hôte.
\item Oublier que le ET logique se fait \textbf{bit à bit}, octet par octet : $1 \text{ ET } 0 = 0$, $0 \text{ ET } 1 = 0$, $0 \text{ ET } 0 = 0$, seul $1 \text{ ET } 1 = 1$.
\item Saisir des masques différents sur les postes (ex. 255.255.255.0 sur PC1 et 255.255.0.0 sur PC2) : le masque doit être \textbf{strictement identique} sur tout le réseau pour que le calcul d'adresse réseau soit cohérent.
\item Conclure à une panne matérielle (câble, switch) alors que le \textbf{pare-feu Windows} (ou antivirus) bloque simplement les requêtes ICMP (\texttt{PING}) : vérifier d'abord la configuration avec \texttt{IPCONFIG}, puis autoriser temporairement le trafic ICMP entrant dans les règles de pare-feu avancé.
\item Utiliser des câbles \textbf{croisés} (crossover) au lieu de câbles \textbf{droits} (straight-through) pour relier un PC à un switch : les cartes modernes gèrent l'auto-MDIX, mais le standard impose le câble droit pour liaison hôte $\leftrightarrow$ switch.
\end{itemize}
\end{attention}

\courssub{Bilan de l'activité}

Cette activité t'a permis de mettre en évidence les points essentiels de la leçon :

\begin{itemize}
\item la \textbf{cohérence d'un réseau local} repose sur trois choix solidaires : une topologie (étoile autour d'un switch), un support (paires torsadées Cat 5e ou supérieure) et un plan d'adressage unique (même réseau, même masque) ;
\item le \textbf{ET logique} entre l'adresse IP et le masque est l'outil décisif pour déterminer l'adresse réseau et vérifier que des postes peuvent communiquer sans routeur (même domaine de diffusion) ;
\item les adresses réseau (partie machine à 0) et de diffusion (partie machine à 1) sont \textbf{réservées} : sur un réseau /24 (classe C par défaut), seules \textbf{254 adresses} sont attribuables aux machines ;
\item la validation pratique passe par deux commandes complémentaires : \texttt{IPCONFIG} (vérifier la configuration locale : IP, masque, passerelle) puis \texttt{PING} (tester la communication bout-à-bout, couche 3) ;
\item enfin, \textbf{DHCP} automatise tout l'adressage (IP, masque, passerelle, DNS) : c'est la solution retenue dès qu'un réseau grandit (cybercafés, établissements scolaires, administrations), car elle garantit l'unicité des adresses et la mobilité des postes.
\end{itemize}

Tu es désormais capable de concevoir, adresser et valider un petit réseau local : une compétence directement mobilisable au Baccalauréat comme dans la vie professionnelle (technicien réseau, administrateur système, gestion de cybercafé).

\coursec{Configuration d'un réseau informatique}

\courssub{Notion de réseau et types de réseaux selon l'étendue géographique}

\begin{definition}[Réseau informatique]
Un \cle{réseau informatique} est un ensemble d'équipements (ordinateurs, serveurs, imprimantes, smartphones, etc.) interconnectés par des supports de transmission (câbles, ondes radio) et des équipements de liaison (switch, routeur), afin de partager des ressources (fichiers, imprimantes, connexion Internet, applications) et d'échanger des informations selon des règles communes appelées \cle{protocoles}.
\end{definition}

\begin{methode}[Identifier le type d'un réseau à partir de sa description]
Pour classer un réseau décrit dans un énoncé, procède toujours dans l'ordre suivant :
\begin{enumerate}
\item \textbf{Repère l'étendue géographique} : une pièce ou quelques mètres (PAN/WPAN), un bâtiment ou un campus (LAN/WLAN), une ville (MAN/WMAN), un pays ou plusieurs continents (WAN/WWAN).
\item \textbf{Repère le support de transmission} : câbles (paires torsadées, coaxial, fibre optique) $\Rightarrow$ réseau \cle{filaire} (PAN, LAN, MAN, WAN) ; ondes radio (Bluetooth, Wi-Fi, WiMAX, 4G/5G, satellite) $\Rightarrow$ réseau \cle{sans fil} (WPAN, WLAN, WMAN, WWAN).
\item \textbf{Conclus en donnant le sigle complet} et sa signification en français (ex. : LAN = \emph{Local Area Network}, réseau local).
\end{enumerate}
\textbf{Réflexes à retenir :}
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}
\hline
\rowcolor{popblueL} \textbf{Sigle} & \textbf{Étendue typique} & \textbf{Exemple camerounais} \\
\hline
PAN / WPAN & quelques mètres (1 à 10 m) & Bluetooth entre téléphone et écouteurs, liaison infrarouge \\
\hline
LAN / WLAN & un bâtiment, une entreprise, un campus (100 m à 1 km) & réseau du cybercafé, du lycée, d'une administration \\
\hline
MAN / WMAN & une ville, une agglomération (10 à 100 km) & réseau fibré de CAMTEL reliant les arrondissements de Yaoundé, WiMAX urbain \\
\hline
WAN / WWAN & pays, continent, monde ( > 100 km) & Internet, réseau 4G/5G national, liaison satellite inter-sites \\
\hline
\end{tabularx}
\end{center}
\end{methode}

\begin{exemplebox}[Classification de réseaux (type Bac)]
Le lycée bilingue de Bafoussam possède un réseau reliant les 40 ordinateurs de ses deux salles informatiques par câbles à paires torsadées. Le proviseur consulte ses mails via le réseau 4G de son téléphone, et ses écouteurs sont connectés à ce téléphone par Bluetooth. Enfin, les ordinateurs du lycée accèdent à Internet grâce à la fibre optique de CAMTEL.
\begin{enumerate}
\item Donner le type de chacun des réseaux mis en jeu, en justifiant.
\item Le réseau du lycée est-il filaire ou sans fil ? Justifier.
\end{enumerate}
\tcblower
\textbf{1. Classification des réseaux.}
\begin{itemize}
\item \textbf{Réseau des salles informatiques} : il relie des ordinateurs situés dans un même établissement (étendue d'un bâtiment). C'est donc un \cle{LAN} (\emph{Local Area Network}, réseau local).
\item \textbf{Réseau 4G du téléphone} : il couvre tout le territoire national via des ondes radio. C'est un \cle{WWAN} (\emph{Wireless Wide Area Network}, réseau étendu sans fil).
\item \textbf{Liaison Bluetooth téléphone--écouteurs} : portée de quelques mètres, sans fil. C'est un \cle{WPAN} (\emph{Wireless Personal Area Network}, réseau personnel sans fil).
\item \textbf{Accès Internet par la fibre CAMTEL} : Internet interconnecte des millions de réseaux à l'échelle mondiale. C'est un \cle{WAN} (\emph{Wide Area Network}, réseau étendu).
\end{itemize}
\textbf{2. Nature du réseau du lycée.} Les ordinateurs sont reliés par des câbles à paires torsadées : le support de transmission est matériel (un câble). Le réseau du lycée est donc un réseau \cle{filaire} (LAN filaire).

\textbf{Conclusion :} le réseau des salles est un LAN filaire, la 4G un WWAN, le Bluetooth un WPAN et Internet un WAN.
\end{exemplebox}

\begin{methode}[Reconnaître une topologie à partir d'un schéma ou d'une description]
\begin{enumerate}
\item \textbf{Distinguer d'abord physique et logique} : la topologie \cle{physique} décrit la disposition réelle des câbles et des machines ; la topologie \cle{logique} décrit la manière dont les données circulent (Ethernet : diffusion/CSMA-CD ; Token Ring : circulation d'un jeton).
\item \textbf{Observer le point central} : si tous les postes sont reliés à un équipement central (switch, hub), c'est une topologie en \cle{étoile}.
\item \textbf{Observer le support commun} : si tous les postes se partagent un unique câble principal terminé aux deux bouts par des résistances de terminaison, c'est une topologie en \cle{bus}.
\item \textbf{Observer la boucle} : si chaque poste est relié à exactement deux voisins formant une boucle fermée, c'est une topologie en \cle{anneau}.
\item \textbf{Observer les liaisons multiples} : si chaque poste est relié à plusieurs (voire tous) les autres, c'est une topologie \cle{maillée} (totale ou partielle).
\end{enumerate}
\textbf{Réflexes :} panne du câble principal $\Rightarrow$ tout le bus tombe ; panne du point central $\Rightarrow$ toute l'étoile tombe ; l'étoile est la topologie la plus utilisée aujourd'hui dans les LAN (avec un switch). Ethernet (standard IEEE 802.3) impose une topologie logique en bus (diffusion) réalisée physiquement en étoile.
\end{methode}

\begin{exoresolu}[Topologies d'un cybercafé (type Bac)]
Dans un cybercafé de Douala, les 12 ordinateurs des clients sont chacun reliés par un câble à un commutateur (switch) placé au comptoir. Le gérant affirme : « notre réseau fonctionne en Ethernet ».
\begin{enumerate}
\item Quelle est la topologie physique de ce réseau ? Justifier et citer un avantage et un inconvénient.
\item « Ethernet » désigne-t-il une topologie physique ou logique ? Expliquer en une phrase comment les données y circulent.
\end{enumerate}
\tcblower
\textbf{1. Topologie physique.} Chaque poste est relié individuellement à un équipement central (le switch) : il s'agit d'une topologie physique en \cle{étoile}.
\begin{itemize}
\item \textbf{Avantage :} la panne d'un câble ou d'un poste ne perturbe pas les autres postes ; on peut ajouter un poste facilement sans couper le réseau.
\item \textbf{Inconvénient :} si le switch (point central) tombe en panne, tout le réseau est paralysé ; de plus, cette topologie consomme beaucoup de câble (un câble par poste).
\end{itemize}
\textbf{2. Nature d'Ethernet.} Ethernet désigne une topologie \cle{logique} (et non physique). Dans un réseau Ethernet (CSMA/CD), toute trame émise est diffusée sur le support partagé : chaque poste la reçoit, compare l'adresse MAC de destination à la sienne et ne conserve la trame que s'il en est le destinataire.

\textbf{Conclusion :} le cybercafé utilise une topologie physique en étoile et une topologie logique Ethernet.
\end{exoresolu}

\courssub{Protocoles de communication et protocoles Internet}

\begin{definition}[Protocole]
Un \cle{protocole} est un ensemble de règles et de conventions (syntaxe, sémantique, synchronisation) qui régissent la communication entre deux entités. Sur Internet, la suite de protocoles \cle{TCP/IP} est le standard universel.
\end{definition}

\begin{propriete}[Principaux protocoles de la suite TCP/IP (niveau application et transport)]
\begin{center}
\begin{tabularx}{\linewidth}{|l|l|X|l|}
\hline
\rowcolor{popblueL} \textbf{Protocole} & \textbf{Port(s) standard} & \textbf{Rôle / Fonction} & \textbf{Mnémotechnique} \\
\hline
\cle{IP} (Internet Protocol) & -- & Adressage (IPv4/IPv6), routage, fragmentation/réassemblage des paquets. Service \emph{non connecté}, \emph{non fiable} (best effort). & \emph{Identification \& Path} \\
\cle{TCP} (Transmission Control Protocol) & -- & Transport \emph{connecté}, \emph{fiable}, ordonné, contrôle de flux/congestion. Utilisé par HTTP, FTP, SMTP, POP3. & \emph{Transmission Control} \\
\cle{UDP} (User Datagram Protocol) & -- & Transport \emph{non connecté}, rapide, pas de garantie. Utilisé par DNS, DHCP, streaming, VoIP, jeux. & \emph{User Datagram} \\
\hline
\cle{HTTP} / \cle{HTTPS} & 80 / 443 & Transfert d'hypertexte (pages web). HTTPS = HTTP + TLS/SSL (chiffrement). & \emph{HyperText Transfer Protocol} \\
\cle{FTP} & 20 (données), 21 (cmd) & Transfert de fichiers (authentification, listage, upload/download). & \emph{File Transfer Protocol} \\
\cle{SMTP} & 25, 465, 587 & \textbf{Envoi} de courrier électronique (client $\rightarrow$ serveur, serveur $\rightarrow$ serveur). & \textbf{S}end \textbf{M}ail \textbf{T}ransfer \textbf{P}rotocol \\
\cle{POP3} & 110, 995 & \textbf{Réception} de courrier (téléchargement du serveur vers client, souvent suppression serveur). & \textbf{P}ost \textbf{O}ffice \textbf{P}rotocol v3 \\
\cle{IMAP} & 143, 993 & \textbf{Réception/Synchronisation} courrier (messages restent sur le serveur, multi-appareils). & \emph{Internet Message Access Protocol} \\
\cle{DHCP} & 67 (srv), 68 (cli) & Attribution \emph{automatique} d'adresse IP, masque, passerelle, DNS aux postes (bail temporaire). & \emph{Dynamic Host Configuration Protocol} \\
\cle{DNS} & 53 & Résolution de noms de domaine $\leftrightarrow$ adresses IP (annuaire distribué). & \emph{Domain Name System} \\
\hline
\end{tabularx}
\end{center}
\textbf{Piège classique :} ne jamais confondre \textbf{SMTP} (envoi / \textbf{S}end) et \textbf{POP3}/\textbf{IMAP} (réception). Au Bac, on cite souvent SMTP et POP3 comme le couple envoi/réception.
\end{propriete}

\begin{exoresolu}[Équipement d'une salle multimédia et protocoles (type Bac)]
Une ONG veut équiper une salle multimédia à Maroua : 10 ordinateurs doivent être mis en réseau local et partager une même connexion Internet fournie par une ligne téléphonique (ADSL). Les élèves devront aussi consulter des pages web et télécharger des fichiers depuis un serveur distant.
\begin{enumerate}
\item Citer, en justifiant, les équipements réseau nécessaires.
\item Citer les protocoles mis en jeu lors de la consultation d'une page web et du téléchargement d'un fichier.
\end{enumerate}
\tcblower
\textbf{1. Équipements nécessaires.}
\begin{itemize}
\item Une \textbf{carte réseau (NIC)} dans chaque ordinateur : c'est l'interface matérielle obligatoire de connexion au réseau (couche 2).
\item Un \textbf{switch} (16 ou 24 ports) : il relie les 10 ordinateurs entre eux au sein du réseau local en acheminant les trames uniquement vers le destinataire (couche 2).
\item Un \textbf{modem ADSL} : il convertit les signaux numériques du réseau en signaux transportables sur la ligne téléphonique cuivre (couche 1).
\item Un \textbf{routeur} : il interconnecte le réseau local de la salle (adresses privées) et le réseau d'Internet (adresses publiques), en choisissant la route des paquets IP et en effectuant le NAT (couche 3).
\end{itemize}
\textit{Remarque :} En pratique, la « Box » de l'opérateur regroupe modem, routeur, switch (4 ports) et Wi-Fi. Si le switch de la box a 4 ports, il faut ajouter un switch 8/16 ports pour les 10 PC.

\textbf{2. Protocoles mis en jeu.}
\begin{itemize}
\item Consultation d'une page web : le protocole \textbf{HTTP} (ou HTTPS sur port 443), qui gère l'échange requête/réponse entre le navigateur (client) et le serveur web. Les données sont segmentées par \textbf{TCP} (port 80/443) et adressées/acheminées par \textbf{IP}.
\item Téléchargement d'un fichier : le protocole \textbf{FTP} (ports 20/21), spécialisé dans le transfert de fichiers (authentification, mode actif/passif). Également transporté par \textbf{TCP/IP}.
\item Dans les deux cas, la résolution du nom de domaine (ex. \texttt{www.example.cm}) en adresse IP utilise le protocole \textbf{DNS} (port 53, UDP/TCP).
\end{itemize}
\textbf{Conclusion :} il faut 10 cartes réseau, un switch, un modem ADSL et un routeur (souvent intégrés dans la Box) ; la navigation utilise HTTP/TCP/IP, le téléchargement FTP/TCP/IP, la résolution DNS/UDP/IP.
\end{exoresolu}

\courssub{Adressage IPv4 : structure, classes, masque, sous-réseau}

\begin{definition}[Adresse IPv4]
Une \cle{adresse IPv4} est un identifiant numérique de 32 bits (4 octets) attribué à chaque interface réseau d'un équipement connecté à un réseau IP. Elle s'écrit en notation décimale pointée : $a.b.c.d$ où chaque octet $a,b,c,d \in [0, 255]$. Elle se décompose en deux parties : \textbf{Partie Réseau} (identifie le réseau) et \textbf{Partie Hôte} (identifie la machine dans ce réseau). La frontière est définie par le \cle{masque de sous-réseau}.
\end{definition}

\begin{propriete}[Classes d'adresses IPv4 (Classful - héritage historique, base du Bac)]
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|X|X|}
\hline
\rowcolor{popblueL} \textbf{Classe} & \textbf{1\textsuperscript{er} octet (décimal)} & \textbf{1\textsuperscript{er} octet (binaire)} & \textbf{Masque par défaut} & \textbf{Usage / Nb réseaux / Nb hôtes max} \\
\hline
A & 1 à 126 & \texttt{0xxxxxxx} & 255.0.0.0 \quad (/8) & Très grands réseaux. $2^7-2=126$ réseaux, $\approx 16,7$ millions d'hôtes/réseau. \\
\hline
B & 128 à 191 & \texttt{10xxxxxx} & 255.255.0.0 \quad (/16) & Réseaux moyens. $2^{14}\approx 16\,384$ réseaux, $\approx 65\,534$ hôtes/réseau. \\
\hline
C & 192 à 223 & \texttt{110xxxxx} & 255.255.255.0 \quad (/24) & Petits réseaux. $\approx 2$ millions de réseaux, $254$ hôtes/réseau. \\
\hline
D & 224 à 239 & \texttt{1110xxxx} & -- & Multicast (un vers plusieurs). Pas d'adressage hôte. \\
\hline
E & 240 à 255 & \texttt{1111xxxx} & -- & Expérimental / Réservé. \\
\hline
\end{tabularx}
\end{center}
\textbf{Adresses réservées spéciales :}
\begin{itemize}
\item \texttt{127.0.0.0/8} (souvent \texttt{127.0.0.1}) : \cle{Loopback} (adresse de boucle locale, test de la pile TCP/IP locale).
\item \texttt{0.0.0.0} : « ce réseau » ou « route par défaut » (dans table de routage).
\item \texttt{255.255.255.255} : Diffusion limitée (broadcast local, ne traverse pas les routeurs).
\item \textbf{Adresses privées (RFC 1918) :} Non routables sur Internet, utilisées en LAN (NAT obligatoire pour sortir).
  \begin{itemize}
  \item Classe A : \texttt{10.0.0.0} -- \texttt{10.255.255.255} (masque /8)
  \item Classe B : \texttt{172.16.0.0} -- \texttt{172.31.255.255} (masque /12)
  \item Classe C : \texttt{192.168.0.0} -- \texttt{192.168.255.255} (masque /16)
  \end{itemize}
\end{itemize}
\end{propriete}

\begin{methode}[Trouver la classe et le masque par défaut à partir du premier octet]
\begin{enumerate}
\item \textbf{Isoler le premier octet} $a$ (le nombre à gauche du premier point).
\item \textbf{Appliquer les intervalles} :
  \begin{itemize}
  \item $1 \le a \le 126$ $\Rightarrow$ \textbf{Classe A}, masque \textbf{255.0.0.0}.
  \item $128 \le a \le 191$ $\Rightarrow$ \textbf{Classe B}, masque \textbf{255.255.0.0}.
  \item $192 \le a \le 223$ $\Rightarrow$ \textbf{Classe C}, masque \textbf{255.255.255.0}.
  \end{itemize}
\item \textbf{Attention :} $a = 127$ $\Rightarrow$ Loopback (pas classe A). $a = 0$ ou $a \ge 224$ $\Rightarrow$ pas d'adresse hôte standard.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Classes d'adresses (type Bac)]
Le service informatique d'un hôpital de Garoua relève les adresses suivantes sur son réseau : 192.168.10.25 ; 172.20.5.100 ; 10.3.45.7 ; 193.5.200.1.
\begin{enumerate}
\item Déterminer la classe de chaque adresse, en justifiant.
\item Donner le masque de sous-réseau par défaut de chacune.
\end{enumerate}
\tcblower
On applique la règle : la classe se lit sur le \textbf{premier octet}.
\begin{enumerate}
\item \textbf{192.168.10.25} : premier octet $192$, or $192 \le 192 \le 223$ $\Rightarrow$ \textbf{Classe C}, masque par défaut \textbf{255.255.255.0}.
\item \textbf{172.20.5.100} : premier octet $172$, or $128 \le 172 \le 191$ $\Rightarrow$ \textbf{Classe B}, masque par défaut \textbf{255.255.0.0}.
\item \textbf{10.3.45.7} : premier octet $10$, or $1 \le 10 \le 126$ $\Rightarrow$ \textbf{Classe A}, masque par défaut \textbf{255.0.0.0}.
\item \textbf{193.5.200.1} : premier octet $193$, or $192 \le 193 \le 223$ $\Rightarrow$ \textbf{Classe C}, masque par défaut \textbf{255.255.255.0}.
\end{enumerate}
\textbf{Conclusion :} 192.168.10.25 et 193.5.200.1 sont de classe C (255.255.255.0), 172.20.5.100 de classe B (255.255.0.0) et 10.3.45.7 de classe A (255.0.0.0). Notez que 10.x, 172.16-31.x, 192.168.x sont des adresses \emph{privées}.
\end{exoresolu}

\begin{methode}[Calculer l'adresse réseau et l'adresse de diffusion (Broadcast)]
Soit une adresse IP et un masque de sous-réseau (donné en décimal pointé ou en notation CIDR /$n$).
\begin{enumerate}
\item \textbf{Écrire l'adresse IP et le masque octet par octet}. Convertir en binaire si le masque n'est pas « aligné sur les octets » (ex. 255.255.255.192).
\item \textbf{Adresse réseau (ID réseau)} : effectuer le \cle{ET logique} bit à bit entre l'adresse IP et le masque.
  \begin{itemize}
  \item Règle rapide : là où le masque vaut \textbf{255} (bits à 1), on \textbf{recopie} l'octet de l'IP. Là où le masque vaut \textbf{0} (bits à 0), on met \textbf{0}.
  \item Si masque « non aligné » (ex. 255.255.255.192 = /26) : convertir l'octet concerné en binaire, faire le ET bit à bit, reconvertir en décimal.
  \end{itemize}
\item \textbf{Adresse de diffusion (Broadcast)} : partir de l'adresse réseau et mettre à \textbf{255} tous les octets (ou bits) situés dans la partie hôte (là où le masque vaut 0).
\item \textbf{Nombre de machines adressables} : $N = 2^{n} - 2$, où $n$ = nombre de bits à 0 dans le masque (bits de la partie hôte). On retire l'adresse réseau (tout à 0) et l'adresse de diffusion (tout à 1).
\end{enumerate}
\end{methode}

\begin{exoresolu}[Calcul complet sur une adresse de classe C (type Bac)]
Le poste du comptable d'une boutique de Bafoussam a pour adresse 192.168.15.37 avec le masque 255.255.255.0.
\begin{enumerate}
\item Déterminer l'adresse réseau de ce sous-réseau.
\item Déterminer l'adresse de diffusion.
\item Combien de machines peut-on adresser dans ce sous-réseau ?
\end{enumerate}
\tcblower
\textbf{1. Adresse réseau.} On effectue le ET logique octet par octet entre l'IP et le masque :
\begin{align*}
\text{IP} \quad &: \quad 192.168.15.37\\
\text{Masque} \quad &: \quad 255.255.255.0\\
\text{ET logique} \quad &: \quad 192.168.15.0
\end{align*}
Justification : pour les trois premiers octets, le masque vaut 255 (tous bits à 1), donc on recopie l'octet de l'IP ; pour le dernier octet, le masque vaut 0, donc le résultat vaut 0. L'adresse réseau est \textbf{192.168.15.0}.

\textbf{2. Adresse de diffusion.} On part de l'adresse réseau et on met à 255 les octets de la partie hôte (là où le masque vaut 0), c'est-à-dire le dernier octet : l'adresse de diffusion est \textbf{192.168.15.255}.

\textbf{3. Nombre de machines adressables.} Le masque 255.255.255.0 comporte $n = 8$ bits à 0 (le dernier octet). Le nombre d'adresses du sous-réseau est :
\[ 2^{n} = 2^{8} = 256 \]
On retire l'adresse réseau (192.168.15.0) et l'adresse de diffusion (192.168.15.255), qui ne sont pas attribuables :
\[ 2^{8} - 2 = 256 - 2 = 254 \]
\textbf{Conclusion :} l'adresse réseau est 192.168.15.0, l'adresse de diffusion est 192.168.15.255, et le sous-réseau peut adresser 254 machines.
\end{exoresolu}

\begin{exoresolu}[Adressage avec masque non aligné / conversion binaire (type Bac, niveau avancé)]
Un poste a pour adresse 172.16.35.20 et pour masque 255.255.255.192 (notation CIDR : /26). Déterminer l'adresse réseau et l'adresse de diffusion, en détaillant le ET logique sur le quatrième octet.
\tcblower
\textbf{Analyse du masque :} 255.255.255.192 $\Rightarrow$ 24 bits à 1 (3 premiers octets) + 2 bits à 1 dans le 4\textsuperscript{e} octet (192 = \texttt{11000000}$_2$). Partie hôte = 6 bits (derniers 6 bits du 4\textsuperscript{e} octet).

\textbf{Adresse réseau.} Les trois premiers octets : masque 255 $\Rightarrow$ on recopie \texttt{172.16.35}.
Quatrième octet : ET logique entre 20 (\texttt{00010100}$_2$) et 192 (\texttt{11000000}$_2$) :
\begin{align*}
20 \quad &: \quad \texttt{00010100}\\
192 \quad &: \quad \texttt{11000000}\\
20 \;\text{ET}\; 192 \quad &: \quad \texttt{00000000} = 0
\end{align*}
Les deux bits de poids fort de 20 sont 0, le ET avec 1 donne 0. Les 6 bits de poids faible sont masqués par des 0. Résultat : 0.
\[ \text{Adresse réseau} = \textbf{172.16.35.0} \]

\textbf{Adresse de diffusion.} On met à 1 les 6 bits de la partie hôte (poids faible du 4\textsuperscript{e} octet) : \texttt{00111111}$_2$ = 63.
\[ \text{Adresse de diffusion} = \textbf{172.16.35.63} \]

\textbf{Nombre de machines :} $n=6$ bits hôte $\Rightarrow 2^6 - 2 = 64 - 2 = \textbf{62 machines}$ (adresses utilisables : 172.16.35.1 à 172.16.35.62).
\textbf{Conclusion :} adresse réseau 172.16.35.0, adresse de diffusion 172.16.35.63, 62 machines adressables.
\end{exoresolu}

\courssub{Création et configuration d'un réseau local de 3 postes (Travaux Pratiques)}

\begin{experience}[TP : Mise en œuvre d'un LAN 3 postes, configuration IPv4 statique et tests]
\textbf{Objectif :} Interconnecter 3 ordinateurs via un switch, configurer l'adressage IPv4 statique, vérifier la configuration (\texttt{ipconfig}) et tester la connectivité (\texttt{ping}).

\textbf{Matériel / Logiciels :}
\begin{itemize}
\item 3 ordinateurs (PC1, PC2, PC3) sous Windows 10/11 ou Linux, chacun équipé d'une carte réseau (NIC) fonctionnelle.
\item 1 Switch (commutateur) 5 ou 8 ports (non manageable suffit).
\item 3 câbles droits (patch cords) à paires torsadées Cat 5e/6, connecteurs RJ45.
\end{itemize}

\textbf{Étape 1 : Câblage physique (Topologie en étoile).}
\begin{enumerate}
\item Éteindre les postes et le switch.
\item Insérer une extrémité de chaque câble dans le port RJ45 de la carte réseau de chaque PC.
\item Insérer l'autre extrémité dans trois ports distincts du switch (ex. ports 1, 2, 3).
\item Allumer le switch, puis les 3 ordinateurs.
\item Vérifier les voyants (LEDs) : \textbf{Link/Act} allumé (vert/orange) sur le port du switch et sur la carte réseau du PC = liaison physique OK (couche 1).
\end{enumerate}

\textbf{Étape 2 : Choix du plan d'adressage (IPv4 statique).}
On choisit un réseau privé de classe C : \textbf{192.168.10.0/24} (Masque \textbf{255.255.255.0}).
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|X|}
\hline
\rowcolor{popblueL} \textbf{Poste} & \textbf{Adresse IPv4} & \textbf{Masque de sous-réseau} & \textbf{Passerelle par défaut} \\
\hline
PC1 (Accueil) & 192.168.10.1 & 255.255.255.0 & \textit{Laisser vide (pas de routeur)} \\
\hline
PC2 (Catalogue) & 192.168.10.2 & 255.255.255.0 & \textit{Laisser vide} \\
\hline
PC3 (Admin) & 192.168.10.3 & 255.255.255.0 & \textit{Laisser vide} \\
\hline
\end{tabularx}
\end{center}
\textbf{Règles d'or :} Même adresse réseau (192.168.10.0) et même masque pour tous. Partie hôte différente (1, 2, 3). Ni .0 (réseau), ni .255 (broadcast).

\textbf{Étape 3 : Configuration IPv4 sur Windows (identique sur les 3 PC, IP différente).}
\begin{enumerate}
\item \texttt{Win+R} $\rightarrow$ \texttt{ncpa.cpl} (Connexions réseau) \textbf{OU} Panneau de configuration $\rightarrow$ Réseau et Internet $\rightarrow$ Centre Réseau et partage $\rightarrow$ Modifier les paramètres de la carte.
\item Clic droit sur \textbf{Ethernet} (ou « Connexion au réseau local ») $\rightarrow$ \textbf{Propriétés}.

\begin{exoresolu}[Mise en réseau d'une bibliothèque scolaire (type Bac)]
La bibliothèque d'un collège de Ngaoundéré dispose de 3 ordinateurs : PC-A (accueil), PC-B (catalogue) et PC-C (administration). On veut les interconnecter en réseau local avec le sous-réseau 192.168.10.0 et le masque 255.255.255.0.

\item Proposer un plan d'adressage complet des trois postes.
\item Donner la commande permettant de vérifier, depuis PC-A, que PC-B est joignable, et le résultat attendu.
\item Donner la commande qui affiche la configuration IP de PC-C.
\item Le technicien a saisi 192.168.10.255 sur PC-C. Expliquer pourquoi c'est une erreur.
\end{enumerate}
\tcblower
\textbf{1. Plan d'adressage.} Tous les postes partagent la même adresse réseau 192.168.10.0 et le même masque ; seule la partie hôte change :
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}
\hline
\rowcolor{popblueL} \textbf{Poste} & \textbf{Adresse IP} & \textbf{Masque de sous-réseau} \\
\hline
PC-A & 192.168.10.1 & 255.255.255.0 \\
\hline
PC-B & 192.168.10.2 & 255.255.255.0 \\
\hline
PC-C & 192.168.10.3 & 255.255.255.0 \\
\hline
\end{tabularx}
\end{center}

\textbf{2. Test depuis PC-A vers PC-B.} Dans l'invite de commandes de PC-A, on tape :
\begin{lstlisting}[language=bash]
ping 192.168.10.2
\end{lstlisting}
Résultat attendu si le réseau fonctionne : quatre lignes du type « Réponse de 192.168.10.2 : octets=32 temps<1ms TTL=128 », suivies de la statistique « Paquets : envoyés = 4, reçus = 4, perdus = 0 ». Cela prouve que PC-A et PC-B communiquent (couches 1 à 3 opérationnelles).

\textbf{3. Affichage de la configuration de PC-C.} On tape dans l'invite de commandes de PC-C :
\begin{lstlisting}[language=bash]
ipconfig
\end{lstlisting}
Cette commande affiche l'adresse IPv4 (192.168.10.3), le masque de sous-réseau (255.255.255.0) et la passerelle par défaut (vide ici) de la carte réseau.

\textbf{4. Erreur sur PC-C.} Avec le masque 255.255.255.0, l'adresse 192.168.10.255 est l'\textbf{adresse de diffusion} (broadcast) du sous-réseau 192.168.10.0 (partie hôte entièrement à 1 : \texttt{11111111}$_2$). Or l'adresse de diffusion est réservée à l'envoi de messages vers \emph{tous} les postes du réseau : elle ne peut \textbf{jamais} être attribuée à une interface hôte. PC-C ne pourrait donc pas communiquer correctement (conflit d'adresse, paquets non routés vers lui) ; il faut lui donner une adresse libre entre 192.168.10.1 et 192.168.10.254.

\textbf{Conclusion :} le plan 192.168.10.1/2/3 avec le masque 255.255.255.0 est correct ; \texttt{ping 192.168.10.2} teste la liaison et \texttt{ipconfig} affiche la configuration ; 192.168.10.255 est interdite car c'est l'adresse de diffusion.
\end{exoresolu}

\begin{attention}[Les 5 erreurs qui coûtent des points au Bac]
\begin{enumerate}
\item \textbf{Confondre topologie physique et topologie logique.} Écrire « la topologie physique est Ethernet » est \textbf{faux} : Ethernet et Token Ring sont des topologies \emph{logiques} ; bus, étoile, anneau et maillée sont des topologies \emph{physiques}. Précise toujours l'adjectif « physique » ou « logique ».
\item \textbf{Confondre SMTP et POP3/IMAP.} SMTP sert à l'\emph{envoi} du courrier (client $\rightarrow$ serveur, serveur $\rightarrow$ serveur), POP3/IMAP à sa \emph{réception} (serveur $\rightarrow$ client). Inverser les deux dans une copie est sanctionné. Astuce : le « \textbf{S} » de SMTP comme \textbf{S}end (envoyer).
\item \textbf{Se tromper de borne dans les classes d'adresses.} Les intervalles sont 1--126 (A), 128--191 (B), 192--223 (C) : \textbf{127 est exclu} (boucle locale, 127.0.0.1) et 127.x n'est ni A, ni B, ni C. Vérifie toujours que le premier octet n'est pas 127 avant de conclure.
\item \textbf{Attribuer l'adresse réseau ou l'adresse de diffusion à un poste.} Avec le masque 255.255.255.0, les adresses en .0 (réseau) et en .255 (diffusion) sont réservées : les adresses attribuables vont de .1 à .254. Oublier le « $-2$ » dans le calcul du nombre de machines ($2^{n}-2$) est l'erreur de calcul la plus fréquente.
\item \textbf{Rédiger le ET logique sans justification.} Au Bac, il ne suffit pas d'écrire le résultat : il faut montrer le raisonnement octet par octet (« masque = 255 donc on recopie l'octet ; masque = 0 donc on met 0 ») ou poser le calcul en binaire sur l'octet concerné. Un résultat seul, même juste, ne rapporte pas tous les points.
\end{enumerate}
\end{attention}

\begin{corrige}[Exercice n°1 - Entraînement Bac]
\begin{enumerate}
\item \textbf{Qualification des réseaux :}
\begin{itemize}
\item \textbf{Intérieur bâtiment :} 20 postes, câbles paires torsadées, étendue $\approx$ 100 m $\Rightarrow$ \textbf{LAN filaire} (topologie physique étoile, logique Ethernet).
\item \textbf{Inter-bâtiments :} 3 bâtiments, 200 m, fibre optique $\Rightarrow$ \textbf{MAN filaire} (ou backbone de campus). Relie des LAN entre eux.
\item \textbf{Liaison 4G :} Sans fil, couverture nationale $\Rightarrow$ \textbf{WWAN} (Wireless Wide Area Network).
\end{itemize}
\item \textbf{Calculs sur 172.18.45.100 / 255.255.255.240 (/28) :}
\begin{enumerate}
\item Premier octet = 172. $128 \le 172 \le 191$ $\Rightarrow$ \textbf{Classe B}. Masque par défaut classe B = \textbf{255.255.0.0} (/16).
\item Masque 255.255.255.240 : 3 premiers octets = 255 $\Rightarrow$ recopie 172.18.45.
4\textsuperscript{e} octet : Masque 240 = \texttt{11110000}$_2$. IP 100 = \texttt{01100100}$_2$.
ET logique :
\[
\begin{array}{c@{\quad}cccccccc}
\text{IP (100)} & 0 & 1 & 1 & 0 & 0 & 1 & 0 & 0 \\
\text{Masque (240)} & 1 & 1 & 1 & 1 & 0 & 0 & 0 & 0 \\ \hline
\text{Réseau} & 0 & 1 & 1 & 0 & 0 & 0 & 0 & 0 = 96
\end{array}
\]
Adresse réseau = \textbf{172.18.45.96}.
Adresse de diffusion : partie hôte (4 derniers bits) à 1 $\Rightarrow$ \texttt{01101111}$_2$ = 111.
Adresse de diffusion = \textbf{172.18.45.111}.
\item Bits hôte $n=4$ (masque /28). Nombre d'adresses $= 2^4 = 16$. Machines adressables $= 16 - 2 = \textbf{14}$ (adresses 97 à 110).
\end{enumerate}
\item \textbf{Protocoles et ports :}
\begin{enumerate}
\item \textbf{DNS} (Domain Name System), port \textbf{53} (UDP principalement, TCP pour zone transfer).
\item \textbf{FTP} (File Transfer Protocol), ports \textbf{21} (commande) et \textbf{20} (données). (SFTP/SSH port 22 aussi accepté si contexte sécurisé).
\item \textbf{IMAP} (Internet Message Access Protocol), port \textbf{143} (ou 993 pour IMAPS/SSL). \textit{Note : POP3 (110/995) télécharge et supprime souvent du serveur ; IMAP synchronise et laisse sur le serveur, ce qui correspond à « en les laissant sur le serveur »}.
\item \textbf{DHCP} (Dynamic Host Configuration Protocol), port \textbf{67} (serveur) / \textbf{68} (client), UDP.
\end{enumerate}
\item \textbf{Schéma attendu (description textuelle pour la correction) :}
\begin{itemize}
\item Nuage « Internet (WAN) » relié par trait plein (fibre/ADSL/4G) à un rectangle « Box FAI » (légende : Modem + Routeur + Switch 4p + Wi-Fi AP).
\item Box relié par câble droit (UTP Cat 6) à un rectangle « Switch 24 ports ».
\item Switch relié par 4 câbles droits (UTP Cat 6) à : « PC1 », « PC2 », « PC3 », « Imprimante réseau ».
\item Flèches annotées : DHCP (Box $\rightarrow$ Postes), DNS (Postes $\rightarrow$ Box/FAI), HTTP (Postes $\rightarrow$ Internet).
\item Légende : Topologie physique en étoile (autour du switch). Adressage privé (ex. 192.168.1.0/24). NAT sur la Box.
\end{itemize}
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 1 --- QCM : Types de réseaux et étendue géographique]

\begin{enumerate}
    \item \textbf{B. LAN} --- Un réseau limité à un bâtiment ou un petit site (salle informatique, bureaux, lycée) est un \emph{Local Area Network}. Le PAN est à l'échelle d'une personne (quelques mètres), le MAN à l'échelle d'une ville, le WAN à l'échelle d'un pays ou du monde.
    \item \textbf{A. WPAN} --- Le Bluetooth relie des équipements personnels (téléphone, oreillette, montre) sur quelques mètres : c'est un réseau personnel sans fil (\emph{Wireless PAN}).
    \item \textbf{C. WAN} --- Un réseau qui interconnecte plusieurs villes à l'échelle nationale (fibre optique CAMTEL Yaoundé--Douala--Garoua) est un \emph{Wide Area Network}.
    \item \textbf{B. WLAN} --- Un réseau Wi-Fi couvrant un campus universitaire reste un réseau local (site unique), mais sans fil : \emph{Wireless LAN}.
\end{enumerate}

\begin{attention}[Points de vigilance]
Ne pas confondre \textbf{MAN} (ville, quelques kilomètres à quelques dizaines de kilomètres) et \textbf{WAN} (pays, continents). Le campus universitaire, même grand, reste un seul site : c'est un LAN/WLAN, pas un MAN.
\end{attention}
\end{corrige}

\begin{corrige}[Exercice 2 --- Vrai / Faux justifié : Topologies et équipements]

\begin{enumerate}
    \item \textbf{VRAI.} Dans un bus 10BASE2, chaque poste est raccordé au câble principal par un connecteur en T ; la défaillance d'un \emph{raccordement} ne coupe que le poste concerné. En revanche, une \emph{coupure du câble principal} (ou l'absence de bouchon terminateur) fait tomber tout le réseau.
    \item \textbf{VRAI.} Le hub est un répéteur multiports : il ne connaît pas les adresses et retransmet chaque trame sur tous ses ports, ce qui multiplie les collisions (domaine de collision unique).
    \item \textbf{VRAI.} Le switch apprend les adresses MAC des machines connectées à chaque port (table CAM) et n'achemine la trame que vers le port du destinataire, ce qui supprime la plupart des collisions.
    \item \textbf{VRAI.} Dans Token Ring, un jeton circule de poste en poste ; seul le détenteur du jeton a le droit d'émettre, ce qui évite toute collision (méthode d'accès déterministe, contrairement à Ethernet/CSMA-CD).
    \item \textbf{FAUX.} La fibre optique transporte la lumière et non un courant électrique : elle est \emph{insensible} aux perturbations électromagnétiques (parasites, foudre, moteurs), contrairement aux câbles cuivre non blindés.
\end{enumerate}

\begin{attention}[Point de vigilance]
La justification est exigée : une réponse « vrai » ou « faux » sans argument technique (table d'adresses MAC, jeton, immunité électromagnétique) ne rapporte pas tous les points.
\end{attention}
\end{corrige}

\begin{corrige}[Exercice 4 --- Calculs directs : Adressage IPv4]

\begin{enumerate}
    \item \texttt{192.168.10.5} : premier octet $192 \in [192 ; 223]$ $\Rightarrow$ \textbf{classe C} (masque par défaut \texttt{255.255.255.0}).
    \item Classe B : masque par défaut \textbf{\texttt{255.255.0.0}}, soit \textbf{/16}.
    \item \texttt{172.16.5.4} ET \texttt{255.255.0.0} : les deux premiers octets sont conservés, les deux derniers mis à zéro $\Rightarrow$ adresse réseau \textbf{\texttt{172.16.0.0}}.
    \item Réseau \texttt{10.0.0.0/8} : les 24 bits d'hôte sont mis à 1 $\Rightarrow$ broadcast \textbf{\texttt{10.255.255.255}}.
    \item Masque /24 : $32 - 24 = 8$ bits d'hôte, soit $2^8 = 256$ adresses ; on retire l'adresse réseau et l'adresse de diffusion : $256 - 2 = \textbf{254 hôtes utilisables}$.
\end{enumerate}

\begin{attention}[Point de vigilance]
La formule du nombre d'hôtes utilisables est $2^n - 2$ ($n$ = nombre de bits d'hôte). Oublier le $-2$ est l'erreur la plus fréquente au Bac.
\end{attention}
\end{corrige}

\begin{corrige}[Exercice 5 --- Analyse d'une configuration IP locale]

\begin{enumerate}
    \item Premier octet $192 \in [192 ; 223]$ : adresse de \textbf{classe C}.
    \item Adresse réseau : ET logique bit à bit entre \texttt{192.168.1.15} et \texttt{255.255.255.0}. Les trois premiers octets sont conservés (masque à 255), le dernier est mis à 0 (masque à 0) :
    \[ 192.168.1.15 \ \text{ET}\ 255.255.255.0 = \textbf{\texttt{192.168.1.0}} \]
    \item Adresse de diffusion : tous les bits d'hôte (dernier octet) à 1 $\Rightarrow$ \textbf{\texttt{192.168.1.255}}.
    \item Bits d'hôte : $32 - 24 = 8$, soit $2^8 - 2 = \textbf{254 machines maximum}$ (de \texttt{192.168.1.1} à \texttt{192.168.1.254}).
    \item La \textbf{passerelle par défaut} \texttt{192.168.1.254} est l'adresse du routeur (ou de la box) par lequel le poste envoie tout paquet destiné à un réseau différent du sien (par exemple Internet). Sans passerelle configurée, le poste ne peut communiquer qu'avec les machines de son propre sous-réseau \texttt{192.168.1.0/24}.
\end{enumerate}

\begin{attention}[Point de vigilance]
L'adresse réseau (\texttt{192.168.1.0}) et l'adresse de diffusion (\texttt{192.168.1.255}) ne sont \emph{jamais attribuables} à une machine. La passerelle doit appartenir au même sous-réseau que le poste.
\end{attention}
\end{corrige}

\begin{corrige}[Exercice 6 --- Test de connectivité avec PING]

\begin{enumerate}
    \item Commande exacte :
\begin{lstlisting}[language=bash]
ping 192.168.1.20
\end{lstlisting}
    Sous Windows, \texttt{ping} envoie par défaut 4 requêtes. Sous Linux, il faut limiter explicitement : \texttt{ping -c 4 192.168.1.20}.
    \item Chaque réponse affiche quatre champs : l'\textbf{adresse IP} du répondeur (\texttt{Réponse de 192.168.1.20}), la \textbf{taille} des données (\texttt{octets=32}), le \textbf{temps} aller-retour (\texttt{temps=1ms}) et le \texttt{TTL}. Le \textbf{TTL} (\emph{Time To Live}) est la durée de vie du paquet : chaque routeur traversé le décrémente de 1 ; arrivé à 0, le paquet est détruit, ce qui empêche les paquets de circuler indéfiniment en cas de boucle de routage. \texttt{TTL=128} est la valeur initiale typique de Windows.
    \item Trois causes possibles du message \texttt{Délai d'attente de la demande dépassé} :
    \begin{itemize}
        \item \textbf{Cause matérielle :} câble débranché ou défectueux, carte réseau ou switch en panne, serveur éteint.
        \item \textbf{Cause de configuration :} adresse IP ou masque incorrect sur l'un des postes (postes dans deux sous-réseaux différents sans passerelle), adresse du serveur erronée.
        \item \textbf{Cause pare-feu :} le pare-feu du serveur bloque les requêtes ICMP (protocole utilisé par \texttt{ping}).
    \end{itemize}
\end{enumerate}

\begin{attention}[Point de vigilance]
Un \texttt{ping} qui échoue ne prouve pas que la machine est éteinte : un pare-feu peut simplement ignorer l'ICMP. On teste alors d'abord \texttt{ping 127.0.0.1} (pile TCP/IP locale), puis la passerelle, puis la machine distante.
\end{attention}
\end{corrige}

\begin{corrige}[Exercice 7 --- Choix de topologie pour un cybercafé]

\begin{enumerate}
    \item \textbf{Topologie proposée : étoile.} Chacun des 12 postes est relié par son propre câble à paires torsadées (RJ45, catégorie 5e ou 6) à un équipement central : un \textbf{switch} 16 ports. Description : le switch est placé au centre de la salle (ou dans un petit coffret mural) ; de lui partent 12 liaisons indépendantes, une par poste.
    \item \textbf{Justification comparative :}
    \begin{itemize}
        \item \textbf{Coût :} l'étoile consomme plus de câble (12 liaisons au lieu d'un seul coaxial) et exige un switch ; le coût initial est donc plus élevé, mais le matériel Ethernet est aujourd'hui bon marché.
        \item \textbf{Fiabilité :} c'est l'argument décisif. En étoile, la panne ou le débranchement d'un câble ne prive que le poste concerné ; le reste du réseau continue de fonctionner. En bus, toute coupure du câble principal (ou bouchon terminateur manquant) arrête tout le réseau --- exactement le problème constaté.
        \item \textbf{Performance :} en bus coaxial (10 Mbit/s partagés, CSMA-CD), toutes les trames se partagent le même support et les collisions sont fréquentes. En étoile commutée, chaque poste dispose d'une liaison dédiée (100 Mbit/s ou 1 Gbit/s) et les collisions disparaissent.
    \end{itemize}
    \item \textbf{Choix : un switch, pas un hub.} Le hub retransmet chaque trame sur tous les ports : bande passante partagée et nombreuses collisions. Le switch construit une table d'adresses MAC et n'envoie la trame que vers le port du destinataire : débit garanti par poste, collisions supprimées, sécurité accrue (les autres clients ne reçoivent pas le trafic d'un poste).
\end{enumerate}

\begin{attention}[Point de vigilance]
La question 2 exige une comparaison sur \emph{trois critères nommés} (coût, fiabilité, performance) : traiter les trois explicitement, en citant le bus à chaque fois.
\end{attention}
\end{corrige}

\begin{corrige}[Exercice 8 --- Communication inter-sous-réseaux]

\begin{enumerate}
    \item Poste A : \texttt{192.168.1.5} ET \texttt{255.255.255.0} = \textbf{\texttt{192.168.1.0}}.
    \item Poste B : \texttt{192.168.2.5} ET \texttt{255.255.255.0} = \textbf{\texttt{192.168.2.0}}.
    \item \textbf{Non, ils ne peuvent pas communiquer directement.} Leurs adresses réseau sont différentes (\texttt{192.168.1.0} $\neq$ \texttt{192.168.2.0}) : ils appartiennent à deux sous-réseaux distincts. Deux machines ne dialoguent directement (sans intermédiaire) que si elles partagent la même adresse réseau.
    \item L'équipement indispensable est un \textbf{routeur}, dont une interface appartient à chaque sous-réseau (par exemple \texttt{192.168.1.254} et \texttt{192.168.2.254}). Sur chaque poste, il faut configurer la \textbf{passerelle par défaut} : \texttt{192.168.1.254} pour le poste A et \texttt{192.168.2.254} pour le poste B. Tout paquet destiné à l'autre sous-réseau sera alors confié au routeur, qui l'acheminera.
\end{enumerate}

\begin{aretenir}[Règle fondamentale]
Deux hôtes communiquent directement si et seulement si (adresse IP ET masque) donne la même adresse réseau des deux côtés. Sinon, il faut un routeur et une passerelle par défaut configurée.
\end{aretenir}
\end{corrige}

\begin{corrige}[Exercice 9 --- Sujet type Bac : Adressage et sous-réseau d'une PME]

\textbf{1. Classe et masque par défaut.} Premier octet $172 \in [128 ; 191]$ : \textbf{classe B}. Masque par défaut : \textbf{/16}, soit \texttt{255.255.0.0}.

\textbf{2. Nouveau masque.} On emprunte 2 bits à la partie hôte : $16 + 2 = 18$ bits de réseau. Nouveau masque : \textbf{/18}, soit \texttt{255.255.192.0} (les 2 bits empruntés sont les deux premiers bits du 3\up{e} octet : $128 + 64 = 192$). Bits réservés au réseau + sous-réseau : \textbf{18}. Bits restants pour les hôtes : $32 - 18 = \textbf{14}$.

\textbf{3. Nombre de sous-réseaux et d'hôtes.}
\[ \text{Sous-réseaux} = 2^2 = 4 \qquad \text{Hôtes par sous-réseau} = 2^{14} - 2 = 16384 - 2 = \textbf{16\,382} \]

\textbf{4. Premier sous-réseau (bits d'emprunt 00).} Le pas (bloc) du 3\up{e} octet vaut $256 - 192 = 64$.
\begin{itemize}
    \item Adresse réseau : \texttt{172.16.0.0}
    \item Première adresse hôte : \texttt{172.16.0.1}
    \item Dernière adresse hôte : \texttt{172.16.63.254}
    \item Broadcast : \texttt{172.16.63.255}
\end{itemize}

\textbf{5. Troisième sous-réseau (bits d'emprunt 10).} Les bits \texttt{10} en tête du 3\up{e} octet donnent $128 + 0 = 128$ : le sous-réseau commence à \texttt{172.16.128.0} et s'étend jusqu'à \texttt{172.16.191.255}.
\begin{itemize}
    \item Adresse réseau : \texttt{172.16.128.0}
    \item Première adresse hôte : \texttt{172.16.128.1}
    \item Dernière adresse hôte : \texttt{172.16.191.254}
    \item Broadcast : \texttt{172.16.191.255}
\end{itemize}

\textbf{6. Vérification pour \texttt{172.16.130.50/18}.} Le masque /18 porte sur le 3\up{e} octet la valeur 192. ET logique sur le 3\up{e} octet :
\begin{align*}
130 &= 1000\,0010_2 \\
192 &= 1100\,0000_2 \\
130 \ \text{ET}\ 192 &= 1000\,0000_2 = 128
\end{align*}
L'adresse réseau obtenue est \texttt{172.16.128.0} : le poste appartient bien au 3\up{e} sous-réseau (Technique). De plus $130 \in [128 ; 191]$, ce qui confirme le résultat.

\textbf{Barème indicatif (sur 10 points) :} classe et masque par défaut : 1 pt ; nouveau masque CIDR + décimal + répartition des bits : 2 pts ; $2^2 = 4$ sous-réseaux et $2^{14} - 2 = 16\,382$ hôtes : 2 pts ; adressage complet du 1\up{er} sous-réseau : 2 pts ; adressage complet du 3\up{e} sous-réseau : 2 pts ; vérification par ET logique : 1 pt.

\begin{attention}[Points de vigilance]
\begin{itemize}
    \item Le pas du sous-réseau se calcule sur l'octet « coupé » : $256 - 192 = 64$, d'où des plages \texttt{0--63}, \texttt{64--127}, \texttt{128--191}, \texttt{192--255} sur le 3\up{e} octet.
    \item Ne pas confondre le 2\up{e} sous-réseau (bits \texttt{01}, réseau \texttt{172.16.64.0}) et le 3\up{e} (bits \texttt{10}, réseau \texttt{172.16.128.0}).
    \item Toujours écrire l'opération ET logique en binaire pour la vérification : c'est la démonstration attendue.
\end{itemize}
\end{attention}
\end{corrige}

\begin{itemize}
    \item le \textbf{routage inter-VLAN} n'est pas activé ou mal configuré (la box/routeur ne sait pas acheminer les paquets entre VLAN 20 et VLAN 10) ;
    \item un \textbf{pare-feu} (sur le poste admin ou sur le routeur) bloque l'ICMP entre les deux VLAN, ou le poste admin est mal configuré (mauvaise passerelle).
\end{itemize}
Commande pour tracer la route :
\begin{lstlisting}[language=bash]
tracert 10.10.10.5
\end{lstlisting}
(sous Linux : \texttt{traceroute 10.10.10.5}). Elle montre à quel routeur le paquet s'arrête, ce qui localise la panne.

\textbf{Barème indicatif (sur 10 points) :} topologie et schéma légendé : 2 pts ; liste du matériel + justification du switch manageable/VLAN : 2 pts ; plan d'adressage complet des deux VLAN : 3 pts ; configuration IP complète du poste : 1,5 pt ; diagnostic + commande \texttt{tracert} : 1,5 pt.

\begin{attention}[Points de vigilance]
\begin{itemize}
    \item La passerelle d'un poste doit toujours appartenir à \emph{son} VLAN : \texttt{10.10.20.254} pour un poste de la salle info, jamais \texttt{10.10.10.254}.
    \item Le ping de la passerelle qui réussit prouve que le problème est \emph{au-delà} du sous-réseau local : raisonner par étapes (local $\rightarrow$ passerelle $\rightarrow$ inter-VLAN) est la démarche attendue.
    \item Citer la limite de \SI{100}{m} du câble cuivre Ethernet si la distance backbone est évoquée.
\end{itemize}
\end{attention}
\end{corrige}

\begin{corrige}[Exercice 11 --- Sujet type Bac : Étude de cas complète -- Protocoles et services]

\textbf{1. Attribution automatique de l'adresse IP.} Protocole : \textbf{DHCP} (\emph{Dynamic Host Configuration Protocol}), ports \textbf{67} (serveur) et \textbf{68} (client), en UDP. Processus DORA en 4 étapes :
\begin{enumerate}
    \item \textbf{D}iscover : le poste diffuse une demande pour trouver un serveur DHCP ;
    \item \textbf{O}ffer : le serveur propose une adresse IP disponible ;
    \item \textbf{R}equest : le poste demande officiellement l'adresse proposée ;
    \item \textbf{A}cknowledge : le serveur confirme l'attribution (bail) avec le masque, la passerelle et les DNS.
\end{enumerate}

\textbf{2. Navigation web.} Protocole : \textbf{HTTP} (port \textbf{80}) ou sa version chiffrée \textbf{HTTPS} (port \textbf{443}). Juste avant, le poste interroge le \textbf{serveur DNS} (port 53) qui traduit le nom de domaine \texttt{www.onbuch.cm} en adresse IP du serveur web : sans cette résolution de nom, le navigateur ne saurait pas à quelle machine envoyer la requête.

\textbf{3. Téléchargement de fichier.} Protocole standard (hors web) : \textbf{FTP} (\emph{File Transfer Protocol}), port \textbf{21} pour le contrôle (port 20 pour les données en mode actif). Aujourd'hui on préfère souvent \textbf{HTTPS} car FTP transmet identifiants et données \emph{en clair}, sans chiffrement, alors que HTTPS chiffre tout l'échange (TLS), ce qui protège les fichiers et l'authentification.

\textbf{4. Réception des mails.} Protocole : \textbf{POP3} (port \textbf{110}, ou \textbf{995} en version chiffrée SSL/TLS). Différence avec \textbf{IMAP} (ports 143/993) : POP3 \emph{télécharge} les messages sur le poste et les supprime par défaut du serveur (consultation hors ligne, mais sur un seul poste) ; IMAP \emph{laisse les messages sur le serveur} et les synchronise, ce qui permet de les consulter depuis plusieurs appareils (ordinateur, téléphone).

\textbf{5. Envoi du mail.} Protocole : \textbf{SMTP} (ports \textbf{25} entre serveurs, \textbf{587} avec authentification, \textbf{465} en SSL). L'authentification \textbf{SMTP AUTH} est obligatoire sur les réseaux publics pour vérifier l'identité de l'expéditeur : sans elle, n'importe qui pourrait utiliser le serveur pour envoyer des spams ou usurper une adresse (relais ouvert).

\textbf{6. Synthèse.}

\begin{center}
\begin{tabular}{|l|l|l|p{4.6cm}|}
\hline
\rowcolor{popblueL}
\textbf{Action} & \textbf{Protocole} & \textbf{Port(s)} & \textbf{Rôle résumé} \\
\hline
Attribution IP auto & DHCP & 67 / 68 (UDP) & Attribution automatique IP, masque, passerelle, DNS \\
\hline
Navigation Web & HTTP / HTTPS & 80 / 443 & Transfert des pages web (chiffré en HTTPS) \\
\hline
Transfert fichier & FTP & 21 (20 données) & Envoi et téléchargement de fichiers \\
\hline
Réception Mail & POP3 & 110 / 995 & Téléchargement des courriels sur le poste \\
\hline
Envoi Mail & SMTP & 25 / 465 / 587 & Acheminement des courriels vers le serveur \\
\hline
\end{tabular}
\end{center}

\textbf{Barème indicatif (sur 10 points) :} DHCP + DORA : 2 pts ; HTTP(S) + rôle du DNS : 2 pts ; FTP + justification HTTPS : 1,5 pt ; POP3 + comparaison IMAP : 1,5 pt ; SMTP + SMTP AUTH : 1,5 pt ; tableau de synthèse complet : 1,5 pt.

\begin{attention}[Points de vigilance]
\begin{itemize}
    \item Ne pas inverser SMTP (envoi) et POP3/IMAP (réception) : c'est l'erreur classique du Bac.
    \item Citer les deux ports quand une version chiffrée existe (110/995, 80/443) et préciser que DHCP fonctionne en \emph{diffusion} (broadcast), car le poste n'a pas encore d'adresse IP.
    \item Pour DORA, les 4 étapes doivent être nommées \emph{dans l'ordre} avec leur signification.
\end{itemize}
\end{attention}
\end{corrige}

\begin{bilan}
\textbf{Définitions clés}
\begin{itemize}
  \item \cle{Réseau informatique} : ensemble d'équipements (ordinateurs, imprimantes\ldots) reliés entre eux afin d'\textbf{échanger des données} et de \textbf{partager des ressources}.
  \item \cle{Topologie physique} : disposition matérielle des câbles et des nœuds (bus, étoile, anneau, maillée). \cle{Topologie logique} : mode de circulation des données (Ethernet, Token Ring).
  \item \cle{Protocole} : ensemble de règles normalisées régissant la communication entre équipements.
  \item \cle{Adresse IP} : identifiant numérique unique d'une machine sur un réseau ; en IPv4, $32$ bits notés en 4 octets (ex. \texttt{192.168.1.10}).
  \item \cle{WIFI} : technologie de réseau local sans fil (norme IEEE 802.11).
\end{itemize}

\textbf{Adressage IPv4 : formules et classes}
\begin{itemize}
  \item Classes : A ($1$ à $126$, masque \texttt{255.0.0.0}), B ($128$ à $191$, masque \texttt{255.255.0.0}), C ($192$ à $223$, masque \texttt{255.255.255.0}).
  \item Adresse réseau : $\text{IP} \;\text{ET logique}\; \text{masque}$ (bit à bit).
  \item Adresse de diffusion (broadcast) : adresse réseau dont tous les bits de la partie machine sont à $1$.
  \item Nombre de machines adressables : $2^{n} - 2$, où $n$ est le nombre de bits de la partie machine.
\end{itemize}

\textbf{Méthodes express}
\begin{itemize}
  \item \emph{Classe d'une IP} : regarder le \textbf{1\textsuperscript{er} octet} et le comparer aux bornes $1$--$126$ / $128$--$191$ / $192$--$223$.
  \item \emph{Configurer 3 postes} : même masque (ex. \texttt{255.255.255.0}), IP distinctes du même réseau (\texttt{192.168.1.11}, \texttt{.12}, \texttt{.13}), câbles vers le switch, puis vérifier avec \texttt{IPCONFIG} (affiche la configuration) et \texttt{PING 192.168.1.12} (teste la liaison).
\end{itemize}
