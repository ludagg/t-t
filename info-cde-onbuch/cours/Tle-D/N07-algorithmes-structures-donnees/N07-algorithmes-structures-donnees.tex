\coursec{Rappels : structure d'un algorithme et instructions de base}

Le proviseur du lycée de Bafoussam dispose d'une liste de 500 élèves avec leurs moyennes, saisies dans le désordre. Il veut savoir si un élève précis figure dans la liste, puis classer les élèves par moyenne décroissante pour le tableau d'honneur. Faire cela à la main prendrait des heures et serait source d'erreurs : il faudrait parcourir 500 lignes une à une, comparer, recopier, sans jamais se tromper. Un ordinateur, lui, fait cela en une fraction de seconde, à condition de lui fournir une \emph{recette} sans ambiguïté : un \cle{algorithme}. Comment organiser les données en mémoire et écrire un algorithme capable de rechercher et de trier automatiquement ces informations ? C'est tout l'objet de cette leçon. Mais avant de manipuler des tableaux de 500 élèves, il faut maîtriser les fondations : la structure d'un algorithme et ses instructions de base. C'est l'objet de cette première section.

\courssub{Qu'est-ce qu'un algorithme ?}

\begin{definition}[Algorithme]
Un \cle{algorithme} est une suite finie et ordonnée d'instructions précises et non ambiguës, permettant de résoudre un problème ou d'obtenir un résultat à partir de données fournies en entrée.
\end{definition}

L'intuition est simple : un algorithme est une recette de cuisine. La recette du ndolé indique les ingrédients (les \emph{données}), les étapes dans l'ordre (les \emph{instructions}) et le plat obtenu (le \emph{résultat}). Comme une recette, un algorithme possède des propriétés essentielles :

\begin{itemize}
\item il est \textbf{fini} : il se termine après un nombre fini d'étapes ;
\item il est \textbf{précis} : chaque instruction a une seule interprétation possible ;
\item il est \textbf{effectif} : chaque instruction peut réellement être exécutée ;
\item il produit un \textbf{résultat} à partir de données d'entrée.
\end{itemize}

\begin{savaistu}[D'où vient le mot « algorithme » ?]
Le mot vient du nom du mathématicien perse Al-Khawarizmi (IX\textsuperscript{e} siècle), dont les ouvrages décrivaient des méthodes de calcul systématiques. Au Cameroun, les algorithmes sont partout : la répartition automatique des élèves par le système OBC (Orientation Baccalauréat Concours), le calcul des soldes Mobile Money, ou encore le classement des candidats aux concours d'entrée dans les grandes écoles.
\end{savaistu}

\courssub{Structure générale d'un algorithme}

Tout algorithme écrit en pseudo-code suit une architecture en trois parties, toujours dans le même ordre :

\begin{enumerate}
\item \textbf{L'en-tête} : le mot-clé \texttt{Algorithme} suivi du nom de l'algorithme ;
\item \textbf{La partie déclarative} : on y annonce toutes les constantes et toutes les variables utilisées, avec leurs types ;
\item \textbf{Le corps} : délimité par les mots-clés \texttt{Début} et \texttt{Fin}, il contient les instructions exécutées dans l'ordre.
\end{enumerate}

\begin{attention}[Erreur fréquente]
Utiliser dans le corps une variable qui n'a pas été déclarée dans la partie déclarative est une erreur. Toute variable ou constante utilisée doit être annoncée \emph{avant} le mot-clé \texttt{Début}. C'est comme inviter un élève à participer à un conseil de classe sans l'avoir inscrit sur la liste : le compilateur (ou le correcteur au Baccalauréat) le refusera.
\end{attention}

\courssub{Constantes et variables}

Pour traiter des informations, l'algorithme les stocke en mémoire dans des « boîtes étiquetées ». Deux cas se présentent : soit la valeur ne change jamais (constante), soit elle peut évoluer (variable).

\begin{definition}[Constante]
Une \cle{constante} est un objet mémoire dont la valeur est fixée une fois pour toutes dans la partie déclarative et ne peut pas être modifiée pendant l'exécution.
\end{definition}

\begin{definition}[Variable]
Une \cle{variable} est un objet mémoire identifié par un nom (l'\emph{identifiant}) et doté d'un \emph{type}, dont la valeur peut changer au cours de l'exécution grâce à l'affectation.
\end{definition}

La syntaxe de déclaration est la suivante :

\begin{lstlisting}
Constante TAUX = 18          // valeur fixe : TVA de 18 %
Constante N = 500            // nombre d'eleves du lycee
Variables i, compteur : Entier
Variables moyenne, somme : Reel
Variable nomEleve : Chaine
Variable admis : Booleen
\end{lstlisting}

\begin{propriete}[Règles sur les identifiants et les types]
Un identifiant commence par une lettre, ne contient ni espace ni caractère spécial, et ne doit pas être un mot réservé (\texttt{Début}, \texttt{Si}, \texttt{Pour}...). Les types usuels sont : \texttt{Entier} (ex. 25), \texttt{Réel} (ex. 13,75), \texttt{Caractère} (ex. 'A'), \texttt{Chaîne} (ex. "Ngo Bell") et \texttt{Booléen} (Vrai ou Faux). Le type détermine les valeurs possibles et les opérations autorisées : on peut additionner deux entiers, mais pas deux booléens.
\end{propriete}

\courssub{Les instructions simples}

Trois instructions suffisent pour faire entrer des données, les transformer et les restituer.

\textbf{1. L'affectation.} C'est l'instruction fondamentale : elle range une valeur dans une variable. On la note avec la flèche $\leftarrow$.

\begin{lstlisting}
somme <- 0              // la variable somme recoit la valeur 0
moyenne <- somme / N    // on calcule puis on range le resultat
i <- i + 1              // la nouvelle valeur de i est l'ancienne + 1
\end{lstlisting}

\begin{propriete}[Sens de l'affectation]
L'instruction \texttt{X $\leftarrow$ expression} s'exécute en deux temps : on \emph{évalue} d'abord l'expression à droite (avec les valeurs actuelles des variables), puis on \emph{range} le résultat dans la variable à gauche. L'ancienne valeur de la variable est définitivement perdue. Ainsi \texttt{i $\leftarrow$ i + 1} n'est pas une équation mathématique impossible, mais un incrément : si \texttt{i} valait 3, il vaut désormais 4.
\end{propriete}

\textbf{2. La lecture (entrée).} \texttt{Lire(X)} permet à l'utilisateur de saisir une valeur au clavier, qui est rangée dans la variable \texttt{X}.

\textbf{3. L'écriture (sortie).} \texttt{Écrire(expression)} affiche une valeur ou un message à l'écran.

\begin{exemplebox}[Un mini-algorithme complet]
\begin{lstlisting}
Algorithme ConversionFCFA
Constante EURO = 655,957        // 1 euro = 655,957 FCFA
Variables montantEuro, montantFCFA : Reel
Debut
    Ecrire("Montant en euros : ")
    Lire(montantEuro)
    montantFCFA <- montantEuro * EURO
    Ecrire("Equivalent en FCFA : ", montantFCFA)
Fin
\end{lstlisting}
Si l'utilisateur saisit 10, l'écran affiche : \texttt{Equivalent en FCFA : 6559,57}.
\end{exemplebox}

\courssub{Rappel des structures alternatives}

Un algorithme ne se contente pas d'exécuter des instructions en ligne droite : il doit parfois \emph{choisir} selon une condition (un élève est-il admis ? sa moyenne est-elle $\geq 10$ ?).

\textbf{La structure Si...Alors...Sinon...FinSi} teste une condition booléenne :

\begin{lstlisting}
Si moyenne >= 10 Alors
    Ecrire("Admis")
Sinon
    Ecrire("Refuse")
FinSi
\end{lstlisting}

La partie \texttt{Sinon} est facultative : si l'on n'a rien à faire quand la condition est fausse, on l'omet.

\textbf{La structure Selon...FinSelon} évite les \texttt{Si} imbriqués quand on teste plusieurs valeurs d'une même variable :

\begin{lstlisting}
Selon mention Faire
    1 : Ecrire("Passable")
    2 : Ecrire("Assez bien")
    3 : Ecrire("Bien")
    4 : Ecrire("Tres bien")
    Sinon Ecrire("Mention inconnue")
FinSelon
\end{lstlisting}

\courssub{Rappel des structures itératives}

Pour traiter 500 élèves, on n'écrit pas 500 fois la même instruction : on utilise une \cle{boucle}, qui répète un bloc d'instructions. Il existe trois formes à connaître parfaitement.

\textbf{1. La boucle Pour...FinPour} : on connaît à l'avance le nombre de répétitions. Un compteur varie automatiquement d'une valeur initiale à une valeur finale.

\begin{lstlisting}
Pour i <- 1 à 500 Faire
    Ecrire("Moyenne de l'eleve ", i, " : ")
    Lire(moy)
FinPour
\end{lstlisting}

\textbf{2. La boucle TantQue...FinTantQue} : on répète \emph{tant qu'une condition est vraie}. Le test se fait \emph{avant} chaque itération : le corps peut ne jamais s'exécuter.

\begin{lstlisting}
TantQue moy <> -1 Faire        // -1 = valeur sentinelle d'arret
    somme <- somme + moy
    Lire(moy)
FinTantQue
\end{lstlisting}

\textbf{3. La boucle Répéter...Jusqu'à} : le corps s'exécute \emph{au moins une fois}, puis on recommence jusqu'à ce que la condition devienne vraie (le test se fait \emph{après}).

\begin{lstlisting}
Repeter
    Ecrire("Saisir une moyenne entre 0 et 20 : ")
    Lire(moy)
Jusqu'a (moy >= 0) Et (moy <= 20)
\end{lstlisting}

\begin{methode}[Bien choisir entre Pour et TantQue]
\begin{enumerate}
\item Pose-toi la question : « le nombre de répétitions est-il connu avant d'entrer dans la boucle ? »
\item Si \textbf{oui} (parcourir 500 élèves, calculer la somme des 100 premiers entiers) : utilise \texttt{Pour}. Le compteur est géré automatiquement, impossible de l'oublier.
\item Si \textbf{non} (lire des moyennes jusqu'à la saisie de $-1$, chercher un élève et s'arrêter dès qu'on l'a trouvé) : utilise \texttt{TantQue} avec une condition d'arrêt claire.
\item Réserve \texttt{Répéter...Jusqu'à} aux cas où le corps doit s'exécuter au moins une fois, typiquement la saisie contrôlée d'une valeur.
\item Vérifie toujours que la condition du \texttt{TantQue} finira par devenir fausse, sinon la boucle est infinie.
\end{enumerate}
\end{methode}

\courssub{Compteur et accumulateur : les deux piliers des boucles}

Deux variables jouent des rôles stéréotypés dans presque toutes les boucles :

\begin{itemize}
\item le \cle{compteur} compte le nombre de passages : initialisé à 0 (ou géré par le \texttt{Pour}), il est incrémenté de 1 à chaque itération (\texttt{cpt $\leftarrow$ cpt + 1}) ;
\item l'\cle{accumulateur} cumule des valeurs : initialisé à 0 pour une somme (à 1 pour un produit), il est enrichi à chaque passage (\texttt{somme $\leftarrow$ somme + moy}).
\end{itemize}

\begin{attention}[Variable non initialisée : l'erreur classique]
Écrire \texttt{somme $\leftarrow$ somme + moy} sans avoir fait \texttt{somme $\leftarrow$ 0} avant la boucle est l'erreur la plus fréquente. La variable contient alors une valeur indéterminée (« résidu mémoire »), et le résultat final est faux et imprévisible. Règle d'or : \textbf{tout compteur et tout accumulateur doit être initialisé AVANT la boucle}, jamais dedans (sinon il serait remis à zéro à chaque tour !).
\end{attention}

\courssub{Exemple chiffré : somme des N premiers entiers}

\begin{exoresolu}[Calcul de $1 + 2 + \dots + N$ avec trace d'exécution]
Énoncé. Écrire un algorithme qui lit un entier $N$ strictement positif et calcule la somme $S = 1 + 2 + \dots + N$. Donner la trace d'exécution pour $N = 4$.
\tcblower
Solution. On utilise un accumulateur \texttt{S} initialisé à 0 et un compteur \texttt{i} géré par la boucle \texttt{Pour}.
\begin{lstlisting}
Algorithme SommePremiersEntiers
Variables N, i, S : Entier
Debut
    Ecrire("Entrer N : ")
    Lire(N)
    S <- 0                  // initialisation de l'accumulateur
    Pour i <- 1 à N Faire
        S <- S + i          // accumulation
    FinPour
    Ecrire("La somme vaut ", S)
Fin
\end{lstlisting}
Trace d'exécution pour $N = 4$ (table d'exécution simplifiée, boucle déroulée) :
\begin{center}
\begin{tabularx}{\linewidth}{|c|l|c|c|X|}
\hline
\rowcolor{popblueL} \textbf{Ligne} & \textbf{Instruction} & \textbf{i} & \textbf{S} & \textbf{Écran} \\
\hline
1 & Lire(N) & -- & -- & Entrer N : 4 \\
\hline
2 & S $\leftarrow$ 0 & -- & 0 & \\
\hline
3 & S $\leftarrow$ S + i & 1 & 1 & \\
\hline
4 & S $\leftarrow$ S + i & 2 & 3 & \\
\hline
5 & S $\leftarrow$ S + i & 3 & 6 & \\
\hline
6 & S $\leftarrow$ S + i & 4 & 10 & \\
\hline
7 & Écrire(S) & 4 & 10 & La somme vaut 10 \\
\hline
\end{tabularx}
\end{center}
Vérification : $1+2+3+4 = 10$, conforme à la formule $\dfrac{N(N+1)}{2} = \dfrac{4 \times 5}{2} = 10$. La trace confirme que l'accumulateur a bien été initialisé à 0 et incrémenté dans le bon ordre.
\end{exoresolu}

\begin{aretenir}[L'essentiel de la section]
Un algorithme comporte trois parties : l'en-tête, la partie déclarative (constantes et variables typées) et le corps entre \texttt{Début} et \texttt{Fin}. Les instructions simples sont la lecture (\texttt{Lire}), l'écriture (\texttt{Écrire}) et l'affectation ($\leftarrow$). Les structures alternatives (\texttt{Si...Alors...Sinon...FinSi}, \texttt{Selon...FinSelon}) permettent les choix ; les structures itératives (\texttt{Pour}, \texttt{TantQue}, \texttt{Répéter...Jusqu'à}) permettent les répétitions. Tout compteur et tout accumulateur doit être initialisé avant la boucle. Ces fondations acquises, nous pouvons maintenant organiser les données en mémoire grâce aux structures de données, objet de la section suivante.
\end{aretenir}

\coursec{Les structures de données}

Dans la section précédente, nous avons revu la structure générale d'un algorithme (en-tête, déclarations, corps délimité par \texttt{Début} et \texttt{Fin}) ainsi que les instructions de base : affectation, lecture, écriture, structures alternatives et itératives. Jusqu'ici, nos algorithmes manipulaient quelques \cle{variables simples} : un âge, une moyenne, un compteur. Cela suffit pour de petits problèmes. Mais imagine maintenant la situation suivante, bien réelle dans nos lycées : le proviseur du lycée de Ngaoundéré veut un programme qui calcule la moyenne de classe de chacun des 60 élèves de la Terminale C, puis affiche le tableau des mérites. Faut-il déclarer 60 variables \texttt{note1}, \texttt{note2}, \ldots, \texttt{note60} ? Et pour les 800 élèves de l'établissement ? Évidemment non. Il faut un moyen d'\emph{organiser} les données : c'est exactement le rôle des \cle{structures de données}, que nous étudions dans cette section.

\courssub{Notion de structure de données}

\begin{definition}[Structure de données]
Une \cle{structure de données} est un \textbf{ensemble organisé de données}, regroupées sous un même nom et accessibles selon des \textbf{règles précises} (mode d'accès, ordre de lecture, opérations autorisées). Le choix d'une structure de données dépend du problème à résoudre : nombre de données, nature des données, opérations fréquentes à effectuer.
\end{definition}

L'idée est toute simple : de la même façon qu'un bibliothécaire ne jette pas les livres en vrac dans une salle mais les range sur des étagères selon un classement, l'informaticien ne laisse pas ses données « en vrac » en mémoire : il les organise pour pouvoir les \emph{retrouver}, les \emph{parcourir} et les \emph{modifier} efficacement. Une structure de données se caractérise donc par deux choses :

\begin{itemize}
\item le \textbf{contenu} : le type des données stockées (entiers, réels, caractères, ou données hétérogènes) ;
\item les \textbf{règles d'accès} : comment atteindre un élément (directement par un indice ? en parcourant du début à la fin ? uniquement le premier arrivé ? uniquement le dernier empilé ?).
\end{itemize}

Le programme officiel distingue trois grandes familles de structures de données :

\begin{enumerate}
\item les \cle{structures finies} : constantes, variables simples et enregistrements ;
\item les \cle{structures indexées} : les tableaux ;
\item les \cle{structures récursives} : les listes, les files et les piles.
\end{enumerate}

\courssub{Les structures finies}

\begin{definition}[Structure finie]
Une \cle{structure finie} est une structure de données dont le \textbf{nombre d'éléments est fixe et connu à l'avance}, et dont chaque élément est accessible \textbf{par son nom}. On y trouve les constantes, les variables simples et les enregistrements.
\end{definition}

\textbf{La constante.} Une \cle{constante} est une donnée dont la valeur est fixée à la déclaration et ne peut \emph{jamais} être modifiée pendant l'exécution. Elle sert à donner un nom à une valeur de référence : le taux de TVA, le nombre de notes d'un bulletin, la valeur de $\pi$.

\textbf{La variable simple.} Une \cle{variable simple} est une zone mémoire nommée, contenant \emph{une seule valeur} d'un type donné (entier, réel, caractère, booléen, chaîne), valeur qui peut changer au cours de l'exécution grâce à l'affectation.

\textbf{L'enregistrement.} Jusqu'ici, tout cela te est familier. La vraie nouveauté est l'\cle{enregistrement}. Observe la fiche d'un élève au secrétariat : elle contient un \emph{nom} (chaîne de caractères), une \emph{date de naissance} (chaîne), une \emph{classe} (chaîne) et une \emph{moyenne} (réel). Ces informations sont de \textbf{types différents}, mais elles décrivent \emph{un même objet} : l'élève. Il serait absurde de les éparpiller dans quatre variables sans lien entre elles.

\begin{definition}[Enregistrement]
Un \cle{enregistrement} est une structure finie qui regroupe sous un même nom plusieurs données de \textbf{types éventuellement différents}, appelées \cle{champs}. Chaque champ est accessible par son nom, selon la syntaxe : \texttt{nomEnregistrement.nomChamp}.
\end{definition}

\begin{propriete}[Déclaration et accès à un enregistrement]
En écriture algorithmique, on déclare d'abord le \emph{type} enregistrement, puis les variables de ce type :
\begin{lstlisting}
Type
    Eleve = Enregistrement
        nom      : Chaine
        classe   : Chaine
        moyenne  : Reel
    FinEnregistrement
Variable
    e : Eleve
\end{lstlisting}
L'accès à un champ se fait avec la notation pointée : \texttt{e.nom} désigne le champ \texttt{nom} de l'enregistrement \texttt{e}. On peut lire, écrire ou affecter chaque champ comme une variable ordinaire : \texttt{e.moyenne $\leftarrow$ 14{,}5}.
\end{propriete}

\courssub{Les structures indexées : les tableaux}

Revenons à nos 60 élèves de Terminale C. Leurs notes d'informatique sont \textbf{toutes de même type} (des réels) et elles sont \textbf{nombreuses}. L'enregistrement ne convient pas : il sert à regrouper des données \emph{différentes} décrivant \emph{un} objet. Ici, c'est l'inverse : des données \emph{identiques en nature}, en \emph{grand nombre}. Il faut une structure indexée : le \cle{tableau}.

\begin{definition}[Structure indexée — tableau]
Une \cle{structure indexée} est une structure de données regroupant un \textbf{nombre fixe d'éléments de même type}, repérés par leur position, appelée \cle{indice}. Le \cle{tableau} est la structure indexée de base : l'accès à un élément est \textbf{direct} grâce à son indice, selon la syntaxe \texttt{nomTableau[i]}.
\end{definition}

On peut se représenter un tableau comme une rangée de casiers numérotés : tous les casiers ont la même taille (même type de contenu), et pour ouvrir un casier, il suffit de connaître son numéro — inutile d'ouvrir les précédents. C'est ce qu'on appelle l'\cle{accès direct} (ou accès indexé).

\begin{propriete}[Déclaration d'un tableau à une dimension]
En écriture algorithmique :
\begin{lstlisting}
Variable
    notes : Tableau[1..60] de Reel
\end{lstlisting}
Cette déclaration réserve 60 cases mémoire contiguës, nommées \texttt{notes[1]}, \texttt{notes[2]}, \ldots, \texttt{notes[60]}. L'élément d'indice $i$ s'utilise comme une variable ordinaire : \texttt{notes[i] $\leftarrow$ 12,5} ou \texttt{Ecrire(notes[i])}.
\end{propriete}

\begin{attention}[Tableau $\neq$ liste : accès direct contre accès séquentiel]
Ne confonds jamais un \textbf{tableau} et une \textbf{liste}. Dans un tableau, l'accès est \emph{direct} : \texttt{T[37]} donne immédiatement le 37\textsuperscript{ème} élément, sans toucher aux 36 premiers. Dans une liste, l'accès est \emph{séquentiel} : pour atteindre le 37\textsuperscript{ème} élément, il faut obligatoirement partir du premier et suivre les chaînons un à un. Conséquence pratique : le tableau est idéal quand on connaît la position des données ; la liste est souple quand le nombre de données varie constamment, mais la recherche y est plus lente.
\end{attention}

\textbf{Mention du tableau à deux dimensions.} Pour représenter les notes de \emph{plusieurs} élèves dans \emph{plusieurs} matières, on utilise un tableau à deux dimensions, analogue à une feuille de tableur : \texttt{bulletin : Tableau[1..60, 1..8] de Reel}. L'élément \texttt{bulletin[i, j]} est alors la note de l'élève $i$ dans la matière $j$. Nous y reviendrons dans les sections suivantes ; retiens simplement qu'il faut \emph{deux indices} : une ligne et une colonne.

\courssub{Les structures récursives : listes, files et piles}

Certaines structures ne sont pas de taille fixe : elles \emph{grandissent} et \emph{rétrécissent} pendant l'exécution, chaque élément « pointant » vers le suivant. On les appelle \cle{structures récursives}, car chaque élément contient (ou référence) un élément de même nature que lui : une liste, c'est un premier élément suivi\ldots{} d'une liste ! Au programme de Terminale, on en attend une \emph{présentation intuitive} : comprendre le principe et les règles d'accès, sans entrer dans la programmation des pointeurs.

\begin{definition}[Structure récursive]
Une \cle{structure récursive} est une structure de données de \textbf{taille variable}, formée d'éléments (appelés \emph{maillons} ou \emph{nœuds}) dont chacun contient une donnée et une référence vers l'élément suivant. L'accès y est \textbf{séquentiel} : on parcourt la chaîne maillon par maillon. Les trois structures récursives classiques sont la \textbf{liste}, la \textbf{file} et la \textbf{pile}.
\end{definition}

\textbf{La liste.} Une \cle{liste} est une suite chaînée d'éléments : chaque maillon connaît le suivant. On peut insérer ou supprimer un élément à n'importe quelle position sans déplacer les autres — contrairement au tableau, où supprimer la case 3 oblige à « tasser » toutes les suivantes. En contrepartie, pour atteindre un élément, il faut parcourir la liste depuis le début.

\textbf{La pile (LIFO).} Une \cle{pile} fonctionne comme une pile d'assiettes au restaurant : on \emph{empile} une assiette \emph{au sommet}, et on \emph{dépile} toujours l'assiette \emph{du sommet}. La règle est \cle{LIFO} (\emph{Last In, First Out}) : le \textbf{dernier entré est le premier sorti}. Deux opérations seulement sont permises : \texttt{empiler} (ajouter au sommet) et \texttt{depiler} (retirer le sommet). C'est le mécanisme utilisé par le bouton « Annuler » (Ctrl+Z) de ton traitement de texte : la dernière action effectuée est la première annulée.

\textbf{La file (FIFO).} Une \cle{file} fonctionne comme la file d'attente devant le guichet d'une agence Express Union : on arrive \emph{par l'arrière}, on est servi \emph{à l'avant}. La règle est \cle{FIFO} (\emph{First In, First Out}) : le \textbf{premier entré est le premier sorti}. Les deux opérations sont : \texttt{enfiler} (ajouter à l'arrière) et \texttt{defiler} (retirer à l'avant).

\begin{savaistu}[La file d'attente : une structure FIFO de la vie quotidienne]
La file d'attente à la banque, à l'hôpital ou devant le guichet de la CAMTEL est \emph{exactement} une structure FIFO : le premier client arrivé est le premier servi, et tout nouveau venu se place à l'arrière. Les informaticiens s'en inspirent partout : les documents envoyés à l'imprimante du cybercafé sont mis en file et imprimés dans l'ordre d'arrivée ; les appels vers le service client d'un opérateur mobile sont placés dans une file (« vous êtes le 3\textsuperscript{ème} appel en attente\ldots »). À l'inverse, l'historique de navigation de ton navigateur (bouton « Précédent ») est une \emph{pile} LIFO : la dernière page visitée est la première à laquelle on revient.
\end{savaistu}

\courssub{Comment choisir la bonne structure de données ?}

Face à un problème concret, le choix de la structure est une étape décisive de la résolution : un mauvais choix rend l'algorithme compliqué, lent, voire faux. Trois questions guident ce choix.

\begin{methode}[Choisir une structure de données adaptée au problème]
\begin{enumerate}
\item \textbf{Les données sont-elles homogènes (même type) ou hétérogènes (types différents) ?}
\begin{itemize}
\item Hétérogènes et décrivant un même objet (nom, âge, moyenne d'un élève) $\rightarrow$ \textbf{enregistrement}.
\item Homogènes et nombreuses (les 60 notes d'une classe) $\rightarrow$ \textbf{tableau}.
\end{itemize}
\item \textbf{Le nombre de données est-il fixe et connu à l'avance ?}
\begin{itemize}
\item Oui $\rightarrow$ structure finie ou tableau (taille fixée à la déclaration).
\item Non, il varie pendant l'exécution $\rightarrow$ structure récursive (liste, file, pile).
\end{itemize}
\item \textbf{Quel mode d'accès le problème impose-t-il ?}
\begin{itemize}
\item Accès direct à l'élément de rang $i$ $\rightarrow$ \textbf{tableau}.
\item Traitement dans l'ordre d'arrivée (premier arrivé, premier servi) $\rightarrow$ \textbf{file} (FIFO).
\item Traitement en ordre inverse (dernier arrivé, premier servi : annulations, retour en arrière) $\rightarrow$ \textbf{pile} (LIFO).
\item Insertions et suppressions fréquentes en plein milieu $\rightarrow$ \textbf{liste}.
\end{itemize}
\end{enumerate}
\end{methode}

\begin{tabularx}{\linewidth}{|l|X|X|X|}
\hline
\rowcolor{popblueL}
\textbf{Structure} & \textbf{Type des éléments} & \textbf{Taille} & \textbf{Mode d'accès} \\
\hline
Variable simple & Une seule valeur & Fixe (1) & Par le nom \\
\hline
Enregistrement & Hétérogènes (champs) & Fixe & Par le nom du champ \\
\hline

\hline

\hline

\hline
\end{tabularx}
\end{center}

\begin{exemplebox}[Modéliser les données d'un élève et d'une classe]
Le secrétariat du lycée veut informatiser ses bulletins. Deux besoins distincts apparaissent :
\begin{itemize}
\item la \textbf{fiche d'un élève} (nom, classe, moyenne) : données de types différents décrivant un seul objet $\rightarrow$ un \textbf{enregistrement} ;
\item les \textbf{6 notes d'informatique} d'un élève : données de même type, en nombre fixe $\rightarrow$ un \textbf{tableau}.
\end{itemize}
\begin{lstlisting}
Type
    Eleve = Enregistrement
        nom     : Chaine
        classe  : Chaine
        moyenne : Reel
    FinEnregistrement
Variable
    e     : Eleve                    // la fiche d'un élève
    notes : Tableau[1..6] de Reel    // ses 6 notes d'informatique
Debut
    e.nom ← "MBALLA Amina"
    e.classe ← "Tle C"
    notes[1] ← 15,5                  // accès direct par l'indice
    e.moyenne ← notes[1]             // un champ s'utilise comme une variable
    Ecrire(e.nom, " a obtenu ", notes[1], " au devoir 1")
Fin
\end{lstlisting}
À l'écran : \texttt{MBALLA Amina a obtenu 15,5 au devoir 1}. Remarque la différence d'accès : \texttt{e.nom} utilise le \emph{nom du champ} (structure finie), \texttt{notes[1]} utilise l'\emph{indice} (structure indexée).
\end{exemplebox}

\begin{exoresolu}[Quelle structure pour quel problème ?]
Énoncé. Pour chacune des situations suivantes, indique la structure de données la plus adaptée et justifie ton choix en une phrase :
\begin{enumerate}
\item mémoriser les températures relevées chaque jour du mois de mars à Yaoundé ;
\item mémoriser la fiche d'un livre de la bibliothèque scolaire (titre, auteur, année, cote) ;
\item gérer les élèves qui se présentent au comptoir de la cantine ;
\item gérer l'historique des pages visitées dans un navigateur (bouton « Précédent ») ;
\item mémoriser les notes des 8 matières pour les 60 élèves de la classe.
\end{enumerate}
\tcblower
Solution détaillée.
\begin{enumerate}
\item \textbf{Tableau} \texttt{temp : Tableau[1..31] de Reel} : 31 données homogènes, en nombre fixe et connu ; l'indice correspond naturellement au jour du mois (accès direct : \texttt{temp[15]} = température du 15 mars).
\item \textbf{Enregistrement} : les quatre informations sont de types différents (chaînes et entier) et décrivent un même objet, le livre ; chaque champ sera accessible par son nom (\texttt{livre.titre}).
\item \textbf{File (FIFO)} : à la cantine, le premier élève arrivé doit être le premier servi ; tout nouvel arrivant se place à l'arrière. C'est la discipline « premier entré, premier sorti ».
\item \textbf{Pile (LIFO)} : le bouton « Précédent » ramène d'abord à la \emph{dernière} page visitée ; c'est la discipline « dernier entré, premier sorti ».
\item \textbf{Tableau à deux dimensions} \texttt{notes : Tableau[1..60, 1..8] de Reel} : données homogènes en grand nombre, repérées par deux indices (l'élève $i$ et la matière $j$), comme une feuille de tableur.
\end{enumerate}
\end{exoresolu}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Une \cle{structure de données} est un ensemble organisé de données accessibles selon des règles précises.
\item \textbf{Structures finies} (nombre fixe, accès par nom) : constantes, variables simples, \textbf{enregistrements} (champs de types différents, accès par \texttt{enregistrement.champ}).
\item \textbf{Structures indexées} : les \textbf{tableaux}, éléments de même type en nombre fixe, accès \emph{direct} par indice \texttt{T[i]} ; le tableau à deux dimensions utilise deux indices \texttt{T[i, j]}.
\item \textbf{Structures récursives} (taille variable, accès séquentiel) : la \textbf{liste} (chaînage de maillons), la \textbf{file} (FIFO : premier entré, premier sorti) et la \textbf{pile} (LIFO : dernier entré, premier sorti).
\item Le choix d'une structure se fait en trois questions : homogène ou hétérogène ? taille fixe ou variable ? accès direct, ordre d'arrivée ou ordre inverse ?
\end{itemize}
\end{aretenir}

Maintenant que le paysage des structures de données est clair, la section suivante se concentrera sur les deux structures au cœur du programme de Terminale : le \emph{tableau} et l'\emph{enregistrement}, que nous apprendrons à déclarer, remplir et parcourir dans des algorithmes complets.

\coursec{Tableaux et enregistrements}

Dans la section précédente, nous avons class\'e les structures de donn\'ees en trois grandes familles~: les structures finies (constantes, variables, enregistrements), les structures index\'ees (tableaux) et les structures r\'ecursives (listes, piles, files). Nous allons maintenant \'etudier en profondeur les deux structures que le programme de Terminale met r\'eellement en \oe uvre dans les algorithmes~: le \cle{tableau} et l'\cle{enregistrement}. Ce sont elles qui permettent de manipuler, dans un algorithme, des ensembles de donn\'ees de la vie r\'eelle~: les 10 notes d'un \'el\`eve, la liste des 45 \'el\`eves d'une classe de Terminale C du lyc\'ee de Nkongsamba, le stock d'une boutique.

\courssub{Le tableau~: une variable \`a plusieurs cases}

\textbf{Le probl\`eme \`a r\'esoudre.} Imaginons que le professeur d'informatique veuille \'ecrire un algorithme qui calcule la moyenne des 10 notes d'informatique d'un \'el\`eve. Avec les connaissances des sections pr\'ec\'edentes, il faudrait d\'eclarer dix variables~: \texttt{n1}, \texttt{n2}, \ldots, \texttt{n10}, \'ecrire dix instructions \texttt{Lire}, puis une addition \`a dix termes. Et si l'on passait \`a 60 notes~? \`A 500 \'el\`eves~? Cette approche est impraticable. Il faut une structure capable de regrouper \emph{plusieurs valeurs de m\^eme type sous un seul nom}, chaque valeur \'etant rep\'er\'ee par sa position.

\begin{definition}[Tableau]
Un \cle{tableau} est une structure de donn\'ees index\'ee qui regroupe, sous un m\^eme nom, un nombre \textbf{fixe} d'\'el\'ements \textbf{de m\^eme type}, chaque \'el\'ement \'etant rep\'er\'e par un num\'ero de position appel\'e \cle{indice}. Le nombre d'\'el\'ements du tableau est sa \cle{taille} (ou dimension), fix\'ee \`a la d\'eclaration et non modifiable ensuite.
\end{definition}

\begin{propriete}[D\'eclaration d'un tableau en \'ecriture algorithmique]
La d\'eclaration d'un tableau se fait dans la partie d\'eclarative de l'algorithme, avec la syntaxe~:
\begin{lstlisting}
Tableau T[1..N] de type
\end{lstlisting}
o\`u \texttt{T} est le nom du tableau, \texttt{N} sa taille (constante enti\`ere) et \texttt{type} le type commun de tous les \'el\'ements (entier, r\'eel, cha\^ine, caract\`ere, bool\'een). L'intervalle \texttt{1..N} signifie que les indices valides vont de 1 \`a N inclus. Ainsi, pour les 10 notes de notre \'el\`eve~:
\begin{lstlisting}
Constante N = 10
Tableau Notes[1..N] de reel
\end{lstlisting}
\end{propriete}

\begin{attention}[Convention sur le premier indice]
En \'ecriture algorithmique au lyc\'ee, on fait d\'emarrer les indices \`a \textbf{1}~: le premier \'el\'ement est \texttt{T[1]} et le dernier \texttt{T[N]}. Attention~: en langage C, que vous \'etudierez plus tard, le premier indice est \textbf{0} et le dernier \texttt{N-1}. Retenez la convention de chaque langage et ne les m\'elangez jamais.
\end{attention}

\textbf{Acc\`es \`a un \'el\'ement.} Toute la puissance du tableau vient de l'acc\`es direct \`a chaque case gr\^ace \`a son indice, entre crochets.

\begin{propriete}[Acc\`es \`a l'\'el\'ement d'indice i]
Si \texttt{T} est un tableau et \texttt{i} un entier tel que $1 \leq i \leq N$, alors \texttt{T[i]} d\'esigne l'\'el\'ement d'indice \texttt{i} et s'utilise exactement comme une variable ordinaire~:
\begin{itemize}
\item en \textbf{\'ecriture} (affectation)~: \texttt{T[i] $\leftarrow$ valeur}~;
\item en \textbf{lecture} (dans une expression ou un affichage)~: \texttt{Ecrire(T[i])} ou \texttt{S $\leftarrow$ S + T[i]}.
\end{itemize}
L'indice peut \^etre une constante (\texttt{T[4]}), une variable (\texttt{T[i]}) ou toute expression enti\`ere (\texttt{T[i+1]}), ce qui permet de parcourir le tableau avec une boucle.
\end{propriete}

\begin{attention}[D\'epassement d'indice~: l'erreur classique]
Acc\'eder \`a \texttt{T[0]} ou \`a \texttt{T[N+1]} est une \textbf{erreur}~: ces cases n'existent pas. En algorithmique, c'est une faute de raisonnement~; en langage C, le programme lit ou \'ecrit dans une zone m\'emoire qui ne lui appartient pas, avec des r\'esultats impr\'evisibles (valeurs absurdes, plantage). Avant tout acc\`es \texttt{T[i]}, v\'erifie mentalement que $1 \leq i \leq N$. Pi\`ege typique~: \'ecrire \texttt{Pour i de 0 a N} au lieu de \texttt{Pour i de 1 a N}.
\end{attention}

\courssub{Remplir et parcourir un tableau}

\textbf{Remplissage par une boucle Pour.} Pour saisir les N \'el\'ements d'un tableau, on ne r\'ep\`ete pas N fois l'instruction \texttt{Lire}~: on utilise une boucle \texttt{Pour} dont le compteur \texttt{i} sert d'indice.

\begin{lstlisting}
Pour i de 1 a N Faire
    Ecrire("Entrez l'element ", i, " : ")
    Lire(T[i])
FinPour
\end{lstlisting}

Au premier tour, \texttt{i} vaut 1 et l'utilisateur remplit \texttt{T[1]}~; au deuxi\`eme tour, \texttt{T[2]}, et ainsi de suite jusqu'\`a \texttt{T[N]}. Une seule instruction \texttt{Lire} suffit donc, quelle que soit la taille du tableau.

\begin{methode}[Sch\'ema type du parcours complet d'un tableau]
Tout traitement qui doit s'appliquer \`a \textbf{tous} les \'el\'ements d'un tableau \texttt{T[1..N]} suit le m\^eme gabarit, \`a apprendre par c\oe ur~:
\begin{enumerate}
\item \textbf{Initialiser} les variables de travail avant la boucle (somme \`a 0, maximum \`a \texttt{T[1]}, compteur \`a 0)~;
\item \textbf{Parcourir}~: \texttt{Pour i de 1 a N Faire}~;
\item \textbf{Traiter} l'\'el\'ement courant \texttt{T[i]} dans le corps de la boucle (l'afficher, l'additionner, le comparer, le compter)~;
\item \textbf{Exploiter} le r\'esultat apr\`es la boucle (afficher la somme, calculer la moyenne, etc.).
\end{enumerate}
\end{methode}

\textbf{Affichage de tous les \'el\'ements.} Application imm\'ediate du sch\'ema~:

\begin{lstlisting}
Ecrire("Contenu du tableau :")
Pour i de 1 a N Faire
    Ecrire("T[", i, "] = ", T[i])
FinPour
\end{lstlisting}

\textbf{Parcours avec traitement.} Voici les quatre traitements classiques exigibles au Baccalaur\'eat, tous fond\'es sur le m\^eme gabarit.

\begin{lstlisting}
// Somme des elements
S <- 0
Pour i de 1 a N Faire
    S <- S + T[i]
FinPour

// Moyenne (N > 0)
Moy <- S / N

// Maximum
Max <- T[1]
Pour i de 2 a N Faire
    Si T[i] > Max Alors
        Max <- T[i]
    FinSi
FinPour

// Comptage : nombre d'elements superieurs a 10
Cpt <- 0
Pour i de 1 a N Faire
    Si T[i] > 10 Alors
        Cpt <- Cpt + 1
    FinSi
FinPour
\end{lstlisting}

Notez bien les initialisations~: la somme et le compteur partent de 0~; le maximum part de \texttt{T[1]} (le premier \'el\'ement r\'eel), et non de 0 --- sinon un tableau ne contenant que des valeurs n\'egatives donnerait un maximum faux.

\begin{exoresolu}[Moyenne de 10 notes]
\'Enonc\'e. \'Ecrire un algorithme qui demande \`a l'utilisateur les 10 notes d'un \'el\`eve (sur 20), les stocke dans un tableau, puis calcule et affiche leur somme et leur moyenne.
\tcblower
Solution d\'etaill\'ee. On applique le sch\'ema type~: d\'eclaration du tableau, boucle de remplissage, puis boucle de cumul.
\begin{lstlisting}
Algorithme MoyenneNotes
Constante N = 10
Variable
    Tableau Notes[1..N] de reel
    i : entier
    S, Moy : reel
Debut
    // 1. Remplissage du tableau
    Pour i de 1 a N Faire
        Ecrire("Note numero ", i, " : ")
        Lire(Notes[i])
    FinPour
    // 2. Calcul de la somme
    S <- 0
    Pour i de 1 a N Faire
        S <- S + Notes[i]
    FinPour
    // 3. Calcul et affichage de la moyenne
    Moy <- S / N
    Ecrire("Somme = ", S)
    Ecrire("Moyenne = ", Moy)
Fin
\end{lstlisting}
V\'erification mentale~: si toutes les notes valent 12, alors $S = 10 \times 12 = 120$ et $\text{Moy} = 120/10 = 12$~: le r\'esultat est coh\'erent.
\end{exoresolu}

\courssub{L'enregistrement~: regrouper des informations de types diff\'erents}

\textbf{Le probl\`eme \`a r\'esoudre.} Le tableau impose que tous ses \'el\'ements soient \emph{de m\^eme type}. Or, pour d\'ecrire un \'el\`eve de Terminale, on a besoin simultan\'ement de son \emph{nom} (cha\^ine), de son \emph{\^age} (entier) et de sa \emph{moyenne} (r\'eel). Trois variables s\'epar\'ees \texttt{nom}, \texttt{age}, \texttt{moyenne} ne disent pas qu'elles d\'ecrivent \emph{le m\^eme} \'el\`eve. Il faut une structure qui regroupe des donn\'ees \textbf{de types diff\'erents} en un seul objet.

\begin{definition}[Enregistrement et champ]
Un \cle{enregistrement} est une structure de donn\'ees finie qui regroupe sous un m\^eme nom plusieurs donn\'ees appel\'ees \cle{champs}, pouvant \^etre de types diff\'erents. Chaque champ poss\`ede un nom et un type. L'enregistrement est d\'efini comme un \textbf{nouveau type}, puis on d\'eclare des variables de ce type.
\end{definition}

\begin{propriete}[D\'eclaration d'un type enregistrement et acc\`es aux champs]
La d\'efinition du type se fait dans la partie d\'eclarative, avant les variables~:
\begin{lstlisting}
Type Etudiant = Enregistrement
    nom     : chaine
    age     : entier
    moyenne : reel
FinEnregistrement
\end{lstlisting}
On d\'eclare ensuite une variable de ce type~: \texttt{E : Etudiant}. L'acc\`es \`a chaque champ se fait par la \textbf{notation point\'ee}~: \texttt{E.nom}, \texttt{E.age}, \texttt{E.moyenne}. Chaque champ s'utilise comme une variable de son type, en lecture comme en \'ecriture~: \texttt{E.age $\leftarrow$ 17}, \texttt{Lire(E.nom)}, \texttt{Ecrire(E.moyenne)}.
\end{propriete}

\begin{exemplebox}[Un \'el\`eve de Terminale en algorithme]
Algorithme complet qui saisit puis affiche la fiche d'un \'el\`eve~:
\begin{lstlisting}
Algorithme FicheEleve
Type Etudiant = Enregistrement
    nom     : chaine
    age     : entier
    moyenne : reel
FinEnregistrement
Variable
    E : Etudiant
Debut
    Ecrire("Nom de l'eleve : ")
    Lire(E.nom)
    Ecrire("Age : ")
    Lire(E.age)
    Ecrire("Moyenne generale : ")
    Lire(E.moyenne)
    // Affichage de la fiche
    Ecrire("--- Fiche de l'eleve ---")
    Ecrire("Nom     : ", E.nom)
    Ecrire("Age     : ", E.age, " ans")
    Ecrire("Moyenne : ", E.moyenne, " / 20")
    Si E.moyenne >= 10 Alors
        Ecrire(E.nom, " est admis(e).")
    Sinon
        Ecrire(E.nom, " doit redoubler d'efforts.")
    FinSi
Fin
\end{lstlisting}
Remarque~: \texttt{E.moyenne >= 10} montre qu'un champ s'utilise dans n'importe quelle expression, comme une variable ordinaire.
\end{exemplebox}

\begin{attention}[Ne pas confondre le type et la variable]
\texttt{Etudiant} est un \textbf{type} (un moule)~: on ne peut pas \'ecrire \texttt{Etudiant.nom}. C'est la \textbf{variable} \texttt{E}, d\'eclar\'ee de type \texttt{Etudiant}, qui poss\`ede des champs~: on \'ecrit \texttt{E.nom}. Autre pi\`ege~: oublier le point et \'ecrire \texttt{Enom} --- l'algorithme chercherait alors une variable nomm\'ee \texttt{Enom}, qui n'existe pas.
\end{attention}

\begin{savaistu}[Hors-programme strict, mais utile pour le Bac~: le tableau d'enregistrements]
Pour g\'erer \emph{toute une classe}, on combine les deux structures~: un \textbf{tableau d'enregistrements}. On d\'eclare \texttt{Tableau Classe[1..45] de Etudiant}~: chaque case du tableau est un enregistrement complet. L'\'el\`eve d'indice \texttt{i} s'appelle alors \texttt{Classe[i].nom} et sa moyenne \texttt{Classe[i].moyenne}. C'est exactement le principe des logiciels de gestion des notes utilis\'es dans les lyc\'ees camerounais~: un tableau de lignes, chaque ligne \'etant une fiche \'el\`eve. Cette combinaison n'est pas exigible en \'ecriture algorithmique, mais la comprendre \'eclaire les exercices de synth\`ese.
\end{savaistu}

\begin{exercice}[Stock d'une boutique]
Une boutique de Douala vend 8 articles. \'Ecrire un algorithme qui~: (a) saisit dans un tableau les quantit\'es en stock des 8 articles~; (b) affiche les quantit\'es sup\'erieures ou \'egales \`a 20~; (c) affiche la quantit\'e totale en stock et le nombre d'articles en rupture (quantit\'e nulle).
\end{exercice}

\begin{corrige}[Exercice~: stock d'une boutique]
\begin{lstlisting}
Algorithme StockBoutique
Constante N = 8
Variable
    Tableau Q[1..N] de entier
    i, Total, Ruptures : entier
Debut
    Pour i de 1 a N Faire
        Ecrire("Quantite de l'article ", i, " : ")
        Lire(Q[i])
    FinPour
    Ecrire("Articles bien approvisionnes :")
    Pour i de 1 a N Faire
        Si Q[i] >= 20 Alors
            Ecrire("Article ", i, " : ", Q[i])
        FinSi
    FinPour
    Total <- 0
    Ruptures <- 0
    Pour i de 1 a N Faire
        Total <- Total + Q[i]
        Si Q[i] = 0 Alors
            Ruptures <- Ruptures + 1
        FinSi
    FinPour
    Ecrire("Stock total : ", Total)
    Ecrire("Articles en rupture : ", Ruptures)
Fin
\end{lstlisting}
On remarque que les deux derniers traitements (somme et comptage) sont fusionn\'es dans une seule boucle~: c'est plus efficace, et cela reste le sch\'ema type du parcours complet.
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Un \cle{tableau} \texttt{T[1..N]} regroupe N valeurs de m\^eme type~; \texttt{T[i]} acc\`ede directement \`a l'\'el\'ement d'indice i, en lecture comme en \'ecriture, avec $1 \leq i \leq N$.
\item Tout parcours suit le m\^eme sch\'ema~: initialisation, boucle \texttt{Pour i de 1 a N}, traitement de \texttt{T[i]}, exploitation du r\'esultat.
\item Un \cle{enregistrement} regroupe des champs de types diff\'erents~; on d\'efinit le type, on d\'eclare une variable, et on acc\`ede aux champs par la notation point\'ee \texttt{E.champ}.
\item Erreur fatale \`a \'eviter~: le d\'epassement d'indice (\texttt{T[0]}, \texttt{T[N+1]}).
\end{itemize}
\end{aretenir}

Maintenant que nous savons stocker et parcourir des donn\'ees, la section suivante r\'epondra \`a une question naturelle~: comment \emph{retrouver} une valeur pr\'ecise dans un tableau~? Ce sera la recherche s\'equentielle.

\coursec{Recherche séquentielle dans un tableau}

Nous savons désormais déclarer un tableau, le remplir et l'afficher élément par élément. Mais une question fondamentale se pose dès que l'on manipule des données : \textbf{comment retrouver une information précise au milieu d'une collection ?} Imagine un fichier d'élèves dans un établissement comme le Lycée de Nkolbisson : on a stocké les noms dans un tableau. Comment savoir si \emph{Kamga} est inscrit, et à quelle ligne il se trouve, sans lire toute la liste manuellement ? C'est exactement le rôle de la \textbf{recherche séquentielle}, l'algorithme de base pour interroger un tableau non trié.

\courssub{Problématique et principe de la recherche séquentielle}

\begin{definition}[Recherche séquentielle]
Soit un tableau \texttt{T} de taille \texttt{N} (indices de 1 à N) et une valeur \texttt{x} à rechercher. La \cle{recherche séquentielle} consiste à parcourir le tableau du premier au dernier élément, en comparant chaque valeur \texttt{T[i]} à \texttt{x}, jusqu'à trouver une correspondance ou épuiser le tableau.
\end{definition}

\begin{propriete}[Principe du témoin (drapeau)]
Pour mémoriser le résultat de la recherche (trouvé ou non), on utilise une variable booléenne, appelée \cle{témoin} ou \cle{drapeau} (souvent nommée \texttt{trouve} ou \texttt{flag}).
\begin{itemize}
    \item \textbf{Initialisation :} \texttt{trouve $\leftarrow$ FAUX} avant la boucle.
    \item \textbf{Mise à jour :} dès qu'on découvre \texttt{T[i] = x}, on affecte \texttt{trouve $\leftarrow$ VRAI}.
    \item \textbf{Condition d'arrêt anticipé :} on n'a plus besoin de continuer la boucle si \texttt{trouve = VRAI}.
\end{itemize}
\end{propriete}

\courssub{Structure de la boucle : arrêt anticipé}

Contrairement à un simple parcours complet (affichage, somme), la recherche peut s'arrêter \emph{avant} la fin du tableau. La structure \texttt{TantQue} est idéale car elle permet de tester une condition composée à chaque itération.

\begin{propriete}[Condition de continuation de la boucle]
La boucle se poursuit \textbf{tant que} :
\begin{enumerate}
    \item On n'a pas dépassé la borne supérieure : \texttt{i $\le$ N}
    \item \textbf{ET} on n'a pas encore trouvé la valeur : \texttt{non trouve} (ou \texttt{trouve = FAUX})
\end{enumerate}
Soit : \texttt{TantQue (i $\le$ N) ET (NON trouve) Faire ... FinTantQue}
\end{propriete}

\begin{attention}[Pièges classiques : initialisation et arrêt]
\begin{itemize}
    \item \textbf{Oublier d'initialiser \texttt{trouve} à FAUX :} si la variable contient une valeur aléatoire (résidu mémoire), l'algorithme peut croire avoir trouvé la valeur avant même de commencer.
    \item \textbf{Utiliser \texttt{Si} au lieu de \texttt{TantQue} pour l'arrêt :} écrire \texttt{Si T[i] = x Alors trouve $\leftarrow$ VRAI FinSi} \emph{à l'intérieur} d'une boucle \texttt{Pour i $\leftarrow$ 1 \`a N} fonctionne, mais parcourt \textbf{tout} le tableau même après avoir trouvé. C'est correct mais inefficace. La boucle \texttt{TantQue} avec condition composée est la forme canonique enseignée au programme.
    \item \textbf{Indice de début :} au Cameroun, dans l'écriture algorithmique officielle (MINESEC), les tableaux sont généralement indexés à partir de \textbf{1}. Vérifie toujours l'énoncé : \texttt{T[1..N]} ou \texttt{T[0..N-1]}.
\end{itemize}
\end{attention}

\courssub{Algorithme complet : RechercheSéquentielle}

Voici l'écriture formelle, rigoureuse et commentée, conforme aux attendus du Baccalauréat.

\begin{lstlisting}[language=, caption={Algorithme : Recherche séquentielle avec témoin}, label={algo:rech_seq}]
Algorithme RechercheSequentielle
// But : Rechercher une valeur x dans un tableau T[1..N]
//       et afficher sa position si trouvée, sinon signaler l'absence.

Variable
    T : Tableau[1..N] d'entiers   // N est une constante connue
    x, i : Entier
    trouve : Booleen
    pos : Entier                  // Pour mémoriser la position trouvée

Début
    // 1. Saisie des données (tableau et valeur cherchée)
    //    (On suppose T déjà rempli ici, ou on ajoute une boucle de remplissage)
    Afficher("Entrez la valeur à rechercher : ")
    Saisir(x)

    // 2. Initialisation du témoin et de l'indice
    trouve <- FAUX
    i <- 1
    pos <- 0                      // 0 = position invalide (non trouvée)

    // 3. Parcours séquentiel avec arrêt anticipé
    TantQue (i <= N) ET (NON trouve) Faire
        Si T[i] = x Alors
            trouve <- VRAI
            pos <- i              // On mémorise l'indice où x a été trouvé
        Sinon
            i <- i + 1            // On passe à l'élément suivant
        FinSi
    FinTantQue

    // 4. Conclusion / Affichage du résultat
    Si trouve Alors
        Afficher("Valeur ", x, " trouvée à la position ", pos)
    Sinon
        Afficher("Valeur ", x, " absente du tableau")
    FinSi
Fin
\end{lstlisting}

\begin{aretenir}[Points clés de l'algorithme]
\begin{itemize}
    \item La variable \texttt{pos} est \textbf{optionnelle} si on veut seulement savoir « trouvé/non trouvé », mais \textbf{indispensable} si l'énoncé demande « à quelle position ».
    \item L'incrémentation \texttt{i $\leftarrow$ i + 1} se fait \textbf{uniquement dans le \texttt{Sinon}}. Si on l'avait mise après le \texttt{FinSi} (hors alternative), on risquerait d'incrémenter \texttt{i} \emph{après} avoir trouvé, perdant ainsi la position exacte (ou accédant hors limites si \texttt{i=N}).
    \item La condition \texttt{(i <= N) ET (NON trouve)} garantit qu'on ne sort jamais des bornes du tableau (\texttt{T[N+1]} n'est jamais accédé).
\end{itemize}
\end{aretenir}

\courssub{Cas particuliers et analyse du coût}

\begin{exemplebox}[Cas particuliers : trace d'exécution (table d'exécution)]
Recherchons \texttt{x = 17} dans \texttt{T = [5, 12, 17, 9, 21]} (\texttt{N=5}).

\begin{center}
\begin{tabularx}{\linewidth}{|c|c|c|c|c|X|}
\hline
\textbf{Itération} & \texttt{i} & \texttt{T[i]} & \textbf{Comparaison} & \texttt{trouve} & \textbf{Action / Commentaire} \\
\hline
Init & -- & -- & -- & \texttt{FAUX} & \texttt{i=1, pos=0} \\
\hline
1 & 1 & 5 & 5 = 17 ? \textbf{FAUX} & \texttt{FAUX} & \texttt{i $\leftarrow$ 2} \\
\hline
2 & 2 & 12 & 12 = 17 ? \textbf{FAUX} & \texttt{FAUX} & \texttt{i $\leftarrow$ 3} \\
\hline
3 & 3 & \textbf{17} & \textbf{17 = 17 ? VRAI} & \texttt{VRAI} & \texttt{pos $\leftarrow$ 3, ARRÊT boucle} \\
\hline
\end{tabularx}
\end{center}
\textbf{Résultat final :} \texttt{trouve = VRAI}, \texttt{pos = 3}. La valeur est en 3$^{\text{ème}}$ position.
\end{exemplebox}

\begin{itemize}
    \item \textbf{Valeur en première position (\texttt{i=1}) :} Une seule comparaison. Meilleur cas : $\Omega(1)$.
    \item \textbf{Valeur absente :} La boucle va jusqu'à \texttt{i = N}, fait \texttt{N} comparaisons, \texttt{trouve} reste \texttt{FAUX}. Pire cas : $O(N)$.
    \item \textbf{Occurrences multiples :} Cet algorithme (tel qu'écrit) s'arrête à la \textbf{première} occurrence trouvée (la plus petit indice). Si l'on veut \emph{toutes} les positions, il faut retirer l'arrêt anticipé (boucle \texttt{Pour} complète) et stocker les indices dans un second tableau.
\end{itemize}

\begin{propriete}[Coût en comparaisons (admis)]
Pour un tableau de taille \texttt{N}, l'algorithme effectue \textbf{au maximum N comparaisons} (cas où x est absent ou en dernière position).
\begin{itemize}
    \item \textbf{Meilleur cas :} 1 comparaison (x = T[1]).
    \item \textbf{Pire cas :} N comparaisons (x absent ou x = T[N]).
    \item \textbf{Moyenne (si x présent et équiprobable) :} $\frac{N+1}{2}$ comparaisons.
\end{itemize}
On dit que la complexité en temps est \textbf{linéaire} : $O(N)$.
\end{propriete}

\begin{savaistu}[Le cahier d'appel du prof]
Quand ton professeur appelle les noms un par un dans la liste de la classe pour savoir si tu es présent, il effectue une \cle{recherche séquentielle} sur un « tableau » non trié (la liste d'appel). S'il trouve ton nom, il coche (témoin = VRAI) et passe au suivant. S'il arrive au bout sans trouver ton nom, tu es absent (témoin = FAUX). C'est exactement l'algorithme que nous venons d'écrire, exécuté par un humain !
\end{savaistu}

\courssub{Méthode : les 4 étapes pour écrire une recherche séquentielle}

\begin{methode}[Écrire un algorithme de recherche séquentielle]
\begin{enumerate}
    \item \textbf{Déclarer} : Tableau \texttt{T[1..N]}, valeur cherchée \texttt{x}, indice \texttt{i}, témoin \texttt{trouve (Booleen)}, position \texttt{pos (Entier)}.
    \item \textbf{Initialiser} : \texttt{trouve $\leftarrow$ FAUX}, \texttt{i $\leftarrow$ 1}, \texttt{pos $\leftarrow$ 0}. Lire \texttt{x} (et remplir \texttt{T} si besoin).
    \item \textbf{Parcourir et Comparer} : Boucle \texttt{TantQue (i $\le$ N) ET (NON trouve) Faire} \\
          \hspace{1cm} \texttt{Si T[i] = x Alors trouve $\leftarrow$ VRAI; pos $\leftarrow$ i} \\
          \hspace{1cm} \texttt{Sinon i $\leftarrow$ i + 1} \\
          \hspace{1cm} \texttt{FinSi} \\
          \texttt{FinTantQue}
    \item \textbf{Conclure} : \texttt{Si trouve Alors Afficher("Trouvé à", pos) Sinon Afficher("Absent") FinSi}.
\end{enumerate}
\end{methode}

\courssub{Exercice résolu : Recherche d'une note dans un bulletin}

\begin{exoresolu}[Recherche d'une note seuil]
\textbf{Énoncé :} On dispose des notes de 30 élèves d'une classe de Terminale D stockées dans un tableau \texttt{NOTES[1..30]} (entiers sur 20). Écrire un algorithme qui permet de savoir s'il existe \textbf{au moins une} note égale à 20/20. Si oui, afficher « Excellence détectée » et le numéro de l'élève (son indice dans le tableau). Sinon afficher « Aucun 20/20 ».

\tcblower

\textbf{Solution détaillée}

\begin{enumerate}
    \item \textbf{Analyse :} C'est une recherche séquentielle classique où \texttt{x = 20} est fixée (pas de saisie utilisateur). Le tableau est déjà rempli. On cherche la \textbf{première} occurrence de 20.
    \item \textbf{Variables :} \texttt{NOTES[1..30] : Entier}, \texttt{i, pos : Entier}, \texttt{trouve : Booleen}.
    \item \textbf{Algorithme :}
\end{enumerate}

\begin{lstlisting}[language=, caption={Algorithme : Détection Excellence}]
Algorithme DetectionExcellence
Constante
    TAILLE = 30
Variable
    NOTES : Tableau[1..TAILLE] d'entiers
    i, pos : Entier
    trouve : Booleen

Debut
    // Remplissage simulé (dans la réalité, notes déjà en mémoire ou saisies)
    Pour i <- 1 A TAILLE Faire
        Afficher("Note élève ", i, " : "); Saisir(NOTES[i])
    FinPour

    // Recherche séquentielle de la valeur 20
    trouve <- FAUX
    i <- 1
    pos <- 0

    TantQue (i <= TAILLE) ET (NON trouve) Faire
        Si NOTES[i] = 20 Alors
            trouve <- VRAI
            pos <- i
        Sinon
            i <- i + 1
        FinSi
    FinTantQue

    // Résultat
    Si trouve Alors
        Afficher("Excellence détectée ! Élève n°", pos, " a 20/20.")
    Sinon
        Afficher("Aucun 20/20 dans cette classe.")
    FinSi
Fin
\end{lstlisting}

\begin{enumerate}\setcounter{enumi}{3}
    \item \textbf{Trace partielle (exemple) :} Si \texttt{NOTES = [14, 20, 18, 20, ...]}.
    \begin{itemize}
        \item \texttt{i=1} : 14 $\neq$ 20 $\rightarrow$ \texttt{i=2}.
        \item \texttt{i=2} : 20 = 20 $\rightarrow$ \texttt{trouve=VRAI, pos=2, ARRÊT}.
    \end{itemize}
    \item \textbf{Sortie :} \texttt{Excellence détectée ! Élève n°2 a 20/20.} (On ne voit pas le 20 de l'élève 4 car arrêt anticipé).
\end{enumerate}
\end{exoresolu}

\coursec{Tri par insertion}

Dans la section précédente, nous avons appris à \emph{rechercher} une valeur dans un tableau grâce à la recherche séquentielle. Nous avons remarqué au passage que cette recherche devient beaucoup plus efficace lorsque le tableau est \cle{trié} : on peut alors s'arrêter dès qu'on dépasse la valeur cherchée, et des méthodes encore plus rapides deviennent possibles (recherche dichotomique). Mais comment obtenir un tableau trié ? C'est précisément l'objet de cette section : découvrir un premier \cle{algorithme de tri}, le \cle{tri par insertion}, qui permet d'ordonner les éléments d'un tableau, par exemple les notes d'une classe de la plus petite à la plus grande.

\courssub{Le problème du tri}

\textbf{Situation.} La fin du trimestre approche au lycée. Le professeur principal de la Terminale C a saisi dans un tableau les moyennes générales des 40 élèves, dans l'ordre de la liste de classe. Pour établir le tableau d'honneur, il veut afficher ces moyennes \emph{de la plus grande à la plus petite} ; pour repérer les élèves en difficulté, il veut les voir \emph{de la plus petite à la plus grande}. Dans les deux cas, il a besoin de \textbf{trier} le tableau.

\begin{definition}[Tri d'un tableau]
\cle{Trier} un tableau, c'est réorganiser ses éléments de manière qu'ils apparaissent dans un ordre donné : \cle{ordre croissant} (chaque élément est inférieur ou égal au suivant) ou \cle{ordre décroissant} (chaque élément est supérieur ou égal au suivant). Un tableau $T$ de $N$ entiers est trié par ordre croissant lorsque :
\[ T[1] \le T[2] \le T[3] \le \dots \le T[N] \]
\end{definition}

\begin{exemplebox}[Tableau trié ou non ?]
Le tableau $T = [1, 3, 5, 8]$ est trié par ordre croissant car $1 \le 3 \le 5 \le 8$. Le tableau $T = [8, 3, 5, 1]$ n'est pas trié car $8 > 3$ : dès le deuxième élément, l'ordre croissant est violé.
\end{exemplebox}

Il existe de nombreux algorithmes de tri (tri par sélection, tri à bulles, tri fusion, tri rapide\ldots). Au programme de Terminale, nous étudions le \cle{tri par insertion}, qui a l'immense avantage d'être celui que tout être humain utilise naturellement.

\courssub{L'intuition : trier ses cartes en main}

Imagine que tu joues aux cartes avec des amis dans la cour du lycée. On te distribue les cartes une à une. Comment fais-tu pour garder ta main triée ? Presque tout le monde procède ainsi :

\begin{enumerate}
\item la première carte est posée seule : une main d'une seule carte est évidemment triée ;
\item à chaque nouvelle carte reçue, tu la compares aux cartes déjà en main, \emph{de droite à gauche} ;
\item tu déplaces vers la droite les cartes plus grandes qu'elle, puis tu l'\textbf{insères} à sa place, dans la zone déjà triée.
\end{enumerate}

À aucun moment tu ne recommences tout depuis le début : tu exploites le fait que la partie gauche de ta main est \emph{déjà triée}, et tu y insères la nouvelle carte. Le tri par insertion applique exactement cette stratégie à un tableau.

\begin{aretenir}[Idée fondamentale du tri par insertion]
On parcourt le tableau de gauche à droite. À l'étape $i$ (avec $i$ allant de $2$ à $N$) :
\begin{itemize}
\item la partie $T[1..i-1]$ est \textbf{déjà triée} (c'est la « main » du joueur) ;
\item on prend la valeur $T[i]$ (la « nouvelle carte ») et on l'\textbf{insère à sa place} dans la partie triée, en décalant d'un cran vers la droite tous les éléments qui lui sont supérieurs.
\end{itemize}
\end{aretenir}

\courssub{Principe détaillé et variables clés}

Formalisons l'insertion de l'élément d'indice $i$. Trois variables jouent un rôle essentiel :

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Variable} & \textbf{Rôle} \\
\hline
$i$ & \textbf{Frontière} entre la partie triée (indices $1$ à $i-1$) et la partie non encore traitée (indices $i$ à $N$). C'est l'indice de l'élément à insérer. \\
\hline
$x$ & \textbf{Sauvegarde} de la valeur $T[i]$ à insérer. Indispensable, car les décalages vont écraser la case $T[i]$. \\
\hline
$j$ & \textbf{Curseur de décalage} : il parcourt la partie triée de droite à gauche (de $i-1$ vers $1$) pour trouver la place de $x$. \\
\hline
\end{tabularx}
\end{center}

L'insertion de $x$ se déroule ainsi : tant que $j \ge 1$ \emph{et} que $T[j] > x$, on recopie $T[j]$ dans $T[j+1]$ (décalage d'un cran vers la droite) et on recule $j$. Quand la boucle s'arrête, la case $T[j+1]$ est libre : on y place $x$.

\begin{attention}[Deux conditions obligatoires dans le TantQue]
La condition de la boucle interne est \texttt{TantQue (j >= 1) ET (T[j] > x)}. Le test \texttt{j >= 1} est \textbf{indispensable} : sans lui, si $x$ est plus petit que tous les éléments déjà triés, $j$ deviendrait $0$ et l'accès à $T[0]$ serait un \emph{débordement de tableau} (indice hors limites). On teste toujours d'abord la validité de l'indice, ensuite la comparaison.
\end{attention}

\courssub{Écriture complète de l'algorithme}

\begin{methode}[Algorithme TriInsertion, commenté ligne par ligne]
\begin{lstlisting}
Algorithme TriInsertion
Variable
    T : Tableau[1..N] de Entier   // tableau a trier
    i, j, x : Entier
Debut
    Pour i De 2 A N Faire          // T[1] seul est deja trie
        x <- T[i]                  // 1. sauvegarder la valeur a inserer
        j <- i - 1                 // 2. partir de la fin de la zone triee
        TantQue (j >= 1) ET (T[j] > x) Faire
            T[j+1] <- T[j]         // 3. decaler T[j] d'un cran a droite
            j <- j - 1             // 4. reculer le curseur
        FinTantQue
        T[j+1] <- x                // 5. inserer x a sa place
    FinPour
Fin
\end{lstlisting}
Commentaire des étapes clés :
\begin{enumerate}
\item \textbf{Ligne 6} : la boucle externe commence à $i = 2$, car un tableau réduit à $T[1]$ est trivialement trié.
\item \textbf{Ligne 7} : on sauvegarde $T[i]$ dans $x$ \emph{avant} tout décalage.
\item \textbf{Lignes 9 à 12} : la boucle interne décale vers la droite tous les éléments de la partie triée qui sont strictement supérieurs à $x$.
\item \textbf{Ligne 13} : à la sortie de la boucle, tous les éléments d'indice $1$ à $j$ sont $\le x$ et ceux d'indice $j+2$ à $i$ sont $> x$ : la bonne case pour $x$ est donc $j+1$.
\end{enumerate}
\end{methode}

\begin{attention}[{Erreur fréquente : écraser T[i] avant de l'avoir sauvegardé}]
Beaucoup d'élèves écrivent directement les décalages sans passer par la variable $x$. Or le premier décalage \texttt{T[j+1] <- T[j]} avec $j = i-1$ recopie $T[i-1]$ dans $T[i]$ : la valeur initiale de $T[i]$ est alors \textbf{définitivement perdue}, et le tableau final contiendra un doublon et une valeur manquante. \textbf{Règle d'or : toujours sauvegarder \texttt{x <- T[i]} en premier.}
\end{attention}

\courssub{Exécution pas à pas et table d'exécution}

Le programme officiel exige de savoir exécuter un algorithme \emph{pas à pas} à l'aide d'une \cle{table d'exécution} (ou table de traçage). Cette table note, pour chaque instruction exécutée, les valeurs de toutes les variables et le contenu du tableau. C'est l'outil indispensable pour valider un algorithme et détecter les erreurs logiques.

\begin{methode}[Construction d'une table d'exécution pour le tri par insertion]
\begin{enumerate}
\item \textbf{Colonnes} : une colonne par variable ($i, j, x$) et une colonne par case du tableau ($T[1], T[2], \dots, T[N]$). On ajoute une colonne « Instruction » (numéro de ligne ou description).
\item \textbf{Lignes} : une nouvelle ligne à \emph{chaque modification} d'une variable ou du tableau (affectation, incrémentation, entrée dans une boucle).
\item \textbf{Initialisation} : noter l'état initial du tableau avant le \texttt{Debut} de la boucle principale.
\item \textbf{Boucle externe} : pour chaque valeur de $i$, noter l'affectation de $x$ et $j$.
\item \textbf{Boucle interne} : à chaque itération, noter le décalage ($T[j+1] \leftarrow T[j]$) et la décrémentation de $j$.
\item \textbf{Insertion} : noter l'affectation finale $T[j+1] \leftarrow x$.
\end{enumerate}
\end{methode}

\courssub{Coût de l'algorithme et propriétés}

Combien de comparaisons le tri par insertion effectue-t-il ? Analysons les cas extrêmes de manière intuitive.

\begin{itemize}
\item \textbf{Meilleur cas} : le tableau est déjà trié. À chaque étape $i$, la condition $T[j] > x$ est fausse dès le premier test : une seule comparaison par étape, soit environ $N$ comparaisons au total. Aucun décalage n'est effectué.
\item \textbf{Pire cas} : le tableau est trié dans l'ordre \emph{décroissant} (par exemple $[9, 7, 5, 3]$). À l'étape $i$, l'élément $x$ doit remonter jusqu'en première position : il faut $i-1$ comparaisons et $i-1$ décalages. Le nombre total de comparaisons est alors :
\[ 1 + 2 + 3 + \dots + (N-1) = \frac{N(N-1)}{2} \]
\end{itemize}

\begin{propriete}[Coût du tri par insertion (admis)]
Le tri par insertion effectue, dans le pire des cas, de l'ordre de $N^2$ comparaisons (on dit qu'il est \cle{quadratique}) : précisément $\dfrac{N(N-1)}{2}$ comparaisons lorsque le tableau est trié en ordre inverse. Pour $N = 1000$, cela représente environ $500\,000$ comparaisons. En revanche, sur un tableau déjà trié ou presque trié, il n'effectue que de l'ordre de $N$ comparaisons.
\end{propriete}

\begin{propriete}[Stabilité]
Le tri par insertion est un tri \cle{stable} : si deux éléments ont la même valeur, leur ordre relatif est préservé. En effet, la condition de décalage est $T[j] > x$ (strictement supérieur) : les éléments égaux à $x$ ne sont pas décalés, $x$ s'insère \emph{après} eux.
\end{propriete}

\begin{savaistu}[Le champion des tableaux presque triés]
Le tri par insertion possède une qualité rare : plus le tableau est proche de l'ordre final, plus il est rapide. Sur un tableau « presque trié » (quelques éléments mal placés seulement), il bat des algorithmes réputés plus sophistiqués. C'est pourquoi les tris utilisés en pratique dans les bibliothèques des langages modernes (comme \texttt{std::sort} en C++ ou \texttt{Timsort} en Python/Java) combinent souvent une méthode puissante pour les grandes masses de données et un tri par insertion pour finir le travail sur les petites zones. C'est aussi le tri qu'utilisent naturellement les joueurs de cartes du monde entier, de Yaoundé à Tokyo, sans même savoir qu'ils appliquent un algorithme étudié en Terminale !
\end{savaistu}

\begin{aretenir}[L'essentiel du tri par insertion]
\begin{itemize}
\item Trier un tableau, c'est ordonner ses éléments (croissant ou décroissant). Pour l'ordre décroissant, il suffit de remplacer \texttt{T[j] > x} par \texttt{T[j] < x} dans la boucle interne.
\item Le tri par insertion reproduit la méthode du joueur de cartes : à l'étape $i$, la partie $T[1..i-1]$ est triée et on insère $T[i]$ à sa place par décalages successifs.
\item Trois variables clés : $i$ (frontière), $x$ (sauvegarde de $T[i]$), $j$ (curseur de décalage).
\item Ne jamais écraser $T[i]$ sans l'avoir sauvegardé dans $x$, et toujours tester $j \ge 1$ avant $T[j] > x$ pour éviter un débordement d'indice.
\item Coût : de l'ordre de $N^2$ comparaisons dans le pire cas, mais linéaire ($N$) dans le meilleur cas et sur les tableaux presque triés.
\item C'est un tri \textbf{stable} (préserve l'ordre des égaux) et \textbf{en place} (pas de tableau auxiliaire nécessaire).
\item La \textbf{table d'exécution} est l'outil de validation rigoureuse : elle suit pas à pas les variables $i, j, x$ et le contenu du tableau.
\end{itemize}
\end{aretenir}

\coursec{Exécution pas à pas et table d'exécution}

Nous venons d'écrire deux algorithmes fondamentaux : la \cle{recherche séquentielle} et le \cle{tri par insertion}. Une question naturelle se pose alors : comment être \emph{certain} qu'un algorithme est correct \emph{avant} de le traduire en langage C et de l'exécuter sur une machine ? Un programme qui boucle indéfiniment ou qui affiche un mauvais résultat coûte du temps, et l'erreur est souvent beaucoup plus facile à repérer sur le papier que dans un code compilé. La réponse des informaticiens est une technique simple et puissante : jouer soi-même le rôle de l'ordinateur, instruction par instruction, en notant tout ce qui se passe. C'est l'\cle{exécution pas à pas}, matérialisée par la \cle{table d'exécution}.

\courssub{Pourquoi exécuter un algorithme à la main ?}

\begin{definition}[Exécution pas à pas]
L'\cle{exécution pas à pas} (ou \emph{trace d'exécution}) d'un algorithme consiste à simuler mentalement le travail du processeur : on exécute les instructions une par une, dans l'ordre où la machine les rencontrerait, et l'on note après chaque instruction la valeur de chaque variable ainsi que ce qui s'affiche à l'écran.
\end{definition}

Cette démarche répond à trois besoins concrets :

\begin{itemize}
\item \textbf{Vérifier} : s'assurer que l'algorithme produit bien le résultat attendu sur un exemple précis ;
\item \textbf{Déboguer} : localiser l'instruction exacte où les valeurs deviennent fausses (boucle infinie, indice hors tableau, mauvaise initialisation) ;
\item \textbf{Comprendre} : intérioriser le fonctionnement d'un algorithme en le « vivant » de l'intérieur, ce qui est indispensable pour l'épreuve d'informatique du Baccalauréat.
\end{itemize}

\begin{savaistu}[Le « test à sec » des grands programmeurs]
En anglais, cette technique s'appelle le \emph{dry run} (littéralement « essai à sec »). Avant l'existence des débogueurs intégrés, les pionniers de l'informatique comme Alan Turing traçaient leurs programmes à la main sur des feuilles quadrillées. Encore aujourd'hui, dans les concours et les entretiens d'embauche des grandes entreprises du numérique, on demande aux candidats d'exécuter un algorithme sur papier : c'est la preuve qu'on le comprend vraiment.
\end{savaistu}

\courssub{Structure d'une table d'exécution}

\begin{definition}[Table d'exécution]
Une \cle{table d'exécution} est un tableau à quatre colonnes :
\begin{enumerate}
\item \textbf{Ligne} : le numéro de la ligne de l'algorithme en cours d'exécution ;
\item \textbf{Instruction} : le texte de l'instruction exécutée (ou l'évaluation de la condition pour un test) ;
\item \textbf{Variables} : les valeurs de l'ensemble des variables \emph{après} l'exécution de l'instruction (on ne reporte en pratique que celles qui changent, les autres conservant leur valeur) ;
\item \textbf{Écran} : ce qui s'affiche à l'écran (uniquement pour les instructions d'écriture).
\end{enumerate}
Chaque ligne de la table correspond à \emph{une seule instruction exécutée}.
\end{definition}

\begin{methode}[Construire une table d'exécution en quatre étapes]
\begin{enumerate}
\item \textbf{Numéroter} les lignes de l'algorithme (chaque instruction simple reçoit un numéro ; les mots-clés de structure \texttt{FinSi}, \texttt{FinTantQue}, \texttt{FinPour} ne sont pas numérotés car ils ne s'exécutent pas) ;
\item \textbf{Préparer} le tableau : une colonne par variable susceptible de changer, plus les colonnes « ligne », « instruction » et « écran » ;
\item \textbf{Exécuter} les instructions dans l'ordre : à chaque instruction, écrire une nouvelle ligne de la table et mettre à jour \emph{uniquement} la variable modifiée (les autres gardent leur valeur précédente) ;
\item \textbf{Conclure} : vérifier que le résultat final (valeurs des variables, affichages) correspond au résultat attendu.
\end{enumerate}
\end{methode}

\begin{attention}[L'erreur classique de la table d'exécution]
L'erreur la plus fréquente consiste à \textbf{recopier ou modifier toutes les variables à chaque ligne}, comme si chaque instruction agissait sur tout. Or une instruction ne modifie \emph{qu'une seule variable} (celle qui reçoit l'affectation) ; toutes les autres conservent leur valeur. Autre piège : oublier qu'un test (\texttt{Si}, \texttt{Tant que}) ne modifie \emph{aucune} variable — il détermine seulement la prochaine instruction exécutée. Enfin, pour une boucle, il faut écrire \emph{autant de lignes que de passages} dans la boucle, et non une seule ligne résumée.
\end{attention}

\courssub{Trace du tri par insertion}

Traçons maintenant le tri par insertion (section 5) sur le tableau $T = [8, 3, 5, 1]$ (indices $1$ à $4$). Rappelons le principe : à l'étape $i$, on insère l'élément $T[i]$ (la \cle{clé}) à sa place dans la partie déjà triée $T[1..i-1]$, en décalant vers la droite les éléments plus grands que lui.

\begin{lstlisting}
Algorithme TriInsertion
Variables : T : tableau[1..4] d'entiers
            i, j, cle : entiers
Debut
 1   Pour i allant de 2 a 4 Faire
 2      cle <- T[i]
 3      j <- i - 1
 4      Tant que (j >= 1) et (T[j] > cle) Faire
 5         T[j+1] <- T[j]      // decalage vers la droite
 6         j <- j - 1
 7      FinTantQue
 8      T[j+1] <- cle          // insertion de la cle
 9   FinPour
Fin
\end{lstlisting}

\begin{exemplebox}[{Trace narrative du tri par insertion sur $[8, 3, 5, 1]$}]
\textbf{Étape $i = 2$ :} $\texttt{cle} = T[2] = 3$, $j = 1$. Comme $T[1] = 8 > 3$, on décale : $T[2] \leftarrow 8$, $j = 0$. La boucle interne s'arrête ($j < 1$), puis $T[1] \leftarrow 3$. Tableau : $[3, 8, 5, 1]$.

\textbf{Étape $i = 3$ :} $\texttt{cle} = T[3] = 5$, $j = 2$. $T[2] = 8 > 5$ : décalage, $T[3] \leftarrow 8$, $j = 1$. $T[1] = 3 \le 5$ : arrêt. $T[2] \leftarrow 5$. Tableau : $[3, 5, 8, 1]$.

\textbf{Étape $i = 4$ :} $\texttt{cle} = T[4] = 1$, $j = 3$. $T[3] = 8 > 1$ : $T[4] \leftarrow 8$, $j = 2$. $T[2] = 5 > 1$ : $T[3] \leftarrow 5$, $j = 1$. $T[1] = 3 > 1$ : $T[2] \leftarrow 3$, $j = 0$. Arrêt, puis $T[1] \leftarrow 1$. Tableau final : $[1, 3, 5, 8]$. Le tableau est trié.
\end{exemplebox}

\courssub{Utiliser la trace pour détecter une erreur}

La table d'exécution est un formidable outil de \cle{débogage}. Deux erreurs classiques y apparaissent immédiatement.

\textbf{1. La boucle infinie.} Supposons qu'on ait oublié la ligne 8 ($i \leftarrow i + 1$) dans la recherche séquentielle. La trace le montre sans pitié : $i$ reste bloqué à $1$, le test de la ligne 4 est toujours VRAI, et la table s'allonge indéfiniment avec des lignes identiques. Dès qu'on remarque que \emph{plusieurs lignes consécutives sont strictement identiques}, on sait que la boucle ne progressera jamais : il manque une instruction de progression (incrémentation).

\textbf{2. La mauvaise initialisation.} Supposons qu'on ait écrit $\texttt{trouve} \leftarrow \text{VRAI}$ à la ligne 2 par erreur. La trace donne : à la ligne 4, le test « non trouve » est FAUX dès le départ, la boucle n'est jamais exécutée, et l'algorithme affiche « Valeur trouvée à la position 1 » alors que $T[1] = 5 \neq 17$. Le résultat final, absurde, révèle l'erreur d'initialisation.

\begin{attention}[Vérifier la condition d'arrêt]
Toute boucle \texttt{Tant que} doit contenir, dans son corps, au moins une instruction qui \emph{fait évoluer} une variable de la condition d'arrêt. Avant de tracer, pose-toi la question : « qu'est-ce qui rapproche la boucle de sa fin ? ». Si la réponse n'est pas évidente, la trace le confirmera : c'est le premier symptôme d'une boucle infinie.
\end{attention}

\courssub{Valider un algorithme : le choix des jeux de tests}

Une seule trace réussie ne prouve pas qu'un algorithme est correct : elle prouve seulement qu'il fonctionne \emph{sur cet exemple}. Pour \cle{valider} sérieusement un algorithme, on le teste sur plusieurs \cle{jeux de tests} choisis avec soin.

\begin{methode}[Choisir ses jeux de tests]
Pour valider un algorithme de recherche ou de tri, prévois au minimum :
\begin{enumerate}
\item \textbf{Le cas normal} : une valeur présente au milieu du tableau, un tableau quelconque non trié (ex. $[8, 3, 5, 1]$) ;
\item \textbf{Les cas limites} : valeur en \emph{première} position, valeur en \emph{dernière} position, tableau à \emph{un seul} élément, tableau déjà trié $[1, 3, 5, 8]$, tableau trié en ordre inverse $[8, 5, 3, 1]$ (c'est le cas le plus coûteux pour le tri par insertion) ;
\item \textbf{Le cas impossible} : valeur absente du tableau (la recherche doit répondre « absente » et non boucler ou planter), tableau vide si le problème l'autorise.
\end{enumerate}
L'algorithme n'est validé que s'il donne le bon résultat sur \emph{tous} ces cas.
\end{methode}

\begin{exemplebox}[{Jeux de tests pour la recherche séquentielle sur $T = [5, 12, 17, 9]$}]
\begin{center}
\begin{tabularx}{\linewidth}{|l|l|X|}
\hline
\rowcolor{popblueL} \textbf{Type de cas} & \textbf{Valeur $x$} & \textbf{Résultat attendu} \\
\hline
Normal & 12 & trouvée, position 2 \\
\hline
Limite (début) & 5 & trouvée, position 1 \\
\hline
Limite (fin) & 9 & trouvée, position 4 \\
\hline
Impossible & 100 & « Valeur absente » \\
\hline
\end{tabularx}
\end{center}
Si l'algorithme échoue sur l'un de ces cas (par exemple une boucle qui s'arrête avant la dernière case à cause d'un test $i < n$ au lieu de $i \le n$), le cas limite « fin » le démasquera.
\end{exemplebox}

\begin{experience}[TP : valider le tri par insertion à la main puis en C]
\textbf{Objectif} : confronter la trace papier à l'exécution réelle.

\textbf{Matériel} : papier quadrillé, crayon, puis un ordinateur avec un compilateur C (Code::Blocks ou GCC).

\textbf{Manipulation 1 (papier)} : trace le tri par insertion sur les quatre jeux de tests suivants : $[8, 3, 5, 1]$ (cas normal), $[1, 2, 3, 4]$ (déjà trié), $[4, 3, 2, 1]$ (inversé), $[7]$ (un seul élément). Compte pour chacun le nombre de décalages (ligne 5 exécutée).

\textbf{Manipulation 2 (machine)} : saisis et exécute le programme C suivant, qui affiche le tableau trié et le nombre total de décalages.

\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void) {
    int T[4] = {8, 3, 5, 1};   /* jeu de test a modifier */
    int n = 4, i, j, cle, decalages = 0;

    for (i = 1; i < n; i++) {   /* indices C : 0 a n-1 */
        cle = T[i];
        j = i - 1;
        while (j >= 0 && T[j] > cle) {
            T[j + 1] = T[j];    /* decalage vers la droite */
            j = j - 1;
            decalages = decalages + 1;
        }
        T[j + 1] = cle;         /* insertion de la cle */
    }

    for (i = 0; i < n; i++) {
        printf("%d ", T[i]);
    }
    printf("\nDecalages : %d\n", decalages);
    return 0;
}
\end{lstlisting}

\textbf{Observations} : pour $[8, 3, 5, 1]$, le programme affiche \texttt{1 3 5 8} et $5$ décalages — exactement ce que la trace papier avait donnée. Pour le tableau déjà trié, $0$ décalage ; pour le tableau inversé, $6$ décalages (le maximum).

\textbf{Interprétation} : la concordance entre la trace manuelle et l'exécution réelle valide l'algorithme. Le tri par insertion est très rapide sur un tableau presque trié et le plus lent sur un tableau inversé : on parle de \emph{meilleur} et de \emph{pire} des cas.
\end{experience}

\begin{exercice}[À toi de jouer]
\begin{enumerate}
\item Construis la table d'exécution de la recherche séquentielle de la valeur $100$ dans $T = [5, 12, 17, 9]$. Que vaut $i$ à la sortie de la boucle ?
\item Trace le tri par insertion sur $T = [2, 1]$ puis sur $T = [1, 2]$. Compare le nombre d'instructions exécutées.
\item Un élève a écrit, dans la boucle du tri par insertion, le test \texttt{Tant que (j >= 1) et (T[j] >= cle)} (avec $\ge$ au lieu de $>$). Trace cet algorithme sur $[5, 5, 3]$. Le résultat est-il encore correct ? Que peut-on dire du nombre de décalages et de la \cle{stabilité} du tri ?
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice]
\begin{enumerate}
\item La boucle s'exécute quatre fois sans jamais trouver $100$ ; $i$ prend successivement les valeurs $1, 2, 3, 4, 5$. À la sortie, $i = 5 > n = 4$ et \texttt{trouve} = FAUX : l'algorithme affiche « Valeur absente ». C'est le comportement attendu.
\item Pour $[2, 1]$ : un décalage ($T[2] \leftarrow 2$) puis $T[1] \leftarrow 1$ ; résultat $[1, 2]$. Pour $[1, 2]$ : le test $T[1] > 2$ est FAUX immédiatement, aucun décalage. Le tableau déjà trié coûte beaucoup moins cher (meilleur cas).
\item Le tableau $[5, 5, 3]$ est trié correctement en $[3, 5, 5]$ : le résultat reste juste. Mais avec $\ge$, les éléments \emph{égaux} à la clé sont aussi décalés, ce qui provoque des décalages inutiles (le tri perd son caractère \emph{stable} — l'ordre relatif des égaux n'est plus conservé — et devient légèrement plus lent). La condition correcte pour un tri stable et optimal est bien $T[j] > \texttt{cle}$.
\end{enumerate}
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item La \cle{table d'exécution} simule l'ordinateur : une ligne par instruction, colonnes \emph{ligne / instruction / variables / écran}.
\item Une instruction ne modifie \emph{qu'une variable} ; un test n'en modifie aucune.
\item La trace permet de \emph{vérifier} un résultat, de \emph{détecter} les boucles infinies et les mauvaises initialisations.
\item Un algorithme n'est validé qu'après plusieurs \cle{jeux de tests} : cas normal, cas limites (début, fin, déjà trié, inversé, un élément) et cas impossible (valeur absente).
\end{itemize}
\end{aretenir}

Trouve <- Faux ; i <- 0

    Si Tab[i].Champ = ValeurCherchee Alors

\end{lstlisting}

\begin{exemplebox}[Tri par insertion croissant (rappel)]
\begin{lstlisting}[language=]
Pour i <- 1 à N-1 Faire
    Cle <- Tab[i] ; j <- i - 1
    TantQue (j >= 0) ET (Tab[j] > Cle) Faire
        Tab[j+1] <- Tab[j] ; j <- j - 1
    FinTantQue
    Tab[j+1] <- Cle
FinPour
\end{lstlisting}
\end{exemplebox}

\begin{propriete}[Adaptation pour ordre décroissant sur champ]
Pour trier un tableau d'enregistrements par un champ numérique \textbf{décroissant}, on inverse la comparaison dans le \texttt{TantQue} :
\texttt{(j >= 0) ET (Tab[j].Champ < Cle.Champ)}.
On décale tant que l'élément courant est \textbf{plus petit} que la clé (on veut les grands devant).
L'affectation \texttt{Tab[j+1] <- Tab[j]} déplace la structure \textbf{entière} (tous les champs).
\end{propriete}

Colonnes obligatoires : \texttt{N° Ligne | Instruction | Variables (Valeurs) | Écran}. Une ligne par instruction exécutée.
\end{exemplebox}

\begin{methode}[Tri par insertion décroissant sur enregistrements]
\begin{enumerate}
    \item La clé \texttt{Cle} est de type \texttt{Eleve} (on déplace l'enregistrement entier).
    \item Boucle principale : \texttt{Pour i \textleftarrow 1 \`a 7 Faire} ($N=8$).
    \item \texttt{Cle \textleftarrow Promo[i]} ; \texttt{j \textleftarrow i-1}.
    \item \textbf{Condition de décalage :} \texttt{TantQue (j >= 0) ET (Promo[j].Moyenne < Cle.Moyenne) Faire}.
    \item \quad \texttt{Promo[j+1] \textleftarrow Promo[j]} (décalage de la structure complète vers la droite).
    \item \quad \texttt{j \textleftarrow j - 1}.
    \item \texttt{Promo[j+1] \textleftarrow Cle} (insertion de la clé à sa place).
\end{enumerate}
\end{methode}

\begin{exoresolu}{Question 3 : Tri par insertion décroissant}
\textbf{Algorithme \texttt{TriDecroissant}}
\begin{lstlisting}[language=]
// Variables locales
Cle : Eleve
i, j : Entier

Debut TriDecroissant
Pour i <- 1 à 7 Faire
    Cle <- Promo[i]       // Sauvegarde de l'élève à insérer
    j <- i - 1
    // Décalage des moyennes PLUS PETITES que Cle.Moyenne
    TantQue (j >= 0) ET (Promo[j].Moyenne < Cle.Moyenne) Faire
        Promo[j+1] <- Promo[j]  // Décalage structure entière
        j <- j - 1
    FinTantQue
    Promo[j+1] <- Cle     // Insertion
FinPour
Fin TriDecroissant
\end{lstlisting}

\begin{attention}[Pièges fréquents sur le tri d'enregistrements]
\begin{itemize}
    \item \textbf{Séparer les champs :} N'affectez \textbf{jamais} seulement \texttt{Promo[j+1].Moyenne \textleftarrow Promo[j].Moyenne}. Le nom resterait à l'ancienne place $\to$ incohérence fatale. \textbf{Solution :} Affectation structurelle \texttt{Promo[j+1] \textleftarrow Promo[j]}.
    \item \textbf{Sens de l'inégalité :} Pour décroissant, on décale si \texttt{Tab[j].Champ < Cle.Champ}. Garder \texttt{>} (croissant) est l'erreur n°1.
    \item \textbf{Ordre dans le \texttt{TantQue} :} \texttt{(j >= 0) ET (Promo[j].Moyenne < Cle.Moyenne)}. La borne \texttt{j >= 0} \textbf{doit être testée en premier} (évaluation paresseuse) pour éviter un accès hors limites \texttt{Promo[-1]}.
\end{itemize}
\end{attention}
\end{exoresolu}

\courssub{Validation croisée (Bilan collectif)}
Les groupes comparent leur trace du \textbf{Tri (Question 3)}. Points de contrôle critiques :
\begin{itemize}
    \item Itération \texttt{i=4} (insertion \texttt{Essomba/17}) : le tableau devient-il \texttt{[17, 15, 13, 11, 8, ...]} ?
    \item Itération \texttt{i=6} (insertion \texttt{Gueye/14}) : vérifiez que \texttt{13} et \texttt{11} ont été décalés vers la droite, mais \texttt{15} est resté en place (arrêt du \texttt{TantQue}).
    \item État final (après \texttt{i=7}) : strictement décroissant \texttt{17, 15, 14, 13, 12, 11, 10, 8}.
\end{itemize}
Toute divergence indique une erreur dans la condition du \texttt{TantQue} ou dans la gestion de l'indice \texttt{j}. Cette démarche simule la \emph{revue de code} (code review) en entreprise.

\courssub{Bilan de l'activité}
Cette activité a permis de mettre en évidence plusieurs points fondamentaux de l'algorithmique appliquée :
\begin{enumerate}
    \item \textbf{L'encapsulation des données :} Le passage du tableau simple (moyennes seules) au \textbf{tableau d'enregistrements} (\texttt{Promo}) est indispensable en situation réelle. On ne trie pas des notes "en l'air", on trie des \emph{dossiers élèves}. L'erreur classique (séparer le nom de la note lors du tri) a été évitée grâce à l'affectation de structure globale (\texttt{Promo[j+1] \textleftarrow Promo[j]}).
    \item \textbf{La généricité des algorithmes classiques :} La recherche séquentielle et le tri par insertion s'appliquent \emph{identiquement} sur des structures complexes, à condition de cibler le bon champ (\texttt{.Moyenne}) dans les comparaisons. L'adaptation "Croissant $\to$ Décroissant" ne change qu'un seul symbole ($>$ devient $<$), mais change radicalement le résultat.
    \item \textbf{La rigueur de la table d'exécution :} C'est l'outil unique pour \textbf{prouver} la correction d'un algorithme itératif. Sans elle, le tri par insertion (avec ses décalages imbriqués) est une "boîte noire" source de bugs. La validation croisée entre groupes simule la \emph{revue de code} professionnelle.
    \item \textbf{La complexité en action :} Sur $N=8$, la recherche a pris 7 tests (pire cas : 8). Le tri par insertion a effectué $\sum_{i=1}^{7} i = 28$ comparaisons dans le pire cas (tableau initialement croissant), mais moins ici car le désordre initial était aléatoire. Cela illustre concrètement la complexité quadratique $O(N^2)$.
\end{enumerate}

\courssub{Rappels : Structure d'un algorithme et instructions de base}

\begin{definition}[Algorithme]
Une suite finie et non ambiguë d'instructions élémentaires permettant de résoudre un problème ou d'obtenir un résultat à partir de données d'entrée. En pseudo-code (convention Bac Cameroun), il suit la structure canonique :
\begin{enumerate}
    \item \textbf{En-tête :} \texttt{Algorithme <Nom>}.
    \item \textbf{Déclarations :} \texttt{Constantes}, \texttt{Types}, \texttt{Variables} (nom : type).
    \item \textbf{Corps :} \texttt{Début} ... \texttt{Fin}.
\end{enumerate}
\end{definition}

\begin{propriete}[Instructions fondamentales]
\begin{itemize}
    \item \textbf{Affectation :} \texttt{Variable $\leftarrow$ Expression} (flèche, pas signe $=$).
    \item \textbf{Entrée/Sortie :} \texttt{Lire(Variable)}, \texttt{Écrire(Expression)}.
    \item \textbf{Conditionnelle :} \texttt{Si <Cond> Alors <Inst> Sinon <Inst> FinSi} (ou \texttt{Si ... Alors ... FinSi}).
    \item \textbf{Boucles bornées :} \texttt{Pour Var de Debut à Fin [Pas] Faire ... FinPour}.
    \item \textbf{Boucles non bornées :} \texttt{TantQue <Cond> Faire ... FinTantQue} (test en entrée) ; \texttt{Répéter ... JusquÀ <Cond>} (test en sortie).
\end{itemize}
\end{propriete}

\begin{exemplebox}[Algorithme simple : Calcul de la moyenne de 3 notes]
\begin{lstlisting}[language=Pascal]
Algorithme MoyenneTroisNotes
Variables
    N1, N2, N3, Moy : Réel
Début
    Écrire("Entrez les 3 notes : ")
    Lire(N1); Lire(N2); Lire(N3)
    Moy <- (N1 + N2 + N3) / 3
    Écrire("La moyenne est : ", Moy)
Fin
\end{lstlisting}
\end{exemplebox}

\courssub{Les structures de données : classification}

\begin{definition}[Structure de donnée]
Organisation logique des données en mémoire pour en faciliter l'accès, la modification et le traitement. Le programme de Terminale en distingue trois familles :
\end{definition}

\begin{propriete}[Les trois familles de structures (Programme MINESEC)]
\begin{itemize}
    \item \textbf{Structures finies (statiques) :} Taille fixée à la compilation.
    \begin{itemize}
        \item \cle{Constante} : Valeur immuable (\texttt{Constante PI = 3,14}).
        \item \cle{Variable simple} : Une seule valeur typée (\texttt{Âge : Entier}).
        \item \cle{Enregistrement (Structure hétérogène)} : Regroupe des champs \emph{nommés} de types \emph{différents} décrivant une même entité (ex: \texttt{Eleve : Nom, Âge, Moyenne}).
    \end{itemize}
    \item \textbf{Structures indexées (Tableaux) :} Collection \emph{ordonnée} d'éléments de \emph{même type}, accessibles par un \cle{indice} (entier). En pseudo-code Bac : indices de \textbf{1 à N}.
    \item \textbf{Structures récursives (Dynamiques) :} Taille variable à l'exécution, gérées par pointeurs/références (Listes chaînées, Piles, Files). \emph{Étudiées en langage C (Module 3), conceptuellement connues en pseudo-code.}
\end{itemize}
\end{propriete}

\courssub{Déclarer et parcourir un tableau unidimensionnel}

\begin{methode}[Déclaration, saisie et affichage d'un tableau]
\textbf{Objectif :} Manipuler une collection ordonnée de données de même type (notes, prix, âges).\par
\medskip
\textbf{Étapes :}
\begin{enumerate}
    \item \textbf{Identifier le besoin :} Combien de valeurs ? Quel type (entier, réel, chaîne) ? $\rightarrow$ Taille $N$ et Type $T$.
    \item \textbf{Déclarer le tableau :} \texttt{Tableau Tab[1..N] de Type} (indices 1 à $N$ inclus, convention Bac).
    \item \textbf{Saisir les éléments (Parcours en lecture) :}
    \begin{itemize}
        \item Initialiser une boucle \texttt{Pour i de 1 à N faire}.
        \item Afficher un invite : \texttt{Écrire("Élément n°", i, " : ")}.
        \item Lire : \texttt{Lire(Tab[i])}.
    \end{itemize}
    \item \textbf{Afficher les éléments (Parcours en écriture) :}
    \begin{itemize}
        \item Boucle \texttt{Pour i de 1 à N faire}.
        \item \texttt{Écrire(Tab[i])} (ou \texttt{Écrire("Tab[", i, "] = ", Tab[i])} pour débuguer).
    \end{itemize}
\end{enumerate}
\medskip
\textbf{Réflexe Bac :} Toujours vérifier les bornes de la boucle ($1$ à $N$). Un indice $0$ ou $N+1$ provoque une erreur d'exécution (dépassement de capacité).
\end{methode}

\begin{exoresolu}[Gestion des notes d'une classe de Terminale C au Lycée de Nkolbisson]
\textbf{Énoncé :} On souhaite saisir les notes de Mathématiques (sur 20) de 30 élèves, les stocker, puis les afficher avec leur rang. Écrire l'algorithme complet.
\tcblower
\textbf{Analyse :} $N = 30$ (constant), Type = \texttt{Entier} (notes entières sur 20). On utilise un tableau \texttt{Notes[1..30]}.
\medskip
\textbf{Algorithme :}
\begin{lstlisting}[language=Pascal]
Algorithme GestionNotes
Constante
    MAX_ELEVES = 30
Variables
    Notes : Tableau[1..MAX_ELEVES] de Entier
    i : Entier
Début
    // Saisie
    Pour i de 1 à MAX_ELEVES faire
        Écrire("Note de l'élève n°", i, " (sur 20) : ")
        Lire(Notes[i])
        // Optionnel : validation 0 <= Notes[i] <= 20
    FinPour

    // Affichage avec rang
    Écrire("--- LISTE DES NOTES ---")
    Pour i de 1 à MAX_ELEVES faire
        Écrire("Rang ", i, " : ", Notes[i], "/20")
    FinPour
Fin
\end{lstlisting}
\medskip
\textbf{Conclusion :} L'algorithme structure les données dans un tableau, garantit l'ordre de saisie (rang = indice) et permet un traitement ultérieur (moyenne, max, recherche).
\end{exoresolu}

\courssub{Manipuler un enregistrement (structure hétérogène)}

\begin{methode}[Déclaration et accès aux champs d'un enregistrement]
\textbf{Objectif :} Regrouper des informations de types différents décrivant une même entité réelle (un élève, un livre, un employé).\par
\medskip
\textbf{Étapes :}
\begin{enumerate}
    \item \textbf{Modéliser l'entité :} Lister les attributs (Nom: Chaîne, Âge: Entier, Moyenne: Réel).
    \item \textbf{Déclarer le type Enregistrement :}
    \texttt{Type Eleve = Enregistrement\\ Nom : Chaîne\\ Age : Entier\\ Moyenne : Réel\\ FinEnregistrement}
    \item \textbf{Déclarer une variable de ce type :} \texttt{UnEleve : Eleve}.
    \item \textbf{Accéder à un champ :} Notation pointée \texttt{Variable.Champ} (ex: \texttt{UnEleve.Nom}, \texttt{UnEleve.Moyenne}).
    \item \textbf{Saisir/Afficher :} Traiter chaque champ indépendamment avec \texttt{Lire} / \texttt{Écrire}.
\end{enumerate}
\medskip
\textbf{Attention :} On ne peut pas écrire \texttt{Lire(UnEleve)} ni \texttt{Écrire(UnEleve)} globalement en pseudo-code standard Bac. Il faut traiter champ par champ.
\end{methode}

\begin{exoresolu}[Fiche élève pour le bulletin numérique MINEDUB]
\textbf{Énoncé :} Définir un type \texttt{Eleve} contenant : Matricule (chaîne 10 car.), Nom (chaîne), Prénom (chaîne), Série (chaîne : "C", "D" ou "E"), MoyenneAnnuelle (réel). Écrire l'algorithme qui saisit les infos d'un élève et affiche son admission au Bac (Admis si Moyenne $\ge$ 10, Ajourné sinon).
\tcblower
\textbf{Algorithme :}
\begin{lstlisting}[language=Pascal]
Algorithme BulletinEleve
Type
    Eleve = Enregistrement
        Matricule : Chaîne
        Nom : Chaîne
        Prenom : Chaîne
        Serie : Chaîne
        MoyenneAnnuelle : Réel
    FinEnregistrement

Variables
    E : Eleve
    Decision : Chaîne
Début
    Écrire("--- SAISIE FICHE ÉLÈVE ---")
    Écrire("Matricule : "); Lire(E.Matricule)
    Écrire("Nom : "); Lire(E.Nom)
    Écrire("Prénom : "); Lire(E.Prenom)
    Écrire("Série (C/D/E) : "); Lire(E.Serie)
    Écrire("Moyenne Annuelle : "); Lire(E.MoyenneAnnuelle)

    Si E.MoyenneAnnuelle >= 10 Alors
        Decision <- "ADMIS AU BACCALAURÉAT"
    Sinon
        Decision <- "AJOURNÉ"
    FinSi

    Écrire("")
    Écrire("=== BULLETIN OFFICIEL ===")
    Écrire("Matricule : ", E.Matricule)

\end{exoresolu}

\courssub{Écrire et exécuter la recherche séquentielle (avec témoin)}

\begin{methode}[Algorithme de recherche séquentielle dans un tableau non trié]
\textbf{Objectif :} Trouver la position d'une valeur \texttt{Val} dans \texttt{Tab[1..N]} ou signaler son absence.\par
\medskip
\textbf{Principe :} Parcourir le tableau du premier au dernier élément. S'arrêter dès qu'on trouve \texttt{Val} (optimisation) ou à la fin.
\medskip
\textbf{Étapes (avec drapeau/témoin \texttt{Trouv} Booléen) :}
\begin{enumerate}
    \item \texttt{Trouv $\leftarrow$ Faux} ; \texttt{Pos $\leftarrow$ 0}.
    \item \texttt{i $\leftarrow$ 1}.
    \item \textbf{Tant que} (\texttt{i $\le$ N} \textbf{et} \texttt{Trouv = Faux}) \textbf{faire}
    \begin{itemize}
        \item \textbf{Si} \texttt{Tab[i] = Val} \textbf{alors} \texttt{Trouv $\leftarrow$ Vrai} ; \texttt{Pos $\leftarrow$ i}
        \item \textbf{Sinon} \texttt{i $\leftarrow$ i + 1}
    \end{itemize}
    \item \textbf{FinTantQue}
    \item \textbf{Si} \texttt{Trouv} \textbf{alors} \texttt{Écrire("Trouvé à l'indice ", Pos)} \textbf{sinon} \texttt{Écrire("Non trouvé")}.
\end{enumerate}
\medskip
\textbf{Variante "Pour" (moins efficace car parcourt tout) :} Boucle \texttt{Pour i de 1 à N}, test \texttt{Si Tab[i]=Val}, stockage indice, drapeau. La version \texttt{TantQue} s'arrête dès la première occurrence (complexité meilleur cas $\mathcal{O}(1)$).
\end{methode}

\begin{exoresolu}[Recherche d'un matricule dans la base des inscrits à l'Université de Yaoundé I]
\textbf{Énoncé :} Un tableau \texttt{Matricules[1..100]} contient les numéros d'inscription (entiers) de 100 étudiants. Écrire l'algorithme de recherche séquentielle d'un matricule saisi par l'utilisateur. Exécuter pas à pas sur l'exemple : \texttt{Tab = [105, 210, 305, 420, 501]}, \texttt{N=5}, \texttt{Val=305}.
\tcblower
\textbf{Algorithme général :}
\begin{lstlisting}[language=Pascal]
Algorithme RechercheSequentielle
Constante TAILLE = 100
Variables
    Tab : Tableau[1..TAILLE] de Entier
    N, i, Val, Pos : Entier
    Trouv : Booléen
Début
    // ... Saisie de N (<=TAILLE) et remplissage Tab ...
    Écrire("Matricule à rechercher : "); Lire(Val)

    Trouv <- Faux
    Pos <- 0
    i <- 1
    TantQue (i <= N) ET (Trouv = Faux) Faire
        Si Tab[i] = Val Alors
            Trouv <- Vrai
            Pos <- i
        Sinon
            i <- i + 1
        FinSi
    FinTantQue

    Si Trouv Alors
        Écrire("Étudiant trouvé à l'indice ", Pos)
    Sinon
        Écrire("Matricule introuvable dans la base.")
    FinSi
Fin
\end{lstlisting}
\medskip
\textbf{Exécution pas à pas (Table d'exécution) pour Val=305 :}
\begin{center}
\begin{tabular}{|c|c|c|c|c|c|c|}
\hline
\textbf{Ligne} & \textbf{Instruction} & \textbf{i} & \textbf{Tab[i]} & \textbf{Val} & \textbf{Trouv} & \textbf{Pos} \\
\hline
1 & Initialisation & 1 & 105 & 305 & F & 0 \\
2 & Test TantQue (1<=5 et F) & 1 & 105 & 305 & F & 0 \\
3 & Si 105=305 ? Non & 1 & 105 & 305 & F & 0 \\
4 & i <- 2 & 2 & 210 & 305 & F & 0 \\
5 & Test TantQue (2<=5 et F) & 2 & 210 & 305 & F & 0 \\
6 & Si 210=305 ? Non & 2 & 210 & 305 & F & 0 \\
7 & i <- 3 & 3 & 305 & 305 & F & 0 \\
8 & Test TantQue (3<=5 et F) & 3 & 305 & 305 & F & 0 \\
9 & Si 305=305 ? \textbf{OUI} & 3 & 305 & 305 & \textbf{V} & \textbf{3} \\
10 & FinTantQue (Trouv=V) $\rightarrow$ Sortie & - & - & - & V & 3 \\
\hline
\end{tabular}
\end{center}
\textbf{Conclusion :} L'algorithme s'arrête à l'indice 3. L'étudiant est trouvé. La table d'exécution prouve la correction de la logique booléenne.
\end{exoresolu}

\courssub{Écrire et exécuter le tri par insertion}

\begin{methode}[Algorithme de tri par insertion (ordre croissant)]
\textbf{Objectif :} Réorganiser \texttt{Tab[1..N]} pour que \texttt{Tab[1] $\le$ Tab[2] $\le$ ... $\le$ Tab[N]}.\par
\medskip
\textbf{Invariant de boucle :} À l'étape \texttt{i}, le sous-tableau \texttt{Tab[1..i-1]} est trié. On insère \texttt{Tab[i]} à sa place dans cette partie triée.
\medskip
\textbf{Étapes :}
\begin{enumerate}
    \item \textbf{Pour} \texttt{i de 2 à N} \textbf{faire} (on commence à 2, car \texttt{Tab[1]} est "trié" tout seul).
    \item \texttt{Cle $\leftarrow$ Tab[i]} (sauvegarde de la valeur à insérer).
    \item \texttt{j $\leftarrow$ i - 1} (dernier indice de la zone triée).
    \item \textbf{Tant que} (\texttt{j $\ge$ 1} \textbf{et} \texttt{Tab[j] > Cle}) \textbf{faire} \textit{(décalage vers la droite)}
    \begin{itemize}
        \item \texttt{Tab[j+1] $\leftarrow$ Tab[j]}
        \item \texttt{j $\leftarrow$ j - 1}
    \end{itemize}
    \item \textbf{FinTantQue}
    \item \texttt{Tab[j+1] $\leftarrow$ Cle} (insertion à la place libérée).
    \item \textbf{FinPour}
\end{enumerate}
\medskip
\textbf{Point clé :} La condition \texttt{Tab[j] > Cle} (strict) garantit la \textbf{stabilité} (ordre relatif des égaux conservé). Si \texttt{>=}, le tri devient instable.
\end{methode}

\begin{exoresolu}[Classement des ventes journalières d'une boutique à Douala Akwa]
\textbf{Énoncé :} On a les ventes (en milliers FCFA) sur 6 jours : \texttt{Ventes = [45, 12, 78, 12, 33, 60]}. Appliquer le tri par insertion. Montrer l'état du tableau après chaque passage de la boucle principale (\texttt{i=2..6}).
\tcblower
\textbf{Exécution pas à pas (Trace complète) :}
\textbf{État initial :} \texttt{[45, 12, 78, 12, 33, 60]}

\begin{itemize}
    \item \textbf{i=2} : \texttt{Cle=12}. \texttt{j=1}. \texttt{Tab[1]=45 > 12} ? Oui. Décale : \texttt{Tab[2]=45}. \texttt{j=0}. Fin TantQue. \texttt{Tab[1]=12}. $\rightarrow$ \textbf{[12, 45, 78, 12, 33, 60]}
    \item \textbf{i=3} : \texttt{Cle=78}. \texttt{j=2}. \texttt{Tab[2]=45 > 78} ? Non. Fin TantQue immédiat. \texttt{Tab[3]=78}. $\rightarrow$ \textbf{[12, 45, 78, 12, 33, 60]} (inchangé)
    \item \textbf{i=4} : \texttt{Cle=12}. \texttt{j=3}. \texttt{Tab[3]=78 > 12} ? Oui. \texttt{Tab[4]=78}. \texttt{j=2}. \texttt{Tab[2]=45 > 12} ? Oui. \texttt{Tab[3]=45}. \texttt{j=1}. \texttt{Tab[1]=12 > 12} ? Non (strict). Fin. \texttt{Tab[2]=12}. $\rightarrow$ \textbf{[12, 12, 45, 78, 33, 60]} \textit{(Stabilité : le 12 d'indice 4 passe APRÈS le 12 d'indice 1)}.
    \item \textbf{i=5} : \texttt{Cle=33}. \texttt{j=4}. \texttt{78>33} ? Oui \texttt{Tab[5]=78}. \texttt{j=3}. \texttt{45>33} ? Oui \texttt{Tab[4]=45}. \texttt{j=2}. \texttt{12>33} ? Non. \texttt{Tab[3]=33}. $\rightarrow$ \textbf{[12, 12, 33, 45, 78, 60]}
    \item \textbf{i=6} : \texttt{Cle=60}. \texttt{j=5}. \texttt{78>60} ? Oui \texttt{Tab[6]=78}. \texttt{j=4}. \texttt{45>60} ? Non. \texttt{Tab[5]=60}. $\rightarrow$ \textbf{[12, 12, 33, 45, 60, 78]}
\end{itemize}
\medskip
\textbf{Tableau final trié :} \texttt{[12, 12, 33, 45, 60, 78]}.
\textbf{Conclusion :} Le tri place les ventes du plus faible au plus fort. Les deux jours à 12 conservent leur ordre relatif (stabilité).
\end{exoresolu}

\courssub{Résoudre un problème concret : Recherche + Comptage}

\begin{methode}[Résolution de problème "Recherche/Comptage dans un tableau"]
\textbf{Approche type Bac :}
\begin{enumerate}
    \item \textbf{Analyse :} Identifier les données d'entrée (tableau, taille, critère), les sorties (position, nombre, booléen), les traitements (parcours, test).
    \item \textbf{Choix structure :} Tableau 1D si données homogènes. Enregistrement si entité complexe (mais alors tableau d'enregistrements).
    \item \textbf{Algorithme :} Déclarer $\rightarrow$ Saisir/Initialiser $\rightarrow$ Traiter (Boucle + Si) $\rightarrow$ Afficher résultat.
    \item \textbf{Test de bord :} Tableau vide ($N=0$), Valeur absente, Valeur présente multiples fois (première ? toutes ?).
\end{enumerate}
\medskip
\textbf{Patron "Comptage d'occurrences" :}
\texttt{Nb $\leftarrow$ 0 ; Pour i de 1 à N faire Si Tab[i]=Val Alors Nb $\leftarrow$ Nb+1 FinSi FinPour}
\end{methode}

\begin{exoresolu}[Analyse des résultats du Baccalauréat - Session Juin]
\textbf{Énoncé :} Un tableau \texttt{Notes[1..50]} contient les notes de SVT (sur 20) des 50 élèves d'une série D. Écrire un algorithme qui :
\begin{enumerate}
    \item Calcule et affiche la moyenne de la classe.
    \item Compte et affiche le nombre d'élèves ayant une note $\ge$ 10 (admis) et $<$ 10 (ajournés).
    \item Trouve et affiche la note maximale et l'indice (rang) du premier élève l'ayant obtenue.
\end{enumerate}
\tcblower
\textbf{Algorithme :}
\begin{lstlisting}[language=Pascal]
Algorithme StatsBacSVT
Constante MAX = 50
Variables
    Notes : Tableau[1..MAX] de Entier
    i, N, Somme, NbAdmis, NbAjournes, MaxNote, IndiceMax : Entier
    Moyenne : Réel
Début
    // Initialisation & Saisie N (supposé <= MAX)
    Écrire("Effectif réel (<=50) : "); Lire(N)
    Somme <- 0
    Pour i de 1 à N faire
        Écrire("Note élève ", i, " : "); Lire(Notes[i])
        Somme <- Somme + Notes[i]
    FinPour

    // 1. Moyenne
    Moyenne <- Somme / N
    Écrire("Moyenne classe : ", Moyenne:0:2)

    // 2. Comptage Admis/Ajournés
    NbAdmis <- 0
    NbAjournes <- 0
    Pour i de 1 à N faire
        Si Notes[i] >= 10 Alors NbAdmis <- NbAdmis + 1
        Sinon NbAjournes <- NbAjournes + 1
        FinSi
    FinPour
    Écrire("Admis : ", NbAdmis, " | Ajournés : ", NbAjournes)

    // 3. Maximum et Premier Indice (Recherche du Max + Position)
    MaxNote <- Notes[1]
    IndiceMax <- 1
    Pour i de 2 à N faire
        Si Notes[i] > MaxNote Alors
            MaxNote <- Notes[i]
            IndiceMax <- i
        FinSi
    FinPour
    Écrire("Meilleure note : ", MaxNote, " (Élève n°", IndiceMax, ")")
Fin
\end{lstlisting}
\medskip
\textbf{Justification :}
\begin{itemize}
    \item Une seule boucle de saisie cumule la somme (efficacité).
    \item Boucle séparée pour comptage (clarté), ou fusionnable.
    \item Recherche du Max : initialisation avec le premier élément (\texttt{Notes[1]}), boucle à partir de 2. Condition stricte \texttt{>} pour garder le \textbf{premier} indice en cas d'égalité.
\end{itemize}
\end{exoresolu}

\courssub{Résoudre un problème concret : Tri + Médiane}

\begin{methode}[Résolution de problème "Tri + Statistique de position (Médiane)"]
\textbf{Approche :}
\begin{enumerate}
    \item Trier le tableau (Insertion ou Bulle/Selection si demandé).
    \item Déterminer la médiane selon la parité de $N$ :
    \begin{itemize}
        \item $N$ impair : Médiane = \texttt{Tab[(N+1)/2]} (indice entier).
        \item $N$ pair : Médiane = \texttt{(Tab[N/2] + Tab[N/2 + 1]) / 2}.
    \end{itemize}
    \item Attention : Indices 1-based (Bac). En C (0-based) : indices \texttt{(N-1)/2} et \texttt{N/2}.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Calcul de la médiane des salaires d'une PME camerounaise]
\textbf{Énoncé :} On dispose des salaires mensuels (en milliers FCFA) de 7 employés : \texttt{Salaires = [150, 350, 200, 500, 250, 180, 400]}.
\begin{enumerate}
    \item Trier ce tableau par insertion (donner l'état final).
    \item Calculer la médiane de cette série statistique.
    \item Écrire l'algorithme général pour $N$ salaires.
\end{enumerate}
\tcblower
\textbf{1. Tri par insertion (résumé des états finaux par passage) :}
Initial : \texttt{[150, 350, 200, 500, 250, 180, 400]}
i=2 (Cle=350) : \texttt{[150, 350, 200, 500, 250, 180, 400]}
i=3 (Cle=200) : \texttt{[150, 200, 350, 500, 250, 180, 400]}
i=4 (Cle=500) : \texttt{[150, 200, 350, 500, 250, 180, 400]}
i=5 (Cle=250) : \texttt{[150, 200, 250, 350, 500, 180, 400]}
i=6 (Cle=180) : \texttt{[150, 180, 200, 250, 350, 500, 400]}
i=7 (Cle=400) : \texttt{[150, 180, 200, 250, 350, 400, 500]}
\textbf{Tableau trié :} \texttt{[150, 180, 200, 250, 350, 400, 500]}

\medskip
\textbf{2. Médiane :} $N=7$ (impair). Position centrale = $(7+1)/2 = 4^{\text{ème}}$ valeur.
\texttt{Tab[4] = 250}.
\textbf{Médiane = 250 000 FCFA.}

\medskip
\textbf{3. Algorithme Général :}
\begin{lstlisting}[language=Pascal]
Algorithme MedianeSalaires
Variables
    Sal : Tableau[1..100] de Entier // Taille max
    N, i, j, Cle, Mediane : Entier
    MedianeReelle : Réel
Début
    // Saisie N et Tableau ...
    // TRI PAR INSERTION
    Pour i de 2 à N faire
        Cle <- Sal[i]
        j <- i - 1
        TantQue (j >= 1) ET (Sal[j] > Cle) faire
            Sal[j+1] <- Sal[j]
            j <- j - 1
        FinTantQue
        Sal[j+1] <- Cle
    FinPour

    // CALCUL MÉDIANE
    Si N Mod 2 = 1 Alors // N impair (Modulo standard pseudo-code)
        Mediane <- Sal[(N+1)/2]
        Écrire("Médiane = ", Mediane)
    Sinon // N pair
        MedianeReelle <- (Sal[N/2] + Sal[N/2 + 1]) / 2.0
        Écrire("Médiane = ", MedianeReelle:0:2)
    FinSi
Fin
\end{lstlisting}
\textbf{Note :} L'opérateur \texttt{Mod} (modulo) teste la parité. La division \texttt{/ 2.0} force le calcul réel pour la médiane paire.
\end{exoresolu}

\courssub{Construire et exploiter une table d'exécution complète}

\begin{methode}[Construction rigoureuse d'une table d'exécution (Trace)]
\textbf{Objectif :} Prouver le fonctionnement d'un algorithme (boucles, conditions, modifications variables) pour le Bac (souvent 4 à 6 points).\par
\medskip
\textbf{Colonnes obligatoires :}
\begin{enumerate}
    \item \textbf{Ligne / N° Instruction} : Numéro de la ligne exécutée (selon numérotation de l'énoncé).
    \item \textbf{Instruction} : Libellé court de l'action (ex: \texttt{i$\leftarrow$1}, \texttt{Si Tab[i]>Max}).
    \item \textbf{Variables modifiées} : Une colonne par variable qui \textbf{change de valeur} dans l'algorithme (indices de boucle, accumulateurs, drapeaux, résultat). Ne pas mettre les constantes ni les variables inchangées.
    \item \textbf{Écran / Sortie} : Ce qui s'affiche (\texttt{Écrire}) à cet instant précis.
\end{enumerate}
\medskip
\textbf{Règles d'or :}
\begin{itemize}
    \item Une ligne du tableau = Une exécution d'une instruction (pas une itération complète de boucle).
    \item Initialiser la première ligne avec les valeurs de départ (après saisie/Début).
    \item Ne pas sauter les lignes de test (\texttt{Si}, \texttt{TantQue}, \texttt{Pour}) : elles font partie du flux.
    \item Arrêter la trace quand la condition d'arrêt est remplie ou à la fin de l'algorithme.
\end{itemize}
\end{methode}

\begin{exoresolu}[Trace complète : Recherche du maximum dans un tableau]
\textbf{Énoncé :} Soit l'algorithme suivant (indices 1..N). Construire la table d'exécution complète pour \texttt{N=4}, \texttt{Tab = [12, 25, 25, 10]}.
\begin{lstlisting}[language=Pascal, numbers=left]
Algorithme MaxTableau
Variables Tab[1..4] : Entier; N, i, Max, Pos : Entier
Début
    N <- 4
    Tab[1]<-12; Tab[2]<-25; Tab[3]<-25; Tab[4]<-10 // Initialisation fixe pour trace
    Max <- Tab[1]      // L1
    Pos <- 1           // L2
    Pour i de 2 à N faire  // L3
        Si Tab[i] > Max alors // L4
            Max <- Tab[i]     // L5
            Pos <- i          // L6
        FinSi                // L7
    FinPour                  // L8
    Écrire(Max, Pos)         // L9
Fin
\end{lstlisting}
\tcblower
\textbf{Table d'exécution :}
\begin{center}
\begin{tabular}{|c|l|c|c|c|c|c|}
\hline
\textbf{Ligne} & \textbf{Instruction} & \textbf{i} & \textbf{Max} & \textbf{Pos} & \textbf{Tab[i]} & \textbf{Écran} \\
\hline
L1 & Max $\leftarrow$ Tab[1] & - & 12 & - & 12 & \\
L2 & Pos $\leftarrow$ 1 & - & 12 & 1 & - & \\
L3 & Pour i=2 (init) & 2 & 12 & 1 & 25 & \\
L4 & Si Tab[2] > Max (25>12) ? V & 2 & 12 & 1 & 25 & \\
L5 & Max $\leftarrow$ Tab[2] & 2 & \textbf{25} & 1 & 25 & \\
L6 & Pos $\leftarrow$ 2 & 2 & 25 & \textbf{2} & 25 & \\
L7 & FinSi & 2 & 25 & 2 & - & \\
L3 & Pour i=3 (incr) & 3 & 25 & 2 & 25 & \\
L4 & Si Tab[3] > Max (25>25) ? F & 3 & 25 & 2 & 25 & \\
L7 & FinSi & 3 & 25 & 2 & - & \\
L3 & Pour i=4 (incr) & 4 & 25 & 2 & 10 & \\
L4 & Si Tab[4] > Max (10>25) ? F & 4 & 25 & 2 & 10 & \\
L7 & FinSi & 4 & 25 & 2 & - & \\
L3 & FinPour (i=5 > N) & - & 25 & 2 & - & \\
L9 & Écrire(Max, Pos) & - & 25 & 2 & - & \textbf{25 2} \\
\hline
\end{tabular}
\end{center}
\textbf{Analyse :} L'algorithme retourne \texttt{Max=25, Pos=2}. La condition stricte \texttt{>} conserve la position de la \textbf{première} occurrence du maximum (indice 2), ignorant la seconde (indice 3). La trace valide ce comportement.
\end{exoresolu}

\begin{attention}[Les 5 erreurs qui coûtent des points au Bac]
\begin{enumerate}
    \item \textbf{Indices de tableau :} Confondre base 1 (Pseudo-code Bac) et base 0 (Langage C). \textbf{Règle :} En pseudo-code officiel Cameroun, les tableaux sont indicés de \textbf{1 à N}. Écrire \texttt{Pour i de 0 à N-1} en pseudo-code est une \textbf{erreur majeure}. En C, c'est l'inverse.
    \item \textbf{Drapeau (Témoin) non initialisé :} Oublier \texttt{Trouv $\leftarrow$ Faux} avant la boucle de recherche. La variable contient une valeur aléatoire $\rightarrow$ logique imprévisible.
    \item \textbf{Condition de boucle \texttt{TantQue} inversée :} Écrire \texttt{TantQue (Trouv) Faire} au lieu de \texttt{TantQue (Non Trouv) Faire} ou \texttt{TantQue (i<=N ET Non Trouv)}. Cela fait soit 0 tour, soit boucle infinie.
    \item \textbf{Décalage dans Tri Insertion :} Écrire \texttt{Tab[j] $\leftarrow$ Tab[j+1]} (vers la gauche) au lieu de \texttt{Tab[j+1] $\leftarrow$ Tab[j]} (vers la droite pour faire de la place). Perte de données garantie.
    \item \textbf{Table d'exécution incomplète :} Ne pas tracer les lignes de test (\texttt{Si}, \texttt{TantQue}, \texttt{FinPour}) ou ne pas mettre la valeur de \texttt{Tab[i]} dans une colonne dédiée quand elle est utilisée dans un test. Le correcteur ne peut pas suivre le raisonnement $\rightarrow$ 0 point sur la trace.
\end{enumerate}
\end{attention}

\begin{corrige}[Exercice 1 — QCM : structure d'un algorithme et tableaux]
\textbf{Réponse exacte : la proposition 2.}

\begin{itemize}
    \item \textbf{Proposition 1 — Fausse.} La déclaration \texttt{Tableau T[10] : Entier} réserve bien 10 cases, mais en indexation \cle{base 0} (convention du langage C), les indices vont de \texttt{0} à \texttt{9}, et non de 1 à 10. La proposition serait vraie uniquement en indexation base 1 (pseudo-code classique au Bac).
    \item \textbf{Proposition 2 — Vraie.} En indexation base 0, la première case du tableau porte l'indice \texttt{0}. L'instruction \texttt{T[0] $\leftarrow$ 5} affecte donc correctement la valeur 5 à la première case. C'est la seule proposition exacte dans ce contexte.
    \item \textbf{Proposition 3 — Fausse.} La boucle \texttt{Pour i $\leftarrow$ 1 à 10 Faire} exécute son corps pour $i = 1, 2, \dots, 10$, soit $10 - 1 + 1 = 10$ itérations, et non 9.
    \item \textbf{Proposition 4 — Fausse.} C'est précisément l'intérêt de l'\cle{enregistrement} : il regroupe des champs de types \emph{différents} (par exemple un nom de type chaîne, un prix de type réel, une quantité de type entier). La structure qui impose l'homogénéité des types est le \emph{tableau}, pas l'enregistrement.
\end{itemize}

\textbf{Point de vigilance :} au Bac, lis toujours attentivement la convention d'indexation (base 0 ou base 1) indiquée dans l'énoncé. En pseudo-code algorithmique (épreuve écrite), l'indexation base 1 (\texttt{1..N}) est la norme ; en langage C (épreuve pratique), c'est systématiquement la base 0 (\texttt{0..N-1}).
\end{corrige}

\begin{corrige}[Exercice 2 — Vrai ou Faux : recherche séquentielle]
\begin{enumerate}
    \item \textbf{Faux.} La recherche \cle{séquentielle} parcourt le tableau élément par élément dans l'ordre : elle ne suppose \emph{aucun} ordre préalable. C'est la recherche \emph{dichotomique} (hors programme) qui exige un tableau trié.
    \item \textbf{Faux.} Le drapeau est initialisé à \texttt{Faux} avant la boucle : il signifie « pas encore trouvé ». Il ne passe à \texttt{Vrai} que lorsqu'on rencontre la valeur cherchée. L'initialiser à \texttt{Vrai} empêcherait la boucle de s'exécuter (voir la condition de la question 4).
    \item \textbf{Vrai.} Dès que \texttt{T[i] = Val}, le drapeau passe à \texttt{Vrai}, la condition \texttt{(drapeau = Faux)} devient fausse et la boucle s'arrête immédiatement : on obtient donc la \emph{première} occurrence.
    \item \textbf{Vrai.} On continue tant que deux conditions sont réunies : on n'a pas dépassé la fin du tableau (\texttt{i $\le$ N}) \emph{et} on n'a pas encore trouvé (\texttt{drapeau = Faux}). Les deux conditions sont indispensables : la première évite le débordement d'indice, la seconde permet l'arrêt anticipé.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 3 — Définitions et vocabulaire]
\begin{enumerate}
    \item \textbf{Enregistrement (type structuré) :} structure de données finie qui regroupe sous un même nom plusieurs variables appelées \cle{champs}, pouvant être de types différents. Chaque champ est accessible individuellement par la notation pointée : \texttt{Variable.NomDuChamp}.
    \item \textbf{Parcours d'un tableau :} action d'accéder successivement, au moyen d'une boucle (généralement \texttt{Pour}), à chacun des éléments du tableau, du premier au dernier indice, afin d'effectuer un traitement (lecture, affichage, recherche, somme\dots).
    \item \textbf{Table d'exécution (trace) :} tableau à colonnes (numéro de ligne ou instruction, valeurs des variables, affichages à l'écran) qui décrit l'évolution de l'état de la mémoire et des sorties au fil de l'exécution pas à pas d'un algorithme. C'est l'outil de vérification et de validation d'une solution algorithmique.
    \item \textbf{Complexité en temps du tri par insertion (pire des cas) :} dans le pire des cas (tableau trié en ordre \emph{décroissant}), chaque élément \texttt{T[i]} est comparé à tous les éléments de la partie déjà triée, soit $1 + 2 + \dots + (N-1) = \dfrac{N(N-1)}{2}$ comparaisons. La complexité en temps est donc \cle{quadratique} : $O(N^2)$.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 5 — Notes d'élèves : maximum et compteur de moyenne]
\begin{lstlisting}
Algorithme Notes_Classe
Constantes
    NB = 20
Variables
    Notes : Tableau [1..NB] d'Entier
    i, Max, NbMoyenne : Entier
Début
    // 1. Remplissage du tableau
    Pour i <- 1 à NB Faire
        Ecrire("Entrez la note de l'élève n° ", i, " : ")
        Lire(Notes[i])
    FinPour

    // 2. Initialisation du traitement
    Max <- Notes[1]
    NbMoyenne <- 0

    // 3. Parcours : maximum et compteur de moyenne
    Pour i <- 1 à NB Faire
        Si Notes[i] > Max Alors
            Max <- Notes[i]
        FinSi
        Si Notes[i] >= 10 Alors
            NbMoyenne <- NbMoyenne + 1
        FinSi
    FinPour

    // 4. Affichage des résultats
    Ecrire("La note maximale de la classe est : ", Max)
    Ecrire("Nombre d'élèves ayant la moyenne : ", NbMoyenne)
Fin
\end{lstlisting}

\begin{itemize}
    \item \texttt{Max} est initialisé à \texttt{Notes[1]} (et non à 0) : c'est la méthode correcte, qui fonctionne même si toutes les notes étaient négatives.

\begin{corrige}[Exercice 7 — Recherche séquentielle : algorithme complet et trace]
\textbf{1. Algorithme avec drapeau.}
\begin{lstlisting}
Algorithme Recherche_Sequentielle
Variables
    T : Tableau [1..10] d'Entier
    i, V : Entier

Début

    Ecrire("Valeur à chercher : ")

\begin{corrige}[Exercice 9 — Sujet type Bac : Correction d'algorithme et table d'exécution]
\textbf{1. Les trois erreurs (3 pts — 1 pt par erreur identifiée et expliquée).}
\begin{itemize}
    \item \textbf{Erreur 1 :} le drapeau \texttt{Trouve} n'est \textbf{jamais initialisé} avant la boucle. Il faut écrire \texttt{Trouve $\leftarrow$ Faux} avant le \texttt{TantQue}.

\begin{corrige}[Exercice 10 — Sujet type Bac : Tri par insertion et analyse]
\textbf{1. Algorithme du tri par insertion (3 pts).}
\begin{lstlisting}
Algorithme Tri_Insertion
Variables
    T : Tableau [1..N] d'Entier
    N, i, j, cle : Entier
Début
    // Remplissage du tableau omis
    Pour i <- 2 à N Faire
        cle <- T[i]
        j <- i - 1
        TantQue (j >= 1) ET (T[j] > cle) Faire
            T[j+1] <- T[j]   // décalage vers la droite
            j <- j - 1
        FinTantQue
        T[j+1] <- cle        // insertion de la clé
    FinPour
Fin
\end{lstlisting}

\textbf{2. Trace pas à pas (4 pts)} sur \texttt{T = [25, 12, 30, 7, 18]} :

\begin{center}
\begin{tabularx}{\linewidth}{|c|c|X|l|}
\hline
\rowcolor{popblueL}
\texttt{i} & \texttt{cle} & Tableau après insertion & Décalages effectués \\
\hline
2 & 12 & [12, 25, 30, 7, 18] & 25 \\
\hline
3 & 30 & [12, 25, 30, 7, 18] & aucun \\
\hline
4 & 7 & [7, 12, 25, 30, 18] & 30, 25, 12 \\
\hline
5 & 18 & [7, 12, 18, 25, 30] & 30, 25 \\
\hline
\end{tabularx}
\end{center}

Le tableau final trié est \texttt{[7, 12, 18, 25, 30]}.

\textbf{3. Complexité (1,5 pt).} Dans le pire des cas, la complexité en temps est $O(N^2)$ (quadratique), car le nombre de comparaisons vaut $1 + 2 + \dots + (N-1) = \dfrac{N(N-1)}{2}$. Ce pire cas se produit lorsque le tableau est initialement \textbf{trié en ordre décroissant} : chaque clé doit être comparée à \emph{tous} les éléments de la partie déjà triée.

\textbf{4. Tri « en place » (1,5 pt).} \textbf{Oui} : le tri par insertion est \cle{en place} car il ne nécessite aucun tableau auxiliaire ; les échanges se font directement dans le tableau \texttt{T}, avec seulement quelques variables supplémentaires (\texttt{cle}, \texttt{i}, \texttt{j}) dont le nombre ne dépend pas de $N$ (mémoire auxiliaire en $O(1)$).

\textbf{Points de vigilance (barème) :} la boucle externe doit démarrer à \texttt{i = 2} ; la sauvegarde \texttt{cle $\leftarrow$ T[i]} avant les décalages est obligatoire (sinon la valeur est écrasée) ; la condition du \texttt{TantQue} doit comporter \texttt{j >= 1} en premier pour éviter l'accès à \texttt{T[0]} ; pour la question 4, citer la mémoire auxiliaire constante est la justification attendue.
\end{corrige}

    Pour i <- 2 à NbClients Faire
        cle <- Clients[i]
        j <- i - 1
        TantQue (j >= 1) ET (Clients[j].DebitMbit < cle.DebitMbit) Faire
            Clients[j+1] <- Clients[j]
            j <- j - 1
        FinTantQue
        Clients[j+1] <- cle
    FinPour
Fin
\end{lstlisting}

\textbf{4. Statistiques (2 pts).}
\begin{lstlisting}
Algorithme Statistiques
Variables
    Clients : Tableau [1..50] d'Abonne
    NbClients, i, NbGrosDebit : Entier
    ChiffreAffaires : Réel
Début
    ChiffreAffaires <- 0
    NbGrosDebit <- 0
    Pour i <- 1 à NbClients Faire
        ChiffreAffaires <- ChiffreAffaires + Clients[i].Mensualite
        Si Clients[i].DebitMbit >= 100 Alors
            NbGrosDebit <- NbGrosDebit + 1
        FinSi
    FinPour
    Ecrire("Chiffre d'affaires mensuel : ", ChiffreAffaires, " FCFA")
    Ecrire("Abonnés avec débit >= 100 Mbit/s : ", NbGrosDebit)
Fin
\end{lstlisting}

\textbf{Points de vigilance (barème) :} question 2, la fonction doit retourner \texttt{0} en cas d'absence (et non un booléen) et ne pas incrémenter \texttt{i} lors de la découverte ; question 3, la clé \texttt{cle} doit être de type \texttt{Abonne} (on déplace des enregistrements entiers, pas seulement les débits, sinon les données seraient mélangées) et l'inversion du sens de tri se fait sur la comparaison \texttt{< cle.DebitMbit} ; question 4, les accumulateurs doivent être initialisés avant la boucle et la condition est \texttt{>= 100} (au sens large).
\end{corrige}

\begin{bilan}
\textbf{Définitions clés}
\begin{itemize}
    \item \cle{Algorithme} : Suite finie et ordonnée d'instructions permettant de résoudre un problème.
    \item \cle{Variable} : Zone mémoire nommée dont la valeur peut changer pendant l'exécution (\texttt{Variable Nom : Type}).
    \item \cle{Constante} : Valeur figée dès la déclaration (\texttt{Constante Nom = Valeur}).
    \item \cle{Tableau} : Structure indexée, collection ordonnée d'éléments de même type, accessibles par un indice (\texttt{Tab[1..N] : Type}).
    \item \cle{Enregistrement} : Structure finie hétérogène regroupant des champs nommés et typés (\texttt{Type Nom = Enregistrement ... Fin}).
    \item \cle{Recherche séquentielle} : Parcours linéaire d'un tableau jusqu'à trouver la valeur cherchée (ou épuiser le tableau). Utilise un \cle{booléen témoin} (\texttt{Trouve}).
    \item \cle{Tri par insertion} : Construction progressive de la zone triée : pour chaque nouvel élément (clé), décalage des éléments plus grands vers la droite.
    \item \cle{Table d'exécution} : Outil de traçage pas à pas (colonnes : N° ligne, Instruction, Variables modifiées, Écran).
\end{itemize}

\textbf{Méthodes express}
\begin{center}
\begin{tabularx}{\linewidth}{|>{\bfseries}l|X|}\hline
\textbf{Action} & \textbf{Étapes clés / Syntaxe} \\\hline
Déclarer \& parcourir un tableau & \texttt{Tab[1..N] : Entier} \\ \texttt{Pour i de 1 à N faire} \\ \quad \texttt{Lire(Tab[i]) / Afficher(Tab[i])} \\ \texttt{FinPour} \\\hline
Déclarer \& utiliser un enregistrement & \texttt{Type Eleve = Enregistrement} \\ \quad \texttt{Nom : Chaine} \\ \quad \texttt{Note : Reel} \\ \texttt{FinEnregistrement} \\ \texttt{Variable E : Eleve} \\ \quad \texttt{E.Nom $\leftarrow$ "Kamga"} \\\hline
Recherche séquentielle (avec drapeau) & \texttt{Trouve $\leftarrow$ Faux ; i $\leftarrow$ 1} \\ \texttt{Tant que (i $\le$ N) ET (Non Trouve) faire} \\ \quad \texttt{Si Tab[i] = Val alors Trouve $\leftarrow$ Vrai} \\ \quad \texttt{Sinon i $\leftarrow$ i + 1} \\ \texttt{FinTantQue} \\\hline
Tri par insertion & \texttt{Pour i de 2 à N faire} \\ \quad \texttt{Cle $\leftarrow$ Tab[i] ; j $\leftarrow$ i-1} \\ \quad \texttt{Tant que (j $\ge$ 1) ET (Tab[j] > Cle) faire} \\ \quad \quad \texttt{Tab[j+1] $\leftarrow$ Tab[j] ; j $\leftarrow$ j-1} \\ \quad \texttt{FinTantQue} \\ \quad \texttt{Tab[j+1] $\leftarrow$ Cle} \\ \texttt{FinPour} \\\hline

    \item $\square$ Je distingue \cle{Variable} (modifiable) et \cle{Constante} (figée) et je les déclare correctement.
    \item $\square$ Je déclare un tableau : \texttt{Tab[1..N] : Type} et je le parcours avec \texttt{Pour i de 1 à N}.
    \item $\square$ Je déclare un type \cle{Enregistrement} et j'accède à un champ par \texttt{Variable.Champ}.
    \item $\square$ J'écris l'algorithme de \cle{recherche séquentielle} avec un drapeau \texttt{Trouve} (booléen) et une boucle \texttt{Tant que}.
    \item $\square$ J'écris l'algorithme de \cle{tri par insertion} : boucle externe \texttt{Pour i de 2 à N}, clé, décalage dans \texttt{Tant que}, insertion finale.
    \item $\square$ Je construis une \cle{table d'exécution} rigoureuse (colonnes : Ligne, Instruction, Variables, Écran) sans sauter d'étape.
    \item $\square$ Je gère les cas limites : tableau vide ($N=0$), tableau à 1 élément, valeur non trouvée, tableau déjà trié.
    \item $\square$ Je connais les complexités : Recherche $O(n)$, Tri insertion $O(n^2)$ (pire cas), $O(n)$ (meilleur cas déjà trié).
    \item $\square$ Je traduis sans erreur l'algorithme en langage \texttt{C} (indices 0..N-1, \texttt{scanf}/\texttt{printf}, types \texttt{int}/\texttt{float}/\texttt{struct}).
    \item $\square$ Je justifie la correction de mes boucles (initialisation, condition d'arrêt, progression, invariants simples).
\end{itemize}
