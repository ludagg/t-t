\coursec{Premiers programmes en C : structure, types, entrées-sorties}

\textbf{Situation d'accroche.} Dans son quartier de Yaoundé, Mme Etoundi dirige une coopérative de tontine. Chaque fin de mois, c'est le même rituel : un gros cahier, une calculatrice, et des heures à vérifier les cotisations. Erreurs de calcul dans les totaux, recherches interminables pour retrouver un membre dans la liste, classement des cotisants refait à la main... Son fils, élève en Terminale TI, lui propose de tout automatiser avec un seul programme exécutable. Mais comment traduire en langage C les algorithmes qu'il a appris à écrire en Première ? Comment lire les montants saisis, calculer, trier les membres par ordre de cotisation et retrouver un nom en une fraction de seconde ? C'est toute la puissance de la programmation monoposte en C que cette leçon va dévoiler, jusqu'à la production d'un vrai programme compilé.

\textbf{Problématique.} Comment passer d'un algorithme écrit en pseudo-code à un programme C compilé, capable de lire des données au clavier, de calculer et d'afficher des résultats ?

\courssub{Le langage C : un langage compilé de bas niveau}

\begin{definition}[Programme]
Un \cle{programme} est une suite d'instructions écrites dans un langage de programmation, destinée à être exécutée par un ordinateur pour réaliser automatiquement une tâche (calculs, saisies, tris, recherches...). Un programme \cle{monoposte} s'exécute sur une seule machine, sans réseau.
\end{definition}

En Première, tu as écrit des algorithmes en pseudo-code : l'ordinateur ne peut pas les exécuter directement. Il faut les \emph{traduire} dans un langage réel. Le \cle{langage C} est un langage \textbf{compilé} et de \textbf{bas niveau} : il est proche de la machine (gestion fine de la mémoire, rapidité d'exécution), ce qui le rend idéal pour écrire des programmes performants.

\begin{definition}[Compilation]
La \cle{compilation} est la traduction complète du code source (fichier \texttt{.c}) en langage machine par un programme appelé \cle{compilateur} (par exemple \texttt{gcc}). Contrairement à un langage interprété, le programme C est traduit \emph{une fois pour toutes} : on obtient un fichier \textbf{exécutable} (\texttt{.exe} sous Windows) qui peut être lancé sans le code source.
\end{definition}

La production d'un exécutable se déroule en quatre étapes principales :

\begin{enumerate}
\item \textbf{Prétraitement (précompilation)} : le préprocesseur traite les directives commençant par \texttt{\#} (\texttt{\#include}, \texttt{\#define}) et produit un code source \emph{étendu} (sans commentaires, avec les en-têtes insérés et les macros remplacées).
\item \textbf{Compilation (proprement dite)} : le compilateur traduit le code source étendu en \textbf{code assembleur}, puis l'assembleur génère le \textbf{fichier objet} (\texttt{.o} ou \texttt{.obj}) : du code machine non encore lié. Les erreurs de syntaxe sont détectées ici.
\item \textbf{Édition de liens} : l'\textbf{éditeur de liens} (\emph{linker}) assemble les fichiers objets et les bibliothèques standards (comme \texttt{stdio}, \texttt{math}) pour produire l'exécutable final. Les erreurs de \emph{référence non résolue} (fonction utilisée mais non définie) apparaissent ici.
\item \textbf{Exécution} : le système d'exploitation charge l'exécutable en mémoire et lance le programme.
\end{enumerate}

Cinquante ans plus tard, il est toujours au cœur de l'informatique mondiale : le noyau \textbf{Linux} est écrit en C, et la plupart des téléphones \textbf{Android} reposent sur ce noyau. \courssub{Prise en main d'un IDE : Code::Blocks}

Pour écrire, compiler et exécuter un programme C, on utilise un \cle{IDE} (\emph{Environnement de Développement Intégré}) comme \textbf{Code::Blocks} ou \textbf{Dev-C++}, qui regroupe l'éditeur de texte, le compilateur (généralement GCC via MinGW sous Windows) et le débogueur.

\begin{methode}[Créer et exécuter un premier programme sous Code::Blocks]
\begin{enumerate}
\item \textbf{Créer un projet} : menu \texttt{File > New > Project}, choisir \texttt{Console application}, langage \texttt{C}, puis donner un nom au projet (ex. \texttt{Tontine}). Choisir le compilateur \texttt{GNU GCC Compiler}.
\item \textbf{Écrire le code} : ouvrir le fichier \texttt{main.c} dans l'éditeur et saisir le programme.
\item \textbf{Compiler} : appuyer sur \texttt{F9} (\texttt{Build}) ; la fenêtre \emph{Build log} affiche les erreurs éventuelles avec le numéro de ligne. Si le projet utilise \texttt{math.h}, vérifier que l'option \texttt{Linker settings > Add} contient \texttt{m} (libm) — souvent automatique.
\item \textbf{Exécuter} : appuyer sur \texttt{Ctrl+F10} (ou \texttt{F9} si tout est déjà compilé) ; une console noire s'ouvre et affiche les résultats.
\item \textbf{Exécuter pas à pas} : placer un point d'arrêt (clic à gauche du numéro de ligne), lancer le débogueur avec \texttt{F8}, puis avancer instruction par instruction avec \texttt{F7} en observant les valeurs des variables dans la fenêtre \emph{Watches}.
\end{enumerate}
\end{methode}

L'exécution pas à pas avec le débogueur est un savoir-faire essentiel : elle permet de \emph{voir} le programme vivre, de comprendre l'ordre d'exécution des instructions et de traquer les bugs.

\courssub{Structure minimale d'un programme C}

Tout programme C, même le plus petit, respecte une architecture fixe :

\begin{lstlisting}[language=C]
#include <stdio.h>   // bibliotheque des entrees-sorties

int main()           // fonction principale : point d'entree du programme
{
    printf("Bonjour la Tontine !\\ ");   // instruction d'affichage
    return 0;        // le programme signale qu'il s'est bien termine
}
\end{lstlisting}

\begin{definition}[Bibliothèque]
Une \cle{bibliothèque} est un ensemble de fonctions prêtes à l'emploi, regroupées dans un fichier d'en-tête (\texttt{.h}). La directive \texttt{\#include <stdio.h>} donne accès aux fonctions d'entrée-sortie \texttt{printf} et \texttt{scanf} ; \texttt{\#include <math.h>} donne accès aux fonctions mathématiques (\texttt{sqrt}, \texttt{pow}, ...).
\end{definition}

\begin{propriete}[Règles de structure d'un programme C]
\begin{itemize}
\item La fonction \texttt{main()} est le \textbf{point d'entrée} : l'exécution commence toujours par sa première instruction.
\item Le corps d'une fonction est délimité par des \textbf{accolades} \texttt{\{ ... \}}.
\item Chaque instruction se termine par un \textbf{point-virgule} \texttt{;}.
\item \texttt{return 0;} indique au système que le programme s'est terminé sans erreur (code de retour \texttt{EXIT\_SUCCESS}).
\item Le C est \textbf{sensible à la casse} : \texttt{Main} et \texttt{main} sont différents.
\end{itemize}
\end{propriete}

\begin{attention}[Les deux erreurs du débutant]
\begin{itemize}
\item \textbf{Oublier le point-virgule} en fin d'instruction : le compilateur signale une erreur \emph{syntax error} souvent à la ligne \emph{suivante}. Vérifie toujours la ligne indiquée \textbf{et} la précédente.
\item \textbf{Oublier l'esperluette \texttt{\&} dans \texttt{scanf}} : le programme compile parfois sans erreur mais \emph{plante} à l'exécution (erreur de segmentation \texttt{SIGSEGV}) ou lit des valeurs absurdes. Détail plus bas.
\end{itemize}
\end{attention}

\courssub{Types de base, variables et constantes}

Un programme manipule des données : montants en FCFA, âges, notes, noms... Chaque donnée doit être rangée dans une \cle{variable} d'un \textbf{type} adapté, car le type détermine la place occupée en mémoire et les opérations autorisées.

\begin{center}
\begin{tabularx}{\linewidth}{|l|l|X|l|}
\hline
\rowcolor{popblueL} \textbf{Type} & \textbf{Taille usuelle} & \textbf{Plage / usage} & \textbf{Exemple} \\
\hline
\texttt{int} & 4 octets & entiers de $-2\,147\,483\,648$ à $2\,147\,483\,647$ & nombre de membres \\
\hline
\texttt{float} & 4 octets & réels, environ 7 chiffres significatifs & une note sur 20 \\
\hline
\texttt{double} & 8 octets & réels, environ 15 chiffres significatifs & montant en FCFA \\
\hline
\texttt{char} & 1 octet & un caractère (code ASCII) & \texttt{'M'} ou \texttt{'F'} \\
\hline
\end{tabularx}
\end{center}

\textbf{Choisir le bon type.} Pour l'âge d'un membre, un \texttt{int} suffit. Pour un montant de cotisation comme $25\,000,50$ FCFA, on préfère \texttt{double} (plus précis que \texttt{float}). Pour une note sur 20, \texttt{float} convient. Pour le sexe d'un membre, un \texttt{char}.

\begin{definition}[Identificateur]
Un \cle{identificateur} est le nom donné à une variable, une constante ou une fonction. Règles en C : il commence par une \textbf{lettre} ou un \textbf{souligné} \texttt{\_}, ne contient que des lettres, chiffres et \texttt{\_}, et ne doit pas être un mot réservé (\texttt{int}, \texttt{return}, \texttt{if}...). Convention : \texttt{montantCotisation}, \texttt{age\_membre}.
\end{definition}

\begin{propriete}[Déclaration de variables et de constantes]
\begin{itemize}
\item Variable : \texttt{type nom;} ou \texttt{type nom = valeur;} (déclaration avec initialisation).
\item Constante préprocesseur : \texttt{\#define TVA 0.1925} (le compilateur remplace chaque \texttt{TVA} par sa valeur ; pas de point-virgule !).
\item Constante typée : \texttt{const double TVA = 0.1925;} (recommandé : le type est vérifié, portée respectée).
\end{itemize}
\end{propriete}

\begin{lstlisting}[language=C]
#include <stdio.h>
#define TAUX_TVA 0.1925   // constante preprocesseur

int main()
{
    const int NB_MEMBRES_MAX = 50;   // constante typee
    int age = 17;                    // entier
    double cotisation = 25000.50;    // reel double precision
    char sexe = 'M';                 // caractere (apostrophes simples)
    return 0;
}
\end{lstlisting}

La fonction \texttt{printf} affiche du texte et des valeurs à l'écran. Les \textbf{spécificateurs de format} indiquent où et comment insérer les valeurs :

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Spécificateur} & \textbf{Effet} \\
\hline
\texttt{\%d} & entier (\texttt{int}) \\
\hline
\texttt{\%f} & réel (\texttt{float} ou \texttt{double}), 6 décimales par défaut \\
\hline
\texttt{\%.2f} & réel arrondi à 2 décimales (idéal pour les montants) \\
\hline
\texttt{\%c} & caractère (\texttt{char}) \\
\hline
\texttt{\%s} & chaîne de caractères \\
\hline
\texttt{\textbackslash n} & saut de ligne ; \texttt{\textbackslash t} : tabulation \\
\hline
\end{tabularx}
\end{center}

\begin{lstlisting}[language=C]
double total = 15230.4567;

printf("Nom\tCotisation\\ ");            // colonnes alignees par tabulation
\end{lstlisting}

\begin{attention}
Utiliser \texttt{\%d} pour afficher un \texttt{double} (ou l'inverse) produit des valeurs aberrantes sans message d'erreur. Le spécificateur doit \textbf{toujours} correspondre au type de la variable.
\end{attention}

\courssub{Entrées formatées avec scanf}

La fonction \texttt{scanf} lit ce que l'utilisateur tape au clavier et le range dans une variable. Point capital : \texttt{scanf} a besoin de l'\textbf{adresse} de la variable, d'où l'\textbf{esperluette} \texttt{\&} devant son nom.

\begin{lstlisting}[language=C]
int age;
double montant;
printf("Entrez votre age : ");
scanf("%d", &age);            // & devant la variable : OBLIGATOIRE
printf("Entrez le montant : ");
scanf("%lf", &montant);       // %lf pour un double, %f pour un float
\end{lstlisting}

\begin{attention}[Piège classique : \%f versus \%lf]
Avec \texttt{printf}, \texttt{\%f} convient pour \texttt{float} et \texttt{double} (promotion automatique). Avec \texttt{scanf}, il faut \texttt{\%f} pour un \texttt{float} mais \texttt{\%lf} pour un \texttt{double}. Oublier le \texttt{l} donne des lectures fausses silencieuses.
\end{attention}

\begin{attention}[Buffer d'entrée et retour de scanf]
\begin{itemize}
\item \texttt{scanf} laisse le caractère \texttt{\textbackslash n} (Entrée) dans le tampon. Un \texttt{scanf("\%c", \&c)} suivant lira ce \texttt{\textbackslash n} au lieu du caractère attendu. \textbf{Parade} : mettre un espace avant \texttt{\%c} (\texttt{" \%c"}) pour ignorer les blancs, ou vider le buffer avec \texttt{while(getchar() != '\textbackslash n');}.
\item \texttt{scanf} renvoie le nombre d'éléments lus avec succès. Testez-le : \texttt{if (scanf("\%lf", \&x) != 1) \{ /* erreur saisie */ \}}.
\end{itemize}
\end{attention}

\begin{attention}[Affichage du prompt avant saisie]
Sur certains systèmes (Linux), la sortie standard est tamponnée par ligne : un \texttt{printf("Entrez x : ")} sans \texttt{\textbackslash n} final n'apparaît \emph{pas} avant le \texttt{scanf} qui suit. \textbf{Bonne pratique} : ajouter \texttt{fflush(stdout);} après le \texttt{printf} de prompt.
\end{attention}

\begin{exemplebox}[Calcul du discriminant d'un trinôme]
Pour résoudre $ax^2+bx+c=0$, on calcule $\Delta = b^2 - 4ac$ :
\begin{lstlisting}[language=C]
#include <stdio.h>
#include <math.h>

int main()
{
    double a = 1, b = -5, c = 6;
    double delta = pow(b, 2) - 4 * a * c;   // ou b*b - 4*a*c
    printf("Delta = %.2f\\ ", delta);        // Delta = 1.00
    if (delta >= 0) {
        double x1 = (-b - sqrt(delta)) / (2 * a);
        double x2 = (-b + sqrt(delta)) / (2 * a);
        printf("x1 = %.2f  x2 = %.2f\\ ", x1, x2);
    }
    return 0;
}
\end{lstlisting}
\end{exemplebox}

\courssub{Exemple chiffré : du prix HT au prix TTC}

\begin{exemplebox}[Programme de calcul du prix TTC (TVA 19,25 \%)]
Au Cameroun, la TVA est de 19,25 \%. Ce programme saisit un prix hors taxe et affiche le prix toutes taxes comprises, arrondi au centime grâce à \texttt{\%.2f} :
\begin{lstlisting}[language=C]
#include <stdio.h>
#define TVA 0.1925   // taux de TVA au Cameroun

int main()
{
    double prixHT, montantTVA, prixTTC;

    printf("Entrez le prix HT : ");
    scanf("%lf", &prixHT);          // lecture d'un double

    montantTVA = prixHT * TVA;
    prixTTC = prixHT + montantTVA;

    printf("Prix HT   : %.2f FCFA\\ ", prixHT);
    printf("TVA       : %.2f FCFA\\ ", montantTVA);
    printf("Prix TTC  : %.2f FCFA\\ ", prixTTC);
    return 0;
}
\end{lstlisting}
Pour un prix HT de $10\,000$ FCFA : TVA $= 10\,000 \times 0{,}1925 = 1\,925$ FCFA, donc prix TTC $= 11\,925,00$ FCFA.
\end{exemplebox}

\begin{exoresolu}[La moyenne de deux notes]
Énoncé : écrire un programme C complet qui saisit deux notes (réelles) d'un élève de Terminale TI, calcule leur moyenne et l'affiche avec deux décimales.
\tcblower
Solution détaillée : on déclare trois variables \texttt{float} (une note sur 20 n'exige pas la précision du \texttt{double}), on lit les deux notes avec \texttt{scanf} et \texttt{\&}, on calcule la moyenne en veillant à écrire \texttt{2.0} (division réelle) et non \texttt{2} :
\begin{lstlisting}[language=C]
#include <stdio.h>

int main()
{
    float note1, note2, moyenne;

    printf("Entrez la premiere note : ");
    scanf("%f", &note1);
    printf("Entrez la deuxieme note : ");
    scanf("%f", &note2);

    moyenne = (note1 + note2) / 2.0;   // 2.0 : division reelle

    printf("La moyenne est : %.2f / 20\\ ", moyenne);
    return 0;
}
\end{lstlisting}
Trace d'exécution : pour \texttt{note1 = 12} et \texttt{note2 = 15}, on obtient \texttt{La moyenne est : 13.50 / 20}. Piège évité : écrire \texttt{/ 2} avec des \texttt{float} fonctionne ici, mais avec deux \texttt{int}, \texttt{(a + b) / 2} serait une \emph{division entière} tronquée — nous y reviendrons dans la section sur les conversions de types.
\end{exoresolu}

\coursec{Opérateurs, conversions de types et expressions}

Dans la section précédente, tu as appris à écrire tes premiers programmes en C : déclarer des variables de types de base (\texttt{int}, \texttt{float}, \texttt{double}, \texttt{char}), lire des données avec \texttt{scanf} et afficher des résultats avec \texttt{printf}. Mais un programme qui se contente de stocker et d'afficher des valeurs ne fait pas grand-chose d'utile. La véritable puissance d'un programme, c'est de \emph{calculer}, de \emph{comparer} et de \emph{prendre des décisions}. Imagine la caisse d'une boutique à Douala : le logiciel doit additionner les prix, appliquer une remise de \num{5}~\% si le total dépasse \num{50000}~FCFA, vérifier que le client est majeur pour certains produits... Toutes ces opérations reposent sur les \cle{opérateurs} et les \cle{expressions}. C'est l'objet de cette section.

\courssub{Opérandes, expressions et opérateurs arithmétiques}

\begin{definition}[Opérande, opérateur, expression]
Une \cle{opérande} est une valeur sur laquelle porte un calcul : une constante (\texttt{5}), une variable (\texttt{prix}) ou le résultat d'un sous-calcul. Un \cle{opérateur} est un symbole qui combine une ou deux opérandes (\texttt{+}, \texttt{*}, \texttt{>}, \ldots). Une \cle{expression} est un assemblage d'opérateurs et d'opérandes qui possède une \emph{valeur} après évaluation : \texttt{3 * note + 2} est une expression dont la valeur dépend de \texttt{note}.
\end{definition}

Le langage C fournit les cinq opérateurs arithmétiques classiques :

\begin{center}
\begin{tabularx}{\linewidth}{|c|l|X|l|}
\hline
\rowcolor{popblueL} \textbf{Opérateur} & \textbf{Nom} & \textbf{Exemple} & \textbf{Résultat} \\
\hline
\texttt{+} & Addition & \texttt{7 + 2} & \texttt{9} \\
\hline
\texttt{-} & Soustraction & \texttt{7 - 2} & \texttt{5} \\
\hline
\texttt{*} & Multiplication & \texttt{7 * 2} & \texttt{14} \\
\hline
\texttt{/} & Division & \texttt{7 / 2} & \texttt{3} (entier !) \\
\hline
\texttt{\%} & Modulo (reste) & \texttt{7 \% 2} & \texttt{1} \\
\hline
\end{tabularx}
\end{center}

\begin{attention}[Division entière contre division réelle]
En C, le résultat de \texttt{/} dépend du \emph{type des opérandes}, pas de celui de la variable qui reçoit le résultat. Si les deux opérandes sont entières, la division est \cle{entière} (troncature) : \texttt{7 / 2} vaut \texttt{3}, tandis que \texttt{7 / 2.0} vaut \num{3,5}. Piège classique du Baccalauréat :
\begin{lstlisting}[language=C]
float moyenne;
moyenne = 15 / 2;      /* moyenne vaut 7.0 et non 7.5 ! */
moyenne = 15 / 2.0;    /* moyenne vaut 7.5 : division reelle */
moyenne = 15.0 / 2;    /* idem : 7.5 */
\end{lstlisting}
De même, l'opérateur \texttt{\%} n'existe \textbf{que pour les entiers} : écrire \texttt{7.5 \% 2} provoque une erreur de compilation.
\end{attention}

\begin{savaistu}[Le modulo, un outil du quotidien]
L'opérateur \texttt{\%} est partout. Pour tester la \emph{parité} d'un nombre, on écrit \texttt{n \% 2 == 0}. Pour gérer des \emph{cycles}, c'est irremplaçable : si aujourd'hui est le jour numéro $j$ de la semaine ($0$ = lundi), alors dans $n$ jours ce sera le jour $(j + n) \,\%\, 7$. Les systèmes de Mobile Money utilisent exactement ce principe pour planifier des rappels périodiques, et ton emploi du temps hebdomadaire au lycée fonctionne pareil !
\end{savaistu}

\courssub{Conversions de types : implicite et explicite (cast)}

Que se passe-t-il quand une expression mélange des types différents, par exemple un \texttt{int} et un \texttt{float} ? Le C ne refuse pas : il \emph{convertit}.

\begin{definition}[Conversion implicite et conversion explicite]
La \cle{conversion implicite} (ou promotion) est réalisée automatiquement par le compilateur : dans une expression mixte, l'opérande de type « plus petit » est convertie vers le type « plus grand » selon la hiérarchie \texttt{char} $\rightarrow$ \texttt{int} $\rightarrow$ \texttt{float} $\rightarrow$ \texttt{double}. Aucune information n'est perdue dans ce sens. La \cle{conversion explicite} (ou \emph{cast}) est demandée par le programmeur avec la syntaxe :
\begin{lstlisting}[language=C]
(type_vise) expression
\end{lstlisting}
Elle peut provoquer une perte d'information : \texttt{(int) 3.99} vaut \texttt{3} (troncature, pas arrondi).
\end{definition}

\begin{exemplebox}[Forcer une division réelle grâce au cast]
Cas typique : calculer la moyenne de deux quantités stockées dans des entiers.
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    int somme = 27, effectif = 4;
    float m1, m2, m3;

    m1 = somme / effectif;            /* 6.0 : division entiere ! */
    m2 = (float)somme / effectif;     /* 6.75 : somme devient 27.0 */
    m3 = (float)(somme / effectif);   /* 6.0 : cast trop tard !   */

    printf("m1 = %.2f, m2 = %.2f, m3 = %.2f\n", m1, m2, m3);
    return 0;
}
\end{lstlisting}
Pour \texttt{m3}, le cast s'applique \emph{après} la division entière : le mal est déjà fait. Il faut convertir \emph{au moins une opérande avant} la division.
\end{exemplebox}

\courssub{Opérateurs relationnels et logiques}

Pour prendre des décisions (section suivante), il faut pouvoir comparer des valeurs. Les opérateurs relationnels sont \texttt{==} (égal), \texttt{!=} (différent), \texttt{<}, \texttt{<=}, \texttt{>}, \texttt{>=}. Une comparaison produit un \texttt{int} valant \texttt{1} (vrai) ou \texttt{0} (faux) : historiquement, le langage C ne possède pas de type booléen natif (la bibliothèque \texttt{stdbool.h}, ajoutée plus tard, fournit \texttt{bool}, \texttt{true} et \texttt{false}, mais elle n'est pas exigée au programme).

\begin{propriete}[Vérité en C (admise, vérifiée sur exemples)]
En C, toute valeur \textbf{nulle} ($0$, $0.0$) est considérée comme \emph{fausse}, et toute valeur \textbf{non nulle} est considérée comme \emph{vraie}. Ainsi \texttt{5 > 3} vaut \texttt{1}, \texttt{5 == 3} vaut \texttt{0}, et une expression comme \texttt{7} seule est « vraie ». On peut donc écrire \texttt{if (stock)} au lieu de \texttt{if (stock != 0)}.
\end{propriete}

\begin{attention}[Le piège n°1 du débutant : \texttt{=} contre \texttt{==}]
\texttt{=} est l'\emph{affectation} (elle range une valeur), \texttt{==} est la \emph{comparaison} (elle teste). Le code suivant compile sans erreur mais est faux :
\begin{lstlisting}[language=C]
int age = 15;
if (age = 18) {   /* ERREUR : on AFFECTE 18 a age ! */
    /* age vaut desormais 18, et 18 est "vrai" :
       le test reussit TOUJOURS */
}
\end{lstlisting}
Conséquence de la propriété précédente : l'expression \texttt{age = 18} vaut \texttt{18}, donc vrai. Astuce de professionnel : écrire \texttt{if (18 == age)} — si tu oublies un \texttt{=}, le compilateur refusera \texttt{18 = age}, car on ne peut pas affecter une valeur à une constante.
\end{attention}

Les opérateurs logiques combinent des conditions : \texttt{\&\&} (ET), \texttt{||} (OU), \texttt{!} (NON).

\begin{center}
\begin{tabularx}{\linewidth}{|c|c|X|X|X|}
\hline
\rowcolor{popblueL} \textbf{a} & \textbf{b} & \textbf{a \&\& b} & \textbf{a || b} & \textbf{!a} \\
\hline
0 & 0 & 0 & 0 & 1 \\
\hline
0 & 1 & 0 & 1 & 1 \\
\hline
1 & 0 & 0 & 1 & 0 \\
\hline
1 & 1 & 1 & 1 & 0 \\
\hline
\end{tabularx}
\end{center}

\begin{propriete}[Évaluation paresseuse]
Le C évalue les conditions de gauche à droite et \emph{s'arrête dès que le résultat est connu} : pour \texttt{a \&\& b}, si \texttt{a} est faux, \texttt{b} n'est pas évalué ; pour \texttt{a || b}, si \texttt{a} est vrai, \texttt{b} n'est pas évalué. Cela permet d'écrire en toute sécurité :
\begin{lstlisting}[language=C]
if (n != 0 && 100 / n > 5) { /* pas de division par zero : */
    /* si n == 0, le second test n'est jamais calcule */
}
\end{lstlisting}
\end{propriete}

\courssub{Affectations composées, incrémentation et décrémentation}

Modifier une variable à partir de sa propre valeur est si fréquent que le C offre des raccourcis :

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Affectation composée} & \textbf{Équivalent} \\
\hline
\texttt{x += 3;} & \texttt{x = x + 3;} \\
\hline
\texttt{x -= 3;} & \texttt{x = x - 3;} \\
\hline
\texttt{x *= 2;} & \texttt{x = x * 2;} \\
\hline
\texttt{x /= 2;} & \texttt{x = x / 2;} \\
\hline
\texttt{x \%= 7;} & \texttt{x = x \% 7;} \\
\hline
\end{tabularx}
\end{center}

Les opérateurs \texttt{++} et \texttt{--} ajoutent ou retranchent 1. Mais leur position change tout :

\begin{exemplebox}[Pré-incrémentation contre post-incrémentation]
\begin{itemize}
\item \texttt{++i} (pré) : on incrémente \emph{d'abord}, puis on utilise la nouvelle valeur ;
\item \texttt{i++} (post) : on utilise l'ancienne valeur \emph{d'abord}, puis on incrémente.
\end{itemize}
\begin{lstlisting}[language=C]
int i, j;

i = 5;
j = i++ * 2;   /* j recoit 5*2 = 10, PUIS i devient 6 */
/* Resultat : j = 10, i = 6 */

i = 5;
j = ++i * 2;   /* i devient 6 D'ABORD, puis j recoit 6*2 */
/* Resultat : j = 12, i = 6 */
\end{lstlisting}
Utilisés seuls sur une ligne (\texttt{i++;}), les deux formes sont strictement équivalentes.
\end{exemplebox}

\courssub{Priorité et associativité des opérateurs}

Que vaut \texttt{3 + 4 * 2} ? Comme en mathématiques, le C applique des règles de \cle{priorité} : la multiplication d'abord, donc $3 + 8 = 11$. L'\cle{associativité} tranche les égalités de priorité : \texttt{20 / 5 / 2} s'évalue de gauche à droite, donc $(20/5)/2 = 2$.

\begin{methode}[Évaluer une expression pas à pas]
\begin{enumerate}
\item Évaluer d'abord le contenu des \textbf{parenthèses}, de la plus interne à la plus externe ;
\item appliquer les \texttt{++}/\texttt{--} et le \texttt{!} ;
\item effectuer les \texttt{*}, \texttt{/}, \texttt{\%} de gauche à droite ;
\item effectuer les \texttt{+}, \texttt{-} de gauche à droite ;
\item effectuer les comparaisons (\texttt{<}, \texttt{<=}, \texttt{>}, \texttt{>=}, puis \texttt{==}, \texttt{!=}) ;
\item appliquer \texttt{\&\&}, puis \texttt{||} ;
\item effectuer l'affectation en dernier.
\end{enumerate}
En cas de doute, mets des parenthèses : elles ne coûtent rien et rendent le code lisible.
\end{methode}

\begin{exoresolu}[Trace à la main d'une expression complexe]
Énoncé : soit \texttt{int a = 10, b = 4, r;} et l'instruction \texttt{r = a \% b + a / b * 2 > 5 \&\& b != 0;}. Donner la valeur finale de \texttt{r} en détaillant chaque étape.
\tcblower
Solution détaillée : on applique la méthode des priorités.
\begin{enumerate}
\item \texttt{\%}, \texttt{/}, \texttt{*} d'abord, de gauche à droite : \texttt{a \% b} $= 10 \% 4 = 2$ ; \texttt{a / b} $= 10 / 4 = 2$ (division entière) ; \texttt{2 * 2 = 4}.
\item Addition : \texttt{2 + 4 = 6}.
\item Comparaisons : \texttt{6 > 5} vaut \texttt{1} ; \texttt{b != 0} s'écrit \texttt{4 != 0}, qui vaut \texttt{1}.
\item \texttt{\&\&} : \texttt{1 \&\& 1} vaut \texttt{1}.
\item Affectation : \texttt{r = 1}.
\end{enumerate}
La valeur finale de \texttt{r} est donc \texttt{1}. Remarque : grâce à l'évaluation paresseuse, si le premier membre du \texttt{\&\&} avait été faux, \texttt{b != 0} n'aurait même pas été évalué.
\end{exoresolu}

\begin{exercice}[À toi de jouer]
Soit \texttt{int x = 7, y = 3, z;} et \texttt{float f;}. \textbf{Chaque question repart des valeurs initiales} \texttt{x = 7} et \texttt{y = 3}.
\begin{enumerate}
\item Donner la valeur de \texttt{z} après : \texttt{z = x / y + x \% y * 5;}
\item Donner les valeurs de \texttt{x}, \texttt{y} et \texttt{z} après : \texttt{z = ++x - y++;}
\item Donner la valeur de \texttt{f} après : \texttt{f = (float)x / y;}
\item L'expression \texttt{x > y \&\& y > 0 || x == 0} vaut-elle 0 ou 1 ?
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice : trace d'expressions]
\begin{enumerate}
\item \texttt{x / y} $= 2$ (division entière), \texttt{x \% y} $= 1$, donc \texttt{z} $= 2 + 1 \times 5 = 7$.
\item \texttt{++x} : \texttt{x} devient 8 puis est utilisé ; \texttt{y++} : on utilise 3 puis \texttt{y} devient 4. Donc \texttt{z} $= 8 - 3 = 5$, \texttt{x} $= 8$, \texttt{y} $= 4$.
\item Le cast transforme \texttt{x} en \texttt{7.0} avant la division : \texttt{f} $= 7{,}0 / 3 \approx 2{,}33$.
\item \texttt{x > y} vaut 1 et \texttt{y > 0} vaut 1, donc \texttt{1 \&\& 1} vaut 1 ; comme \texttt{\&\&} est prioritaire sur \texttt{||}, le résultat est \texttt{1 || 0} $= 1$.
\end{enumerate}
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item \texttt{/} entre entiers tronque ; \texttt{\%} donne le reste et n'existe que pour les entiers.
\item Conversion implicite : vers le type le plus grand ; cast \texttt{(type)expr} : à placer \emph{avant} l'opération critique.
\item Toute valeur non nulle est vraie, $0$ est faux ; ne jamais confondre \texttt{=} et \texttt{==}.
\item \texttt{\&\&} et \texttt{||} s'évaluent paresseusement, de gauche à droite.
\item \texttt{i++} utilise puis incrémente ; \texttt{++i} incrémente puis utilise.
\item Priorité : parenthèses, puis \texttt{++}/\texttt{--}/\texttt{!}, puis \texttt{* / \%}, puis \texttt{+ -}, puis comparaisons, puis \texttt{\&\&}, puis \texttt{||}, puis affectation.
\end{itemize}
\end{aretenir}

Tu maîtrises désormais l'écriture et l'évaluation des expressions : c'est le carburant de tout programme C. Dans la prochaine section, nous mettrons ces expressions au service de la \emph{décision} et de la \emph{répétition} avec les structures alternatives (\texttt{if}, \texttt{switch}) et les boucles (\texttt{for}, \texttt{while}, \texttt{do...while}).

\coursec{Structures alternatives et boucles}

Dans la section précédente, tu as appris à construire des \emph{expressions} : calculs arithmétiques, comparaisons, conditions logiques. Mais jusqu'ici, nos programmes s'exécutaient toujours de la même façon : ligne après ligne, du haut vers le bas, sans jamais hésiter ni recommencer. Or un programme utile doit pouvoir \emph{prendre des décisions} (« si la note est supérieure ou égale à 10, afficher Admis ») et \emph{répéter des tâches} (« calculer la moyenne des 25 élèves de la classe »). C'est exactement le rôle des \cle{structures alternatives} et des \cle{boucles}, que nous allons étudier maintenant. Ce sont les outils qui transforment une simple suite de calculs en un véritable programme intelligent.

\courssub{Les structures alternatives : \texttt{if} et \texttt{if...else}}

\textbf{Intuition.} Imagine le système de délibération d'un conseil de classe : \emph{si} la moyenne est au moins 10, l'élève est admis ; \emph{sinon}, il est ajourné. Le programme doit choisir un chemin parmi deux, selon une condition. C'est ce que réalise l'instruction \texttt{if}.

\begin{definition}[Structure alternative]
Une \cle{structure alternative} est une instruction qui permet d'exécuter un bloc d'instructions \textbf{uniquement si une condition est vraie}. En C, une condition est une expression dont la valeur est interprétée comme \emph{vraie} si elle est \textbf{différente de 0}, et \emph{fausse} si elle vaut \textbf{0}.
\end{definition}

\begin{propriete}[Syntaxe du \texttt{if} simple et du \texttt{if...else}]
\begin{lstlisting}[language=C]
if (condition) {
    // instructions executees si condition est vraie
}

if (condition) {
    // instructions si vrai
} else {
    // instructions si faux
}
\end{lstlisting}
La condition est \textbf{toujours entre parenthèses}. Si le bloc ne contient qu'\emph{une seule} instruction, les accolades sont facultatives, mais nous te conseillons vivement de les mettre systématiquement : cela évite de nombreux bugs lors des modifications ultérieures du code.
\end{propriete}

\begin{exemplebox}[Décision d'admission au Baccalauréat]
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void) {
    float moyenne;
    printf("Entrez la moyenne du candidat : ");
    scanf("%f", &moyenne);

    if (moyenne >= 10) {
        printf("Candidat ADMIS.\n");
    } else {
        printf("Candidat AJOURNE.\n");
    }
    return 0;
}
\end{lstlisting}
Ici, la condition \texttt{moyenne >= 10} utilise un opérateur relationnel vu à la section précédente. Un seul des deux blocs est exécuté, jamais les deux.
\end{exemplebox}

\textbf{Conditions composées.} On combine plusieurs tests avec les opérateurs logiques \texttt{\&\&} (ET), \texttt{||} (OU) et \texttt{!} (NON). Par exemple, la mention « Bien » s'obtient avec une moyenne entre 14 et 16 :

\begin{lstlisting}[language=C]
if (moyenne >= 14 && moyenne < 16) {
    printf("Mention Bien.\n");
}
\end{lstlisting}

\begin{attention}[Ne jamais écrire \texttt{if (a = 10)}]
L'erreur classique du débutant est d'écrire \texttt{if (moyenne = 10)} avec un seul \texttt{=}. Ce n'est \textbf{pas} une comparaison mais une \emph{affectation} : la variable reçoit 10, et l'expression vaut 10, donc elle est considérée \emph{vraie} ! Le bloc s'exécute toujours. La comparaison d'égalité s'écrit \texttt{==}. De même, ne place jamais de point-virgule juste après la parenthèse du \texttt{if} : \texttt{if (x > 0);} crée un corps vide et le bloc qui suit s'exécute dans tous les cas.
\end{attention}

\courssub{Imbrication des \texttt{if} et problème du \texttt{else} pendu}

On peut placer un \texttt{if} à l'intérieur d'un autre : c'est l'\cle{imbrication}. C'est indispensable pour traiter plusieurs cas, comme le calcul des mentions.

\begin{exemplebox}[Calcul de la mention avec \texttt{if} imbriqués]
\begin{lstlisting}[language=C]
if (moyenne >= 16) {
    printf("Mention Tres Bien\n");
} else if (moyenne >= 14) {
    printf("Mention Bien\n");
} else if (moyenne >= 12) {
    printf("Mention Assez Bien\n");
} else if (moyenne >= 10) {
    printf("Mention Passable\n");
} else {
    printf("Ajourné\n");
}
\end{lstlisting}
Les conditions sont évaluées \emph{dans l'ordre} : dès qu'une est vraie, son bloc s'exécute et toutes les autres sont ignorées. L'ordre des tests est donc crucial : tester d'abord \texttt{moyenne >= 10} rendrait les autres branches inaccessibles.
\end{exemplebox}

\begin{attention}[Le \texttt{else} pendu]
En C, un \texttt{else} se rattache \textbf{toujours au \texttt{if} le plus proche qui n'a pas encore de \texttt{else}}. Dans le code suivant, l'indentation trompe le lecteur :
\begin{lstlisting}[language=C]
if (note >= 10)
    if (note >= 12)
        printf("Bien\n");
else
    printf("Ajourné\n");  // rattache au 2e if, pas au 1er !
\end{lstlisting}
Le \texttt{else} appartient au second \texttt{if}, alors que l'indentation suggère le contraire. \textbf{Bonne pratique} : mets toujours des accolades et indente rigoureusement (décalage constant de 4 espaces) pour que la structure du code reflète sa logique.
\end{attention}

\courssub{La structure \texttt{switch} : choix multiples}

\textbf{Intuition.} Quand une même variable peut prendre plusieurs valeurs précises (1, 2, 3, 4 pour un menu), enchaîner des \texttt{if...else if} devient lourd. La structure \texttt{switch} est faite pour cela : elle compare la valeur d'une expression à une liste de cas.

\begin{propriete}[Syntaxe du \texttt{switch}]
\begin{lstlisting}[language=C]
switch (expression) {   // expression de type entier ou char
    case valeur1:
        // instructions
        break;
    case valeur2:
        // instructions
        break;
    default:            // facultatif : tous les autres cas
        // instructions
}
\end{lstlisting}
L'expression doit être de type \textbf{entier} (\texttt{int}, \texttt{char}) : on ne peut pas faire un \texttt{switch} sur un \texttt{float} ni sur une chaîne de caractères. Le \texttt{default} traite tous les cas non prévus.
\end{propriete}

\begin{exemplebox}[Menu de calculatrice]
\begin{lstlisting}[language=C]
int choix;
float a, b;
printf("1. Addition\n2. Soustraction\n3. Multiplication\n4. Division\n");
printf("Votre choix : ");
scanf("%d", &choix);
printf("Entrez deux nombres : ");
scanf("%f %f", &a, &b);

switch (choix) {
    case 1:
        printf("Resultat : %.2f\n", a + b);
        break;
    case 2:
        printf("Resultat : %.2f\n", a - b);
        break;
    case 3:
        printf("Resultat : %.2f\n", a * b);
        break;
    case 4:
        if (b != 0) {
            printf("Resultat : %.2f\n", a / b);
        } else {
            printf("Erreur : division par zero !\n");
        }
        break;
    default:
        printf("Choix invalide.\n");
}
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Oublier le \texttt{break} : le \emph{fall-through}]
Si tu oublies le \texttt{break} à la fin d'un \texttt{case}, l'exécution \textbf{continue dans le cas suivant} sans tester sa condition : c'est le \emph{fall-through} (passage en cascade). Avec \texttt{choix = 1} et sans \texttt{break}, le programme afficherait le résultat de l'addition \emph{puis} celui de la soustraction, puis de la multiplication ! Ce comportement est parfois utilisé volontairement pour regrouper des cas (plusieurs \texttt{case} vides qui se suivent partagent le même bloc), mais c'est une source d'erreurs redoutable chez le débutant.
\end{attention}

\courssub{Les boucles : répéter sans se répéter}

\begin{definition}[Itération, compteur et accumulateur]
Une \cle{itération} (ou boucle) est une structure qui répète l'exécution d'un bloc d'instructions tant qu'une condition est satisfaite. Un \cle{compteur} est une variable qui compte les passages dans la boucle (souvent nommée \texttt{i}). Un \cle{accumulateur} est une variable qui \emph{cumule} progressivement un résultat (somme, produit) : on l'initialise avant la boucle et on le met à jour à chaque tour.
\end{definition}

\textbf{La boucle \texttt{for}.} On l'utilise quand le nombre de tours est \emph{connu à l'avance}. Sa syntaxe regroupe les trois éléments de pilotage sur une seule ligne :

\begin{lstlisting}[language=C]
for (initialisation ; condition ; increment) {
    // corps de la boucle
}
\end{lstlisting}

Exemple : la somme $S = 1 + 2 + \dots + N$ des $N$ premiers entiers, avec un accumulateur :

\begin{lstlisting}[language=C]
int N, i, somme = 0;   // accumulateur initialise a 0
printf("Entrez N : ");
scanf("%d", &N);
for (i = 1; i <= N; i++) {
    somme = somme + i;   // accumulation
}
printf("Somme = %d\n", somme);
\end{lstlisting}

Pour $N = 4$, la variable \texttt{somme} vaut successivement 1, 3, 6, 10 : on obtient bien $1+2+3+4 = 10$.

\textbf{La boucle \texttt{while}.} On l'utilise quand on ne sait pas \emph{combien} de tours seront nécessaires : on répète \emph{tant qu'}une condition est vraie. Le test est fait \emph{avant} chaque exécution du corps, qui peut donc ne jamais s'exécuter.

\begin{lstlisting}[language=C]
int i = 1;
while (i <= 5) {       // test AVANT le corps
    printf("%d ", i);
    i++;               // fait evoluer la condition
}
\end{lstlisting}

\textbf{La boucle \texttt{do...while}.} Identique au \texttt{while}, mais le test est fait \emph{après} le corps : celui-ci s'exécute donc \textbf{au moins une fois}. C'est la boucle idéale pour la saisie contrôlée.

\begin{exemplebox}[Saisie contrôlée d'une note entre 0 et 20, puis mention]
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void) {
    float note;
    do {
        printf("Entrez une note entre 0 et 20 : ");
        scanf("%f", &note);
        if (note < 0 || note > 20) {
            printf("Note invalide, recommencez.\n");
        }
    } while (note < 0 || note > 20);   // on recommence tant que c'est faux

    printf("Note validee : %.2f\n", note);
    if (note >= 16) {
        printf("Mention Tres Bien\n");
    } else if (note >= 14) {
        printf("Mention Bien\n");
    } else if (note >= 12) {
        printf("Mention Assez Bien\n");
    } else if (note >= 10) {
        printf("Mention Passable\n");
    } else {
        printf("Ajourné\n");
    }
    return 0;
}
\end{lstlisting}
La question est posée une première fois, puis reposée \emph{tant que} la valeur saisie est hors de l'intervalle $[0\,;\,20]$. C'est le schéma type de toute saisie sécurisée.
\end{exemplebox}

\begin{attention}[La boucle infinie]
Dans un \texttt{while}, si la condition ne dépend de rien qui évolue dans le corps, elle reste vraie éternellement :
\begin{lstlisting}[language=C]
int i = 1;
while (i <= 5) {
    printf("%d ", i);   // i n'est jamais modifie : boucle infinie !
}
\end{lstlisting}
\textbf{Règle de survie} : vérifie toujours qu'au moins une variable de la condition est modifiée dans le corps de la boucle, et qu'elle finira par rendre la condition fausse. Autre piège : \texttt{while (i <= 5);} avec un point-virgule crée un corps vide et boucle sans fin.
\end{attention}

\courssub{Équivalence entre boucles et choix de la bonne boucle}

\begin{propriete}[Toute boucle \texttt{for} peut se réécrire en \texttt{while}, et réciproquement]
Construisons l'équivalence sur l'exemple de la somme des $N$ premiers entiers. La version \texttt{for} :
\begin{lstlisting}[language=C]
for (i = 1; i <= N; i++) {
    somme = somme + i;
}
\end{lstlisting}
se décompose mécaniquement en trois étapes : l'\emph{initialisation} est placée avant la boucle, la \emph{condition} devient celle du \texttt{while}, et l'\emph{incrément} est déplacé à la fin du corps :
\begin{lstlisting}[language=C]
i = 1;                  // 1. initialisation AVANT
while (i <= N) {        // 2. condition dans le while
    somme = somme + i;
    i++;                // 3. increment A LA FIN du corps
}
\end{lstlisting}
Les deux programmes effectuent exactement les mêmes opérations dans le même ordre : ils sont \emph{équivalents}. Réciproquement, tout \texttt{while} dont le pilotage repose sur un compteur peut se compacter en \texttt{for}. En revanche, un \texttt{do...while} ne peut pas toujours se remplacer par un \texttt{while} sans dupliquer le corps, car il garantit une première exécution sans test.
\end{propriete}

\begin{methode}[Choisir sa boucle]
\begin{enumerate}
    \item Le nombre de tours est-il \textbf{connu à l'avance} (par exemple $N$ élèves, les tables de 1 à 10) ? $\rightarrow$ utilise \texttt{for}.
    \item Sinon, la répétition dépend-elle d'une \textbf{condition qui peut être fausse dès le départ} (lire des données tant qu'on n'a pas atteint la fin) ? $\rightarrow$ utilise \texttt{while}.
    \item Le corps doit-il s'exécuter \textbf{au moins une fois} avant tout test (saisie contrôlée, menu à reafficher) ? $\rightarrow$ utilise \texttt{do...while}.
\end{enumerate}
\end{methode}

\courssub{Compteurs, accumulateurs et boucles imbriquées}

\textbf{Factorielle itérative.} La factorielle de $n$ est le produit $n! = 1 \times 2 \times \dots \times n$. L'accumulateur est ici un \emph{produit}, donc initialisé à 1 (et non à 0 !) :

\begin{lstlisting}[language=C]
int n, i;
long fact = 1;   // accumulateur-produit initialise a 1
printf("Entrez n : ");
scanf("%d", &n);
for (i = 1; i <= n; i++) {
    fact = fact * i;
}
printf("%d! = %ld\n", n, fact);
\end{lstlisting}

\textbf{Boucles imbriquées.} On place une boucle dans une autre pour parcourir des structures à deux dimensions : lignes et colonnes. La boucle interne tourne \emph{entièrement} à chaque tour de la boucle externe.

\begin{lstlisting}[language=C]
// Table de multiplication de 1 a 5
int i, j;
for (i = 1; i <= 5; i++) {          // boucle externe : les lignes
    for (j = 1; j <= 5; j++) {      // boucle interne : les colonnes
        printf("%4d", i * j);       // %4d : affichage aligne sur 4 caracteres
    }
    printf("\n");                   // retour a la ligne apres chaque ligne
}
\end{lstlisting}

\textbf{Instructions \texttt{break} et \texttt{continue} (complément Bac).} Dans une boucle, \texttt{break} provoque la \emph{sortie immédiate} de la boucle (utile pour arrêter une recherche dès que l'élément est trouvé) ; \texttt{continue} saute le reste du corps et passe \emph{directement au tour suivant}. Par exemple, pour afficher les nombres de 1 à 10 sauf les multiples de 3 :

\begin{lstlisting}[language=C]
for (i = 1; i <= 10; i++) {
    if (i % 3 == 0) {
        continue;   // on saute les multiples de 3
    }
    printf("%d ", i);
}
\end{lstlisting}

\begin{exoresolu}[Moyenne d'une classe avec saisie contrôlée]
Énoncé. Écris un programme qui demande le nombre $N$ d'élèves d'une classe de Terminale TI, fait saisir les $N$ notes (chacune contrôlée entre 0 et 20), puis affiche la moyenne de la classe et le nombre d'élèves admis (note $\geq 10$).
\tcblower
Solution détaillée. Le nombre de notes est connu ($N$) : boucle \texttt{for} externe. Chaque note doit être validée : boucle \texttt{do...while} interne. On utilise un accumulateur \texttt{somme} et un compteur \texttt{admis}.
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void) {
    int N, i, admis = 0;        // compteur d'admis
    float note, somme = 0.0f;   // accumulateur

    printf("Nombre d'eleves : ");
    scanf("%d", &N);

    for (i = 1; i <= N; i++) {
        do {
            printf("Note de l'eleve %d (0 a 20) : ", i);
            scanf("%f", &note);
        } while (note < 0 || note > 20);

        somme = somme + note;   // accumulation
        if (note >= 10) {
            admis++;            // comptage
        }
    }

    printf("Moyenne de la classe : %.2f\n", somme / N);
    printf("Nombre d'admis : %d sur %d\n", admis, N);
    return 0;
}
\end{lstlisting}
Trace pour $N = 3$ et les notes 12, 7, 15 : \texttt{somme} vaut successivement 12, 19, 34 ; \texttt{admis} vaut 1, 1, 2. Le programme affiche une moyenne de $34/3 \approx 11,33$ et 2 admis sur 3. Remarque l'écriture \texttt{somme / N} : comme \texttt{somme} est un \texttt{float}, la division est bien réelle (pas de division entière).
\end{exoresolu}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
    \item \texttt{if...else} exécute un bloc selon qu'une condition est vraie ou fausse ; un \texttt{else} se rattache toujours au \texttt{if} le plus proche : accolades obligatoires pour éviter les pièges.
    \item \texttt{switch} compare une expression entière à des cas ; chaque \texttt{case} doit se terminer par \texttt{break} sous peine de \emph{fall-through}.
    \item \texttt{for} : nombre de tours connu ; \texttt{while} : répétition conditionnelle (0 tour possible) ; \texttt{do...while} : au moins un tour (saisie contrôlée).
    \item Toute boucle \texttt{for} se réécrit en \texttt{while} (initialisation avant, incrément à la fin du corps).
    \item Compteur = variable qui compte ; accumulateur = variable qui cumule (somme initialisée à 0, produit initialisé à 1).
    \item Dans toute boucle, la condition doit évoluer dans le corps, sinon : boucle infinie.
\end{itemize}
\end{aretenir}

\begin{enumerate}
    \item Écris un programme qui affiche tous les nombres pairs entre 1 et 50, d'abord avec un \texttt{for}, puis avec un \texttt{while}.
    \item Écris un programme qui demande un entier $n$ et affiche sa table de multiplication de 1 à 12.
    \item Réécris le menu de la calculatrice en utilisant un \texttt{do...while} pour que le menu se réaffiche tant que l'utilisateur ne choisit pas l'option « 5. Quitter ».
    \item Écris un programme qui calcule et affiche la somme $1 + \frac{1}{2} + \frac{1}{3} + \dots + \frac{1}{n}$ (attention à la division entière !).
\end{enumerate}
\end{exercice}

Dans la prochaine section, nous apprendrons à \emph{découper} nos programmes en fonctions réutilisables, à comprendre la portée des variables et à regrouper des données dans des enregistrements : de quoi structurer des applications de plus en plus ambitieuses.

\coursec{Fonctions, portée des variables et enregistrements}

Dans la section précédente, tu as appris à contrôler le déroulement d'un programme grâce aux structures alternatives (\texttt{if}, \texttt{switch}) et aux boucles (\texttt{for}, \texttt{while}, \texttt{do...while}). Tes programmes tiennent désormais dans un seul bloc \texttt{main()} qui peut devenir très long : imagine le programme de gestion des notes d'un lycée de Yaoundé, avec saisie, calculs de moyennes, classement, affichage des bulletins... tout cela dans une seule fonction de plusieurs centaines de lignes devient illisible, impossible à tester et à corriger. Les professionnels du logiciel résolvent ce problème depuis toujours par un principe simple : \emph{diviser pour régner}. On découpe le grand problème en petits sous-problèmes, et chaque sous-problème devient une \cle{fonction}. C'est l'objet de cette section, qui te donnera aussi un outil pour regrouper des données de natures différentes : l'\cle{enregistrement}.

\courssub{Notion de fonction : prototype, définition, appel}

\begin{definition}[Fonction]
Une \cle{fonction} est un bloc d'instructions nommé, qui reçoit éventuellement des données en entrée (les \emph{paramètres}), effectue un traitement, et renvoie éventuellement un résultat (la \emph{valeur de retour}). Une fonction peut être \emph{appelée} depuis une autre fonction, autant de fois que nécessaire.
\end{definition}

Tu connais déjà des fonctions : \texttt{printf}, \texttt{scanf} (bibliothèque \texttt{stdio.h}) et \texttt{sqrt}, \texttt{cos} (bibliothèque \texttt{math.h}). La grande nouveauté de cette section, c'est que tu vas écrire \emph{tes propres} fonctions.

Une fonction en C se manifeste sous trois formes complémentaires :

\begin{itemize}
  \item le \cle{prototype} (ou déclaration) : il annonce au compilateur le nom de la fonction, son type de retour et les types de ses paramètres. Il se termine par un point-virgule ;
  \item la \cle{définition} : elle contient le corps de la fonction, c'est-à-dire les instructions effectivement exécutées ;
  \item l'\cle{appel} : c'est l'utilisation de la fonction, qui déclenche l'exécution de son corps.
\end{itemize}

\begin{propriete}[Syntaxe du prototype et de la définition]
\begin{lstlisting}[language=C]
// Prototype (place avant main, apres les #include)
type_retour nom_fonction(type1 param1, type2 param2);

// Definition
type_retour nom_fonction(type1 param1, type2 param2)
{
    // instructions
    return expression;   // obligatoire si type_retour n'est pas void
}
\end{lstlisting}
Le type de retour peut être \texttt{int}, \texttt{float}, \texttt{char}, etc. Le mot-clé \texttt{return} termine immédiatement la fonction et renvoie la valeur à l'appelant.
\end{propriete}

\begin{methode}[Écrire une fonction en 4 étapes]
\begin{enumerate}
  \item \textbf{Choisir le type de retour} : que doit produire la fonction ? Un réel (\texttt{float}), un entier (\texttt{int}), rien du tout (\texttt{void}) ?
  \item \textbf{Nommer la fonction} avec un verbe ou un nom explicite : \texttt{calculerMoyenne}, \texttt{afficherMenu}. Un bon nom rend le programme auto-documenté.
  \item \textbf{Lister les paramètres} : de quelles données la fonction a-t-elle besoin pour travailler ? Préciser le type de chacune.
  \item \textbf{Écrire le corps} : les instructions du traitement, terminées par \texttt{return} si la fonction renvoie une valeur. Ne pas oublier le prototype avant \texttt{main()}.
\end{enumerate}
\end{methode}

\begin{exemplebox}[Première fonction complète : la moyenne de deux notes]
\begin{lstlisting}[language=C]
#include <stdio.h>

// Prototype : annonce de la fonction au compilateur
float moyenne(float a, float b);

int main(void)
{
    float n1, n2, m;
    printf("Note 1 : ");
    scanf("%f", &n1);
    printf("Note 2 : ");
    scanf("%f", &n2);
    m = moyenne(n1, n2);   // appel : n1 et n2 sont les parametres effectifs
    printf("Moyenne = %.2f\n", m);
    return 0;
}

// Definition de la fonction
float moyenne(float a, float b)   // a et b : parametres formels
{
    float resultat;
    resultat = (a + b) / 2;
    return resultat;              // on aurait pu ecrire : return (a+b)/2;
}
\end{lstlisting}
\end{exemplebox}

\begin{definition}[Paramètres formels et effectifs]
Les \cle{paramètres formels} sont les variables déclarées dans l'en-tête de la fonction (\texttt{a} et \texttt{b} ci-dessus) : ce sont des \emph{noms de rôle}. Les \cle{paramètres effectifs} (ou arguments) sont les valeurs concrètes transmises lors de l'appel (\texttt{n1} et \texttt{n2}). Lors de l'appel, chaque paramètre formel reçoit une \emph{copie} du paramètre effectif correspondant, dans l'ordre.
\end{definition}

\begin{attention}[Prototype manquant : l'erreur classique du débutant]
Si tu appelles une fonction avant que le compilateur ne l'ait vue (ni prototype ni définition au-dessus de l'appel), tu obtiens une erreur ou un avertissement du type \emph{implicit declaration of function}. Le compilateur ne connaît alors ni le type de retour ni les types des paramètres, et peut générer un programme faux. \textbf{Règle d'or} : toujours placer les prototypes juste après les \texttt{\#include}, ou définir les fonctions \emph{avant} \texttt{main()}. Vérifie aussi que le prototype et la définition ont exactement les mêmes types.
\end{attention}

\courssub{Transmission des paramètres par valeur}

\begin{propriete}[Passage par valeur en C]
En C, les paramètres sont \textbf{toujours transmis par valeur} : la fonction travaille sur une \emph{copie} des arguments. Toute modification d'un paramètre à l'intérieur de la fonction n'a \textbf{aucun effet} sur la variable de l'appelant.
\end{propriete}

Illustrons cette propriété fondamentale, souvent mal comprise :

\begin{lstlisting}[language=C]
#include <stdio.h>

void doubler(int x);   // prototype

int main(void)
{
    int n = 5;
    doubler(n);
    printf("n = %d\n", n);   // affiche n = 5 : n n'a PAS change !
    return 0;
}

void doubler(int x)
{
    x = 2 * x;   // modifie seulement la COPIE locale x
    printf("x = %d\n", x);   // affiche x = 10
}
\end{lstlisting}

La variable \texttt{n} de \texttt{main} et le paramètre \texttt{x} de \texttt{doubler} sont deux cases mémoire \emph{différentes}. Au moment de l'appel, la valeur 5 est recopiée dans \texttt{x}. Quand \texttt{doubler} termine, sa case \texttt{x} est détruite et \texttt{n} vaut toujours 5. Pour « renvoyer » un résultat, on utilise donc \texttt{return} (la transmission par adresse, avec les pointeurs, dépasse le programme de Terminale TI).

\courssub{Variables locales, variables globales et pile d'appels}

\begin{definition}[Variable locale]
Une \cle{variable locale} est déclarée à l'intérieur d'une fonction (ou d'un bloc). Sa \emph{portée} est limitée à cette fonction : elle est invisible ailleurs. Sa \emph{durée de vie} correspond au temps d'exécution de la fonction : elle est créée à l'entrée et détruite à la sortie.
\end{definition}

\begin{definition}[Variable globale]
Une \cle{variable globale} est déclarée en dehors de toute fonction, généralement après les \texttt{\#include}. Elle est accessible depuis \emph{toutes} les fonctions du fichier et existe pendant toute la durée du programme.
\end{definition}

\begin{exemplebox}[Portée locale contre globale]
\begin{lstlisting}[language=C]
#include <stdio.h>

int compteur = 0;   // variable GLOBALE : visible partout

void incrementer(void)
{
    int pas = 1;        // variable LOCALE a incrementer
    compteur = compteur + pas;   // acces a la globale : autorise
}

int main(void)
{
    incrementer();
    incrementer();
    printf("compteur = %d\n", compteur);   // affiche 2
    // printf("%d", pas);  // ERREUR de compilation : pas est inconnu ici
    return 0;
}
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Les dangers des variables globales]
Les globales semblent pratiques, mais elles rendent les programmes fragiles : n'importe quelle fonction peut les modifier, et quand une erreur apparaît, il est très difficile de savoir \emph{qui} a changé la valeur. Deux fonctions qui utilisent la même globale deviennent impossibles à tester séparément. \textbf{Règle professionnelle} : privilégie les variables locales et les paramètres ; réserve les globales aux constantes partagées (par exemple un taux de TVA déclaré avec \texttt{const}).
\end{attention}

Pour bien comprendre la mécanique des appels, il faut visualiser la \cle{pile d'appels} (\emph{call stack}) : à chaque appel de fonction, un \emph{cadre} contenant ses paramètres et ses variables locales est empilé ; au \texttt{return}, le cadre est dépilé et l'exécution reprend dans l'appelant.

\courssub{Fonctions \texttt{void} et modularisation : l'exemple de la calculatrice}

Une fonction \textbf{sans valeur de retour} est déclarée avec le type \texttt{void} : elle effectue une action (affichage, saisie) mais ne renvoie rien ; on y écrit \texttt{return;} ou rien du tout. Une fonction \textbf{sans paramètre} s'écrit avec des parenthèses contenant \texttt{void} : \texttt{void afficherMenu(void)}.

Décomposons une calculatrice en fonctions, chacune faisant une seule chose :

\begin{lstlisting}[language=C]
#include <stdio.h>

/* ---- Prototypes ---- */
float additionner(float a, float b);
float soustraire(float a, float b);
void  afficherMenu(void);

int main(void)
{
    int choix;
    float x, y;
    afficherMenu();              // fonction sans parametre, sans retour
    scanf("%d", &choix);
    printf("Deux nombres : ");
    scanf("%f %f", &x, &y);
    if (choix == 1)
        printf("Somme = %.2f\n", additionner(x, y));
    else if (choix == 2)
        printf("Difference = %.2f\n", soustraire(x, y));
    else
        printf("Choix invalide.\n");
    return 0;
}

/* ---- Definitions ---- */
void afficherMenu(void)
{
    printf("=== CALCULATRICE ===\n");
    printf("1. Addition\n2. Soustraction\nVotre choix : ");
}

float additionner(float a, float b)
{
    return a + b;
}

float soustraire(float a, float b)
{
    return a - b;
}
\end{lstlisting}

Le \texttt{main()} devient une sorte de « chef d'orchestre » très lisible : il appelle des fonctions dont le nom dit exactement ce qu'elles font. C'est la \cle{modularisation}.

\begin{savaistu}[Une fonction = une seule tâche, bien faite]
Découper un programme en fonctions est le premier pas vers la programmation professionnelle. Le principe de « responsabilité unique » — chaque fonction fait une seule chose et la fait bien — est au cœur du génie logiciel. Dans les startups tech de Douala ou de Yaoundé qui développent des applications de paiement mobile, le code est organisé en milliers de petites fonctions testées individuellement : quand un bug apparaît, on sait immédiatement où chercher, et une fonction corrigée profite à tout le programme.
\end{savaistu}

\begin{exoresolu}[Moyennes de trois élèves]
Énoncé : écrire un programme qui demande les deux notes de trois élèves et affiche la moyenne de chacun, en utilisant une fonction \texttt{float moyenne(float a, float b)}.
\tcblower
Solution détaillée : la fonction est écrite une seule fois, puis appelée trois fois dans une boucle — c'est tout l'intérêt de la modularisation.
\begin{lstlisting}[language=C]
#include <stdio.h>

float moyenne(float a, float b);   // prototype

int main(void)
{
    int i;
    float n1, n2;
    for (i = 1; i <= 3; i++)
    {
        printf("Eleve %d - note 1 : ", i);
        scanf("%f", &n1);
        printf("Eleve %d - note 2 : ", i);
        scanf("%f", &n2);
        printf("-> Moyenne de l'eleve %d : %.2f\n",
               i, moyenne(n1, n2));   // appel dans printf
    }
    return 0;
}

float moyenne(float a, float b)
{
    return (a + b) / 2;
}
\end{lstlisting}
Trace chiffrée : pour l'élève 1 avec \texttt{n1 = 12} et \texttt{n2 = 16}, l'appel copie 12 dans \texttt{a} et 16 dans \texttt{b} ; la fonction renvoie $(12 + 16)/2 = 14$. Pour l'élève 2 avec 8 et 13, elle renvoie $10,5$ ; pour l'élève 3 avec 15 et 9, elle renvoie $12$. Sans fonction, il aurait fallu recopier la formule trois fois — et la corriger trois fois en cas d'erreur.
\end{exoresolu}

\courssub{Les enregistrements : la structure \texttt{struct}}

Jusqu'ici, une variable ne contient qu'\emph{une seule} valeur d'\emph{un seul} type. Or une fiche élève réunit des informations de types différents : un nom (chaîne), une moyenne (réel), un âge (entier). Le C permet de regrouper ces données dans un \cle{enregistrement}.

\begin{definition}[Enregistrement (struct)]
Un \cle{enregistrement} est un type de données composé, défini avec le mot-clé \texttt{struct}, qui regroupe plusieurs variables appelées \emph{champs}, chacune avec son propre type. On accède à chaque champ avec l'opérateur \emph{point} : \texttt{variable.champ}.
\end{definition}

\begin{propriete}[Syntaxe de déclaration et d'utilisation]
\begin{lstlisting}[language=C]
// Declaration du type (apres les #include, avant les fonctions)
struct Eleve
{
    char nom[30];
    float moyenne;
    int age;
};

// Dans une fonction : declaration d'une variable de ce type
struct Eleve e1;

// Acces aux champs avec l'operateur point
e1.age = 17;
e1.moyenne = 13.75;
\end{lstlisting}
Le point-virgule après l'accolade fermante de la \texttt{struct} est \textbf{obligatoire} : son oubli est une erreur de compilation fréquente.
\end{propriete}

\begin{popfigure}

\begin{attention}[Pièges classiques avec les struct]
\begin{itemize}
  \item Oublier le \texttt{;} après l'accolade fermante de la déclaration : erreur de compilation parfois difficile à localiser.
  \item Écrire \texttt{scanf("\%s", \&e.nom)} : pour une chaîne (tableau de \texttt{char}), il ne faut \textbf{pas} de \texttt{\&}, car le nom d'un tableau désigne déjà son adresse. En revanche le \texttt{\&} reste obligatoire pour les champs \texttt{int} et \texttt{float}.
  \item Confondre le \emph{type} (\texttt{struct Eleve}) et la \emph{variable} (\texttt{e}) : c'est la variable qui porte les valeurs, via le point.
  \item \texttt{scanf("\%s")} s'arrête au premier espace. Pour un nom composé (ex. « Jean Pierre »), utilise \texttt{fgets(e.nom, 30, stdin)} et retire le \texttt{\textbackslash n} final.
\end{itemize}
\end{attention}

\courssub{Algorithme intégrant un enregistrement : la tontine}

Mettons tout ensemble — enregistrement, boucle, fonction — dans une application réaliste : la gestion simplifiée des membres d'une \emph{tontine}, cette association d'épargne rotative très répandue au Cameroun. Chaque membre est décrit par son nom et sa cotisation mensuelle.

\begin{experience}[TP : gestion des membres d'une tontine]
\textbf{Objectif} : saisir les membres d'une tontine, calculer le total des cotisations et afficher la liste.

\textbf{Logiciels} : Code::Blocks (ou Dev-C++), compilateur GCC.

\textbf{Manipulation} : crée un projet console en C, saisis le programme ci-dessous, compile (F9) puis exécute pas à pas (F8 dans Code::Blocks) en observant les champs de la variable \texttt{m} dans la fenêtre des variables.
\begin{lstlisting}[language=C]
#include <stdio.h>

#define NB_MEMBRES 3   // constante : nombre de membres

struct Membre
{
    char nom[30];
    float cotisation;   // en FCFA
};

float totalCotisations(struct Membre m);   // prototype

int main(void)
{
    struct Membre m;
    float total = 0;
    int i;

    for (i = 1; i <= NB_MEMBRES; i++)
    {
        printf("Membre %d - nom : ", i);
        scanf("%s", m.nom);
        printf("Membre %d - cotisation (FCFA) : ", i);
        scanf("%f", &m.cotisation);
        total = total + totalCotisations(m);
    }
    printf("\nTotal des cotisations : %.0f FCFA\n", total);
    return 0;
}

float totalCotisations(struct Membre m)
{
    printf("Enregistre : %s (%.0f FCFA)\n", m.nom, m.cotisation);
    return m.cotisation;
}
\end{lstlisting}
\textbf{Observations} : l'enregistrement \texttt{m} est transmis à la fonction \emph{par valeur} : la fonction reçoit une copie complète de la fiche. En exécution pas à pas, on voit les champs \texttt{m.nom} et \texttt{m.cotisation} se remplir à chaque tour de boucle.

\textbf{Interprétation} : regrouper \texttt{nom} et \texttt{cotisation} dans une \texttt{struct} garantit que les deux informations d'un même membre voyagent toujours ensemble — impossible de mélanger le nom de l'un avec la cotisation de l'autre.
\end{experience}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
  \item Une fonction se déclare par un \cle{prototype}, se définit avec un corps, et s'utilise par un \cle{appel}. Le mot-clé \texttt{return} renvoie le résultat ; \texttt{void} signifie « pas de retour » ou « pas de paramètre ».
  \item En C, les paramètres sont transmis \cle{par valeur} : la fonction travaille sur une copie et ne peut pas modifier les variables de l'appelant.
  \item Une variable \cle{locale} n'existe que dans sa fonction ; une variable \cle{globale} est visible partout mais doit être évitée (sauf constantes).
  \item Une \cle{struct} regroupe des champs de types différents ; on accède à un champ par l'opérateur point : \texttt{e.moyenne}.
  \item Toujours placer les prototypes après les \texttt{\#include} pour éviter l'erreur d'« implicit declaration ».
\end{itemize}
\end{aretenir}

\coursec{Algorithmes classiques : recherche séquentielle et tri par sélection}

Dans la section précédente, tu as appris à découper un programme en \cle{fonctions}, à maîtriser la \cle{portée} des variables (locales et globales) et à regrouper des données hétérogènes dans un \cle{enregistrement} (\texttt{struct}). Nous allons maintenant mettre ces acquis au service de deux problèmes extrêmement concrets, que rencontre tout développeur camerounais qui écrit une application monoposte : \emph{retrouver} une information dans une liste (par exemple le nom d'un élève dans le tableau des inscrits d'un lycée de Yaoundé) et \emph{ranger} des données dans l'ordre (par exemple classer les cotisants d'une tontine par montant). Ces deux problèmes se résolvent par deux algorithmes classiques au programme officiel : la \cle{recherche séquentielle} et le \cle{tri par sélection}.

\courssub{Rappel : les tableaux en langage C}

Avant de chercher ou de trier, il faut stocker les données. En C, un \cle{tableau} est une suite de cases mémoire de même type, accessibles par un \cle{indice}.

\begin{propriete}[Déclaration et indices d'un tableau en C]
La déclaration \texttt{int T[50];} réserve 50 cases entières nommées \texttt{T[0]}, \texttt{T[1]}, \ldots, \texttt{T[49]}. Le premier indice est \textbf{toujours 0} et le dernier \textbf{toujours N-1} pour un tableau de N cases. La saisie et l'affichage se font par une boucle \texttt{for}.
\end{propriete}

\begin{exemplebox}[Saisie et affichage des notes d'une classe]
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void) {
    int T[50];   /* tableau pouvant contenir jusqu'à 50 notes */
    int N, i;

    printf("Nombre de notes (max 50) : ");
    scanf("%d", &N);

    /* Saisie : on remplit les cases 0 à N-1 */
    for (i = 0; i < N; i++) {
        printf("Note numéro %d : ", i + 1);
        scanf("%d", &T[i]);
    }

    /* Affichage : on relit les cases 0 à N-1 */
    printf("Notes saisies : ");
    for (i = 0; i < N; i++) {
        printf("%d ", T[i]);
    }
    printf("\n");
    return 0;
}
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Ne jamais dépasser l'indice N-1]
L'erreur la plus fréquente (et la plus dangereuse) est d'écrire \texttt{T[N]} ou de faire tourner une boucle avec la condition \texttt{i <= N}. Le C ne vérifie \textbf{pas} les bornes : lire ou écrire \texttt{T[N]} accède à une zone mémoire qui n'appartient pas au tableau. Le programme peut alors afficher des valeurs absurdes, modifier d'autres variables, ou planter de façon imprévisible. Retiens la règle d'or : boucle \texttt{for (i = 0; i < N; i++)}, jamais \texttt{<= N}.
\end{attention}

\courssub{La recherche séquentielle}

\textbf{Intuition.} Tu cherches la fiche d'un élève nommé « Kamga » dans un paquet de fiches non rangées. Il n'y a qu'une seule méthode : prendre les fiches une par une, dans l'ordre, jusqu'à tomber sur la bonne — ou constater, arrivé au bout du paquet, qu'elle n'y est pas. C'est exactement la recherche séquentielle.

\begin{definition}[Recherche séquentielle]
La \cle{recherche séquentielle} (ou recherche linéaire) d'une valeur $x$ dans un tableau $T$ de $N$ éléments consiste à comparer $x$ successivement à \texttt{T[0]}, \texttt{T[1]}, \ldots, \texttt{T[N-1]}, jusqu'à trouver une case égale à $x$ (on retourne alors son indice) ou épuiser le tableau (la valeur est absente).
\end{definition}

\textbf{Démarche pas à pas :}
\begin{enumerate}
\item Initialiser un indice $i$ à $0$ et un booléen \texttt{trouve} à faux.
\item Tant que $i < N$ et que \texttt{T[i]} est différent de $x$, avancer : $i \leftarrow i+1$.
\item À la sortie de la boucle, si $i < N$, la valeur est trouvée à l'indice $i$ ; sinon elle est absente.
\end{enumerate}

\begin{exemplebox}[Fonction de recherche séquentielle complète]
\begin{lstlisting}[language=C]
#include <stdio.h>

/* Retourne l'indice de la première occurrence de x dans T,
   ou -1 si x est absent. */
int rechercheSequentielle(int T[], int N, int x) {
    int i = 0;
    while (i < N && T[i] != x) {
        i++;   /* on avance tant qu'on n'a pas trouvé */
    }
    if (i < N) {
        return i;    /* trouvé à l'indice i */
    } else {
        return -1;   /* valeur absente : convention -1 */
    }
}

int main(void) {
    int notes[6] = {12, 5, 9, 3, 7, 14};
    int pos = rechercheSequentielle(notes, 6, 9);
    if (pos != -1) {
        printf("Valeur trouvée à l'indice %d\n", pos);
    } else {
        printf("Valeur absente du tableau\n");
    }
    return 0;
}
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Deux pièges classiques]
\begin{itemize}
\item Dans la condition \texttt{while (i < N \&\& T[i] != x)}, le test \texttt{i < N} doit figurer \textbf{en premier} : grâce à l'évaluation paresseuse du \texttt{\&\&}, si $i$ atteint $N$, le second test n'est pas évalué et on ne lit jamais \texttt{T[N]}.
\item Ne confonds pas « retourner l'indice » et « retourner la valeur » : la fonction renvoie la \emph{position} $i$, pas \texttt{T[i]}.
\end{itemize}
\end{attention}

\begin{propriete}[Coût de la recherche séquentielle]
Si la valeur cherchée est absente (ou se trouve en dernière case), la recherche séquentielle effectue exactement $N$ comparaisons. Dans tous les cas, elle en effectue \textbf{au plus} $N$ : on dit que son coût est \cle{linéaire} en $N$. Ce résultat est admis, mais tu peux le vérifier expérimentalement en ajoutant un compteur incrémenté à chaque tour de boucle et en l'affichant.
\end{propriete}

\courssub{Le tri par sélection}

\textbf{Intuition.} Le proviseur veut afficher les notes d'une classe de la plus petite à la plus grande. Une méthode naturelle : parcourir toute la liste, repérer la \emph{plus petite} note et la placer en première position ; puis, parmi les notes \emph{restantes}, repérer la plus petite et la placer en deuxième position ; et ainsi de suite. À chaque tour, la zone déjà triée grandit d'une case.

\begin{definition}[Tri par sélection]
Le \cle{tri par sélection} d'un tableau de $N$ éléments consiste, pour chaque position $i$ allant de $0$ à $N-2$, à :
\begin{enumerate}
\item rechercher l'\cle{indice du minimum} dans la sous-partie non triée \texttt{T[i..N-1]} ;
\item échanger le contenu de \texttt{T[i]} avec celui de cette case minimale.
\end{enumerate}
Après le tour $i$, les cases \texttt{T[0..i]} contiennent les $i+1$ plus petits éléments, dans l'ordre croissant : c'est la \emph{zone triée}.
\end{definition}

\begin{definition}[Indice du minimum]
L'\cle{indice du minimum} d'une sous-partie \texttt{T[i..N-1]} est la position \texttt{imin} telle que \texttt{T[imin]} est le plus petit élément de cette sous-partie. On le calcule en initialisant \texttt{imin = i}, puis en parcourant $j$ de $i+1$ à $N-1$ : chaque fois que \texttt{T[j] < T[imin]}, on met à jour \texttt{imin = j}.
\end{definition}

\begin{methode}[Échanger deux cases : la variable temporaire est obligatoire]
Pour échanger \texttt{T[i]} et \texttt{T[j]}, il faut \textbf{toujours} une variable temporaire, sinon l'une des deux valeurs est écrasée et perdue :
\begin{lstlisting}[language=C]
int temp = T[i];   /* 1. on sauvegarde T[i] */
T[i] = T[j];       /* 2. on copie T[j] dans T[i] */
T[j] = temp;       /* 3. on restaure l'ancien T[i] dans T[j] */
\end{lstlisting}
Écrire directement \texttt{T[i] = T[j]; T[j] = T[i];} est un bug classique : après la première affectation, l'ancienne valeur de \texttt{T[i]} est définitivement perdue.
\end{methode}

\begin{exemplebox}[Code C complet du tri par sélection]
\begin{lstlisting}[language=C]
#include <stdio.h>

/* Tri par sélection : range T[0..N-1] en ordre croissant */
void triSelection(int T[], int N) {
    int i, j, imin, temp;
    for (i = 0; i < N - 1; i++) {        /* N-1 tours suffisent */
        /* 1. recherche de l'indice du minimum dans T[i..N-1] */
        imin = i;
        for (j = i + 1; j < N; j++) {
            if (T[j] < T[imin]) {
                imin = j;
            }
        }
        /* 2. échange de T[i] et T[imin] via variable temporaire */
        temp = T[i];
        T[i] = T[imin];
        T[imin] = temp;
    }
}

int main(void) {
    int notes[5] = {12, 5, 9, 3, 7};
    int i;
    triSelection(notes, 5);
    printf("Tableau trié : ");
    for (i = 0; i < 5; i++) {
        printf("%d ", notes[i]);   /* affiche : 3 5 7 9 12 */
    }
    printf("\n");
    return 0;
}
\end{lstlisting}
\end{exemplebox}

\begin{exoresolu}[{Trace complète du tri de $[12, 5, 9, 3, 7]$}]
Énoncé : effectuer la trace manuelle du tri par sélection du tableau $[12, 5, 9, 3, 7]$ et dénombrer les comparaisons.
\tcblower
\textbf{Tour 1} ($i=0$) : on cherche le minimum de $[12, 5, 9, 3, 7]$. Comparaisons : $5<12$ (oui, imin$=1$), $9<5$ (non), $3<5$ (oui, imin$=3$), $7<3$ (non) : \textbf{4 comparaisons}. Échange de \texttt{T[0]} et \texttt{T[3]} : $[3, 5, 9, 12, 7]$.

\textbf{Tour 2} ($i=1$) : minimum de $[5, 9, 12, 7]$. Comparaisons : $9<5$ (non), $12<5$ (non), $7<5$ (non) : \textbf{3 comparaisons}. imin$=1=i$, l'échange laisse le tableau inchangé : $[3, 5, 9, 12, 7]$.

\textbf{Tour 3} ($i=2$) : minimum de $[9, 12, 7]$. Comparaisons : $12<9$ (non), $7<9$ (oui, imin$=4$) : \textbf{2 comparaisons}. Échange de \texttt{T[2]} et \texttt{T[4]} : $[3, 5, 7, 12, 9]$.

\textbf{Tour 4} ($i=3$) : minimum de $[12, 9]$. Comparaison : $9<12$ (oui, imin$=4$) : \textbf{1 comparaison}. Échange : $[3, 5, 7, 9, 12]$.

Total : $4+3+2+1 = 10$ comparaisons, et le tableau est trié. On remarque qu'aucun tour n'est nécessaire pour la dernière case : quand les $N-1$ premières sont en place, la dernière l'est forcément.
\end{exoresolu}

\courssub{Combien de comparaisons ? Le coût quadratique du tri par sélection}

Comptons les comparaisons dans le cas général d'un tableau de $N$ éléments. Au tour $i$, la recherche du minimum dans la sous-partie \texttt{T[i..N-1]}, qui contient $N-i$ cases, exige $N-i-1$ comparaisons. Le nombre total de comparaisons est donc :
\[
C(N) \;=\; (N-1) + (N-2) + \dots + 2 + 1 \;=\; \sum_{k=1}^{N-1} k .
\]

\begin{propriete}[Le tri par sélection effectue exactement $\dfrac{N(N-1)}{2}$ comparaisons]
Démonstration guidée. Notons $S = 1 + 2 + \dots + (N-1)$. Écrivons la somme dans les deux sens et additionnons membre à membre :
\begin{align*}
S &= 1 + 2 + \dots + (N-2) + (N-1)\\
S &= (N-1) + (N-2) + \dots + 2 + 1\\
\hline
2S &= \underbrace{N + N + \dots + N + N}_{N-1 \text{ termes}} = N(N-1)
\end{align*}
car chaque colonne verticale totalise $N$ (par exemple $1 + (N-1) = N$, $2 + (N-2) = N$, etc.) et il y a $N-1$ colonnes. Donc :
\[ S = \frac{N(N-1)}{2}. \]
Le tri par sélection effectue donc exactement $\dfrac{N(N-1)}{2}$ comparaisons, \emph{quel que soit} l'ordre initial du tableau. Vérification avec notre exemple : $N=5$ donne $\dfrac{5 \times 4}{2} = 10$ comparaisons, conforme à la trace.
\end{propriete}

On dit que le tri par sélection a un coût \cle{quadratique} : quand $N$ double, le nombre de comparaisons est multiplié par environ 4. Le graphique suivant montre cette croissance.

\begin{savaistu}[Et pour les très grands tableaux ?]
Le tri par sélection est le plus simple à comprendre et à programmer, mais son coût quadratique devient rédhibitoire pour de très grands volumes : trier un million de fiches demanderait environ $5 \times 10^{11}$ comparaisons. Les informaticiens utilisent alors des tris plus rapides comme le \cle{tri rapide} (\emph{quicksort}, inventé par Tony Hoare en 1960), dont le coût moyen est de l'ordre de $N \log_2 N$ — soit environ 20 millions d'opérations pour un million de fiches, c'est-à-dire 25\,000 fois moins. C'est ce genre d'algorithme qui permet aux applications de Mobile Money de traiter des millions de transactions. Au baccalauréat, cependant, c'est bien le tri par sélection qui est exigible : maîtrise-le parfaitement.
\end{savaistu}

\courssub{Application : classer les cotisants d'une tontine par montant décroissant}

Une tontine de quartier à Douala veut afficher ses cotisants du plus gros contributeur au plus modeste. Il suffit d'\emph{inverser le sens de la comparaison} : au lieu de chercher le minimum, on cherche le \textbf{maximum} de la zone non triée. On en profite pour utiliser un enregistrement (section précédente) afin de trier les montants \emph{sans perdre les noms}.

\begin{exemplebox}[Tri décroissant des cotisants (enregistrements)]
\begin{lstlisting}[language=C]
#include <stdio.h>
#include <string.h>

typedef struct {
    char nom[30];
    float montant;   /* cotisation en FCFA */
} Cotisant;

/* Tri par sélection adapté : ordre DÉCROISSANT sur le montant */
void triCotisants(Cotisant T[], int N) {
    int i, j, imax;
    Cotisant temp;
    for (i = 0; i < N - 1; i++) {
        imax = i;                       /* on cherche le MAXIMUM */
        for (j = i + 1; j < N; j++) {
            if (T[j].montant > T[imax].montant) {  /* > au lieu de < */
                imax = j;
            }
        }
        temp = T[i];        /* échange d'enregistrements complets */
        T[i] = T[imax];
        T[imax] = temp;
    }
}

int main(void) {
    Cotisant tontine[4] = {
        {"Mballa", 50000}, {"Ngo Bell", 120000},
        {"Etoundi", 75000}, {"Fotso", 200000}
    };
    int i;
    triCotisants(tontine, 4);
    printf("Classement des cotisants :\n");
    for (i = 0; i < 4; i++) {
        printf("%d. %-10s : %.0f FCFA\n",
               i + 1, tontine[i].nom, tontine[i].montant);
    }
    return 0;
}
\end{lstlisting}
Affichage obtenu : Fotso (200\,000), Ngo Bell (120\,000), Etoundi (75\,000), Mballa (50\,000). Remarque que l'échange porte sur l'enregistrement \emph{entier} : le nom suit toujours son montant.
\end{exemplebox}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Un tableau \texttt{int T[N]} s'indice de \texttt{0} à \texttt{N-1} ; toute boucle de parcours s'écrit \texttt{for (i = 0; i < N; i++)}.
\item La \cle{recherche séquentielle} compare la valeur cherchée à chaque case dans l'ordre : au plus $N$ comparaisons (coût linéaire) ; on retourne l'indice trouvé ou $-1$ si la valeur est absente.
\item Le \cle{tri par sélection} place à chaque tour le minimum de la zone non triée en tête de cette zone, par échange avec variable temporaire.
\item Il effectue exactement $\dfrac{N(N-1)}{2}$ comparaisons (somme des entiers de $1$ à $N-1$) : coût quadratique, indépendant de l'ordre initial.
\item Pour trier en ordre décroissant, on remplace la recherche du minimum par celle du maximum (\texttt{>} au lieu de \texttt{<}).
\end{itemize}
\end{aretenir}

\coursec{Récursivité, gestion des erreurs et projet d'application complète}

Dans la section précédente, nous avons résolu deux grands problèmes classiques — la recherche séquentielle et le tri par sélection — à l'aide de boucles. Mais il existe une autre manière, plus élégante, d'exprimer certains algorithmes : au lieu de \emph{répéter} un traitement, on le \emph{décompose} en un problème plus petit de même nature. C'est l'idée de la \cle{récursivité}. Nous verrons ensuite comment lire et corriger les erreurs signalées par le compilateur, puis nous terminerons par deux projets complets qui mobilisent tout ce que tu as appris dans cette leçon.

\courssub{La notion de fonction récursive}

\textbf{Intuition : les poupées russes.} Imagine une tontine de quartier à Yaoundé : pour connaître le total collecté, le président demande au trésorier, qui demande à son adjoint, et ainsi de suite jusqu'au dernier membre qui, lui, connaît sa cotisation. Chacun ajoute sa part au résultat remonté par le suivant. Le problème « total de $n$ membres » a été ramené au problème « total de $n-1$ membres », jusqu'à un cas si petit qu'on le résout directement. C'est exactement le mécanisme d'une fonction récursive.

\begin{definition}[Fonction récursive, cas de base, cas récursif]
Une \cle{fonction récursive} est une fonction qui \textbf{s'appelle elle-même} dans son propre corps. Toute fonction récursive correcte comporte deux parties :
\begin{itemize}
\item le \cle{cas de base} (ou condition d'arrêt) : un cas trivial résolu \emph{sans} nouvel appel récursif ;
\item le \cle{cas récursif} : la fonction s'appelle elle-même sur un problème \emph{strictement plus petit}, qui se rapproche du cas de base.
\end{itemize}
Si le cas de base est absent ou jamais atteint, les appels s'empilent sans fin jusqu'à épuiser la mémoire de la pile : c'est le \cle{débordement de pile} (\emph{stack overflow}), qui fait planter le programme.
\end{definition}

\textbf{L'exemple fondateur : la factorielle.} En mathématiques, $n! = n \times (n-1) \times \dots \times 2 \times 1$, avec $0! = 1$. On peut la définir autrement :
\[ \text{fact}(0) = 1 \qquad \text{et} \qquad \text{fact}(n) = n \times \text{fact}(n-1) \quad \text{pour } n \geq 1. \]
Cette définition se traduit en C \emph{mot pour mot} :

\begin{lstlisting}[language=C]
long fact(int n) {
    if (n == 0)          /* cas de base : on s'arrete ici */
        return 1;
    else                 /* cas recursif : probleme plus petit */
        return n * fact(n - 1);
}
\end{lstlisting}

\begin{exemplebox}[Trace détaillée de fact(4)]
L'appel \texttt{fact(4)} déclenche \textbf{5 appels empilés} sur la pile d'exécution. Phase de descente : \texttt{fact(4)} attend \texttt{fact(3)}, qui attend \texttt{fact(2)}, qui attend \texttt{fact(1)}, qui attend \texttt{fact(0)}. Phase de remontée :
\begin{align*}
\text{fact}(0) &= 1 \\
\text{fact}(1) &= 1 \times \text{fact}(0) = 1 \times 1 = 1 \\
\text{fact}(2) &= 2 \times \text{fact}(1) = 2 \times 1 = 2 \\
\text{fact}(3) &= 3 \times \text{fact}(2) = 3 \times 2 = 6 \\
\text{fact}(4) &= 4 \times \text{fact}(3) = 4 \times 6 = 24
\end{align*}
Résultat final : $4! = 4 \times 3 \times 2 \times 1 \times 1 = 24$. Chaque appel possède \emph{sa propre copie} de la variable \texttt{n} sur la pile.
\end{exemplebox}

\begin{propriete}[Correction de fact : démonstration par récurrence]
Montrons que \texttt{fact(n)} renvoie bien $n!$ pour tout entier $n \geq 0$.
\begin{itemize}
\item \textbf{Initialisation} : pour $n = 0$, la fonction renvoie $1$, et $0! = 1$ par convention. La propriété est vraie au rang $0$.
\item \textbf{Hérédité} : supposons que \texttt{fact(k)} renvoie $k!$ pour un entier $k \geq 0$ quelconque. Alors \texttt{fact(k+1)} renvoie $(k+1) \times \text{fact}(k) = (k+1) \times k! = (k+1)!$. La propriété est vraie au rang $k+1$.
\item \textbf{Conclusion} : par récurrence, \texttt{fact(n)} renvoie $n!$ pour tout $n \geq 0$.
\end{itemize}
Ce raisonnement est le modèle général de preuve de toute fonction récursive : vérifier le cas de base, puis supposer le sous-problème correct et en déduire le problème courant.
\end{propriete}

\begin{methode}[Concevoir une fonction récursive en 3 questions]
Avant d'écrire la moindre ligne de code, réponds par écrit à ces trois questions :
\begin{enumerate}
\item \textbf{Quel est le cas de base ?} Le plus petit problème résolvable directement (ex. \texttt{fact(0) = 1}).
\item \textbf{Comment ramener $n$ à un problème plus petit ?} L'appel récursif doit porter sur une donnée \emph{strictement réduite} (ex. \texttt{fact(n-1)}), sinon la récursion ne s'arrêtera jamais.
\item \textbf{Que combiner au retour ?} Quelle opération relie le résultat du sous-problème au résultat attendu (ex. multiplier par \texttt{n}) ?
\end{enumerate}
Vérifie enfin sur un petit exemple ($n = 2$ ou $3$) que la descente atteint bien le cas de base.
\end{methode}

\textbf{D'autres exemples classiques.} La même méthode s'applique à la somme des $n$ premiers entiers, à la puissance et à la célèbre suite de Fibonacci (souvent proposée au Bac) :

\begin{lstlisting}[language=C]
int somme(int n) {          /* 1 + 2 + ... + n */
    if (n == 0) return 0;   /* cas de base */
    return n + somme(n - 1);
}

double puissance(double x, int n) {   /* x^n, n >= 0 */
    if (n == 0) return 1;
    return x * puissance(x, n - 1);
}

int fibo(int n) {           /* suite de Fibonacci */
    if (n <= 1) return n;   /* deux cas de base : fibo(0)=0, fibo(1)=1 */
    return fibo(n - 1) + fibo(n - 2);
}
\end{lstlisting}

\begin{attention}[Récursif ou itératif ?]
Toute fonction récursive peut s'écrire avec une boucle, et réciproquement. La version récursive est souvent \textbf{plus lisible} et plus proche de la définition mathématique, mais elle \textbf{consomme de la mémoire} (un cadre de pile par appel) et peut être \textbf{moins efficace} : \texttt{fibo(n)} récursif recalcule plusieurs fois les mêmes valeurs et devient très lent dès $n \approx 40$. En pratique, on choisit la récursivité quand le problème est \emph{naturellement} récursif (arborescences, fractales), et la boucle quand l'itération est simple. Et surtout : \textbf{jamais de fonction récursive sans cas de base atteignable} — \texttt{fact(-1)} avec notre code provoque un débordement de pile, car $n$ ne vaudra jamais $0$. À noter aussi : les factorielles grandissent très vite et dépassent la capacité d'un \texttt{long} dès $n = 21$ ; au-delà, le résultat affiché est faux (dépassement de capacité silencieux).
\end{attention}

\begin{savaistu}[La récursivité est partout]
La récursivité est au cœur de nombreux algorithmes avancés : les \textbf{fractales} (figures géométriques auto-similaires comme le flocon de Koch), l'\textbf{exploration des dossiers} d'un disque dur (un dossier contient des dossiers qui contiennent des dossiers...), les \textbf{jeux d'échecs} (le programme évalue un coup en explorant récursivement les réponses possibles de l'adversaire), et même les moteurs de recherche de fichiers de ton système d'exploitation. Les grandes écoles et les entreprises technologiques testent presque toujours la récursivité lors de leurs entretiens d'embauche.
\end{savaistu}

\courssub{Gestion des erreurs de compilation}

\textbf{Intuition.} Le compilateur est ton meilleur correcteur : il ne se trompe jamais sur la \emph{syntaxe}, et ses messages, bien qu'en anglais, contiennent toujours trois informations précieuses : le \textbf{fichier}, la \textbf{ligne} et la \textbf{cause} de l'erreur. Apprendre à les lire, c'est gagner des heures.

Il faut distinguer deux familles d'erreurs :
\begin{itemize}
\item les \cle{erreurs syntaxiques} : le programme viole la grammaire du C (point-virgule manquant, parenthèse oubliée...). Le compilateur les détecte et \textbf{refuse de produire l'exécutable} ;
\item les \cle{erreurs logiques} : le programme compile et s'exécute, mais produit un \textbf{résultat faux} (mauvaise formule, boucle infinie, condition inversée). Seuls les tests et le débogueur permettent de les débusquer.
\end{itemize}

\begin{attention}[Corrige toujours la PREMIÈRE erreur d'abord]
Une erreur signalée à la ligne 25 est très souvent \emph{causée} par un oubli à la ligne 24 (par exemple un point-virgule manquant). Une seule faute peut déclencher une cascade de 20 messages en aval. La bonne démarche : \textbf{corriger la première erreur de la liste, recompiler}, et constater que la moitié des messages a disparu. Ne t'acharne jamais sur la dernière erreur avant d'avoir traité la première.
\end{attention}

\textbf{Le débogueur de l'IDE.} Pour traquer les erreurs \emph{logiques}, Code::Blocks et Dev-C++ intègrent un débogueur. La démarche :
\begin{enumerate}
\item placer un \cle{point d'arrêt} (\emph{breakpoint}) sur la ligne suspecte (clic dans la marge ou touche F5) ;
\item lancer le programme en mode \emph{Debug} : l'exécution se fige au point d'arrêt ;
\item avancer \cle{pas à pas} (F7 : entrer dans les fonctions ; F8 : ligne suivante) ;
\item observer dans la fenêtre \emph{Watches} la \textbf{valeur des variables} à chaque étape et repérer le moment où elle devient fausse.
\end{enumerate}
C'est l'outil idéal pour visualiser concrètement la pile d'appels d'une fonction récursive : tu verras \texttt{fact} apparaître plusieurs fois avec des valeurs de \texttt{n} différentes.

\courssub{Projet guidé : deux applications complètes}

\begin{experience}[Projet 1 : calculatrice à menu]
\textbf{Objectif :} produire un exécutable complet combinant boucle \texttt{do...while}, \texttt{switch} et fonctions.\par
\textbf{Matériel :} un ordinateur avec Code::Blocks (ou Dev-C++) installé.\par
\textbf{Étapes :}
\begin{enumerate}
\item Créer un projet console C dans Code::Blocks, écrire le code ci-dessous.
\item Compiler (F9), corriger les éventuelles erreurs en commençant par la première.
\item Tester chaque opération, y compris la division par zéro, puis quitter avec le choix 0.
\end{enumerate}
\begin{lstlisting}[language=C]
#include <stdio.h>

double addition(double a, double b) { return a + b; }
double produit(double a, double b)  { return a * b; }

int main(void) {
    int choix;
    double x, y;
    do {
        printf("\n=== CALCULATRICE ===\n");
        printf("1. Addition\n2. Multiplication\n0. Quitter\n");
        printf("Votre choix : ");
        scanf("%d", &choix);
        switch (choix) {
            case 1:
                printf("Deux nombres : ");
                scanf("%lf %lf", &x, &y);
                printf("Resultat : %.2f\n", addition(x, y));
                break;
            case 2:
                printf("Deux nombres : ");
                scanf("%lf %lf", &x, &y);
                printf("Resultat : %.2f\n", produit(x, y));
                break;
            case 0:
                printf("Au revoir !\n");
                break;
            default:
                printf("Choix invalide.\n");
        }
    } while (choix != 0);   /* la boucle recommence tant qu'on ne quitte pas */
    return 0;
}
\end{lstlisting}
\textbf{Observation :} le menu réapparaît après chaque opération grâce au \texttt{do...while}, qui garantit au moins un affichage. Le \texttt{switch} aiguille vers la bonne fonction. Remarque le format \texttt{\%lf} dans \texttt{scanf} : il est \emph{obligatoire} pour lire un \texttt{double} (alors que \texttt{printf} accepte \texttt{\%f} pour un \texttt{double}).
\end{experience}

\begin{exoresolu}[Projet 2 : mini-gestionnaire de tontine]
Énoncé. Une tontine regroupe au plus 50 membres. Écrire un programme C qui : (a) saisit les membres (nom, mise mensuelle) dans un tableau d'enregistrements ; (b) trie les membres par mise décroissante (tri par sélection) ; (c) recherche un membre par son nom (recherche séquentielle) ; (d) affiche le total collecté chaque mois.
\tcblower
Solution détaillée. On déclare une \texttt{struct Membre}, un tableau \texttt{t} et un compteur \texttt{n}. Le tri par sélection échange des enregistrements complets ; la recherche compare les chaînes avec \texttt{strcmp} (bibliothèque \texttt{string.h}).
\begin{lstlisting}[language=C]
#include <stdio.h>
#include <string.h>

#define MAX 50

typedef struct {
    char nom[30];
    float mise;          /* mise mensuelle en FCFA */
} Membre;

/* Tri par selection : mises decroissantes */
void trier(Membre t[], int n) {
    int i, j, max;
    Membre tmp;
    for (i = 0; i < n - 1; i++) {
        max = i;
        for (j = i + 1; j < n; j++)
            if (t[j].mise > t[max].mise)
                max = j;
        tmp = t[i]; t[i] = t[max]; t[max] = tmp;
    }
}

/* Recherche sequentielle par nom : retourne l'indice ou -1 */
int rechercher(Membre t[], int n, char nom[]) {
    int i;
    for (i = 0; i < n; i++)
        if (strcmp(t[i].nom, nom) == 0)
            return i;
    return -1;
}

int main(void) {
    Membre t[MAX];
    int n, i, pos;
    float total = 0;
    char nomCherche[30];

    printf("Nombre de membres (max %d) : ", MAX);
    scanf("%d", &n);
    for (i = 0; i < n; i++) {
        printf("Nom du membre %d : ", i + 1);
        scanf("%s", t[i].nom);
        printf("Mise mensuelle (FCFA) : ");
        scanf("%f", &t[i].mise);
    }

    trier(t, n);
    printf("\n--- Membres tries par mise decroissante ---\n");
    for (i = 0; i < n; i++) {
        printf("%-15s %10.0f FCFA\n", t[i].nom, t[i].mise);
        total += t[i].mise;
    }
    printf("Total mensuel collecte : %.0f FCFA\n", total);

    printf("\nNom a rechercher : ");
    scanf("%s", nomCherche);
    pos = rechercher(t, n, nomCherche);
    if (pos >= 0)
        printf("%s mise %.0f FCFA (rang %d).\n",
               t[pos].nom, t[pos].mise, pos + 1);
    else
        printf("Membre introuvable.\n");
    return 0;
}
\end{lstlisting}
Remarque la transmission du tableau \texttt{t} aux fonctions : en C, un tableau est passé par \emph{adresse}, donc \texttt{trier} modifie directement le tableau du \texttt{main}. Le \texttt{typedef} permet d'écrire simplement \texttt{Membre} au lieu de \texttt{struct Membre}. Enfin, \texttt{strcmp(a, b)} renvoie \texttt{0} quand les deux chaînes sont \emph{identiques} : on teste donc \texttt{== 0}, et non \texttt{== 1}.
\end{exoresolu}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Une fonction récursive s'appelle elle-même : \textbf{cas de base} (arrêt) + \textbf{cas récursif} (problème réduit). Sans cas de base atteignable : débordement de pile.
\item Conception en 3 questions : cas de base ? réduction du problème ? combinaison au retour ?
\item Le compilateur indique fichier, ligne et cause : corriger \textbf{la première erreur d'abord}, puis recompiler.
\item Erreur syntaxique $\neq$ erreur logique : la seconde se traque au débogueur (points d'arrêt, pas à pas, observation des variables).
\item Un programme complet combine structures de contrôle, fonctions, tableaux et enregistrements : tu sais désormais en produire un de bout en bout.
\end{itemize}
\end{aretenir}

\begin{aretenir}[Boîte à outils de la leçon]
\begin{itemize}
  \item \textbf{Enregistrement} : \texttt{struct Membre \{ char nom[50]; int montant; char mois[15]; \};} — on accède aux champs par le point : \texttt{m.montant}. Attention au point-virgule final après l'accolade fermante.
  \item \textbf{Entrées-sorties} : \texttt{printf("\%d", x)}, \texttt{scanf("\%d", \&x)} ; pour une chaîne : \texttt{scanf("\%s", m.nom)} (pas de \texttt{\&} devant un tableau, car un tableau est déjà une adresse). Comparaison de chaînes : \texttt{strcmp(a, b) == 0} (bibliothèque \texttt{string.h}).
  \item \textbf{Menu} : boucle \texttt{do \{ ... \} while (choix != 6);} avec \texttt{switch (choix)} et un \texttt{case} par option, sans oublier les \texttt{break}.
  \item \textbf{Recherche séquentielle} : parcourir du premier au dernier élément ; si \texttt{strcmp(t[i].nom, cherche) == 0}, on a trouvé à l'indice $i$ et on peut sortir avec \texttt{break}.
  \item \textbf{Tri par sélection décroissant} : pour $i$ de $0$ à $n-2$, chercher l'indice \texttt{iMax} du maximum dans $t[i..n-1]$, puis échanger \texttt{t[i]} et \texttt{t[iMax]} via une variable temporaire de type \texttt{struct Membre}.
  \item \textbf{Transmission de paramètres} : un tableau passé à une fonction est transmis par \emph{adresse} : les modifications faites dans la fonction sont visibles dans \texttt{main}. Une valeur de retour (\texttt{long}) s'obtient avec \texttt{return}.
\end{itemize}
\end{aretenir}

\begin{exoresolu}[Le gestionnaire de tontine — solution complète]
\textbf{Étape 1 — Analyse.} Les données sont hétérogènes (chaînes + entier) : c'est le cas typique d'un \texttt{struct}. Le nombre de membres varie : on gère un tableau \texttt{tontine} et un compteur global \texttt{nb}. Chaque fonctionnalité du menu devient une fonction, ce qui rend le programme lisible et testable séparément.

\textbf{Étape 2 — Programme complet.}

\begin{lstlisting}[language=C]
#include <stdio.h>
#include <string.h>

#define MAX 100

/* Declaration de l'enregistrement */
struct Membre {
    char nom[50];
    int montant;
    char mois[15];
};

/* Variables globales : tableau et effectif */
struct Membre tontine[MAX];
int nb = 0;

/* 1. Enregistrement avec saisie controlee */
void enregistrer() {
    if (nb >= MAX) {
        printf("Tontine pleine !\n");
        return;
    }
    printf("Nom du membre (sans espace) : ");
    scanf("%s", tontine[nb].nom);
    printf("Mois de cotisation : ");
    scanf("%s", tontine[nb].mois);
    /* Saisie controlee : on recommence tant que le montant est invalide */
    do {
        printf("Montant (5000 a 100000 FCFA) : ");
        scanf("%d", &tontine[nb].montant);
        if (tontine[nb].montant < 5000 || tontine[nb].montant > 100000)
            printf("Montant invalide, recommencez.\n");
    } while (tontine[nb].montant < 5000 || tontine[nb].montant > 100000);
    nb++;
    printf("Membre enregistre avec succes.\n");
}

/* 2. Affichage formate de la liste */
void afficher() {
    int i;
    printf("\n%-20s %-15s %10s\n", "NOM", "MOIS", "MONTANT");
    printf("-----------------------------------------------\n");
    for (i = 0; i < nb; i++)
        printf("%-20s %-15s %10d\n",
               tontine[i].nom, tontine[i].mois, tontine[i].montant);
}

/* 3. Recherche sequentielle par nom */
void rechercher() {
    char cherche[50];
    int i, trouve = 0;
    printf("Nom a rechercher : ");
    scanf("%s", cherche);
    for (i = 0; i < nb; i++) {
        if (strcmp(tontine[i].nom, cherche) == 0) {
            printf("Trouve : %s a cotise %d FCFA en %s.\n",
                   tontine[i].nom, tontine[i].montant, tontine[i].mois);
            trouve = 1;
            break; /* on arrete des la premiere occurrence */
        }
    }
    if (!trouve)
        printf("Aucun membre de ce nom.\n");
}

/* 4. Tri par selection : montants decroissants */
void trier() {
    int i, j, iMax;
    struct Membre temp;
    for (i = 0; i < nb - 1; i++) {
        iMax = i;
        for (j = i + 1; j < nb; j++)
            if (tontine[j].montant > tontine[iMax].montant)
                iMax = j;
        /* Echange des structures entieres */
        temp = tontine[i];
        tontine[i] = tontine[iMax];
        tontine[iMax] = temp;
    }
    printf("Liste triee par montant decroissant.\n");
}

/* 5. Total des cotisations (tableau + taille en parametres) */
long totalCotisations(struct Membre t[], int n) {
    long s = 0;
    int i;
    for (i = 0; i < n; i++)
        s += t[i].montant;
    return s;
}

int main() {
    int choix;
    /* Pre-chargement du jeu d'essai de Mme Etoundi */
    strcpy(tontine[0].nom, "Ngo");      tontine[0].montant = 25000; strcpy(tontine[0].mois, "Janvier");
    strcpy(tontine[1].nom, "Kamdem");   tontine[1].montant = 50000; strcpy(tontine[1].mois, "Janvier");
    strcpy(tontine[2].nom, "Fouda");    tontine[2].montant = 10000; strcpy(tontine[2].mois, "Fevrier");
    strcpy(tontine[3].nom, "Mbarga");   tontine[3].montant = 75000; strcpy(tontine[3].mois, "Janvier");
    strcpy(tontine[4].nom, "Aissatou"); tontine[4].montant = 30000; strcpy(tontine[4].mois, "Fevrier");
    nb = 5;

    do {
        printf("\n===== TONTINE ETOILE DU CENTRE =====\n");
        printf("1. Enregistrer un membre\n");
        printf("2. Afficher la liste\n");
        printf("3. Rechercher un membre\n");
        printf("4. Trier par montant decroissant\n");
        printf("5. Total des cotisations\n");
        printf("6. Quitter\n");
        printf("Votre choix : ");
        scanf("%d", &choix);
        switch (choix) {
            case 1: enregistrer(); break;
            case 2: afficher(); break;
            case 3: rechercher(); break;
            case 4: trier(); break;
            case 5: printf("Total : %ld FCFA\n",
                           totalCotisations(tontine, nb)); break;
            case 6: printf("Au revoir, Mme Etoundi !\n"); break;
            default: printf("Choix invalide.\n");
        }
    } while (choix != 6);
    return 0;
}
\end{lstlisting}

\textbf{Étape 3 — Justifications.}
\begin{itemize}
  \item Le total est déclaré \texttt{long} car une tontine de 100 membres à \num{100000} FCFA atteint \num{10000000} FCFA : valeur encore compatible avec \texttt{int}, mais \texttt{long} est plus sûr (format \texttt{\%ld} obligatoire dans \texttt{printf}).
  \item On n'écrit \textbf{pas} \texttt{\&} devant \texttt{tontine[nb].nom} dans \texttt{scanf("\%s", ...)} : un tableau de caractères est déjà une adresse. En revanche, le \texttt{\&} est indispensable pour l'entier : \texttt{scanf("\%d", \&tontine[nb].montant)}.
  \item \texttt{strcmp} retourne 0 en cas d'égalité : le test est \texttt{== 0}, jamais \texttt{!= 0}.
  \item Les chaînes du pré-chargement sont copiées avec \texttt{strcpy} : on ne peut pas affecter une chaîne à un tableau par \texttt{=} après sa déclaration.
  \item \texttt{scanf("\%s", ...)} s'arrête au premier espace : c'est pourquoi le jeu d'essai utilise les seuls noms de famille (\texttt{Ngo}, \texttt{Kamdem}...). Saisir \og Ngo Bell \fg{} couperait la chaîne et décalerait la saisie suivante. Une version professionnelle utiliserait \texttt{fgets}, hors programme de Terminale.
\end{itemize}

\textbf{Étape 4 — Vérification au débogueur.} Point d'arrêt sur la ligne de l'échange dans \texttt{trier}. Premier passage ($i=0$) : le maximum du tableau est \num{75000} (Mbarga, indice 3) ; après échange, Mbarga occupe la position 0. Deuxième passage ($i=1$) : le maximum de la sous-partie restante est \num{50000} (Kamdem). Après $n-1 = 4$ passages, l'ordre obtenu est : Mbarga (\num{75000}), Kamdem (\num{50000}), Aissatou (\num{30000}), Ngo (\num{25000}), Fouda (\num{10000}). L'option 5 affiche bien \texttt{Total : 190000 FCFA} : le cahier des charges est respecté.
\end{exoresolu}

\begin{methode}[Vérifier un tri par sélection avec une trace d'exécution]
Pour valider ton tri sur papier (compétence exigée au Bac) avant même de compiler :
\begin{enumerate}
  \item Écris le tableau initial sur une ligne, un montant par case, avec les indices $0$ à $n-1$.
  \item Pour chaque valeur de $i$ de $0$ à $n-2$, souligne la sous-partie $t[i..n-1]$ et entoure son maximum : c'est \texttt{iMax}.
  \item Barre les cases $i$ et \texttt{iMax} et écris les valeurs échangées sur la ligne suivante.
  \item Vérifie qu'à la fin du passage $i$, les $i+1$ premières cases sont définitivement triées.
  \item Compte les passages : il doit y en avoir exactement $n-1$, soit 4 pour 5 membres.
\end{enumerate}
Cette trace est aussi ce que tu observes, case par case, dans la fenêtre \emph{Watch} du débogueur de Code::Blocks.
\end{methode}

\begin{attention}[Erreurs fréquentes rencontrées pendant l'activité]
\begin{itemize}
  \item \textbf{Point-virgule oublié} après l'accolade fermante de la déclaration du \texttt{struct} : le compilateur signale une erreur à la ligne \emph{suivante}, ce qui déroute souvent.
  \item \textbf{\texttt{break} oublié} dans un \texttt{case} : les options du menu s'enchaînent toutes (exécution en cascade).
  \item \textbf{Échange sans variable temporaire} dans le tri : la première valeur écrasée est perdue définitivement.
  \item \textbf{Condition de boucle inversée} dans la saisie contrôlée : tester \texttt{< 5000 || > 100000} (montant \emph{invalide}), et non \texttt{\&\&} — un montant ne peut pas être à la fois inférieur à \num{5000} et supérieur à \num{100000}, la boucle ne recommencerait jamais.
  \item \textbf{Comparaison de chaînes avec \texttt{==}} : cela compare des adresses, pas les contenus ; toujours utiliser \texttt{strcmp}.
  \item \textbf{Dépassement de tableau} : saisir un nom de plus de 49 caractères avec \texttt{scanf("\%s", ...)} écrase la mémoire voisine (comportement imprévisible). En production, on limite avec \texttt{\%49s}.
  \item \textbf{Format inadapté} : afficher un \texttt{long} avec \texttt{\%d} au lieu de \texttt{\%ld} produit une valeur fausse ou un avertissement du compilateur.
\end{itemize}
\end{attention}

\coursec{Premiers programmes en C : structure, types, entrées-sorties}

\begin{propriete}[Types de base, constantes et entrées-sorties formatées]
En C, tout programme manipule des données typées. Les types fondamentaux sont :
\begin{itemize}
\item \texttt{int} : entier signé (généralement 32 bits, intervalle $\approx \pm 2 \times 10^9$).
\item \texttt{float} : réel simple précision (6--7 chiffres significatifs).
\item \texttt{double} : réel double précision (15--16 chiffres) ; par défaut pour les littéraux à virgule.
\item \texttt{char} : caractère unique (codé sur 1 octet, valeur ASCII).
\end{itemize}
Une \cle{constante} nommée se déclare avec \texttt{const} (ex. \texttt{const int MAX = 100;}) : elle occupe de la mémoire mais est en lecture seule.
Les bibliothèques standard \texttt{stdio.h} (entrées-sorties) et \texttt{math.h} (fonctions mathématiques : \texttt{sqrt}, \texttt{cos}, \texttt{fabs}, \texttt{pow}...) s'incluent par \texttt{\#include <...>}.
\end{propriete}

\courssub{Méthode 1 : Écrire et exécuter pas à pas un programme C avec un IDE}

\begin{methode}[De l'algorithme au programme exécutable sous Code::Blocks]
Pour écrire, compiler et exécuter pas à pas un programme C à l'aide d'un IDE (Code::Blocks, Dev-C++), suis toujours la même démarche :
\begin{enumerate}
\item \textbf{Analyser le problème} : identifier les données d'entrée, les traitements et les résultats attendus. Écrire l'algorithme en pseudo-code d'abord.
\item \textbf{Créer le projet} : dans Code::Blocks, \emph{File $\to$ New $\to$ Project $\to$ Console application $\to$ C}. Le fichier principal s'appelle \texttt{main.c}.
\item \textbf{Structurer le programme} : en-têtes de bibliothèques (\texttt{\#include <stdio.h>}, \texttt{\#include <math.h>}), déclarations des constantes et variables, puis la fonction \texttt{main()} qui retourne \texttt{0}.
\item \textbf{Compiler} : touche \emph{F9} (Build and Run). Lire attentivement la fenêtre \emph{Build log} : chaque erreur indique le fichier, la ligne et la nature du problème (erreur de syntaxe, variable non déclarée, type incompatible, \emph{linker error} pour \texttt{math.h} sans \texttt{-lm}...).
\item \textbf{Exécuter pas à pas} : placer un point d'arrêt (clic dans la marge ou \emph{F5}), lancer le débogueur (\emph{F8}), avancer instruction par instruction (\emph{F7} = \emph{Next line} / pas à pas principal) en observant les valeurs des variables dans la fenêtre \emph{Watches}.
\item \textbf{Tester} : prévoir un jeu d'essai couvrant les cas normaux et les cas limites (valeur nulle, valeur négative, borne supérieure, saisie invalide).
\end{enumerate}
\textbf{Réflexes à retenir :} chaque instruction se termine par \texttt{;} ; les formats de \texttt{printf}/\texttt{scanf} sont \texttt{\%d} (int), \texttt{\%f} (float), \texttt{\%lf} (double dans \texttt{scanf}), \texttt{\%c} (char) ; dans \texttt{scanf}, on passe l'\emph{adresse} de la variable avec \texttt{\&} (sauf pour un tableau de caractères, déjà adresse).
\end{methode}

\begin{exoresolu}[Programme de facturation d'un cybercafé]
\textbf{Énoncé (type Bac).} Un cybercafé de Yaoundé facture la connexion Internet à \num{250} FCFA l'heure. Une remise de 10 \% est accordée pour toute durée strictement supérieure à 5 heures. Écrire un programme C qui saisit le nombre d'heures (entier positif), calcule et affiche le montant à payer.
\tcblower
\textbf{Solution détaillée.}

\emph{Étape 1 — Analyse.} Entrée : \texttt{heures} (int). Traitement : montant brut $= 250 \times \text{heures}$ ; si heures $> 5$, appliquer une remise de 10 \%. Sortie : le montant à payer (float).

\emph{Étape 2 — Programme.}
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    const int PRIX_HEURE = 250;   // tarif horaire en FCFA
    int heures;
    float montant;

    printf("Nombre d'heures de connexion : ");
    scanf("%d", &heures);         // & obligatoire : adresse de la variable

    montant = PRIX_HEURE * heures; // conversion implicite int -> float
    if (heures > 5) {
        montant = montant * 0.9f; // remise de 10 % (littéral float 0.9f)
    }

    printf("Montant a payer : %.2f FCFA\\ ", montant);
    return 0;
}
\end{lstlisting}

\emph{Étape 3 — Vérification par jeu d'essai.}
\begin{itemize}
\item heures $= 3$ : montant $= 250 \times 3 = 750$ FCFA (pas de remise, car $3 \leq 5$). Affichage : \texttt{750.00 FCFA}.
\item heures $= 8$ : brut $= 250 \times 8 = 2000$ ; remise : $2000 \times 0{,}9 = 1800$ FCFA. Affichage : \texttt{1800.00 FCFA}.
\item Cas limite heures $= 5$ : la condition $5 > 5$ est fausse, donc pas de remise : $1250$ FCFA. C'est bien ce que demande l'énoncé (« strictement supérieure »).
\end{itemize}

\emph{Étape 4 — Exécution pas à pas.} On place un point d'arrêt sur la ligne du \texttt{scanf}, on lance le débogueur (\emph{F8}) et on avance avec \emph{F7} : dans la fenêtre \emph{Watches}, on observe \texttt{heures} qui passe à 8 après la saisie, puis \texttt{montant} qui vaut 2000 puis 1800 après le \texttt{if}.

\textbf{Conclusion.} Le programme compile sans erreur et produit les résultats attendus sur tout le jeu d'essai : il est correct.
\end{exoresolu}

\coursec{Opérateurs, conversions de types et expressions}

\begin{propriete}[Opérateurs, conversions et priorités en C]
\textbf{Opérateurs arithmétiques :} \texttt{+ - * / \%} (modulo, reste de la division entière). \textbf{Incrémentation/décrémentation :} \texttt{++x} (préfixe, incrémente puis utilise), \texttt{x++} (postfixe, utilise puis incrémente) ; idem pour \texttt{--}.
\textbf{Opérateurs d'affectation composée :} \texttt{+= -= *= /= \%=} (ex. \texttt{x += 3} $\equiv$ \texttt{x = x + 3}).
\textbf{Opérateurs relationnels :} \texttt{< <= > >= == !=} (renvoient 1 si vrai, 0 si faux).
\textbf{Opérateurs logiques :} \texttt{\&\&} (ET), \texttt{||} (OU), \texttt{!} (NON) — évaluation paresseuse (\emph{short-circuit}).
\textbf{Conversion implicite (promotion) :} dans une expression mixte, le type « plus petit » est promu vers le « plus grand » (\texttt{int} $\to$ \texttt{float} $\to$ \texttt{double}). \textbf{Conversion explicite (cast) :} \texttt{(type)expression} (ex. \texttt{(float)somme / n} pour forcer une division réelle).
\textbf{Tableau de priorité (du plus fort au plus faible) :}
\begin{enumerate}
\item \texttt{() [] -> . ++ --} (postfixes)
\item \texttt{++ -- + - ! ~ (type) * \& sizeof} (unaires, préfixes)
\item \texttt{* / \%}
\item \texttt{+ -}
\item \texttt{< <= > >=}
\item \texttt{== !=}
\item \texttt{\&\&}
\item \texttt{||}
\item \texttt{? :} (conditionnel)
\item \texttt{= += -= *= /= \%=} (associativité à droite)
\item \texttt{,}
\end{enumerate}
\emph{En cas de doute, parenthéser.}
\end{propriete}

\coursec{Structures alternatives et boucles}

\courssub{Méthode 2 : Choisir et rédiger la bonne structure de contrôle}

\begin{methode}[Structures alternatives et répétitives]
\begin{enumerate}
\item \textbf{Alternative simple ou double} : \texttt{if (condition) \{ ... \} else \{ ... \}}. La condition est toute expression scalaire (0 = faux, non-zéro = vrai).
\item \textbf{Alternative multiple (cas disjoints sur une même variable entière/caractère)} : \texttt{switch (variable) \{ case val1: ... break; case val2: ... break; default: ... \}}. \textbf{Ne jamais oublier \texttt{break} (sauf fall-through volontaire documenté).}
\item \textbf{Boucle \texttt{for}} : nombre d'itérations connu à l'avance. Syntaxe : \texttt{for (init; cond; incr) \{ ... \}}. L'initialisation, la condition et l'incrémentation sont optionnelles (mais les \texttt{;} restent).
\item \textbf{Boucle \texttt{while}} : répétition conditionnelle pouvant ne jamais s'exécuter (test en entrée). \texttt{while (cond) \{ ... \}}.
\item \textbf{Boucle \texttt{do...while}} : répétition s'exécutant \emph{au moins une fois} (saisie contrôlée, menu). \texttt{do \{ ... \} while (cond);} — \textbf{attention au \texttt{;} final}.
\item \textbf{Garantir la terminaison} : au moins une variable de la condition doit être modifiée dans le corps de la boucle.
\item \textbf{Accumulateurs et compteurs} : initialiser \emph{avant} la boucle (\texttt{somme = 0;}, \texttt{compteur = 0;}), mettre à jour \emph{dans} la boucle.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Statistiques des notes d'une classe de Terminale TI]
\textbf{Énoncé (type Bac).} Écrire un programme C qui saisit les notes d'informatique des élèves d'une classe (la saisie s'arrête quand on entre une note négative), puis affiche le nombre de notes saisies, la moyenne de la classe et le nombre d'élèves admis (note $\geq 10$). Chaque note saisie doit être validée : si elle dépasse 20, elle est rejetée et redemandée.
\tcblower
\textbf{Solution détaillée.}

\emph{Étape 1 — Choix des structures.} Le nombre de notes est inconnu $\to$ boucle \texttt{while} pilotée par la valeur saisie (sentinelle négative). La validation d'une note doit s'exécuter au moins une fois $\to$ \texttt{do...while}. Le test d'admission $\to$ \texttt{if}.

\emph{Étape 2 — Programme.}
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    float note, somme = 0.0f;
    int effectif = 0, admis = 0;

    printf("Entrez une note (note negative pour terminer) : ");
    scanf("%f", &note);

    while (note >= 0) {
        do {   // validation : la note doit etre <= 20
            if (note > 20) {
                printf("Note invalide, ressaisissez : ");
                scanf("%f", &note);
            }
        } while (note > 20);

        if (note >= 0) {          // la ressaisie a pu donner une sentinelle
            somme = somme + note;
            effectif++;
            if (note >= 10) {
                admis++;
            }
            printf("Entrez une note (note negative pour terminer) : ");
            scanf("%f", &note);
        }
    }

    if (effectif > 0) {
        printf("Effectif : %d\\ ", effectif);
        printf("Moyenne : %.2f / 20\\ ", somme / effectif);
        printf("Admis : %d\\ ", admis);
    } else {
        printf("Aucune note saisie.\\ ");
    }
    return 0;
}
\end{lstlisting}

\emph{Étape 3 — Trace d'exécution} avec les saisies $12$, $7$, $25 \to 15$, $-1$ :
\begin{align*}
\text{note} = 12 &: \quad \text{somme} = 12,\ \text{effectif} = 1,\ \text{admis} = 1\\
\text{note} = 7 &: \quad \text{somme} = 19,\ \text{effectif} = 2,\ \text{admis} = 1\\
\text{note} = 25 &: \quad \text{rejetée (do...while), ressaisie } 15 :\\
&\quad \text{somme} = 34,\ \text{effectif} = 3,\ \text{admis} = 2\\
\text{note} = -1 &: \quad \text{sortie de boucle}
\end{align*}
Moyenne $= \dfrac{34}{3} \approx 11{,}33$. Affichage : \texttt{Effectif : 3}, \texttt{Moyenne : 11.33 / 20}, \texttt{Admis : 2}.

\emph{Étape 4 — Justifications.} La boucle \texttt{while} termine car la variable \texttt{note} est re-lue à chaque itération ; la division \texttt{somme / effectif} est protégée par le test \texttt{effectif > 0} (sinon division par zéro) ; \texttt{somme} étant un \texttt{float}, la division est réelle et non entière.

\textbf{Conclusion.} Le programme affiche correctement l'effectif (3), la moyenne (11,33/20) et le nombre d'admis (2), en rejetant les notes invalides.
\end{exoresolu}

\coursec{Fonctions, portée des variables et enregistrements}

\courssub{Méthode 3 : Déclarer et appeler des fonctions, gérer la portée des variables}

\begin{methode}[Concevoir une fonction en C]
\begin{enumerate}
\item \textbf{Identifier le sous-problème} : une tâche répétée ou autonome (calcul, test, affichage) mérite une fonction.
\item \textbf{Définir l'interface} : le \emph{type de retour} (ou \texttt{void} si la fonction ne renvoie rien), le \emph{nom}, et la \emph{liste des paramètres} typés. Exemple : \texttt{float moyenne(float a, float b);}.
\item \textbf{Placer le prototype avant \texttt{main}} (ou la définition complète), puis la définition après \texttt{main}.
\item \textbf{Appeler la fonction} avec des arguments du bon type : \texttt{m = moyenne(n1, n2);}.
\item \textbf{Respecter la portée} : une variable déclarée \emph{dans} une fonction est \cle{locale} (invisible ailleurs, détruite à la fin de l'appel) ; une variable déclarée \emph{hors de toute fonction} est \cle{globale} (visible partout — à utiliser avec parcimonie).
\item \textbf{Transmission des paramètres} : en C, le passage se fait \emph{par valeur} : la fonction travaille sur une copie. Pour modifier la variable de l'appelant, on passe son adresse (pointeur) : \texttt{void echanger(int *a, int *b)} appelé par \texttt{echanger(\&x, \&y);}.
\end{enumerate}
\textbf{Réflexe Bac :} un même nom peut désigner une variable globale et une variable locale ; c'est la \emph{locale} qui masque la globale dans la fonction.
\end{methode}

\begin{exoresolu}[Fonctions et portée : conversion et équation du second degré]
\textbf{Énoncé (type Bac).} 1) Écrire une fonction \texttt{float discriminant(float a, float b, float c)} qui retourne $b^2 - 4ac$, en utilisant \texttt{math.h}. 2) Écrire un programme complet qui saisit $a$, $b$, $c$ ($a \neq 0$) et affiche les solutions réelles de $ax^2+bx+c=0$ selon le signe du discriminant. 3) On considère le code suivant : que vaut \texttt{x} après l'appel \texttt{modifier(x)} ? Justifier.
\begin{lstlisting}[language=C]
void modifier(int n) { n = n + 10; }
int x = 5;
\end{lstlisting}
\tcblower
\textbf{Solution détaillée.}

\emph{1) et 2) — Programme complet.}
\begin{lstlisting}[language=C]
#include <stdio.h>
#include <math.h>   // pour sqrt ; compiler avec -lm sous gcc (ex. gcc main.c -o main -lm)

float discriminant(float a, float b, float c)
{
    return b * b - 4 * a * c;   // variables locales a, b, c
}

int main(void)
{
    float a, b, c, delta;

    printf("Coefficients a b c : ");
    scanf("%f %f %f", &a, &b, &c);

    delta = discriminant(a, b, c);   // appel : passage par valeur

    if (delta < 0) {
        printf("Pas de solution reelle.\\ ");
    } else if (delta == 0) {
        printf("Solution double : x = %.2f\\ ", -b / (2 * a));
    } else {
        printf("x1 = %.2f\\ ", (-b - sqrt(delta)) / (2 * a));
        printf("x2 = %.2f\\ ", (-b + sqrt(delta)) / (2 * a));
    }
    return 0;
}
\end{lstlisting}
Vérification avec $a=1$, $b=-3$, $c=2$ : $\Delta = (-3)^2 - 4 \times 1 \times 2 = 9 - 8 = 1 > 0$, d'où $x_1 = \dfrac{3 - 1}{2} = 1$ et $x_2 = \dfrac{3 + 1}{2} = 2$. Le programme affiche \texttt{x1 = 1.00} et \texttt{x2 = 2.00} : correct.

\emph{3) — Question de portée et de transmission.} Après \texttt{modifier(x)}, la variable globale \texttt{x} vaut toujours \textbf{5}. Justification : le paramètre \texttt{n} est une variable \emph{locale} qui reçoit une \emph{copie} de la valeur de \texttt{x} (passage par valeur) ; l'affectation \texttt{n = n + 10} modifie uniquement cette copie, détruite à la fin de l'appel. Pour modifier réellement \texttt{x}, il faudrait passer son adresse :
\begin{lstlisting}[language=C]
void modifier(int *n) { *n = *n + 10; }
/* appel : */ modifier(&x);   // x vaut alors 15
\end{lstlisting}

\textbf{Conclusion.} Le programme résout correctement l'équation du second degré grâce à la fonction \texttt{discriminant}, et la question 3 illustre la règle fondamentale : en C, tout paramètre est transmis par valeur ; seul le passage d'adresse permet de modifier la variable de l'appelant.
\end{exoresolu}

\courssub{Méthode 4 : Intégrer un enregistrement (struct) dans un programme}

\begin{methode}[Déclarer et exploiter une structure]
\begin{enumerate}
\item \textbf{Modéliser l'objet} : lister les champs (attributs) et choisir le type de chacun. Exemple : un élève = matricule (int), nom (chaîne), moyenne (float).
\item \textbf{Déclarer le type} avant \texttt{main} :
\begin{lstlisting}[language=C]
struct Eleve {
    int matricule;
    char nom[30];
    float moyenne;
};
\end{lstlisting}
Ne pas oublier le \texttt{;} après l'accolade fermante.
\item \textbf{Déclarer les variables} : \texttt{struct Eleve e;} ou un tableau \texttt{struct Eleve classe[50];}.
\item \textbf{Accéder aux champs} avec l'opérateur point : \texttt{e.moyenne = 14.5f;}. Pour une chaîne, utiliser \texttt{scanf("\%s", e.nom);} (sans \texttt{\&}, un tableau est déjà une adresse) ou \texttt{strcpy} de \texttt{string.h} pour une affectation hors saisie.
\item \textbf{Exploiter le tableau d'enregistrements} avec une boucle \texttt{for} : \texttt{classe[i].moyenne}.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Gestion des élèves d'un lycée de Douala]
\textbf{Énoncé (type Bac).} Un lycée souhaite informatiser le suivi de ses élèves de Terminale TI. Écrire un programme C qui : déclare un enregistrement \texttt{Eleve} (matricule, nom, moyenne) ; saisit les informations de $N$ élèves ($N \leq 100$) ; affiche le nom et la moyenne du major de la classe.
\tcblower
\textbf{Solution détaillée.}

\emph{Étape 1 — Modélisation.} L'enregistrement regroupe trois champs de types différents ; le major est l'élève dont la moyenne est maximale : on parcourt le tableau en mémorisant l'indice du maximum.

\emph{Étape 2 — Programme.}
\begin{lstlisting}[language=C]
#include <stdio.h>

struct Eleve {
    int matricule;
    char nom[30];
    float moyenne;
};

int main(void)
{
    struct Eleve classe[100];
    int n, i, indiceMajor = 0;

    printf("Nombre d'eleves (<= 100) : ");
    scanf("%d", &n);

    for (i = 0; i < n; i++) {
        printf("Eleve %d - matricule : ", i + 1);
        scanf("%d", &classe[i].matricule);
        printf("Nom : ");
        scanf("%s", classe[i].nom);      // pas de & : tableau de char
        printf("Moyenne : ");
        scanf("%f", &classe[i].moyenne);
    }

    for (i = 1; i < n; i++) {   // recherche du maximum
        if (classe[i].moyenne > classe[indiceMajor].moyenne) {
            indiceMajor = i;
        }
    }

    printf("Major : %s avec %.2f / 20\\ ",
           classe[indiceMajor].nom, classe[indiceMajor].moyenne);
    return 0;
}
\end{lstlisting}

\emph{Étape 3 — Trace} avec 3 élèves : (101, « Ngo », $12{,}5$), (102, « Kamga », $16{,}0$), (103, « Etoundi », $14{,}75$).
\begin{align*}
i = 1 &: \quad 16{,}0 > 12{,}5 \Rightarrow \text{indiceMajor} = 1\\
i = 2 &: \quad 14{,}75 < 16{,}0 \Rightarrow \text{indiceMajor inchangé}
\end{align*}
Affichage : \texttt{Major : Kamga avec 16.00 / 20}.

\emph{Étape 4 — Justifications.} On initialise \texttt{indiceMajor} à 0 et on démarre la boucle à $i = 1$ pour comparer chaque élément au maximum courant ; la comparaison stricte \texttt{>} conserve le \emph{premier} major en cas d'égalité ; l'accès aux champs se fait via \texttt{classe[i].moyenne} car \texttt{classe[i]} est une structure.

\textbf{Conclusion.} Le programme saisit correctement les $N$ enregistrements et affiche le major : Kamga avec 16,00/20.
\end{exoresolu}

\coursec{Algorithmes classiques : recherche séquentielle et tri par sélection}

\courssub{Méthode 5 : Recherche séquentielle et tri par sélection sur un tableau}

\begin{methode}[Les deux algorithmes classiques à maîtriser]
\textbf{Recherche séquentielle} (tableau quelconque, trié ou non) :
\begin{enumerate}
\item Parcourir le tableau de l'indice 0 à $n-1$.
\item Comparer chaque élément à la valeur cherchée ; dès qu'on la trouve, retourner l'indice et \emph{arrêter} le parcours.
\item Si la boucle se termine sans trouver, retourner $-1$ (convention « absent »).
\end{enumerate}
Coût : au plus $n$ comparaisons.

\textbf{Tri par sélection} (ordre croissant) :
\begin{enumerate}
\item Pour $i$ de 0 à $n-2$ : chercher l'indice \texttt{imin} du \emph{minimum} dans la sous-partie non triée $[i, n-1]$.
\item Échanger \texttt{t[i]} et \texttt{t[imin]} (échange en trois temps avec une variable temporaire).
\item La partie $[0, i]$ est triée définitivement après chaque passage.
\end{enumerate}
Coût : $\dfrac{n(n-1)}{2}$ comparaisons, au plus $n-1$ échanges. \textbf{Réflexe :} l'échange s'écrit \texttt{tmp = t[i]; t[i] = t[imin]; t[imin] = tmp;} — jamais deux affectations sans variable temporaire.
\end{methode}

\begin{exoresolu}[Notes du concours d'entrée à l'ENSP]
\textbf{Énoncé (type Bac).} Un tableau \texttt{t} contient les $n$ notes ($n \leq 200$) des candidats à un concours. 1) Écrire une fonction \texttt{int recherche(float t[], int n, float note)} qui retourne l'indice de la première occurrence de \texttt{note}, ou $-1$ si elle est absente. 2) Écrire une fonction \texttt{void triSelection(float t[], int n)} qui trie le tableau par ordre croissant avec le tri par sélection. 3) Donner le nombre de comparaisons effectuées par le tri pour $n = 50$.
\tcblower
\textbf{Solution détaillée.}

\emph{1) Recherche séquentielle.}
\begin{lstlisting}[language=C]
int recherche(float t[], int n, float note)
{
    int i;
    for (i = 0; i < n; i++) {
        if (t[i] == note) {
            return i;   // trouve : on sort immediatement
        }
    }
    return -1;          // absent
}
\end{lstlisting}
Justification : le parcours est exhaustif (de 0 à $n-1$) et le \texttt{return} garantit l'arrêt à la première occurrence ; si aucune comparaison n'est vraie, on atteint la fin et on retourne $-1$.

\emph{2) Tri par sélection.}
\begin{lstlisting}[language=C]
void triSelection(float t[], int n)
{
    int i, j, imin;
    float tmp;
    for (i = 0; i < n - 1; i++) {
        imin = i;                       // minimum suppose
        for (j = i + 1; j < n; j++) {   // recherche du vrai minimum
            if (t[j] < t[imin]) {
                imin = j;
            }
        }
        if (imin != i) {                // echange en trois temps
            tmp = t[i];
            t[i] = t[imin];
            t[imin] = tmp;
        }
    }
}
\end{lstlisting}
Trace sur \texttt{t = [14, 9, 12]} : passage $i=0$ : minimum de $[14, 9, 12]$ = 9 (indice 1) $\to$ échange $\to$ \texttt{[9, 14, 12]} ; passage $i=1$ : minimum de $[14, 12]$ = 12 (indice 2) $\to$ échange $\to$ \texttt{[9, 12, 14]}. Le tableau est trié.

\emph{3) Nombre de comparaisons pour $n = 50$.} La boucle interne effectue $n - 1 - i$ comparaisons au passage $i$ ; le total est :
\[
\sum_{i=0}^{n-2} (n - 1 - i) = (n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2}
\]
Pour $n = 50$ : $\dfrac{50 \times 49}{2} = \num{1225}$ comparaisons (et au plus $49$ échanges).

\textbf{Conclusion.} La fonction \texttt{recherche} retourne l'indice de la première occurrence ou $-1$, le \texttt{triSelection} ordonne le tableau en $\frac{n(n-1)}{2}$ comparaisons, soit \num{1225} pour 50 candidats.
\end{exoresolu}

\coursec{Récursivité, gestion des erreurs et projet d'application complète}

\courssub{Méthode 6 : Écrire une fonction récursive et produire une application complète}

\begin{methode}[Concevoir une fonction récursive sans erreur]
\begin{enumerate}
\item \textbf{Trouver le cas de base} (condition d'arrêt) : la valeur pour laquelle le résultat est connu directement. Exemple : $0! = 1$.
\item \textbf{Trouver la relation de récurrence} : exprimer le problème en fonction d'un sous-problème \emph{plus petit}. Exemple : $n! = n \times (n-1)!$.
\item \textbf{Rédiger la fonction} : tester le cas de base \emph{en premier} avec un \texttt{if}, puis le cas général avec un appel récursif.
\item \textbf{Vérifier la convergence} : chaque appel doit se rapprocher du cas de base (paramètre qui décroît strictement), sinon pile d'appels infinie et plantage (\emph{stack overflow}).
\item \textbf{Tracer l'exécution} sur une petite valeur pour valider : empiler les appels, puis dépiler les résultats.
\end{enumerate}
\textbf{Projet d'application complète} (calculatrice) : menu avec \texttt{do...while} + \texttt{switch}, une fonction par opération, saisie contrôlée, gestion de la division par zéro, compilation et tests systématiques de chaque option du menu.
\end{methode}

\begin{exoresolu}[Factorielle récursive et calculatrice complète]
\textbf{Énoncé (type Bac).} 1) Écrire une fonction récursive \texttt{long factorielle(int n)} qui calcule $n!$ pour $n \geq 0$. 2) Donner la trace de \texttt{factorielle(4)}. 3) Que se passe-t-il si l'utilisateur appelle \texttt{factorielle(-3)} avec votre code ? Proposer une correction. 4) Intégrer cette fonction dans une calculatrice complète à menu (addition, soustraction, multiplication, division, factorielle, quitter).
\tcblower
\textbf{Solution détaillée.}

\emph{1) Fonction récursive.} Cas de base : $0! = 1$. Récurrence : $n! = n \times (n-1)!$.
\begin{lstlisting}[language=C]
long factorielle(int n)
{
    if (n <= 1) {          // cas de base : 0! = 1! = 1
        return 1;
    }
    return n * factorielle(n - 1);   // cas general
}
\end{lstlisting}

\emph{2) Trace de \texttt{factorielle(4)}.} Empilement puis dépilement :
\begin{align*}
\text{factorielle}(4) &= 4 \times \text{factorielle}(3)\\
&= 4 \times (3 \times \text{factorielle}(2))\\
&= 4 \times (3 \times (2 \times \text{factorielle}(1)))\\
&= 4 \times (3 \times (2 \times 1)) = 24
\end{align*}
Le résultat retourné est bien $24 = 4!$.

\emph{3) Appel \texttt{factorielle(-3)}.} La condition \texttt{n <= 1} est vraie dès le premier appel ($-3 \leq 1$), donc la fonction retourne $1$ : pas de plantage, mais un résultat mathématiquement faux (la factorielle n'est pas définie pour $n < 0$). Correction : valider la saisie dans le programme principal (refuser tout entier négatif) ou retourner une valeur d'erreur :
\begin{lstlisting}[language=C]
long factorielle(int n)
{
    if (n < 0)  return -1;   // code d'erreur
    if (n <= 1) return 1;
    return n * factorielle(n - 1);
}
\end{lstlisting}

\emph{4) Calculatrice complète.}
\begin{lstlisting}[language=C]
#include <stdio.h>

long factorielle(int n)
{
    if (n < 0)  return -1;
    if (n <= 1) return 1;
    return n * factorielle(n - 1);
}

int main(void)
{
    int choix, n;
    float a, b;

    do {
        printf("\\ --- CALCULATRICE ---\\ ");
        printf("1.Addition 2.Soustraction 3.Multiplication\\ ");
        printf("4.Division 5.Factorielle 0.Quitter\\ Choix : ");
        scanf("%d", &choix);

        switch (choix) {
        case 1:
            printf("a b : "); scanf("%f %f", &a, &b);
            printf("= %.2f\\ ", a + b); break;
        case 2:
            printf("a b : "); scanf("%f %f", &a, &b);
            printf("= %.2f\\ ", a - b); break;
        case 3:
            printf("a b : "); scanf("%f %f", &a, &b);
            printf("= %.2f\\ ", a * b); break;
        case 4:
            printf("a b : "); scanf("%f %f", &a, &b);
            if (b != 0) printf("= %.2f\\ ", a / b);
            else printf("Erreur : division par zero\\ ");
            break;
        case 5:
            printf("n : "); scanf("%d", &n);
            if (factorielle(n) != -1)
                printf("%d! = %ld\\ ", n, factorielle(n));
            else printf("Erreur : n negatif\\ ");
            break;
        case 0:
            printf("Au revoir !\\ "); break;
        default:
            printf("Choix invalide.\\ ");
        }
    } while (choix != 0);

    return 0;
}
\end{lstlisting}
Justifications : le \texttt{do...while} garantit l'affichage du menu au moins une fois et la répétition jusqu'au choix 0 ; chaque \texttt{case} se termine par \texttt{break} pour éviter l'exécution en cascade ; la division est protégée par le test \texttt{b != 0} ; le cas d'erreur de la factorielle est intercepté.

\textbf{Conclusion.} La fonction récursive est correcte ($4! = 24$), sécurisée contre les entrées négatives, et la calculatrice complète compile et fonctionne : le projet d'application monoposte est abouti.
\end{exoresolu}

\begin{attention}[Les 5 erreurs qui coûtent des points au Bac]
\begin{enumerate}
\item \textbf{Oublier le \texttt{\&} dans \texttt{scanf}.} Écrire \texttt{scanf("\%d", age);} au lieu de \texttt{scanf("\%d", \&age);} : le programme compile parfois mais plante ou produit des valeurs aberrantes à l'exécution. Exception à connaître : les chaînes de caractères (\texttt{scanf("\%s", nom);}) ne prennent \emph{pas} de \texttt{\&}.
\item \textbf{Confondre \texttt{=} (affectation) et \texttt{==} (comparaison).} \texttt{if (note = 10)} affecte 10 à \texttt{note} et la condition est toujours vraie : bug logique majeur, très pénalisé dans une copie.
\item \textbf{Oublier le \texttt{break} dans un \texttt{switch}.} Sans \texttt{break}, l'exécution « tombe » dans les cas suivants (fall-through) : plusieurs blocs s'exécutent au lieu d'un seul. Chaque \texttt{case} doit se terminer par \texttt{break}, sauf volonté explicite justifiée.
\item \textbf{Division entière involontaire.} \texttt{moyenne = somme / effectif;} avec deux \texttt{int} tronque le résultat ($34 / 3$ donne $11$ et non $11{,}33$). Il faut qu'au moins un opérande soit réel : déclarer \texttt{somme} en \texttt{float} ou écrire \texttt{(float) somme / effectif} (conversion explicite, \emph{cast}).
\item \textbf{Fonction récursive sans cas de base (ou qui ne converge pas).} Oublier \texttt{if (n <= 1) return 1;} ou appeler \texttt{factorielle(n)} au lieu de \texttt{factorielle(n - 1)} provoque une récursion infinie et un débordement de pile (\emph{stack overflow}). Toujours écrire le cas de base en premier et vérifier que le paramètre décroît vers lui. Erreur associée : boucle \texttt{while} dont la condition ne change jamais (boucle infinie) — la variable de contrôle doit être modifiée dans le corps de la boucle.
\end{enumerate}
\end{attention}

\begin{corrige}[Exercice 1 — QCM : à chaud sur le langage C]
\begin{enumerate}
\item \textbf{Réponse b)} : \texttt{printf} est déclarée dans \texttt{stdio.h} (\emph{standard input/output}). La bibliothèque \texttt{math.h} contient les fonctions mathématiques (\texttt{sqrt}, \texttt{cos}, \dots).
\item \textbf{Réponse b)} : \texttt{scanf("\%d", \&age);}. La fonction \texttt{scanf} a besoin de l'\emph{adresse} de la variable (opérateur \texttt{\&}) pour pouvoir y écrire la valeur saisie. Oublier le \texttt{\&} est l'erreur classique qui provoque un plantage à l'exécution.
\item \textbf{Réponse b)} : $3$. Les deux opérandes de \texttt{7 / 2} sont des entiers : c'est une \emph{division entière} (quotient euclidien), la partie décimale est tronquée. Pour obtenir $3,5$, il faudrait écrire \texttt{7.0 / 2} ou \texttt{(float)7 / 2}.
\item \textbf{Réponse b)} : l'expression est vraie si et seulement si $x \geq 0$ \emph{et} $x \leq 20$, c'est-à-dire $x \in [0\,;\,20]$.
\item \textbf{Réponse c)} : une fonction récursive est une fonction qui \emph{s'appelle elle-même}, avec une condition d'arrêt pour garantir la terminaison.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 2 — Vrai ou faux, avec justification]
\begin{enumerate}
\item \textbf{VRAI.} Le C est un langage à déclaration obligatoire : le compilateur doit connaître le type de chaque variable avant sa première utilisation, sinon il signale une erreur du type \emph{undeclared identifier}.
\item \textbf{FAUX.} Utilisées seules comme instruction, elles sont équivalentes. Mais dans une expression, \texttt{i++} (post-incrémentation) fournit l'ancienne valeur de \texttt{i} puis incrémente, tandis que \texttt{++i} (pré-incrémentation) incrémente d'abord puis fournit la nouvelle valeur.
\item \textbf{FAUX.} L'oubli du \texttt{break} ne provoque \emph{aucune} erreur de compilation : c'est une erreur \emph{logique}. L'exécution « tombe » (\emph{fall-through}) dans le \texttt{case} suivant et exécute ses instructions.
\item \textbf{FAUX.} Une variable déclarée à l'intérieur d'une fonction est \emph{locale} : elle n'existe et n'est visible que dans cette fonction (plus précisément dans son bloc). Seule une variable déclarée en dehors de toute fonction est globale.
\item \textbf{VRAI.} Dans un \texttt{do...while}, le test est effectué \emph{après} le corps de boucle : celui-ci est donc exécuté au moins une fois, quelle que soit la condition initiale.
\item \textbf{FAUX.} L'opérateur \texttt{\%} n'accepte que des opérandes \emph{entiers} (\texttt{int}, \texttt{long}, \dots). Appliqué à un \texttt{float}, il provoque une erreur de compilation. Pour les réels, on utilise \texttt{fmod} de \texttt{math.h}.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 3 — Définitions et vocabulaire]
\begin{enumerate}
\item \begin{itemize}
\item \cle{Compilation} : traduction du code source C (fichier \texttt{.c}) en langage machine exécutable par le processeur, réalisée par un compilateur (par exemple \texttt{gcc}), avec détection des erreurs de syntaxe.
\item \cle{Variable locale} : variable déclarée à l'intérieur d'une fonction (ou d'un bloc) ; elle n'existe que pendant l'exécution de cette fonction et n'est visible que dans celle-ci.
\item \cle{Variable globale} : variable déclarée en dehors de toute fonction ; elle est visible et utilisable par toutes les fonctions du programme, et existe pendant toute la durée d'exécution.
\item \cle{Enregistrement} (\texttt{struct}) : type composé regroupant sous un même nom plusieurs variables (\emph{champs}) de types éventuellement différents, par exemple un client avec son nom, sa quantité et son prix unitaire.
\end{itemize}
\item La \emph{déclaration} (prototype) annonce au compilateur l'interface de la fonction : son type de retour, son nom et les types de ses paramètres, terminée par un point-virgule (ex. : \texttt{float moyenne(float t[], int n);}). La \emph{définition} fournit en plus le \emph{corps} de la fonction, c'est-à-dire les instructions entre accolades qui réalisent le traitement.
\item Les trois étapes du tri par sélection, répétées pour chaque position $i$ de $0$ à $n-2$ :
\begin{enumerate}
\item \textbf{Rechercher} l'indice du plus petit élément dans la partie non triée du tableau (positions $i$ à $n-1$) ;
\item \textbf{Échanger} cet élément avec celui situé à la position $i$ ;
\item La partie triée \textbf{s'étend} alors d'une position (les $i+1$ premiers éléments sont définitivement en place).
\end{enumerate}
\item La \emph{condition d'arrêt} (ou cas de base) est le cas pour lequel la fonction retourne directement un résultat \emph{sans} s'appeler elle-même (par exemple $n = 0$ pour la puissance). Si elle est absente (ou jamais atteinte), la fonction s'appelle indéfiniment : la pile d'appels déborde (\emph{stack overflow}) et le programme plante.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 4 — Calculs directs : évaluation d'expressions]
\begin{enumerate}
\item \texttt{a / b} : division entière $10 / 3 = 3$ (type \texttt{int}). \quad \texttt{x / y} : division réelle $10 / 3 \approx 3,333333$ (type \texttt{float}). \quad \texttt{a \% b} : reste de $10 = 3 \times 3 + 1$, donc $1$ (type \texttt{int}).
\item \texttt{(float)a / b} : le \emph{cast} convertit \texttt{a} en $10,0$ avant la division ; le résultat est $3,333333$ (type \texttt{float}).
\item \texttt{a += b} équivaut à \texttt{a = a + b} : l'expression vaut $13$ et \texttt{a} contient désormais $13$.
\item \texttt{i++ + 2} : la post-incrémentation fournit l'ancienne valeur $5$, l'expression vaut $5 + 2 = 7$, puis \texttt{i} passe à $6$. Ensuite \texttt{++i + 2} : \texttt{i} est d'abord incrémenté à $7$, l'expression vaut $7 + 2 = 9$. Valeur finale de \texttt{i} : $7$.
\item \texttt{(a > b) \&\& !(b == 0)} : avec les valeurs initiales, \texttt{a > b} est vrai ($10 > 3$) et \texttt{b} est non nul, donc \texttt{!(b == 0)} est vrai. L'expression vaut \textbf{vrai} ($1$).
\item \texttt{sqrt(16) + abs(-7)} $= 4 + 7 = 11$. Attention aux types : \texttt{sqrt} retourne un \texttt{double} ($4,0$) et \texttt{abs} un \texttt{int} ($7$) ; la somme est de type \texttt{double} et vaut $11,0$.
\begin{attention}[Bibliothèques et \texttt{abs}/\texttt{fabs}]
En C standard, \texttt{abs} (entier) est déclarée dans \texttt{stdlib.h} et \texttt{fabs} (réel) dans \texttt{math.h}. Certains compilateurs éducatifs acceptent \texttt{abs} via \texttt{math.h}, mais il est rigoureux d'inclure \texttt{stdlib.h} pour \texttt{abs(int)}.
\end{attention}
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 5 — Lecture de code : prédire l'affichage]
\begin{enumerate}
\item Affichage produit :
\begin{lstlisting}
i = 3, s = 4
Bien
Tres bien
\end{lstlisting}
Justification des lignes A et B :
\begin{itemize}
\item \textbf{Ligne A} : \texttt{s += i++;} — la post-incrémentation fournit l'ancienne valeur $1$ : $s = 0 + 1 = 1$, puis $i$ passe à $2$.
\item \textbf{Ligne B} : \texttt{s += ++i;} — la pré-incrémentation incrémente d'abord : $i$ passe à $3$, puis $s = 1 + 3 = 4$.
\end{itemize}
D'où l'affichage \texttt{i = 3, s = 4}.
\item Le \texttt{case 2} ne contient \emph{pas} de \texttt{break} : après avoir affiché « Bien », l'exécution \emph{tombe} dans le \texttt{case 3} et affiche aussi « Tres bien ». C'est le mécanisme de \emph{fall-through}. Le \texttt{break} placé après le \texttt{case 3} arrête ensuite la cascade (le \texttt{default} n'est donc pas exécuté).
\item Il suffit d'ajouter un \texttt{break;} à la fin du \texttt{case 2} (et, par bonne pratique, à la fin du \texttt{case 1} aussi) :
\begin{lstlisting}[language=C]
case 2: printf("Bien\n");
        break;
\end{lstlisting}
\item Vérification pratique : dans Code::Blocks, place un point d'arrêt sur la ligne A (clic dans la marge), lance le débogueur (F8), avance pas à pas (F7) et observe l'évolution de \texttt{i} et \texttt{s} dans la fenêtre des variables (\emph{Watches}). Les valeurs successives $i = 2$, $s = 1$ puis $i = 3$, $s = 4$ confirment la prédiction.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 6 — Équation du second degré]
\begin{lstlisting}[language=C]
#include <stdio.h>
#include <math.h>   /* pour sqrt */

int main(void)
{
    float a, b, c, delta, x1, x2;

    printf("Entrez a, b et c (a non nul) : ");
    scanf("%f %f %f", &a, &b, &c);

    delta = b * b - 4 * a * c;

    if (delta > 0) {
        x1 = (-b - sqrt(delta)) / (2 * a);
        x2 = (-b + sqrt(delta)) / (2 * a);
        printf("Deux solutions : x1 = %.2f et x2 = %.2f\n", x1, x2);
    } else {
        if (delta == 0) {
            x1 = -b / (2 * a);
            printf("Solution double : x0 = %.2f\n", x1);
        } else {
            printf("Pas de solution reelle\n");
        }
    }
    return 0;
}
\end{lstlisting}
Tests :
\begin{itemize}
\item $(1, -3, 2)$ : $\Delta = 9 - 8 = 1 > 0$, solutions $x_1 = 1$ et $x_2 = 2$.
\item $(1, 2, 1)$ : $\Delta = 4 - 4 = 0$, solution double $x_0 = -1$.
\item $(1, 0, 1)$ : $\Delta = -4 < 0$, affichage « Pas de solution réelle ».

\begin{corrige}[Exercice 7 — Table de multiplication et somme des entiers]
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    int N, k, i, S = 0;

    /* 1. Saisie controlee : N strictement positif */
    do {
        printf("Entrez un entier strictement positif : ");
        scanf("%d", &N);
    } while (N <= 0);

    /* 2. Table de multiplication de N */
    for (k = 1; k <= 10; k++) {
        printf("%d x %d = %d\n", N, k, N * k);
    }

    /* 3. Somme 1 + 2 + ... + N avec une boucle while */
    i = 1;
    while (i <= N) {
        S = S + i;
        i++;
    }
    printf("Somme calculee : S = %d\n", S);

    /* 4. Verification par la formule */
    printf("Formule N(N+1)/2 = %d\n", N * (N + 1) / 2);
    if (S == N * (N + 1) / 2) {
        printf("Les deux valeurs sont egales : resultat correct.\n");
    }
    return 0;
}
\end{lstlisting}
Exemple avec $N = 5$ : la boucle \texttt{while} donne $S = 1+2+3+4+5 = 15$ et la formule donne $\dfrac{5 \times 6}{2} = 15$ : les deux valeurs coïncident. Le \texttt{do...while} garantit que la question est posée au moins une fois et reposée tant que $N \leq 0$.
\end{corrige}

\begin{corrige}[Exercice 8 — Correction guidée : chasse aux erreurs]
Les six erreurs, dans l'ordre d'apparition :
\begin{enumerate}
\item \texttt{float n1, n2, n3, moyenne} : \textbf{point-virgule manquant} en fin de déclaration $\rightarrow$ \texttt{float n1, n2, n3, moyenne;}.
\item \texttt{scanf("\%f \%f \%f", n1, n2, n3);} : \texttt{scanf} attend les \textbf{adresses} des variables $\rightarrow$ \texttt{scanf("\%f \%f \%f", \&n1, \&n2, \&n3);}.
\item \texttt{if (moyenne = 10)} : c'est une \textbf{affectation}, pas une comparaison ; il faut l'opérateur d'égalité $\rightarrow$ \texttt{if (moyenne == 10)}. (Avec \texttt{=}, la condition vaut $10$, toujours vraie, et la moyenne est écrasée.)
\item \verb|printf("Admis\n")| : \textbf{point-virgule manquant} $\rightarrow$ \verb|printf("Admis\n");|.
\item \verb|printf("Moyenne = %d\n", moyenne);| : \textbf{format incorrect}, \texttt{moyenne} est un \texttt{float} $\rightarrow$ \verb|printf("Moyenne = %.2f\n", moyenne);|.
\item \texttt{return 0} : \textbf{point-virgule manquant} $\rightarrow$ \texttt{return 0;}.
\end{enumerate}
Programme corrigé :
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    float n1, n2, n3, moyenne;
    printf("Entrez trois notes : ");
    scanf("%f %f %f", &n1, &n2, &n3);
    moyenne = (n1 + n2 + n3) / 3;
    if (moyenne >= 10) {
        printf("Admis\n");
    }
    printf("Moyenne = %.2f\n", moyenne);
    return 0;
}
\end{lstlisting}
\emph{Remarque} : on a aussi écrit \texttt{int main(void)} et remplacé \texttt{== 10} par \texttt{>= 10}, plus logique pour l'admission (une moyenne de $12$ doit donner « Admis »).
\end{corrige}

\begin{corrige}[Exercice 9 — Bac blanc : gestion des notes d'une classe de Terminale TI]
\textbf{Principe du tri par sélection (question 4)} : pour chaque position $i$ de $0$ à $n-2$, on recherche le plus petit élément de la partie non triée (positions $i$ à $n-1$), on l'échange avec l'élément en position $i$, et la partie triée s'étend ainsi d'une position à chaque passe.

Programme complet :
\begin{lstlisting}[language=C]
#include <stdio.h>

float moyenne(float t[], int n)
{
    float somme = 0;
    int i;
    for (i = 0; i < n; i++) {
        somme += t[i];
    }
    return somme / n;
}

int recherche(float t[], int n, float val)
{
    int i;
    for (i = 0; i < n; i++) {
        if (t[i] == val) {
            return i;   /* premiere occurrence trouvee */
        }
    }
    return -1;          /* absente */
}

void triSelection(float t[], int n)
{
    int i, j, iMin;
    float tmp;
    for (i = 0; i < n - 1; i++) {
        iMin = i;
        for (j = i + 1; j < n; j++) {
            if (t[j] < t[iMin]) {
                iMin = j;
            }
        }
        if (iMin != i) {
            tmp = t[i]; t[i] = t[iMin]; t[iMin] = tmp;
        }
    }
}

int main(void)
{
    float notes[10], val;
    int i, indice;

    /* 1. Saisie controlee des 10 notes */
    for (i = 0; i < 10; i++) {
        do {
            printf("Note de l'eleve %d (0 a 20) : ", i + 1);
            scanf("%f", &notes[i]);
        } while (notes[i] < 0 || notes[i] > 20);
    }

    /* 2. Moyenne */
    printf("Moyenne de la classe : %.2f\n", moyenne(notes, 10));

    /* 3. Recherche sequentielle */
    printf("Note a rechercher : ");
    scanf("%f", &val);
    indice = recherche(notes, 10, val);
    if (indice == -1) {
        printf("Note absente du tableau.\n");
    } else {
        printf("Note trouvee a l'indice %d.\n", indice);
    }

    /* 4 et 5. Tri puis classement */
    triSelection(notes, 10);
    printf("Classement (du plus faible au plus fort) :\n");
    for (i = 0; i < 10; i++) {
        printf("Rang %d : %.2f\n", i + 1, notes[i]);
    }
    return 0;
}
\end{lstlisting}

\begin{attention}[Comparaison de flottants]
La fonction \texttt{recherche} utilise \texttt{t[i] == val}. Comme les notes sont des valeurs entières (0 à 20) stockées dans des \texttt{float}, l'égalité exacte fonctionne ici. \textbf{En général}, pour des mesures réelles, on teste \texttt{fabs(t[i] - val) < EPSILON} avec une tolérance (ex. $10^{-6}$).
\end{attention}

\textbf{Application numérique} — tableau initial : $[12\,;\,8\,;\,15\,;\,8\,;\,19\,;\,10\,;\,14\,;\,6\,;\,11\,;\,16]$.
\begin{itemize}
\item \textbf{Passe 1} ($i = 0$) : le minimum de la partie $[0..9]$ est $6$ (indice $7$). Échange des positions $0$ et $7$ :
\[ [6\,;\,8\,;\,15\,;\,8\,;\,19\,;\,10\,;\,14\,;\,12\,;\,11\,;\,16] \]
\item \textbf{Passe 2} ($i = 1$) : le minimum de la partie $[1..9]$ est $8$ (indice $1$, déjà en place, aucun échange effectif) :
\[ [6\,;\,8\,;\,15\,;\,8\,;\,19\,;\,10\,;\,14\,;\,12\,;\,11\,;\,16] \]
\end{itemize}
Moyenne : $\dfrac{12+8+15+8+19+10+14+6+11+16}{10} = \dfrac{119}{10} = 11,9$.

Après tri complet : $[6\,;\,8\,;\,8\,;\,10\,;\,11\,;\,12\,;\,14\,;\,15\,;\,16\,;\,19]$. La note $14$ occupe le rang $7$ (en comptant à partir du rang $1$ pour la plus petite note).

\textbf{Barème indicatif (20 pts)} : saisie contrôlée $3$ ; fonction \texttt{moyenne} $3$ ; recherche séquentielle $3$ ; principe du tri énoncé $2$ ; \texttt{triSelection} correct $4$ ; affichage du classement $2$ ; application numérique (passes, moyenne, rang) $3$.

\textbf{Points de vigilance} : le contrôle $0 \leq \text{note} \leq 20$ doit utiliser un \texttt{do...while} \emph{à l'intérieur} du \texttt{for} ; la recherche doit retourner $-1$ en cas d'absence (valeur sentinelle) ; la boucle externe du tri s'arrête à $n-2$ ; l'échange exige une variable temporaire.
\end{corrige}

\begin{corrige}[Exercice 10 — Bac blanc : facturation dans une boutique de Douala]
\begin{enumerate}
\item Déclaration de la structure :
\begin{lstlisting}[language=C]
struct Client {
    char nom[30];
    int quantite;
    float prixUnitaire;
};
\end{lstlisting}
\item Fonction de calcul du montant net :
\begin{lstlisting}[language=C]
float montantNet(struct Client c)
{
    float brut = c.quantite * c.prixUnitaire;
    if (brut > 100000) {
        return brut * 0.95f;   /* remise de 5 % */
    }
    return brut;
}
\end{lstlisting}
Le paramètre \texttt{c} est transmis \textbf{par valeur} : la fonction reçoit une \emph{copie} de la structure. Conséquence : toute modification de \texttt{c} à l'intérieur de la fonction serait sans effet sur le client du \texttt{main} (ici on ne fait que lire, donc c'est correct).
\item et 4. Programme principal :
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    struct Client clients[5];
    int i, iMax = 0;
    float net, caTotal = 0, netMax;

    for (i = 0; i < 5; i++) {
        printf("Client %d - nom : ", i + 1);
        scanf("%29s", clients[i].nom); /* %29s evite le debordement */
        printf("Quantite : ");
        scanf("%d", &clients[i].quantite);
        printf("Prix unitaire (FCFA) : ");
        scanf("%f", &clients[i].prixUnitaire);
    }

    for (i = 0; i < 5; i++) {
        net = montantNet(clients[i]);
        printf("%s doit payer %.0f FCFA\n", clients[i].nom, net);
        caTotal += net;
        if (i == 0 || net > netMax) {
            netMax = net;
            iMax = i;
        }
    }
    printf("Meilleur client : %s (%.0f FCFA)\n",
           clients[iMax].nom, netMax);
    printf("Chiffre d'affaires total : %.0f FCFA\n", caTotal);
    return 0;
}
\end{lstlisting}
\item Fonction récursive et trace :
\begin{lstlisting}[language=C]
float puissance(float x, int n)
{
    if (n == 0) {
        return 1;              /* condition d'arret */
    }
    return x * puissance(x, n - 1);
}
\end{lstlisting}
Trace de \texttt{puissance(2, 5)} — phase de descente puis de remontée :
\begin{align*}
\text{puissance}(2,5) &= 2 \times \text{puissance}(2,4)\\
\text{puissance}(2,4) &= 2 \times \text{puissance}(2,3)\\
\text{puissance}(2,3) &= 2 \times \text{puissance}(2,2)\\
\text{puissance}(2,2) &= 2 \times \text{puissance}(2,1)\\
\text{puissance}(2,1) &= 2 \times \text{puissance}(2,0)\\
\text{puissance}(2,0) &= 1 \quad \text{(cas de base)}
\end{align*}
Remontée : $\text{puissance}(2,1) = 2$, puis $4$, $8$, $16$, et enfin $\text{puissance}(2,5) = 32$. Vérification : $2^5 = 32$.
\end{enumerate}
\textbf{Barème indicatif (20 pts)} : structure $3$ ; \texttt{montantNet} avec remise conditionnelle $4$ ; transmission par valeur expliquée $2$ ; saisie du tableau de structures $3$ ; maximum et chiffre d'affaires $3$ ; fonction récursive $3$ ; trace complète $2$.

\textbf{Points de vigilance} : la remise ne s'applique que si le brut \emph{dépasse strictement} \num{100000} FCFA ; pour le maximum, initialiser avec le premier élément (et non $0$) ; la condition d'arrêt $n = 0$ de la récursivité doit être citée explicitement ; \texttt{scanf("\%29s", ...)} limite la lecture à 29 caractères pour éviter le débordement de tampon et ne lit toujours pas les espaces dans les noms composés.
\end{corrige}

\begin{corrige}[Exercice 11 — Bac blanc : calculatrice à menu pour un cybercafé]
\begin{enumerate}
\item Les quatre fonctions :
\begin{lstlisting}[language=C]
float addition(float a, float b)       { return a + b; }
float soustraction(float a, float b)   { return a - b; }
float multiplication(float a, float b) { return a * b; }
float division(float a, float b)       { return a / b; }
\end{lstlisting}
Pour la division, le test du diviseur nul ne peut pas être fait proprement \emph{à l'intérieur} de la fonction : celle-ci doit retourner un réel dans tous les cas, et aucune valeur réelle ne peut signifier « erreur » de façon fiable (retourner $0$ serait ambigu, car $0 / 5 = 0$ est un résultat légitime). \textbf{Solution} : tester le diviseur \emph{dans le \texttt{main}} avant l'appel (ou passer un paramètre supplémentaire, par exemple l'adresse d'un entier indicateur d'erreur).
\item et 3. Programme principal :
\begin{lstlisting}[language=C]
#include <stdio.h>

int compteur = 0;   /* variable globale (question 5) */

float addition(float a, float b)       { return a + b; }
float soustraction(float a, float b)   { return a - b; }
float multiplication(float a, float b) { return a * b; }
float division(float a, float b)       { return a / b; }

int main(void)
{
    int choix;
    float a, b;

    do {
        printf("\n--- CALCULATRICE ---\n");
        printf("1. Addition\n2. Soustraction\n");
        printf("3. Multiplication\n4. Division\n0. Quitter\n");
        printf("Votre choix : ");
        scanf("%d", &choix);

        if (choix >= 1 && choix <= 4) {
            printf("Entrez deux nombres : ");
            scanf("%f %f", &a, &b);
        }

        switch (choix) {
            case 1:
                printf("Resultat : %.2f\n", addition(a, b));
                compteur++;
                break;
            case 2:
                printf("Resultat : %.2f\n", soustraction(a, b));
                compteur++;
                break;
            case 3:
                printf("Resultat : %.2f\n", multiplication(a, b));
                compteur++;
                break;
            case 4:
                if (b == 0) {
                    printf("Division par zero impossible\n");
                } else {
                    printf("Resultat : %.2f\n", division(a, b));
                    compteur++;
                }
                break;
            case 0:
                printf("Au revoir !\n");
                break;
            default:
                printf("Choix invalide, recommencez.\n");
        }
    } while (choix != 0);

    printf("Operations effectuees : %d\n", compteur);
    return 0;
}
\end{lstlisting}
\item Le \texttt{do...while} est le bon choix car le menu doit être affiché \emph{au moins une fois} avant de connaître le choix de l'utilisateur : la condition \texttt{choix != 0} ne peut être évaluée qu'\emph{après} la première saisie. Avec un \texttt{while}, il faudrait initialiser artificiellement \texttt{choix} à une valeur non nulle avant la boucle.
\item La variable globale \texttt{compteur} est déclarée en dehors de toute fonction : elle est visible partout et conserve sa valeur pendant toute la session. Une variable \emph{locale}, déclarée dans une fonction, n'existe que pendant l'appel de celle-ci et n'est visible que dans son bloc. \textbf{Inconvénient des globales} : elles peuvent être modifiées par n'importe quelle fonction, ce qui rend les erreurs difficiles à tracer et nuit à la lisibilité et à la maintenance du programme ; il vaut mieux, quand c'est possible, passer des paramètres.
\end{enumerate}
\textbf{Barème indicatif (20 pts)} : quatre fonctions $4$ ; explication du problème de la division et solution $3$ ; boucle \texttt{do...while} et menu $3$ ; \texttt{switch} complet avec \texttt{break} et \texttt{default} $4$ ; gestion du diviseur nul $2$ ; justification du \texttt{do...while} $2$ ; variable globale, affichage final et discussion $2$.

\textbf{Points de vigilance} : chaque \texttt{case} doit se terminer par \texttt{break} ; le compteur ne doit être incrémenté que pour une opération \emph{réussie} (pas pour une division par zéro ni un choix invalide) ; les prototypes des fonctions doivent figurer avant le \texttt{main} si les définitions sont placées après.
\end{corrige}

\begin{bilan}
\textbf{Définitions clés}
\begin{itemize}
  \item \cle{Programme C} : suite d'instructions organisée autour de la fonction \texttt{main()}, traduite en langage machine par un \cle{compilateur} (ex. GCC via Code::Blocks).
  \item \cle{Variable} : zone mémoire nommée et typée (\texttt{int}, \texttt{float}, \texttt{double}, \texttt{char}) ; \cle{constante} : valeur fixe déclarée avec \texttt{const} ou \texttt{\#define}.
  \item \cle{Enregistrement} (\texttt{struct}) : type composé regroupant plusieurs champs de types différents (ex. un élève : nom, âge, moyenne).
  \item \cle{Fonction} : bloc réutilisable déclaré avec un type de retour, un nom et des paramètres ; \cle{variable locale} (visible dans la fonction) vs \cle{variable globale} (visible partout).
  \item \cle{Fonction récursive} : fonction qui s'appelle elle-même, avec un \cle{cas de base} qui arrête les appels.
\end{itemize}

\textbf{Syntaxe à connaître par cœur}
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Notion} & \textbf{Syntaxe C} \\
\hline
Entrée-sortie & \texttt{printf("\%d", n);} \quad \texttt{scanf("\%f", \&x);} \\
\hline
Alternative & \texttt{if (cond) \{...\} else \{...\}} ; \texttt{switch (n) \{ case 1: ...; break; default: ...\}} \\
\hline
Boucles & \texttt{for (i=0; i<n; i++)} ; \texttt{while (cond)} ; \texttt{do \{...\} while (cond);} \\
\hline
Fonction & \texttt{float moyenne(float a, float b) \{ return (a+b)/2; \}} \\
\hline
Enregistrement & \texttt{struct Eleve \{ char nom[30]; float moy; \};} \\
\hline
Maths (math.h) & \texttt{sqrt(x)}, \texttt{abs(n)}, \texttt{cos(x)}, \texttt{pow(x, y)} — compiler avec \texttt{-lm} \\
\hline
\end{tabularx}
\end{center}

\textbf{Opérateurs et priorités (du plus prioritaire au moins prioritaire)}
\[ \texttt{()}\ \succ\ \texttt{++ --}\ \succ\ \texttt{* / \%}\ \succ\ \texttt{+ -}\ \succ\ \texttt{< <= > >=}\ \succ\ \texttt{== !=}\ \succ\ \texttt{\&\&}\ \succ\ \texttt{||}\ \succ\ \texttt{= += -= *= /=} \]
Conversion de type : \texttt{(float)a / b} force une division réelle ; \texttt{7 / 2} vaut $3$ mais \texttt{7.0 / 2} vaut $3{,}5$.

\textbf{Méthodes express}
\begin{enumerate}
  \item \cle{Recherche séquentielle} : parcourir le tableau de $0$ à $n-1$ ; si \texttt{t[i] == x}, retourner $i$ ; sinon retourner $-1$. Coût : $n$ comparaisons au pire.
  \item \cle{Tri par sélection} : pour $i$ de $0$ à $n-2$, chercher l'indice du minimum dans $[i, n-1]$, puis échanger \texttt{t[i]} et \texttt{t[min]}.
  \item \cle{Récursivité} : écrire d'abord le cas de base (ex. \texttt{if (n == 0) return 1;}), puis l'appel récursif sur un problème plus petit (\texttt{return n * fact(n-1);}).
  \item \cle{Corriger une erreur de compilation} : lire le premier message (fichier, ligne), vérifier \texttt{;} oublié, parenthèses/accolades, variable non déclarée, \texttt{\&} dans \texttt{scanf}.
\end{enumerate}
\end{bilan}

\begin{aretenir}[Checklist avant le Bac]
\begin{itemize}
  \item $\square$ Je sais écrire la structure minimale d'un programme C (\texttt{\#include <stdio.h>}, \texttt{int main()}, \texttt{return 0;}).
  \item $\square$ Je maîtrise les formats de \texttt{printf}/\texttt{scanf} : \texttt{\%d}, \texttt{\%f}, \texttt{\%c}, \texttt{\%s}, et le \texttt{\&} devant la variable lue.
  \item $\square$ Je connais les types de base et je sais déclarer une constante avec \texttt{const} ou \texttt{\#define}.
  \item $\square$ Je distingue division entière et division réelle, et je sais utiliser un \emph{cast} : \texttt{(float)a}.
  \item $\square$ Je cite les opérateurs relationnels et logiques (\texttt{==}, \texttt{!=}, \texttt{\&\&}, \texttt{||}, \texttt{!}) sans les confondre avec \texttt{=}.
  \item $\square$ Je sais choisir entre \texttt{if...else}, \texttt{switch}, \texttt{for}, \texttt{while} et \texttt{do...while} selon la situation.
  \item $\square$ Je sais déclarer et appeler une fonction, et distinguer variable locale et variable globale.
  \item $\square$ Je sais déclarer un \texttt{struct} et accéder à ses champs avec le point : \texttt{e.moy}.
  \item $\square$ Je sais écrire la recherche séquentielle et le tri par sélection sur un tableau.
  \item $\square$ Je sais écrire une fonction récursive avec son cas de base (factorielle, somme, Fibonacci).
  \item $\square$ Je sais compiler, exécuter pas à pas dans Code::Blocks et corriger les erreurs signalées.
  \item $\square$ Je sais produire un programme complet et exécutable (ex. calculatrice, gestion de notes d'une classe).
\end{itemize}
\end{aretenir}
