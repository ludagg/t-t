\coursec{Structures alternatives : if, else, elseif, switch}

À la cybercafétéria « Espace Jeunes » de Yaoundé, les inscriptions au concours de la Fonction publique se font encore dans un grand cahier cartonné : doublons, ratures, pages arrachées, et des recherches interminables quand un candidat revient réclamer sa fiche. Le propriétaire, séduit par les plateformes comme \emph{impots.cm}, veut un petit site web où chaque candidat s'inscrit en ligne, où l'on peut modifier ou supprimer une fiche, et afficher la liste des inscrits du jour. Mais un tel site doit aussi \emph{prendre des décisions} : si le candidat a moins de 21 ans, afficher un message ; si sa moyenne est supérieure à 10, afficher « Admis » ; sinon, proposer le rattrapage. Comment faire dialoguer une page PHP avec une base de données MySQL ? Comment répéter l'affichage de centaines de lignes sans écrire centaines de lignes de code ? Comment, surtout, faire en sorte qu'un programme \emph{choisisse} quoi faire selon les données ? C'est tout l'objet de cette leçon, et nous commençons par la brique fondamentale de toute décision : les \cle{structures alternatives}.

\courssub{Rappel algorithmique : qu'est-ce qu'une structure alternative ?}

Jusqu'ici, tes scripts PHP s'exécutaient de haut en bas, ligne après ligne, comme une recette de cuisine. Or un vrai programme doit pouvoir \emph{réagir} : afficher « Connexion réussie » si le mot de passe est correct, et « Accès refusé » sinon. En algorithmique, tu connais déjà cette idée sous la forme :

\begin{lstlisting}
Si condition Alors
    instructions 1
Sinon
    instructions 2
FinSi
\end{lstlisting}

\begin{definition}[Structure alternative]
Une \cle{structure alternative} (ou structure conditionnelle) est une instruction qui exécute un bloc de code selon qu'une \cle{condition} — une expression dont la valeur est \textbf{vraie} ou \textbf{fausse} — est vérifiée ou non. Elle permet au programme de choisir entre plusieurs chemins d'exécution.
\end{definition}

Une condition est une \emph{expression booléenne} : elle ne peut valoir que \texttt{true} ou \texttt{false}. Pour la construire, PHP met à ta disposition deux familles d'opérateurs.

\begin{propriete}[Opérateurs de comparaison et opérateurs logiques]
\textbf{Opérateurs de comparaison} (comparent deux valeurs et renvoient un booléen) :
\begin{itemize}
  \item \texttt{==} : égalité de valeur ; \texttt{!=} : différence ;
  \item \texttt{<}, \texttt{>} : strictement inférieur, strictement supérieur ;
  \item \texttt{<=}, \texttt{>=} : inférieur ou égal, supérieur ou égal.
\end{itemize}
\textbf{Opérateurs logiques} (combinent des conditions) :
\begin{itemize}
  \item \texttt{\&\&} : ET logique — vrai si les deux conditions sont vraies ;
  \item \texttt{||} : OU logique — vrai si au moins une condition est vraie ;
  \item \texttt{!} : NON logique — inverse la valeur de la condition.
\end{itemize}
Exemple : \texttt{(\$age >= 18) \&\& (\$age <= 35)} est vrai si l'âge est compris entre 18 et 35 ans inclus.
\end{propriete}

\courssub{La structure if : exécuter un bloc seulement si...}

La forme la plus simple ne prévoit qu'un seul chemin : on exécute un bloc \emph{uniquement} si la condition est vraie, sinon on le saute.

\begin{propriete}[Syntaxe de if]
\begin{lstlisting}[language=Php]
if (condition) {
    // instructions executees si la condition est vraie
}
// la suite du programme s'execute dans tous les cas
\end{lstlisting}
La condition est placée entre parenthèses ; le bloc d'instructions est délimité par des accolades \texttt{\{ \}}. Si la condition est fausse, PHP ignore le bloc et poursuit après l'accolade fermante.
\end{propriete}

\begin{exemplebox}[Contrôle d'âge à l'inscription]
\begin{lstlisting}[language=Php]
<?php
$age = 19;
if ($age < 18) {
    echo "Inscription refusee : vous devez etre majeur.";
}
echo "Bienvenue sur Espace Jeunes.";
?>
\end{lstlisting}
Ici, le message de refus n'apparaît que si \texttt{\$age} est strictement inférieur à 18 ; le message de bienvenue s'affiche dans tous les cas.
\end{exemplebox}

\begin{attention}[Le piège mortel : = au lieu de ==]
L'erreur la plus fréquente (et la plus redoutée au Bac) est de confondre l'\cle{affectation} \texttt{=} et la \cle{comparaison} \texttt{==}. Le code suivant est faux :
\begin{lstlisting}[language=Php]
if ($a = 5) {   // ERREUR : on AFFECTE 5 a $a !
    echo "a vaut 5";
}
\end{lstlisting}
\texttt{\$a = 5} range 5 dans \texttt{\$a}, puis PHP évalue la valeur affectée : 5 est considéré comme \textbf{vrai}. Le test est donc \emph{toujours} vrai, quelle que soit la valeur initiale de \texttt{\$a}. La version correcte est \texttt{if (\$a == 5)}. Retiens : \textbf{un seul = pour ranger, deux == pour comparer}.
\end{attention}

\courssub{if ... else : traiter le cas contraire}

Le plus souvent, on veut faire quelque chose \emph{aussi} quand la condition est fausse : c'est le rôle de \texttt{else}.

\begin{propriete}[Syntaxe de if ... else]
\begin{lstlisting}[language=Php]
if (condition) {
    // instructions si la condition est VRAIE
} else {
    // instructions si la condition est FAUSSE
}
\end{lstlisting}
Un seul des deux blocs est exécuté, jamais les deux, jamais aucun : l'alternative est \emph{exclusive et complète}.
\end{propriete}

\begin{exemplebox}[Décision d'admission binaire]
\begin{lstlisting}[language=Php]
<?php
$moyenne = 9.75;
if ($moyenne >= 10) {
    echo "Admis au concours.";
} else {
    echo "Non admis cette annee.";
}
?>
\end{lstlisting}
Avec \texttt{\$moyenne = 9.75}, la condition \texttt{\$moyenne >= 10} est fausse : c'est le bloc \texttt{else} qui s'exécute.
\end{exemplebox}

\courssub{if ... elseif ... else : la cascade de conditions}

La réalité offre rarement seulement deux issues. Au Baccalauréat, une moyenne de 15 n'a pas le même sens qu'une moyenne de 11 : il faut tester \emph{plusieurs cas ordonnés}. On enchaîne alors des \texttt{elseif} (contraction de « else if »).

\begin{propriete}[Syntaxe et ordre d'évaluation de la cascade]
\begin{lstlisting}[language=Php]
if (condition1) {
    // si condition1 est vraie
} elseif (condition2) {
    // sinon, si condition2 est vraie
} elseif (condition3) {
    // sinon, si condition3 est vraie
} else {
    // sinon (toutes les conditions sont fausses)
}
\end{lstlisting}
PHP évalue les conditions \textbf{de haut en bas}. Dès qu'une condition est vraie, son bloc est exécuté et \textbf{tous les autres sont ignorés}. Le \texttt{else} final, facultatif, ramasse tous les cas restants. L'\textbf{ordre des tests est donc crucial} : on place en général les conditions les plus restrictives en premier.
\end{propriete}

\begin{attention}[Ordre des tests : un bug silencieux]
Si tu écris \texttt{if (\$moy >= 10)} \emph{avant} \texttt{elseif (\$moy >= 14)}, un élève à 16 entrera dans le premier bloc et n'obtiendra jamais sa mention « Bien ». Le programme ne signale aucune erreur : il donne simplement un mauvais résultat. Teste toujours du plus exigeant vers le moins exigeant.
\end{attention}

\courssub{switch : le choix multiple sur une même variable}

Quand il faut comparer \emph{une même variable} à \emph{plusieurs valeurs constantes} (un jour de la semaine, un code de filière, un choix de menu), la cascade de \texttt{elseif} devient lourde et répétitive. PHP propose alors une structure dédiée : \texttt{switch}.

\begin{propriete}[Syntaxe de switch]
\begin{lstlisting}[language=Php]
switch (variable) {
    case valeur1:
        // instructions si variable == valeur1
        break;
    case valeur2:
        // instructions si variable == valeur2
        break;
    default:
        // instructions si aucun cas ne correspond
}
\end{lstlisting}
PHP compare la variable à chaque \texttt{case} par égalité (comparaison faible \texttt{==}). Le mot-clé \texttt{break;} termine le \texttt{switch} : sans lui, l'exécution \emph{continue dans les cas suivants}. Le \texttt{default}, facultatif, joue le rôle du \texttt{else} final.
\end{propriete}

\begin{exemplebox}[Menu de la cybercafétéria]
\begin{lstlisting}[language=Php]
<?php
$choix = 2;
switch ($choix) {
    case 1:
        echo "Nouvelle inscription";
        break;
    case 2:
        echo "Modifier une fiche";
        break;
    case 3:
        echo "Supprimer une fiche";
        break;
    case 4:
        echo "Liste des inscrits du jour";
        break;
    default:
        echo "Choix invalide.";
}
?>
\end{lstlisting}
Avec \texttt{\$choix = 2}, seul « Modifier une fiche » s'affiche.
\end{exemplebox}

\begin{attention}[Oublier le break : l'exécution en cascade]
Sans \texttt{break;}, PHP ne s'arrête pas à la fin du cas trouvé : il exécute \textbf{tous les cas suivants} jusqu'à la fin du \texttt{switch} (ou jusqu'au prochain \texttt{break}). C'est le comportement « en cascade » (\emph{fall-through}).
\begin{lstlisting}[language=Php]
<?php
$choix = 2;
switch ($choix) {
    case 2:
        echo "Modification ";
        // break oublie ici !
    case 3:
        echo "Suppression ";
    default:
        echo "Invalide";
}
?>
\end{lstlisting}
Affiche : \texttt{Modification Suppression Invalide}. Ce comportement n'est utile que dans un cas précis : faire partager le même traitement à plusieurs valeurs en empilant des \texttt{case} vides (\texttt{case 1: case 2: ...}). Sinon, chaque \texttt{case} doit se terminer par \texttt{break;}.
\end{attention}

\courssub{if/elseif ou switch : comment choisir ?}

Les deux structures peuvent souvent exprimer la même décision, mais elles ne sont pas interchangeables.

\begin{methode}[Choisir entre if/elseif et switch]
\begin{enumerate}
  \item Pose-toi la question : est-ce que je teste \textbf{l'égalité d'une seule et même variable} à plusieurs \textbf{valeurs constantes} (nombres, chaînes) ?
  \item Si \textbf{oui} (menu, jour de la semaine, code filière...) : utilise \texttt{switch}, plus lisible et plus compact. N'oublie pas les \texttt{break;}.
  \item Si \textbf{non} — intervalles (\texttt{\$moy >= 14}), conditions composées avec \texttt{\&\&} ou \texttt{||}, comparaisons portant sur des variables différentes — : utilise la cascade \texttt{if/elseif/else}, en ordonnant les tests du plus restrictif au moins restrictif.
\end{enumerate}
\end{methode}

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}
\hline
\rowcolor{popblueL}
\textbf{Critère} & \textbf{if / elseif / else} & \textbf{switch} \\
\hline
Type de test & Toute condition (intervalles, ET/OU) & Égalité à des constantes uniquement \\
\hline
Variable testée & Peut changer à chaque test & Une seule variable pour tous les cas \\
\hline
Lisibilité & Bonne pour 2 à 4 cas & Excellente pour de nombreux cas \\
\hline
Risque classique & Mauvais ordre des tests & Oubli du \texttt{break} \\
\hline
\end{tabularx}
\end{center}

\courssub{Exemple complet : la mention au Baccalauréat}

Mettons tout cela en œuvre dans le cas d'école qui tombe régulièrement à l'examen : afficher la mention d'un élève selon sa moyenne.

\begin{exoresolu}[Mentions du Bac en PHP]
\textbf{Énoncé.} Écrire un script PHP qui, à partir d'une variable \texttt{\$moyenne} comprise entre 0 et 20, affiche la décision du jury : « Ajourné » si la moyenne est inférieure à 10 ; « Passable » de 10 à moins de 12 ; « Assez Bien » de 12 à moins de 14 ; « Bien » de 14 à moins de 16 ; « Très Bien » à partir de 16. Tester le script avec la moyenne 13,5.
\tcblower
\textbf{Solution.} On utilise une cascade \texttt{if/elseif/else} car les tests portent sur des \emph{intervalles}, ce que \texttt{switch} ne sait pas faire. On ordonne les conditions de la plus exigeante à la moins exigeante.
\begin{lstlisting}[language=Php]
<?php
$moyenne = 13.5;   // moyenne de l'eleve sur 20

if ($moyenne >= 16) {
    $mention = "Tres Bien";
} elseif ($moyenne >= 14) {
    $mention = "Bien";
} elseif ($moyenne >= 12) {
    $mention = "Assez Bien";
} elseif ($moyenne >= 10) {
    $mention = "Passable";
} else {
    $mention = "Ajourne";
}

echo "Moyenne : $moyenne /20 - Mention : $mention";
?>
\end{lstlisting}
\textbf{Trace d'exécution} avec \texttt{\$moyenne = 13.5} :
\begin{itemize}
  \item \texttt{13.5 >= 16} ? Faux.
  \item \texttt{13.5 >= 14} ? Faux.
  \item \texttt{13.5 >= 12} ? \textbf{Vrai} : \texttt{\$mention} reçoit « Assez Bien » et les tests suivants sont ignorés.
\end{itemize}
Le script affiche : \texttt{Moyenne : 13.5 /20 - Mention : Assez Bien}. Remarque l'astuce d'ordre : grâce à la cascade, il suffit d'écrire la borne inférieure de chaque intervalle ; la borne supérieure est garantie par l'échec des tests précédents.
\end{exoresolu}

Dans une application réelle comme celle d'Espace Jeunes, la moyenne proviendrait d'un formulaire HTML. On la récupère alors via le tableau \texttt{\$\_POST} :

\begin{exemplebox}[Décision à partir d'un formulaire]
\begin{lstlisting}[language=Php]
<?php
// Le formulaire HTML envoie un champ nomme "moyenne"
$moy = $_POST["moyenne"];

if ($moy >= 10) {
    echo "Admis(e) au concours. Felicitations !";
} elseif ($moy >= 8) {
    echo "Rattrapage : preparez l'epreuve orale.";
} else {
    echo "Ajourne(e). Retentez votre chance l'an prochain.";
}
?>
\end{lstlisting}
Avec une moyenne saisie de 8,5, le visiteur lit : « Rattrapage : préparez l'épreuve orale. »
\end{exemplebox}

\begin{savaistu}[L'opérateur ternaire : le if/else en une ligne]
PHP propose une forme compacte du \texttt{if/else}, appelée \cle{opérateur ternaire} : \texttt{condition ? valeurSiVrai : valeurSiFaux}. Par exemple :
\begin{lstlisting}[language=Php]
$statut = ($moyenne >= 10) ? "Admis" : "Ajourne";
// equivalent a un if/else complet, en une seule ligne
\end{lstlisting}
Très apprécié des développeurs pour les affectations courtes, il est un complément utile à connaître pour le Bac. Son nom vient du fait qu'il prend \emph{trois} opérandes. Attention toutefois : dès que le traitement dépasse une instruction simple, reviens au \texttt{if/else} classique, bien plus lisible.
\end{savaistu}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
  \item Une \cle{structure alternative} exécute un bloc selon qu'une condition est vraie ou fausse.
  \item \texttt{if} seul : un cas ; \texttt{if/else} : deux cas exclusifs ; \texttt{if/elseif/else} : cascade évaluée \textbf{de haut en bas}, dont l'ordre est déterminant.
  \item \texttt{switch} compare \textbf{une même variable} à des \textbf{valeurs constantes} ; chaque \texttt{case} se termine par \texttt{break;}, sous peine d'exécution en cascade.
  \item \texttt{==} compare, \texttt{=} affecte : \texttt{if (\$a = 5)} est toujours vrai — l'erreur classique à bannir.
  \item Intervalles ou conditions composées $\Rightarrow$ \texttt{if/elseif} ; égalités multiples sur une variable $\Rightarrow$ \texttt{switch}.
\end{itemize}
\end{aretenir}

\begin{exercice}[À toi de jouer]
\begin{enumerate}
  \item Écrire un script qui affiche si un candidat peut s'inscrire au concours : il faut avoir au moins 18 ans \textbf{et} être titulaire du Baccalauréat (variable booléenne \texttt{\$bac}).
  \item Écrire un \texttt{switch} qui affiche le nom du jour de la semaine à partir d'un numéro \texttt{\$jour} de 1 (lundi) à 7 (dimanche), avec un message d'erreur pour toute autre valeur.
  \item Réécrire la cascade des mentions du Bac en commençant par les plus petites moyennes. Quelle condition faut-il alors écrire à chaque étape ?
\end{enumerate}
\end{exercice}

Maintenant que ton programme sait \emph{décider}, il doit apprendre à \emph{répéter} : afficher les 300 inscrits du jour sans écrire 300 fois la même instruction. C'est l'objet de la section suivante, consacrée aux structures répétitives.

\coursec{Structures répétitives : for, foreach, while, do...while}

Dans la section précédente, nous avons appris à faire des \emph{choix} dans un script grâce aux structures alternatives (\texttt{if}, \texttt{elseif}, \texttt{else}, \texttt{switch}) : le programme emprunte un chemin ou un autre, mais chaque instruction n'est exécutée qu'\emph{une seule fois}. Or, dans une application web réelle, on a très souvent besoin de \emph{répéter} un traitement : afficher les 20 arrondissements d'une région, lister tous les élèves d'une classe de Terminale TI, calculer la moyenne de 15 notes, afficher toutes les lignes renvoyées par une requête MySQL. Recopier vingt fois la même instruction serait absurde, illisible et impossible à maintenir. C'est précisément le problème que résolvent les \cle{structures répétitives}, encore appelées \cle{boucles}.

\begin{definition}[Structure répétitive (boucle)]
Une \cle{structure répétitive} (ou \cle{boucle}) est une instruction qui répète l'exécution d'un bloc de code \emph{tant qu'une condition est vérifiée}. Chaque exécution du bloc s'appelle une \cle{itération}. Une boucle bien construite repose sur trois éléments :
\begin{itemize}
  \item l'\cle{initialisation} : on donne une valeur de départ à une variable de contrôle (le \cle{compteur}) ;
  \item la \cle{condition d'arrêt} : une expression booléenne testée à chaque passage ; tant qu'elle est vraie, la boucle continue ;
  \item l'\cle{incrémentation} (ou modification du compteur) : on fait évoluer le compteur dans le corps de la boucle pour que la condition finisse par devenir fausse.
\end{itemize}
\end{definition}

PHP propose quatre boucles : \texttt{for}, \texttt{while}, \texttt{do...while} et \texttt{foreach}. Étudions-les une à une.

\courssub{La boucle for : quand le nombre d'itérations est connu}

\textbf{Intuition.} Tu sais déjà combien de fois tu veux répéter : afficher les tables de multiplication de 1 à 10, numéroter les 20 arrondissements, calculer la somme des entiers de 1 à 100. Dans ce cas, la boucle \texttt{for} concentre les trois éléments de contrôle (initialisation, condition, incrémentation) sur une seule ligne : c'est la plus compacte et la plus sûre.

\begin{propriete}[Syntaxe de la boucle for]
\begin{lstlisting}[language=Php]
for (initialisation ; condition ; incrementation) {
    // instructions repetees tant que la condition est vraie
}
\end{lstlisting}
L'ordre d'exécution est le suivant :
\begin{enumerate}
  \item l'\texttt{initialisation} est exécutée \emph{une seule fois}, avant le premier tour ;
  \item la \texttt{condition} est évaluée : si elle est fausse, la boucle s'arrête immédiatement (le corps peut donc ne jamais s'exécuter) ;
  \item si elle est vraie, le corps est exécuté, \emph{puis} l'\texttt{incrementation}, puis on retourne à l'étape 2.
\end{enumerate}
\end{propriete}

\begin{exemplebox}[Exemple chiffré : somme des entiers de 1 à 100 avec for]
\begin{lstlisting}[language=Php]
<?php
    $somme = 0;                    // accumulateur, initialise a zero
    for ($i = 1; $i <= 100; $i++) {
        $somme = $somme + $i;      // on ajoute le compteur a chaque tour
    }
    echo "La somme de 1 a 100 vaut : $somme";  // affiche 5050
?>
\end{lstlisting}
Déroulé : \texttt{\$i} vaut successivement 1, 2, 3, \ldots, 100. À chaque tour, on ajoute \texttt{\$i} à \texttt{\$somme}. Après le 100\textsuperscript{e} tour, \texttt{\$i} devient 101, la condition \texttt{\$i <= 100} devient fausse et la boucle s'arrête. Résultat affiché : \textbf{5050}.
\end{exemplebox}

\courssub{La boucle while : répéter tant qu'une condition est vraie}

\textbf{Intuition.} Parfois, on ne sait \emph{pas} à l'avance combien de tours seront nécessaires : on continue « tant que » quelque chose est vrai. Exemples : tant qu'il reste des lignes dans le résultat d'une requête MySQL, tant que le solde Mobile Money est insuffisant, tant que l'utilisateur saisit un mot de passe incorrect. La boucle \texttt{while} teste la condition \emph{en entrée} : si elle est fausse dès le départ, le corps n'est jamais exécuté.

\begin{propriete}[Syntaxe de la boucle while]
\begin{lstlisting}[language=Php]
while (condition) {
    // instructions repetees tant que la condition est vraie
    // le compteur DOIT etre modifie ici
}
\end{lstlisting}
La condition est testée \emph{avant} chaque itération. Le nombre minimal d'exécutions du corps est donc \textbf{zéro}.
\end{propriete}

\begin{exemplebox}[La somme de 1 à 100 réécrite avec while]
\begin{lstlisting}[language=Php]
<?php
    $somme = 0;
    $i = 1;                  // 1. initialisation (hors de la boucle)
    while ($i <= 100) {      // 2. condition testee en entree
        $somme = $somme + $i;
        $i++;                // 3. incrementation (dans le corps)
    }
    echo "La somme de 1 a 100 vaut : $somme";  // affiche 5050
?>
\end{lstlisting}
On retrouve exactement les trois éléments du \texttt{for}, mais dispersés : l'initialisation avant la boucle, la condition entre parenthèses, l'incrémentation dans le corps.
\end{exemplebox}

\begin{propriete}[Équivalence for / while (admise, justifiée sur exemple)]
Toute boucle \texttt{for} peut se réécrire en \texttt{while}, et réciproquement. Les deux scripts précédents le prouvent : ils produisent le même résultat (5050) avec la même logique. La différence est \emph{syntaxique}, pas fonctionnelle : le \texttt{for} regroupe les trois éléments de contrôle sur une ligne (plus lisible quand le nombre de tours est connu), le \texttt{while} les sépare (plus souple quand la condition dépend d'un événement imprévisible, comme la lecture d'une ligne de base de données).
\end{propriete}

\courssub{La boucle do...while : exécuter au moins une fois}

\textbf{Intuition.} Il existe des situations où le traitement doit être fait \emph{au moins une fois} avant de décider de continuer : demander un mot de passe (on le demande une première fois, puis on redemande tant qu'il est faux), afficher un menu, jouer une partie avant de proposer de rejouer. La boucle \texttt{do...while} teste la condition \emph{en sortie}, c'est-à-dire \emph{après} le corps.

\begin{propriete}[Syntaxe de la boucle do...while]
\begin{lstlisting}[language=Php]
do {
    // instructions executees AU MOINS une fois
} while (condition);   // attention au point-virgule final !
\end{lstlisting}
Le corps est exécuté une première fois \emph{sans aucun test}, puis la condition est évaluée : si elle est vraie, on recommence ; sinon, on sort. Le nombre minimal d'exécutions est donc \textbf{un}. Ne jamais oublier le \texttt{;} après la parenthèse fermante du \texttt{while}.
\end{propriete}

\begin{exemplebox}[Simulation d'une saisie contrôlée]
\begin{lstlisting}[language=Php]
<?php
    $essai = 0;
    $codeSecret = "1234";               // Code stocke en chaine de caracteres
    $saisies = array("0000", "1111", "1234"); // Simulations de saisies (chaines)

    do {
        $essai++;
        $saisie = $saisies[$essai - 1]; // Recuperation de la saisie simulee
        echo "Essai $essai : code $saisie <br>";
    } while ($saisie !== $codeSecret && $essai < 3); // Comparaison stricte

    if ($saisie === $codeSecret) {
        echo "Acces autorise.";
    } else {
        echo "Trop d'echecs. Compte verrouille.";
    }
?>
\end{lstlisting}
Le corps s'exécute une première fois même si le premier code saisi est le bon : c'est toute la différence avec \texttt{while}. L'utilisation de chaînes de caractères pour les codes PIN évite le piège de l'interprétation octale des nombres commençant par 0 en PHP.
\end{exemplebox}

\courssub{La boucle foreach : la reine du parcours de tableaux}

\textbf{Intuition.} En PHP, les données viennent très souvent sous forme de \emph{tableaux} : liste d'arrondissements, notes d'un élève, et surtout les résultats des requêtes MySQL que nous étudierons bientôt. Parcourir un tableau avec \texttt{for} et des indices est possible mais fastidieux (et impossible pour les tableaux associatifs dont les clés sont des chaînes). La boucle \texttt{foreach} est faite pour cela : elle visite \emph{automatiquement} chaque élément, sans compteur à gérer.

\begin{propriete}[Les deux formes de foreach]
\begin{lstlisting}[language=Php]
// Forme 1 : on recupere seulement les valeurs
foreach ($tableau as $valeur) {
    // $valeur contient successivement chaque element
}

// Forme 2 : on recupere la cle ET la valeur
foreach ($tableau as $cle => $valeur) {
    // utile pour les tableaux associatifs
}
\end{lstlisting}
La boucle s'arrête d'elle-même à la fin du tableau : \textbf{aucun risque de boucle infinie}, aucun compteur à initialiser.
\end{propriete}

\begin{exemplebox}[Afficher les 20 arrondissements d'une région avec foreach]
\begin{lstlisting}[language=Php]
<?php
    // Tableau indexe : arrondissements de la region du Centre (extrait)
    $arrondissements = array(
        "Yaounde I", "Yaounde II", "Yaounde III", "Yaounde IV",
        "Yaounde V", "Yaounde VI", "Yaounde VII", "Mfoundi (rural)",
        "Mbankomo", "Okola", "Obala", "Nkolafamba",
        "Soa", "Akonolinga", "Mbalmayo", "Nkoteng",
        "Bafia", "Ntui", "Saa", "Esse"
    );

    echo "<h3>Les 20 arrondissements de la liste</h3>";
    echo "<ol>";
    foreach ($arrondissements as $ville) {
        echo "<li>$ville</li>";   // un element de liste par arrondissement
    }
    echo "</ol>";

    // Tableau associatif : region => chef-lieu
    $chefsLieux = array(
        "Centre"    => "Yaounde",
        "Littoral"  => "Douala",
        "Ouest"     => "Bafoussam",
        "Nord-Ouest"=> "Bamenda"
    );
    foreach ($chefsLieux as $region => $capitale) {
        echo "Le chef-lieu de la region du $region est $capitale.<br>";
    }
?>
\end{lstlisting}
La première boucle produit une liste numérotée HTML de 20 éléments ; la seconde exploite la forme \texttt{\$cle => \$valeur}, indispensable pour les tableaux associatifs.
\end{exemplebox}

\begin{savaistu}[foreach, la boucle reine du couple PHP/MySQL]
Dans quelques sections, tu exécuteras des requêtes SQL depuis PHP grâce à l'extension \texttt{mysqli}. Chaque appel à \texttt{mysqli\_fetch\_assoc()} renvoie une ligne de résultat sous forme de tableau associatif (par exemple \texttt{\$ligne["nom\_eleve"]}). En pratique, on parcourt ces résultats avec un \texttt{while} (\emph{tant qu'il reste une ligne}), puis on exploite chaque ligne comme un tableau — et dès que les résultats sont stockés dans un tableau PHP, c'est \texttt{foreach} qui prend le relais pour l'affichage. Maîtriser \texttt{foreach}, c'est déjà maîtriser la moitié de l'interfaçage PHP/MySQL.
\end{savaistu}

\begin{methode}[Choisir la bonne boucle]
\begin{enumerate}
  \item Tu parcours un \textbf{tableau} ? $\rightarrow$ \texttt{foreach}, sans hésiter.
  \item Tu connais le \textbf{nombre exact de tours} ? $\rightarrow$ \texttt{for}.
  \item Tu répètes \textbf{tant qu'une condition} est vraie, sans connaître le nombre de tours ? $\rightarrow$ \texttt{while}.
  \item Le corps doit s'exécuter \textbf{au moins une fois} avant tout test ? $\rightarrow$ \texttt{do...while}.
\end{enumerate}
\end{methode}

\courssub{Le danger des boucles infinies}

Une \cle{boucle infinie} est une boucle dont la condition ne devient \emph{jamais} fausse : le script tourne sans fin, consomme le processeur et finit par être tué par le serveur (ou bloque la page). Deux causes classiques : une condition mal conçue (toujours vraie) et l'\textbf{oubli de l'incrémentation} du compteur.

\begin{attention}[Erreur fréquente : oublier \$i++ dans un while]
\begin{lstlisting}[language=Php]
<?php
    $i = 1;
    while ($i <= 10) {
        echo "$i <br>";
        // OUBLI de $i++ : $i reste egal a 1 pour toujours
        // La condition $i <= 10 est TOUJOURS vraie :
        // boucle infinie qui bloque le serveur !
    }
?>
\end{lstlisting}
Sur un hébergement mutualisé, un tel script peut faire échouer toutes les pages du site. PHP finit par interrompre le script après le délai \texttt{max\_execution\_time} (30 secondes par défaut), mais le mal est fait : le visiteur n'a rien vu.
\end{attention}

\begin{methode}[Pour éviter toute boucle infinie, vérifier trois points]
\begin{enumerate}
  \item \textbf{Initialisation} : le compteur a-t-il une valeur de départ correcte \emph{avant} la boucle ?
  \item \textbf{Condition d'arrêt} : la condition peut-elle réellement devenir fausse un jour ? (Tester \texttt{\$i <= 100} en incrémentant \texttt{\$i} : oui. Tester \texttt{\$i != 100} en partant de 1 par pas de 2 : non, car \texttt{\$i} saute de 99 à 101 !)
  \item \textbf{Modification du compteur} : le corps de la boucle fait-il \emph{progresser} le compteur vers la sortie (incrémentation, lecture de la ligne suivante, etc.) ?
\end{enumerate}
\end{methode}

\begin{exoresolu}[Compter les élèves admis au Baccalauréat TI]
\textbf{Énoncé.} Les notes sur 20 de 8 candidats sont stockées dans le tableau \texttt{\$notes = array(12, 8, 15, 9, 10, 14, 7, 11)}. Un candidat est admis si sa note est supérieure ou égale à 10. Écrire un script PHP qui affiche chaque note avec la mention « Admis » ou « Refusé », puis le nombre total d'admis.
\tcblower
\textbf{Solution détaillée.} On parcourt un tableau : la boucle adaptée est \texttt{foreach}. On utilise un compteur \texttt{\$admis} initialisé à 0, incrémenté à chaque note admise grâce à une structure \texttt{if} (combinaison boucle + alternative, très fréquente au Baccalauréat).
\begin{lstlisting}[language=Php]
<?php
    $notes = array(12, 8, 15, 9, 10, 14, 7, 11);
    $admis = 0;                       // compteur d'admis
    $numero = 1;                      // numero du candidat

    foreach ($notes as $note) {
        if ($note >= 10) {
            echo "Candidat $numero : $note/20 - Admis<br>";
            $admis++;                 // on incremente le compteur
        } else {
            echo "Candidat $numero : $note/20 - Refuse<br>";
        }
        $numero++;
    }
    echo "<strong>Nombre d'admis : $admis</strong>";
?>
\end{lstlisting}
\textbf{Résultat affiché :} les candidats 1, 3, 5, 6 et 8 sont admis ; le script conclut par « Nombre d'admis : 5 ». Remarque la structure générale : \texttt{foreach} pour le parcours, \texttt{if/else} pour la décision, compteur \texttt{\$admis} pour l'accumulation — c'est le squelette de la plupart des traitements de données que tu rencontreras, y compris sur les résultats MySQL.
\end{exoresolu}

\begin{exercice}[À toi de jouer]
\begin{enumerate}
  \item Écris un script avec \texttt{for} qui affiche la table de multiplication de 7 (de $7 \times 1$ à $7 \times 12$).
  \item Réécris ce script avec \texttt{while}, puis avec \texttt{do...while}. Que constates-tu si la condition de départ est fausse dans chacun des trois cas ?
  \item Le tableau associatif \texttt{\$operateurs = array("MTN" => "Mobile Money", "Orange" => "Orange Money", "Nexttel" => "Nexttel Possa")} associe un opérateur à son service de paiement. Affiche chaque couple sous la forme « MTN propose Mobile Money » à l'aide de \texttt{foreach}.
\end{enumerate}
\end{exercice}

\begin{aretenir}[L'essentiel des structures répétitives]
\begin{itemize}
  \item Une boucle répète un bloc tant qu'une condition est vraie ; elle repose sur l'\textbf{initialisation}, la \textbf{condition d'arrêt} et l'\textbf{incrémentation}.
  \item \texttt{for} : nombre de tours connu ; \texttt{while} : test en entrée, 0 exécution possible ; \texttt{do...while} : test en sortie, 1 exécution minimum ; \texttt{foreach} : parcours automatique des tableaux.
  \item Toute boucle \texttt{for} peut se réécrire en \texttt{while} : la différence est syntaxique, pas fonctionnelle.
  \item Oublier l'incrémentation dans un \texttt{while} provoque une \textbf{boucle infinie} : toujours vérifier l'initialisation, la condition d'arrêt et la modification du compteur.
  \item \texttt{foreach} est la boucle reine de l'interfaçage PHP/MySQL : c'est elle qui parcourt les tableaux de résultats.
\end{itemize}
\end{aretenir}

\coursec{La fonction date()}

Dans la section précédente, tu as appris à répéter des traitements avec \texttt{for}, \texttt{foreach}, \texttt{while} et \texttt{do...while}. Ces boucles permettent, par exemple, d'afficher la liste des élèves inscrits à un cours. Mais une question se pose immédiatement dans toute application réelle : \emph{quand} chaque élève s'est-il inscrit ? Le site impots.cm horodate chaque déclaration, l'application d'une startup camerounaise enregistre la date de chaque transaction Mobile Money, et ton projet scolaire de gestion de bibliothèque doit mémoriser la date d'emprunt de chaque livre. Toutes ces informations temporelles passent par une fonction PHP fondamentale : \cle{date()}.

\courssub{Rôle et syntaxe de la fonction date()}

\begin{definition}[La fonction date()]
\cle{date()} est une fonction prédéfinie de PHP qui retourne la \textbf{date et l'heure courantes du serveur}, formatées en une \textbf{chaîne de caractères} selon un modèle (format) fourni en paramètre.
\begin{lstlisting}[language=Php]
string date(string $format, ?int $timestamp = null)
\end{lstlisting}
Le paramètre \texttt{\$format} est une chaîne composée de \textbf{codes de format} (des lettres ayant chacune une signification précise) mélangés éventuellement à des caractères libres (slashes, deux-points, espaces, texte). Le second paramètre \texttt{\$timestamp} est optionnel : s'il est omis, la fonction utilise l'heure courante (retournée par \texttt{time()}). La fonction retourne une chaîne que l'on peut afficher avec \texttt{echo} ou stocker dans une variable.
\end{definition}

L'idée est simple : le serveur connaît en permanence la date et l'heure (grâce à son horloge système). La fonction \texttt{date()} ne fait que \emph{lire} cette horloge et \emph{présenter} le résultat comme tu le souhaites. Tu ne choisis pas la date, tu choisis seulement son \textbf{format d'affichage}.

\begin{exemplebox}[Premiers pas avec date()]
\begin{lstlisting}[language=Php]
<?php
    // Affiche par exemple : 15/03/2025
    echo date('d/m/Y');

    echo "<br>";

    // Affiche par exemple : 14:30:05
    echo date('H:i:s');

    echo "<br>";

    // Stocke la date du jour dans une variable
    $aujourdhui = date('Y-m-d');
    echo "Nous sommes le " . $aujourdhui;
?>
\end{lstlisting}
Chaque lettre du format est remplacée par la valeur correspondante de l'horloge du serveur ; les caractères \texttt{/} et \texttt{:} sont recopiés tels quels.
\end{exemplebox}

\begin{aretenir}[Exemple chiffré de référence]
Si l'horloge du serveur indique le 15 mars 2025 à 14 h 30, alors l'instruction :
\begin{lstlisting}[language=Php]
echo date('d/m/Y à H:i');
\end{lstlisting}
affiche exactement : \textbf{15/03/2025 à 14:30}. Le mot « à » est du texte libre, recopié tel quel dans le résultat.
\end{aretenir}

\begin{attention}[Erreur fréquente : confondre m et i]
Le piège classique du Bac : \texttt{m} désigne le \textbf{mois} et \texttt{i} les \textbf{minutes}. Ainsi, \texttt{date('H:m:s')} n'affiche \emph{pas} l'heure avec les minutes : il affiche l'heure, puis le \textbf{mois}, puis les secondes ! Le 15 mars à 14 h 30, on obtiendrait \texttt{14:03:05} au lieu de \texttt{14:30:05}. Retiens : \textbf{m}ois = \texttt{m}, m\textbf{i}nutes = \texttt{i}. De même, \texttt{H} (majuscule) est l'heure sur 24 h, alors que \texttt{h} (minuscule) est l'heure sur 12 h (avec AM/PM).
\end{attention}

\courssub{Le problème du fuseau horaire}

Voici une situation vécue par beaucoup de développeurs débutants : tu installes WampServer, tu écris \texttt{echo date('H:i');} à 10 h du matin à Yaoundé, et la page affiche... 09 h ou 11 h. Que s'est-il passé ?

La fonction \texttt{date()} lit l'heure du serveur \emph{dans le fuseau horaire configuré par PHP}. Par défaut, cette configuration est souvent \texttt{UTC} (temps universel) ou le fuseau du pays d'origine de l'hébergeur. Or le Cameroun se trouve dans le fuseau \textbf{UTC+1} (heure d'Afrique de l'Ouest, sans changement d'heure saisonnier). Si PHP est réglé sur UTC, toutes tes heures seront décalées d'une heure : un élève inscrit à 08 h 00 précises sera enregistré à 07 h 00. Pour un système de notes ou de présence, c'est inacceptable.

PHP fournit heureusement une fonction pour corriger cela : \cle{date\_default\_timezone\_set()}.

\begin{methode}[Obtenir l'heure exacte du Cameroun]
Pour que toutes les dates et heures de ton script correspondent à l'heure locale camerounaise :
\begin{enumerate}
\item Place, \textbf{au tout début du script} (avant tout appel à \texttt{date()}), l'instruction :
\begin{lstlisting}[language=Php]
date_default_timezone_set('Africa/Douala');
\end{lstlisting}
\item Utilise ensuite \texttt{date()} normalement : elle retournera l'heure de Douala et Yaoundé (UTC+1).
\item Si ton projet comporte plusieurs pages, recopie cette ligne en tête de chaque script concerné (ou place-la dans un fichier \texttt{config.php} inclus partout via \texttt{require\_once}).
\end{enumerate}
\end{methode}

\begin{exemplebox}[Heure locale correcte]
\begin{lstlisting}[language=Php]
<?php
    // Réglage du fuseau horaire sur le Cameroun (UTC+1)
    date_default_timezone_set('Africa/Douala');

    // Désormais, date() retourne l'heure locale exacte
    echo "Il est " . date('H:i:s') . " à Yaoundé.";
    // Affiche par exemple : Il est 10:15:42 à Yaoundé.
?>
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Oublier le fuseau horaire]
Si tu oublies \texttt{date\_default\_timezone\_set()}, PHP utilise le fuseau par défaut du serveur, qui n'est pas forcément celui du Cameroun, surtout si ton site est hébergé en Europe ou en Amérique. Conséquence : des horodatages faux, incohérents entre le serveur et les utilisateurs. En production, vérifie aussi la directive \texttt{date.timezone} du fichier \texttt{php.ini} pour une configuration globale.
\end{attention}

\courssub{Applications concrètes de date()}

\textbf{1. Afficher la date du jour sur une page.} C'est l'usage le plus simple : un bandeau en haut du site de ton établissement, par exemple.

\begin{lstlisting}[language=Php]
<?php
    date_default_timezone_set('Africa/Douala');
    echo "<p>Lycee de Nkol-Eton - Nous sommes le "
         . date('d/m/Y') . "</p>";
?>
\end{lstlisting}

\textbf{2. Horodatage d'une inscription.} Quand un utilisateur s'inscrit, on mémorise le moment exact de son inscription dans une variable, que l'on enregistrera ensuite dans la base de données.

\begin{lstlisting}[language=Php]
<?php
    date_default_timezone_set('Africa/Douala');

    // Moment exact de l'inscription, au format DATETIME de MySQL
    $date_inscription = date('Y-m-d H:i:s');
    echo "Inscription enregistree le " . $date_inscription;
    // Exemple : Inscription enregistree le 2025-03-15 14:30:05
?>
\end{lstlisting}

\textbf{3. Calcul d'ancienneté.} En combinant \texttt{date()} avec une date stockée, on peut calculer une durée. Par exemple, l'année courante moins l'année d'embauche donne l'ancienneté d'un employé :

\begin{lstlisting}[language=Php]
<?php
    $annee_embauche = 2019;
    $anciennete = date('Y') - $annee_embauche;
    // date('Y') retourne l'année courante, par ex. 2025 (chaîne convertie en entier)
    echo "Anciennete : " . $anciennete . " ans"; // 6 ans
?>
\end{lstlisting}

\courssub{Stocker une date dans MySQL}

C'est ici que \texttt{date()} prend toute son importance pour la suite de la leçon (l'interfaçage avec MySQL). MySQL possède des types de colonnes spécialisés pour les dates :

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|l|}
\hline
\rowcolor{popblueL} \textbf{Type MySQL} & \textbf{Contenu} & \textbf{Format attendu} \\
\hline
\texttt{DATE} & Une date seule (jour, mois, année) & \texttt{AAAA-MM-JJ} \\
\hline
\texttt{DATETIME} & Une date avec l'heure & \texttt{AAAA-MM-JJ HH:MM:SS} \\
\hline
\end{tabularx}
\end{center}

Le point capital : MySQL attend les dates au format \textbf{anglo-saxon} \texttt{AAAA-MM-JJ} (année d'abord), et non au format français \texttt{JJ/MM/AAAA}. Le format PHP correspondant est donc \texttt{date('Y-m-d')} pour un champ \texttt{DATE} et \texttt{date('Y-m-d H:i:s')} pour un champ \texttt{DATETIME}.

\begin{exemplebox}[Insérer la date du jour dans une table]
Supposons une table \texttt{membre(id, nom, date\_inscription)} où \texttt{date\_inscription} est de type \texttt{DATE} :
\begin{lstlisting}[language=Php]
<?php
    date_default_timezone_set('Africa/Douala');

    // Date du jour au format accepté par MySQL
    $jour = date('Y-m-d');   // ex. 2025-03-15

    // Construction de la requête d'insertion
    $sql = "INSERT INTO membre (nom, date_inscription)
            VALUES ('Amina', '$jour')";
    // La requête générée est :
    // INSERT INTO membre (nom, date_inscription)
    // VALUES ('Amina', '2025-03-15')
?>
\end{lstlisting}
Nous verrons dans les sections suivantes comment exécuter cette requête avec \texttt{mysqli\_query()}.
\end{exemplebox}

\begin{attention}[Faille de sécurité : Injection SQL]
Dans l'exemple ci-dessus, la variable \texttt{\$jour} (ou \texttt{\$nom}) est insérée \emph{directement} dans la chaîne de la requête SQL. Si la valeur provient d'une saisie utilisateur (formulaire \texttt{\$\_POST}), un attaquant pourrait injecter du code SQL malveillant (ex. \texttt{' OR '1'='1}). C'est la faille n°1 du web : l'\textbf{injection SQL}.
\begin{itemize}
\item \textbf{Ne jamais} concaténer des variables non contrôlées dans une requête SQL.
\item La parade standard avec \texttt{mysqli} est l'utilisation de \textbf{requêtes préparées} (\texttt{mysqli\_prepare}, \texttt{bind\_param}, \texttt{execute}), que nous verrons en détail dans la section « Exécution des requêtes ».
\item En attendant, pour les exercices où les valeurs sont \emph{fixes} (codées en dur dans le script), la concaténation est tolérée pour la simplicité pédagogique.
\end{itemize}
\end{attention}

\begin{savaistu}[Et côté MySQL ?]
MySQL possède ses propres fonctions de date : \texttt{NOW()} retourne la date et l'heure courantes, \texttt{CURDATE()} la date seule. On peut donc écrire directement \texttt{INSERT INTO membre (nom, date\_inscription) VALUES ('Amina', CURDATE())} sans passer par PHP. Alors pourquoi utiliser \texttt{date()} côté PHP ? Parce qu'elle permet de \emph{contrôler} et d'\emph{afficher} la date avant l'enregistrement, et de la réutiliser dans le script (ex. dans un email de confirmation). Au Baccalauréat, la démarche attendue est le plus souvent : \texttt{\$d = date('Y-m-d');} puis insertion de \texttt{\$d} dans la requête.
\end{savaistu}

\begin{exoresolu}[Horodatage d'une inscription à un concours]
Énoncé : le site d'un concours d'entrée dans une école de Douala doit, lors de l'inscription d'un candidat, afficher le message « Inscription de \emph{nom} validée le \emph{JJ/MM/AAAA} à \emph{HH:MM} » et préparer la date au format MySQL pour un champ \texttt{DATETIME}. Le nom du candidat est \texttt{"Biya Steve"}. Écris le script PHP complet (heure du Cameroun). \tcblower
Solution détaillée :
\begin{lstlisting}[language=Php]
<?php
    // Étape 1 : régler le fuseau horaire sur le Cameroun
    date_default_timezone_set('Africa/Douala');

    // Étape 2 : récupérer le nom du candidat
    $nom = "Biya Steve";

    // Étape 3 : préparer les deux formats de date
    $date_affichee = date('d/m/Y à H:i');  // format français
    $date_mysql    = date('Y-m-d H:i:s');  // format DATETIME

    // Étape 4 : afficher le message de confirmation
    echo "Inscription de $nom validée le $date_affichee";
    // Ex. : Inscription de Biya Steve validée le 15/03/2025 à 14:30

    // Étape 5 : préparer la requête SQL (exécution vue plus loin)
    // ATTENTION : en situation réelle, utiliser une requête préparée !
    $sql = "INSERT INTO candidat (nom, date_inscription)
            VALUES ('$nom', '$date_mysql')";
?>
\end{lstlisting}
Points de vigilance : le fuseau horaire est réglé \emph{avant} tout appel à \texttt{date()} ; on utilise bien \texttt{i} (minutes) et non \texttt{m} (mois) ; le format d'affichage français (\texttt{d/m/Y}) est distingué du format de stockage MySQL (\texttt{Y-m-d H:i:s}).
\end{exoresolu}

\coursec{Connexion à MySQL avec l'extension mysqli}

Dans la section précédente, nous avons appris à manipuler la fonction \texttt{date()} pour produire dynamiquement la date et l'heure côté serveur. Tu sais désormais écrire des scripts PHP qui calculent, testent et bouclent. Mais une application web réelle — un site de gestion de notes, une boutique en ligne, un portail de paiement Mobile Money (MTN MoMo, Orange Money) — ne peut pas garder ses données dans de simples variables : celles-ci disparaissent dès que le script se termine. Il faut un \emph{serveur de bases de données} pour stocker les informations de façon permanente. C'est là qu'intervient \cle{MySQL}, et c'est l'objet de cette section : apprendre à \textbf{connecter un script PHP à une base MySQL} grâce à l'extension \texttt{mysqli}.

\courssub{Architecture client/serveur : qui parle à qui ?}

\begin{definition}[SGBD et serveur MySQL]
Un \cle{SGBD} (Système de Gestion de Bases de Données) est un logiciel serveur qui stocke, organise et protège les données, et qui répond aux \cle{requêtes} exprimées en langage SQL. \cle{MySQL} est le SGBD libre le plus utilisé avec PHP ; il est installé automatiquement avec WampServer et XAMPP.
\end{definition}

Lorsqu'un internaute visite une page dynamique, trois acteurs collaborent :

\begin{enumerate}
  \item le \textbf{navigateur} (client web) envoie une requête HTTP au serveur web ;
  \item le serveur \textbf{Apache} exécute le script \textbf{PHP}, qui joue alors le rôle de \emph{client du SGBD} : il ouvre une connexion vers \textbf{MySQL}, envoie des requêtes SQL et récupère les résultats ;
  \item PHP assemble la page \textbf{HTML} finale, qu'Apache renvoie au navigateur.
\end{enumerate}

Point capital à bien comprendre : \textbf{le navigateur ne dialogue jamais directement avec MySQL}. Toutes les requêtes SQL transitent par le script PHP, qui est le seul à connaître les identifiants de connexion. C'est une garantie de sécurité : le code PHP n'est jamais envoyé au client, seul le HTML produit l'est.

\begin{savaistu}[Le « i » de mysqli]
L'extension \texttt{mysqli} signifie \emph{MySQL improved} (« MySQL amélioré »). Elle a remplacé l'ancienne extension \texttt{mysql\_} (sans le « i »), jugée obsolète et \textbf{supprimée définitivement depuis PHP 7}. Les anciens scripts utilisant \texttt{mysql\_connect()} ne fonctionnent donc plus du tout sur les serveurs modernes. Au Baccalauréat TI, on exige l'écriture \texttt{mysqli} : un script avec \texttt{mysql\_connect()} est considéré comme faux. Au Cameroun, la quasi-totalité des hébergements mutualisés (ceux utilisés par les startups et les sites d'administrations) tournent sous PHP 7 ou 8 : seul \texttt{mysqli} (ou PDO) y est accepté.
\end{savaistu}

\courssub{Établir la connexion : \texttt{mysqli\_connect()}}

Avant de poser la moindre question à MySQL, le script doit \emph{ouvrir une connexion}, exactement comme on compose un numéro avant de parler au téléphone. Il faut fournir trois informations : \textbf{où} se trouve le serveur (l'hôte), \textbf{qui} se connecte (l'utilisateur) et son \textbf{mot de passe}.

\begin{definition}[\texttt{mysqli\_connect}]
\cle{mysqli\_connect} est la fonction qui ouvre une connexion entre le script PHP et le serveur MySQL. Elle retourne un \cle{objet \texttt{mysqli}} (identifiant de connexion représentant le canal de communication), que l'on conserve dans une variable pour toutes les opérations suivantes. En cas d'échec, elle retourne \texttt{false}.
\end{definition}

\begin{propriete}[Syntaxe de \texttt{mysqli\_connect}]
\begin{lstlisting}[language=Php]
$cnx = mysqli_connect(hote, utilisateur, mot_de_passe);
\end{lstlisting}
Sous WampServer ou XAMPP (configuration par défaut en salle informatique), les valeurs typiques sont :
\begin{itemize}
  \item \texttt{hote} : \texttt{'localhost'} (MySQL tourne sur la même machine que PHP) ;
  \item \texttt{utilisateur} : \texttt{'root'} (super-utilisateur créé à l'installation) ;
  \item \texttt{mot\_de\_passe} : \texttt{''} (chaîne vide par défaut sous WAMP/XAMPP).
\end{itemize}
\end{propriete}

\begin{attention}[« root » sans mot de passe : uniquement en local !]
La configuration \texttt{('localhost','root','')} est acceptable \textbf{uniquement sur le poste de développement} (salle informatique du lycée, machine personnelle). Sur un serveur en production, utiliser \texttt{root} sans mot de passe est une faille de sécurité majeure : n'importe qui lisant le script obtient un accès total à toutes les bases. En production, on crée un utilisateur MySQL dédié, avec un mot de passe fort et des droits limités à la seule base de l'application.
\end{attention}

\begin{savaistu}[Paramètre « base de données » de \texttt{mysqli\_connect}]
La fonction \texttt{mysqli\_connect} accepte un \textbf{4\textsuperscript{e} paramètre optionnel} : le nom de la base de données à sélectionner immédiatement.
\begin{lstlisting}[language=Php]
$cnx = mysqli_connect('localhost', 'root', '', 'ecole');
\end{lstlisting}
Cela évite l'appel séparé à \texttt{mysqli\_select\_db}. Toutefois, le programme officiel exige la maîtrise de \texttt{mysqli\_select\_db} comme étape distincte ; aux examens, privilégie la méthode en deux étapes (connexion puis sélection) pour faire apparaître explicitement la logique.
\end{savaistu}

\courssub{Gérer les erreurs de connexion : \texttt{die()} et \texttt{mysqli\_connect\_error()}}

Que se passe-t-il si MySQL est éteint, si le mot de passe est faux ou si le serveur est injoignable ? \texttt{mysqli\_connect} retourne \texttt{false}, et toutes les requêtes suivantes échoueraient en cascade avec des messages d'erreur peu lisibles. La bonne pratique consiste à \textbf{arrêter immédiatement le script} avec un message clair.

\begin{definition}[\texttt{die}]
\cle{die(message)} est la fonction qui arrête immédiatement l'exécution du script en affichant le message passé en argument. Aucune ligne située après \texttt{die()} n'est exécutée. On l'utilise pour \emph{bloquer proprement} le script lorsqu'une opération indispensable (comme la connexion) a échoué. Son alias \texttt{exit()} est strictement équivalent.
\end{definition}

On combine \texttt{die()} avec l'opérateur \texttt{or} et la fonction \texttt{mysqli\_connect\_error()}, qui retourne une \emph{description textuelle de la dernière erreur de connexion} (par exemple : \emph{Access denied for user 'root'@'localhost'}).

\begin{methode}[Séquence type de connexion à une base MySQL]
La connexion complète se fait toujours en deux étapes protégées par \texttt{die()}, suivies de la définition du jeu de caractères (indispensable pour les accents) :
\begin{enumerate}
  \item \textbf{Ouvrir la connexion au serveur} et vérifier qu'elle a réussi :
\begin{lstlisting}[language=Php]
$cnx = mysqli_connect('localhost', 'root', '')
    or die('Erreur de connexion : ' . mysqli_connect_error());
\end{lstlisting}
  \item \textbf{Sélectionner la base de données} sur laquelle on va travailler :
\begin{lstlisting}[language=Php]
mysqli_select_db($cnx, 'ma_base')
    or die('Base introuvable');
\end{lstlisting}
  \item \textbf{Définir le jeu de caractères} (UTF-8) pour éviter les problèmes d'accents :
\begin{lstlisting}[language=Php]
mysqli_set_charset($cnx, 'utf8mb4')
    or die('Erreur encodage : ' . mysqli_error($cnx));
\end{lstlisting}
\end{enumerate}
Si ces trois lignes sont passées sans message d'erreur, la variable \texttt{\$cnx} contient une connexion valide, correctement encodée, et prête à recevoir des requêtes SQL.
\end{methode}

\courssub{Choisir la base de données : \texttt{mysqli\_select\_db()}}

Un serveur MySQL héberge en général \emph{plusieurs} bases de données (sous WampServer, on en voit déjà plusieurs dès l'installation : \texttt{mysql}, \texttt{information\_schema}, \texttt{performance\_schema}, etc.). Se connecter au serveur ne suffit donc pas : il faut indiquer \textbf{sur quelle base} portent les requêtes.

\begin{propriete}[Syntaxe de \texttt{mysqli\_select\_db}]
\begin{lstlisting}[language=Php]
mysqli_select_db($cnx, 'nom_de_la_base');
\end{lstlisting}
Le premier paramètre est l'identifiant de connexion retourné par \texttt{mysqli\_connect}, le second est le nom de la base (sensible à la casse sur certains serveurs Linux). La fonction retourne \texttt{true} en cas de succès, \texttt{false} sinon — d'où l'usage systématique de \texttt{or die(...)}.
\end{propriete}

\begin{attention}[Erreur fréquente : oublier \texttt{mysqli\_select\_db}]
C'est le bug classique du débutant : la connexion réussit, mais toutes les requêtes échouent avec l'erreur \emph{« No database selected »} (« aucune base sélectionnée »). La cause est presque toujours l'oubli de \texttt{mysqli\_select\_db(\$cnx, ...)} après \texttt{mysqli\_connect}. Vérifie aussi que le nom de la base est \emph{exactement} celui créé dans phpMyAdmin (respect des majuscules/minuscules et des underscores : \texttt{ecole} n'est pas \texttt{Ecole}).
\end{attention}

\courssub{Jeu de caractères : \texttt{mysqli\_set\_charset()}}

Sans instruction explicite, la connexion peut utiliser un encodage par défaut (souvent \texttt{latin1}) qui corrompt les caractères accentués (é, è, à, ç, ô) lors des insertions ou des lectures. Au Cameroun, où les noms propres contiennent de nombreux accents (\emph{Bafoussam}, \emph{Yaoundé}, \emph{Nkongsamba}, \emph{Mbappé}), cette étape est \textbf{obligatoire}.

\begin{propriete}[Syntaxe de \texttt{mysqli\_set\_charset}]
\begin{lstlisting}[language=Php]
mysqli_set_charset($cnx, 'utf8mb4');
\end{lstlisting}
Utilise \texttt{utf8mb4} (support complet d'Unicode, y compris émojis) plutôt que l'ancien \texttt{utf8}. Place cet appel \textbf{immédiatement après} \texttt{mysqli\_select\_db}.
\end{propriete}

\courssub{Fermer la connexion : \texttt{mysqli\_close()}}

Une connexion ouverte consomme des ressources sur le serveur MySQL (mémoire, processus, verrous). Un bon script libère donc la connexion dès qu'il n'en a plus besoin, en toute fin de script :

\begin{propriete}[Syntaxe de \texttt{mysqli\_close}]
\begin{lstlisting}[language=Php]
mysqli_close($cnx);
\end{lstlisting}
La fonction ferme la connexion identifiée par \texttt{\$cnx} et retourne \texttt{true} en cas de succès. Après cet appel, la variable \texttt{\$cnx} n'est plus utilisable pour des requêtes.
\end{propriete}

En pratique, PHP ferme automatiquement les connexions à la fin du script ; néanmoins, l'appel explicite à \texttt{mysqli\_close()} est une \textbf{bonne pratique exigée dans les rédactions au Bac} : elle montre que tu maîtrises le cycle de vie complet de la connexion.

\courssub{Script type complet et réutilisable : \texttt{connexion.php}}

Voici le script de connexion complet, commenté ligne par ligne, tel qu'on l'attend au Baccalauréat. Il se connecte au serveur, choisit la base \texttt{ecole}, force l'encodage UTF-8 et affiche un message de confirmation.

\begin{exemplebox}[Script \texttt{connexion.php} complet et commenté]
\begin{lstlisting}[language=Php]
<?php
// ============================================
// connexion.php : connexion a la base "ecole"
// ============================================

// 1. Ouverture de la connexion au serveur MySQL
//    En cas d'echec, die() stoppe le script avec un message clair
$cnx = mysqli_connect('localhost', 'root', '')
    or die('Erreur de connexion au serveur : ' . mysqli_connect_error());

// 2. Selection de la base de donnees "ecole"
mysqli_select_db($cnx, 'ecole')
    or die('Base de donnees introuvable');

// 3. Definition du jeu de caracteres (UTF-8 complet)
mysqli_set_charset($cnx, 'utf8mb4')
    or die('Erreur encodage : ' . mysqli_error($cnx));

// 4. Si le script arrive ici, tout s'est bien passe
echo 'Connexion reussie a la base ecole';

// 5. Fermeture de la connexion (bonne pratique)
mysqli_close($cnx);
?>
\end{lstlisting}
\end{exemplebox}

Testé sous WampServer avec une base \texttt{ecole} existante, ce script affiche simplement : \emph{Connexion réussie à la base ecole}. Si MySQL est arrêté, on obtient par exemple : \emph{Erreur de connexion au serveur : Connection refused}. Si la base n'existe pas : \emph{Base de données introuvable}. Si l'encodage échoue (très rare) : \emph{Erreur encodage : ...}. Chaque cas d'échec produit donc un message explicite, ce qui facilite énormément le débogage.

\courssub{Bonnes pratiques : mutualiser la connexion avec \texttt{include} / \texttt{require}}

Dans une application réelle, \emph{tous} les scripts (liste des élèves, saisie des notes, bulletins, paiement Mobile Money...) ont besoin de la connexion. Recopier les mêmes lignes partout est une mauvaise idée : si le mot de passe change, il faudrait modifier des dizaines de fichiers. La solution professionnelle consiste à écrire la connexion \textbf{une seule fois} dans un fichier \texttt{connexion.php}, puis à l'\emph{inclure} dans chaque script.

\begin{propriete}[Inclure le fichier de connexion]
\begin{lstlisting}[language=Php]
<?php
// liste_eleves.php : affiche les eleves
require('connexion.php');   // $cnx est maintenant disponible

// ... requetes SQL avec $cnx ...

mysqli_close($cnx);
?>
\end{lstlisting}
\begin{itemize}
  \item \texttt{include('connexion.php')} : en cas de fichier absent, émet un avertissement (\texttt{Warning}) et \emph{continue} le script ;
  \item \texttt{require('connexion.php')} : en cas de fichier absent, provoque une erreur fatale (\texttt{Fatal error}) et \emph{arrête} le script.
\end{itemize}
Pour une connexion à la base, on préfère \texttt{require} : sans connexion, le reste du script n'a aucun sens.
\end{propriete}

Dans ce cas, le fichier \texttt{connexion.php} ne contient que les étapes 1 à 3 (connexion, sélection de la base, encodage), \textbf{sans} le \texttt{echo} de confirmation ni le \texttt{mysqli\_close()} — la fermeture reste à la charge de chaque script appelant.

\begin{exemplebox}[Fichier \texttt{connexion.php} mutualisé (sans echo, sans close)]
\begin{lstlisting}[language=Php]
<?php
// connexion.php : a includer avec require()
// Ne contient PAS mysqli_close()

$cnx = mysqli_connect('localhost', 'root', '')
    or die('Erreur de connexion : ' . mysqli_connect_error());

mysqli_select_db($cnx, 'ecole')
    or die('Base ecole introuvable');

mysqli_set_charset($cnx, 'utf8mb4')
    or die('Erreur encodage : ' . mysqli_error($cnx));
?>
\end{lstlisting}
\end{exemplebox}

\begin{exoresolu}[Écrire la connexion à la base d'un cybercafé]
Énoncé. Un cybercafé de Bafoussam gère ses postes clients dans une base MySQL nommée \texttt{cybercafe}, hébergée en local sous WampServer. Écris le script \texttt{connexion.php} mutualisé permettant de s'y connecter, avec gestion des erreurs et encodage UTF-8, puis le début du script \texttt{postes.php} qui l'utilise.
\tcblower
Solution détaillée. On applique la séquence type en trois étapes protégées par \texttt{die()}, puis l'inclusion dans le script métier avec \texttt{require}.
\begin{lstlisting}[language=Php]
<?php
// connexion.php (mutualise)
$cnx = mysqli_connect('localhost', 'root', '')
    or die('Erreur de connexion : ' . mysqli_connect_error());

mysqli_select_db($cnx, 'cybercafe')
    or die('Base cybercafe introuvable');

mysqli_set_charset($cnx, 'utf8mb4')
    or die('Erreur encodage : ' . mysqli_error($cnx));
?>
\end{lstlisting}
\begin{lstlisting}[language=Php]
<?php
// postes.php
require('connexion.php');   // connexion, base, encodage prets

// ... ici : requetes SQL sur la table des postes ...

?>
\end{lstlisting}
Points de vigilance : ne pas oublier \texttt{mysqli\_select\_db} (sinon \emph{No database selected}), ne pas oublier \texttt{mysqli\_set\_charset} (sinon accents corrompus), utiliser \texttt{require} plutôt qu'\texttt{include} pour la connexion, et fermer la connexion en fin de script métier.

\begin{experience}[TP guidé : tester sa première connexion PHP/MySQL]
\textbf{Objectif :} vérifier expérimentalement le cycle complet de connexion sous WampServer.

\textbf{Matériel/logiciels :} un poste avec WampServer (ou XAMPP) installé, un navigateur.

\textbf{Manipulation :}
\begin{enumerate}
  \item Lance WampServer et attends que l'icône soit \emph{verte} (Apache et MySQL démarrés).
  \item Ouvre phpMyAdmin (\texttt{http://localhost/phpmyadmin}), onglet \emph{Bases de données}, et crée une base nommée \texttt{ecole} (interclassement \texttt{utf8mb4\_general\_ci}).
  \item Dans le dossier \texttt{C:\textbackslash wamp64\textbackslash www}, crée un dossier \texttt{test}, puis le fichier \texttt{connexion.php} en recopiant le script complet de l'exemple ci-dessus (avec \texttt{echo} et \texttt{close}).
  \item Dans le navigateur, saisis \texttt{http://localhost/test/connexion.php} et observe le message.
  \item Arrête le service MySQL (clic gauche sur l'icône Wamp $\rightarrow$ MySQL $\rightarrow$ Arrêter le service) et recharge la page.
  \item Redémarre MySQL, renomme la base en \texttt{ecole2} dans phpMyAdmin, et recharge encore la page.
  \item (Optionnel) Modifie \texttt{connexion.php} pour mettre un mauvais mot de passe (\texttt{'pwd'}) et teste.
\end{enumerate}
\textbf{Observations :} à l'étape 4, le message \emph{Connexion réussie à la base ecole} s'affiche ; à l'étape 5, \texttt{die()} affiche l'erreur de connexion au serveur (ex. \emph{Connection refused}) ; à l'étape 6, le message \emph{Base de données introuvable} apparaît ; à l'étape 7, \emph{Access denied for user 'root'@'localhost'}.

\textbf{Interprétation :} chaque étape de la séquence de connexion est protégée indépendamment, ce qui permet d'identifier précisément l'origine d'une panne — compétence indispensable pour déboguer une application réelle.
\end{experience}

\begin{aretenir}[L'essentiel de la connexion PHP/MySQL]
\begin{itemize}
  \item Le script PHP est le \textbf{client} du serveur MySQL ; le navigateur ne voit jamais ni la base ni le code PHP.
  \item \texttt{\$cnx = mysqli\_connect('localhost','root','') or die(...)} ouvre la connexion ; \texttt{mysqli\_connect\_error()} décrit l'erreur éventuelle.
  \item \texttt{mysqli\_select\_db(\$cnx, 'base') or die(...)} choisit la base — son oubli provoque \emph{No database selected}.
  \item \texttt{mysqli\_set\_charset(\$cnx, 'utf8mb4')} garantit l'intégrité des accents (é, è, à, ç...).
  \item \texttt{mysqli\_close(\$cnx)} libère la connexion en fin de script.
  \item On mutualise la connexion dans un fichier \texttt{connexion.php} inclus avec \texttt{require}.
  \item Au Bac : on écrit \texttt{mysqli}, jamais l'ancienne extension \texttt{mysql\_} supprimée depuis PHP 7.
\end{itemize}
\end{aretenir}

Maintenant que le canal de communication est ouvert, sécurisé et correctement encodé, il reste à l'exploiter : la section suivante montrera comment \textbf{exécuter des requêtes SQL} (insertion, modification, suppression, sélection) depuis PHP avec \texttt{mysqli\_query()}, puis comment lire et afficher les résultats avec \texttt{mysqli\_fetch\_assoc()}, \texttt{mysqli\_fetch\_row()}, \texttt{mysqli\_num\_rows()}.

\coursec{Exécution des requêtes SQL depuis PHP}

Dans la section précédente, nous avons appris à ouvrir une connexion au serveur MySQL avec \texttt{mysqli\_connect()} et à choisir une base de travail avec \texttt{mysqli\_select\_db()}. Mais une connexion ouverte ne fait rien toute seule : c'est un simple \cle{tuyau} entre ton script PHP et le serveur MySQL. Il faut maintenant faire circuler des ordres dans ce tuyau : insérer un élève, modifier une note, supprimer un candidat, consulter la liste des inscrits. C'est précisément le rôle de la fonction \texttt{mysqli\_query()}, véritable cœur de l'interfaçage PHP/MySQL. C'est elle qui transforme ton site statique en véritable \cle{application web} pilotée par une base de données.

\courssub{La fonction mysqli\_query() : envoyer un ordre au serveur}

\begin{definition}[La fonction mysqli\_query]
\texttt{mysqli\_query()} est la fonction de l'extension \cle{mysqli} qui envoie une requête SQL au serveur MySQL, sur la connexion et la base précédemment sélectionnées. Sa syntaxe générale est :
\begin{lstlisting}[language=Php]
$resultat = mysqli_query($cnx, $sql);
\end{lstlisting}
où \texttt{\$cnx} est l'identifiant de connexion retourné par \texttt{mysqli\_connect()} et \texttt{\$sql} une chaîne de caractères contenant la requête SQL.
\end{definition}

\begin{propriete}[Valeur de retour de mysqli\_query]
La valeur retournée dépend du \emph{type} de requête exécutée :
\begin{itemize}
  \item pour \texttt{INSERT}, \texttt{UPDATE}, \texttt{DELETE} : la fonction retourne \texttt{true} en cas de succès, \texttt{false} en cas d'échec ;
  \item pour \texttt{SELECT} (et \texttt{SHOW}, \texttt{DESCRIBE}) : elle retourne un \cle{jeu de résultats} (objet de type \texttt{mysqli\_result}) en cas de succès, \texttt{false} en cas d'échec.
\end{itemize}
En cas d'échec, la fonction \texttt{die(mysqli\_error(\$cnx))} permet d'arrêter le script en affichant le message d'erreur exact renvoyé par MySQL.
\end{propriete}

\begin{attention}[false n'est pas un jeu de résultats vide]
Deux situations très différentes ne doivent pas être confondues :
\begin{itemize}
  \item un \texttt{SELECT} qui ne trouve aucune ligne retourne un jeu de résultats \emph{vide} (mais valide) : \texttt{mysqli\_query()} a réussi ;
  \item un \texttt{SELECT} syntaxiquement faux (table inexistante, faute de frappe dans un nom de colonne) retourne \texttt{false}.
\end{itemize}
On teste donc toujours le retour avec \texttt{if (\$resultat === false)} ou \texttt{if (!\$resultat)} avant d'exploiter les données.
\end{attention}

\begin{methode}[Exécuter une requête SQL depuis PHP : la démarche en trois temps]
Quelle que soit la requête, la démarche est toujours la même :
\begin{enumerate}
  \item \textbf{Construire} la chaîne SQL dans une variable, par exemple \texttt{\$sql = "INSERT INTO eleve ..." ;} — cela rend le script lisible et facilite le débogage (on peut afficher \texttt{\$sql} pour vérifier la requête) ;
  \item \textbf{Envoyer} la requête avec \texttt{\$resultat = mysqli\_query(\$cnx, \$sql) ;}
  \item \textbf{Tester} le résultat : si succès, afficher un message de confirmation ou exploiter le jeu de résultats ; sinon, arrêter proprement avec \texttt{die(mysqli\_error(\$cnx))}.
\end{enumerate}
\end{methode}

\courssub{Insertion : la requête INSERT alimentée par un formulaire}

\textbf{Intuition.} Le cas le plus fréquent dans une application web camerounaise — inscription d'un élève, enregistrement d'un client Mobile Money, dépôt d'une candidature — consiste à récupérer les données saisies dans un formulaire HTML et à les enregistrer dans une table. Le tableau superglobal \texttt{\$\_POST} contient les valeurs envoyées par le formulaire ; il suffit de les insérer dans la chaîne SQL.

\begin{propriete}[Syntaxe de la requête INSERT]
\begin{lstlisting}[language=SQL]
INSERT INTO nom_table (colonne1, colonne2, ...) 
VALUES (valeur1, valeur2, ...);
\end{lstlisting}
Depuis PHP, on construit cette chaîne en y injectant les variables issues de \texttt{\$\_POST} par concaténation ou interpolation.
\end{propriete}

\begin{attention}[Apostrophes obligatoires autour des valeurs textuelles]
Dans une requête SQL, les valeurs de type texte (\texttt{VARCHAR}, \texttt{CHAR}, \texttt{DATE}...) doivent être entourées d'\cle{apostrophes}, tandis que les valeurs numériques s'écrivent sans apostrophes :
\begin{lstlisting}[language=Php]
$sql = "INSERT INTO eleve (nom, age) VALUES ('$nom', $age)";
// Correct : 'Ngo Bell' entre apostrophes, 17 sans apostrophes
\end{lstlisting}
Oublier les apostrophes autour d'une chaîne provoque une erreur SQL (\texttt{false} retourné). C'est l'erreur la plus fréquente des débutants.
\end{attention}

\courssub{Modification : la requête UPDATE}

\textbf{Intuition.} Un élève change de classe, un client modifie son numéro de téléphone : il faut mettre à jour des enregistrements existants sans les recréer.

\begin{propriete}[Syntaxe de la requête UPDATE]
\begin{lstlisting}[language=SQL]
UPDATE nom_table 
SET colonne1 = valeur1, colonne2 = valeur2 
WHERE condition;
\end{lstlisting}
La clause \texttt{WHERE} désigne \emph{précisément} les lignes à modifier, le plus souvent par la clé primaire (\texttt{WHERE id = 5}).
\end{propriete}

\begin{exemplebox}[Corriger la classe d'un élève]
\begin{lstlisting}[language=Php]
$sql = "UPDATE eleve SET classe = 'Tle TI' WHERE id = 12";
if (mysqli_query($cnx, $sql)) {
    echo "Enregistrement modifié avec succès.";
} else {
    die("Erreur : " . mysqli_error($cnx));
}
\end{lstlisting}
\end{exemplebox}

\courssub{Suppression : la requête DELETE}

\textbf{Intuition.} Un candidat se désiste, un produit est retiré du catalogue : on supprime la ligne correspondante de la table.

\begin{propriete}[Syntaxe de la requête DELETE]
\begin{lstlisting}[language=SQL]
DELETE FROM nom_table WHERE condition;
\end{lstlisting}
\end{propriete}

\begin{attention}[Le danger du UPDATE ou DELETE sans WHERE]
Sans clause \texttt{WHERE}, la requête s'applique à \textbf{toutes} les lignes de la table :
\begin{itemize}
  \item \texttt{UPDATE eleve SET classe = 'Tle C'} re-classe \emph{tous} les élèves de l'établissement ;
  \item \texttt{DELETE FROM eleve} \emph{vide entièrement} la table, sans demander de confirmation !
\end{itemize}
Règle d'or : un \texttt{UPDATE} ou un \texttt{DELETE} doit \emph{toujours} comporter un \texttt{WHERE} ciblant la clé primaire. Avant d'exécuter une suppression en production, on teste d'abord la condition avec un \texttt{SELECT} : \texttt{SELECT * FROM eleve WHERE id = 12} permet de vérifier qu'on vise bien la bonne ligne.
\end{attention}

\courssub{Sélection : la requête SELECT et le jeu de résultats}

Contrairement aux trois requêtes précédentes, \texttt{SELECT} ne modifie rien : elle \emph{interroge} la base et retourne un \cle{jeu de résultats}, c'est-à-dire un tableau de lignes que le script parcourra ensuite (avec \texttt{mysqli\_fetch\_assoc()}, \texttt{mysqli\_num\_rows()}, etc. — ce sera l'objet de la section suivante).

\begin{lstlisting}[language=Php]
$sql = "SELECT nom, classe FROM eleve WHERE classe = 'Tle TI'";
$resultat = mysqli_query($cnx, $sql);
if ($resultat === false) {
    die("Erreur SQL : " . mysqli_error($cnx));
}
// $resultat est ici un jeu de résultats exploitable
$nb = mysqli_num_rows($resultat);
echo "$nb élève(s) trouvé(s).";
\end{lstlisting}

<?php
// 1. Connexion au serveur MySQL
$cnx = mysqli_connect("localhost", "root", "")
       or die("Connexion impossible : " . mysqli_connect_error());

// 2. Sélection de la base
mysqli_select_db($cnx, "concours")
       or die("Base introuvable : " . mysqli_error($cnx));

$nom      = $_POST['nom'];
$sexe     = $_POST['sexe'];

// 4. Construction de la requête d'insertion
//    (chaînes et dates entre apostrophes !)

        VALUES ('$nom', '$sexe', '$datnaiss')";

// 5. Envoi de la requête et test du résultat
if (mysqli_query($cnx, $sql)) {
    echo "1 enregistrement ajouté : bienvenue $nom !";
} else {
    die("Échec de l'insertion : " . mysqli_error($cnx));
}

// 6. Fermeture de la connexion
mysqli_close($cnx);
?>
\end{lstlisting}
\end{exemplebox}

\begin{lstlisting}[language=SQL]
INSERT INTO candidat (nom, sexe, datnaiss) 
VALUES ('Ngo Bell', 'M', '2006-04-12');
\end{lstlisting}
La fonction retourne \texttt{true}, et le message « 1 enregistrement ajouté : bienvenue Ngo Bell ! » s'affiche dans le navigateur.

\begin{exoresolu}[Modification du numéro de téléphone d'un candidat]
Énoncé. La table \texttt{candidat} possède les colonnes \texttt{id}, \texttt{nom}, \texttt{telephone}. Écrire le script PHP qui met à jour le téléphone du candidat d'\texttt{id} égal à 7 avec la valeur \texttt{699123456} reçue par \texttt{\$\_POST['tel']}, en affichant un message de succès ou l'erreur SQL.
\tcblower
Solution détaillée. On suit la démarche en trois temps : construction, envoi, test.
\begin{lstlisting}[language=Php]
<?php
$cnx = mysqli_connect("localhost", "root", "")
       or die("Connexion impossible");
mysqli_select_db($cnx, "concours") 
       or die("Base introuvable");

$tel = $_POST['tel'];

// 1. Construction : WHERE obligatoire pour ne viser que l'id 7
$sql = "UPDATE candidat SET telephone = '$tel' WHERE id = 7";

// 2 et 3. Envoi et test
if (mysqli_query($cnx, $sql)) {
    echo "Téléphone mis à jour pour le candidat n° 7.";
} else {
    die("Erreur : " . mysqli_error($cnx));
}
mysqli_close($cnx);
?>
\end{lstlisting}
Sans la clause \texttt{WHERE id = 7}, \emph{tous} les candidats auraient reçu le même numéro de téléphone : catastrophe garantie !
\end{exoresolu}

\begin{attention}[Injection SQL : le piège de la concaténation directe]
Construire une requête en concaténant directement \texttt{\$\_POST} expose l'application aux \cle{injections SQL} : un utilisateur malveillant peut saisir dans le champ nom la valeur \texttt{' OR '1'='1} et détourner la requête pour lire ou détruire des données. Les parades professionnelles sont :
\begin{itemize}
  \item \texttt{mysqli\_real\_escape\_string(\$cnx, \$nom)} qui neutralise les caractères dangereux ;
  \item les \cle{requêtes préparées} (\texttt{mysqli\_prepare()}, \texttt{bind\_param()}), qui séparent totalement le code SQL des données.
\end{itemize}
Ces techniques sont un complément utile à connaître, \emph{non exigible} au programme de Terminale TI, mais indispensables dès que tu développeras une vraie application.
\end{attention}

\begin{savaistu}[L'injection SQL, une faille bien réelle au Cameroun]
L'injection SQL figure depuis plus de vingt ans dans le classement OWASP des failles web les plus critiques. Au Cameroun, l'ANTIC (Agence Nationale des Technologies de l'Information et de la Communication) sensibilise régulièrement les développeurs et administrations à ce risque : plusieurs sites institutionnels et plateformes locales ont été défigurés ou vidés de leurs données à cause de formulaires non protégés. Maîtriser \texttt{mysqli\_query()} c'est bien ; savoir sécuriser ce qu'on lui envoie, c'est déjà penser comme un professionnel.
\end{savaistu}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
  \item \texttt{mysqli\_query(\$cnx, \$sql)} envoie une requête SQL au serveur : elle retourne \texttt{true}/\texttt{false} pour \texttt{INSERT}, \texttt{UPDATE}, \texttt{DELETE}, et un jeu de résultats (ou \texttt{false}) pour \texttt{SELECT}.
  \item La démarche type : construire la chaîne \texttt{\$sql}, l'envoyer, tester le résultat avec \texttt{if} ou \texttt{die(mysqli\_error(\$cnx))}.
  \item Les valeurs textuelles et les dates s'écrivent entre apostrophes dans la requête ; les nombres sans apostrophes.
  \item \texttt{UPDATE} et \texttt{DELETE} exigent une clause \texttt{WHERE} ciblant la clé primaire, sous peine de modifier ou supprimer toute la table.
  \item Les données d'un formulaire arrivent dans \texttt{\$\_POST} ; leur concaténation directe expose aux injections SQL (parade : \texttt{mysqli\_real\_escape\_string()} ou requêtes préparées).
\end{itemize}
\end{aretenir}

\coursec{Lecture et affichage des résultats}

Dans la section précédente, tu as appris à exécuter une requête SQL depuis PHP grâce à \texttt{mysqli\_query()}. Tu as constaté une dissymétrie fondamentale : pour une requête \texttt{INSERT}, \texttt{UPDATE} ou \texttt{DELETE}, la fonction retourne simplement \texttt{true} ou \texttt{false}, car il n'y a rien à « lire ». Mais pour une requête \texttt{SELECT}, \texttt{mysqli\_query()} retourne un objet particulier, appelé \cle{jeu de résultats} (ou \emph{result set}), qui contient toutes les lignes sélectionnées. Ce n'est \textbf{pas} un tableau PHP ordinaire : on ne peut pas écrire directement \texttt{\$res[0]['nom']}. Il faut utiliser des fonctions spécialisées de la famille \texttt{mysqli\_fetch\_*} pour extraire les lignes une à une. C'est précisément l'objet de cette section : transformer un jeu de résultats MySQL en données affichables dans une page web.

\courssub{Nature du jeu de résultats : un tableau de lignes parcouru par un pointeur}

\begin{definition}[Jeu de résultats]
Un \cle{jeu de résultats} est la structure de données retournée par \texttt{mysqli\_query()} après l'exécution d'une requête \texttt{SELECT}. Il se présente comme un \textbf{tableau de lignes} : chaque ligne correspond à un enregistrement de la table, et chaque ligne est elle-même composée de colonnes (les champs sélectionnés). Le jeu de résultats possède un \cle{pointeur de ligne} interne, positionné initialement \emph{avant} la première ligne.
\end{definition}

L'image mentale à retenir est celle d'un \textbf{guichet de la CAMTEL} qui distribue des tickets : le jeu de résultats est la file d'attente des clients, et le pointeur est l'employé qui appelle les clients un par un. Chaque appel à une fonction \texttt{mysqli\_fetch\_*} « sert » le client suivant et fait avancer la file. Quand il n'y a plus personne, l'employé annonce « suivant : personne » — en PHP, c'est la valeur \texttt{NULL}.

\courssub{Compter les lignes : \texttt{mysqli\_num\_rows()}}

Avant même de parcourir les résultats, il est souvent utile de savoir \emph{combien} de lignes la requête a retournées : pour afficher « 5 élève(s) trouvé(s) », pour vérifier qu'une recherche n'est pas vide, ou pour décider d'afficher un message « aucun résultat ».

\begin{propriete}[Syntaxe de \texttt{mysqli\_num\_rows()}]
\texttt{int mysqli\_num\_rows(mysqli\_result \$resultat)} retourne le \textbf{nombre de lignes} contenues dans le jeu de résultats passé en paramètre. Elle s'applique uniquement aux résultats d'une requête \texttt{SELECT} (ou \texttt{SHOW}). Elle ne modifie pas le pointeur : on peut l'appeler avant ou après le parcours.
\end{propriete}

\begin{lstlisting}[language=Php]
<?php
$cnx = mysqli_connect("localhost", "root", "")
       or die("Connexion impossible : " . mysqli_connect_error());
mysqli_select_db($cnx, "lycee") or die("Base introuvable");

$res = mysqli_query($cnx, "SELECT nom, age FROM eleve");
$nb  = mysqli_num_rows($res);
echo $nb . " eleve(s) trouve(s).";
?>
\end{lstlisting}

\begin{attention}[\texttt{mysqli\_num\_rows()} ne fonctionne pas avec INSERT/UPDATE/DELETE]
Pour une requête de modification, \texttt{mysqli\_query()} retourne un booléen et non un jeu de résultats : appeler \texttt{mysqli\_num\_rows(true)} provoque une erreur. Pour connaître le nombre de lignes \emph{affectées} par un \texttt{UPDATE} ou un \texttt{DELETE}, on utilise \texttt{mysqli\_affected\_rows(\$cnx)} — hors programme, mais utile en projet.
\end{attention}

\courssub{Extraire une ligne : les trois fonctions \texttt{mysqli\_fetch\_*}}

PHP propose trois fonctions d'extraction, qui diffèrent uniquement par la \textbf{forme du tableau} retourné. Les trois partagent le même comportement : elles retournent la ligne courante, avancent le pointeur d'une ligne, et retournent \texttt{NULL} quand le résultat est épuisé.

\textbf{1. \texttt{mysqli\_fetch\_row()} : tableau à indices numériques.}\par
Chaque ligne est retournée sous la forme d'un tableau indexé par des entiers, dans l'ordre des champs du \texttt{SELECT} : \texttt{\$ligne[0]} est le premier champ, \texttt{\$ligne[1]} le deuxième, etc.

\textbf{2. \texttt{mysqli\_fetch\_assoc()} : tableau associatif.}\par
Chaque ligne est retournée sous la forme d'un tableau associatif dont les \textbf{clés sont les noms des champs} : \texttt{\$ligne['nom']}, \texttt{\$ligne['age']}. C'est la forme la plus lisible et la plus robuste.

\begin{definition}[\texttt{mysqli\_fetch\_assoc()}]
\texttt{array|null mysqli\_fetch\_assoc(mysqli\_result \$resultat)} retourne la \textbf{ligne courante} du jeu de résultats sous forme de \cle{tableau associatif} (les clés sont les noms des champs de la requête), puis \textbf{avance le pointeur} d'une ligne. Elle retourne \texttt{NULL} lorsque toutes les lignes ont été parcourues.
\end{definition}

\textbf{3. \texttt{mysqli\_fetch\_array()} : les deux formes à la fois.}\par
Chaque ligne est retournée dans un tableau qui contient \emph{à la fois} les indices numériques et les clés associatives : on peut écrire indifféremment \texttt{\$ligne[0]} ou \texttt{\$ligne['nom']}. Pratique, mais le tableau est deux fois plus volumineux en mémoire.

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}
\hline
\rowcolor{popblueL}
\textbf{Fonction} & \textbf{Accès aux champs} & \textbf{Usage typique} \\
\hline
\texttt{mysqli\_fetch\_row()} & \texttt{\$ligne[0]}, \texttt{\$ligne[1]}\ldots & Rapide, mais fragile si l'ordre des champs change \\
\hline
\texttt{mysqli\_fetch\_assoc()} & \texttt{\$ligne['nom']}, \texttt{\$ligne['age']} & \textbf{Recommandé} : lisible et explicite \\
\hline
\texttt{mysqli\_fetch\_array()} & les deux formes & Polyvalent, mais redondant \\
\hline
\end{tabularx}
\end{center}

\begin{attention}[Erreur classique : mélanger les indices]
Avec \texttt{mysqli\_fetch\_row()}, les indices sont \textbf{numériques} : écrire \texttt{\$ligne['nom']} produit l'erreur \emph{Undefined array key "nom"} et affiche une chaîne vide. Réciproquement, avec \texttt{mysqli\_fetch\_assoc()}, \texttt{\$ligne[0]} n'existe pas. Choisis une fonction et reste cohérent avec ses indices. Autre piège : les clés de \texttt{fetch\_assoc} sont \textbf{sensibles à la casse} — \texttt{\$ligne['Nom']} ne vaut pas \texttt{\$ligne['nom']}.
\end{attention}

\begin{savaistu}[\texttt{fetch\_array} avec un mode]
\texttt{mysqli\_fetch\_array()} accepte un deuxième paramètre optionnel : \texttt{mysqli\_fetch\_array(\$res, MYSQLI\_ASSOC)} est \emph{strictement équivalent} à \texttt{mysqli\_fetch\_assoc(\$res)}, et \texttt{MYSQLI\_NUM} équivaut à \texttt{fetch\_row}. Au Baccalauréat, \texttt{mysqli\_fetch\_assoc()} reste la forme la plus lisible et la plus attendue par les correcteurs : privilégie-la systématiquement.
\end{savaistu}

\courssub{Le schéma canonique de parcours : la boucle \texttt{while}}

Comment afficher \emph{toutes} les lignes alors qu'on ne sait pas combien la requête en retourne ? La réponse tient en une propriété remarquable des fonctions \texttt{fetch}.

\begin{propriete}[Arrêt naturel de la boucle — admise et illustrée]
Chaque appel à une fonction \texttt{mysqli\_fetch\_*} avance le pointeur d'une ligne et retourne la ligne lue. Lorsque le pointeur a dépassé la dernière ligne, la fonction retourne \texttt{NULL}, valeur évaluée comme \textbf{faux} dans un test. Par conséquent, la boucle :
\begin{center}
\texttt{while (\$ligne = mysqli\_fetch\_assoc(\$res)) \{ ... \}}
\end{center}
s'exécute exactement une fois par ligne et \textbf{s'arrête naturellement} en fin de résultat, sans test supplémentaire.
\end{propriete}

Comprends bien la subtilité : dans la condition du \texttt{while}, il y a une \textbf{affectation} (\texttt{=}) et non une comparaison (\texttt{==}). À chaque itération, PHP appelle \texttt{mysqli\_fetch\_assoc()}, range la ligne dans \texttt{\$ligne}, puis évalue cette valeur : un tableau non vide vaut \emph{vrai}, \texttt{NULL} vaut \emph{faux}. C'est l'idiome le plus célèbre du PHP/MySQL.

\begin{methode}[Schéma canonique d'affichage d'un SELECT]
Pour afficher les résultats d'une requête de sélection, suis toujours les mêmes étapes :
\begin{enumerate}
\item Exécuter la requête : \texttt{\$res = mysqli\_query(\$cnx, \$sql);} et vérifier que \texttt{\$res} n'est pas \texttt{false}.
\item (Optionnel) Compter : \texttt{echo mysqli\_num\_rows(\$res) . ' résultat(s)';}
\item Parcourir : \texttt{while (\$l = mysqli\_fetch\_assoc(\$res)) \{ echo \$l['champ']; \}}
\item Libérer et fermer : \texttt{mysqli\_close(\$cnx);} en fin de script.
\end{enumerate}
Ce schéma en quatre temps fonctionne pour \emph{toute} requête \texttt{SELECT}, quelle que soit la table.
\end{methode}

\courssub{Affichage dans un tableau HTML généré dynamiquement}

Le débouché naturel d'un jeu de résultats est un tableau HTML : les lignes de la base deviennent des lignes \texttt{<tr>}, les champs deviennent des cellules \texttt{<td>}. La technique consiste à \textbf{ouvrir} le tableau et à écrire sa ligne d'en-tête \emph{avant} la boucle, à générer une ligne \texttt{<tr>} \emph{par itération}, puis à \textbf{fermer} le tableau \emph{après} la boucle.

\begin{exemplebox}[Liste des élèves de Terminale TI]
Le script complet ci-dessous interroge la table \texttt{eleve} et affiche les cinq élèves dans un tableau HTML bordé, précédés du nombre de résultats.
\begin{lstlisting}[language=Php]
<?php
// 1. Connexion au serveur MySQL puis choix de la base
$cnx = mysqli_connect("localhost", "root", "")
       or die("Connexion impossible : " . mysqli_connect_error());
mysqli_select_db($cnx, "lycee") or die("Base introuvable");

// 2. Execution de la requete de selection
$sql = "SELECT nom, age, moyenne FROM eleve ORDER BY nom";
$res = mysqli_query($cnx, $sql)
       or die("Erreur SQL : " . mysqli_error($cnx));

// 3. Nombre de lignes retournees
echo "<p>" . mysqli_num_rows($res) . " eleve(s) trouve(s).</p>";

// 4. Ouverture du tableau HTML et ligne d'en-tete
echo "<table border='1' cellspacing='0' cellpadding='5'>";
echo "<tr><th>Nom</th><th>Age</th><th>Moyenne</th></tr>";

// 5. Parcours canonique : une ligne HTML par enregistrement
while ($ligne = mysqli_fetch_assoc($res)) {
    echo "<tr>";
    echo "<td>" . $ligne['nom']     . "</td>";
    echo "<td>" . $ligne['age']     . "</td>";
    echo "<td>" . $ligne['moyenne'] . "</td>";
    echo "</tr>";
}

// 6. Fermeture du tableau et de la connexion
echo "</table>";
mysqli_close($cnx);
?>
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Ouvrir et fermer le tableau hors de la boucle]
Une erreur très fréquente consiste à placer \texttt{echo "<table>";} \emph{à l'intérieur} du \texttt{while} : le navigateur reçoit alors cinq tableaux d'une ligne au lieu d'un tableau de cinq lignes. Règle d'or : tout ce qui est répété va \emph{dans} la boucle (les \texttt{<tr>}), tout ce qui est unique reste \emph{dehors} (\texttt{<table>}, \texttt{<th>}, \texttt{</table>}).
\end{attention}

\begin{exoresolu}[Bulletins de la classe]
\textbf{Énoncé.} La table \texttt{eleve} de la base \texttt{lycee} contient les champs \texttt{nom}, \texttt{age} et \texttt{moyenne}. Écris un script PHP qui affiche, pour chaque élève, une ligne « Amina (17 ans) — moyenne : 14,5 », puis indique le nombre total d'élèves. Si la table est vide, le script doit afficher « Aucun élève enregistré ».
\tcblower
\textbf{Solution détaillée.} On applique le schéma canonique, en ajoutant un test sur \texttt{mysqli\_num\_rows()} pour traiter le cas vide :
\begin{lstlisting}[language=Php]
<?php
$cnx = mysqli_connect("localhost", "root", "")
       or die("Connexion impossible");
mysqli_select_db($cnx, "lycee") or die("Base introuvable");

$res = mysqli_query($cnx, "SELECT nom, age, moyenne FROM eleve")
       or die("Erreur SQL : " . mysqli_error($cnx));

if (mysqli_num_rows($res) == 0) {
    echo "Aucun eleve enregistre.";
} else {
    while ($l = mysqli_fetch_assoc($res)) {
        echo $l['nom'] . " (" . $l['age'] . " ans) - moyenne : "
             . $l['moyenne'] . "<br>";
    }
    echo "<p>Total : " . mysqli_num_rows($res) . " eleve(s).</p>";
}
mysqli_close($cnx);
?>
\end{lstlisting}
Points de vigilance : le test \texttt{== 0} se fait \emph{avant} la boucle ; \texttt{mysqli\_num\_rows()} peut être rappelé après le parcours car il ne dépend pas du pointeur ; les clés \texttt{'nom'}, \texttt{'age'}, \texttt{'moyenne'} correspondent exactement aux champs du \texttt{SELECT}.
\end{exoresolu}

\begin{experience}[TP guidé : afficher les clients d'un cybercafé]
\textbf{Objectif.} Produire une page web listant les clients enregistrés dans la base d'un cybercafé de Yaoundé.
\textbf{Logiciels.} WampServer (ou XAMPP), un navigateur, un éditeur de texte.
\begin{enumerate}
\item Lance WampServer, ouvre \texttt{phpMyAdmin} et crée la base \texttt{cybercafe} avec la table \texttt{client}(\texttt{id} INT AUTO\_INCREMENT PRIMARY KEY, \texttt{nom} VARCHAR(50), \texttt{forfait} VARCHAR(20), \texttt{solde} INT).
\item Insère au moins quatre clients (ex. « Ngo Bell », forfait « Journée », solde 500 FCFA).
\item Crée le fichier \texttt{clients.php} dans \texttt{www} et écris le script de connexion, la requête \texttt{SELECT * FROM client}, l'affichage du nombre de clients, puis le tableau HTML bordé avec les colonnes Nom, Forfait, Solde.
\item Ouvre \texttt{http://localhost/clients.php} et vérifie que le nombre affiché correspond aux lignes du tableau.
\item \textbf{Manipulation.} Ajoute un client via phpMyAdmin, recharge la page : le tableau s'allonge \emph{sans modifier le code}. C'est toute la puissance de la génération dynamique.
\item \textbf{Interprétation.} Supprime tous les clients : que se passe-t-il ? Ajoute le test \texttt{mysqli\_num\_rows() == 0} pour afficher un message propre.
\end{enumerate}
\end{experience}

\begin{exercice}[Recherche par filière]
La table \texttt{eleve} possède un champ \texttt{filiere}. Écris un script qui n'affiche que les élèves de la filière « TI » dans un tableau HTML, avec leur nombre. Que se passe-t-il si aucun élève n'est en TI ? Propose une solution élégante.
\end{exercice}

\begin{corrige}[Exercice : recherche par filière]
On ajoute une clause \texttt{WHERE} à la requête, puis on teste le nombre de lignes avant d'ouvrir le tableau :
\begin{lstlisting}[language=Php]
<?php
$cnx = mysqli_connect("localhost", "root", "") or die("Connexion impossible");
mysqli_select_db($cnx, "lycee") or die("Base introuvable");

$res = mysqli_query($cnx, "SELECT nom, age FROM eleve WHERE filiere='TI'")
       or die("Erreur SQL : " . mysqli_error($cnx));

$nb = mysqli_num_rows($res);
if ($nb == 0) {
    echo "Aucun eleve en filiere TI.";
} else {
    echo "<p>$nb eleve(s) en TI.</p>";
    echo "<table border='1'><tr><th>Nom</th><th>Age</th></tr>";
    while ($l = mysqli_fetch_assoc($res)) {
        echo "<tr><td>" . $l['nom'] . "</td><td>" . $l['age'] . "</td></tr>";
    }
    echo "</table>";
}
mysqli_close($cnx);
?>
\end{lstlisting}
Sans le test, un résultat vide produirait un tableau HTML réduit à sa seule ligne d'en-tête — d'où l'intérêt du message alternatif.
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Un \texttt{SELECT} retourne un \cle{jeu de résultats} : un tableau de lignes parcouru par un pointeur interne.
\item \texttt{mysqli\_num\_rows(\$res)} donne le nombre de lignes ; \texttt{mysqli\_fetch\_assoc(\$res)} retourne la ligne courante en tableau associatif et avance le pointeur ; \texttt{NULL} signale la fin.
\item Le schéma canonique \texttt{while (\$l = mysqli\_fetch\_assoc(\$res)) \{ ... \}} parcourt toutes les lignes sans connaître leur nombre à l'avance.
\item Pour un tableau HTML : ouverture et en-tête \emph{avant} la boucle, un \texttt{<tr>} par itération, fermeture \emph{après}.
\end{itemize}
Tu maîtrises désormais la chaîne complète « requête $\rightarrow$ résultat $\rightarrow$ affichage ». Il ne reste qu'à assembler toutes les briques dans la synthèse : une mini-application web PHP/MySQL complète.
\end{aretenir}

\courssub{Le cahier des charges : une application CRUD}

\begin{definition}[Application CRUD]
Une \cle{application CRUD} est une application qui permet les quatre opérations fondamentales sur les données d'une base :
\begin{itemize}
\item \textbf{C}reate : créer un enregistrement (requête \texttt{INSERT}) ;
\item \textbf{R}ead : lire et afficher les enregistrements (requête \texttt{SELECT}) ;
\item \textbf{U}pdate : modifier un enregistrement existant (requête \texttt{UPDATE}) ;
\item \textbf{D}elete : supprimer un enregistrement (requête \texttt{DELETE}).
\end{itemize}
\end{definition}

Notre mini-application « Gestion des candidats » devra permettre à un secrétaire de :
\begin{enumerate}
\item \textbf{ajouter} un candidat (nom, prénom, série, moyenne) via un formulaire ;
\item \textbf{lister} tous les candidats dans un tableau HTML ;
\item \textbf{modifier} les informations d'un candidat via un formulaire pré-rempli ;
\item \textbf{supprimer} un candidat après confirmation.
\end{enumerate}

La base de données s'appellera \texttt{concours} et contiendra une seule table \texttt{candidats} :

\begin{lstlisting}[language=SQL]
CREATE DATABASE IF NOT EXISTS concours;
USE concours;

CREATE TABLE candidats (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nom VARCHAR(50) NOT NULL,
    prenom VARCHAR(50) NOT NULL,
    serie VARCHAR(10) NOT NULL,
    moyenne DECIMAL(4,2) NOT NULL,
    date_inscription DATETIME DEFAULT CURRENT_TIMESTAMP
);
\end{lstlisting}

Observe la ligne des liens : pour le candidat d'\texttt{id} égal à 3, PHP génère le HTML \texttt{<a href='supprimer.php?id=3'>Supprimer</a>}. C'est le mécanisme clé qui lie l'interface (HTML) à la logique métier (PHP/SQL).

\courssub{Ajout, suppression et modification}

\textbf{ajout.php} regroupe l'affichage du formulaire (méthode GET) et son traitement (méthode POST) dans un même fichier. On teste \texttt{\$\_SERVER["REQUEST\_METHOD"]} pour distinguer les deux phases.

\begin{lstlisting}[language=Php]
<?php
require "connexion.php";

// Traitement du formulaire (méthode POST)
if ($_SERVER["REQUEST_METHOD"] === "POST") {
    // Récupération et nettoyage basique
    $nom     = trim($_POST["nom"]);
    $prenom  = trim($_POST["prenom"]);
    $serie   = trim($_POST["serie"]);
    $moyenne = (float) $_POST["moyenne"]; // cast numérique

    // Requête paramétrée idéale en pro ; ici concaténation pour niveau Terminale
    $sql = "INSERT INTO candidats (nom, prenom, serie, moyenne)
            VALUES ('$nom', '$prenom', '$serie', $moyenne)";
    mysqli_query($conn, $sql)
        or die("Erreur INSERT : " . mysqli_error($conn));

    header("Location: index.php"); // PRG pattern : Post-Redirect-Get
    exit;
}
?>

<html lang="fr">
<head><meta charset="utf-8"><title>Ajout candidat</title></head>
<body>
<h1>Nouveau candidat</h1>
<form method="post" action="ajout.php">
    Nom : <input type="text" name="nom" required><br><br>
    Prenom : <input type="text" name="prenom" required><br><br>
    Serie : <input type="text" name="serie" required><br><br>
    Moyenne : <input type="number" step="0.01" name="moyenne" required><br><br>
    <input type="submit" value="Enregistrer">

\textbf{supprimer.php} est concis : il valide la présence de l'identifiant, le caste en entier (sécurité), exécute le \texttt{DELETE} et redirige vers la liste.

\begin{lstlisting}[language=Php]
<?php
require "connexion.php";

// Sécurité : l'id existe-t-il et est-il numérique ?
if (isset($_GET["id"])) {
    $id = (int) $_GET["id"]; // conversion en entier (neutralise injections)
    $sql = "DELETE FROM candidats WHERE id = $id";
    mysqli_query($conn, $sql)
        or die("Erreur DELETE : " . mysqli_error($conn));
}
// Redirection systématique (même si id absent)
header("Location: index.php");
exit;
?>
\end{lstlisting}

\textbf{modifier.php} combine les deux techniques : d'abord un \texttt{SELECT ... WHERE id = ...} pour pré-remplir le formulaire avec les valeurs actuelles (arrivée par GET), puis un \texttt{UPDATE} quand le formulaire est soumis (envoi par POST).

\begin{lstlisting}[language=Php]
<?php
require "connexion.php";

// --- CAS 1 : Soumission du formulaire de modification (POST) ---
if ($_SERVER["REQUEST_METHOD"] === "POST" && isset($_POST["id"])) {
    $id      = (int) $_POST["id"];
    $nom     = trim($_POST["nom"]);
    $prenom  = trim($_POST["prenom"]);
    $serie   = trim($_POST["serie"]);
    $moyenne = (float) $_POST["moyenne"];

    $sql = "UPDATE candidats
            SET nom='$nom', prenom='$prenom',
                serie='$serie', moyenne=$moyenne
            WHERE id=$id";
    mysqli_query($conn, $sql)
        or die("Erreur UPDATE : " . mysqli_error($conn));

    header("Location: index.php");
    exit;
}

// --- CAS 2 : Arrivée sur la page via lien (GET) : pré-remplissage ---
if (isset($_GET["id"])) {
    $id = (int) $_GET["id"];
    $res = mysqli_query($conn,
        "SELECT * FROM candidats WHERE id = $id")
        or die("Erreur SELECT : " . mysqli_error($conn));
    $c = mysqli_fetch_assoc($res);

    // Vérification cruciale : le candidat existe-t-il ?
    if (!$c) {
        die("Candidat introuvable (id=$id).");
    }
} else {
    die("Aucun candidat précisé.");
}
?>
<!DOCTYPE html>
<html lang="fr">
<head><meta charset="utf-8"><title>Modifier candidat</title></head>
<body>
<h1>Modifier le candidat #<?php echo $c["id"]; ?></h1>
<form method="post" action="modifier.php">
    <!-- Champ caché : l'id voyage avec le formulaire sans être visible -->
    <input type="hidden" name="id" value="<?php echo $c["id"]; ?>">
    
    Nom : <input type="text" name="nom" 
           value="<?php echo htmlspecialchars($c["nom"]); ?>" required><br><br>
    Prenom : <input type="text" name="prenom" 
           value="<?php echo htmlspecialchars($c["prenom"]); ?>" required><br><br>
    Serie : <input type="text" name="serie" 
           value="<?php echo htmlspecialchars($c["serie"]); ?>" required><br><br>
    Moyenne : <input type="number" step="0.01" name="moyenne" 
           value="<?php echo $c["moyenne"]; ?>" required><br><br>
    <input type="submit" value="Mettre a jour">
    <a href="index.php">Annuler</a>
</form>
</body>
</html>
\end{lstlisting}

Remarque le champ caché \texttt{<input type="hidden" name="id" ...>} : il permet de transmettre l'identifiant au moment de la soumission POST, sans que l'utilisateur puisse le modifier facilement. C'est un classique du développement web. Note aussi l'usage de \texttt{htmlspecialchars()} dans les attributs \texttt{value} : cela protège l'affichage si les données contiennent des guillemets ou des caractères spéciaux.

\begin{attention}[Faille d'injection SQL — Rappel vital]
Concaténer directement \texttt{\$\_POST["nom"]} dans une requête, comme ci-dessus pour rester lisible au niveau Terminale, expose l'application aux \cle{injections SQL} : un utilisateur malveillant peut taper \texttt{' OR '1'='1} dans le formulaire et modifier/supprimer toute la table. En production, on utilise \textbf{les requêtes préparées} (\texttt{mysqli\_prepare}, \texttt{bind\_param}, \texttt{execute}) qui séparent le code SQL des données. Retiens l'idée : \emph{jamais confiance aveugle aux données venant de l'utilisateur}.
\end{attention}

\courssub{Horodatage avec date() et stratégie de débogage}

La fonction \texttt{date()} vue précédemment trouve ici une application naturelle : afficher en pied de page l'heure de génération de la liste, ou tracer les opérations dans un journal (fichier log).

\begin{lstlisting}[language=Php]
// Dans index.php, avant </body> par exemple
echo "<p style='text-align:center; color:gray; margin-top:20px;'>";
echo "Liste générée le " . date("d/m/Y") . " à " . date("H:i:s");
echo "</p>";
// Affiche : Liste générée le 14/03/2025 à 09:42:17
\end{lstlisting}

Pour les tests et le débogage, la démarche professionnelle est double :
\begin{itemize}
\item \textbf{Côté PHP} : chaque \texttt{mysqli\_query()} est suivi de \texttt{or die(mysqli\_error(\$conn))} pour afficher le message d'erreur exact de MySQL (syntaxe, contrainte, droit) au lieu d'une page blanche muette.
\item \textbf{Côté phpMyAdmin} : après chaque ajout, modification ou suppression, on ouvre la table \texttt{candidats} dans phpMyAdmin (onglet \emph{Parcourir}) pour vérifier visuellement que l'opération a bien eu lieu et que les données sont cohérentes.
\end{itemize}

\begin{methode}[Démarche de construction d'une application CRUD]
\begin{enumerate}
\item Créer la base et la table dans phpMyAdmin (ou par script SQL exécuté une fois).
\item Écrire \texttt{connexion.php} et le tester seul (page blanche = OK, message d'erreur = correction).
\item Écrire la liste : \texttt{SELECT} + boucle \texttt{while} dans \texttt{index.php}. Tester avec les données de test.
\item Ajouter l'insertion : formulaire + \texttt{INSERT} dans \texttt{ajout.php}. Tester l'ajout et vérifier dans phpMyAdmin.
\item Ajouter la modification (\texttt{SELECT} de pré-remplissage + \texttt{UPDATE}) dans \texttt{modifier.php}. Tester.
\item Ajouter la suppression (\texttt{DELETE} via \texttt{\$\_GET}) dans \texttt{supprimer.php}. Tester.
\item \textbf{À chaque étape} : tester immédiatement dans le navigateur ET dans phpMyAdmin avant de passer à la suivante.
\end{enumerate}
\end{methode}

\begin{savaistu}[Des petits fichiers aux grands frameworks]
Cette architecture en petits fichiers spécialisés (\texttt{index}, \texttt{ajout}, \texttt{modifier}, \texttt{supprimer} partageant \texttt{connexion.php}) est l'ancêtre direct des \cle{frameworks} modernes comme Laravel, Symfony ou CodeIgniter, qui organisent le code selon le motif architectural MVC (Modèle-Vue-Contrôleur). Les développeurs camerounais qui conçoivent des plateformes de paiement mobile (API MTN MoMo, Orange Money), des applications de gestion pour les PME de Douala ou des portails administratifs (impots.cm, ANTIC) utilisent ces frameworks quotidiennement — mais la logique CRUD que tu viens de construire à la main reste exactement la même sous le capot. Maîtriser ce « PHP natif », c'est comprendre ce que le framework automatise pour toi.
\end{savaistu}

\begin{aretenir}[L'essentiel de la synthèse]
\begin{itemize}
\item Une application CRUD couvre les quatre opérations de base : \texttt{INSERT}, \texttt{SELECT}, \texttt{UPDATE}, \texttt{DELETE}.
\item On découpe le projet en fichiers spécialisés partageant un \texttt{connexion.php} inclus par \texttt{require} (factorisation, maintenance).
\item L'identifiant d'un enregistrement voyage par l'URL (\texttt{?id=3}, lu dans \texttt{\$\_GET}) pour les liens (suppression, édition) ou par un champ caché \texttt{<input type="hidden">} (lu dans \texttt{\$\_POST}) pour les formulaires de modification.
\item Le formulaire de modification est pré-rempli grâce à un \texttt{SELECT ... WHERE id = ...} exécuté à l'arrivée sur la page (GET).
\item Toujours tester \texttt{isset(\$\_GET['id'])} / \texttt{isset(\$\_POST['...'])} avant usage, caster les identifiants en \texttt{(int)}, et vérifier chaque opération dans phpMyAdmin.
\item \texttt{htmlspecialchars()} dans les \texttt{value} des inputs protège l'affichage (XSS basique) ; les requêtes préparées protègent la base (SQLi).
\end{itemize}
\end{aretenir}

\courssub{Ressources à mobiliser}

\begin{aretenir}[Boîte à outils de la leçon]
\begin{itemize}
\item \textbf{Structures de contrôle} : \texttt{if / elseif / else} pour les conditions (contrôle de l'année de naissance), \texttt{switch} pour les cas multiples (couleur selon l'épreuve), \texttt{while} pour parcourir un résultat de requête.
\item \textbf{Fonction \texttt{date()}} : \texttt{date('Y-m-d')} retourne la date du jour au format SQL ; \texttt{date('Y', strtotime(\$d))} extrait l'année d'une date.
\item \textbf{Connexion} : \texttt{\$cnx = mysqli\_connect(hote, user, mdp) or die(...)} puis \texttt{mysqli\_select\_db(\$cnx, 'base') or die(...)}.
\item \textbf{Exécution} : \texttt{\$res = mysqli\_query(\$cnx, \$sql)} ; pour un \texttt{SELECT}, \texttt{mysqli\_num\_rows(\$res)} donne le nombre de lignes.
\item \textbf{Lecture} : \texttt{while (\$ligne = mysqli\_fetch\_assoc(\$res))} donne un tableau associatif par ligne.
\item \textbf{Requêtes} : \texttt{INSERT INTO ... VALUES}, \texttt{SELECT ... FROM}, \texttt{UPDATE ... SET ... WHERE id=...}, \texttt{DELETE FROM ... WHERE id=...} — la clause \texttt{WHERE} est \emph{indispensable} pour ne modifier ou supprimer qu'une seule ligne.
\item \textbf{Fermeture} : \texttt{mysqli\_close(\$cnx)} en fin de script.
\end{itemize}
\end{aretenir}

\begin{attention}[Pièges fréquents rencontrés pendant l'activité]
\begin{itemize}
\item Oublier le \texttt{WHERE} dans \texttt{UPDATE} ou \texttt{DELETE} : \textbf{toute la table} est alors modifiée ou vidée. C'est l'erreur la plus grave de l'activité.
\item Comparer la date de naissance entière à 2005 au lieu d'en extraire l'année avec \texttt{date('Y', strtotime(...))}.
\item Concaténer \texttt{\$\_GET['id']} directement dans la requête sans vérification : c'est une porte ouverte à l'\cle{injection SQL}. En production, on filtrerait avec \texttt{(int)} ou des requêtes préparées.
\item Oublier \texttt{exit;} après \texttt{header("Location: ...")} : le script continue de s'exécuter.
\end{itemize}
\end{attention}

\courssub{Structures alternatives : if, else, elseif, switch}

\begin{methode}[Choisir et rédiger une structure de contrôle PHP]
\begin{enumerate}
\item \textbf{Identifier le type de décision} : une condition unique (\texttt{if}), deux cas exclusifs (\texttt{if...else}), plusieurs cas fondés sur des comparaisons (\texttt{if...elseif...else}), ou plusieurs cas fondés sur \emph{une seule valeur} (\texttt{switch}).
\item \textbf{Écrire la condition avec les bons opérateurs} : comparaison \texttt{==} (égalité de valeur), \texttt{===} (égalité de valeur et de type), \texttt{!=}, \texttt{<}, \texttt{<=}, \texttt{>}, \texttt{>=} ; logique \texttt{\&\&} (ET), \texttt{||} (OU), \texttt{!} (NON).
\item \textbf{Ouvrir et fermer systématiquement les accolades} \texttt{\{ \}} dès la rédaction, même pour une seule instruction, et indenter le bloc de 4 espaces.
\item \textbf{Pour un \texttt{switch}} : un \texttt{case} par valeur possible, un \texttt{break;} à la fin de chaque cas pour éviter la chute en cascade, et un \texttt{default:} pour traiter les valeurs imprévues.
\item \textbf{Tester mentalement} le script avec des valeurs limites (borne inférieure, borne supérieure, cas d'erreur, valeur \texttt{null}).
\end{enumerate}
\end{methode}

\begin{exemplebox}[Structure \texttt{switch} : menu d'une application de gestion de notes]
Le \texttt{switch} est idéal pour tester une variable contre une liste de valeurs constantes (entiers, chaînes). Ici, le choix d'un menu principal.
\begin{lstlisting}[language=Php]
<?php
    $choix = "moyenne"; // Valeur simulée, en pratique issue de \$_GET ou \$_POST

    switch ($choix) {
        case "saisie":
            echo "Affichage du formulaire de saisie des notes.";
            break;
        case "moyenne":
            echo "Calcul et affichage de la moyenne de la classe.";
            break;
        case "bulletin":
            echo "Génération du bulletin PDF.";
            break;
        default:
            echo "Option inconnue : " . htmlspecialchars($choix);
            break;
    }
?>
\end{lstlisting}
\emph{Remarque :} \texttt{htmlspecialchars()} protège contre les failles XSS si \texttt{\$choix} provient de l'utilisateur.
\end{exemplebox}

\begin{exoresolu}[Moyenne et mention d'un candidat au BEPC]
Une école de Yaoundé veut automatiser l'affichage des mentions au BEPC. Écrire un script PHP qui, à partir d'une moyenne stockée dans la variable \texttt{\$moy}, affiche : « Refusé » si la moyenne est strictement inférieure à 10 ; « Passable » si elle est comprise entre 10 et 11,99 ; « Assez Bien » entre 12 et 13,99 ; « Bien » entre 14 et 15,99 ; « Très Bien » à partir de 16. Le script affichera ensuite la liste des 5 premiers numéros de table à l'aide d'une boucle.
\tcblower
\textbf{Raisonnement.} Il s'agit de plusieurs cas fondés sur des \emph{intervalles} (comparaisons), donc la structure adaptée est \texttt{if...elseif...else} et non \texttt{switch} (qui ne teste que l'égalité à une valeur). Les bornes doivent être testées dans l'ordre décroissant pour éviter les chevauchements (une moyenne de 16 validerait aussi \texttt{>= 14} si l'ordre était croissant). Pour la liste des numéros, le nombre d'itérations est connu (5) : on utilise \texttt{for}.

\begin{lstlisting}[language=Php]
<?php
    $moy = 13.5; // moyenne du candidat sur 20

    // Structure alternative : tests dans l'ordre decroissant
    if ($moy >= 16) {
        echo "Mention : Tres Bien<br>";
    } elseif ($moy >= 14) {
        echo "Mention : Bien<br>";
    } elseif ($moy >= 12) {
        echo "Mention : Assez Bien<br>";
    } elseif ($moy >= 10) {
        echo "Mention : Passable<br>";
    } else {
        echo "Mention : Refuse<br>";
    }

    // Structure repetitive : nombre d'iterations connu
    for ($i = 1; $i <= 5; $i++) {
        echo "Numero de table : " . $i . "<br>";
    }
?>
\end{lstlisting}

\textbf{Vérification.} Avec \texttt{\$moy = 13.5} : le test \texttt{\$moy >= 16} est faux, \texttt{\$moy >= 14} est faux, \texttt{\$moy >= 12} est vrai $\Rightarrow$ affichage « Mention : Assez Bien », ce qui est correct car $12 \leq 13{,}5 < 14$. La boucle affiche les numéros 1, 2, 3, 4, 5 puis s'arrête car la condition \texttt{\$i <= 5} devient fausse pour \texttt{\$i = 6}.

\textbf{Conclusion.} Le script affiche « Mention : Assez Bien » suivi des cinq numéros de table. L'ordre décroissant des tests garantit qu'aucune moyenne ne tombe dans deux cas à la fois.
\end{exoresolu}

\courssub{Structures répétitives : for, foreach, while, do...while}

\begin{methode}[Choisir et rédiger une structure répétitive PHP]
\begin{enumerate}
\item \textbf{Identifier le type de répétition} :
  \begin{itemize}
  \item Nombre d'itérations connu à l'avance $\Rightarrow$ \texttt{for} (ex. afficher 10 lignes).
  \item Parcours d'un tableau ou d'un jeu de résultats $\Rightarrow$ \texttt{foreach} (plus lisible, pas de gestion d'index).
  \item Condition d'arrêt basée sur une expression booléenne, test \emph{avant} la première itération $\Rightarrow$ \texttt{while} (ex. lire un fichier tant que non fin).
  \item Condition d'arrêt, test \emph{après} la première itération (au moins une exécution garantie) $\Rightarrow$ \texttt{do...while} (ex. menu interactif, saisie utilisateur).
  \end{itemize}
\item \textbf{Initialiser, tester, incrémenter} : pour \texttt{for}, vérifier l'initialisation (\texttt{\$i=0} ou \texttt{1}), la condition de continuation (\texttt{\$i < \$n} ou \texttt{\$i <= \$n}) et l'incrémentation (\texttt{\$i++}).
\item \textbf{Éviter les boucles infinies} : s'assurer que la condition de sortie devient \texttt{false} à un moment (variable modifiée dans le corps de la boucle).
\end{enumerate}
\end{methode}

\begin{exemplebox}[Boucle \texttt{foreach} : parcours d'un tableau d'élèves]
Le \texttt{foreach} est la structure privilégiée pour parcourir les tableaux associatifs (résultats de BDD, formulaires).
\begin{lstlisting}[language=Php]
<?php
    $eleves = [
        "24G001" => "Abena",
        "24G002" => "Biya",
        "24G003" => "Essomba"
    ];

    echo "<ul>";
    foreach ($eleves as $matricule => $nom) {
        echo "<li>[$matricule] $nom</li>";
    }
    echo "</ul>";
?>
\end{lstlisting}
\end{exemplebox}

\begin{exemplebox}[Boucle \texttt{do...while} : saisie contrôlée (simulation)]
Utile pour imposer au moins une exécution, par exemple pour valider une saisie utilisateur (ici simulée).
\begin{lstlisting}[language=Php]
<?php
    $note = -1; // Initialisation invalide pour forcer l'entree dans la boucle
    do {
        // En reel : $note = (float)readline("Note (0-20) : ");
        $note = 15; // Simulation d'une saisie valide
        if ($note < 0 || $note > 20) {
            echo "Note invalide, recommencez.<br>";
        }
    } while ($note < 0 || $note > 20);
    echo "Note valide enregistree : $note";
?>
\end{lstlisting}
\end{exemplebox}

\courssub{La fonction date()}

\begin{methode}[Afficher une date ou une heure avec \texttt{date()}]
\begin{enumerate}
\item \textbf{Retenir la syntaxe générale} : \texttt{date("format")} renvoie une \emph{chaîne de caractères} représentant la date/heure courante du \emph{serveur}.
\item \textbf{Mémoriser les codes de format essentiels} :
  \begin{center}
  \begin{tabularx}{\linewidth}{|l|X|l|X|}\hline
  \textbf{Code} & \textbf{Signification} & \textbf{Code} & \textbf{Signification} \\\hline
  \texttt{d} & Jour sur 2 chiffres (01--31) & \texttt{Y} & Année sur 4 chiffres (2025) \\\hline
  \texttt{m} & Mois sur 2 chiffres (01--12) & \texttt{H} & Heure 24h (00--23) \\\hline
  \texttt{i} & Minutes (00--59) & \texttt{s} & Secondes (00--59) \\\hline
  \texttt{l} & Nom du jour (anglais) & \texttt{w} & Indice jour (0=Dim...6=Sam) \\\hline
  \end{tabularx}
  \end{center}
\item \textbf{Composer le format} avec des séparateurs libres : \texttt{date("d/m/Y H:i:s")} donne \texttt{12/05/2025 14:30:05}.
\item \textbf{Pour comparer des dates} (ex. majorité), extraire l'année avec \texttt{date("Y")} (retourne chaîne, conversion auto en entier) ou utiliser \texttt{strtotime()} pour des calculs précis.
\item \textbf{Attention au fuseau horaire} : par défaut UTC. En local (WampServer), configurer \texttt{date.timezone = Africa/Douala} dans \texttt{php.ini} ou appeler \texttt{date\_default\_timezone\_set("Africa/Douala");} en début de script.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Contrôle d'âge sur une plateforme d'inscription]
Une startup camerounaise de e-learning n'accepte que les élèves âgés d'au moins 15 ans. Écrire un script PHP qui affiche la date du jour au format \texttt{jj/mm/aaaa}, calcule l'âge d'un élève né en 2007 et affiche « Inscription autorisée » ou « Inscription refusée ».
\tcblower
\textbf{Raisonnement.} On récupère l'année courante avec \texttt{date("Y")}, qui renvoie une chaîne ; PHP la convertit automatiquement en entier lors de la soustraction. L'âge approché est $\text{année courante} - \text{année de naissance}$. On compare ensuite cet âge à 15 avec un \texttt{if...else}.

\begin{lstlisting}[language=Php]
<?php
    date_default_timezone_set("Africa/Douala"); // Bonne pratique

    // 1. Affichage de la date du jour
    echo "Nous sommes le " . date("d/m/Y") . "<br>";

    // 2. Calcul de l'age
    $anneeNaissance = 2007;
    $anneeCourante = (int)date("Y"); // Cast explicite pour clarete
    $age = $anneeCourante - $anneeNaissance; // 2025 - 2007 = 18

    echo "Age de l'eleve : " . $age . " ans<br>";

    // 3. Decision
    if ($age >= 15) {
        echo "Inscription autorisee";
    } else {
        echo "Inscription refusee";
    }
?>
\end{lstlisting}

\textbf{Vérification.} Si la date du serveur est le 12/05/2025 : la première ligne affiche « Nous sommes le 12/05/2025 » ; l'âge calculé vaut $2025 - 2007 = 18$ ; comme $18 \geq 15$, le test est vrai et le script affiche « Inscription autorisée ».

\textbf{Conclusion.} Le script affiche la date du jour, l'âge de 18 ans et le message « Inscription autorisée ». (En production, on comparerait les dates complètes jour/mois pour un âge exact au jour près.)
\end{exoresolu}

\courssub{Connexion à MySQL avec l'extension mysqli}

\begin{propriete}[Fonctions mysqli essentielles (style procédural)]
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}\hline
\textbf{Fonction} & \textbf{Rôle} \\\hline
\texttt{mysqli\_connect(hote, user, mdp, [base], [port])} & Ouvre une connexion, retourne un objet \texttt{\$cnx} ou \texttt{false}. \\\hline
\texttt{mysqli\_select\_db(\$cnx, "nom\_base")} & Sélectionne la base de données courante. Retourne \texttt{true/false}. \\\hline
\texttt{mysqli\_query(\$cnx, \$sql)} & Exécute une requête. Retourne : \texttt{false} (échec), \texttt{true} (INSERT/UPDATE/DELETE OK), ou objet résultat (SELECT OK). \\\hline
\texttt{mysqli\_fetch\_assoc(\$res)} & Retourne la ligne suivante en tableau associatif \texttt{\$ligne["champ"]}, ou \texttt{false} si fin. \\\hline
\texttt{mysqli\_fetch\_row(\$res)} & Retourne la ligne suivante en tableau indexé \texttt{\$ligne[0]}, \texttt{\$ligne[1]}... \\\hline
\texttt{mysqli\_fetch\_array(\$res)} & Retourne les deux (indices numériques + associatifs). \\\hline
\texttt{mysqli\_num\_rows(\$res)} & Retourne le nombre de lignes d'un résultat SELECT. \\\hline
\texttt{mysqli\_close(\$cnx)} & Ferme la connexion, libère les ressources serveur. \\\hline
\texttt{mysqli\_real\_escape\_string(\$cnx, \$str)} & Échappe les caractères spéciaux (protection injection SQL). \\\hline
\texttt{die(message)} & Affiche \texttt{message} et \emph{arrête immédiatement} le script. \\\hline
\end{tabularx}
\end{center}
\end{propriete}

\begin{methode}[Établir une connexion PHP--MySQL en 4 étapes (Squelette Bac)]
\begin{enumerate}
\item \textbf{Ouvrir la connexion} au serveur : \texttt{\$cnx = mysqli\_connect("localhost", "root", "");} (WampServer par défaut).
\item \textbf{Sécuriser avec \texttt{die()}} : tester la connexion et arrêter le script proprement en cas d'échec : \texttt{if (!\$cnx) \{ die("..."); \}} ou forme idiomatique \texttt{\$cnx = ... or die("...");}.
\item \textbf{Sélectionner la base} : \texttt{mysqli\_select\_db(\$cnx, "nom\_base") or die("Base introuvable");}.
\item \textbf{Fermer la connexion} en fin de script : \texttt{mysqli\_close(\$cnx);}.
\end{enumerate}
\textbf{Réflexe Bac :} Une connexion correcte contient toujours ces 4 appels, dans cet ordre : \texttt{connect} $\to$ test \texttt{die} $\to$ \texttt{select\_db} $\to$ (requêtes) $\to$ \texttt{close}.
\end{methode}

\begin{exoresolu}[Connexion à la base d'un cybercafé]
Le gérant d'un cybercafé de Douala veut connecter son site à la base MySQL \texttt{cybercafe} hébergée en local (utilisateur \texttt{root}, mot de passe vide). Écrire le script PHP de connexion complet, avec gestion des erreurs, qui affiche « Connexion réussie à la base cybercafe ».
\tcblower
\textbf{Raisonnement.} On applique la démarche en 4 étapes : connexion au serveur, arrêt contrôlé en cas d'échec grâce à \texttt{die()}, sélection de la base, puis fermeture. La fonction \texttt{die()} affiche un message et \emph{stoppe immédiatement} l'exécution du script, ce qui évite d'exécuter des requêtes sur une connexion inexistante.

\begin{lstlisting}[language=Php]
<?php
    // Etape 1 : connexion au serveur MySQL
    $cnx = mysqli_connect("localhost", "root", "");

    // Etape 2 : gestion de l'erreur de connexion
    if (!$cnx) {
        die("Echec de connexion au serveur MySQL : " . mysqli_connect_error());
    }

    // Etape 3 : selection de la base de donnees
    $base = mysqli_select_db($cnx, "cybercafe");
    if (!$base) {
        die("Base de donnees introuvable : " . mysqli_error($cnx));
    }

    echo "Connexion reussie a la base cybercafe";

    // Etape 4 : fermeture de la connexion
    mysqli_close($cnx);
?>
\end{lstlisting}

\textbf{Vérification.} Si WampServer est démarré et que la base \texttt{cybercafe} existe, \texttt{mysqli\_connect} renvoie un objet connexion (valeur vraie), le test \texttt{!\$cnx} est faux, la sélection réussit et le message de succès s'affiche. Si MySQL est arrêté, \texttt{\$cnx} vaut \texttt{false} et \texttt{die()} affiche l'erreur puis stoppe le script.

\textbf{Conclusion.} Le script établit une connexion sécurisée en 4 étapes et affiche « Connexion réussie à la base cybercafe » ; toute défaillance est interceptée par \texttt{die()}.
\end{exoresolu}

\courssub{Exécution des requêtes SQL depuis PHP : INSERT, UPDATE, DELETE}

\begin{methode}[Envoyer une requête de manipulation (INSERT, UPDATE, DELETE) depuis PHP]
\begin{enumerate}
\item \textbf{Écrire la requête SQL} dans une chaîne PHP. Règle d'or : les valeurs textuelles et les dates sont entre apostrophes \texttt{'...'}, les nombres sans apostrophe. Les noms de tables/champs sans guillemets (ou backticks \texttt{\`} si mots-clés).
\item \textbf{Protéger les données utilisateur} : \textbf{impératif} avant d'insérer des variables dans le SQL. Utiliser \texttt{mysqli\_real\_escape\_string(\$cnx, \$variable)} sur chaque variable d'origine externe (\texttt{\$\_POST}, \texttt{\$\_GET}).
\item \textbf{Envoyer la requête} : \texttt{\$res = mysqli\_query(\$cnx, \$sql);}. Pour INSERT/UPDATE/DELETE, \texttt{\$res} vaut \texttt{true} (succès) ou \texttt{false} (échec) — \emph{pas} un jeu de résultats.
\item \textbf{Tester le résultat} avec \texttt{if (\$res)} ou \texttt{or die(...)}.
\item \textbf{Vérifier la syntaxe SQL} :
  \begin{itemize}
  \item \texttt{INSERT INTO table (champs) VALUES (valeurs);}
  \item \texttt{UPDATE table SET champ = valeur WHERE condition;}
  \item \texttt{DELETE FROM table WHERE condition;}
  \end{itemize}
\item \textbf{Ne jamais oublier la clause \texttt{WHERE}} dans UPDATE et DELETE, sous peine de modifier ou supprimer \emph{toute} la table.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Gestion des abonnés d'un cybercafé]
Dans la base \texttt{cybercafe}, la table \texttt{abonne(id, nom, forfait, solde)} contient les abonnés. Écrire un script PHP qui : (a) insère l'abonné \texttt{(1, 'Kamga', 'Mensuel', 5000)} ; (b) passe le solde de Kamga à 3000 ; (c) supprime l'abonné d'\texttt{id} égal à 4. Chaque opération doit confirmer son succès.
\tcblower
\textbf{Raisonnement.} Les trois opérations sont des requêtes de \emph{manipulation} : elles ne renvoient pas de lignes, seulement un booléen. On écrit chaque requête dans une variable \texttt{\$sql}, on l'exécute avec \texttt{mysqli\_query} et on teste le résultat. Les clauses \texttt{WHERE} ciblent précisément les lignes concernées.

\begin{lstlisting}[language=Php]
<?php
    $cnx = mysqli_connect("localhost", "root", "")
           or die("Echec de connexion : " . mysqli_connect_error());
    mysqli_select_db($cnx, "cybercafe")
           or die("Base introuvable : " . mysqli_error($cnx));

    // (a) Insertion : texte entre apostrophes, nombres sans
    $sql1 = "INSERT INTO abonne (id, nom, forfait, solde)
             VALUES (1, 'Kamga', 'Mensuel', 5000)";
    if (mysqli_query($cnx, $sql1)) {
        echo "Abonne insere avec succes<br>";
    } else {
        echo "Echec de l'insertion : " . mysqli_error($cnx) . "<br>";
    }

    // (b) Modification : WHERE obligatoire pour cibler Kamga
    $sql2 = "UPDATE abonne SET solde = 3000 WHERE nom = 'Kamga'";
    if (mysqli_query($cnx, $sql2)) {
        echo "Solde mis a jour<br>";
    } else {
        echo "Echec MAJ : " . mysqli_error($cnx) . "<br>";
    }

    // (c) Suppression : WHERE obligatoire pour cibler l'id 4
    $sql3 = "DELETE FROM abonne WHERE id = 4";
    if (mysqli_query($cnx, $sql3)) {
        echo "Abonne supprime<br>";
    } else {
        echo "Echec suppression : " . mysqli_error($cnx) . "<br>";
    }

    mysqli_close($cnx);
?>
\end{lstlisting}

\textbf{Vérification.} (a) La requête insère une ligne ; \texttt{mysqli\_query} renvoie \texttt{true} $\Rightarrow$ « Abonne insere avec succes ». (b) Seule la ligne où \texttt{nom = 'Kamga'} est modifiée : le solde passe de 5000 à 3000. (c) Seule la ligne \texttt{id = 4} est supprimée ; les autres abonnés sont conservés.

\textbf{Conclusion.} Le script réalise les trois manipulations (insertion, modification, suppression) en confirmant chaque succès, grâce à des requêtes SQL correctement ciblées par \texttt{WHERE}.
\end{exoresolu}

\courssub{Lecture et affichage des résultats d'une requête SELECT}

\begin{methode}[Exploiter un SELECT avec mysqli]
\begin{enumerate}
\item \textbf{Exécuter} : \texttt{\$res = mysqli\_query(\$cnx, \$sql);} — pour un SELECT, \texttt{\$res} est un \emph{jeu de résultats} (pointeur sur les lignes), ou \texttt{false} en cas d'erreur SQL.
\item \textbf{Compter les lignes} si besoin : \texttt{\$nb = mysqli\_num\_rows(\$res);} (ne fonctionne que sur un objet résultat SELECT).
\item \textbf{Parcourir les lignes une à une} dans une boucle \texttt{while}, avec au choix :
  \begin{itemize}
  \item \texttt{mysqli\_fetch\_assoc(\$res)} : tableau \emph{associatif} (\texttt{\$l["nom"]}) — \textbf{le plus lisible et robuste} (insensible à l'ordre des colonnes).
  \item \texttt{mysqli\_fetch\_row(\$res)} : tableau à \emph{indices numériques} (\texttt{\$l[0]}, \texttt{\$l[1]}...).
  \item \texttt{mysqli\_fetch\_array(\$res)} : les deux à la fois (consomme plus de mémoire).
  \end{itemize}
  Chaque appel renvoie la ligne suivante, puis \texttt{false} quand il n'y en a plus : c'est ce qui arrête naturellement la boucle \texttt{while}.
\item \textbf{Afficher} les champs avec \texttt{echo}, idéalement dans un tableau HTML (\texttt{<table>}).
\item \textbf{Fermer} la connexion avec \texttt{mysqli\_close(\$cnx);}.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Affichage des livres d'une bibliothèque scolaire]
La table \texttt{livre(code, titre, auteur, prix)} de la base \texttt{biblio} contient les livres de la bibliothèque d'un lycée de Bafoussam. Écrire un script PHP qui affiche le nombre total de livres, puis la liste de tous les livres (titre, auteur, prix) sous forme de tableau HTML.
\tcblower
\textbf{Raisonnement.} Le SELECT renvoie un jeu de résultats. On compte d'abord les lignes avec \texttt{mysqli\_num\_rows}, puis on parcourt le jeu avec \texttt{while} et \texttt{mysqli\_fetch\_assoc}, qui donne accès aux champs par leur nom — code plus lisible et moins sensible à l'ordre des colonnes. L'affichage se fait ligne par ligne dans un tableau HTML ouvert avant la boucle et fermé après.

\begin{lstlisting}[language=Php]
<?php
    $cnx = mysqli_connect("localhost", "root", "")
           or die("Echec de connexion : " . mysqli_connect_error());
    mysqli_select_db($cnx, "biblio") or die("Base introuvable : " . mysqli_error($cnx));

    $sql = "SELECT * FROM livre";
    $res = mysqli_query($cnx, $sql) or die("Requete invalide : " . mysqli_error($cnx));

    // Nombre de lignes retournees
    $nb = mysqli_num_rows($res);
    echo "La bibliotheque contient " . $nb . " livre(s).<br>";

    // Affichage dans un tableau HTML
    echo "<table border='1' cellpadding='5'>";
    echo "<tr><th>Titre</th><th>Auteur</th><th>Prix (FCFA)</th></tr>";
    while ($ligne = mysqli_fetch_assoc($res)) {
        echo "<tr>";
        echo "<td>" . htmlspecialchars($ligne["titre"]) . "</td>";
        echo "<td>" . htmlspecialchars($ligne["auteur"]) . "</td>";
        echo "<td>" . number_format($ligne["prix"], 0, ',', ' ') . "</td>";
        echo "</tr>";
    }
    echo "</table>";

    mysqli_close($cnx);
?>
\end{lstlisting}

\textbf{Vérification.} Supposons la table contenant 3 livres. \texttt{mysqli\_num\_rows} renvoie 3 $\Rightarrow$ « La bibliotheque contient 3 livre(s). ». La boucle \texttt{while} s'exécute 3 fois : aux itérations 1, 2, 3, \texttt{mysqli\_fetch\_assoc} renvoie un tableau associatif (valeur vraie) ; à la 4\up{e} tentative, il renvoie \texttt{false} et la boucle s'arrête. Le tableau HTML comporte donc 1 ligne d'en-tête et 3 lignes de données. \texttt{htmlspecialchars()} protège l'affichage (XSS), \texttt{number\_format} formate le prix (ex: 15 000).

\textbf{Conclusion.} Le script affiche le nombre de livres puis le catalogue complet dans un tableau HTML, en parcourant le jeu de résultats avec \texttt{mysqli\_fetch\_assoc} jusqu'à épuisement des lignes.
\end{exoresolu}

\courssub{Synthèse : mini-application web PHP/MySQL complète}

\begin{methode}[Assembler une application d'enregistrement et de consultation (CRUD simplifié)]
\begin{enumerate}
\item \textbf{Analyser le besoin} : identifier le formulaire HTML (champs de saisie), la table MySQL cible et les traitements (enregistrer, lister).
\item \textbf{Créer le formulaire HTML} avec \texttt{method="post"} et un \texttt{action} pointant vers le script de traitement. Ajouter \texttt{required} sur les champs obligatoires.
\item \textbf{Dans le script PHP (ordre strict)} :
  \begin{enumerate}
  \item Connexion à la BDD (4 étapes : connect, die, select\_db, die).
  \item Récupération \textbf{et nettoyage} des données : \texttt{\$var = mysqli\_real\_escape\_string(\$cnx, \$\_POST["champ"] ?? '');}. L'opérateur \texttt{??} (null coalescing) évite les notices "Undefined array key".
  \item Construction de la requête INSERT avec les variables nettoyées.
  \item Exécution et test du résultat.
  \item Requête SELECT pour afficher la liste actualisée.
  \item Fermeture de la connexion.
  \end{enumerate}
\item \textbf{Tester chaque étape séparément} : formulaire seul, connexion seule, insertion seule, avant d'assembler.
\end{enumerate}
\end{methode}

\begin{attention}[Les 6 erreurs qui coûtent des points au Bac]
\begin{enumerate}
\item \textbf{Confondre \texttt{=} et \texttt{==} dans une condition.} \texttt{if (\$moy = 10)} \emph{affecte} 10 à \texttt{\$moy} et le test est toujours vrai ! La comparaison s'écrit \texttt{==} (valeur) ou \texttt{===} (valeur + type). C'est l'erreur de logique la plus fréquente.
\item \textbf{Oublier le \texttt{break;} dans un \texttt{switch}.} Sans \texttt{break}, PHP exécute \emph{tous} les cas qui suivent le cas trouvé (chute en cascade) : le résultat affiché est faux alors que la condition était juste.
\item \textbf{Oublier la clause \texttt{WHERE} dans UPDATE ou DELETE.} \texttt{DELETE FROM abonne;} vide \emph{toute} la table. Au Bac, une requête de modification ou de suppression sans condition de ciblage est sanctionnée.
\item \textbf{Traiter le résultat d'un SELECT comme un booléen, ou celui d'un INSERT comme un jeu de lignes.} \texttt{mysqli\_query} renvoie un jeu de résultats pour SELECT (à parcourir avec \texttt{mysqli\_fetch\_assoc} et \texttt{mysqli\_num\_rows}) mais un simple booléen pour INSERT/UPDATE/DELETE. Appeler \texttt{mysqli\_num\_rows} sur un INSERT provoque une erreur fatale.
\item \textbf{Oublier la gestion d'erreur et la fermeture de la connexion.} Une connexion sans \texttt{or die(...)} laisse le script planter silencieusement, et l'absence de \texttt{mysqli\_close(\$cnx);} montre une démarche incomplète. Le squelette attendu est : \texttt{connect} $\to$ \texttt{die} $\to$ \texttt{select\_db} $\to$ requêtes $\to$ \texttt{close}.
\item \textbf{Injection SQL : insérer des variables \texttt{\$\_POST} brutes dans la requête.} \texttt{VALUES ('\$nom')} sans \texttt{mysqli\_real\_escape\_string} permet à un attaquant d'injecter du SQL (ex: \texttt{' OR '1'='1}). \textbf{Systématiser l'échappement} ou utiliser les requêtes préparées (\texttt{mysqli\_prepare}) en production.
\end{enumerate}
\end{attention}

\coursec{Corrigés des exercices}

\begin{corrige}[Exercice 1 — QCM : les structures de contrôle]
\begin{enumerate}
\item \textbf{Réponse b}. Le \texttt{switch} compare la valeur d'\emph{une seule} variable (ou expression) à plusieurs \cle{constantes} (les \texttt{case}). Pour répéter un bloc, on utilise une boucle ; pour des conditions complexes avec \texttt{\&\&} ou \texttt{||}, on préfère \texttt{if...elseif} ; pour parcourir un tableau, on utilise \texttt{foreach}.
\item \textbf{Réponse b}. Sans \texttt{break}, PHP poursuit l'exécution dans les \texttt{case} suivants (phénomène appelé \emph{fall-through}). Le \texttt{break} fait donc sortir du bloc \texttt{switch} dès qu'un cas a été traité. Il n'arrête pas le script (c'est le rôle de \texttt{die()}) et ne ferme aucune connexion.
\item \textbf{Réponse a}. \texttt{foreach (\$tableau as \$valeur)} parcourt automatiquement tous les éléments d'un \cle{tableau} (indexé ou associatif), sans qu'on ait à gérer de compteur.
\item \textbf{Réponse b}. \texttt{die("message")} affiche le message passé en argument puis \cle{arrête immédiatement} l'exécution du script. On l'utilise classiquement après un échec de connexion : \texttt{or die("Echec de connexion");}.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 2 — Vrai ou faux]
\begin{enumerate}
\item \textbf{Vrai}. Dans une boucle \texttt{do...while}, le test de la condition est effectué \emph{après} l'exécution du bloc : le corps de la boucle est donc exécuté \cle{au moins une fois}, même si la condition est fausse dès le départ. C'est la différence fondamentale avec \texttt{while}, qui teste avant.
\item \textbf{Faux}. C'est \texttt{mysqli\_fetch\_assoc()} qui retourne un tableau \emph{associatif} (clés = noms des colonnes). \texttt{mysqli\_fetch\_row()} retourne un tableau à \emph{indices numériques} : \texttt{\$ligne[0]}, \texttt{\$ligne[1]}, etc.
\item \textbf{Vrai}. Appliquée au résultat d'une requête \texttt{SELECT}, \texttt{mysqli\_num\_rows(\$resultat)} retourne le nombre de lignes (enregistrements) que la requête a renvoyées.
\item \textbf{Faux}. C'est l'inverse : \texttt{mysqli\_close(\$connexion);} doit être appelée \emph{en dernier}, après toutes les requêtes. Fermer la connexion avant \texttt{mysqli\_query()} rendrait toute requête impossible, puisque celle-ci a besoin de la connexion active.
\item \textbf{Vrai}. Dans le format de \texttt{date()}, \texttt{d} représente le jour sur deux chiffres, \texttt{m} le mois sur deux chiffres et \texttt{Y} l'année sur quatre chiffres : on obtient par exemple \texttt{14/06/2025}.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 3 — Définitions]
\begin{enumerate}
\item \textbf{Structure alternative} : structure de contrôle qui permet d'exécuter un bloc d'instructions ou un autre \emph{selon qu'une condition est vraie ou fausse} (ex. : \texttt{if...else}, \texttt{switch}).
\item \textbf{Structure répétitive (boucle)} : structure de contrôle qui permet d'exécuter un même bloc d'instructions \emph{plusieurs fois}, tant qu'une condition reste vraie ou pour chaque élément d'un ensemble (ex. : \texttt{for}, \texttt{while}, \texttt{do...while}, \texttt{foreach}).
\item \textbf{Extension \texttt{mysqli}} : bibliothèque de fonctions PHP (\emph{MySQL improved}) qui permet à un script de se connecter à un serveur MySQL, de sélectionner une base, d'envoyer des requêtes SQL et d'en exploiter les résultats.
\item \textbf{Requête de manipulation des données} : instruction SQL qui agit sur le \emph{contenu} des tables : insertion (\texttt{INSERT INTO}), modification (\texttt{UPDATE}), suppression (\texttt{DELETE}) et sélection/lecture (\texttt{SELECT}).
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 4 — Lecture de code : que vaut le résultat ?]
\begin{enumerate}
\item La variable \texttt{\$note} vaut 14. On évalue les conditions dans l'ordre :
\begin{itemize}
\item \texttt{\$note < 10} : $14 < 10$ est \textbf{faux} ;
\item \texttt{\$note < 12} : $14 < 12$ est \textbf{faux} ;
\item \texttt{\$note < 14} : $14 < 14$ est \textbf{faux} (l'inégalité est stricte !) ;
\item on entre donc dans le \texttt{else}.
\end{itemize}
Le message affiché est : \textbf{« Bien ou plus »}. Le piège classique est de croire que 14 vérifie \texttt{\$note < 14} : une inégalité stricte exclut la valeur elle-même.
\item La boucle \texttt{for} s'exécute pour $i = 1, 2, 3$ et affiche $i \times 7$ :
\[ 1 \times 7 = 7, \qquad 2 \times 7 = 14, \qquad 3 \times 7 = 21. \]
Affichage obtenu : \textbf{7 14 21} (suivi d'un espace après chaque nombre).
\item Si l'on remplace \texttt{\$i++} par \texttt{\$i--}, la variable \texttt{\$i} \emph{décroît} : $1, 0, -1, -2, \dots$ La condition \texttt{\$i <= 3} resterait alors \emph{toujours vraie} : on obtient une \cle{boucle infinie} qui affiche 7, 0, $-7$, $-14$, \dots{} sans jamais s'arrêter (jusqu'à l'interruption par le serveur au bout du temps maximal d'exécution). C'est l'erreur classique du compteur qui évolue dans le mauvais sens.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 5 — La mention du Baccalauréat]
\begin{enumerate}
\item Script avec \texttt{if...elseif...else} :
\begin{lstlisting}[language=Php]
<?php
    $moyenne = $_POST['moyenne'];

    if ($moyenne < 10) {
        echo "Mention : Ajourné";
    } elseif ($moyenne < 12) {
        echo "Mention : Passable";
    } elseif ($moyenne < 14) {
        echo "Mention : Assez Bien";
    } elseif ($moyenne < 16) {
        echo "Mention : Bien";
    } else {
        echo "Mention : Très Bien";
    }
?>
\end{lstlisting}
L'ordre des tests est essentiel : chaque \texttt{elseif} n'est évalué que si les précédents sont faux, ce qui garantit que les bornes inférieures sont déjà exclues.
\item Avec \texttt{switch} : \texttt{intval(\$moyenne / 2)} donne le quotient entier de la moyenne par 2. On vérifie les cas : moyenne dans $[0;10[$ donne un quotient de 0 à 4 ; $[10;12[$ donne 5 ; $[12;14[$ donne 6 ; $[14;16[$ donne 7 ; 16 et plus donne 8, 9 ou 10.
\begin{lstlisting}[language=Php]
<?php
    $moyenne = $_POST['moyenne'];
    $q = intval($moyenne / 2);

    switch ($q) {
        case 0:
        case 1:
        case 2:
        case 3:
        case 4:
            echo "Mention : Ajourné";
            break;
        case 5:
            echo "Mention : Passable";
            break;
        case 6:
            echo "Mention : Assez Bien";
            break;
        case 7:
            echo "Mention : Bien";
            break;
        default:
            echo "Mention : Très Bien";
    }
?>
\end{lstlisting}
Remarque : les cas 0 à 4 « tombent » volontairement les uns sur les autres (absence de \texttt{break}) pour partager le même traitement ; le \texttt{default} couvre les quotients 8, 9 et 10.
\item On encadre le traitement par un test de validité :
\begin{lstlisting}[language=Php]
<?php
    $moyenne = $_POST['moyenne'];

    if ($moyenne < 0 || $moyenne > 20) {
        echo "Erreur : la moyenne doit etre comprise entre 0 et 20.";
    } elseif ($moyenne < 10) {
        echo "Mention : Ajourné";
    } elseif ($moyenne < 12) {
        echo "Mention : Passable";
    } elseif ($moyenne < 14) {
        echo "Mention : Assez Bien";
    } elseif ($moyenne < 16) {
        echo "Mention : Bien";
    } else {
        echo "Mention : Très Bien";
    }
?>
\end{lstlisting}
Le test de validité est placé \emph{en premier} : une moyenne de $-3$ ou de $25$ ne peut plus déclencher une mention absurde.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 6 — Table de multiplication et boucle infinie]
\begin{enumerate}
\item Avec une boucle \texttt{for} :
\begin{lstlisting}[language=Php]
<?php
    echo "<table border='1'>";
    echo "<tr><th>Opération</th><th>Résultat</th></tr>";
    for ($i = 1; $i <= 10; $i++) {
        echo "<tr>";
        echo "<td>7 x " . $i . "</td>";
        echo "<td>" . (7 * $i) . "</td>";
        echo "</tr>";
    }
    echo "</table>";
?>
\end{lstlisting}
\item Avec une boucle \texttt{while} :
\begin{lstlisting}[language=Php]
<?php
    echo "<table border='1'>";
    echo "<tr><th>Opération</th><th>Résultat</th></tr>";
    $i = 1;                    // initialisation AVANT la boucle
    while ($i <= 10) {
        echo "<tr>";
        echo "<td>7 x " . $i . "</td>";
        echo "<td>" . (7 * $i) . "</td>";
        echo "</tr>";
        $i++;                  // incrementation DANS la boucle
    }
    echo "</table>";
?>
\end{lstlisting}
\item \textbf{Cause de la boucle infinie} : l'instruction d'incrémentation \texttt{\$i++;} a été oubliée dans le corps de la boucle. La variable \texttt{\$i} reste donc bloquée à 1, et la condition \texttt{\$i <= 10} demeure vraie éternellement. Correction :
\begin{lstlisting}[language=Php]
<?php
    $i = 1;
    while ($i <= 10) {
        echo "7 x " . $i . " = " . (7 * $i) . "<br>";
        $i++;   // ne jamais oublier de faire progresser le compteur
    }
?>
\end{lstlisting}
\textbf{Règle à retenir} : dans une boucle \texttt{while}, il faut toujours vérifier les trois ingrédients : initialisation avant la boucle, condition d'arrêt, et modification du compteur dans le corps.
\end{enumerate}
\end{corrige}

        echo "<td>" . $ligne['etablissement'] . "</td>";
        echo "<td>" . $ligne['moyenne'] . "</td>";
        echo "</tr>";
    }
    echo "</table>";
    mysqli_close($cnx);
?>
\end{lstlisting}
\texttt{mysqli\_fetch\_array()} retourne un tableau à la fois numérique et associatif : on peut donc écrire \texttt{\$ligne['nom']} ou \texttt{\$ligne[1]}.
\item Script \texttt{admissibles.php} : même structure, avec la requête filtrante et le comptage :
\begin{lstlisting}[language=Php]
<?php
    $cnx = mysqli_connect("localhost", "root", "")
        or die("Echec de connexion");
    mysqli_select_db($cnx, "candidats_bac")
        or die("Base introuvable");

    $sql = "SELECT * FROM candidat WHERE moyenne >= 10";
    $res = mysqli_query($cnx, $sql) or die("Erreur SQL");

    echo "<table border='1'>";
    echo "<tr><th>Nom</th><th>Etablissement</th><th>Moyenne</th></tr>";
    while ($ligne = mysqli_fetch_assoc($res)) {
        echo "<tr><td>" . $ligne['nom'] . "</td><td>"
             . $ligne['etablissement'] . "</td><td>"
             . $ligne['moyenne'] . "</td></tr>";
    }
    echo "</table>";

    echo "<p>Nombre d'admissibles : "
         . mysqli_num_rows($res) . "</p>";
    mysqli_close($cnx);
?>
\end{lstlisting}
\item Script \texttt{supprimer.php} :
\begin{lstlisting}[language=Php]
<?php
    // a) Verification du parametre id dans l'URL
    if (!isset($_GET['id'])) {
        die("Erreur : aucun identifiant fourni.");
    }
    $id = intval($_GET['id']);   // securisation (voir question 5)

    $cnx = mysqli_connect("localhost", "root", "")
        or die("Echec de connexion");
    mysqli_select_db($cnx, "candidats_bac")
        or die("Base introuvable");

    // b) Requete de suppression ciblee
    $sql = "DELETE FROM candidat WHERE id = " . $id;
    $ok = mysqli_query($cnx, $sql);

    // c) Message de confirmation ou d'erreur
    if ($ok) {
        echo "Le candidat a ete supprime avec succes.";
    } else {
        echo "Erreur : la suppression a echoue.";
    }
    mysqli_close($cnx);
?>
\end{lstlisting}
La clause \texttt{WHERE id = ...} est indispensable : sans elle, \texttt{DELETE} viderait \emph{toute} la table.
\item Instruction à insérer en haut de chaque page :
\begin{lstlisting}[language=Php]
<?php echo "Date du jour : " . date("d/m/Y"); ?>
\end{lstlisting}
\item Deux précautions de sécurité avant d'utiliser \texttt{\$\_GET['id']} :
\begin{itemize}
\item \textbf{Contrôler le type} de la valeur, par exemple avec \texttt{intval(\$\_GET['id'])}, qui force la conversion en entier : toute chaîne malveillante est neutralisée ;
\item \textbf{Se prémunir contre l'injection SQL} : une valeur saisie dans l'URL peut contenir du code SQL hostile (ex. \texttt{?id=1 OR 1=1}). Il faut échapper la valeur avec \texttt{mysqli\_real\_escape\_string(\$cnx, \$\_GET['id'])} ou, mieux, utiliser des requêtes préparées. On peut aussi vérifier que l'identifiant existe réellement dans la base avant de supprimer.
\end{itemize}
\end{enumerate}
\textbf{Points de vigilance au Bac} : toujours justifier le rôle de \texttt{die()} (arrêt du script avec message), citer la condition d'application de \texttt{mysqli\_num\_rows()} (résultat d'un \texttt{SELECT}), et mentionner l'injection SQL dès qu'une donnée provient de l'utilisateur.
\end{corrige}

\begin{corrige}[Exercice 10 — Type Bac : modification des données d'un élève]
\textbf{Barème indicatif (sur 20)} : question 1 : 5 pts ; question 2 : 5 pts ; question 3 : 6 pts ; question 4 : 4 pts.

\begin{enumerate}
\item Vérification du paramètre et lecture de l'élève :
\begin{lstlisting}[language=Php]
<?php
    if (!isset($_GET['id'])) {
        die("Erreur : aucun eleve selectionne.");
    }
    $id = intval($_GET['id']);

    $cnx = mysqli_connect("localhost", "root", "")
        or die("Echec de connexion");
    mysqli_select_db($cnx, "ecole") or die("Base introuvable");

    $sql = "SELECT * FROM eleve WHERE id = " . $id;
    $res = mysqli_query($cnx, $sql) or die("Erreur SQL");

    if (mysqli_num_rows($res) == 0) {
        die("Aucun eleve ne porte cet identifiant.");
    }
?>
\end{lstlisting}
\item Pré-remplissage du formulaire avec \texttt{mysqli\_fetch\_assoc()} :
\begin{lstlisting}[language=Php]
<?php
    $eleve = mysqli_fetch_assoc($res);
?>
<form method="post" action="modifier.php?id=<?php echo $id; ?>">
    Nom : <input type="text" name="nom"
        value="<?php echo $eleve['nom']; ?>"><br>
    Classe : <input type="text" name="classe"
        value="<?php echo $eleve['classe']; ?>"><br>
    Moyenne : <input type="text" name="moyenne"
        value="<?php echo $eleve['moyenne']; ?>"><br>
    <input type="submit" value="Enregistrer">
</form>
\end{lstlisting}
L'attribut \texttt{value} de chaque champ reçoit la valeur lue dans la base : le formulaire apparaît ainsi pré-rempli.
\item Traitement de la validation (méthode \texttt{POST}) :
\begin{lstlisting}[language=Php]
<?php
    if (isset($_POST['nom'])) {
        $nom     = $_POST['nom'];
        $classe  = $_POST['classe'];
        $moyenne = $_POST['moyenne'];
        $id      = intval($_GET['id']);

        $cnx = mysqli_connect("localhost", "root", "")
            or die("Echec de connexion");
        mysqli_select_db($cnx, "ecole") or die("Base introuvable");

        // Attention : en production, échapper $nom et $classe
        // avec mysqli_real_escape_string($cnx, $nom) etc.
        // ou utiliser des requêtes préparées (PDO/mysqli).
        $sql = "UPDATE eleve
                SET nom = '$nom', classe = '$classe',
                    moyenne = $moyenne
                WHERE id = $id";
        $ok = mysqli_query($cnx, $sql);

        if ($ok) {
            echo "Les informations de l'élève ont été mises à jour.";
        } else {
            echo "Erreur lors de la mise à jour.";
        }
        mysqli_close($cnx);
    }
?>
\end{lstlisting}
\item \textbf{Pourquoi la clause \texttt{WHERE} est vitale} : une requête \texttt{UPDATE} sans \texttt{WHERE} s'applique à \emph{toutes les lignes} de la table. Ici, \texttt{UPDATE eleve SET nom = ..., classe = ..., moyenne = ...} écraserait les données de \textbf{tous les élèves} du Collège Vogt : chacun se retrouverait avec le même nom, la même classe et la même moyenne que l'élève modifié. C'est une perte de données massive et irréversible (sauf sauvegarde). La clause \texttt{WHERE id = \$id} garantit que \emph{seule} la ligne de l'élève concerné est modifiée. Même remarque pour \texttt{DELETE} : sans \texttt{WHERE}, toute la table est vidée.
\end{enumerate}
\textbf{Points de vigilance au Bac} : exiger la justification du rôle de \texttt{isset()} (éviter l'erreur « Undefined array key » et les accès sans paramètre), et la citation explicite du danger d'un \texttt{UPDATE} ou d'un \texttt{DELETE} sans \texttt{WHERE}.
\end{corrige}

\begin{corrige}[Exercice 11 — Type Bac : cybercafé et fonctions de lecture des résultats]
\textbf{Barème indicatif (sur 20)} : question 1 : 6 pts ; question 2 : 6 pts ; question 3 : 4 pts ; question 4 : 4 pts.

\begin{enumerate}
\item Différences entre les trois fonctions de lecture :
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}
\hline
\rowcolor{popblueL} \textbf{Fonction} & \textbf{Type de tableau retourné} & \textbf{Accès aux colonnes} \\
\hline
\texttt{mysqli\_fetch\_row()} & tableau à indices numériques & \texttt{\$ligne[0]}, \texttt{\$ligne[1]}, \dots{} dans l'ordre du \texttt{SELECT} \\
\hline
\texttt{mysqli\_fetch\_assoc()} & tableau associatif & \texttt{\$ligne['client']}, \texttt{\$ligne['montant']} (noms des colonnes) \\
\hline
\texttt{mysqli\_fetch\_array()} & tableau mixte (numérique \emph{et} associatif) & les deux formes ci-dessus sont utilisables \\
\hline
\end{tabularx}
\end{center}
Les trois fonctions lisent une ligne du résultat, avancent le curseur interne d'une position, et retournent \texttt{null} lorsqu'il n'y a plus de ligne — ce qui permet de les utiliser comme condition d'une boucle \texttt{while}.
\item \textbf{Cause exacte de l'erreur} : le script utilise \texttt{mysqli\_fetch\_row()}, qui retourne un tableau à \emph{indices numériques}, mais le code accède aux valeurs par des \emph{clés associatives} (\texttt{\$ligne['client']} et \texttt{\$ligne['montant']}). Ces clés n'existent pas dans le tableau retourné : PHP signale donc « Undefined array key ». Deux corrections :

Correction 1 — on conserve \texttt{mysqli\_fetch\_row()} et on utilise les indices numériques (\texttt{client} est la 1\textsuperscript{re} colonne du \texttt{SELECT}, donc l'indice 0 ; \texttt{montant} l'indice 1) :
\begin{lstlisting}[language=Php]
<?php
    $cnx = mysqli_connect("localhost", "root", "");
    mysqli_select_db($cnx, "cybercafe");
    $res = mysqli_query($cnx,
        "SELECT client, montant FROM session_nav");
    while ($ligne = mysqli_fetch_row($res)) {
        echo $ligne[0] . " : " . $ligne[1] . "<br>";
    }
    mysqli_close($cnx);
?>
\end{lstlisting}
Correction 2 — on remplace par \texttt{mysqli\_fetch\_assoc()}, qui accepte les clés nommées :
\begin{lstlisting}[language=Php]
<?php
    $cnx = mysqli_connect("localhost", "root", "");
    mysqli_select_db($cnx, "cybercafe");
    $res = mysqli_query($cnx,
        "SELECT client, montant FROM session_nav");
    while ($ligne = mysqli_fetch_assoc($res)) {
        echo $ligne['client'] . " : " . $ligne['montant'] . "<br>";
    }
    mysqli_close($cnx);
?>
\end{lstlisting}
\item Montant total encaissé avec un accumulateur :
\begin{lstlisting}[language=Php]
<?php
    $cnx = mysqli_connect("localhost", "root", "")
        or die("Echec de connexion");
    mysqli_select_db($cnx, "cybercafe") or die("Base introuvable");

    $res = mysqli_query($cnx, "SELECT montant FROM session_nav");
    $total = 0;                       // accumulateur initialise a 0
    while ($ligne = mysqli_fetch_assoc($res)) {
        $total = $total + $ligne['montant'];
    }
    echo "Montant total encaissé : " . $total . " FCFA";
    mysqli_close($cnx);
?>
\end{lstlisting}
Principe de l'accumulateur : on initialise \texttt{\$total} à 0 \emph{avant} la boucle, puis on y ajoute le montant de chaque ligne lue. (En pratique, on obtiendrait le même résultat en une seule requête : \texttt{SELECT SUM(montant) FROM session\_nav}.)
\item Date du jour en français : \texttt{date("w")} donne le numéro du jour de la semaine (0 = dimanche, \dots, 6 = samedi) et \texttt{date("n")} le numéro du mois (1 à 12). On utilise ces numéros comme indices de deux tableaux de noms français :
\begin{lstlisting}[language=Php]
<?php
    $jours = array("dimanche", "lundi", "mardi", "mercredi",
                   "jeudi", "vendredi", "samedi");
    $mois = array(1 => "janvier", "février", "mars", "avril",
                  "mai", "juin", "juillet", "août", "septembre",
                  "octobre", "novembre", "décembre");

    $nomJour = $jours[date("w")];    // ex. "vendredi"
    $nomMois = $mois[date("n")];     // ex. "juin"

    echo $nomJour . " " . date("d") . " " . $nomMois
         . " " . date("Y");
    // affiche par exemple : vendredi 14 juin 2025
?>
\end{lstlisting}
Attention : le tableau \texttt{\$mois} est démarré à l'indice 1 (notation \texttt{1 => "janvier"}) car \texttt{date("n")} retourne 1 pour janvier, alors qu'un tableau PHP commence par défaut à l'indice 0.
\end{enumerate}
\textbf{Points de vigilance au Bac} : savoir associer chaque fonction de lecture au type de tableau qu'elle retourne ; savoir diagnostiquer l'erreur « Undefined array key » comme une incohérence entre la fonction de lecture et le mode d'accès ; initialiser l'accumulateur avant la boucle.
\end{corrige}

\begin{bilan}
\textbf{1. Définitions clés}
\begin{itemize}
  \item \cle{Structure alternative} : exécute un bloc d'instructions selon qu'une \textbf{condition} est vraie ou fausse (\texttt{if}, \texttt{else}, \texttt{elseif}, \texttt{switch}).
  \item \cle{Structure répétitive} (boucle) : répète un bloc tant qu'une condition est vraie (\texttt{while}, \texttt{do...while}) ou un nombre connu de fois (\texttt{for}, \texttt{foreach}).
  \item \cle{Extension mysqli} : bibliothèque PHP permettant de dialoguer avec le SGBD \cle{MySQL} (connexion, requêtes, lecture des résultats).
  \item \cle{Jeu de résultats} : ensemble de lignes retourné par une requête \texttt{SELECT}, parcouru ligne par ligne avec les fonctions \texttt{mysqli\_fetch\_*}.
\end{itemize}

\textbf{2. Syntaxes à connaître par c\oe ur}
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Notion} & \textbf{Syntaxe PHP} \\
\hline
Alternative & \texttt{if (\$cond) \{...\} elseif (\$c2) \{...\} else \{...\}} \\
\hline
Choix multiple & \texttt{switch (\$x) \{ case 1: ...; break; default: ...; \}} \\
\hline
Boucle \texttt{for} & \texttt{for (\$i=0; \$i<10; \$i++) \{...\}} \\
\hline
Boucle \texttt{foreach} & \texttt{foreach (\$tab as \$val) \{...\}} \\
\hline
Boucle \texttt{while} & \texttt{while (\$cond) \{...\}} \\
\hline
Boucle \texttt{do...while} & \texttt{do \{...\} while (\$cond);} (au moins 1 passage) \\
\hline
Date & \texttt{date("d/m/Y H:i")} $\rightarrow$ 15/03/2025 14:30 \\
\hline
Connexion & \texttt{\$cnx = mysqli\_connect("localhost","root","") or die("Erreur");} \\
\hline
Base & \texttt{mysqli\_select\_db(\$cnx, "mabase");} \\
\hline
Requête & \texttt{\$res = mysqli\_query(\$cnx, "SELECT * FROM eleve");} \\
\hline
Lecture & \texttt{while (\$lig = mysqli\_fetch\_assoc(\$res)) \{...\}} \\
\hline
Comptage & \texttt{\$n = mysqli\_num\_rows(\$res);} \\
\hline
Fermeture & \texttt{mysqli\_close(\$cnx);} \\
\hline
\end{tabularx}
\end{center}

\textbf{3. Les trois fonctions de lecture (à ne pas confondre)}
\begin{itemize}
  \item \texttt{mysqli\_fetch\_row(\$res)} : tableau à indices \textbf{numériques} (\texttt{\$lig[0]}).
  \item \texttt{mysqli\_fetch\_assoc(\$res)} : tableau \textbf{associatif} (\texttt{\$lig["nom"]}).
  \item \texttt{mysqli\_fetch\_array(\$res)} : les \textbf{deux} à la fois.
\end{itemize}

\textbf{4. Méthode express : interroger MySQL en 5 étapes}
\begin{enumerate}
  \item Se connecter : \texttt{mysqli\_connect(...)} avec \texttt{or die(...)}.
  \item Choisir la base : \texttt{mysqli\_select\_db(...)}.
  \item Envoyer la requête : \texttt{mysqli\_query(\$cnx, \$sql)}.
  \item Exploiter : boucle \texttt{while} + \texttt{mysqli\_fetch\_assoc} (ou \texttt{num\_rows}).
  \item Fermer : \texttt{mysqli\_close(\$cnx)}.
\end{enumerate}

\textbf{5. Requêtes de manipulation depuis PHP}
\begin{itemize}
  \item Insertion : \texttt{INSERT INTO eleve VALUES (NULL, 'Amina', 15.5);}
  \item Modification : \texttt{UPDATE eleve SET moyenne=16 WHERE id=3;}
  \item Suppression : \texttt{DELETE FROM eleve WHERE id=3;}
  \item Sélection : \texttt{SELECT nom, moyenne FROM eleve WHERE moyenne>=10;}
\end{itemize}
\end{bilan}
