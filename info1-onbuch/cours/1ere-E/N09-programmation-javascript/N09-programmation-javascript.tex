\coursec{Pourquoi JavaScript ? – Du HTML statique au Web dynamique}

\textbf{Situation d'accroche.} Il est 17 h dans un cybercafé du quartier Nlongkak à Yaoundé. Un client, commerçant qui vient de recevoir un devis en euros, veut convertir instantanément le montant de ses achats en francs CFA. Le gérant lui ouvre une petite page web : le client tape le montant, clique sur un bouton « Convertir », et le résultat s'affiche \emph{immédiatement}, sans que la page se recharge, sans attendre une réponse d'un serveur lointain. Le client, étonné, demande : « Mais comment la page a-t-elle su calculer toute seule ? »

Voilà notre problématique : \textbf{comment rendre une page HTML vivante et interactive, capable de réagir aux actions de l'utilisateur et d'effectuer des traitements, pour répondre à ce besoin quotidien ?} La réponse tient en un mot : \cle{JavaScript}. Mais pour comprendre pourquoi ce langage est indispensable, il faut d'abord mesurer les limites du HTML que tu as étudié dans les leçons précédentes.

\courssub{Rappel : le HTML, un langage d'affichage statique}

Le \cle{HTML} (\emph{HyperText Markup Language}) est un langage de \textbf{balisage} : il décrit la \emph{structure} et le \emph{contenu} d'une page web (titres, paragraphes, tableaux, images, liens, formulaires). Le navigateur lit le fichier HTML de haut en bas et l'affiche. Une fois la page affichée, elle est \textbf{figée} : c'est ce qu'on appelle une page \cle{statique}.

\begin{exemplebox}[Une page HTML purement statique]
Voici la page du cybercafé écrite uniquement en HTML. Elle affiche un taux de change, mais elle ne peut rien calculer :
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Cybercafé Nlongkak - Taux du jour</title>
</head>
<body>
    <h1>Bienvenue au Cybercafé Nlongkak</h1>
    <p>Taux du jour : 1 euro = 655,957 FCFA</p>
    <p>Pour convertir, prenez votre calculatrice !</p>
</body>
</html>
\end{lstlisting}
Le client doit sortir sa calculatrice : la page ne fait qu'\emph{afficher}. Aucun clic, aucune saisie ne déclenche le moindre traitement.
\end{exemplebox}

\courssub{Les limites du HTML face au besoin d'interactivité}

Reprenons le besoin du client : saisir un montant, cliquer, obtenir un résultat. Analysons pourquoi le HTML seul échoue :

\begin{itemize}
    \item \textbf{Pas de calcul.} HTML ne connaît ni l'addition, ni la multiplication, ni aucune opération. On ne peut pas lui demander de calculer $150 \times 655{,}957$.
    \item \textbf{Pas de réaction aux actions de l'utilisateur.} Un clic sur un bouton, la saisie dans une zone de texte, le déplacement de la souris : HTML peut \emph{afficher} un bouton ou un champ, mais ne peut pas \emph{réagir} à leur utilisation.
    \item \textbf{Pas de décision ni de répétition.} Impossible d'écrire « si le montant est négatif, afficher une erreur » ou « répéter pour chaque article du panier » : HTML n'a ni structure conditionnelle, ni boucle.
    \item \textbf{Rechargement obligatoire.} Sans JavaScript, la seule façon d'obtenir un nouveau contenu est de renvoyer les données vers un serveur et de recharger toute la page : aller-retour réseau, attente, consommation de forfait data — un vrai problème quand la connexion est lente ou coûteuse.
\end{itemize}

\begin{aretenir}[L'essentiel sur les limites du HTML]
HTML décrit et affiche ; il ne \textbf{calcule} pas, ne \textbf{décide} pas et ne \textbf{réagit} pas. Pour rendre une page interactive, il faut lui adjoindre un véritable langage de programmation exécuté par le navigateur : JavaScript.
\end{aretenir}

\courssub{JavaScript : le langage qui rend la page vivante}

\begin{definition}[Script]
Un \cle{script} est une portion de code, écrite dans un langage de script comme \cle{JavaScript}, qui est \textbf{interprétée et exécutée par le navigateur web} (Chrome, Firefox, Edge...) au moment du chargement de la page ou en réponse à une action de l'utilisateur. Contrairement à un programme compilé classique, le script n'a pas besoin d'être transformé au préalable en fichier exécutable : le navigateur lit le texte du code et l'exécute directement.
\end{definition}

JavaScript est donc un langage de \textbf{programmation} complet : variables, opérateurs, structures conditionnelles, boucles, fonctions — tout ce que tu as découvert en algorithmique s'y retrouve. Sa particularité : il vit \emph{à l'intérieur} de la page web et peut la modifier en temps réel.

\textbf{Le mécanisme clé : le DOM.} Quand le navigateur charge une page HTML, il construit en mémoire une représentation de la page sous forme d'arborescence d'objets appelée \cle{DOM} (\emph{Document Object Model}). Chaque balise (titre, paragraphe, bouton, champ de saisie) devient un « objet » que JavaScript peut lire et modifier : changer un texte, récupérer une valeur saisie, afficher un résultat. C'est la \textbf{manipulation du DOM} qui permet à la page de réagir sans se recharger.

\begin{propriete}[Avantages et limites de JavaScript]
\textbf{Avantages :}
\begin{itemize}
    \item \textbf{Exécution côté client} : le code tourne dans le navigateur de l'utilisateur, ce qui évite les allers-retours vers le serveur. La réponse est immédiate, même avec une connexion lente.
    \item \textbf{Interactivité immédiate} : la page réagit aux clics, aux saisies, aux déplacements de souris grâce aux \cle{événements}.
    \item \textbf{Manipulation du DOM} : le script peut modifier le contenu et l'apparence de la page sans rechargement.
    \item \textbf{Simplicité de mise en œuvre} : aucun logiciel à installer, un simple éditeur de texte et un navigateur suffisent.
\end{itemize}
\textbf{Limites :}
\begin{itemize}
    \item \textbf{Sécurité} : pour protéger l'utilisateur, JavaScript exécuté dans une page \textbf{ne peut pas accéder aux fichiers locaux} du disque dur, ni lire d'autres documents de l'ordinateur.
    \item \textbf{Dépendance au navigateur} : le code peut se comporter légèrement différemment selon le navigateur, et l'utilisateur peut désactiver JavaScript.
    \item \textbf{Code visible} : n'importe qui peut afficher le code source de la page et lire le script ; on n'y place donc jamais de secret (mot de passe, clé...).
\end{itemize}
\end{propriete}

\begin{attention}[JavaScript n'est pas Java !]
Malgré la ressemblance des noms, \textbf{JavaScript et Java sont deux langages totalement différents}, ni compatibles ni interchangeables. JavaScript s'exécute dans le navigateur ; Java est un langage compilé à usage général. Ne confonds jamais les deux dans une copie d'examen !
\end{attention}

\begin{savaistu}[Le moteur V8 : JavaScript à la vitesse de l'éclair]
On dit que JavaScript est « interprété », mais les navigateurs modernes font bien mieux. Le moteur \textbf{V8} de Google Chrome (aussi utilisé par Edge et Node.js) analyse le code JavaScript et le \textbf{compile en code machine à la volée} pendant l'exécution : c'est la compilation \emph{JIT} (\emph{Just-In-Time}). Résultat : des scripts exécutés presque aussi vite qu'un programme natif. Né en 1995 en seulement dix jours sous le nom de \emph{LiveScript}, JavaScript est aujourd'hui le langage le plus utilisé au monde — y compris au Cameroun, où il anime les plateformes de services en ligne et les applications mobiles hybrides.
\end{savaistu}

\courssub{Insérer un script dans une page HTML : la balise \texttt{<script>}}

Pour intégrer du JavaScript dans une page, on utilise la balise \texttt{<script>...</script>}. Deux questions se posent alors : \emph{où} placer cette balise, et \emph{quand} le script sera-t-il exécuté ?

\textbf{Deux emplacements possibles :}
\begin{enumerate}
    \item \textbf{Dans l'en-tête \texttt{<head>}} : le script est chargé avant le contenu de la page. C'est l'endroit naturel pour déclarer des fonctions qui seront appelées plus tard (par exemple au clic sur un bouton).
    \item \textbf{En fin de \texttt{<body>}}, juste avant \texttt{</body>} : le script n'est exécuté qu'après l'affichage de tout le contenu. C'est l'endroit idéal pour un script qui manipule directement les éléments de la page, car ils existent déjà dans le DOM.
\end{enumerate}

\begin{exemplebox}[Premier script : notre convertisseur réagit enfin]
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Convertisseur FCFA - Euro</title>
    <script>
        // Fonction appelée au clic sur le bouton
        function convertir() {
            var montant = parseFloat(document.getElementById("euro").value);
            var resultat = montant * 655.957;
            document.getElementById("sortie").innerHTML =
                montant + " euro(s) = " + resultat + " FCFA";
        }
    </script>
</head>
<body>
    <h1>Convertisseur du Cybercafé Nlongkak</h1>
    <label>Montant en euros :</label>
    <input type="text" id="euro">
    <button onclick="convertir()">Convertir</button>
    <p id="sortie"></p>
</body>
</html>
\end{lstlisting}
Le script est placé dans le \texttt{<head>} : la fonction \texttt{convertir()} y est \emph{définie} mais ne s'exécute que lorsque l'utilisateur clique sur le bouton, grâce à l'événement \texttt{onclick}. Nous détaillerons tout ce mécanisme (variables, conversion de type, fonctions, événements, manipulation du DOM) dans les sections 2, 5 et 6.
\end{exemplebox}

\courssub{Le problème du blocage : les attributs \texttt{defer} et \texttt{async}}

Un script placé dans le \texttt{<head>} sans précaution possède un défaut : le navigateur, en le rencontrant, \textbf{interrompt l'affichage de la page} pour télécharger et exécuter le script, puis reprend. On dit que le script est \cle{bloquant}. Si le script est volumineux ou le réseau lent, l'utilisateur patiente devant une page blanche.

Deux attributs de la balise \texttt{<script>} résolvent ce problème :
\begin{itemize}
    \item \texttt{\cle{defer}} : le script est téléchargé \emph{en parallèle} du chargement de la page, mais n'est exécuté qu'\textbf{après} la construction complète du DOM, dans l'ordre d'apparition des scripts.
    \item \texttt{\cle{async}} : le script est téléchargé en parallèle et exécuté \textbf{dès qu'il est prêt}, sans attendre le reste de la page (à réserver aux scripts indépendants, comme les statistiques de visite).
\end{itemize}

\begin{methode}[Bien placer son script]
Pour garantir que le script trouve tous les éléments de la page sans bloquer l'affichage :
\begin{enumerate}
    \item Si le script est dans un fichier externe et manipule la page : place la balise dans le \texttt{<head>} avec l'attribut \texttt{defer} : \texttt{<script src="app.js" defer></script>}.
    \item Sinon (petit script intégré) : place la balise \texttt{<script>} juste \textbf{avant} \texttt{</body>}.
    \item Réserve \texttt{async} aux scripts totalement indépendants du contenu de la page.
    \item Évite les scripts lourds sans \texttt{defer} ni \texttt{async} dans le \texttt{<head>}.
\end{enumerate}
\end{methode}

\begin{attention}[Erreur fréquente : le script qui bloque la page]
Oublier \texttt{defer} ou \texttt{async} sur un script volumineux placé dans le \texttt{<head>} bloque l'affichage : la page reste blanche pendant le téléchargement. Autre piège lié : un script exécuté \emph{trop tôt} qui cherche un élément pas encore chargé (par exemple \texttt{document.getElementById("euro")} avant que le champ existe) provoque une erreur et le reste du script ne s'exécute pas. D'où la règle d'or : \textbf{\texttt{defer} dans le \texttt{<head>}, ou script en fin de \texttt{<body>}}.
\end{attention}

\begin{exemplebox}[Exemple chiffré : l'impact sur le temps de chargement]
Le gérant du cybercafé a mesuré le temps d'affichage complet de sa page sur la connexion 3G du quartier :
\begin{center}
\begin{tabularx}{\linewidth}{|X|c|}
\hline
\rowcolor{popblueL} \textbf{Configuration de la page} & \textbf{Temps d'affichage} \\
\hline
Page sans JavaScript & 0,8 s \\
\hline
Script bloquant (300 ko) dans le \texttt{<head>} sans attribut & 1,5 s \\
\hline
Même script avec \texttt{defer} & 0,9 s \\
\hline
\end{tabularx}
\end{center}
Le script bloquant a presque \textbf{doublé} le temps d'attente ($1{,}5 - 0{,}8 = 0{,}7$ s de blocage), alors qu'avec \texttt{defer} le surcoût n'est plus que de $0{,}1$ s : le téléchargement se fait en parallèle de l'affichage. Sur un forfait data limité et une connexion instable, ce gain est décisif pour les clients du cybercafé.
\end{exemplebox}

\courssub{Bonne pratique : séparer le JavaScript dans un fichier \texttt{.js}}

Comme en CSS, il est vivement recommandé de \textbf{séparer} le code JavaScript du code HTML : on écrit le script dans un fichier externe d'extension \texttt{.js}, puis on l'inclut dans la page avec l'attribut \texttt{src}.

\begin{exemplebox}[Code séparé : fichier externe]
Fichier \texttt{convertisseur.js} :
\begin{lstlisting}[language=JavaScript]
// Fichier convertisseur.js : logique de l'application
function convertir() {
    var montant = parseFloat(document.getElementById("euro").value);
    var resultat = montant * 655.957;
    document.getElementById("sortie").innerHTML =
        montant + " euro(s) = " + resultat + " FCFA";
}
\end{lstlisting}
Fichier \texttt{index.html} :
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Convertisseur FCFA - Euro</title>
    <script src="convertisseur.js" defer></script>
</head>
<body>
    <h1>Convertisseur du Cybercafé Nlongkak</h1>
    <input type="text" id="euro">
    <button onclick="convertir()">Convertir</button>
    <p id="sortie"></p>
</body>
</html>
\end{lstlisting}
Avantages : le code est plus lisible, réutilisable dans plusieurs pages, et le navigateur peut le mettre en cache (chargement plus rapide lors des visites suivantes). Remarque : une balise \texttt{<script>} avec un attribut \texttt{src} doit avoir un \textbf{corps vide}.
\end{exemplebox}

\begin{exoresolu}[Choisir le bon emplacement de script]
\textbf{Énoncé.} Le gérant du cybercafé écrit une page contenant un grand script de 250 ko qui, dès le chargement, colore en vert tous les prix affichés dans un tableau. Il place la balise \texttt{<script src="prix.js"></script>} dans le \texttt{<head>}, sans attribut. Ses clients se plaignent que la page met longtemps à s'afficher, et parfois les prix ne sont pas colorés. Expliquer les deux problèmes et proposer une correction.
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
    \item \textbf{Problème 1 — blocage de l'affichage.} Sans \texttt{defer} ni \texttt{async}, le navigateur suspend l'affichage de la page le temps de télécharger et d'exécuter les 250 ko du script : d'où la page blanche et l'attente constatées par les clients.
    \item \textbf{Problème 2 — DOM pas encore construit.} Le script s'exécute \emph{avant} que le tableau des prix n'existe dans le DOM. S'il cherche les cellules du tableau trop tôt, il ne les trouve pas et la coloration échoue.
    \item \textbf{Correction.} Deux solutions équivalentes :
    \begin{itemize}
        \item ajouter l'attribut \texttt{defer} : \texttt{<script src="prix.js" defer></script>} dans le \texttt{<head>} — le téléchargement se fait en parallèle et l'exécution attend la fin de la construction du DOM ;
        \item ou déplacer la balise juste avant \texttt{</body>} : \texttt{<script src="prix.js"></script>}.
    \end{itemize}
    Dans les deux cas, la page s'affiche sans blocage et le tableau existe lorsque le script s'exécute : les prix sont correctement colorés en vert.
\end{enumerate}
\end{exoresolu}

\textbf{Objectif.} Vérifier concrètement qu'un script du \texttt{<head>} s'exécute avant le contenu du \texttt{<body>}, et qu'un script en fin de \texttt{<body>} trouve bien les éléments de la page.

\textbf{Matériel.} Un ordinateur avec un éditeur de texte (Notepad++, Sublime Text ou Bloc-notes) et un navigateur (Chrome ou Firefox).

\textbf{Manipulation.}
\begin{enumerate}
    \item Crée un fichier \texttt{test.html} contenant le code ci-dessous :
\begin{lstlisting}[language=HTML]

    \item Enregistre le fichier, puis ouvre-le avec le navigateur (double-clic).

    \item \textbf{JavaScript} est un langage de programmation exécuté \textbf{côté client}, dans le navigateur ; il rend la page interactive et manipule le \textbf{DOM}.

\end{itemize}

\coursec{Variables, types de données et conversions}

Dans la section précédente, nous avons vu que le HTML seul ne sait produire que des pages \emph{statiques} : une fois affichée, la page ne réagit plus à l'utilisateur. JavaScript vient combler cette lacune en permettant à la page de \emph{calculer}, de \emph{mémoriser} et de \emph{réagir}. Mais pour calculer, il faut d'abord pouvoir \textbf{stocker des valeurs} : le total d'une facture dans une boutique de Douala, la note d'un élève, le montant en FCFA à convertir en euros. C'est précisément le rôle des \cle{variables}. Cette section est donc le véritable point de départ de la programmation JavaScript : sans variables, aucun script ne peut exister.

\courssub{La notion de variable}

\begin{definition}[Variable]
Une \cle{variable} est un \textbf{conteneur nommé} qui stocke en mémoire une valeur (nombre, texte, vrai/faux, etc.) que le programme peut lire et réutiliser. Cette valeur est \textbf{modifiable} au cours de l'exécution si la variable est déclarée avec \texttt{let} ou \texttt{var} ; elle est \textbf{non réaffectable} (constante) si elle est déclarée avec \texttt{const}.
\end{definition}

Imagine une boîte étiquetée dans la réserve d'une boutique : l'étiquette est le \emph{nom} de la variable, le contenu de la boîte est sa \emph{valeur}. On peut ouvrir la boîte pour lire le contenu, ou remplacer le contenu par un autre. En algorithmique, tu as déjà rencontré cette idée avec l'instruction \texttt{Variable x : Entier}. JavaScript reprend le même concept, avec sa propre syntaxe.

\courssub{Déclaration des variables : var, let et const}

\begin{propriete}[Syntaxe de déclaration]
En JavaScript, on déclare une variable avec l'un des trois mots-clés suivants, suivis du nom de la variable et éventuellement d'une valeur initiale :
\begin{itemize}
  \item \texttt{var nom = valeur;} : portée \textbf{fonction} (la variable est visible dans toute la fonction où elle est déclarée). C'est la forme historique, aujourd'hui déconseillée car source de confusions.
  \item \texttt{let nom = valeur;} : portée \textbf{bloc} (la variable n'existe qu'entre les accolades \texttt{\{ \}} où elle est déclarée), valeur \textbf{réaffectable}. C'est la forme moderne recommandée pour les variables ordinaires.
  \item \texttt{const nom = valeur;} : portée \textbf{bloc}, valeur \textbf{non réaffectable} : l'initialisation est obligatoire et toute nouvelle affectation provoque une erreur.
\end{itemize}
Chaque instruction se termine par un point-virgule \texttt{;} (fortement recommandé).
\end{propriete}

\begin{exemplebox}[Déclarer et utiliser des variables]
\begin{lstlisting}[language=JavaScript]
let nomEleve = "Amina";      // variable texte, modifiable
let age = 16;                // variable numerique, modifiable
const TAUX_TVA = 19.25;      // constante : ne changera jamais

age = age + 1;               // reaffectation autorisee avec let
// TAUX_TVA = 20;            // ERREUR : impossible de reaffecter une const
var ancien = "style var";    // ancienne syntaxe, a eviter
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Règles de nommage des variables]
Le nom d'une variable JavaScript doit respecter des règles strictes :
\begin{itemize}
  \item il commence obligatoirement par une \textbf{lettre}, un \textbf{souligné} \texttt{\_} ou un \textbf{dollar} \texttt{\$} ; jamais par un chiffre (\texttt{2notes} est interdit) ;
  \item il ne contient ni espace, ni tiret, ni accent (préfère \texttt{noteMaths} à \texttt{note maths}) ;
  \item JavaScript est \textbf{sensible à la casse} : \texttt{moyenne}, \texttt{Moyenne} et \texttt{MOYENNE} sont trois variables \emph{différentes} ;
  \item les \textbf{mots réservés} du langage sont interdits : \texttt{let}, \texttt{const}, \texttt{var}, \texttt{function}, \texttt{if}, \texttt{else}, \texttt{for}, \texttt{while}, \texttt{return}, etc.
\end{itemize}
Par convention, on utilise la notation \emph{camelCase} : première lettre minuscule, puis une majuscule à chaque nouveau mot : \texttt{montantTotal}, \texttt{nombreEleves}.
\end{attention}

\courssub{Les types primitifs de données}

Contrairement à l'algorithmique scolaire où l'on déclare \texttt{Entier}, \texttt{Réel} ou \texttt{Chaîne}, JavaScript détermine \textbf{automatiquement} le type d'une variable à partir de la valeur qu'on lui affecte. On distingue sept \cle{types primitifs}.

\begin{definition}[Types primitifs]
Un \cle{type primitif} est une catégorie de valeurs simples (non composées d'objets). JavaScript en définit sept :
\begin{itemize}
  \item \texttt{Number} : tous les nombres, entiers ou décimaux (\texttt{42}, \texttt{3.14}, \texttt{-7}) ;
  \item \texttt{String} : les chaînes de caractères, entre guillemets simples ou doubles (\texttt{"Bonjour"}) ;
  \item \texttt{Boolean} : les valeurs logiques \texttt{true} ou \texttt{false} ;
  \item \texttt{Undefined} : valeur d'une variable déclarée mais jamais initialisée ;
  \item \texttt{Null} : absence volontaire de valeur (\texttt{let x = null;}) ;
  \item \texttt{Symbol} : identifiant unique (usage avancé) ;
  \item \texttt{BigInt} : entiers de taille arbitraire, notés avec un \texttt{n} final (\texttt{9007199254740993n}).
\end{itemize}
\end{definition}

L'opérateur \texttt{typeof} permet de \textbf{vérifier le type} d'une valeur ou d'une variable : il renvoie une chaîne indiquant le type.

Par une erreur historique conservée pour compatibilité, \texttt{typeof null} renvoie \texttt{"object"} et non \texttt{"null"}. Pour tester si une variable vaut \texttt{null}, on écrit directement \texttt{x === null}.
\end{attention}

\courssub{Le typage dynamique}

\begin{definition}[Typage dynamique]
JavaScript est un langage à \cle{typage dynamique} : le type d'une variable n'est pas fixé à la déclaration ; il dépend de la valeur qu'elle contient et peut \textbf{changer au cours de l'exécution}.
\end{definition}

\begin{exemplebox}[Une variable qui change de type]
\begin{lstlisting}[language=JavaScript]
let donnee = 25;            // donnee est un Number
alert(typeof donnee);       // affiche "number"

donnee = "vingt-cinq";      // la meme variable devient une String
alert(typeof donnee);       // affiche "string"

donnee = true;              // puis un Boolean
alert(typeof donnee);       // affiche "boolean"
\end{lstlisting}
Ce comportement est souple, mais dangereux : si tu perds de vue le type réel d'une variable, les opérations peuvent produire des résultats surprenants (voir la conversion implicite ci-dessous). En algorithmique classique, au contraire, le type est fixé une fois pour toutes à la déclaration.
\end{exemplebox}

\courssub{Les conversions de type}

Pourquoi convertir ? Parce que \textbf{toute saisie utilisateur} (via \texttt{prompt()} ou une zone de texte) arrive sous forme de \textbf{chaîne de caractères}. Si l'utilisateur tape \texttt{5000} pour un montant en FCFA, JavaScript reçoit la chaîne \texttt{"5000"}, pas le nombre $5000$. Avant tout calcul, il faut donc \emph{convertir}.

\textbf{Conversion explicite}\par

\begin{propriete}[Fonctions de conversion explicite]
\begin{itemize}
  \item \texttt{parseInt(chaine, base)} : convertit une chaîne en \textbf{nombre entier}. Le second argument est la base de numération (10 pour le décimal — toujours le préciser). La lecture s'arrête au premier caractère non numérique.
  \item \texttt{parseFloat(chaine)} : convertit une chaîne en \textbf{nombre décimal}.
  \item \texttt{Number(valeur)} : conversion générale en nombre ; renvoie \texttt{NaN} si la chaîne n'est pas entièrement numérique.
  \item \texttt{String(valeur)} : convertit en chaîne de caractères.
  \item \texttt{Boolean(valeur)} : convertit en booléen ; les valeurs \texttt{0}, \texttt{""} (chaîne vide), \texttt{null}, \texttt{undefined} et \texttt{NaN} deviennent \texttt{false}, tout le reste devient \texttt{true}.
\end{itemize}
\end{propriete}

\begin{methode}[Convertir une saisie utilisateur]
Pour récupérer un nombre saisi par l'utilisateur et pouvoir calculer avec :
\begin{enumerate}
  \item Appeler \texttt{prompt()} qui renvoie toujours une \textbf{chaîne} (ou \texttt{null} si l'utilisateur annule).
  \item Convertir immédiatement avec \texttt{parseFloat()} (nombre décimal) ou \texttt{parseInt(chaine, 10)} (entier).
  \item Tester le résultat avec \texttt{isNaN()} pour détecter une saisie invalide.
\end{enumerate}
Modèle à retenir : \texttt{let n = parseFloat(prompt('Entrez un nombre:'));}
\end{methode}

\begin{attention}[Erreurs fréquentes avec parseInt]
\texttt{parseInt('10px', 10)} renvoie \texttt{10} : la fonction lit les chiffres tant qu'elle le peut, puis s'arrête. En revanche, \texttt{parseInt('abc', 10)} renvoie \texttt{NaN} (\emph{Not a Number}) car aucun chiffre ne se trouve au début. \textbf{Toujours tester le résultat avec \texttt{isNaN()}} avant de calculer :
\begin{lstlisting}[language=JavaScript]
let n = parseInt(prompt('Entrez un entier:'), 10);
if (isNaN(n)) {
  alert('Saisie invalide !');
} else {
  alert('Le double est ' + (2 * n));
}
\end{lstlisting}
Autre piège : \texttt{parseInt('3.99', 10)} renvoie \texttt{3} (troncature, pas arrondi). Pour un montant en FCFA avec décimaux, utilise \texttt{parseFloat()}.
\end{attention}

\textbf{Conversion implicite}\par

JavaScript convertit parfois les types \textbf{automatiquement}, sans qu'on le demande. C'est la \cle{conversion implicite} (ou \emph{coercition}), source des bugs les plus classiques du débutant.

\begin{propriete}[Priorité de conversion]
\begin{itemize}
  \item Avec l'opérateur \texttt{+}, si \textbf{l'un des deux opérandes est une chaîne}, JavaScript convertit l'autre en chaîne et effectue une \textbf{concaténation} (collage des textes).
  \item Avec les opérateurs \texttt{-}, \texttt{*} et \texttt{/}, JavaScript convertit toujours les chaînes numériques en \textbf{Number} et effectue le calcul arithmétique.
\end{itemize}
\end{propriete}

\begin{exemplebox}[Exemple chiffré : le piège du +]
\begin{lstlisting}[language=JavaScript]
let a = '5';   // a est une CHAINE
let b = 2;     // b est un NOMBRE

alert(a + b);  // affiche "52" : concatenation, pas addition !
alert(a - b);  // affiche 3 : '5' est converti en 5, puis 5 - 2
alert(a * b);  // affiche 10
alert(a / b);  // affiche 2.5
alert(b + b);  // affiche 4 : deux nombres, vraie addition
\end{lstlisting}
Explication pas à pas de \texttt{a + b} : JavaScript voit que \texttt{a} est une chaîne ; il convertit donc \texttt{b} en chaîne \texttt{"2"} et colle les deux textes : \texttt{"5" + "2"} donne \texttt{"52"}. Pour obtenir $7$, il fallait écrire \texttt{parseFloat(a) + b}.
\end{exemplebox}

\begin{aretenir}[L'essentiel des conversions]
\begin{itemize}
  \item Une saisie \texttt{prompt()} est \textbf{toujours une chaîne} : convertis-la avant tout calcul.
  \item \texttt{+} avec une chaîne $\Rightarrow$ concaténation ; \texttt{-}, \texttt{*}, \texttt{/} $\Rightarrow$ conversion en nombre.
  \item \texttt{typeof} permet de vérifier le type d'une variable à tout moment.
  \item \texttt{isNaN()} permet de valider une conversion numérique.
\end{itemize}
\end{aretenir}

\begin{savaistu}[const ne rend pas tout immuable]
Beaucoup d'élèves croient qu'une variable déclarée \texttt{const} est totalement figée. En réalité, \texttt{const} verrouille seulement la \textbf{liaison} entre le nom et la valeur : on ne peut pas réaffecter le nom. Mais si la valeur est un \textbf{objet} ou un \textbf{tableau}, son contenu peut changer !
\begin{lstlisting}[language=JavaScript]
const eleve = { nom: "Amina", note: 14 };
eleve.note = 17;        // AUTORISE : on modifie une propriete
// eleve = { nom: "Bob" };  // ERREUR : reaffectation interdite
\end{lstlisting}
C'est comme une salle de classe (\texttt{const salle}) : on ne peut pas changer de salle, mais on peut déplacer les tables à l'intérieur.
\end{savaistu}

\begin{exoresolu}[Calcul du montant TTC d'un article]
\textbf{Énoncé.} Une boutique de Yaoundé vend un article hors taxe. Écris un script qui demande le prix hors taxe (en FCFA), applique une TVA constante de $19,25\,\%$, et affiche le montant TTC. On veillera à convertir la saisie et à vérifier sa validité.
\tcblower
\textbf{Solution détaillée.}
\begin{lstlisting}[language=JavaScript]
// Constante : le taux ne change jamais pendant l'execution
const TAUX_TVA = 19.25;

// 1. Saisie : prompt() renvoie une chaine, on convertit en nombre
let prixHT = parseFloat(prompt('Prix hors taxe (FCFA) :'));

// 2. Verification de la validite de la saisie
if (isNaN(prixHT)) {
  alert('Erreur : veuillez entrer un nombre valide.');
} else {
  // 3. Calcul : prixHT est bien un Number, pas de concatenation
  let montantTTC = prixHT * (1 + TAUX_TVA / 100);
  // 4. Affichage : ici le + est une concatenation volontaire
  alert('Montant TTC : ' + montantTTC + ' FCFA');
}
\end{lstlisting}
\textbf{Trace d'exécution} pour une saisie de \texttt{10000} : \texttt{prompt} renvoie la chaîne \texttt{"10000"}, \texttt{parseFloat} la convertit en $10000$ ; le calcul donne $10000 \times 1{,}1925 = 11925$ ; l'alerte affiche « Montant TTC : 11925 FCFA ». Sans \texttt{parseFloat}, l'expression \texttt{prixHT * (1 + TAUX\_TVA/100)} fonctionnerait encore (conversion implicite de \texttt{*}), mais \texttt{prixHT + 1925} aurait produit la chaîne \texttt{"100001925"} : d'où l'importance de convertir \emph{systématiquement} dès la saisie.
\end{exoresolu}

\begin{exercice}[À toi de jouer]
\begin{enumerate}
  \item Déclare une constante \texttt{TAUX\_CHANGE} valant $655{,}957$ (taux euro/FCFA) et une variable \texttt{montantEuro}. Demande à l'utilisateur un montant en euros, convertis-le correctement, puis affiche l'équivalent en FCFA.
  \item Prédis le résultat de chaque expression, puis vérifie dans la console du navigateur : \texttt{'3' + 4}, \texttt{'3' - 4}, \texttt{3 + '4' + 5}, \texttt{typeof NaN}, \texttt{Boolean('')}, \texttt{parseInt('12.9', 10)}.
  \item Explique pourquoi \texttt{let 1erPrix = 500;} provoque une erreur, et propose deux noms corrects.
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice : conversions et nommage]
\begin{enumerate}
  \item Script de conversion :
\begin{lstlisting}[language=JavaScript]
const TAUX_CHANGE = 655.957;
let montantEuro = parseFloat(prompt('Montant en euros :'));
if (isNaN(montantEuro)) {
  alert('Saisie invalide.');
} else {
  let montantFCFA = montantEuro * TAUX_CHANGE;
  alert(montantEuro + ' EUR = ' + montantFCFA + ' FCFA');
}
\end{lstlisting}
  \item \texttt{'3' + 4} $\Rightarrow$ \texttt{"34"} (concaténation) ; \texttt{'3' - 4} $\Rightarrow$ $-1$ (conversion en nombre) ; \texttt{3 + '4' + 5} $\Rightarrow$ \texttt{"345"} (le premier \texttt{+} produit la chaîne \texttt{"34"}, puis concaténation avec \texttt{5}) ; \texttt{typeof NaN} $\Rightarrow$ \texttt{"number"} (NaN est de type Number !) ; \texttt{Boolean('')} $\Rightarrow$ \texttt{false} ; \texttt{parseInt('12.9', 10)} $\Rightarrow$ $12$ (troncature).
  \item Un nom de variable ne peut pas commencer par un chiffre. Noms corrects : \texttt{premierPrix} ou \texttt{prix1}.
\end{enumerate}
\end{corrige}

Tu maîtrises désormais le stockage et la conversion des données : la matière première de tout script. Dans la section suivante, nous apprendrons à \emph{combiner} ces valeurs grâce aux \textbf{opérateurs} arithmétiques, de comparaison et logiques, pour construire de véritables expressions de calcul.

\coursec{Opérateurs et expressions}

Dans la section précédente, nous avons appris à \emph{déclarer des variables} et à y stocker des valeurs : un âge, un prix en FCFA, une température, un nom. Mais une variable qui ne sert qu'à stocker est comme une calculatrice dont on n'utiliserait que la mémoire : l'intérêt reste limité. Le véritable pouvoir d'un programme apparaît lorsqu'on \emph{combine} ces valeurs : calculer le total d'une facture au cybercafé, vérifier qu'un élève est admissible (moyenne $\geq 10$ \textbf{et} assiduité correcte), convertir des devises, incrémenter un compteur de visiteurs d'un site. Toutes ces actions reposent sur un même outil : les \cle{opérateurs}, qui permettent de construire des \cle{expressions}.

\begin{definition}[Expression et opérateur]
Une \cle{expression} est une combinaison de valeurs, de variables et d'\cle{opérateurs} que JavaScript \emph{évalue} pour produire un résultat. Un \cle{opérateur} est un symbole (ou un mot-clé) qui réalise une opération sur un ou plusieurs \emph{opérandes}. Par exemple, dans \texttt{3 + 4}, l'opérateur est \texttt{+} et les opérandes sont \texttt{3} et \texttt{4} ; l'expression s'évalue en \texttt{7}.
\end{definition}

\courssub{Les opérateurs arithmétiques}

Les opérateurs arithmétiques réalisent les calculs mathématiques usuels. Ce sont les premiers outils du programmeur : total d'une commande, moyenne des notes, conversion d'unités.

\begin{propriete}[Opérateurs arithmétiques de JavaScript]
\begin{center}
\begin{tabularx}{\linewidth}{|l|l|X|}
\hline
\rowcolor{popblueL} \textbf{Opérateur} & \textbf{Nom} & \textbf{Exemple (résultat)} \\
\hline
\texttt{+} & Addition & \texttt{7 + 2} donne \texttt{9} \\
\hline
\texttt{-} & Soustraction & \texttt{7 - 2} donne \texttt{5} \\
\hline
\texttt{*} & Multiplication & \texttt{7 * 2} donne \texttt{14} \\
\hline
\texttt{/} & Division & \texttt{7 / 2} donne \texttt{3.5} \\
\hline
\texttt{\%} & Reste de la division (modulo) & \texttt{7 \% 2} donne \texttt{1} \\
\hline
\texttt{Math.pow(a,b)} & Puissance (exponentiation) & \texttt{Math.pow(2,3)} donne \texttt{8} \\
\hline
\end{tabularx}
\end{center}
\end{propriete}

Deux de ces opérateurs méritent une attention particulière.

\textbf{Le modulo \texttt{\%}.} Il renvoie le \emph{reste} de la division entière. C'est l'outil roi pour tester la divisibilité : \texttt{n \% 2 === 0} est vrai si et seulement si \texttt{n} est pair. Au marché de Mokolo, si tu veux répartir 53 cahiers dans des cartons de 10, \texttt{53 \% 10} te donne les 3 cahiers restants.

\textbf{La puissance \texttt{Math.pow}.} Introduite récemment dans le langage, \texttt{Math.pow(a,b)} calcule $a^b$ : \texttt{Math.pow(5,2)} vaut \texttt{25}. Attention : la puissance est \emph{associative à droite}, c'est-à-dire que $2^{(3^2)} = 2^9 = 512$, et non $(2^3)^2 = 64$.

\begin{exemplebox}[Calculs arithmétiques commentés]
\begin{lstlisting}[language=JavaScript]
let prixUnitaire = 1500;   // prix d'un cahier en FCFA
let quantite = 7;
let total = prixUnitaire * quantite;   // 10500
let remise = total * 0.10;             // 10 % de remise : 1050
let net = total - remise;              // 9450
let reste = quantite % 2;              // 1 : quantite impaire
let surface = 3 ** 2;                  // 9 (carre de cote 3)
console.log(net);                      // affiche 9450
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Le piège du \texttt{+} avec les chaînes]
L'opérateur \texttt{+} a un double rôle : il \emph{additionne} les nombres mais \emph{concatène} (colle) les chaînes de caractères. Ainsi \texttt{"5" + 3} donne la chaîne \texttt{"53"}, et non \texttt{8} ! C'est pourquoi les valeurs lues avec \texttt{prompt()} — toujours des chaînes — doivent être converties avec \texttt{parseInt()} ou \texttt{parseFloat()} avant tout calcul, comme nous l'avons vu à la section 2.
\end{attention}

\courssub{Affectation composée, incrémentation et décrémentation}

Très souvent, on veut \emph{modifier} une variable à partir de sa valeur actuelle : ajouter un montant à un solde, retirer un article du stock, compter les visiteurs. JavaScript offre des raccourcis pour cela.

\begin{propriete}[Affectations composées]
Pour tout opérateur arithmétique $\oplus$, l'instruction \texttt{x $\oplus$= a} est équivalente à \texttt{x = x $\oplus$ a}. On dispose ainsi de \texttt{+=}, \texttt{-=}, \texttt{*=}, \texttt{/=}, \texttt{\%=} et \texttt{**=}.
\end{propriete}

\begin{exemplebox}[Solde d'un compte mobile money]
\begin{lstlisting}[language=JavaScript]
let solde = 5000;     // solde initial en FCFA
solde += 2000;        // depot : solde = 7000
solde -= 1500;        // retrait : solde = 5500
solde *= 2;           // doublement (jeu) : solde = 11000
solde /= 11;          // partage : solde = 1000
solde %= 300;         // reste : solde = 100
\end{lstlisting}
\end{exemplebox}

\textbf{Incrémentation et décrémentation.} Le cas particulier « ajouter 1 » ou « retirer 1 » est si fréquent (compteurs, boucles) qu'il possède ses propres opérateurs : \texttt{++} et \texttt{--}. Ils existent en deux positions :

\begin{itemize}
\item \textbf{Postfixée} (\texttt{x++}) : la variable est incrémentée, mais l'expression \emph{vaut l'ancienne valeur} ;
\item \textbf{Préfixée} (\texttt{++x}) : la variable est incrémentée, et l'expression \emph{vaut la nouvelle valeur}.
\end{itemize}

\begin{exemplebox}[Préfixe contre postfixe]
\begin{lstlisting}[language=JavaScript]
let a = 5;
let b = a++;   // b recoit 5, PUIS a devient 6
let c = 5;
let d = ++c;   // c devient 6, PUIS d recoit 6
// Resultat : a = 6, b = 5, c = 6, d = 6
let e = 10;
e--;           // e = 9 (equivalent a e = e - 1)
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Piège classique]
Dans une instruction seule, \texttt{x++;} et \texttt{++x;} ont le même effet. La différence n'apparaît que lorsque l'expression est \emph{utilisée} dans un calcul ou une affectation. Pour éviter toute confusion au Probatoire, utilise \texttt{x++} seul sur sa ligne et effectue les affectations séparément.
\end{attention}

\courssub{Les opérateurs de comparaison}

Un programme interactif doit pouvoir \emph{comparer} : la moyenne est-elle au moins égale à 10 ? Le mot de passe saisi est-il le bon ? Les comparaisons produisent un \emph{booléen} : \texttt{true} (vrai) ou \texttt{false} (faux).

\begin{propriete}[Opérateurs de comparaison]
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Opérateur} & \textbf{Signification} \\
\hline
\texttt{==} & Égalité \emph{simple} (avec conversion de type) \\
\hline
\texttt{===} & Égalité \emph{stricte} (même type \textbf{et} même valeur) \\
\hline
\texttt{!=} & Différent (avec conversion de type) \\
\hline
\texttt{!==} & Strictement différent \\
\hline
\texttt{>}, \texttt{<} & Supérieur, inférieur \\
\hline
\texttt{>=}, \texttt{<=} & Supérieur ou égal, inférieur ou égal \\
\hline
\end{tabularx}
\end{center}
\end{propriete}

\begin{attention}[\texttt{==} contre \texttt{===} : le piège de la coercition]
L'opérateur \texttt{==} effectue une \emph{conversion de type} (coercition) avant de comparer : \texttt{5 == "5"} vaut \texttt{true}, car la chaîne \texttt{"5"} est convertie en nombre ! Pire, \texttt{0 == false} et \texttt{"" == false} valent aussi \texttt{true}. L'opérateur \texttt{===}, lui, compare le \emph{type} \textbf{et} la \emph{valeur} : \texttt{5 === "5"} vaut \texttt{false}. \textbf{Règle d'or : privilégie toujours \texttt{===} et \texttt{!==}.} Et n'oublie jamais qu'un seul \texttt{=} est une \emph{affectation}, pas une comparaison : écrire \texttt{if (x = 5)} au lieu de \texttt{if (x === 5)} est l'une des erreurs les plus fréquentes des débutants.
\end{attention}

\courssub{Les opérateurs logiques : \texttt{\&\&}, \texttt{||}, \texttt{!}}

Les comparaisons seules ne suffisent pas : pour être admis au Probatoire, il faut une moyenne $\geq 10$ \emph{et} une conduite correcte ; pour payer en ligne, on utilise Orange Money \emph{ou} MTN MoMo. Les opérateurs logiques combinent plusieurs conditions booléennes.

\begin{propriete}[Opérateurs logiques]
\begin{itemize}
\item \texttt{a \&\& b} (ET logique) : vaut \texttt{true} seulement si \texttt{a} \textbf{et} \texttt{b} sont vrais ;
\item \texttt{a || b} (OU logique) : vaut \texttt{true} si \texttt{a} \textbf{ou} \texttt{b} (au moins l'un des deux) est vrai ;
\item \texttt{!a} (NON logique) : inverse la valeur, \texttt{!true} vaut \texttt{false}.
\end{itemize}
\end{propriete}

\begin{exemplebox}[Exemple chiffré complet]
\begin{lstlisting}[language=JavaScript]
let x = 5;
x += 3;                          // x = 8
let y = 2 ** 3;                  // y = 8
let z = (5 > 3) && (2 < 1);      // true && false  ->  z = false
let admis = (x >= 10) || (y === 8);  // false || true -> true
let mineur = !(x >= 18);         // !(false) -> true
\end{lstlisting}
\end{exemplebox}

\begin{propriete}[Théorème (admis) : évaluation paresseuse ou court-circuit]
JavaScript évalue les expressions logiques de gauche à droite et \emph{s'arrête dès que le résultat est connu} :
\begin{itemize}
\item dans \texttt{a \&\& b}, si \texttt{a} est \emph{falsy} (faux, \texttt{0}, \texttt{""}, \texttt{null}, \texttt{undefined}, \texttt{NaN}), alors \texttt{b} \textbf{n'est pas évalué} et le résultat est \texttt{a} ;
\item dans \texttt{a || b}, si \texttt{a} est \emph{truthy}, alors \texttt{b} \textbf{n'est pas évalué} et le résultat est \texttt{a}.
\end{itemize}
Ce comportement, appelé \cle{court-circuit}, est très utile : \texttt{age \&\& age >= 18} évite de tester une valeur absente.
\end{propriete}

\begin{savaistu}[L'opérateur \texttt{??} (nullish coalescing)]
Depuis la norme ES2020, JavaScript propose l'opérateur \texttt{??} : \texttt{a ?? b} renvoie \texttt{b} \emph{uniquement} si \texttt{a} vaut \texttt{null} ou \texttt{undefined} ; sinon il renvoie \texttt{a}. Contrairement à \texttt{||}, il ne déclenche pas le remplacement pour \texttt{0} ou \texttt{""}, qui sont des valeurs légitimes. Exemple : \texttt{let nom = saisie ?? "Visiteur";} affiche « Visiteur » seulement si rien n'a été saisi.
\end{savaistu}

\courssub{L'expression ternaire}

Pour choisir entre deux valeurs selon une condition, JavaScript offre une écriture compacte en une seule ligne.

\begin{propriete}[Opérateur ternaire]
La syntaxe \texttt{condition ? valeurSiVrai : valeurSiFaux} évalue la \texttt{condition} ; si elle est vraie, l'expression vaut \texttt{valeurSiVrai}, sinon elle vaut \texttt{valeurSiFaux}. C'est l'équivalent raccourci d'un \texttt{if...else} qui affecte une variable.
\end{propriete}

\begin{exemplebox}[Mention automatique]
\begin{lstlisting}[language=JavaScript]
let moyenne = 12.5;
let mention = (moyenne >= 10) ? "Admis" : "Ajourné";
// mention vaut "Admis"
let parite = (7 % 2 === 0) ? "pair" : "impair";   // "impair"
\end{lstlisting}
\end{exemplebox}

\courssub{Priorité des opérateurs}

Que vaut \texttt{2 + 3 * 4} ? Comme en mathématiques, JavaScript ne lit pas simplement de gauche à droite : chaque opérateur possède un \emph{niveau de priorité}. L'expression vaut $2 + (3 \times 4) = 14$, car \texttt{*} est prioritaire sur \texttt{+}.

\begin{propriete}[Priorité des opérateurs (de la plus forte à la plus faible)]
\begin{enumerate}
\item Groupement \texttt{( )} ; accès membre \texttt{.} et \texttt{[ ]}, \texttt{new} ;
\item Incrémentation \texttt{++}, \texttt{--} ;
\item Puissance \texttt{**} (associative à droite) ;
\item Multiplication \texttt{*}, division \texttt{/}, modulo \texttt{\%} ;
\item Addition \texttt{+}, soustraction \texttt{-} ;
\item Comparaisons \texttt{<}, \texttt{<=}, \texttt{>}, \texttt{>=} ;
\item Égalités \texttt{==}, \texttt{===}, \texttt{!=}, \texttt{!==} ;
\item ET logique \texttt{\&\&} ;
\item OU logique \texttt{||} ;
\item Ternaire \texttt{? :} ;
\item Affectations \texttt{=}, \texttt{+=}, \texttt{-=}, \texttt{*=}, \texttt{/=} \ldots
\end{enumerate}
En résumé : \texttt{**} avant \texttt{* /} avant \texttt{+ -} ; \texttt{\&\&} avant \texttt{||} ; l'affectation arrive \textbf{en dernier}.
\end{propriete}

\begin{methode}[Évaluer une expression complexe pas à pas]
Pour déterminer la valeur d'une expression sans se tromper :
\begin{enumerate}
\item \textbf{Repère} tous les opérateurs et classe-les par priorité ;
\item \textbf{Évalue} d'abord les parenthèses, puis les opérateurs de plus forte priorité ;
\item \textbf{Remplace} chaque sous-expression par sa valeur au fur et à mesure, en réécrivant l'expression simplifiée ;
\item \textbf{Termine} par l'affectation, toujours évaluée en dernier.
\end{enumerate}
En cas de doute, \textbf{parenthèse systématiquement} pour lever toute ambiguïté : écris \texttt{(a + b) * c} plutôt que \texttt{a + b * c} si tu veux additionner d'abord. Les parenthèses ne coûtent rien et rendent le code plus lisible.
\end{methode}

\begin{exoresolu}[Évaluation complète d'une expression]
Énoncé. Soit le programme suivant :
\begin{lstlisting}[language=JavaScript]
let a = 4, b = 3, c = 2;
let r = a + b * c ** 2 > 10 && a !== b ? "OUI" : "NON";
\end{lstlisting}
Déterminer la valeur de \texttt{r} en détaillant chaque étape.
\tcblower
Solution détaillée. On applique les priorités de la plus forte à la plus faible.
\begin{enumerate}
\item Puissance : \texttt{c ** 2} $= 2^2 = 4$. L'expression devient \texttt{a + b * 4 > 10 \&\& a !== b ? "OUI" : "NON"}.
\item Multiplication : \texttt{b * 4} $= 3 \times 4 = 12$. Il reste \texttt{a + 12 > 10 \&\& a !== b ? ...}.
\item Addition : \texttt{a + 12} $= 4 + 12 = 16$. Il reste \texttt{16 > 10 \&\& a !== b ? ...}.
\item Comparaison : \texttt{16 > 10} vaut \texttt{true}. Il reste \texttt{true \&\& a !== b ? ...}.
\item Égalité stricte : \texttt{a !== b}, c'est-à-dire \texttt{4 !== 3}, vaut \texttt{true}. Il reste \texttt{true \&\& true ? ...}.
\item ET logique : \texttt{true \&\& true} vaut \texttt{true}. Il reste \texttt{true ? "OUI" : "NON"}.
\item Ternaire : la condition est vraie, donc l'expression vaut \texttt{"OUI"}.
\item Affectation (en dernier) : \texttt{r} reçoit la valeur \texttt{"OUI"}.
\end{enumerate}
Conclusion : \texttt{r = "OUI"}. Remarque l'ordre : la puissance avant la multiplication, la multiplication avant l'addition, les comparaisons avant \texttt{\&\&}, et l'affectation tout à la fin.
\end{exoresolu}

\begin{experience}[TP : tester les opérateurs dans la console du navigateur]
\textbf{Objectif :} vérifier expérimentalement les priorités et le comportement des opérateurs.
\textbf{Matériel :} un ordinateur avec un navigateur (Chrome ou Firefox).
\begin{enumerate}
\item Ouvre un nouvel onglet, puis la console avec la touche \texttt{F12} (onglet \emph{Console}).
\item Tape \texttt{2 + 3 * 4} puis Entrée : observe \texttt{14}. Tape ensuite \texttt{(2 + 3) * 4} : observe \texttt{20}.
\item Teste la coercition : \texttt{5 == "5"} donne \texttt{true}, mais \texttt{5 === "5"} donne \texttt{false}.
\item Teste le court-circuit : \texttt{false \&\& alert("coucou")} n'affiche rien, alors que \texttt{true \&\& alert("coucou")} ouvre la boîte de dialogue.
\item Teste le ternaire : \texttt{let m = 8; m >= 10 ? "Admis" : "Ajourné"} affiche \texttt{"Ajourné"}.
\end{enumerate}
\textbf{Interprétation :} la console évalue chaque expression en respectant la pyramide de priorité ; le court-circuit empêche l'exécution de la seconde partie lorsque le résultat est déjà connu.
\end{experience}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Les opérateurs arithmétiques \texttt{+ - * /} construisent les calculs ; \texttt{\%} donne le reste et \texttt{Math.pow} la puissance.
\item \texttt{x += a} équivaut à \texttt{x = x + a} ; \texttt{++} et \texttt{--} ajoutent ou retirent 1 (préfixe : nouvelle valeur ; postfixe : ancienne valeur).
\item Privilégie \texttt{===} et \texttt{!==} : \texttt{==} convertit les types et réserve de mauvaises surprises.
\item \texttt{\&\&}, \texttt{||} et \texttt{!} combinent les conditions, avec évaluation en court-circuit.
\item Le ternaire \texttt{cond ? v1 : v2} remplace un \texttt{if...else} d'affectation.
\item Priorité : \texttt{**} avant \texttt{* /} avant \texttt{+ -} ; \texttt{\&\&} avant \texttt{||} ; l'affectation en dernier. En cas de doute : parenthèse !
\end{itemize}
\end{aretenir}

Ces opérateurs sont les briques élémentaires de tout calcul. Dans la section suivante, nous les assemblerons dans les \emph{structures de contrôle} — instructions séquentielles, conditionnelles et itératives — pour donner à nos programmes la capacité de décider et de répéter.

\coursec{Structures de contrôle : séquentielles, conditionnelles, itératives}

Dans la section précédente, nous avons appris à construire des \cle{expressions} à l'aide des opérateurs arithmétiques, de comparaison et logiques : nous savons désormais calculer une valeur, tester une égalité ou combiner plusieurs conditions. Mais une expression seule ne fait rien d'elle-même. Pour obtenir un véritable programme, il faut organiser les instructions dans le temps : les exécuter \emph{dans l'ordre}, n'en exécuter certaines \emph{que si} une condition est vraie, ou les \emph{répéter} tant qu'un objectif n'est pas atteint. C'est exactement le rôle des \cle{structures de contrôle}. Tu les as déjà rencontrées en algorithmique sous forme de pseudo-code (\texttt{Si...Alors}, \texttt{Pour...FinPour}, \texttt{Tant que...}) ; nous allons maintenant les traduire en JavaScript, presque mot à mot.

\courssub{La structure séquentielle : l'ordre naturel des instructions}

\begin{definition}[Instruction et séquence]
Une \cle{instruction} est un ordre élémentaire donné à l'ordinateur (affectation, affichage, appel de fonction). Un programme JavaScript est par défaut une \cle{structure séquentielle} : les instructions s'exécutent \textbf{les unes après les autres}, de haut en bas, dans l'ordre d'écriture. Chaque instruction se termine par un \cle{point-virgule} \texttt{;} (celui-ci est optionnel en fin de ligne, mais son usage systématique est fortement recommandé).
\end{definition}

\begin{exemplebox}[Une séquence simple]
\begin{lstlisting}[language=JavaScript]
let prix = 5000;              // instruction 1 : declaration
let quantite = 3;             // instruction 2
let total = prix * quantite;  // instruction 3 : utilise les deux precedentes
alert("Total : " + total + " FCFA");  // instruction 4 : affiche 15000
\end{lstlisting}
L'ordre compte : si l'on affichait \texttt{total} avant de l'avoir calculé, le résultat serait \texttt{undefined}. L'ordinateur est un exécutant discipliné mais sans imagination : il fait exactement ce qui est écrit, dans l'ordre où c'est écrit.
\end{exemplebox}

\begin{attention}[Le point-virgule oublié]
JavaScript tolère l'absence de \texttt{;} en fin de ligne, mais certains cas ambigus provoquent des erreurs difficiles à diagnostiquer. Règle d'or au lycée : \textbf{terminer systématiquement chaque instruction par un point-virgule}.
\end{attention}

\courssub{Les structures conditionnelles : \texttt{if}, \texttt{else if}, \texttt{else}}

\textbf{Intuition.} Le bureau d'un lycée affiche « Admis » si la moyenne est au moins 10, « Ajourné » sinon. Le programme doit \emph{choisir} entre plusieurs chemins : c'est la structure conditionnelle.

\begin{propriete}[Syntaxe de la conditionnelle]
\begin{lstlisting}[language=JavaScript]
if (condition1) {
    // instructions executees si condition1 est vraie
} else if (condition2) {
    // instructions si condition1 fausse ET condition2 vraie
} else {
    // instructions si aucune condition n'est vraie
}
\end{lstlisting}
La \texttt{condition} est une expression booléenne (qui vaut \texttt{true} ou \texttt{false}). Les accolades \texttt{\{} et \texttt{\}} délimitent un \cle{bloc} d'instructions. Les parties \texttt{else if} (répétables) et \texttt{else} (au plus une) sont facultatives.
\end{propriete}

\begin{exemplebox}[Appréciation d'une note]
\begin{lstlisting}[language=JavaScript]
let moyenne = parseFloat(prompt("Moyenne generale ?"));
if (moyenne >= 16) {
    alert("Excellent !");
} else if (moyenne >= 14) {
    alert("Bien");
} else if (moyenne >= 10) {
    alert("Passable : admis");
} else {
    alert("Insuffisant : ajourne");
}
\end{lstlisting}
Les conditions sont évaluées \textbf{dans l'ordre} : dès que l'une est vraie, son bloc s'exécute et les suivantes sont ignorées. Ainsi, pour une moyenne de 15, le test \texttt{moyenne >= 16} échoue, puis \texttt{moyenne >= 14} réussit : seul « Bien » est affiché.
\end{exemplebox}

\begin{attention}[Confondre \texttt{=} et \texttt{===}]
Écrire \texttt{if (note = 10)} au lieu de \texttt{if (note === 10)} ne teste rien : cela \emph{affecte} 10 à \texttt{note} et la condition est alors considérée comme vraie ! En JavaScript, la comparaison stricte s'écrit \texttt{===} (égalité de valeur \emph{et} de type). C'est l'erreur classique n°1 des débutants.
\end{attention}

\courssub{Le choix multiple : \texttt{switch / case / default}}

Quand une même variable doit être comparée à plusieurs valeurs précises (un jour de la semaine, un code de région, une option de menu), enchaîner les \texttt{else if} devient lourd. La structure \cle{switch} est plus lisible.

\begin{propriete}[Syntaxe du \texttt{switch}]
\begin{lstlisting}[language=JavaScript]
switch (expression) {
    case valeur1:
        // instructions si expression === valeur1
        break;
    case valeur2:
        // instructions si expression === valeur2
        break;
    default:
        // instructions si aucun cas ne correspond
}
\end{lstlisting}
La comparaison est \textbf{stricte} (\texttt{===}) : valeur et type doivent coïncider. Le mot-clé \texttt{break} est indispensable pour sortir du \texttt{switch} ; sans lui, l'exécution « tombe » dans le cas suivant (\emph{fall-through}).
\end{propriete}

\begin{exemplebox}[Menu d'un convertisseur]
\begin{lstlisting}[language=JavaScript]
let choix = parseInt(prompt("1: FCFA->Euro  2: Euro->FCFA"));
switch (choix) {
    case 1:
        alert("Conversion FCFA vers Euro");
        break;
    case 2:
        alert("Conversion Euro vers FCFA");
        break;
    default:
        alert("Choix invalide !");
}
\end{lstlisting}
Ici \texttt{parseInt} est crucial : \texttt{prompt} renvoie une chaîne de caractères, et \texttt{"1" === 1} est faux (comparaison stricte). Sans conversion, c'est le \texttt{default} qui s'exécuterait toujours.
\end{exemplebox}

\courssub{Les boucles : répéter sans se répéter}

\textbf{Intuition.} Un cybercafé de Yaoundé veut imprimer 30 factures numérotées. Écrire 30 fois la même instruction serait absurde : on écrit l'instruction \emph{une seule fois} dans une \cle{boucle}, et l'ordinateur la répète autant que nécessaire. Il existe trois formes de boucles, qui correspondent exactement aux structures vues en algorithmique.

\textbf{La boucle \texttt{for} : nombre d'itérations connu.}

\begin{propriete}[Syntaxe de \texttt{for}]
\begin{lstlisting}[language=JavaScript]
for (initialisation; condition; incrementation) {
    // corps de la boucle
}
\end{lstlisting}
\begin{enumerate}
\item L'\texttt{initialisation} s'exécute \textbf{une seule fois} au départ ;
\item la \texttt{condition} est testée \textbf{avant chaque tour} : si elle est fausse, la boucle s'arrête ;
\item le corps s'exécute, puis l'\texttt{incrémentation} s'exécute, et on retourne à l'étape 2.
\end{enumerate}
C'est la boucle typique lorsqu'on sait \emph{combien de fois} on veut répéter.
\end{propriete}

\begin{exemplebox}[Somme des 10 premiers entiers]
\begin{lstlisting}[language=JavaScript]
// Somme 1..10
let s = 0;
for (let i = 1; i <= 10; i++) {
    s += i;   // equivaut a s = s + i
}
console.log(s); // 55
\end{lstlisting}
Trace d'exécution : \texttt{i} vaut successivement 1, 2, \ldots, 10 ; à chaque tour \texttt{s} accumule la valeur de \texttt{i}. Quand \texttt{i} devient 11, la condition \texttt{i <= 10} est fausse et la boucle s'arrête. Résultat : $1+2+\cdots+10 = 55$.
\end{exemplebox}

\textbf{La boucle \texttt{while} : répéter tant qu'une condition est vraie.}

\begin{propriete}[Syntaxe de \texttt{while}]
\begin{lstlisting}[language=JavaScript]
while (condition) {
    // corps : execute tant que condition est vraie
}
\end{lstlisting}
Le test a lieu \textbf{avant} chaque itération : si la condition est fausse dès le départ, le corps ne s'exécute \emph{jamais}. On l'utilise quand le nombre de tours n'est pas connu à l'avance (saisie jusqu'à une valeur valide, division répétée, etc.).
\end{propriete}

\begin{exemplebox}[Saisie contrôlée d'une note]
\begin{lstlisting}[language=JavaScript]
let note = parseFloat(prompt("Note (0 a 20) ?"));
while (isNaN(note) || note < 0 || note > 20) {
    alert("Valeur incorrecte !");
    note = parseFloat(prompt("Note (0 a 20) ?"));
}
alert("Note enregistree : " + note);
\end{lstlisting}
On ne sait pas combien de fois l'utilisateur se trompera : le \texttt{while} est le bon outil. La fonction \texttt{isNaN} détecte le cas où la saisie n'est pas un nombre (par exemple si l'utilisateur tape « bonjour »).
\end{exemplebox}

\textbf{La boucle \texttt{do...while} : au moins une exécution.}

\begin{propriete}[Syntaxe de \texttt{do...while}]
\begin{lstlisting}[language=JavaScript]
do {
    // corps : execute AU MOINS une fois
} while (condition);
\end{lstlisting}
Le test a lieu \textbf{après} le corps : celui-ci s'exécute donc toujours au moins une fois. Idéal pour un menu que l'on affiche d'abord, puis que l'on réaffiche tant que l'utilisateur ne quitte pas. Attention au \texttt{;} final après la parenthèse !
\end{propriete}

\begin{exemplebox}[Menu répété]
\begin{lstlisting}[language=JavaScript]
let rep;
do {
    rep = prompt("Convertir encore ? (o/n)");
} while (rep !== "o" && rep !== "n");
\end{lstlisting}
La question est posée une première fois, puis reposée tant que la réponse n'est ni \texttt{"o"} ni \texttt{"n"}.
\end{exemplebox}

\textbf{Interrompre une boucle : \texttt{break} et \texttt{continue}.}

\begin{definition}[\texttt{break} et \texttt{continue}]
\begin{itemize}
\item \cle{break} : sort \textbf{immédiatement} de la boucle (ou du \texttt{switch}) ; l'exécution reprend après l'accolade fermante ;
\item \cle{continue} : abandonne le tour en cours et passe \textbf{directement à l'itération suivante} (le test et l'incrémentation sont effectués).
\end{itemize}
\end{definition}

\begin{exemplebox}[Recherche et filtrage]
\begin{lstlisting}[language=JavaScript]
// Cherche le premier multiple de 7 superieur a 50
for (let n = 51; ; n++) {
    if (n % 7 === 0) { alert("Trouve : " + n); break; } // 56
}
// Affiche les entiers de 1 a 10 sauf les multiples de 3
for (let i = 1; i <= 10; i++) {
    if (i % 3 === 0) continue;  // on saute 3, 6, 9
    console.log(i);
}
\end{lstlisting}
Dans la première boucle, la condition est volontairement vide (toujours vraie) : c'est le \texttt{break} qui assure la sortie dès que l'on trouve 56.
\end{exemplebox}

\begin{attention}[La boucle infinie]
Oublier l'incrémentation dans un \texttt{while} (\texttt{while (i <= 10) \{ s += i; \}} sans \texttt{i++}) ou écrire une condition toujours vraie (\texttt{for (let i = 1; i >= 1; i++)}) produit une \cle{boucle infinie} : la page se fige et le navigateur finit par proposer d'arrêter le script. \textbf{Règle de survie :} avant de lancer une boucle, vérifie toujours (1) que la variable de contrôle est initialisée, (2) qu'elle \emph{évolue} dans le corps, (3) que la condition finira par devenir fausse.
\end{attention}

\begin{propriete}[Portée de \texttt{let} dans les boucles]
Une variable déclarée avec \texttt{let} dans l'en-tête d'un \texttt{for} (\texttt{for (let i = ...)}) est \textbf{locale à la boucle} : elle n'existe pas après l'accolade fermante. De plus, \texttt{let} crée une \emph{nouvelle liaison} à chaque itération : si le corps définit une fonction qui utilise \texttt{i}, chaque fonction « se souvient » de la valeur de \texttt{i} à son tour (mécanisme de \emph{fermeture}). Avec l'ancien mot-clé \texttt{var}, une seule variable était partagée, source de bugs célèbres. Au lycée comme en pratique professionnelle : \textbf{toujours utiliser \texttt{let}} (ou \texttt{const} si la variable n'est pas réaffectée).
\end{propriete}

\begin{propriete}[Invariant de boucle (théorème admis)]
Un \cle{invariant de boucle} est une propriété qui reste vraie \emph{avant et après chaque itération}. Pour la somme des 10 premiers entiers, l'invariant est : « au début du tour numéro $k$, $s = 1+2+\cdots+(k-1)$ ». Vrai au départ ($s=0$), conservé à chaque tour, il garantit qu'à la sortie $s = 1+2+\cdots+10 = 55$ : la boucle est \emph{correcte}. Cette notion, fondamentale pour prouver les programmes, est ici admise et \textbf{non exigée au Probatoire}.
\end{propriete}

\courssub{Traduire un algorithme en JavaScript}

\begin{methode}[De l'algorithme au code JavaScript]
\begin{enumerate}
\item \textbf{Identifier les variables} : pour chaque \texttt{Variable x : ...} du pseudo-code, écrire \texttt{let x;} (avec \texttt{prompt} + \texttt{parseInt}/\texttt{parseFloat} pour les entrées).
\item \textbf{Repérer les conditions} : \texttt{Si...Alors...Sinon...FinSi} devient \texttt{if / else} avec accolades.
\item \textbf{Repérer les boucles} : \texttt{Pour i de 1 a n} devient \texttt{for (let i = 1; i <= n; i++)} ; \texttt{Tant que...} devient \texttt{while}.
\item \textbf{Traduire les sorties} : \texttt{Écrire(...)} devient \texttt{alert(...)}, \texttt{document.write(...)} ou \texttt{console.log(...)}.
\item \textbf{Tester mentalement} sur un petit exemple (table de trace) avant d'exécuter.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Table de multiplication d'un nombre]
Énoncé : traduis en JavaScript l'algorithme suivant, qui affiche la table de multiplication d'un entier $n$ saisi par l'utilisateur.
\begin{lstlisting}
Algorithme TableMultiplication
Variable n, i : Entier
Debut
    Ecrire("Entrez un entier : ")
    Lire(n)
    Pour i de 1 a 10 Faire
        Ecrire(n, " x ", i, " = ", n*i)
    FinPour
Fin
\end{lstlisting}
\tcblower
Solution détaillée : la variable \texttt{n} vient d'une saisie, donc \texttt{prompt} suivi de \texttt{parseInt} (étape 1) ; la boucle \texttt{Pour} devient un \texttt{for} de 1 à 10 inclus, d'où la condition \texttt{i <= 10} (étape 3) ; l'écriture devient \texttt{document.write} avec concaténation (étape 4).
\begin{lstlisting}[language=JavaScript]
let n = parseInt(prompt("Entrez un entier :"));
for (let i = 1; i <= 10; i++) {
    document.write(n + " x " + i + " = " + (n * i) + "<br>");
}
\end{lstlisting}
Vérification pour $n = 7$ : le premier tour affiche \texttt{7 x 1 = 7}, le dernier \texttt{7 x 10 = 70}, puis \texttt{i} vaut 11 et la boucle s'arrête. La correspondance ligne à ligne avec le pseudo-code est immédiate : c'est toute la force de l'algorithmique, qui rend le langage presque transparent.
\end{exoresolu}

\begin{savaistu}[La boucle \texttt{for...of} (ES6)]
Depuis la norme ECMAScript 2015 (ES6), JavaScript propose \texttt{for...of}, qui parcourt \textbf{directement les valeurs} d'un objet itérable (tableau, chaîne de caractères, \texttt{Map}) sans gérer d'indice :
\begin{lstlisting}[language=JavaScript]
let prenoms = ["Amina", "Biya", "Etoundi"];
for (let p of prenoms) {
    console.log(p);   // affiche chaque prenom, sans i !
}
\end{lstlisting}
Plus courte et moins sujette aux erreurs d'indices, elle coexiste avec le \texttt{for} classique, qui reste indispensable dès qu'on a besoin de la position ou d'un pas particulier.
\end{savaistu}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Par défaut, les instructions s'exécutent \textbf{séquentiellement}, chacune terminée par \texttt{;}.
\item \texttt{if / else if / else} choisit un chemin ; \texttt{switch} compare \textbf{strictement} (\texttt{===}) une expression à plusieurs valeurs, avec \texttt{break} pour sortir.
\item \texttt{for} : nombre de tours connu ; \texttt{while} : test avant, zéro exécution possible ; \texttt{do...while} : test après, \textbf{au moins une} exécution.
\item \texttt{break} sort de la boucle, \texttt{continue} saute au tour suivant.
\item Toute boucle doit avoir une condition de sortie atteignable : méfie-toi des boucles infinies !
\end{itemize}
\end{aretenir}

\begin{exercice}[À toi de jouer]
\begin{enumerate}
\item Écris un script qui demande un entier $n$ et affiche « pair » ou « impair » (opérateur \texttt{\%}).
\item Écris une boucle \texttt{while} qui calcule le plus petit entier $k$ tel que $2^k \ge 1000$.
\item Traduis en JavaScript : « Saisir l'âge ; si âge $< 18$ afficher "mineur", sinon si âge $\le 60$ afficher "adulte", sinon "senior" ».
\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice n°1]
\begin{lstlisting}[language=JavaScript]
let n = parseInt(prompt("Entrez un entier :"));
if (n % 2 === 0) {
    alert(n + " est pair");
} else {
    alert(n + " est impair");
}
\end{lstlisting}
\end{corrige}

\begin{corrige}[Exercice n°2]
\begin{lstlisting}[language=JavaScript]
let k = 0, p = 1;        // p = 2^k
while (p < 1000) {
    p = p * 2;           // on multiplie par 2
    k++;                 // et on compte
}
alert("k = " + k);       // k = 10 car 2^10 = 1024 >= 1000
\end{lstlisting}
Invariant : au début de chaque tour, $p = 2^k$. La boucle s'arrête dès que $p \ge 1000$, donc $k$ est bien le plus petit entier cherché.
\end{corrige}

\begin{corrige}[Exercice n°3]
\begin{lstlisting}[language=JavaScript]
let age = parseInt(prompt("Votre age ?"));
if (age < 18) {
    alert("mineur");
} else if (age <= 60) {
    alert("adulte");
} else {
    alert("senior");
}
\end{lstlisting}
\end{corrige}

\coursec{Fonctions et gestion d'événements (onclick)}

Dans la section précédente, tu as appris à traduire en JavaScript les structures de contrôle : séquences d'instructions, alternatives (\texttt{if}/\texttt{else}) et boucles (\texttt{while}, \texttt{for}). Tu peux donc déjà écrire des programmes complets. Mais imagine la situation suivante : dans le site de la boutique de ta famille, tu dois calculer la TVA de 19,25~\% à dix endroits différents de la page. Vas-tu recopier dix fois le même calcul ? Et si le taux change, vas-tu modifier dix lignes ? C'est exactement le problème que résolvent les \cle{fonctions} : écrire une fois un bloc d'instructions, lui donner un nom, et le réutiliser autant de fois que nécessaire. Mieux encore : grâce aux \cle{événements} comme le clic de souris, ces fonctions pourront être déclenchées par l'utilisateur, rendant enfin tes pages interactives.

\courssub{Déclaration et appel d'une fonction}

\begin{definition}[Fonction]
Une \cle{fonction} est un sous-programme réutilisable, identifié par un nom, qui regroupe un bloc d'instructions. Elle peut recevoir des données en entrée appelées \cle{paramètres}, et peut renvoyer un résultat grâce au mot-clé \texttt{return}. Tant qu'elle n'est pas \emph{appelée}, une fonction ne s'exécute pas : sa déclaration ne fait que la mémoriser.
\end{definition}

\begin{propriete}[Syntaxe de déclaration d'une fonction]
\begin{lstlisting}[language=JavaScript]
function nomDeLaFonction(parametre1, parametre2) {
    // instructions
    return resultat; // facultatif
}
\end{lstlisting}
Règles à respecter :
\begin{itemize}
\item le mot-clé \texttt{function} est obligatoire, suivi du nom de la fonction (mêmes règles que pour les variables : lettres, chiffres, \texttt{\_}, sans commencer par un chiffre) ;
\item les parenthèses sont obligatoires, même sans paramètre : \texttt{function saluer() \{ ... \}} ;
\item les accolades délimitent le \emph{corps} de la fonction ;
\item \texttt{return} renvoie une valeur et \textbf{arrête immédiatement} l'exécution de la fonction : toute instruction placée après un \texttt{return} exécuté est ignorée ;
\item sans \texttt{return}, la fonction renvoie la valeur spéciale \texttt{undefined}.
\end{itemize}
\end{propriete}

\begin{exemplebox}[Une fonction qui calcule un carré]
\begin{lstlisting}[language=JavaScript]
// Declaration de la fonction
function carre(x) {
    return x * x;
}

// Appels de la fonction
alert(carre(7));        // affiche 49
let aire = carre(12);   // aire vaut 144
alert(carre(2) + carre(3)); // affiche 13
\end{lstlisting}
L'\emph{appel} consiste à écrire le nom suivi des \cle{arguments} entre parenthèses : \texttt{carre(7)}. La valeur 7 est copiée dans le paramètre \texttt{x}, le corps s'exécute, et le résultat 49 remplace l'appel dans l'expression.
\end{exemplebox}

\begin{attention}[Paramètre et argument : ne pas confondre]
Le \cle{paramètre} est la variable déclarée dans l'en-tête (\texttt{x} dans \texttt{function carre(x)}). L'\cle{argument} est la valeur concrète fournie lors de l'appel (\texttt{7} dans \texttt{carre(7)}). Autre piège classique : écrire \texttt{carre} sans parenthèses ne \emph{lance pas} la fonction, cela désigne la fonction elle-même comme une valeur.
\end{attention}

\begin{propriete}[Hoisting (remontée des déclarations)]
Les déclarations de fonctions avec le mot-clé \texttt{function} sont \emph{remontées} (hoisted) en haut de leur portée par le moteur JavaScript : on peut donc appeler une fonction \textbf{avant} sa déclaration dans le code. En revanche, les expressions de fonction affectées à \texttt{let} ou \texttt{const} sont remontées mais restent dans la \emph{zone morte temporelle} (TDZ) jusqu'à leur initialisation : les appeler avant leur définition provoque une erreur \texttt{ReferenceError}.
\begin{lstlisting}[language=JavaScript]
direBonjour(); // OK : declaration remontee
function direBonjour() { alert("Bonjour !"); }

doubler(5); // ERREUR ReferenceError : const en TDZ ici
const doubler = function(x) { return x * 2; };
\end{lstlisting}
\end{propriete}

\courssub{Expressions de fonction et fonctions fléchées}

\begin{savaistu}[Les fonctions sont des valeurs de première classe]
En JavaScript, une fonction est une valeur comme une autre : on peut l'\emph{affecter} à une variable, la \emph{passer en argument} à une autre fonction, et même la \emph{retourner} comme résultat. On dit que les fonctions sont des \og objets de première classe \fg{}. C'est l'une des grandes forces du langage, et c'est ce qui rend possible la gestion des événements : on donne une fonction au navigateur pour qu'il l'exécute plus tard, au moment du clic.
\end{savaistu}

\begin{definition}[Fonction anonyme et expression de fonction]
Une \cle{fonction anonyme} est une fonction sans nom. Une \cle{expression de fonction} consiste à créer une fonction (souvent anonyme) et à l'affecter à une variable :
\begin{lstlisting}[language=JavaScript]
const f = function(x) {
    return x * 2;
};
alert(f(21)); // affiche 42
\end{lstlisting}
Depuis la norme ES6 (2015), on dispose d'une écriture plus courte : la \cle{fonction fléchée} (\emph{arrow function}) :
\begin{lstlisting}[language=JavaScript]
const double = x => x * 2;          // un seul parametre, return implicite
const somme = (a, b) => a + b;      // plusieurs parametres : parentheses
const saluer = () => alert("Salut !"); // aucun parametre : parentheses vides

// Forme avec bloc : le return redevient obligatoire
const maxi = (a, b) => {
    if (a > b) { return a; }
    return b;
};
\end{lstlisting}
Si le corps tient en une seule expression, on omet les accolades et le mot \texttt{return} (retour implicite).
\end{definition}

\courssub{Portée des variables et passage des arguments}

\begin{definition}[Portée locale]
Les paramètres et les variables déclarées avec \texttt{let} ou \texttt{const} \emph{à l'intérieur} d'une fonction sont \cle{locales} : elles n'existent que pendant l'exécution de la fonction et sont invisibles à l'extérieur. Une variable déclarée hors de toute fonction est \cle{globale} : accessible partout. Une fonction peut lire une variable globale ; on parle de \cle{fermeture} (\emph{closure}) lorsqu'une fonction \og se souvient \fg{} des variables de l'environnement où elle a été créée, même après la fin de cet environnement.
\end{definition}

\begin{exemplebox}[Portée locale et closure]
\begin{lstlisting}[language=JavaScript]
function compteur() {
    let n = 0;                 // variable locale
    return function() {        // fonction anonyme retournee
        n = n + 1;             // elle "se souvient" de n : closure
        return n;
    };
}
const clic = compteur();
alert(clic()); // 1
alert(clic()); // 2 : n a ete conserve entre les appels
\end{lstlisting}
\end{exemplebox}

\begin{propriete}[Passage par valeur et par référence]
\begin{itemize}
\item Les types \emph{primitifs} (nombres, chaînes, booléens) sont passés \textbf{par valeur} : la fonction reçoit une copie ; modifier le paramètre ne modifie pas la variable de l'appelant.
\item Les \emph{objets} (tableaux, objets) sont passés \textbf{par référence} (plus précisément : la référence est passée par valeur) : la fonction reçoit l'adresse de l'objet ; modifier son \emph{contenu} à l'intérieur de la fonction modifie l'objet original.
\end{itemize}
\begin{lstlisting}[language=JavaScript]
function essai(nombre, tableau) {
    nombre = 99;        // ne modifie que la copie locale
    tableau[0] = 99;    // modifie le tableau original !
}
let a = 5;
let t = [1, 2, 3];
essai(a, t);
alert(a);    // 5 : inchange (passage par valeur)
alert(t[0]); // 99 : modifie (passage par reference)
\end{lstlisting}
\end{propriete}

\courssub{Gestion des événements : onclick et addEventListener}

Voici enfin la clé de l'interactivité. Jusqu'ici, ton code s'exécutait au chargement de la page. Avec les \cle{événements}, le navigateur \emph{surveille} les actions de l'utilisateur (clic, saisie, survol...) et exécute la fonction que tu as associée à chaque action.

\begin{definition}[Événement et gestionnaire d'événement]
Un \cle{événement} est un signal émis par le navigateur lorsqu'une action se produit sur la page (clic, frappe au clavier, chargement terminé...). Un \cle{gestionnaire d'événement} (\emph{listener}) est la fonction que l'on associe à cet événement pour y répondre. L'événement de clic se nomme \texttt{click} ; l'attribut HTML correspondant est \texttt{onclick}.
\end{definition}

Il existe deux façons d'associer une fonction à un clic :

\begin{lstlisting}[language=HTML]
<!-- Methode 1 : attribut HTML (simple mais deconseillee) -->
<button onclick="convertir()">Convertir</button>

<!-- Methode 2 : addEventListener (bonne pratique) -->
<button id="btn">Convertir</button>
<script>
    function convertir() {
        alert("Conversion en cours...");
    }
    document.getElementById('btn').addEventListener('click', convertir);
</script>
\end{lstlisting}

\begin{methode}[Associer proprement une fonction à un bouton]
\begin{enumerate}
\item Dans le HTML, donner un \texttt{id} unique au bouton : \texttt{<button id="btn">}.
\item Dans le script, définir la fonction de traitement, par exemple \texttt{function convertir() \{ ... \}}.
\item Récupérer l'élément : \texttt{document.getElementById('btn')}.
\item Brancher l'écouteur : \texttt{.addEventListener('click', convertir);} — attention, on écrit \texttt{convertir} \textbf{sans parenthèses} : on \emph{transmet} la fonction, on ne l'appelle pas.
\item Placer le script en fin de \texttt{<body>} pour que le bouton existe déjà au moment du branchement.
\end{enumerate}
\end{methode}

\begin{attention}[\texttt{convertir} ou \texttt{convertir()} ?]
Écrire \texttt{addEventListener('click', convertir())} appelle la fonction \emph{immédiatement} au chargement et branche son résultat (souvent \texttt{undefined}) : le clic ne fera plus rien. Il faut passer la \emph{référence} de la fonction : \texttt{addEventListener('click', convertir)}.
\end{attention}

\begin{attention}[Le mot-clé \texttt{this} dans les gestionnaires]
Dans un gestionnaire écrit avec \texttt{function} classique, \texttt{this} désigne \textbf{l'élément HTML cible} du clic (le bouton). Avec une fonction fléchée, \texttt{this} désigne le contexte lexical englobant (souvent \texttt{window}), donc \emph{pas} le bouton. Pour modifier le bouton cliqué, préfère une \texttt{function} classique ou utilise \texttt{event.target}.
\end{attention}

\begin{definition}[L'objet \texttt{event}]
Lors d'un événement, le navigateur crée un objet \texttt{event} (souvent noté \texttt{e}) qu'il transmet au gestionnaire. Propriétés utiles :
\begin{itemize}
\item \texttt{e.target} : l'élément HTML qui a déclenché l'événement ;
\item \texttt{e.type} : le nom de l'événement (\texttt{"click"}) ;
\item \texttt{e.preventDefault()} : annule le comportement par défaut (par exemple l'envoi d'un formulaire ou la navigation d'un lien).
\end{itemize}
\begin{lstlisting}[language=JavaScript]
document.getElementById('btn').addEventListener('click', function(e) {
    alert("Clic sur : " + e.target.id + " (evenement " + e.type + ")");
});
\end{lstlisting}
\end{definition}

\begin{propriete}[Bonne pratique : séparer HTML et JavaScript]
Préfère \texttt{addEventListener} à l'attribut \texttt{onclick} : le code HTML décrit la structure, le code JavaScript décrit le comportement. Cette séparation rend le site plus lisible, plus facile à maintenir, et évite de multiplier les fonctions globales inutiles. Regroupe tes scripts en fin de \texttt{<body>} ou dans un fichier \texttt{.js} externe lié par \texttt{<script src="script.js"></script>}.
\end{propriete}

\begin{exoresolu}[Un bouton qui calcule la TVA]
Énoncé : écrire une page contenant un bouton \og Calculer la TVA \fg{}. Au clic, la page demande un prix hors taxe (en FCFA) via \texttt{prompt()}, calcule la TVA de 19,25~\% à l'aide d'une fonction \texttt{tva(montant)}, puis affiche le montant de la TVA avec \texttt{alert()}.
\tcblower
Solution détaillée :
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html lang="fr">
<head>
    <meta charset="UTF-8">
    <title>Calcul de TVA</title>
</head>
<body>
    <button id="btnTva">Calculer la TVA</button>

    <script>
        // 1. Declaration de la fonction de calcul
        function tva(montant) {
            return montant * 0.1925;
        }

        // 2. Gestionnaire d'evenement
        function calculer() {
            let saisie = prompt("Prix hors taxe (FCFA) :");
            // Attention : parseFloat attend un point decimal, pas une virgule
            let prix = parseFloat(saisie.replace(',', '.')); 
            if (isNaN(prix)) {
                alert("Veuillez saisir un nombre valide.");
            } else {
                alert("TVA = " + tva(prix) + " FCFA");
            }
        }

        // 3. Branchement de l'evenement click
        document.getElementById('btnTva').addEventListener('click', calculer);
    </script>
</body>
</html>
\end{lstlisting}
Trace d'exécution : l'utilisateur clique, saisit \texttt{100000} ; \texttt{parseFloat} donne $100000$ ; \texttt{tva(100000)} renvoie $100000 \times 0{,}1925 = 19250$ ; la boîte affiche \og TVA = 19250 FCFA \fg{}.
\end{exoresolu}

\begin{attention}[parseFloat et le séparateur décimal]
En JavaScript, \texttt{parseFloat} (et \texttt{parseInt}) ne reconnaissent que le \textbf{point} comme séparateur décimal. Au Cameroun, on utilise la virgule (ex. \texttt{1500,50}). Si l'utilisateur tape une virgule, \texttt{parseFloat("1500,50")} renverra \texttt{1500} (il s'arrête à la virgule). \textbf{Solution} : remplacer la virgule par un point avant conversion : \texttt{parseFloat(saisie.replace(',', '.'))}. Cette astuce sera indispensable pour vos convertisseurs de la section 6.
\end{attention}

\item Crée une page avec deux boutons partageant le même gestionnaire : au clic, affiche l'\texttt{id} du bouton cliqué grâce à \texttt{event.target}.
\item Que vaut \texttt{a} après l'exécution de \texttt{function f(x)\{x=0;\}} puis \texttt{let a=8; f(a);} ? Justifie avec la notion de passage par valeur.
\end{enumerate}
\end{exercice}

\begin{enumerate}

\item On écrit un seul gestionnaire \texttt{function qui(e)\{ alert(e.target.id); \}} que l'on branche sur chaque bouton avec \texttt{addEventListener('click', qui)}.
\item \texttt{a} vaut toujours 8 : le nombre est passé par valeur, la fonction ne modifie que sa copie locale \texttt{x}.
\end{enumerate}
\end{corrige}

\begin{aretenir}[L'essentiel de la section]
Une fonction se déclare avec \texttt{function}, \texttt{const f = function(...)} ou la forme fléchée \texttt{const f = x => ...}. Elle s'exécute uniquement lorsqu'on l'\emph{appelle}. Les déclarations \texttt{function} sont remontées (hoisting), pas les expressions \texttt{const} (zone morte temporelle). Les variables locales sont invisibles hors de la fonction ; les primitifs sont passés par valeur, les objets par référence. Enfin, l'interactivité repose sur les événements : \texttt{addEventListener('click', maFonction)} associe une fonction à un clic, et l'objet \texttt{event} renseigne sur l'action de l'utilisateur. Tu disposes maintenant de toutes les briques pour construire, dans la prochaine section, de véritables convertisseurs interactifs en maîtrisant \texttt{prompt()}, \texttt{alert()}, \texttt{confirm()}, \texttt{parseInt()}, \texttt{parseFloat()} et \texttt{document.write()}.
\end{aretenir}

\coursec{Entrées/Sorties et réalisation de convertisseurs pratiques}

Après avoir maîtrisé la déclaration de fonctions et la gestion de l'événement \texttt{onclick} (section 5), nous disposons désormais de tous les outils pour construire des applications web interactives complètes. Une application, aussi simple soit-elle, suit invariablement le schéma \textbf{Entrée $\rightarrow$ Traitement $\rightarrow$ Sortie}. Cette section explore en profondeur les mécanismes natifs d'entrée/sortie de JavaScript, les bonnes pratiques de manipulation du DOM pour l'affichage, et aboutit à la conception rigoureuse de trois convertisseurs pratiques : devises, températures et dates.

\courssub{Boîtes de dialogue natives : \texttt{prompt}, \texttt{alert}, \texttt{confirm}}

Historiquement, JavaScript propose trois méthodes bloquantes (modales) appartenant à l'objet \texttt{window} (souvent omis) pour interagir avec l'utilisateur sans formulaire HTML. Elles sont utiles pour des scripts pédagogiques, des tests rapides ou des confirmations critiques, mais leur aspect visuel est imposé par le navigateur et non personnalisable.

\begin{definition}[Boîtes de dialogue natives]
\begin{itemize}
    \item \textbf{\texttt{prompt(message, defaut)} :} Affiche une boîte avec un champ de saisie. Renvoie la \textbf{chaîne de caractères} saisie, ou \texttt{null} si l'utilisateur annule. Le second argument (optionnel) pré-remplit le champ.
    \item \textbf{\texttt{alert(message)} :} Affiche un message d'information avec un bouton « OK ». Ne renvoie aucune valeur (\texttt{undefined}). Bloque l'exécution du script jusqu'à la fermeture.
    \item \textbf{\texttt{confirm(question)} :} Affiche une boîte avec « OK » et « Annuler ». Renvoie un \textbf{booléen} : \texttt{true} si OK, \texttt{false} si Annuler.
\end{itemize}
\end{definition}

\begin{exemplebox}[Utilisation basique des boîtes natives]
\begin{lstlisting}[language=JavaScript]
// 1. Saisie d'un nom (chaîne)
let nom = prompt("Entrez votre nom :", "Visiteur");
if (nom !== null && nom.trim() !== "") {
    alert("Bienvenue " + nom + " !");
} else {
    alert("Aucun nom saisi.");
}

// 2. Confirmation avant action irréversible
let confirmation = confirm("Voulez-vous vraiment supprimer ce fichier ?");
if (confirmation) {
    // code de suppression...
    alert("Fichier supprimé.");
} else {
    alert("Suppression annulée.");
}
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Pièges de \texttt{prompt} et conversions]
\texttt{prompt} renvoie \textbf{toujours une chaîne} (\texttt{string}), même si l'utilisateur tape des chiffres. Toute opération arithmétique (+, -, *, /) sur cette chaîne sans conversion préalable provoquera une concaténation (pour +) ou une conversion implicite hasardeuse (pour -, *, /).
\begin{lstlisting}[language=JavaScript]
let a = prompt("Nombre A :"); // ex. "10"
let b = prompt("Nombre B :"); // ex. "5"
alert(a + b); // Affiche "105" (concaténation !) et non 15.
\end{lstlisting}
\emph{Solution :} Convertir explicitement avec \texttt{Number()}, \texttt{parseInt()} ou \texttt{parseFloat()} (voir 6.2).
\end{attention}

\courssub{Écriture dans le document : \texttt{document.write} vs manipulation du DOM}

\begin{propriete}[\texttt{document.write(texte)}]
Écrit directement dans le flux HTML \textbf{pendant le chargement initial de la page} (parsing). Si elle est appelée \textbf{après} le chargement complet (ex. dans un gestionnaire d'événement \texttt{onclick}), elle \textbf{écrase intégralement le document} (page blanche) et y écrit le nouveau contenu. À proscrire dans les applications interactives modernes.
\end{propriete}

\begin{aretenir}[Bonnes pratiques d'affichage (DOM)]
Pour modifier le contenu d'une page déjà chargée, on sélectionne un élément HTML (via \texttt{id}, \texttt{class}, \texttt{tag}) et on modifie ses propriétés :
\begin{itemize}
    \item \texttt{element.textContent = "texte"} : Insère du \textbf{texte pur} (échappe les balises HTML, sécurisé contre XSS). \textbf{Préféré par défaut}.
    \item \texttt{element.innerHTML = "<b>HTML</b>"} : Interprète la chaîne comme du HTML. Utile pour injecter une structure complexe, mais \textbf{dangereux} si la chaîne provient d'une saisie utilisateur non validée (failles XSS).
    \item \texttt{element.value = "valeur"} : Modifie la valeur d'un champ de formulaire (\texttt{<input>}, \texttt{<select>}, \texttt{<textarea>}).
\end{itemize}
\end{aretenir}

\begin{exemplebox}[Manipulation moderne du DOM (à privilégier)]
\begin{lstlisting}[language=HTML]
<!-- HTML -->
<p id="message">Contenu initial</p>
<input type="text" id="champSaisie" placeholder="Tapez ici">
<button onclick="mettreAJour()">Mettre à jour</button>

<script>
function mettreAJour() {
    // 1. Récupération des éléments
    let zoneAffichage = document.getElementById("message");
    let champ = document.getElementById("champSaisie");

    // 2. Lecture de la valeur saisie (ENTRÉE)
    let saisie = champ.value; // Toujours une chaîne

    // 3. Traitement (ex: mise en majuscules)
    let resultat = saisie.toUpperCase();

    // 4. Affichage (SORTIE) - Sécurisé
    zoneAffichage.textContent = "Vous avez tapé : " + resultat;
    
    // 5. Bonus : vider le champ après action
    champ.value = "";
}
</script>
\end{lstlisting}
\end{exemplebox}

\courssub{Conversions de type : \texttt{Number}, \texttt{parseInt}, \texttt{parseFloat}}

Le passage de \texttt{string} (saisie) à \texttt{number} (calcul) est l'opération la plus critique en JavaScript.

\begin{propriete}[Fonctions de conversion vers nombre]
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}\hline
\textbf{Fonction} & \textbf{Comportement} & \textbf{Renvoie} \\\hline
\texttt{Number(chaine)} & Conversion stricte. Espaces ignorés. Échoue si format invalide. & \texttt{number} ou \texttt{NaN} \\\hline
\texttt{parseInt(chaine, base)} & Analyse depuis le début, s'arrête au 1er caractère non numérique. Base 10 par défaut (mais \textbf{toujours préciser la base 10}). & \texttt{integer} ou \texttt{NaN} \\\hline
\texttt{parseFloat(chaine)} & Analyse depuis le début, accepte \textbf{un} point décimal, s'arrête au 1er caractère invalide. Ignore espaces initiaux. & \texttt{float} ou \texttt{NaN} \\\hline
\end{tabularx}
\end{center}
\end{propriete}

\begin{propriete}[Cas particuliers de \texttt{parseFloat}]
\begin{itemize}
    \item \texttt{parseFloat("  12.34  ")} $\rightarrow$ \texttt{12.34} (espaces ignorés).
    \item \texttt{parseFloat("12.34.56")} $\rightarrow$ \texttt{12.34} (s'arrête au 2e point).
    \item \texttt{parseFloat("12px")} $\rightarrow$ \texttt{12} (utile pour CSS).
    \item \texttt{parseFloat("abc")} $\rightarrow$ \texttt{NaN}.
\end{itemize}
\end{propriete}

\begin{exemplebox}[Conversion robuste pour un convertisseur]
\begin{lstlisting}[language=JavaScript]
function lireNombre(idChamp) {
    let champ = document.getElementById(idChamp);
    let brut = champ.value.trim(); // Supprime espaces début/fin
    
    if (brut === "") return null; // Champ vide
    
    // parseFloat gère virgule ou point selon locale ? 
    // ATTENTION : JS standard n'accepte QUE le point '.' comme séparateur décimal.
    // Remplacer la virgule par un point si utilisateur FR :
    let normalise = brut.replace(/,/g, '.'); 
    
    let nombre = parseFloat(normalise);
    
    if (isNaN(nombre)) {
        alert("Veuillez entrer un nombre valide (ex: 12.5 ou 12,5).");
        champ.focus();
        return null;
    }
    return nombre;
}
\end{lstlisting}
\end{exemplebox}

\courssub{Théorie des conversions linéaires : fonctions affines}

\begin{propriete}[Modèle mathématique des conversions d'unités]
Toute conversion entre deux échelles proportionnelles (devises, longueurs, masses) ou affine (températures °C/°F) s'exprime par une \textbf{fonction affine} :
\[ f(x) = a \cdot x + b \]
\begin{itemize}
    \item \textbf{Conversion proportionnelle (devise, m $\leftrightarrow$ km) :} $b = 0$. $a = \text{taux}$.
    \item \textbf{Conversion affine (température) :} $a = \frac{9}{5}$, $b = 32$ pour °C $\rightarrow$ °F.
\end{itemize}
La programmation consiste à identifier les coefficients $a$ et $b$ pour chaque paire d'unités.
\end{propriete}

\courssub{Convertisseur de devises : FCFA $\leftrightarrow$ EUR}

Le taux de change officiel (zone CEMAC) est fixe : \textbf{1 EUR = 655,957 FCFA} (arrondi souvent à 655,96 pour l'affichage).

\begin{methode}[Créer un convertisseur de devises générique]
\begin{enumerate}
    \item Définir la constante \texttt{TAUX} (FCFA pour 1 EUR).
    \item Créer une fonction \texttt{convertirDevise(montant, sens)} où \texttt{sens} vaut \texttt{"FCFA\_VERS\_EUR"} ou \texttt{"EUR\_VERS\_FCFA"}.
    \item Appliquer la formule : 
    \begin{itemize}
        \item FCFA $\rightarrow$ EUR : $montant / TAUX$
        \item EUR $\rightarrow$ FCFA : $montant \times TAUX$
    \end{itemize}
    \item Formater le résultat (2 décimales pour EUR, 0 ou 3 pour FCFA) avec \texttt{toFixed(n)}.
\end{enumerate}
\end{methode}

\begin{exemplebox}[Code complet : Convertisseur FCFA/EUR]
\begin{lstlisting}[language=JavaScript]
const TAUX_EUR_FCFA = 655.957; // 1 EUR = 655.957 FCFA

/**
 * Convertit un montant entre FCFA et EUR.
 * @param {number} montant - Valeur numérique positive.
 * @param {string} sens - "FCFA_EUR" ou "EUR_FCFA".
 * @returns {string} - Résultat formaté avec unité.
 */
function convertirDevise(montant, sens) {
    let resultat;
    let unite;
    
    if (sens === "FCFA_EUR") {
        resultat = montant / TAUX_EUR_FCFA;
        unite = " EUR";
        // Arrondi à 2 décimales (centimes d'euro)
        return resultat.toFixed(2) + unite;
    } 
    else if (sens === "EUR_FCFA") {
        resultat = montant * TAUX_EUR_FCFA;
        unite = " FCFA";
        // Arrondi à l'entier (pas de centime FCFA) ou 3 décimales
        return Math.round(resultat).toLocaleString('fr-FR') + unite;
    }
    return "Sens invalide";
}

// Test console
console.log(convertirDevise(10000, "FCFA_EUR")); // "15.24 EUR"
console.log(convertirDevise(15.24, "EUR_FCFA")); // "10 000 FCFA" (approx)
\end{lstlisting}
\end{exemplebox}

\courssub{Convertisseur de températures : °C $\leftrightarrow$ °F $\leftrightarrow$ K}

Formules exactes :
\begin{align*}
    F &= C \times \frac{9}{5} + 32 \quad &\text{(°C vers °F)} \\
    C &= (F - 32) \times \frac{5}{9} \quad &\text{(°F vers °C)} \\
    K &= C + 273.15 \quad &\text{(°C vers Kelvin)} \\
    C &= K - 273.15 \quad &\text{(Kelvin vers °C)}
\end{align*}

\begin{methode}[Stratégie « Pivot Celsius » pour $N$ unités]
Plutôt que d'écrire $N \times (N-1)$ fonctions, on convertit \textbf{tout vers une unité pivot (ici °C)}, puis du pivot vers la cible. Cela ne demande que $2N$ fonctions.
\begin{enumerate}
    \item \texttt{versCelsius(valeur, uniteSource)} : renvoie °C.
    \item \texttt{depuisCelsius(valeurCelsius, uniteCible)} : renvoie valeur dans cible.
    \item \texttt{convertirTemp(valeur, source, cible)} : orchestration.
\end{enumerate}
\end{methode}

\begin{exemplebox}[Convertisseur température générique]
\begin{lstlisting}[language=JavaScript]
function versCelsius(valeur, unite) {
    switch (unite) {
        case "C": return valeur;
        case "F": return (valeur - 32) * 5/9;
        case "K": return valeur - 273.15;
        default: return NaN;
    }
}

function depuisCelsius(celsius, unite) {
    switch (unite) {
        case "C": return celsius;
        case "F": return celsius * 9/5 + 32;
        case "K": return celsius + 273.15;
        default: return NaN;
    }
}

function convertirTemperature(valeur, source, cible) {
    if (source === cible) return valeur.toFixed(2) + " " + cible;
    
    let c = versCelsius(valeur, source);
    if (isNaN(c)) return "Unité source inconnue";
    
    let res = depuisCelsius(c, cible);
    if (isNaN(res)) return "Unité cible inconnue";
    
    // Affichage : 2 décimales pour C/F, 3 pour K (précision scientifique)
    let precision = (cible === "K") ? 3 : 2;
    return res.toFixed(precision) + " " + cible;
}

// Tests
console.log(convertirTemperature(100, "C", "F")); // "212.00 F"
console.log(convertirTemperature(32, "F", "C"));  // "0.00 C"
console.log(convertirTemperature(0, "C", "K"));   // "273.150 K"
\end{lstlisting}
\end{exemplebox}

function convertirDevise(montant, source, cible) {
    if (source === cible) return montant.toFixed(2) + " " + cible;
    let eur = (source === "FCFA") ? montant / TAUX_EUR_FCFA : montant;
    let res = (cible === "FCFA") ? eur * TAUX_EUR_FCFA : eur;

function convertirTemp(val, src, cib) {
    if (src === cib) return val.toFixed(2) + " " + cib;
    // Vers Celsius
    let c = (src==="C")?val:(src==="F")?(val-32)*5/9:val-273.15;

\courssub{Exercice résolu : Convertisseur d'unités de longueur}

\begin{exoresolu}[Convertisseur Mètres $\leftrightarrow$ Pieds $\leftrightarrow$ Pouces]
\textbf{Énoncé :} Écrire une fonction JavaScript \texttt{convertirLongueur(valeur, uniteSource, uniteCible)} gérant les unités : \texttt{"m"} (mètre), \texttt{"ft"} (pied), \texttt{"in"} (pouce). 
Rappels : 1 m = 3.28084 ft ; 1 ft = 12 in.
Afficher le résultat avec 4 décimales pour les mètres, 2 pour les pieds/pouces.

\tcblower
\textbf{Solution détaillée :}

\textbf{1. Analyse mathématique (Pivot Mètre) :}
\begin{align*}
    \text{Vers mètre :} \quad & m = \begin{cases} 
    val & \text{si } src=\texttt{"m"} \\
    val / 3.28084 & \text{si } src=\texttt{"ft"} \\
    val / (3.28084 \times 12) & \text{si } src=\texttt{"in"}
    \end{cases} \\
    \text{Depuis mètre :} \quad & res = \begin{cases} 
    m & \text{si } cib=\texttt{"m"} \\
    m \times 3.28084 & \text{si } cib=\texttt{"ft"} \\
    m \times 3.28084 \times 12 & \text{si } cib=\texttt{"in"}
    \end{cases}
\end{align*}

\textbf{2. Implémentation JavaScript :}
\begin{lstlisting}[language=JavaScript]
const PIED_PAR_METRE = 3.28084;
const POUCES_PAR_PIED = 12;

function versMetre(val, unite) {
    switch (unite) {
        case "m": return val;
        case "ft": return val / PIED_PAR_METRE;
        case "in": return val / (PIED_PAR_METRE * POUCES_PAR_PIED);
        default: return NaN;
    }
}

function depuisMetre(m, unite) {
    switch (unite) {
        case "m": return m;
        case "ft": return m * PIED_PAR_METRE;
        case "in": return m * PIED_PAR_METRE * POUCES_PAR_PIED;
        default: return NaN;
    }
}

function convertirLongueur(valeur, source, cible) {
    if (source === cible) return formater(valeur, cible);
    
    let metres = versMetre(valeur, source);
    if (isNaN(metres)) return "Unité source invalide";
    
    let resultat = depuisMetre(metres, cible);
    if (isNaN(resultat)) return "Unité cible invalide";
    
    return formater(resultat, cible);
}

function formater(nombre, unite) {
    // Précision adaptée à l'unité
    let decimales = (unite === "m") ? 4 : 2;
    return nombre.toFixed(decimales) + " " + unite;
}

// Tests
console.log(convertirLongueur(1, "m", "ft"));    // "3.28 ft"
console.log(convertirLongueur(12, "in", "m"));   // "0.3048 m"
console.log(convertirLongueur(3.28084, "ft", "in")); // "39.37 in"
\end{lstlisting}

\textbf{3. Points clés validés :}
\begin{itemize}
    \item Utilisation de constantes nommées (\texttt{PIED\_PAR\_METRE}) pour la lisibilité.
    \item Stratégie Pivot (Mètre) évitant les 6 conversions croisées.
    \item Fonction \texttt{formater} externalisée pour la présentation.
    \item Gestion des unités identiques (retour direct) et invalides (\texttt{NaN}).
\end{itemize}
\end{exoresolu}

\begin{enumerate}

\courssub{Situation}

\begin{itemize}
\item « 50\,000 FCFA, ça fait combien en euros ? Et en dollars ? » (taux pratiqués au comptoir : $1$~\texteuro{} $= 656$~FCFA ; $1$~\$ $= 600$~FCFA) ;
\item « Le bulletin météo annonce 86~degrés Fahrenheit à Douala, c'est chaud ou pas ? » ;
\item « Mon bon de commande est valable 90~jours à partir du 15 mars 2025, il expire quand ? ».
\end{itemize}

M.~Kamdem demande à la classe de Première~C du lycée voisin de lui concevoir une page Web unique, nommée \texttt{convertisseur.html}, utilisable \textbf{hors connexion} sur le poste du comptoir. La page devra proposer :

\begin{enumerate}

\item une \textbf{zone de saisie} pour la valeur à convertir, une liste pour l'\textbf{unité source} et une liste pour l'\textbf{unité cible} ;

\item l'affichage du résultat dans une balise \texttt{<output>}, sans recharger la page ;
\item des messages clairs en cas d'erreur de saisie, et une demande de confirmation avant chaque conversion.

Pour les devises, les conversions possibles sont : FCFA $\rightarrow$ Euro, FCFA $\rightarrow$ Dollar, Euro $\rightarrow$ FCFA, Dollar $\rightarrow$ FCFA. \textbf{Étape 3 — Les fonctions spécialisées.} Chaque fonction reçoit des paramètres déjà validés et \emph{retourne} une chaîne : elle ne s'occupe ni de la saisie ni de l'affichage (principe de décomposition).

// ===== Fonctions specialisees =====

function convertirDevises(montant, source, cible) {
  var resultat;
  if (source === "FCFA" && cible === "EUR") {
    resultat = montant / 656;
    return montant + " FCFA = " + resultat.toFixed(2) + " EUR";
  } else if (source === "FCFA" && cible === "USD") {
    resultat = montant / 600;
    return montant + " FCFA = " + resultat.toFixed(2) + " USD";
  } else if (source === "EUR" && cible === "FCFA") {
    resultat = montant * 656;
    return montant + " EUR = " + resultat + " FCFA";
  } else if (source === "USD" && cible === "FCFA") {
    resultat = montant * 600;
    return montant + " USD = " + resultat + " FCFA";
  } else {
    return "Conversion de devises non prevue.";
  }
}

function convertirTemperature(valeur, source, cible) {
  var resultat;
  if (source === "C" && cible === "F") {
    resultat = (9 / 5) * valeur + 32;
    return valeur + " C = " + resultat.toFixed(1) + " F";
  } else if (source === "F" && cible === "C") {
    resultat = (5 / 9) * (valeur - 32);
    return valeur + " F = " + resultat.toFixed(1) + " C";
  } else {
    return "Conversion de temperature non prevue.";
  }
}

function convertirDate(dateDepart, nbJours) {
  var d = new Date(dateDepart);       // format AAAA-MM-JJ
  if (isNaN(d.getTime())) {
    return "Date de depart invalide.";
  }
  d.setDate(d.getDate() + nbJours);   // ajout des jours
  return "Date d'arrivee : " + d.toLocaleDateString("fr-FR");
}
\end{lstlisting}

\textbf{Étape 4 — La fonction principale.} Elle orchestre tout : lecture, confirmation, validation, aiguillage, affichage.

\begin{lstlisting}[language=JavaScript]
// ===== Fonction principale (evenement onclick) =====

function convertir() {
  // 1. Recuperation des valeurs (toujours des chaines)
  var type   = document.getElementById("type").value;
  var source = document.getElementById("source").value;
  var cible  = document.getElementById("cible").value;
  var message;

  // 2. Confirmation avant traitement
  if (!confirm("Lancer la conversion ?")) {
    return; // l'utilisateur a annule
  }

  // 3. Aiguillage selon le type choisi
  if (type === "devises" || type === "temperature") {
    var valeur = parseFloat(document.getElementById("valeur").value);
    // parseFloat : montants et temperatures peuvent etre decimaux
    if (isNaN(valeur)) {
      alert("Erreur : saisissez une valeur numerique !");
      return;
    }
    if (type === "devises") {
      message = convertirDevises(valeur, source, cible);
    } else {
      message = convertirTemperature(valeur, source, cible);
    }
  } else { // type === "date"
    var dateDepart = document.getElementById("valeur").value;
    var nbJours = parseInt(document.getElementById("jours").value, 10);
    // parseInt : un nombre de jours est forcement entier
    if (isNaN(nbJours) || nbJours < 0) {
      alert("Erreur : nombre de jours invalide !");
      return;
    }
    message = convertirDate(dateDepart, nbJours);
  }

  // 4. Affichage du resultat sans recharger la page
  document.getElementById("resultat").textContent = message;
}
\end{lstlisting}

\begin{itemize}

\begin{methode}[Insérer du JavaScript dans une page HTML]
Pour rendre une page HTML interactive avec JavaScript, procède ainsi :
\begin{enumerate}
  \item Ouvre la balise \texttt{<script>} et ferme-la avec \texttt{</script>} : tout le code JavaScript se place entre les deux. La balise peut figurer dans \texttt{<head>} (chargement avant l'affichage) ou dans \texttt{<body>} (exécution au fil de la lecture).
  \item Écris les instructions JavaScript, chacune terminée par un \cle{point-virgule} \texttt{;} (bonne pratique exigée à l'examen, bien que JS tolère parfois l'omission).
  \item Pour afficher un résultat dans le flux de la page, utilise \texttt{document.write("texte")} ; pour une boîte de dialogue modale, \texttt{alert("texte")} ; pour une boîte de confirmation, \texttt{confirm("question")} (renvoie \texttt{true} ou \texttt{false}) ; pour une saisie, \texttt{prompt("message")} (renvoie une \emph{chaîne} ou \texttt{null}).
  \item Enregistre le fichier avec l'extension \texttt{.html} et ouvre-le dans un navigateur pour tester.
  \item Pour isoler le script, on peut aussi le placer dans un fichier \texttt{.js} externe appelé par \texttt{<script src="fichier.js"></script>} (à placer de préférence avant \texttt{</body>}).
\end{enumerate}
\textbf{Réflexe Bac :} si l'énoncé demande de « compléter une page », repère où placer \texttt{<script>} et vérifie que chaque balise ouverte est fermée.
\end{methode}

\begin{methode}[Déclarer des variables et convertir les types]
\begin{enumerate}
  \item \cle{Déclare} chaque variable avec le mot-clé \texttt{var} suivi du nom (sans espace, sans accent, commençant par une lettre ou \texttt{\_} ou \texttt{\$}) : \texttt{var age;} (notation \texttt{var} imposée par le programme de 1ère).
  \item \cle{Affecte} une valeur avec \texttt{=} : \texttt{age = 17;} ou directement \texttt{var age = 17;}
  \item Retiens les trois types de base : \cle{nombre} (entier ou réel, ex. \texttt{42}, \texttt{3.14}), \cle{chaîne de caractères} (entre guillemets doubles ou simples, ex. \texttt{"Yaoundé"}), \cle{booléen} (\texttt{true} ou \texttt{false}).
  \item \textbf{Point critique :} \texttt{prompt()} renvoie \emph{toujours une chaîne} (ou \texttt{null} si annulé). Avant tout calcul, convertis explicitement :
  \begin{itemize}
    \item \texttt{parseInt(chaine, 10)} pour obtenir un \cle{entier} (le second argument \texttt{10} force la base décimale, évitant les surprises octales) ;
    \item \texttt{parseFloat(chaine)} pour obtenir un \cle{nombre réel} (attention : il ne reconnaît que le \textbf{point} comme séparateur décimal, pas la virgule française).
  \end{itemize}
  \item Vérifie le type d'une variable avec l'opérateur \texttt{typeof} si un doute subsiste (ex. \texttt{typeof age} renvoie \texttt{"number"}).
\end{enumerate}
\textbf{Réflexe Bac :} dès qu'une valeur provient de \texttt{prompt()} et sert dans un calcul, écris immédiatement la conversion ; c'est le piège n°1 des sujets.
\end{methode}

\begin{exoresolu}[Variables et conversions]
\textbf{Énoncé.} Une élève saisit son âge via \texttt{prompt("Quel est votre âge ?")} stocké dans la variable \texttt{a}.
\begin{enumerate}
  \item Quel est le type de \texttt{a} après la saisie de la valeur 16 ?
  \item On exécute \texttt{b = a + 2;} puis \texttt{c = parseInt(a, 10) + 2;}. Donner les valeurs de \texttt{b} et \texttt{c} en justifiant.
  \item Écrire l'instruction qui calcule correctement l'âge de l'élève dans 2 ans.
\end{enumerate}
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
  \item La fonction \texttt{prompt()} renvoie \emph{toujours} une \cle{chaîne de caractères}. Donc \texttt{a} est de type \textbf{chaîne} et contient \texttt{"16"} (avec guillemets), même si l'utilisateur a tapé des chiffres.
  \item Analysons les deux affectations :
  \begin{itemize}
    \item \texttt{b = a + 2;} : l'opérateur \texttt{+} appliqué à une chaîne et un nombre déclenche la \cle{concaténation} : le nombre \texttt{2} est transformé en chaîne et collé à \texttt{"16"}. Donc $b = \texttt{"162"}$ (chaîne).
    \item \texttt{c = parseInt(a, 10) + 2;} : \texttt{parseInt("16", 10)} convertit la chaîne en l'entier $16$ ; l'addition est alors arithmétique : $c = 16 + 2 = 18$ (nombre).
  \end{itemize}
  \item L'instruction correcte est :
\begin{lstlisting}[language=JavaScript]
var ageDans2Ans = parseInt(a, 10) + 2;
\end{lstlisting}
\end{enumerate}
\textbf{Conclusion :} sans conversion, \texttt{a + 2} donne la chaîne \texttt{"162"} et non $18$ ; il faut donc toujours appliquer \texttt{parseInt()} (ou \texttt{parseFloat()} pour un réel) à une donnée issue de \texttt{prompt()} avant tout calcul.
\end{exoresolu}

\begin{attention}[Séparateur décimal : le piège de la virgule]
En JavaScript, les littéraux numériques et les fonctions \texttt{parseFloat}/\texttt{parseInt} n'acceptent que le \textbf{point} comme séparateur décimal.
Si un élève camerounais tape \texttt{12,5} (avec une virgule) dans un \texttt{prompt}, \texttt{parseFloat("12,5")} renverra \texttt{12} (il s'arrête à la virgule).
\begin{itemize}
  \item \textbf{Solution pédagogique :} pour un convertisseur réel, remplacer la virgule par un point avant conversion : \texttt{parseFloat(saisie.replace(",", "."))}.
  \item \textbf{Au Probatoire :} les sujets utilisent généralement des valeurs entières ou des réels écrits avec un point dans l'énoncé. Sois vigilant(e) si tu dois tester ton propre code.
\end{itemize}
\end{attention}

\begin{methode}[Utiliser les opérateurs et évaluer une expression]
\begin{enumerate}
  \item \cle{Arithmétiques} : \texttt{+} (addition/concaténation), \texttt{-}, \texttt{*}, \texttt{/}, et \texttt{\%} (reste de la division euclidienne, appelé \emph{modulo}).
  \item \cle{Comparaison} (résultat booléen) : \texttt{==} (égal, avec conversion de type), \texttt{===} (strictement égal, même type et même valeur — \emph{recommandé}), \texttt{!=} (différent), \texttt{!==} (strictement différent), \texttt{<}, \texttt{>}, \texttt{<=}, \texttt{>=}. Attention : \texttt{=} seul est une \emph{affectation}, \texttt{==} est un \emph{test}.
  \item \cle{Logiques} : \texttt{\&\&} (ET : vrai si les deux conditions sont vraies), \texttt{||} (OU : vrai si au moins une condition est vraie), \texttt{!} (NON).
  \item \cle{Affectations composées} : \texttt{x += 3} équivaut à \texttt{x = x + 3} ; de même \texttt{-=}, \texttt{*=}, \texttt{/=}. Les opérateurs \texttt{++} et \texttt{--} ajoutent ou retranchent 1 : \texttt{x++} équivaut à \texttt{x = x + 1}.
  \item Pour évaluer une expression, respecte les priorités : parenthèses, puis \texttt{*}, \texttt{/}, \texttt{\%}, puis \texttt{+}, \texttt{-}, puis comparaisons, puis \texttt{\&\&}, puis \texttt{||}.
\end{enumerate}
\textbf{Réflexe Bac :} pour une table d'exécution, déroule les instructions \emph{ligne par ligne} en notant la valeur de chaque variable après chaque affectation.
\end{methode}

\begin{exoresolu}[Table d'exécution et opérateurs]
\textbf{Énoncé.} On considère le script suivant :
\begin{lstlisting}[language=JavaScript]
var x = 10;
var y = 4;
x += y;
y++;
var r = x % y;
var test = (x > 12) && (y < 6);
\end{lstlisting}
Donner les valeurs finales de \texttt{x}, \texttt{y}, \texttt{r} et \texttt{test}, en détaillant chaque étape.
\tcblower
\textbf{Solution détaillée.} On construit la table d'exécution ligne par ligne :
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|}\hline
\rowcolor{popblueL} \textbf{Instruction} & \textbf{Effet} & \textbf{Valeurs après exécution} \\ \hline
\texttt{var x = 10;} & initialisation & $x = 10$ \\ \hline
\texttt{var y = 4;} & initialisation & $x = 10$, $y = 4$ \\ \hline
\texttt{x += y;} & équivaut à \texttt{x = x + y} $= 10 + 4$ & $x = 14$, $y = 4$ \\ \hline
\texttt{y++;} & équivaut à \texttt{y = y + 1} & $x = 14$, $y = 5$ \\ \hline
\texttt{var r = x \% y;} & reste de $14 \div 5$ : $14 = 5 \times 2 + 4$ & $r = 4$ \\ \hline
\texttt{var test = ...} & $(14 > 12)$ est vrai ; $(5 < 6)$ est vrai ; vrai \texttt{\&\&} vrai $=$ vrai & $\texttt{test} = \texttt{true}$ \\ \hline
\end{tabularx}
\end{center}
\textbf{Justifications :} pour le modulo, la division euclidienne de $14$ par $5$ donne un quotient de $2$ et un reste de $4$, d'où $r = 4$. Pour le test logique, l'opérateur \texttt{\&\&} exige que \emph{les deux} conditions soient vraies : c'est le cas ici.
\textbf{Conclusion :} les valeurs finales sont $x = 14$, $y = 5$, $r = 4$ et $\texttt{test} = \texttt{true}$.
\end{exoresolu}

\begin{methode}[Traduire un algorithme conditionnel ou itératif en JavaScript]
\begin{enumerate}
  \item \textbf{Alternative} : \texttt{if (condition) \{ ... \} else \{ ... \}}. La condition est entre \cle{parenthèses}, les blocs entre \cle{accolades}. Pour plusieurs cas, enchaîne \texttt{else if (condition) \{ ... \}}.
  \item \textbf{Boucle bornée} (nombre de tours connu) : \texttt{for (var i = 1; i <= n; i++) \{ ... \}} avec les trois parties : initialisation ; condition de continuation ; incrémentation.
  \item \textbf{Boucle conditionnelle} (on répète tant qu'une condition est vraie) : \texttt{while (condition) \{ ... \}}. Vérifie qu'une instruction dans le corps \emph{fait évoluer} la condition, sinon boucle infinie.
  \item Traduction mot à mot depuis l'écriture algorithmique : « Si ... Alors ... Sinon ... FinSi » $\rightarrow$ \texttt{if/else} ; « Pour i de 1 à n Faire ... FinPour » $\rightarrow$ \texttt{for} ; « Tant que ... Faire ... FinTantQue » $\rightarrow$ \texttt{while}.
  \item Teste ton script à la main sur 2 ou 3 valeurs avant de conclure.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Traduction d'un algorithme : mention au Probatoire]
\textbf{Énoncé.} On donne l'algorithme suivant, qui affiche la mention d'un candidat selon sa moyenne $m$ sur 20 :
\begin{lstlisting}
Algorithme Mention
Variable m : reel
Debut
   Ecrire("Entrer la moyenne : ")
   Lire(m)
   Si m >= 10 Alors
      Ecrire("Admis")
   Sinon
      Ecrire("Refuse")
   FinSi
Fin
\end{lstlisting}
\begin{enumerate}
  \item Traduire cet algorithme en JavaScript (saisie par \texttt{prompt()}, affichage par \texttt{alert()}).
  \item Que s'affiche-t-il si l'utilisateur saisit 12.5 (avec un point) ? Justifier.
\end{enumerate}
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
  \item Traduction ligne par ligne : « Ecrire + Lire » devient un \texttt{prompt()} (qui affiche le message \emph{et} lit la réponse) ; la moyenne étant un \emph{réel}, on convertit avec \texttt{parseFloat()} en gérant le séparateur décimal ; « Si/Sinon » devient \texttt{if/else} ; « Ecrire » devient \texttt{alert()}.
\begin{lstlisting}[language=JavaScript]
var saisie = prompt("Entrer la moyenne :");
// Gestion du séparateur décimal (virgule ou point)
var m = parseFloat(saisie.replace(",", "."));
if (m >= 10) {
   alert("Admis");
} else {
   alert("Refuse");
}
\end{lstlisting}
  \item L'utilisateur saisit \texttt{12.5} (avec un point, notation JS standard). La fonction \texttt{prompt()} renvoie la chaîne \texttt{"12.5"}, convertie par \texttt{parseFloat()} en le nombre $12,5$. Le test $12,5 \geq 10$ est \textbf{vrai} : c'est donc le premier bloc qui s'exécute.
\end{enumerate}
\textbf{Conclusion :} le script traduit fidèlement l'algorithme ; pour une moyenne de $12,5$, la boîte de dialogue affiche « Admis ».
\end{exoresolu}

\begin{methode}[Déclarer une fonction et l'appeler avec onclick]
\begin{enumerate}
  \item \cle{Déclare} la fonction avec le mot-clé \texttt{function} (minuscules), suivi du nom, des paramètres entre parenthèses (éventuellement vides) et du corps entre accolades :
  \texttt{function nom(param1, param2) \{ ... \}}
  \item Si la fonction doit fournir un résultat, utilise \texttt{return resultat;} ; sinon elle se contente d'exécuter des actions (affichages, modifications du DOM).
  \item \cle{Appelle} la fonction en écrivant son nom suivi des arguments entre parenthèses : \texttt{nom(5, 3);}. Une fonction non appelée ne s'exécute \emph{jamais}.
  \item Pour déclencher la fonction par un clic, ajoute l'\cle{événement} \texttt{onclick} sur un bouton HTML : \texttt{<input type="button" value="Calculer" onclick="nom()">}.
  \item Réflexe de rédaction : le nom de la fonction dans \texttt{onclick} doit être \emph{strictement identique} (majuscules comprises) à celui de la déclaration.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Fonction et événement onclick]
\textbf{Énoncé.} Un commerçant de Douala veut un bouton « Appliquer la remise » qui, lorsqu'on clique dessus, calcule et affiche le prix d'un article de \num{50000} FCFA après une remise de 10 \%. 
\begin{enumerate}
  \item Écrire la fonction JavaScript \texttt{remise()} qui effectue ce calcul et affiche le nouveau prix par \texttt{alert()}.
  \item Écrire la balise HTML du bouton déclenchant cette fonction.
\end{enumerate}
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
  \item Calcul : une remise de 10 \% sur \num{50000} FCFA vaut $50000 \times \frac{10}{100} = 5000$ FCFA ; le nouveau prix est donc $50000 - 5000 = 45000$ FCFA. On programme ce calcul de façon générale :
\begin{lstlisting}[language=JavaScript]
function remise() {
   var prix = 50000;
   var nouveauPrix = prix - prix * 10 / 100;
   alert("Nouveau prix : " + nouveauPrix + " FCFA");
}
\end{lstlisting}
Remarque : \texttt{prix * 10 / 100} est évalué de gauche à droite : $50000 \times 10 = 500000$, puis $500000 / 100 = 5000$ ; la soustraction donne bien $45000$.
  \item Le bouton utilise l'événement \texttt{onclick} pour \cle{appeler} la fonction :
\begin{lstlisting}[language=HTML]
<input type="button" value="Appliquer la remise" onclick="remise()">
\end{lstlisting}
\end{enumerate}
\textbf{Conclusion :} au clic sur le bouton, l'événement \texttt{onclick} déclenche l'appel de \texttt{remise()}, qui affiche « Nouveau prix : 45000 FCFA ».
\end{exoresolu}

\begin{methode}[Programmer un convertisseur avec des zones de saisie]
\begin{enumerate}
  \item Crée le formulaire HTML : une \cle{zone de saisie} \texttt{<input type="text" id="...">} pour la valeur à convertir, un bouton avec \texttt{onclick}, et éventuellement une zone pour le résultat (ex. \texttt{<output id="res">} ou \texttt{<input type="text" id="res" readonly>}).
  \item Dans la fonction JavaScript, \cle{récupère} la valeur saisie avec \texttt{document.getElementById("identifiant").value}. Cette valeur est une \emph{chaîne} : convertis-la avec \texttt{parseFloat(saisie.replace(",", "."))} ou \texttt{parseInt(saisie, 10)}.
  \item Applique la \cle{formule de conversion} (par exemple $T_F = T_C \times 1,8 + 32$ pour les températures, ou montant $\times$ taux pour les devises).
  \item \cle{Affiche} le résultat : soit par \texttt{alert()}, soit en écrivant dans une zone de résultat avec \texttt{document.getElementById("resultat").value = ...} ou \texttt{.textContent = ...}.
  \item Teste avec une valeur connue (ex. $0\,°\mathrm{C} = 32\,°\mathrm{F}$) pour valider la formule.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Convertisseur FCFA -- Euro]
\textbf{Énoncé.} Pour sa boutique en ligne, une commerçante de Bafoussam veut une page contenant une zone de saisie d'identifiant \texttt{montant} (somme en FCFA), un bouton « Convertir », et qui affiche par \texttt{alert()} l'équivalent en euros, sachant que $1$ euro $= 656$ FCFA. Écrire le code HTML/JavaScript complet de la page.
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
  \item \textbf{Formule :} si $1$ € $= 656$ FCFA, alors un montant $M$ en FCFA vaut $\dfrac{M}{656}$ euros.
  \item \textbf{Structure :} zone de saisie \texttt{montant}, bouton dont l'\texttt{onclick} appelle \texttt{convertir()}, fonction qui lit, convertit, calcule et affiche.
\end{enumerate}
\begin{lstlisting}[language=HTML]
<!DOCTYPE html>
<html>
  <head>
    <meta charset="UTF-8">
    <title>Convertisseur FCFA - Euro</title>
    <script>
      function convertir() {
         // 1. Recuperation de la valeur saisie (chaine)
         var saisie = document.getElementById("montant").value;
         // 2. Conversion en nombre reel (gestion virgule/point)
         var fcfa = parseFloat(saisie.replace(",", "."));
         // 3. Application de la formule
         var euro = fcfa / 656;
         // 4. Affichage du resultat (arrondi à 2 décimales pour lisibilité)
         alert(fcfa + " FCFA = " + euro.toFixed(2) + " euros");
      }
    </script>
  </head>
  <body>
    Montant en FCFA : <input type="text" id="montant">
    <input type="button" value="Convertir" onclick="convertir()">
  </body>
</html>
\end{lstlisting}
\textbf{Vérification :} pour $M = 6560$ FCFA saisis, \texttt{parseFloat("6560")} donne $6560$, puis $6560 / 656 = 10$ : la boîte affiche « 6560 FCFA = 10.00 euros », ce qui est exact.
\textbf{Conclusion :} la page lit le montant saisi, le convertit grâce à \texttt{parseFloat()} (après remplacement virgule/point), applique la formule $\text{euro} = \text{fcfa}/656$ et affiche le résultat formaté au clic sur le bouton.
\end{exoresolu}

\begin{attention}[Les 5 erreurs qui coûtent des points au Bac]
\begin{enumerate}
  \item \textbf{Oublier la conversion après \texttt{prompt()} :} \texttt{prompt()} renvoie une chaîne ; \texttt{a + b} concatène alors au lieu d'additionner (\texttt{"2" + "3"} donne \texttt{"23"}, pas $5$). Toujours écrire \texttt{parseInt(saisie, 10)} ou \texttt{parseFloat(saisie.replace(",", "."))} avant un calcul.
  \item \textbf{Confondre \texttt{=} et \texttt{==} (ou \texttt{===}) :} dans un \texttt{if}, on \emph{teste} avec \texttt{===} (ex. \texttt{if (note === 10)}). Écrire \texttt{if (note = 10)} est une affectation : la variable vaut 10, le test est vrai, la logique du programme est détruite.
  \item \textbf{Oublier les accolades ou les parenthèses :} la condition d'un \texttt{if}, d'un \texttt{while} ou d'un \texttt{for} est \emph{toujours} entre parenthèses, et le corps d'une fonction ou d'un bloc entre accolades. Une accolade manquante rend tout le script inutilisable (erreur de syntaxe).
  \item \textbf{Déclarer une fonction sans jamais l'appeler :} une fonction ne s'exécute que si elle est appelée (par \texttt{onclick="maFonction()"} ou par une instruction d'appel \texttt{maFonction();}). Vérifier aussi que le nom dans \texttt{onclick} est identique, majuscules comprises, au nom déclaré (\texttt{function MaFonction} vs \texttt{onclick="mafonction()"} $\rightarrow$ erreur).
  \item \textbf{Se tromper de formule de conversion ou de sens du calcul :} pour un convertisseur, poser d'abord la formule sur le brouillon (ex. euro $=$ FCFA $/$ taux, et non FCFA $\times$ taux) et la valider sur une valeur connue avant de rédiger le code.
\end{enumerate}
\end{attention}

\begin{corrige}[Exercice 1 — QCM : bases du langage]
\begin{enumerate}
    \item \textbf{Réponse B.} La seule balise HTML valide pour insérer du JavaScript est \texttt{<script>...</script>}. Les balises \texttt{<javascript>}, \texttt{<js>} et \texttt{<code>} n'existent pas dans le standard HTML (ou n'ont pas ce rôle : \texttt{<code>} sert à afficher du code, pas à l'exécuter).
    \item \textbf{Réponse C.} L'opérateur \texttt{+} avec une chaîne déclenche la \cle{concaténation} : le nombre \texttt{2} est converti en chaîne \texttt{"2"}, puis collé à \texttt{"5"} : résultat \texttt{"52"} (type \texttt{string}). C'est la coercition de type vers la chaîne.
    \item \textbf{Réponse C.} \texttt{alert()} affiche une boîte modale avec un message et un seul bouton « OK ». \texttt{prompt()} demande une saisie, \texttt{confirm()} propose « OK » et « Annuler », \texttt{console.log()} écrit dans la console (invisible pour l'utilisateur).
    \item \textbf{Réponse B.} \texttt{===} est l'égalité \cle{stricte} : elle compare la valeur \emph{et} le type sans conversion. \texttt{==} effectue une conversion préalable (\texttt{"5" == 5} vaut \texttt{true}, mais \texttt{"5" === 5} vaut \texttt{false}). \texttt{=} est l'affectation, \texttt{!=} la différence non stricte.
    \item \textbf{Réponse B.} \texttt{parseInt()} lit les caractères de gauche à droite tant qu'ils forment un entier : il lit \texttt{"12"}, s'arrête au point (non valide pour un entier) et renvoie le \emph{nombre} \texttt{12}. Le suffixe \texttt{"px"} est ignoré. \texttt{parseFloat("12.34px")} aurait renvoyé \texttt{12.34}.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 2 — Vrai ou Faux ? Justifie]
\begin{enumerate}
    \item \textbf{Faux.} L'événement \texttt{onclick} se déclenche au \emph{simple} clic. Le double-clic correspond à l'événement \texttt{ondblclick}.
    \item \textbf{Vrai.} \texttt{prompt()} renvoie toujours une chaîne de caractères (\texttt{string}) quand l'utilisateur valide, ou \texttt{null} s'il annule. D'où la nécessité de \texttt{parseInt()} ou \texttt{parseFloat()} pour faire des calculs.
    \item \textbf{Faux.} C'est l'inverse : \texttt{var} a une portée de \emph{fonction} (ou globale), pas de bloc. Ce sont \texttt{let} et \texttt{const} qui ont une portée de bloc (limitée aux accolades \texttt{\{ \}}).
    \item \textbf{Vrai.} \texttt{document.write()} écrit dans le flux HTML pendant le chargement. Appelée \emph{après} la fin du chargement, elle rouvre le document et \textbf{écrase tout le contenu existant} de la page : c'est pourquoi on lui préfère \texttt{innerHTML}.
    \item \textbf{Vrai.} \texttt{\&\&} est paresseux (\emph{short-circuit}) : si le premier opérande est \texttt{false}, le résultat est forcément \texttt{false} et le second opérande n'est pas évalué. De même, \texttt{||} n'évalue le second opérande que si le premier est \texttt{false}.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 3 — Vocabulaire et définitions]
\begin{enumerate}
    \item Un \textbf{Script} est un programme écrit en JavaScript, interprété par le navigateur.
    \item Une \textbf{Variable} est un conteneur nommé qui stocke une valeur modifiable.
    \item Un \textbf{Événement} est une action de l'utilisateur (clic, frappe, survol\ldots) à laquelle le script peut réagir.
    \item Le \textbf{DOM} (Document Object Model) est la représentation arborescente de la page HTML.
    \item \textbf{parseFloat} convertit une chaîne en nombre à virgule flottante.
    \item Un bloc de code réutilisable avec paramètres et valeur de retour s'appelle une \textbf{Fonction}.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 4 — Prédiction de résultats]
\begin{enumerate}
    \item \texttt{resultat = 5} (nombre). L'opérateur \texttt{-} n'a pas de sens sur les chaînes : JavaScript convertit \texttt{"5"} en nombre $5$, puis calcule $10 - 5 = 5$.
    \item \texttt{resultat = "105"} (chaîne). Avec \texttt{+}, la présence d'une chaîne impose la concaténation : \texttt{5} devient \texttt{"5"}, d'où \texttt{"10" + "5" = "105"}.
    \item \texttt{resultat = 1}. \texttt{Number(true)} vaut $1$ et \texttt{Number(false)} vaut $0$ ; donc $1 + 0 = 1$.
    \item \texttt{resultat = 21}. La pré-incrémentation \texttt{++s} convertit d'abord la chaîne \texttt{"20"} en nombre $20$, l'incrémente à $21$, puis affecte $21$ à \texttt{resultat} (et à \texttt{s}).
    \item \texttt{resultat = 6}. \texttt{parseFloat("3,14")} lit \texttt{"3"}, s'arrête devant la virgule (le séparateur décimal de JavaScript est le \emph{point}) et renvoie $3$. Donc $3 \times 2 = 6$.
\end{enumerate}
\end{corrige}

\begin{attention}[Point de vigilance]
Le piège classique : \texttt{+} concatène, les autres opérateurs arithmétiques (\texttt{-}, \texttt{*}, \texttt{/}) convertissent en nombre. Et \texttt{parseFloat} n'accepte que le point décimal : \texttt{"3,14"} donne $3$, il faut écrire \texttt{"3.14"} pour obtenir $3{,}14$.
\end{attention}

\courssub{Définitions Clés}

\begin{definition}[Script JavaScript]
Suite d'instructions écrites en langage JavaScript, interprétées par le navigateur côté client pour rendre une page Web interactive.
\end{definition}

\begin{definition}[Variable]
Espace mémoire nommé (\texttt{let} ou \texttt{const}) stockant une valeur de type \textbf{Number}, \textbf{String}, \textbf{Boolean}, \textbf{Null}, \textbf{Undefined}, \textbf{Object}. Typage dynamique : le type change selon la valeur affectée.
\end{definition}

\begin{definition}[Événement]
Action de l'utilisateur (clic, survol, frappe clavier, chargement page) détectée par le navigateur et pouvant déclencher l'exécution d'une fonction JavaScript.
\end{definition}

\begin{definition}[Fonction]
Bloc de code réutilisable, identifié par un nom, acceptant des paramètres (entrées) et pouvant retourner une valeur (\texttt{return}). Déclenchée par un appel explicite ou un événement.
\end{definition}

\courssub{Méthodes Express}

\begin{methode}[Écrire et tester un script simple]
\begin{enumerate}
    \item Créer un fichier \texttt{index.html} avec structure HTML5 valide.
    \item Insérer \texttt{<script>} avant \texttt{</body>} (recommandé) ou dans \texttt{<head>}.
    \item Déclarer variables avec \texttt{let}/\texttt{const}.
    \item Utiliser \texttt{prompt()} pour entrées, \texttt{parseInt()/parseFloat()} pour convertir.
    \item Traiter avec opérateurs et structures de contrôle.
    \item Afficher résultat via \texttt{alert()}, \texttt{console.log()} ou \texttt{document.write()}.
    \item Ouvrir dans navigateur, ouvrir outils développeur (F12) pour console/debug.
\end{enumerate}
\end{methode}

\begin{methode}[Programmer un convertisseur (ex: Devises FCFA $\leftrightarrow$ EUR)]
\begin{enumerate}
    \item Identifier données : taux fixe (ex: 1 EUR = 655,957 FCFA), sens de conversion.
    \item Saisir montant via \texttt{prompt()} et convertir en \texttt{Number} (\texttt{parseFloat}).
    \item Vérifier validité : \texttt{if (isNaN(montant) || montant <= 0)}.
    \item Calculer : \texttt{resultat = montant * taux} ou \texttt{/ taux}.
    \item Formater affichage : \texttt{resultat.toFixed(2)} pour 2 décimales.
    \item Afficher via \texttt{alert()} ou injection dans le DOM (\texttt{element.textContent = ...}).
\end{enumerate}
\end{methode}

\begin{aretenir}[Checklist avant le Bac]
\begin{itemize}
    \item $\square$ Je sais insérer du JavaScript dans une page HTML (\texttt{<script>} interne/externe).
    \item $\square$ Je distingue \texttt{let} (variable) de \texttt{const} (constante) et je nomme correctement mes identificateurs (camelCase).
    \item $\square$ Je maîtrise les 3 types primitifs principaux : \texttt{Number}, \texttt{String}, \texttt{Boolean} et le typage dynamique.
    \item $\square$ Je convertis systématiquement les saisies \texttt{prompt()} avec \texttt{parseInt()} ou \texttt{parseFloat()}.
    \item $\square$ J'utilise \texttt{===} (égalité stricte) au lieu de \texttt{==} pour éviter la coercition implicite.
    \item $\square$ J'écris correctement les structures \texttt{if/else}, \texttt{for}, \texttt{while} avec accolades \{\} et indentation.
    \item $\square$ Je sais déclarer une \texttt{function} avec paramètres et \texttt{return}, et l'appeler.
    \item $\square$ Je lie une fonction à un clic via \texttt{onclick="maFonction()"} dans la balise HTML.
    \item $\square$ Je conçois un convertisseur complet : saisie $\to$ conversion $\to$ test validité $\to$ calcul $\to$ affichage formaté.
    \item $\square$ Je débogue avec \texttt{console.log()} et la console navigateur (F12).
    \item $\square$ Je connais les limites : JS côté client seulement, pas d'accès direct BDD/serveur, désactivable par l'utilisateur.
\end{itemize}
\end{aretenir}
