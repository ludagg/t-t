\coursec{Environnement de développement (IDE) et premier programme}

\textbf{Situation d'accroche.} Le lycée de Nkongsamba veut informatiser le calcul des moyennes de ses élèves de Première. Jusqu'ici, le surveillant général saisit les notes à la main dans un cahier, ce qui provoque des erreurs de report, des oublis et, à chaque fin de trimestre, des contestations de bulletins. Un ancien élève de l'établissement, aujourd'hui étudiant en informatique, propose d'écrire un petit programme en langage C : ce programme lira les notes saisies au clavier, calculera automatiquement la moyenne et affichera le bulletin à l'écran. Mais avant d'arriver là, plusieurs questions se posent : \emph{quel logiciel faut-il installer pour écrire un programme C ? Comment transformer le texte du programme en un fichier que l'ordinateur peut exécuter ? Quelle est la forme minimale d'un programme C ?}

\textbf{Problématique.} Comment installer et utiliser un environnement de développement pour écrire, compiler et exécuter un premier programme en langage C ?

\courssub{Qu'est-ce qu'un IDE ?}

Pour écrire une lettre, tu utilises un logiciel de traitement de texte. Pour écrire un programme, un simple éditeur de texte ne suffit pas : l'ordinateur ne comprend que le \cle{langage machine} (des suites de 0 et de 1), alors que le programmeur écrit dans un langage évolué comme le C. Il faut donc, au minimum, trois outils :

\begin{itemize}
\item un \cle{éditeur de code} pour taper le texte du programme (le \cle{code source}) ;
\item un \cle{compilateur} pour traduire ce code source en langage machine ;
\item des outils de test (dont le \cle{débogueur}) pour repérer et corriger les erreurs.
\end{itemize}

Installer ces trois outils séparément serait fastidieux. C'est pourquoi on utilise un logiciel unique qui les regroupe tous : l'IDE.

\begin{definition}[IDE]
Un \cle{IDE} (\emph{Integrated Development Environment}, en français \emph{environnement intégré de développement}) est un logiciel qui regroupe, dans une même interface, l'\textbf{éditeur de code}, le \textbf{compilateur} et les \textbf{outils de test} (débogueur, console d'exécution) d'un ou plusieurs langages de programmation.
\end{definition}

\begin{exemplebox}[Quelques IDE utilisables pour le langage C]
\begin{itemize}
\item \textbf{Code::Blocks} : gratuit, léger, livré avec le compilateur MinGW ; très répandu dans les lycées et universités ;
\item \textbf{Dev-C++} : gratuit, simple d'emploi, idéal pour débuter sous Windows ;
\item \textbf{Visual Studio Code} : éditeur moderne et gratuit de Microsoft, auquel on ajoute une extension C et un compilateur ;
\item \textbf{CodeLite}, \textbf{Eclipse CDT} : autres alternatives gratuites.
\end{itemize}
Dans la suite de la leçon, nous travaillerons avec \textbf{Code::Blocks}, mais tout ce qui est dit reste valable avec Dev-C++.
\end{exemplebox}

\begin{propriete}[Rôle du compilateur]
Le \cle{compilateur} est un programme qui \textbf{traduit l'ensemble du code source} (fichier \texttt{.c}) en \textbf{langage machine} directement exécutable par le processeur (fichier \texttt{.exe} sous Windows). Contrairement à un interpréteur qui traduit ligne par ligne à chaque exécution, le compilateur traduit \emph{une fois pour toutes} : le programme traduit s'exécute ensuite très rapidement. Le compilateur \textbf{signale les erreurs de syntaxe} avec le numéro de ligne concerné.
\end{propriete}

\begin{savaistu}[Le langage C, un monument de l'informatique]
Le langage C a été créé en \textbf{1972} par \textbf{Dennis Ritchie} dans les laboratoires Bell (États-Unis), pour réécrire le système d'exploitation UNIX. Plus de cinquante ans après, il reste l'un des langages les plus utilisés au monde : les noyaux de \textbf{Windows}, de \textbf{Linux} et d'\textbf{Android}, les logiciels embarqués des compteurs ENEO ou des téléphones, sont en grande partie écrits en C. Apprendre le C, c'est apprendre la langue dans laquelle les ordinateurs modernes sont construits !
\end{savaistu}

\courssub{Installation de Code::Blocks et création d'un projet}

Avant d'écrire la moindre ligne de code, il faut installer l'outil. Voici la démarche complète, telle qu'on la réalise sur les postes d'une salle multimédia de lycée.

\begin{methode}[Installer Code::Blocks sous Windows]
\begin{enumerate}
\item Ouvrir un navigateur et se rendre sur le site officiel \texttt{www.codeblocks.org}, rubrique \texttt{Downloads}.
\item Télécharger la version \textbf{avec compilateur inclus} : le fichier dont le nom contient \texttt{mingw-setup.exe} (par exemple \texttt{codeblocks-20.03mingw-setup.exe}). C'est essentiel : sans compilateur, l'IDE ne peut rien traduire.
\item Double-cliquer sur le fichier téléchargé et suivre l'assistant : \texttt{Next}, accepter la licence, garder les composants par défaut, choisir le dossier d'installation, puis \texttt{Install}.
\item Au premier lancement, Code::Blocks détecte automatiquement le compilateur \textbf{GNU GCC} : cliquer sur \texttt{OK}.
\item Vérifier l'installation : menu \texttt{Settings $\rightarrow$ Compiler}, l'onglet doit indiquer \texttt{GNU GCC Compiler}.
\end{enumerate}
\end{methode}

\begin{attention}[Erreur fréquente à l'installation]
Beaucoup d'élèves téléchargent la version \emph{sans} compilateur (le fichier sans \texttt{mingw} dans son nom). Résultat : à la compilation, le message \emph{« can't find compiler executable »} apparaît. Solution : réinstaller la version \texttt{mingw-setup}, ou indiquer manuellement le chemin du compilateur dans \texttt{Settings $\rightarrow$ Compiler $\rightarrow$ Toolchain executables}.
\end{attention}

Une fois l'IDE installé, on ne crée pas un fichier « au hasard » : on crée un \cle{projet console}, c'est-à-dire un programme qui s'exécute dans une fenêtre texte (la \cle{console}), sans interface graphique. C'est le type de programme adapté à notre niveau.

\begin{methode}[Créer un nouveau projet console dans Code::Blocks]
\begin{enumerate}
\item Menu \texttt{File $\rightarrow$ New $\rightarrow$ Project...}, choisir \textbf{Console application}, cliquer \texttt{Go} puis \texttt{Next}.
\item Sélectionner le langage \textbf{C} (et non C++), puis \texttt{Next}.
\item Donner un titre au projet, par exemple \texttt{Bulletin}, choisir le dossier de rangement (par exemple \texttt{Mes documents\textbackslash ProgrammesC}), puis \texttt{Next}.
\item Laisser le compilateur \texttt{GNU GCC} et les configurations \texttt{Debug}/\texttt{Release} cochées, cliquer \texttt{Finish}.
\item Dans l'arborescence à gauche, ouvrir \texttt{Sources $\rightarrow$ main.c} : l'éditeur affiche un squelette de programme prêt à compléter.
\end{enumerate}
\end{methode}

\courssub{Le cycle de développement d'un programme C}

Écrire un programme, ce n'est pas taper du texte puis « espérer ». C'est suivre un cycle précis, que tout programmeur répète des dizaines de fois par jour :

\begin{enumerate}
\item \textbf{Écrire} le code source dans l'éditeur (fichier d'extension \texttt{.c}) ;
\item \textbf{Compiler} (menu \texttt{Build}) : le compilateur traduit et signale les erreurs ;
\item \textbf{Corriger} les erreurs signalées, puis recompiler jusqu'à obtenir \emph{0 error} ;
\item \textbf{Exécuter} (menu \texttt{Run}) : le fichier exécutable \texttt{.exe} est lancé et la console affiche les résultats ;
\item \textbf{Tester} avec plusieurs jeux de données pour vérifier que les résultats sont corrects.
\end{enumerate}

\courssub{Structure minimale d'un programme C}

Tout programme C, du plus petit au plus grand, respecte une architecture fixe. Observons-la sur le programme le plus simple possible.

\begin{exemplebox}[Premier programme : afficher un message]
\begin{lstlisting}[language=C]
/* Mon premier programme en C
   Affiche un message de bienvenue a l'ecran */
#include <stdio.h>   // bibliotheque des entrees/sorties

int main()           // fonction principale : le programme commence ici
{
    printf("Bonjour la classe !\n");   // affiche le message
    return 0;        // signale que le programme s'est bien termine
}
\end{lstlisting}
\end{exemplebox}

Analysons chaque élément, car chacun est indispensable :

\begin{itemize}
\item \texttt{\#include <stdio.h>} : une \cle{directive de préprocesseur} qui demande d'inclure la \cle{bibliothèque} standard des entrées/sorties (\emph{standard input/output}). Sans elle, la fonction \texttt{printf} est inconnue du compilateur. Nous détaillerons les bibliothèques dans la section suivante.
\item \texttt{int main()} : la \cle{fonction principale}. Tout programme C possède \textbf{une et une seule} fonction \texttt{main} : c'est par elle que l'exécution commence. Le mot \texttt{int} indique qu'elle renvoie un nombre entier au système.
\item Les \textbf{accolades} \texttt{\{ \}} délimitent le \emph{corps} de la fonction : toutes les instructions entre \texttt{\{} et \texttt{\}} appartiennent à \texttt{main}.
\item \texttt{printf("...")} : l'instruction qui \textbf{affiche} le texte à l'écran. Le symbole \texttt{\textbackslash n} provoque un \emph{saut de ligne}.
\item Le \textbf{point-virgule} \texttt{;} termine \textbf{chaque instruction}. C'est la ponctuation du langage C : comme le point en fin de phrase en français.
\item \texttt{return 0 ;} : la fonction \texttt{main} renvoie la valeur $0$ au système d'exploitation, ce qui signifie par convention « tout s'est bien passé ».
\end{itemize}

\begin{propriete}[Commentaires et casse en langage C]
\begin{itemize}
\item Un \cle{commentaire} est un texte ignoré par le compilateur, destiné au lecteur humain. Il en existe deux formes : \texttt{//} pour un commentaire jusqu'à la fin de la ligne, et \texttt{/* ... */} pour un commentaire sur plusieurs lignes.
\item Le langage C est \cle{sensible à la casse} : il distingue les majuscules des minuscules. Ainsi \texttt{main}, \texttt{Main} et \texttt{MAIN} sont trois noms \emph{différents}. Écrire \texttt{Printf} au lieu de \texttt{printf} provoque une erreur de compilation.
\end{itemize}
\end{propriete}

\begin{attention}[Les deux erreurs classiques du débutant]
\begin{itemize}
\item \textbf{Oublier le point-virgule} en fin d'instruction : le compilateur signale alors une erreur de syntaxe, souvent \emph{à la ligne suivante}, car c'est là qu'il découvre que l'instruction précédente n'était pas terminée. Cherche donc l'erreur une ligne \emph{au-dessus} de celle indiquée !
\item \textbf{Oublier une accolade fermante} \texttt{\}} : le compilateur signale une erreur en fin de fichier (\emph{« expected '\}' at end of input »}). Compte toujours tes accolades : autant d'ouvrantes que de fermantes.
\end{itemize}
\end{attention}

\begin{exoresolu}[Identifier et corriger les erreurs d'un programme]
\textbf{Énoncé.} Un élève de Première D a tapé le programme suivant, mais la compilation échoue. Trouve les trois erreurs et réécris le programme corrigé.
\begin{lstlisting}[language=C]

{
    printf("Moyenne generale : 14,5 / 20\n")
    return 0;
\end{lstlisting}
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
\item \texttt{int Main()} : le C est sensible à la casse ; la fonction principale doit s'écrire \texttt{main} en minuscules. Avec \texttt{Main}, le compilateur ne trouve aucun point d'entrée du programme.

\item Il manque l'\textbf{accolade fermante} \texttt{\}} qui clôt le corps de la fonction \texttt{main}.
\end{enumerate}
Programme corrigé :
\begin{lstlisting}[language=C]
#include <stdio.h>

int main()
{
    printf("Moyenne generale : 14,5 / 20\n");

}
\end{lstlisting}

\end{exoresolu}

\item Le \cle{compilateur} traduit le code source (\texttt{.c}) en exécutable (\texttt{.exe}) et signale les erreurs de syntaxe.
\item Le cycle de développement : \textbf{écrire $\rightarrow$ compiler $\rightarrow$ corriger $\rightarrow$ exécuter $\rightarrow$ tester}.
\item Tout programme C contient les directives \texttt{\#include}, une unique fonction \texttt{int main()}, un corps délimité par des accolades, des instructions terminées par \texttt{;} et un \texttt{return 0 ;} final.
\item Le C est sensible à la casse ; les commentaires \texttt{//} et \texttt{/* */} documentent le code sans affecter l'exécution.
\end{itemize}
\end{aretenir}

\coursec{Bibliothèques et fonctions d'entrée/sortie}

Dans la section précédente, tu as installé ton IDE et écrit ton premier programme C : la fameuse structure minimale avec \texttt{main()}. Tu as peut-être remarqué, sans trop t'y attarder, cette ligne mystérieuse tout en haut du programme : \texttt{\#include <stdio.h>}. Le moment est venu de percer ce mystère. Car sans elle, impossible d'afficher quoi que ce soit à l'écran ou de lire ce que l'utilisateur tape au clavier. Cette section va te révéler comment un programme C dialogue avec l'extérieur : grâce aux \cle{bibliothèques} et à leurs fonctions d'\cle{entrée/sortie}.

\courssub{Qu'est-ce qu'une bibliothèque ?}

\textbf{Situation de départ.} Imagine que tu gères la cantine du lycée et que tu veuilles un programme qui calcule la racine carrée du nombre de plats pour organiser les tables carrées. Faut-il que tu écrives toi-même l'algorithme de calcul d'une racine carrée ? Heureusement non ! Des programmeurs ont déjà écrit, testé et optimisé ces fonctions il y a des décennies. Elles sont rangées dans des fichiers que l'on appelle \emph{bibliothèques}.

\begin{definition}[Bibliothèque]
Une \cle{bibliothèque} est un fichier d'en-tête, d'extension \texttt{.h} (pour \emph{header}), qui contient des \textbf{fonctions prêtes à l'emploi} : afficher du texte, lire le clavier, calculer une racine carrée, etc. On l'inclut en tête de programme avec la directive :
\begin{lstlisting}[language=C]
#include <nom_de_la_bibliotheque.h>
\end{lstlisting}
\end{definition}

\begin{propriete}[Placement et rôle de \texttt{\#include}]
La directive \texttt{\#include} est une instruction du \textbf{préprocesseur} : avant même la compilation, elle recopie le contenu du fichier d'en-tête dans ton programme. Elle doit donc être placée \textbf{tout en haut du fichier}, avant \texttt{main()}, une par ligne. Sans l'inclusion d'une bibliothèque, l'utilisation de ses fonctions provoque une erreur de compilation (« fonction non déclarée »).
\end{propriete}

\courssub{La bibliothèque stdio.h : afficher avec printf}

\texttt{stdio.h} (\emph{standard input/output}) est la bibliothèque indispensable : c'est elle qui permet au programme de « parler » (afficher à l'écran) et d'« écouter » (lire le clavier).

\textbf{Intuition.} La fonction \texttt{printf} (\emph{print formatted}, « afficher avec format ») affiche du texte à l'écran. Mais souvent, on veut afficher la \emph{valeur} d'une variable au milieu d'une phrase. On place alors dans le texte un \textbf{trou} symbolisé par le caractère \texttt{\%}, et on donne ensuite la variable qui viendra remplir ce trou.

\begin{definition}[Les caractères \texttt{\%} et \texttt{\&}]
Le caractère \cle{\%} introduit un \textbf{format} d'affichage ou de saisie : \texttt{\%d} pour un entier, \texttt{\%f} pour un réel, \texttt{\%c} pour un caractère, \texttt{\%s} pour une chaîne de caractères. Le caractère \cle{\&} placé devant le nom d'une variable désigne son \textbf{adresse mémoire} (l'endroit exact où elle est stockée).
\end{definition}

\begin{propriete}[Syntaxe de \texttt{printf}]
\begin{lstlisting}[language=C]
printf("texte avec formats", variable1, variable2);
\end{lstlisting}
\begin{itemize}
\item Chaque format \texttt{\%...} est remplacé, dans l'ordre, par la valeur de la variable correspondante.
\item La séquence \texttt{\textbackslash n} provoque un \textbf{saut de ligne}.
\item \texttt{\%.2f} affiche un réel arrondi à \textbf{2 chiffres après la virgule} (pratique pour une moyenne !).
\end{itemize}
\end{propriete}

\begin{exemplebox}[Premiers affichages]
\begin{lstlisting}[language=C]
int age = 16;
float moyenne = 13.456;
printf("J'ai %d ans.\n", age);          /* J'ai 16 ans. */
printf("Moyenne : %.2f\n", moyenne);    /* Moyenne : 13.46 */
printf("Note : %c\n", 'A');             /* Note : A */
\end{lstlisting}
\end{exemplebox}

\begin{attention}[Formats et types doivent correspondre]
Utiliser \texttt{\%d} pour afficher un \texttt{float} (ou \texttt{\%f} pour un \texttt{int}) ne provoque pas toujours d'erreur de compilation, mais affiche des valeurs aberrantes. Retiens le trio : \texttt{int} $\rightarrow$ \texttt{\%d}, \texttt{float} $\rightarrow$ \texttt{\%f}, \texttt{char} $\rightarrow$ \texttt{\%c}.
\end{attention}

\courssub{Lire le clavier avec scanf : le rôle du caractère \&}

\textbf{Intuition.} \texttt{scanf} fait l'inverse de \texttt{printf} : elle lit ce que l'utilisateur tape au clavier et le \textbf{range dans une variable}. Mais pour ranger une valeur dans une maison, il faut connaître son \emph{adresse}. C'est exactement le rôle du caractère \texttt{\&} : \texttt{\&age} signifie « l'adresse de la case mémoire nommée \texttt{age} ». On dit que \texttt{scanf} utilise un \cle{mode d'adressage} par adresse : on ne donne pas la valeur de la variable, mais son emplacement, pour que la fonction puisse y écrire directement.

\begin{propriete}[Syntaxe de \texttt{scanf}]
\begin{lstlisting}[language=C]
scanf("format", &variable);
\end{lstlisting}
Le format doit correspondre au type de la variable : \texttt{\%d} pour un \texttt{int}, \texttt{\%f} pour un \texttt{float}, \texttt{\%c} pour un \texttt{char}.
\end{propriete}

\begin{methode}[Lire correctement une variable avec \texttt{scanf}]
\begin{enumerate}
\item Identifier le \textbf{type} de la variable à remplir (\texttt{int}, \texttt{float}, \texttt{char}).
\item Choisir le \textbf{format} correspondant : \texttt{\%d}, \texttt{\%f} ou \texttt{\%c}.
\item Écrire \texttt{scanf("format", \&variable);} en n'oubliant \textbf{jamais} le \texttt{\&} devant le nom de la variable.
\item Afficher avant la saisie un message d'invite avec \texttt{printf} pour guider l'utilisateur.
\end{enumerate}
\end{methode}

\begin{attention}[Erreur fréquente n°1 : oublier le \&]
Écrire \texttt{scanf("\%d", age);} sans le \texttt{\&} est l'erreur classique du débutant : \texttt{scanf} reçoit la \emph{valeur} de \texttt{age} au lieu de son \emph{adresse}, et tente d'écrire à un emplacement mémoire invalide. Résultat : le programme \textbf{plante} (fenêtre qui se ferme brutalement, erreur de segmentation). De même, saisir un \texttt{float} avec \texttt{\%d} fausse complètement la valeur lue.
\end{attention}

\courssub{Les autres bibliothèques : stdlib.h, math.h, conio.h}

\textbf{stdlib.h} (\emph{standard library}) fournit des fonctions utilitaires : \texttt{system("cls")} efface l'écran de la console (sous Windows), \texttt{rand()} génère un nombre pseudo-aléatoire, \texttt{exit(0)} termine immédiatement le programme, \texttt{abs(x)} renvoie la valeur absolue d'un entier.

\textbf{math.h} contient les fonctions mathématiques : \texttt{sqrt(x)} (racine carrée), \texttt{pow(x, y)} ($x^y$), \texttt{fabs(x)} (valeur absolue d'un réel). Indispensable pour les calculs scientifiques des séries C, D et E. \emph{Note : pour utiliser ces fonctions, il faut parfois lier explicitement la bibliothèque mathématique à la compilation (option \texttt{-lm} sous GCC), mais les IDE scolaires (Code::Blocks, Dev-C++) le font automatiquement.}

\textbf{conio.h} (\emph{console input/output}, disponible sous Windows) fournit \texttt{getch()}, qui lit un caractère au clavier \emph{sans l'afficher} et sans attendre la touche Entrée. Placé juste avant \texttt{return 0;}, il force le programme à attendre une touche : la fenêtre console reste ouverte et tu peux lire tes résultats.

\begin{savaistu}[Pourquoi la fenêtre se ferme-t-elle trop vite ?]
Quand tu lances ton programme depuis l'IDE, la console s'ouvre, exécute le programme en une fraction de seconde, puis se ferme aussitôt : impossible de lire le résultat ! La fonction \texttt{getch()} de \texttt{conio.h} résout ce problème : elle met le programme en \textbf{pause} jusqu'à ce qu'une touche soit pressée. C'est l'astuce utilisée par tous les élèves camerounais qui programment en C sous Windows avec Code::Blocks ou Dev-C++.
\end{savaistu}

\begin{exoresolu}[Moyenne de deux notes]
Énoncé. Écrire un programme C complet qui demande à un élève ses deux notes de séquence (réels), calcule sa moyenne et l'affiche avec deux chiffres après la virgule.
\tcblower
Solution détaillée.
\begin{lstlisting}[language=C]
#include <stdio.h>   /* printf et scanf */
#include <stdlib.h>  /* fonctions utilitaires */
#include <conio.h>   /* getch : pause ecran */

int main()
{
    float note1, note2, moy;   /* declaration des variables */

    printf("Entrez la premiere note : ");
    scanf("%f", &note1);       /* %f car float, & obligatoire */

    printf("Entrez la deuxieme note : ");
    scanf("%f", &note2);

    moy = (note1 + note2) / 2; /* calcul de la moyenne */

    printf("Votre moyenne est : %.2f\n", moy);

    getch();     /* pause : la fenetre reste ouverte */
    return 0;
}
\end{lstlisting}
Trace d'exécution : si l'utilisateur saisit \texttt{12} puis \texttt{15}, le programme calcule $moy = (12 + 15) / 2 = 13{,}5$ et affiche : \texttt{Votre moyenne est : 13.50}. Remarque l'usage de \texttt{\%.2f} qui arrondit proprement l'affichage, et le \texttt{\&} devant chaque variable dans \texttt{scanf}.
\end{exoresolu}

\textbf{Matériel :} un poste avec Code::Blocks (ou Dev-C++) installé.

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
\item Une \cle{bibliothèque} (\texttt{.h}) regroupe des fonctions prêtes à l'emploi ; on l'inclut en tête de programme avec \texttt{\#include <nom.h>}.
\item \texttt{stdio.h} : \texttt{printf} (afficher) et \texttt{scanf} (saisir) ; \texttt{stdlib.h} : utilitaires (\texttt{abs}, \texttt{rand}...) ; \texttt{math.h} : calculs (\texttt{sqrt}, \texttt{pow}, \texttt{fabs}) ; \texttt{conio.h} : \texttt{getch()}.
\item Le caractère \cle{\%} introduit un format : \texttt{\%d} (entier), \texttt{\%f} (réel), \texttt{\%c} (caractère), \texttt{\%s} (chaîne) ; \texttt{\textbackslash n} saute une ligne.
\item Dans \texttt{scanf}, le caractère \cle{\&} donne l'\textbf{adresse} de la variable (mode d'adressage) : l'oublier fait planter le programme.
\end{itemize}
\end{aretenir}

\coursec{Variables, types et mode d'adressage}

Dans la section précédente, nous avons découvert les fonctions \texttt{printf} et \texttt{scanf} pour dialoguer avec l'utilisateur. Nous avons vu que \texttt{scanf} exigeait un symbole mystérieux \texttt{\&} devant le nom de la variable. Pourquoi ce symbole ? Que devient l'information une fois stockée ? Comment une fonction peut-elle modifier une variable qui lui est confiée ? C'est tout l'objet de cette section : comprendre comment les données sont organisées en mémoire et comment les fonctions y accèdent.

\courssub{Types de base, déclaration et initialisation}

En C, toute variable doit être \textbf{déclarée} avant d'être utilisée. La déclaration réserve une zone en mémoire (la \emph{RAM}) et associe un \textbf{nom} (l'identificateur) à cette zone. Le \textbf{type} détermine la taille de la zone réservée et la manière dont les bits sont interprétés (entier, réel, caractère).

\begin{definition}[Types de base en C]
Les quatre types fondamentaux (dits \emph{scalaire}) sont :
\begin{itemize}
    \item \cle{int} : entier signé (généralement 4 octets sur architecture 32/64 bits modernes). Intervalle typique : $[-2\,147\,483\,648 ; 2\,147\,483\,647]$.
    \item \cle{float} : réel simple précision (4 octets, environ 6-7 chiffres significatifs).
    \item \cle{double} : réel double précision (8 octets, environ 15 chiffres significatifs). C'est le type par défaut pour les constantes réelles (\texttt{3.14} est un \texttt{double}).
    \item \cle{char} : caractère unique (1 octet). Stocke un code ASCII/UTF-8 (ex. \texttt{'A'}, \texttt{'7'}, \texttt{'+'}).
\end{itemize}
\end{definition}

\begin{propriete}[Syntaxe de déclaration et d'initialisation]
\begin{itemize}
    \item \textbf{Déclaration simple :} \texttt{type identificateur ;} (la valeur est indéterminée, « poubelle »).
    \item \textbf{Initialisation à la déclaration :} \texttt{type identificateur = valeur ;}
    \item \textbf{Déclaration multiple :} \texttt{type id1, id2 = val2, id3 ;}
\end{itemize}
Les identificateurs respectent les règles : lettres, chiffres, underscore \texttt{\_}, ne commencent pas par un chiffre, sensible à la casse (\texttt{note} $\neq$ \texttt{Note}).
\end{propriete}

\begin{exemplebox}[Déclarations variées]
\begin{lstlisting}[language=C]
#include <stdio.h>

int main() {
    // Entiers
    int age = 17;           // Initialisation
    int nombreEleves;       // Non initialisé (valeur aléatoire)
    nombreEleves = 45;      // Affectation ultérieure

    // Réels
    float moyenne = 12.5f;  // Le suffixe 'f' force le type float
    double pi = 3.141592653589793; // Précision supérieure

    // Caractères
    char initiale = 'K';    // Guillemets simples obligatoires
    char toucheEntree = '\n'; // Caractère d'échappement (retour à la ligne)

    // Affichage avec les bons spécificateurs de format
    printf("Age : %d ans\n", age);
    printf("Moyenne : %.2f / 20\n", moyenne);
    printf("PI approx : %.10f\n", pi);
    printf("Initiale : %c (code ASCII %d)\n", initiale, initiale);

    return 0;
}
\end{lstlisting}
\emph{Remarque :} \texttt{\%d} pour \texttt{int}, \texttt{\%f} pour \texttt{float}/\texttt{double} (en \texttt{printf}, \texttt{float} est promu en \texttt{double}), \texttt{\%c} pour \texttt{char}. Le \texttt{.2f} limite l'affichage à 2 décimales.
\end{exemplebox}

\courssub{La mémoire et l'opérateur \texttt{\&} (adresse de)}

Chaque variable déclarée occupe une ou plusieurs \textbf{cases mémoire} contiguës. Chaque case a une \textbf{adresse} unique (un numéro d'ordre hexadécimal, ex. \texttt{0x7ffd4a3c}). L'opérateur \texttt{\&} (lu « adresse de ») permet de récupérer cette adresse.

\begin{definition}[Opérateur \texttt{\&} (adresse de)]
Si \texttt{x} est une variable, \texttt{\&x} est une \textbf{constante} (on ne peut pas la modifier) de type « adresse de \texttt{x} » (techniquement un \emph{pointeur}, notion approfondie en Terminale). Elle indique \emph{où} se trouve \texttt{x} en mémoire.
\end{definition}

C'est pourquoi \texttt{scanf} exige \texttt{\&variable} : la fonction a besoin de savoir \emph{où} écrire la valeur lue au clavier. Si on oublie le \texttt{\&}, \texttt{scanf} écrit à une adresse aléatoire (contenu de la variable non initialisée) $\rightarrow$ plantage ou corruption mémoire.

\courssub{Paramètres de fonction et modes d'adressage}

Une \textbf{fonction} reçoit des données via ses \textbf{paramètres formels} (déclarés dans l'en-tête) qui prennent les valeurs des \textbf{arguments réels} (fourni à l'appel). Le \textbf{mode d'adressage} (ou mode de passage) définit \emph{comment} cette transmission s'effectue.

\begin{definition}[Mode d'adressage (Passage de paramètres)]
Le mode d'adressage précise la mécanique de transmission des données entre l'appelant et la fonction appelée :
\begin{enumerate}
    \item \textbf{Passage par valeur (par défaut en C) :} La fonction reçoit une \textbf{copie} de la valeur de l'argument. Toute modification du paramètre à l'intérieur de la fonction n'affecte \emph{que la copie locale} ; la variable de l'appelant reste inchangée.
    \item \textbf{Passage par adresse (simulé en C) :} L'appelant transmet l'\textbf{adresse} de la variable (\texttt{\&var}). Le paramètre formel est alors une variable capable de stocker une adresse (un \emph{pointeur}). La fonction peut \textbf{modifier le contenu de la case mémoire d'origine} en déréférençant l'adresse (opérateur \texttt{*}).
\end{enumerate}
\end{definition}

\begin{propriete}[Règle fondamentale en C (admise)]
\textbf{En langage C, tout passage de paramètre se fait par valeur.}
Pour obtenir l'effet d'un passage par adresse (modifier la variable appelante), on \textbf{passe explicitement l'adresse de la variable} (\texttt{\&variable}) et le paramètre formel est déclaré comme un pointeur (ex. \texttt{int *p}).
\end{propriete}

\begin{exemplebox}[Échec du passage par valeur : tentative d'échange]
\begin{lstlisting}[language=C]
#include <stdio.h>

// Version INCORRECTE : passage par valeur
void echange_valeur(int x, int y) {
    int temp = x;
    x = y;
    y = temp;
    printf("Dans echange_valeur : x=%d, y=%d\n", x, y); // Affiche 9, 5
}

int main() {
    int a = 5, b = 9;
    printf("Avant appel : a=%d, b=%d\n", a, b); // Affiche 5, 9
    echange_valeur(a, b); // Copies de 5 et 9 transmises
    printf("Apres appel  : a=%d, b=%d\n", a, b); // Affiche 5, 9 (INCHANGÉ !)
    return 0;
}
\end{lstlisting}
Ici, \texttt{x} et \texttt{y} sont des variables locales à \texttt{echange\_valeur}. Elles meurent à la fin de la fonction. \texttt{a} et \texttt{b} n'ont jamais été touchées.
\end{exemplebox}

\begin{exoresolu}[Échange réussi par passage d'adresses]
\textbf{Énoncé :} Écrire une fonction \texttt{echange} qui inverse réellement le contenu de deux variables entières \texttt{a} et \texttt{b} du \texttt{main}. Tracer l'exécution pas à pas.

\textbf{Solution détaillée :}

\begin{lstlisting}[language=C]
#include <stdio.h>

// Paramètres formels : pointeurs (adresses)
void echange(int *px, int *py) {
    int temp = *px; // 1. Lit la valeur À L'ADRESSE px (déréférencement *)
    *px = *py;      // 2. Écrit la valeur de py DANS l'adresse px
    *py = temp;     // 3. Écrit temp DANS l'adresse py
}

int main() {
    int a = 5, b = 9;
    printf("1. Avant : a=%d (adresse %p), b=%d (adresse %p)\n", a, &a, b, &b);
    
    echange(&a, &b); // Appel : on transmet LES ADRESSES
    
    printf("4. Apres : a=%d, b=%d\n", a, b);
    return 0;
}
\end{lstlisting}

\textbf{Trace d'exécution détaillée (exécution pas à pas) :}

\begin{center}
\begin{tabularx}{\linewidth}{|c|X|c|c|}
\hline
\textbf{Étape} & \textbf{Action} & \textbf{État mémoire (a, b)} & \textbf{Commentaire} \\
\hline
1 & \texttt{int a=5, b=9;} & a=5 @\texttt{0x100}, b=9 @\texttt{0x104} & Allocation dans \texttt{main} \\
\hline
2 & \texttt{echange(\&a, \&b);} & \texttt{px = 0x100}, \texttt{py = 0x104} & \texttt{px} pointe vers \texttt{a}, \texttt{py} vers \texttt{b} \\
\hline
3 & \texttt{temp = *px;} & \texttt{temp = 5} & \texttt{*} lit le contenu de \texttt{0x100} \\
\hline
4 & \texttt{*px = *py;} & \textbf{a=9}, b=9 & \texttt{*} écrit 9 à \texttt{0x100} (\texttt{a} change !) \\
\hline
5 & \texttt{*py = temp;} & a=9, \textbf{b=5} & \texttt{*} écrit 5 à \texttt{0x104} (\texttt{b} change !) \\
\hline
6 & Fin fonction & a=9, b=5 & Variables locales \texttt{px, py, temp} détruites \\
\hline
\end{tabularx}
\end{center}

\textbf{Résultat final :} \texttt{Apres : a=9, b=5}. L'échange a bien eu lieu car la fonction a écrit directement dans les cases mémoire de \texttt{a} et \texttt{b} grâce à leurs adresses.
\end{exoresolu}

\begin{attention}[Piège classique : confusion valeur / adresse]
\begin{itemize}
    \item \textbf{Erreur :} \texttt{void f(int x) \{ x = 10; \}} appelé par \texttt{f(a);} $\rightarrow$ \texttt{a} ne change pas.
    \item \textbf{Correct :} \texttt{void f(int *x) \{ *x = 10; \}} appelé par \texttt{f(\&a);} $\rightarrow$ \texttt{a} devient 10.
    \item \textbf{Erreur \texttt{scanf} :} \texttt{scanf("\%d", age);} au lieu de \texttt{scanf("\%d", \&age);}. Le programme lit l'entrée mais l'écrit n'importe où (souvent \texttt{Segmentation fault}).
    \item \textbf{Oubli du \texttt{*} dans la fonction :} Recevoir \texttt{int *p} mais écrire \texttt{p = 10;} (change l'adresse locale, pas la valeur pointée). Il faut \texttt{*p = 10;}.
\end{itemize}
\end{attention}

\begin{savaistu}[Le \texttt{\&} et le \texttt{*} : un duo inséparable]
L'opérateur \texttt{\&} (adresse de) est l'\textbf{opérateur de référencement} : il fabrique une référence (une adresse) vers une variable.
Son inverse est l'opérateur \texttt{*} (étoile), appelé \textbf{opérateur de déréférencement} (ou indirection) : \texttt{*p} signifie « la valeur stockée \emph{à l'adresse} contenue dans \texttt{p} ».
\begin{itemize}
    \item \texttt{p = \&a;} \quad ($\leftarrow$ \texttt{p} reçoit l'adresse de \texttt{a})
    \item \texttt{*p = 20;} \quad ($\leftarrow$ on met 20 \emph{dans} la case pointée par \texttt{p}, donc dans \texttt{a})
\end{itemize}
Cette mécanique \texttt{\&} / \texttt{*} est le cœur de la manipulation mémoire en C. Les pointeurs (\texttt{int *}, \texttt{float *}, etc.) seront le sujet principal de votre programme de \textbf{Terminale}. Maîtriser \texttt{\&} et le passage d'adresse dès la Première, c'est préparer cet avenir sereinement !
\end{savaistu}

\begin{methode}[Comment choisir le mode de passage pour une fonction ?]
\begin{enumerate}
    \item \textbf{La fonction a-t-elle besoin de modifier la variable de l'appelant ?}
        \begin{itemize}
            \item \textbf{NON} (lecture seule : calcul, affichage, test) $\rightarrow$ \textbf{Passage par valeur}. Simple, sûr, efficace pour les petits types (\texttt{int}, \texttt{float}, \texttt{char}).
            \item \textbf{OUI} (échange, saisie, modification d'état, retour de plusieurs résultats) $\rightarrow$ \textbf{Passage par adresse}.
        \end{itemize}
    \item \textbf{Si passage par adresse :}
        \begin{itemize}
            \item Dans l'en-tête : type pointeur (\texttt{void f(int *p);}).
            \item Dans le corps : déréférencer pour lire/écrire (\texttt{*p = ...;} ou \texttt{x = *p;}).
            \item À l'appel : passer l'adresse (\texttt{f(\&variable);}).
        \end{itemize}
    \item \textbf{Cas particulier : les tableaux.} Un nom de tableau \emph{est déjà une adresse} (adresse du premier élément). On ne met \textbf{jamais} de \texttt{\&} devant un nom de tableau pour le passer à une fonction (voir section 5 sur les tableaux).
\end{enumerate}
\end{methode}

\begin{experience}[TP guidé : Observer les adresses et tester les passages]
\textbf{Objectif :} Visualiser les adresses mémoire et constater la différence entre passage par valeur et passage par adresse.
\textbf{Matériel :} IDE C (Code::Blocks, Dev-C++, VS Code + GCC) ou compilateur en ligne (OnlineGDB, Replit).

\textbf{Manipulation :}
\begin{enumerate}
    \item Créez un nouveau projet \texttt{TestAdresses.c}.
    \item Copiez le code ci-dessous.
    \item Compilez et exécutez. Notez les adresses affichées (elles changent à chaque exécution : \emph{ASLR}).
    \item Commentez l'appel \texttt{modifier\_valeur} et décommentez \texttt{modifier\_adresse}. Réexécutez.
\end{enumerate}

\begin{lstlisting}[language=C]
#include <stdio.h>

void afficher_adresses(int v, int *pv) {
    printf("  [Fonction] Valeur recue (copie) : %d @ %p\n", v, (void*)&v);
    printf("  [Fonction] Adresse recue (pointeur) : %p -> valeur %d\n", (void*)pv, *pv);
}

void modifier_valeur(int x) { x = 999; } // Passage par valeur
void modifier_adresse(int *px) { *px = 999; } // Passage par adresse

int main() {
    int variable = 42;
    printf("--- Dans main ---\n");
    printf("Variable 'variable' = %d @ %p\n\n", variable, (void*)&variable);

    printf("1. Appel passage par VALEUR :\n");
    afficher_adresses(variable, &variable);
    modifier_valeur(variable);
    printf("Apres modifier_valeur : variable = %d (inchangé ?)\n\n", variable);

    printf("2. Appel passage par ADRESSE :\n");
    afficher_adresses(variable, &variable);
    modifier_adresse(&variable);
    printf("Apres modifier_adresse : variable = %d (modifié !)\n", variable);

    return 0;
}
\end{lstlisting}

\textbf{Observations attendues :}
\begin{itemize}
    \item L'adresse de \texttt{variable} dans \texttt{main} (\texttt{\&variable}) est \textbf{identique} à l'adresse affichée par \texttt{afficher\_adresses} pour le pointeur \texttt{pv}.
    \item L'adresse du paramètre \texttt{v} (copie) dans \texttt{afficher\_adresses} est \textbf{différente} de celle de \texttt{variable}.
    \item \texttt{modifier\_valeur} ne change pas \texttt{variable} (reste 42).
    \item \texttt{modifier\_adresse} change \texttt{variable} (devient 999).
\end{itemize}

\textbf{Interprétation :} Cela prouve concrètement que C passe \emph{toujours} par valeur (la copie \texttt{v} a une adresse différente), mais qu'en passant \texttt{\&variable}, on donne à la fonction les moyens d'agir sur l'original.
\end{experience}

\begin{aretenir}[Synthèse : Variables, Types et Adressage]
\begin{itemize}
    \item \textbf{Types de base :} \texttt{int}, \texttt{float}, \texttt{double}, \texttt{char}. Déclaration : \texttt{type nom = valeur;}.
    \item \textbf{Mémoire :} Chaque variable a une \textbf{adresse} unique (hexadécimal).
    \item \textbf{Opérateur \texttt{\&} :} \texttt{\&x} donne l'adresse de \texttt{x}. Indispensable pour \texttt{scanf} et le passage par adresse.
    \item \textbf{Passage par valeur (défaut) :} Copie locale. \textbf{Ne modifie pas l'original.}
    \item \textbf{Passage par adresse (simulé) :} On passe \texttt{\&x}. Paramètre formel : pointeur \texttt{type *p}. Accès à la valeur : \texttt{*p}. \textbf{Modifie l'original.}
    \item \textbf{Règle d'or :} Pour modifier un argument $\rightarrow$ passage d'adresse (\texttt{\&} à l'appel, \texttt{*} dans la fonction).
\end{itemize}
\end{aretenir}

\coursec{Les structures répétitives : for, while, do...while}

Dans la section précédente, tu as appris à déclarer des variables, à choisir le bon type (\texttt{int}, \texttt{float}, \texttt{char}) et tu as compris le mode d'adressage qui permet à \texttt{scanf} de modifier une variable grâce à l'opérateur \texttt{\&}. Tu sais donc maintenant stocker et saisir des données. Mais un programme qui ne fait les choses qu'une seule fois reste limité : imagine que le proviseur te demande d'afficher la table de multiplication de 7, ou de calculer la somme des notes de 60 élèves d'une classe de Première C. Vas-tu écrire 60 fois la même instruction ? Bien sûr que non : il faut \cle{répéter} des instructions. C'est le rôle des \cle{structures répétitives} (ou boucles), que tu as déjà rencontrées en algorithmique avec \texttt{Pour} et \texttt{TantQue}. Nous allons maintenant les traduire en langage C.

\courssub{Rappel algorithmique : les deux grandes familles de boucles}

En algorithmique, tu as distingué deux situations :

\begin{itemize}
\item La \cle{boucle à nombre d'itérations connu} : on sait \emph{à l'avance} combien de fois on va répéter. Exemple : « afficher la table de 7, de $1$ à $10$ ». On utilise \texttt{Pour ... FinPour}.
\item La \cle{boucle à condition d'arrêt} : on ne sait pas combien de fois on va répéter ; on continue \emph{tant qu'une condition est vraie}. Exemple : « redemander la note tant qu'elle n'est pas entre 0 et 20 ». On utilise \texttt{TantQue ... FinTantQue} ou \texttt{Répéter ... Jusqu'à}.
\end{itemize}

Le langage C propose exactement trois instructions pour couvrir ces situations : \texttt{for}, \texttt{while} et \texttt{do...while}. Le tableau de correspondance suivant résume tout.

\begin{attention}[Inversion de sens pour do...while]
Le \texttt{Répéter ... Jusqu'à} de l'algorithmique s'arrête quand la condition devient \emph{vraie}, alors que le \texttt{do...while} du C \emph{continue} tant que la condition est vraie. Les conditions sont donc \textbf{contraires} : « Jusqu'à note valide » devient « \texttt{while(note invalide)} ».
\end{attention}

\courssub{La boucle for : quand le nombre d'itérations est connu}

\begin{definition}[Boucle for]
La boucle \cle{for} répète un bloc d'instructions un nombre de fois déterminé, en faisant évoluer automatiquement une variable appelée \cle{compteur}. Sa syntaxe est :
\begin{lstlisting}[language=C]
for(initialisation ; condition ; increment) {
    instructions;
}
\end{lstlisting}
\end{definition}

Les trois parties entre parenthèses, séparées par des \textbf{points-virgules}, jouent chacune un rôle précis :

\begin{enumerate}
\item \texttt{initialisation} : exécutée \textbf{une seule fois}, au tout début (ex. \texttt{i=1}) ;
\item \texttt{condition} : testée \textbf{avant chaque itération} ; si elle est fausse, la boucle s'arrête (ex. \texttt{i<=10}) ;
\item \texttt{increment} : exécuté \textbf{après chaque itération}, pour faire progresser le compteur (ex. \texttt{i++}).
\end{enumerate}

Pour écrire ces conditions, tu disposes des opérateurs de comparaison du C : \texttt{==} (égal), \texttt{!=} (différent), \texttt{<}, \texttt{>}, \texttt{<=}, \texttt{>=}. Et pour faire évoluer le compteur, le C offre des opérateurs raccourcis très pratiques :

\begin{center}
\begin{tabularx}{\linewidth}{|l|l|X|}
\hline
\rowcolor{popblueL} \textbf{Opérateur} & \textbf{Équivalent} & \textbf{Effet} \\
\hline
\texttt{i++} & \texttt{i = i + 1} & incrémente \texttt{i} de 1 \\
\hline
\texttt{i-{}-} & \texttt{i = i - 1} & décrémente \texttt{i} de 1 \\
\hline
\texttt{i += 3} & \texttt{i = i + 3} & augmente \texttt{i} de 3 \\
\hline
\texttt{i -= 2} & \texttt{i = i - 2} & diminue \texttt{i} de 2 \\
\hline
\end{tabularx}
\end{center}

\begin{exemplebox}[La table de multiplication de 7]
Voici le programme complet qui affiche la table de 7, de $7 \times 1 = 7$ jusqu'à $7 \times 10 = 70$ :
\begin{lstlisting}[language=C]
#include <stdio.h>
#include <stdlib.h>

int main() {
    int i;                 // compteur de la boucle

    printf("Table de multiplication de 7\n");
    for(i = 1; i <= 10; i++) {
        printf("7 x %d = %d\n", i, 7 * i);
    }
    return 0;
}
\end{lstlisting}
Déroulement : \texttt{i} vaut 1, le test \texttt{i<=10} est vrai, on affiche « 7 x 1 = 7 », puis \texttt{i++} fait passer \texttt{i} à 2, et ainsi de suite. Quand \texttt{i} atteint 11, le test devient faux et la boucle s'arrête. Le programme a donc affiché exactement 10 lignes avec seulement 3 lignes de code.
\end{exemplebox}

\courssub{La boucle while : le test avant chaque itération}

\begin{definition}[Boucle while]
La boucle \cle{while} (« tant que ») répète un bloc d'instructions \textbf{tant qu'une condition est vraie}. Le test est effectué \emph{avant} chaque itération : si la condition est fausse dès le départ, le corps de la boucle n'est \textbf{jamais exécuté}.
\begin{lstlisting}[language=C]
while(condition) {
    instructions;
}
\end{lstlisting}
\end{definition}

C'est la boucle idéale quand on ne connaît pas le nombre de répétitions à l'avance. Par exemple, calculons la somme $S = 1 + 2 + \cdots + n$ où $n$ est saisi par l'utilisateur :

\begin{lstlisting}[language=C]
#include <stdio.h>

int main() {
    int n, i, somme;

    printf("Entrez n : ");
    scanf("%d", &n);        // ne pas oublier le & !

    i = 1;                  // initialisation AVANT la boucle
    somme = 0;
    while(i <= n) {         // test avant chaque iteration
        somme = somme + i;  // accumulation
        i++;                // increment OBLIGATOIRE
    }
    printf("Somme = %d\n", somme);
    return 0;
}
\end{lstlisting}

Pour $n = 4$, la table d'exécution est la suivante :

\begin{center}
\begin{tabularx}{\linewidth}{|l|X|X|X|}
\hline
\rowcolor{popblueL} \textbf{Itération} & \textbf{Test \texttt{i<=n}} & \textbf{\texttt{somme}} & \textbf{\texttt{i} après \texttt{i++}} \\
\hline
1 & $1 \le 4$ : vrai & 1 & 2 \\
\hline
2 & $2 \le 4$ : vrai & 3 & 3 \\
\hline
3 & $3 \le 4$ : vrai & 6 & 4 \\
\hline
4 & $4 \le 4$ : vrai & 10 & 5 \\
\hline
5 & $5 \le 4$ : faux, sortie & 10 & 5 \\
\hline
\end{tabularx}
\end{center}

Le programme affiche bien \texttt{Somme = 10}.

\courssub{La boucle do...while : le corps s'exécute au moins une fois}

\begin{definition}[Boucle do...while]
La boucle \cle{do...while} exécute d'abord le corps, \emph{puis} teste la condition : le corps est donc exécuté \textbf{au moins une fois}, même si la condition est fausse dès le départ.
\begin{lstlisting}[language=C]
do {
    instructions;
} while(condition);
\end{lstlisting}
Remarque le \textbf{point-virgule obligatoire} après \texttt{while(condition)} : c'est la seule boucle du C qui se termine ainsi.
\end{definition}

L'organigramme ci-dessous met en évidence la différence fondamentale entre \texttt{while} (test en entrée) et \texttt{do...while} (test en sortie).

Application typique : la \cle{saisie contrôlée}. On veut obliger l'utilisateur à entrer une note entre 0 et 20. Il faut lui poser la question au moins une fois, et recommencer tant que la valeur est invalide :

\begin{lstlisting}[language=C]
#include <stdio.h>

int main() {
    float note;

    do {
        printf("Entrez une note entre 0 et 20 : ");
        scanf("%f", &note);
    } while(note < 0 || note > 20);   // on recommence si invalide

    printf("Note validee : %.2f\n", note);
    return 0;
}
\end{lstlisting}

Ici, la condition de poursuite \texttt{note < 0 || note > 20} est bien le \emph{contraire} de la condition d'arrêt « note valide » de l'algorithmique.

\courssub{Équivalence entre for et while}

\begin{propriete}[Toute boucle for peut s'écrire avec while]
Les deux constructions suivantes sont strictement équivalentes :
\begin{lstlisting}[language=C]
for(i = 1; i <= n; i++) {
    instructions;
}
\end{lstlisting}
\begin{lstlisting}[language=C]
i = 1;                  // initialisation sortie de la boucle
while(i <= n) {         // meme condition
    instructions;
    i++;                // increment deplace a la fin du corps
}
\end{lstlisting}
\end{propriete}

Démonstration guidée, ligne à ligne, sur la table de 7. Partons du \texttt{for} :

\begin{enumerate}
\item On \textbf{extrait l'initialisation} \texttt{i = 1} et on la place \emph{avant} la boucle : c'est la première chose que le \texttt{for} exécute, une seule fois.
\item La \textbf{condition} \texttt{i <= 10} devient la condition du \texttt{while} : dans les deux cas, elle est testée avant chaque passage.
\item Le corps \texttt{printf(...)} reste \textbf{inchangé}.
\item L'\textbf{incrément} \texttt{i++}, que le \texttt{for} exécute après chaque passage, est recopié comme \emph{dernière instruction} du corps du \texttt{while}.
\end{enumerate}

On obtient :

\begin{lstlisting}[language=C]
i = 1;
while(i <= 10) {
    printf("7 x %d = %d\n", i, 7 * i);
    i++;
}
\end{lstlisting}

Ce programme affiche exactement les mêmes 10 lignes que la version avec \texttt{for}. Le \texttt{for} n'est donc qu'une écriture plus compacte et plus sûre (on ne risque pas d'oublier l'incrément, il est dans l'en-tête).

\courssub{Choisir la bonne boucle et éviter la boucle infinie}

\begin{methode}[Quelle boucle choisir ?]
Face à un problème, pose-toi ces questions dans l'ordre :
\begin{enumerate}
\item \textbf{Le nombre de répétitions est-il connu à l'avance ?} (table de multiplication, 60 élèves, 12 mois) $\Rightarrow$ utilise \texttt{for}.
\item \textbf{La répétition dépend-elle d'une condition, avec un test à faire AVANT la première exécution ?} (tant que la somme ne dépasse pas un seuil, tant qu'on n'a pas trouvé) $\Rightarrow$ utilise \texttt{while}.
\item \textbf{Le corps doit-il s'exécuter au moins une fois avant tout test ?} (saisie contrôlée, menu) $\Rightarrow$ utilise \texttt{do...while}.
\end{enumerate}
\end{methode}

\begin{attention}[Les deux erreurs qui créent une boucle infinie]
\textbf{Erreur n°1 : le point-virgule juste après le test.}
\begin{lstlisting}[language=C]
while(i <= 10);        // ERREUR : ce ; cree un corps VIDE
{
    printf("%d\n", i);
    i++;
}
\end{lstlisting}
Le \texttt{;} seul constitue le corps de la boucle : le programme tourne indéfiniment sur une boucle vide, car \texttt{i} ne change jamais. Le bloc entre accolades n'est exécuté qu'après... donc jamais.

\textbf{Erreur n°2 : oublier l'incrément.}
\begin{lstlisting}[language=C]
i = 1;
while(i <= 10) {
    printf("%d\n", i);
    // i++ oublie : i reste a 1, boucle infinie !
}
\end{lstlisting}
La condition reste vraie éternellement. Dans toute boucle \texttt{while} ou \texttt{do...while}, vérifie toujours qu'au moins une instruction du corps fait progresser la condition vers l'arrêt.
\end{attention}

\begin{savaistu}[do...while : la boucle des menus]
Le \texttt{do...while} est la boucle préférée des programmeurs pour les \textbf{menus interactifs}. Pourquoi ? Parce qu'un menu doit s'afficher \emph{au moins une fois} pour que l'utilisateur puisse choisir, puis on recommence tant que le choix est invalide ou différent de « Quitter ». C'est exactement le principe des applications mobiles camerounaises de transfert d'argent : le menu « 1. Envoyer / 2. Retirer / 0. Quitter » s'affiche, puis se réaffiche tant que tu n'as pas choisi 0. En C :
\begin{lstlisting}[language=C]
int choix;
do {
    printf("1. Envoyer  2. Retirer  0. Quitter : ");
    scanf("%d", &choix);
} while(choix != 0);
\end{lstlisting}
\end{savaistu}

\begin{exoresolu}[Somme des n premiers entiers pairs]
\textbf{Énoncé.} Écrire un programme C qui demande un entier $n \geq 1$ à l'utilisateur (avec saisie contrôlée), puis calcule et affiche la somme des $n$ premiers entiers pairs : $S = 2 + 4 + 6 + \cdots + 2n$.
\tcblower
\textbf{Solution détaillée.} Analysons : la saisie contrôlée exige un \texttt{do...while} (on pose la question au moins une fois) ; le calcul de la somme porte sur un nombre connu de termes ($n$ termes), donc un \texttt{for}. Le $i$-ème entier pair vaut $2i$.
\begin{lstlisting}[language=C]
#include <stdio.h>

int main() {
    int n, i, somme = 0;

    // Saisie controlee : n doit etre >= 1
    do {
        printf("Entrez un entier n >= 1 : ");
        scanf("%d", &n);
    } while(n < 1);

    // Somme des n premiers pairs : 2 + 4 + ... + 2n
    for(i = 1; i <= n; i++) {
        somme += 2 * i;    // equivalent a somme = somme + 2*i
    }

    printf("Somme des %d premiers pairs = %d\n", n, somme);
    return 0;
}
\end{lstlisting}
Vérification pour $n = 3$ : la boucle ajoute $2$, puis $4$, puis $6$, donc \texttt{somme = 12}. Le programme affiche : \texttt{Somme des 3 premiers pairs = 12}. C'est correct, car $2 + 4 + 6 = 12$ (on retrouve d'ailleurs la formule $S = n(n+1) = 3 \times 4 = 12$).
\end{exoresolu}

\item Réécris le programme de la table de 7 en utilisant uniquement une boucle \texttt{while}.
\item Écris un programme qui demande un mot de passe (entier, par exemple 1234) et recommence la saisie tant que le mot de passe est faux. Quelle boucle choisis-tu et pourquoi ?
\end{enumerate}

\begin{enumerate}

\end{lstlisting}
\item \begin{lstlisting}[language=C]

    printf("7 x %d = %d\n", i, 7 * i);

}
\end{lstlisting}
\item On choisit \texttt{do...while}, car il faut demander le mot de passe au moins une fois avant de pouvoir le tester :
\begin{lstlisting}[language=C]

\end{lstlisting}
\end{enumerate}
\end{corrige}

\begin{aretenir}[L'essentiel des boucles en C]
\begin{itemize}
\item \texttt{for(init ; condition ; increment)} : nombre d'itérations connu ; l'en-tête regroupe tout le pilotage de la boucle.
\item \texttt{while(condition)} : test \emph{avant} chaque passage ; le corps peut ne jamais s'exécuter.
\item \texttt{do \{...\} while(condition);} : test \emph{après} ; le corps s'exécute au moins une fois ; attention au \texttt{;} final.
\item Tout \texttt{for} se réécrit en \texttt{while} : initialisation avant, condition dans le test, incrément à la fin du corps.
\item Jamais de \texttt{;} juste après \texttt{while(condition)}, et jamais de boucle sans instruction qui fait progresser la condition vers l'arrêt.
\end{itemize}
\end{aretenir}

\coursec{Les tableaux à une dimension}

Dans la section précédente, tu as appris à répéter des traitements grâce aux boucles \texttt{for}, \texttt{while} et \texttt{do...while}. Ces boucles deviennent véritablement puissantes lorsqu'elles manipulent des \emph{collections} de données. Imagine le professeur de Première C du lycée de Nkongsamba qui veut calculer la moyenne des notes d'informatique de ses 5 élèves. Jusqu'ici, il faudrait déclarer cinq variables distinctes : \texttt{note1}, \texttt{note2}, \texttt{note3}, \texttt{note4}, \texttt{note5}. Et s'il y avait 60 élèves ? Soixante variables, soixante \texttt{scanf}, soixante additions écrites à la main : c'est impraticable. Le langage C résout ce problème avec une structure fondamentale : le \cle{tableau}.

\courssub{Définition et intuition}

\begin{definition}[Tableau à une dimension]
Un \cle{tableau à une dimension} est une \cle{variable composée} qui regroupe, sous un \emph{seul nom}, plusieurs valeurs \emph{de même type}, stockées dans des cases mémoire \emph{contiguës}. Chaque case est repérée par un numéro appelé \cle{indice}, qui commence toujours à \textbf{0}.
\end{definition}

L'image mentale à retenir est celle d'une rangée de casiers numérotés dans la salle des professeurs : tous les casiers ont la même taille (même type de contenu), ils sont placés les uns à côté des autres (cases contiguës), et on accède à chacun par son numéro. La seule surprise pour un débutant : le premier casier porte le numéro 0, pas le numéro 1.

\begin{aretenir}[Les trois caractéristiques d'un tableau]
\begin{itemize}
  \item \textbf{Un seul nom} pour toute la collection (ici \texttt{notes}) ;
  \item \textbf{un seul type} pour toutes les cases (un tableau de \texttt{float} ne contient que des \texttt{float}) ;
  \item \textbf{des indices de 0 à taille $-1$} : un tableau de 5 cases a les indices 0, 1, 2, 3 et 4.
\end{itemize}
\end{aretenir}

\courssub{Déclaration d'un tableau}

\begin{propriete}[Syntaxe de déclaration]
La déclaration d'un tableau suit la syntaxe :
\begin{lstlisting}[language=C]
type nom[taille];
\end{lstlisting}
où \texttt{type} est le type commun des éléments (\texttt{int}, \texttt{float}, \texttt{char}\dots), \texttt{nom} est l'identificateur du tableau et \texttt{taille} est un entier \emph{constant} indiquant le nombre de cases. La déclaration réserve en mémoire \texttt{taille} cases contiguës.
\end{propriete}

Par exemple, pour stocker les notes de 5 élèves :

\begin{lstlisting}[language=C]
float notes[5];   /* reserve 5 cases de type float, indices 0 a 4 */
int ages[10];     /* reserve 10 cases de type int, indices 0 a 9 */
char nom[20];     /* reserve 20 cases de type char (chaine de caracteres) */
\end{lstlisting}

\begin{attention}[Taille fixée à la déclaration]
La taille d'un tableau est fixée une fois pour toutes à la déclaration : on ne peut pas l'agrandir ensuite. Choisis donc une taille suffisante dès le départ (par exemple \texttt{float notes[60];} pour une classe complète, quitte à n'utiliser qu'une partie des cases).
\end{attention}

\courssub{Accès aux éléments et initialisation}

Pour lire ou modifier une case, on écrit le nom du tableau suivi de l'indice entre crochets :

\begin{lstlisting}[language=C]
float notes[5];
notes[0] = 12.5;   /* ecrit 12.5 dans la premiere case */
notes[4] = 18.0;   /* ecrit 18.0 dans la derniere case */
printf("La premiere note est %.2f\n", notes[0]);
\end{lstlisting}

L'indice peut être n'importe quelle expression entière : une constante (\texttt{notes[2]}), une variable (\texttt{notes[i]}) ou même un calcul (\texttt{notes[i+1]}). C'est cette souplesse qui rend les boucles si efficaces avec les tableaux.

\begin{propriete}[Initialisation à la déclaration]
On peut donner les valeurs directement à la déclaration, entre accolades, séparées par des virgules :
\begin{lstlisting}[language=C]
int t[5] = {12, 8, 15, 7, 20};
\end{lstlisting}
Les valeurs sont placées dans l'ordre : \texttt{t[0]} vaut 12, \texttt{t[1]} vaut 8, \dots, \texttt{t[4]} vaut 20. Si l'on fournit moins de valeurs que la taille, les cases restantes sont mises à 0.
\end{propriete}

\begin{attention}[{Le premier élément est t[0], pas t[1]}]
L'erreur la plus fréquente chez les débutants est de croire que \texttt{t[1]} est la première case. Non : \texttt{t[0]} est la première, \texttt{t[1]} la deuxième, et pour un tableau de taille $n$, la \emph{dernière} case est \texttt{t[n-1]}. Accéder à \texttt{t[n]} (par exemple \texttt{notes[5]} pour un tableau de taille 5) est un \cle{dépassement d'indice} : le C ne signale aucune erreur à la compilation, mais le programme lit ou écrit en dehors de la zone réservée, ce qui provoque un \textbf{comportement imprévisible} (valeurs absurdes, plantage, résultats faux).
\end{attention}

\courssub{Remplissage d'un tableau avec une boucle for et scanf}

Saisir les cases une par une serait absurde : c'est exactement le travail d'une boucle \texttt{for}. La variable de boucle joue le rôle d'indice.

\begin{methode}[Remplir un tableau de taille n]
\begin{enumerate}
  \item Déclarer le tableau : \texttt{float notes[5];}
  \item Déclarer une variable entière d'indice : \texttt{int i;}
  \item Faire varier \texttt{i} de \texttt{0} à \texttt{n-1} avec \texttt{for(i = 0; i < n; i++)} ;
  \item Dans le corps de la boucle, saisir la case courante : \texttt{scanf("\%f", \&notes[i]);}
\end{enumerate}
\end{methode}

Remarque bien la présence du \cle{\&} devant \texttt{notes[i]} : chaque case du tableau est une variable ordinaire, et \texttt{scanf} a besoin de son \emph{adresse} (c'est le mode d'adressage vu dans la section 3).

\begin{lstlisting}[language=C]
int i;
float notes[5];

for (i = 0; i < 5; i++) {
    printf("Entrez la note de l'eleve %d : ", i + 1);
    scanf("%f", &notes[i]);   /* & obligatoire : case = variable float */
}
\end{lstlisting}

À l'exécution, l'utilisateur saisit successivement \texttt{notes[0]}, puis \texttt{notes[1]}, \dots, jusqu'à \texttt{notes[4]}. Le message affiche \texttt{i + 1} pour que l'utilisateur voie « élève 1 » à « élève 5 », même si les indices internes vont de 0 à 4.

\courssub{Parcours et traitements classiques}

Une fois le tableau rempli, on le \cle{parcourt} — c'est-à-dire qu'on visite chaque case une à une — pour y appliquer un traitement. Tous les parcours classiques reposent sur le même squelette de boucle.

\begin{methode}[Le squelette universel du parcours]
Pour traiter un tableau de taille \texttt{n}, utilise systématiquement :
\begin{lstlisting}[language=C]
for (i = 0; i < n; i++) {
    /* traitement de t[i] */
}
\end{lstlisting}
La condition est \texttt{i < n}, \textbf{jamais} \texttt{i <= n}. Avec \texttt{i <= n}, la boucle atteindrait \texttt{i == n}, donc la case \texttt{t[n]} qui n'existe pas : dépassement d'indice garanti.
\end{methode}

Voyons les quatre traitements que tu dois savoir écrire les yeux fermés.

\textbf{1. Affichage de tous les éléments.}

\begin{lstlisting}[language=C]
for (i = 0; i < 5; i++) {
    printf("notes[%d] = %.2f\n", i, notes[i]);
}
\end{lstlisting}

\textbf{2. Somme des éléments.} On utilise un \emph{accumulateur} initialisé à 0, auquel on ajoute chaque case :

\begin{lstlisting}[language=C]
float somme = 0;
for (i = 0; i < 5; i++) {
    somme = somme + notes[i];   /* accumulation */
}
\end{lstlisting}

\textbf{3. Moyenne.} C'est la somme divisée par le nombre d'éléments :

\begin{lstlisting}[language=C]
float moyenne = somme / 5;
\end{lstlisting}

\textbf{4. Recherche du maximum.} On suppose que le maximum est la première case, puis on le corrige chaque fois qu'on rencontre une case plus grande :

\begin{lstlisting}[language=C]
float max = notes[0];          /* hypothese de depart */
for (i = 1; i < 5; i++) {      /* on commence a l'indice 1 */
    if (notes[i] > max) {
        max = notes[i];        /* nouveau champion */
    }
}
printf("La meilleure note est %.2f\n", max);
\end{lstlisting}

\begin{attention}[Initialiser avant la boucle]
Un accumulateur (\texttt{somme}) ou un champion (\texttt{max}) doit être initialisé \emph{avant} la boucle, jamais dedans. Si tu écris \texttt{somme = 0;} dans le corps de la boucle, elle est remise à zéro à chaque tour et le résultat final ne contient que la dernière case.
\end{attention}

\begin{savaistu}[Le nom d'un tableau est une adresse]
En C, le nom d'un tableau représente l'\emph{adresse de sa première case}. C'est pourquoi, pour une chaîne de caractères, on écrit \texttt{scanf("\%s", nom);} \textbf{sans} le symbole \texttt{\&} : \texttt{nom} est déjà une adresse. En revanche, pour une case individuelle comme \texttt{notes[i]} (qui est une simple valeur \texttt{float}), le \texttt{\&} reste obligatoire. Cette subtilité explique aussi pourquoi les tableaux se transmettent si facilement aux fonctions : on passe en réalité l'adresse du début du tableau.
\end{savaistu}

\courssub{Exemple résolu : la moyenne de la classe}

\begin{exoresolu}[Moyenne des notes de 5 élèves]
\textbf{Énoncé.} Écris un programme C complet qui saisit les notes d'informatique de 5 élèves dans un tableau, puis calcule et affiche la somme, la moyenne de la classe et la meilleure note.
\tcblower
\textbf{Solution détaillée.} On applique la méthode : déclaration, remplissage par boucle, puis trois parcours (somme, affichage, maximum). On inclut \texttt{conio.h} pour \texttt{getch()} comme le prévoit le programme officiel.

\begin{lstlisting}[language=C]
#include <stdio.h>
#include <stdlib.h>
#include <conio.h>

int main() {
    float notes[5];      /* tableau des 5 notes */
    float somme = 0;     /* accumulateur */
    float moyenne, max;
    int i;

    /* 1. Remplissage du tableau */
    for (i = 0; i < 5; i++) {
        printf("Entrez la note de l'eleve %d : ", i + 1);
        scanf("%f", &notes[i]);
    }

    /* 2. Calcul de la somme */
    for (i = 0; i < 5; i++) {
        somme = somme + notes[i];
    }
    moyenne = somme / 5;

    /* 3. Recherche du maximum */
    max = notes[0];
    for (i = 1; i < 5; i++) {
        if (notes[i] > max) {
            max = notes[i];
        }
    }

    /* 4. Affichage des resultats */
    printf("\nSomme des notes    : %.2f\n", somme);
    printf("Moyenne de classe  : %.2f\n", moyenne);
    printf("Meilleure note     : %.2f\n", max);

    getch();
    return 0;
}
\end{lstlisting}

\textbf{Exemple d'exécution} avec les notes 12, 8, 15, 7 et 20 : la somme vaut $12 + 8 + 15 + 7 + 20 = 62$, la moyenne vaut $62 / 5 = 12{,}40$ et la meilleure note est 20. Le programme affiche donc :
\begin{lstlisting}
Somme des notes    : 62.00
Moyenne de classe  : 12.40
Meilleure note     : 20.00
\end{lstlisting}
\end{exoresolu}

\courssub{Erreurs fréquentes et bonnes habitudes}

\begin{attention}[Les quatre pièges classiques des tableaux]
\begin{itemize}
  \item \textbf{Décalage d'indice} : écrire \texttt{for(i = 1; i <= 5; i++)} au lieu de \texttt{for(i = 0; i < 5; i++)}. La boucle saute la case 0 et touche la case 5 qui n'existe pas.
  \item \textbf{Condition \texttt{i <= n}} : avec une taille \texttt{n}, le dernier indice valide est \texttt{n - 1}. La condition doit être \texttt{i < n}.
  \item \textbf{Oublier le \texttt{\&} dans \texttt{scanf}} : \texttt{scanf("\%f", notes[i]);} sans \texttt{\&} provoque un plantage, car \texttt{scanf} attend une adresse.
  \item \textbf{Tableau non initialisé} : lire une case avant de l'avoir remplie donne une valeur aléatoire (« résidu » de la mémoire). Remplis toujours le tableau avant de le parcourir.
\end{itemize}
\end{attention}

\end{enumerate}
\end{exercice}

\begin{corrige}[Exercice 2]
\begin{lstlisting}[language=C]
#include <stdio.h>

int main() {
    int t[6];
    int i, min;

    for (i = 0; i < 6; i++) {
        printf("Entrez l'entier %d : ", i + 1);
        scanf("%d", &t[i]);
    }

    min = t[0];                 /* hypothese de depart */
    for (i = 1; i < 6; i++) {
        if (t[i] < min) {
            min = t[i];
        }
    }
    printf("Le minimum est %d\n", min);
    return 0;
}
\end{lstlisting}
Le raisonnement est symétrique de celui du maximum : on part de la première case et l'on corrige le champion dès qu'une case plus petite apparaît.
\end{corrige}

\begin{aretenir}[L'essentiel sur les tableaux à une dimension]
\begin{itemize}
  \item Un tableau regroupe sous un seul nom plusieurs valeurs \emph{de même type} dans des cases contiguës.
  \item Déclaration : \texttt{type nom[taille];} — les indices vont de \texttt{0} à \texttt{taille - 1}.
  \item Initialisation : \texttt{int t[5] = \{12, 8, 15, 7, 20\};}
  \item Tout traitement (saisie, affichage, somme, moyenne, maximum) s'écrit avec \texttt{for(i = 0; i < n; i++)}.
  \item Le nom d'un tableau est l'adresse de sa première case ; une case individuelle reste une variable ordinaire qui exige \texttt{\&} dans \texttt{scanf}.
\end{itemize}
\end{aretenir}

Tu sais désormais stocker et traiter des collections de données : c'est un cap décisif. Dans la prochaine section, nous verrons comment \emph{compiler, tester et corriger} tes programmes dans l'IDE, car un programme qui manipule des tableaux doit être vérifié avec soin, notamment aux frontières des indices.

\coursec{Compilation, tests et correction d'un programme}

Dans la section précédente, nous avons appris à déclarer et à manipuler des \cle{tableaux} à une dimension, par exemple pour stocker les notes de toute une classe. Mais un programme, même bien écrit sur le papier, ne fonctionne presque jamais du premier coup : il faut le \cle{compiler}, lire les messages du compilateur, \cle{corriger} les erreurs, puis le \cle{tester} méthodiquement. C'est cette dernière étape du travail du programmeur — souvent la plus longue dans la pratique — que nous allons maintenant maîtriser. Imagine un professeur du lycée de Nkongsamba qui veut calculer automatiquement la moyenne de sa classe de Première D : un seul caractère mal placé dans son programme peut fausser les moyennes de 80 élèves !

\courssub{Rôle du compilateur}

\begin{definition}[Compilateur]
Le \cle{compilateur} est un programme qui traduit le \cle{code source} (fichier \texttt{.c} écrit par le programmeur) en \cle{langage machine} exécutable par le processeur (fichier \texttt{.exe} sous Windows). Avant de traduire, il effectue une \cle{vérification de la syntaxe} : chaque instruction est-elle bien formée ? chaque variable est-elle déclarée ? les parenthèses et accolades sont-elles équilibrées ?
\end{definition}

Le compilateur C (par exemple \texttt{gcc}, intégré aux IDE comme Code::Blocks ou Dev-C++) travaille en deux temps principaux :

\begin{enumerate}
  \item \textbf{Analyse (vérification syntaxique)} : il lit le fichier source ligne par ligne et vérifie la conformité aux règles du langage C. S'il détecte une erreur, il s'arrête et affiche un message indiquant le fichier, le numéro de ligne et la nature du problème.
  \item \textbf{Traduction (génération de code)} : si aucune erreur bloquante n'est détectée, il produit le programme exécutable en langage machine (souvent via une étape d'édition de liens pour inclure les bibliothèques).
\end{enumerate}

\begin{propriete}[Erreurs et avertissements]
Le compilateur distingue deux catégories de messages :
\begin{itemize}
  \item les \cle{erreurs} (\emph{error}) : elles \textbf{bloquent} la compilation ; aucun exécutable n'est produit tant qu'elles ne sont pas corrigées ;
  \item les \cle{avertissements} (\emph{warning}) : ils \textbf{ne bloquent pas} la compilation, mais signalent une construction suspecte (variable non initialisée, format douteux dans \texttt{printf}, conversion implicite...). Un avertissement est souvent le signe d'un futur bug : il faut toujours les lire et les traiter.
\end{itemize}
\end{propriete}

\begin{methode}[Comment lire les messages du compilateur]
\begin{enumerate}
  \item Compile le programme (touche \texttt{F9} dans Code::Blocks, \texttt{F11} dans Dev-C++).
  \item Lis \textbf{le premier message d'erreur} de la liste, pas le dernier : une seule erreur (par exemple un \texttt{;} oublié) peut en déclencher plusieurs autres en cascade sur les lignes suivantes.
  \item Double-clique sur le message : l'IDE place le curseur sur la ligne fautive (ou juste après).
  \item Corrige, puis \textbf{recompile immédiatement}. Souvent, plusieurs messages disparaissent d'un coup.
  \item Recommence jusqu'à obtenir « 0 erreur, 0 avertissement ».
\end{enumerate}
\end{methode}

\begin{attention}[Compiler ne suffit pas !]
Un programme qui compile sans erreur n'est \textbf{pas forcément juste}. Le compilateur vérifie la \emph{syntaxe}, pas la \emph{logique} (sémantique). Par exemple, la boucle \texttt{for(i = 1; i <= n; i++)} compile parfaitement, mais si le tableau est déclaré \texttt{float notes[30]} (indices 0 à 29), l'indice \texttt{n} peut dépasser la taille du tableau ou fausser le calcul. \textbf{Seuls les tests valident la logique du programme.}
\end{attention}

\courssub{Méthode de test : le jeu d'essai}

\begin{definition}[Jeu d'essai]
Un \cle{jeu d'essai} (ou jeu de test) est un ensemble de valeurs d'entrée choisies délibérément, accompagné pour chacune du \textbf{résultat attendu}, calculé à la main \emph{avant} l'exécution. On compare ensuite le résultat affiché par le programme au résultat attendu.
\end{definition}

\begin{methode}[Construire un bon jeu d'essai]
Pour tester un programme, prévois au moins \textbf{trois catégories} de valeurs :
\begin{enumerate}
  \item les \textbf{valeurs ordinaires} : celles du cas normal (par exemple des notes 12, 14, 9) ;
  \item les \textbf{valeurs limites} : celles qui se situent aux bornes du domaine (0 et 20 pour une note) ;
  \item les \textbf{valeurs aberrantes (invalides)} : celles que le programme devrait rejeter ou traiter avec prudence (-5, 25 pour une note).
\end{enumerate}
Pour chaque cas, note dans un tableau : les entrées, le résultat attendu, le résultat obtenu, et ta conclusion (test réussi ou échoué).
\end{methode}

\courssub{Débogage : suivre l'exécution pas à pas}

Lorsqu'un programme compile mais donne un résultat faux, il faut \emph{observer} ce qui se passe à l'intérieur. Deux outils simples suffisent à notre niveau :

\begin{itemize}
  \item le \texttt{printf} \cle{de débogage} : on insère temporairement des affichages des valeurs des variables à des points stratégiques (dans une boucle, après un calcul) ;
  \item \texttt{getch()} : en plaçant cette fonction (bibliothèque \texttt{conio.h}, spécifique aux environnements Windows comme Code::Blocks/Dev-C++) à des endroits choisis, on \textbf{met le programme en pause} ; il attend qu'on appuie sur une touche, ce qui laisse le temps de lire les affichages.
\end{itemize}

\begin{exemplebox}[Trace d'exécution avec printf et getch]
\begin{lstlisting}[language=C]
for (i = 0; i < n; i++) {
    somme = somme + notes[i];
    /* Affichage temporaire de débogage */
    printf("DEBUG : i = %d, note = %.2f, somme = %.2f\n",
           i, notes[i], somme);
    getch(); /* pause : appuyer sur une touche pour continuer */
}
\end{lstlisting}
Une fois l'erreur trouvée et corrigée, on \textbf{retire} ces instructions de débogage.
\end{exemplebox}

\courssub{La démarche complète de développement}

\begin{methode}[Du problème au programme fiable]
\begin{enumerate}
  \item \textbf{Analyser le problème} : identifier les entrées, les traitements, les sorties.
  \item \textbf{Écrire l'algorithme} en pseudo-code, sur papier.
  \item \textbf{Coder en C} dans l'IDE, en respectant la structure du programme.
  \item \textbf{Compiler} et corriger les erreurs de syntaxe, en commençant par la première.
  \item \textbf{Tester} avec le jeu d'essai préparé (valeurs ordinaires, limites, aberrantes).
  \item \textbf{Corriger} les erreurs de logique révélées par les tests, puis recommencer le cycle.
\end{enumerate}
\end{methode}

\courssub{Correction guidée d'un programme fautif}

\begin{exoresolu}[Quatre erreurs à traquer]
Voici un programme censé calculer la moyenne de $n$ notes saisies au clavier. Il contient \textbf{4 erreurs types}. Trouve-les et corrige-les.
\begin{lstlisting}[language=C]
#include <stdio.h>
int main() {
    int n, i;
    float note, somme, moyenne;
    printf("Nombre de notes : ");
    scanf("%d", n);
    somme = 0
    for (i = 0; i <= n; i++) {
        printf("Note %d : ", i + 1);
        scanf("%f", &note);
        somme = somme + note;
    }
    moyenne = somme / n;
    printf("Moyenne = %d\n", moyenne);
    return 0;
}
\end{lstlisting}
\tcblower
\textbf{Correction ligne par ligne :}
\begin{enumerate}
  \item \texttt{scanf("\%d", n);} $\rightarrow$ il manque l'\textbf{adresse} de la variable : \texttt{scanf("\%d", \&n);} (le caractère \texttt{\&} donne l'adresse mémoire de \texttt{n}).
  \item \texttt{somme = 0} $\rightarrow$ \textbf{point-virgule manquant} : \texttt{somme = 0;}
  \item \texttt{for (i = 0; i <= n; i++)} $\rightarrow$ la boucle s'exécute $n+1$ fois au lieu de $n$ : il faut \texttt{i < n}. C'est une erreur de \emph{logique} : le compilateur ne la signale pas, seuls les tests la révèlent !
  \item \texttt{printf("Moyenne = \%d\textbackslash n", moyenne);} $\rightarrow$ \texttt{moyenne} est un \texttt{float} : il faut le format \texttt{\%f} (idéalement \texttt{\%.2f} pour deux décimales).
\end{enumerate}
Programme corrigé :
\begin{lstlisting}[language=C]
#include <stdio.h>
int main() {
    int n, i;
    float note, somme, moyenne;
    printf("Nombre de notes : ");
    scanf("%d", &n);              /* erreur 1 : & ajouté */
    somme = 0;                    /* erreur 2 : ; ajouté */
    for (i = 0; i < n; i++) {     /* erreur 3 : < au lieu de <= */
        printf("Note %d : ", i + 1);
        scanf("%f", &note);
        somme = somme + note;
    }
    moyenne = somme / n;
    printf("Moyenne = %.2f\n", moyenne); /* erreur 4 : %f */
    return 0;
}
\end{lstlisting}
\end{exoresolu}

\courssub{Atelier guidé : le programme « moyenne d'une classe »}

\begin{experience}[TP — Écrire, compiler, tester et valider un programme complet]
\textbf{Objectif :} produire un programme fiable qui calcule la moyenne des notes d'une classe, en refusant les notes hors de l'intervalle $[0\,;20]$.

\textbf{Matériel :} un ordinateur avec un IDE C installé (Code::Blocks ou Dev-C++).

\textbf{Étape 1 — Analyse.} Entrées : le nombre $n$ d'élèves, puis $n$ notes. Traitement : somme puis division par $n$, avec contrôle de validité de chaque note. Sortie : la moyenne arrondie à deux décimales.

\textbf{Étape 2 — Algorithme (extrait).}
\begin{lstlisting}
Algorithme MoyenneClasse
Variables : n, i : entier ; notes : tableau reel ; somme, moyenne : reel
Debut
    Lire n
    somme <- 0
    Pour i de 0 a n-1 Faire
        Repeter Lire notes[i] Jusqu'a 0 <= notes[i] <= 20
        somme <- somme + notes[i]
    FinPour
    moyenne <- somme / n
    Ecrire moyenne
Fin
\end{lstlisting}

\textbf{Étape 3 — Codage en C.}
\begin{lstlisting}[language=C]
#include <stdio.h>
#include <conio.h>

int main() {
    int n, i;
    float notes[100];   /* tableau des notes (100 élèves max) */
    float somme, moyenne;

    printf("Nombre d'élèves (max 100) : ");
    scanf("%d", &n);

    /* Protection contre division par zéro et débordement */
    if (n <= 0 || n > 100) {
        printf("Effectif invalide.\n");
        getch();
        return 1;
    }

    somme = 0;
    for (i = 0; i < n; i++) {
        do {
            printf("Note de l'élève %d (0 à 20) : ", i + 1);
            scanf("%f", &notes[i]);
            if (notes[i] < 0 || notes[i] > 20) {
                printf("Note invalide, recommencez !\n");
            }
        } while (notes[i] < 0 || notes[i] > 20);
        somme = somme + notes[i];
    }

    moyenne = somme / n;
    printf("Moyenne de la classe : %.2f / 20\n", moyenne);

    getch();   /* pause pour lire le résultat */
    return 0;
}
\end{lstlisting}

\textbf{Étape 4 — Compilation.} Appuie sur \texttt{F9} (Code::Blocks). Objectif : « 0 error, 0 warning ». Si un message apparaît, lis le premier, corrige, recompile.

\textbf{Étape 5 — Tests avec le jeu d'essai.} Exécute le programme avec chaque ligne du tableau de jeu d'essai vu plus haut : $(12; 14; 9)$ doit donner $11{,}67$ ; $(0; 0)$ donne $0{,}00$ ; $(20; 20)$ donne $20{,}00$ ; la saisie de $-5$ ou $25$ doit être refusée avec le message « Note invalide ».

\textbf{Étape 6 — Interprétation.} Si tous les tests passent, le programme est \textbf{validé}. Sinon, place des \texttt{printf} de débogage dans la boucle pour observer \texttt{somme} et \texttt{i}, corrige, et recommence le cycle.
\end{experience}

\begin{attention}[Pièges classiques lors des tests]
\begin{itemize}
  \item Tester uniquement avec des valeurs « gentilles » : c'est avec les valeurs limites et aberrantes qu'on découvre les vrais bugs.
  \item Oublier de retester après une correction : une correction peut introduire un nouveau bug (on parle de \emph{régression}).
  \item Laisser les \texttt{printf} de débogage dans la version finale du programme.
  \item \textbf{Débordement de tableau :} dans le TP, si l'utilisateur entre $n > 100$, le programme écrit hors de \texttt{notes[100]}. Toujours vérifier les bornes après une saisie de taille.
  \item \textbf{Division par zéro :} si $n = 0$, l'instruction \texttt{moyenne = somme / n} plante le programme. Tester $n > 0$ avant de diviser.
  \item \texttt{conio.h} et \texttt{getch()} sont spécifiques à Windows (Code::Blocks, Dev-C++). Sur Linux/macOS, on utilise \texttt{getchar()} (dans \texttt{stdio.h}) pour faire une pause.
\end{itemize}
\end{attention}

\begin{aretenir}[L'essentiel de la section]
\begin{itemize}
  \item Le \cle{compilateur} vérifie la syntaxe puis traduit le code source en langage machine ; les \cle{erreurs} bloquent, les \cle{avertissements} avertissent.
  \item On corrige toujours la \textbf{première} erreur affichée, puis on recompile.
  \item Un programme qui compile n'est pas forcément juste : seul un \cle{jeu d'essai} (valeurs ordinaires, limites, aberrantes) valide la logique.
  \item \texttt{printf} de débogage et \texttt{getch()} permettent de suivre l'exécution pas à pas.
  \item La démarche complète : analyser $\rightarrow$ algorithmiser $\rightarrow$ coder $\rightarrow$ compiler $\rightarrow$ tester $\rightarrow$ corriger.
\end{itemize}
\end{aretenir}

\begin{savaistu}[D'où vient le mot « bug » ?]
On appelle \cle{bug} (littéralement « insecte » en anglais) une erreur de programme, et \cle{débogage} l'action de la corriger. Le terme est devenu célèbre en 1947, lorsque l'équipe de Grace Hopper, pionnière de la programmation, découvrit un véritable insecte (un papillon de nuit) coincé dans un relais de l'ordinateur Harvard Mark II, provoquant une panne. L'insecte fut collé dans le journal de bord avec la mention « premier cas réel de bug trouvé » ! Depuis, « chasser les bugs » est le quotidien de tous les programmeurs du monde — y compris ceux des entreprises technologiques camerounaises qui développent les applications mobiles de paiement que tu utilises peut-être déjà.
\end{savaistu}

\courssub{Situation}

Le Lycée Bilingue de Nkongsamba vient d'équiper sa salle informatique. Mme Etoundi, enseignante de Première C et responsable des moyennes, perd chaque trimestre plusieurs heures à calculer à la main les statistiques de sa classe : moyenne générale, note la plus élevée, note la plus faible et nombre d'élèves admis (note supérieure ou égale à 10/20). Elle fait appel à toi et à ton groupe pour automatiser cette tâche.

Elle te fournit le cahier des charges suivant :

\begin{enumerate}
\item Le programme demande d'abord le \cle{nombre d'élèves} de la classe. Ce nombre doit être compris entre 1 et 100 ; toute autre valeur est refusée et la question est reposée.
\item Le programme saisit ensuite, dans un \cle{tableau}, la note de chaque élève. Une note doit appartenir à l'intervalle $[0\,;20]$ ; toute note invalide (par exemple $-3$ ou $25$) est refusée et ressaisie.
\item Le programme calcule et affiche : la \cle{moyenne} de la classe (avec deux chiffres après la virgule), la \cle{note maximale}, la \cle{note minimale} et le \cle{nombre d'admis} (note $\geq 10$).
\end{enumerate}

\textbf{Jeu d'essai imposé} (5 élèves) : $12$ ; $0$ ; $20$ ; $7{,}5$ ; une note invalide $25$ (qui doit être refusée) remplacée par $14$. Résultats attendus : moyenne $= \dfrac{12+0+20+7{,}5+14}{5} = 10{,}70$ ; maximum $= 20$ ; minimum $= 0$ ; admis $= 3$.

\courssub{Consignes}

Par groupes de 3 ou 4, vous réaliserez les tâches suivantes, dans l'ordre :

\begin{enumerate}
\item \textbf{Conception sur papier.} Écrivez l'algorithme complet en pseudo-code (déclarations, saisies contrôlées, calculs, affichages). Identifiez les variables nécessaires et leurs types.
\item \textbf{Choix des boucles.} Justifiez le choix de \texttt{do...while} pour les saisies contrôlées et de \texttt{for} pour le parcours du tableau.
\item \textbf{Codage.} Saisissez le programme dans l'IDE en respectant la structure d'un programme C (bibliothèques, \texttt{main}, accolades, points-virgules).
\item \textbf{Compilation et correction.} Compilez. Notez chaque message d'erreur affiché par l'IDE, expliquez sa cause et corrigez-le.
\item \textbf{Validation.} Exécutez le programme avec le jeu d'essai imposé et vérifiez que les résultats affichés correspondent aux résultats attendus. Testez aussi le cas limite : un seul élève de note $10$.
\item \textbf{Bilan collectif.} Comparez avec les autres groupes : types choisis (\texttt{int} ou \texttt{float} pour les notes ?), initialisation du maximum et du minimum, clarté des messages affichés.
\end{enumerate}

\courssub{Ressources à mobiliser}

\begin{aretenir}[Boîte à outils de l'activité]
\begin{itemize}
\item \textbf{Structure minimale} : \texttt{\#include <stdio.h>}, fonction \texttt{int main(void)} ou \texttt{void main()}, corps entre accolades, chaque instruction terminée par \texttt{;}.
\item \textbf{Entrées/sorties} : \texttt{printf("format", variables)} avec \texttt{\%d} (entier), \texttt{\%f} (réel), \texttt{\%.2f} (réel à 2 décimales) ; \texttt{scanf("\%d", \&variable)} — ne jamais oublier le \texttt{\&} (adressage).

\courssub{Démarche et corrigé commenté}

\begin{exoresolu}[Le bulletin automatique du Lycée de Nkongsamba]
Écrire l'algorithme puis le programme C répondant au cahier des charges de Mme Etoundi, et le valider avec le jeu d'essai imposé.

\tcblower

\textbf{Étape 1 — Analyse et choix des variables.} Il faut : un entier \texttt{n} (nombre d'élèves, entre 1 et 100), un tableau \texttt{notes} de réels (les notes peuvent être décimales, comme $7{,}5$), un indice entier \texttt{i}, un réel \texttt{somme}, deux réels \texttt{max} et \texttt{min}, un entier \texttt{admis}. On dimensionne le tableau à 100 cases, borne maximale du cahier des charges.

\textbf{Étape 2 — Choix des boucles.} Pour les saisies contrôlées, on choisit \texttt{do...while} car la question doit être posée \emph{au moins une fois} avant de pouvoir tester la réponse : c'est exactement la sémantique de cette boucle. Pour le parcours du tableau, le nombre de tours est connu ($n$) : la boucle \texttt{for} est la plus naturelle.

\textbf{Étape 3 — Algorithme en pseudo-code.}
\begin{lstlisting}
Algorithme Bulletin
Variables : n, i, admis : Entier
            notes : Tableau[1..100] de Reel
            somme, max, min : Reel
Debut
    Repeter
        Ecrire("Nombre d'eleves (1 a 100) : ")
        Lire(n)
    Jusqu'a (n >= 1) ET (n <= 100)
    Pour i de 1 a n Faire
        Repeter
            Ecrire("Note de l'eleve ", i, " : ")
            Lire(notes[i])
        Jusqu'a (notes[i] >= 0) ET (notes[i] <= 20)
    FinPour
    somme <- 0 ; max <- notes[1] ; min <- notes[1] ; admis <- 0
    Pour i de 1 a n Faire
        somme <- somme + notes[i]
        Si notes[i] > max Alors max <- notes[i] FinSi
        Si notes[i] < min Alors min <- notes[i] FinSi
        Si notes[i] >= 10 Alors admis <- admis + 1 FinSi
    FinPour
    Ecrire("Moyenne : ", somme / n)
    Ecrire("Maximum : ", max, "  Minimum : ", min)
    Ecrire("Admis : ", admis)
Fin
\end{lstlisting}

\textbf{Étape 4 — Traduction en langage C.}
\begin{lstlisting}[language=C]
#include <stdio.h>   /* printf, scanf */
#include <stdlib.h>  /* fonctions utilitaires */
#include <conio.h>   /* getch */

int main(void)
{
    int n, i, admis;
    float notes[100];       /* tableau de 100 cases : indices 0 a 99 */
    float somme, max, min;

    /* 1) Saisie controlee du nombre d'eleves */
    do {
        printf("Nombre d'eleves de la classe (1 a 100) : ");
        scanf("%d", &n);    /* & obligatoire : adresse de n */
    } while (n < 1 || n > 100);

    /* 2) Saisie controlee des notes dans le tableau */
    for (i = 0; i < n; i++) {
        do {
            printf("Note de l'eleve %d (0 a 20) : ", i + 1);
            scanf("%f", &notes[i]);
        } while (notes[i] < 0 || notes[i] > 20);
    }

    /* 3) Parcours du tableau : somme, max, min, admis */
    somme = 0;
    max = notes[0];         /* initialisation a la premiere note */
    min = notes[0];
    admis = 0;
    for (i = 0; i < n; i++) {
        somme = somme + notes[i];
        if (notes[i] > max) max = notes[i];
        if (notes[i] < min) min = notes[i];
        if (notes[i] >= 10) admis = admis + 1;
    }

    /* 4) Affichage des resultats */
    printf("\n--- BULLETIN STATISTIQUE DE LA CLASSE ---\n");
    printf("Moyenne de la classe : %.2f / 20\n", somme / n);
    printf("Note maximale        : %.2f\n", max);
    printf("Note minimale        : %.2f\n", min);
    printf("Nombre d'admis       : %d sur %d\n", admis, n);

    getch();    /* maintient la fenetre ouverte */
    return 0;
}
\end{lstlisting}

\textbf{Étape 5 — Compilation et erreurs typiques rencontrées.} Lors de la première compilation, les groupes rencontrent en général : « \emph{missing terminating " character} » (guillemet oublié dans un \texttt{printf}), « \emph{expected ; before \}} » (point-virgule manquant), ou un programme qui « plante » parce que le \texttt{\&} a été omis dans \texttt{scanf}. Chaque message indique le numéro de ligne : on lit, on comprend, on corrige, on recompile.

\textbf{Étape 6 — Validation avec le jeu d'essai.} On saisit $n = 5$, puis les notes $12$, $0$, $20$, $7{,}5$, puis $25$ : le programme refuse $25$ (message reposé) et accepte $14$. Affichage obtenu : moyenne $= 10{,}70$, maximum $= 20{,}00$, minimum $= 0{,}00$, admis $= 3$ sur $5$. Les résultats attendus sont confirmés : le programme est validé. Le cas limite $n = 1$ avec la note $10$ donne moyenne $= 10{,}00$ et $1$ admis : correct.
\end{exoresolu}

\begin{attention}[Pièges à éviter dans ce programme]
\begin{itemize}
\item Oublier le \texttt{\&} dans \texttt{scanf} : comportement imprévisible, souvent un plantage.
\item Écrire \texttt{somme / n} avec \texttt{somme} déclarée en \texttt{int} : la division entière tronquerait la moyenne ($53{,}5 / 5$ donnerait $10$ au lieu de $10{,}70$). D'où le choix de \texttt{float} pour \texttt{somme}.
\item Initialiser \texttt{max} à $0$ : si toutes les notes étaient... cela fonctionne ici car les notes sont positives, mais l'initialisation propre et générale est \texttt{max = notes[0]}.
\item Utiliser \texttt{<= n} dans la boucle \texttt{for} : la case \texttt{notes[n]} n'existe pas, les indices s'arrêtent à $n-1$.
\end{itemize}
\end{attention}

\begin{methode}[Écrire et exécuter son premier programme C]
Pour passer de l'algorithme au programme C exécutable, suis toujours la même démarche :
\begin{enumerate}
\item \textbf{Installer un IDE} adapté (Code::Blocks avec le compilateur MinGW/GCC, ou Dev-C++). Vérifier à l'ouverture que le compilateur est détecté (menu \emph{Settings $\to$ Compiler} dans Code::Blocks).

\item \textbf{Écrire la structure minimale} : inclusion de la bibliothèque \texttt{stdio.h}, fonction \texttt{main} qui retourne un entier, accolades ouvrante et fermante.
\item \textbf{Compiler} (touche F9 ou \emph{Build}) : le compilateur traduit le code source en langage machine et signale les erreurs avec leur numéro de ligne.
\item \textbf{Exécuter} (F10 ou \emph{Run}) et vérifier l'affichage dans la console.
\end{enumerate}
Réflexe à acquérir : tout programme C contient \textbf{une et une seule} fonction \texttt{main} ; chaque instruction se termine par un point-virgule \texttt{;} ; le programme se termine par \texttt{return 0;} qui signale au système que tout s'est bien passé.
\end{methode}

\end{lstlisting}

\begin{methode}[Utiliser printf, scanf et getch avec les bonnes bibliothèques]
\begin{enumerate}
\item \textbf{Choisir la bibliothèque} selon le besoin (voir tableau ci-dessus).
\item \textbf{Inclure} la bibliothèque en tête de fichier : \texttt{\#include <nom.h>}.
\item \textbf{Afficher} avec \texttt{printf("format", variables)} en utilisant les \textbf{spécificateurs de format} :
\begin{itemize}
\item \texttt{\%d} ou \texttt{\%i} : entier signé (\texttt{int})
\item \texttt{\%f} : réel simple précision (\texttt{float})
\item \texttt{\%lf} : réel double précision (\texttt{double}) — \emph{obligatoire pour scanf avec double}
\item \texttt{\%c} : caractère (\texttt{char})
\item \texttt{\%s} : chaîne de caractères (tableau de \texttt{char} terminé par \texttt{\textbackslash 0})
\item \texttt{\%p} : adresse mémoire (pointeur, hexadécimal)
\end{itemize}
\item \textbf{Saisir} avec \texttt{scanf("format", \&variable)} : le caractère \texttt{\&} (esperluette) donne l'\textbf{adresse} de la variable, indispensable pour que \texttt{scanf} puisse la modifier. \textbf{Exception :} un tableau de caractères (chaîne) s'écrit \textbf{sans} \texttt{\&} car le nom du tableau représente déjà son adresse.
\item \textbf{Faire une pause} en fin de programme avec \texttt{getch();} (bibliothèque \texttt{conio.h}) pour laisser la console ouverte avant sa fermeture automatique.
\end{enumerate}
Réflexe : le nombre de \texttt{\%} dans le format doit être \textbf{exactement égal} au nombre de variables passées, dans le même ordre et avec le bon type.
\end{methode}

\begin{exemplebox}[Spécificateurs de format avancés pour printf]
\begin{lstlisting}[language=C]
printf("Entier : %d\n", 42);           // 42
printf("Reel : %.2f\n", 3.14159);      // 3.14 (2 decimales)
printf("Reel : %10.2f\n", 3.14);       // largeur 10, aligne a droite
printf("Caractere : %c\n", 'A');       // A
printf("Chaine : %s\n", "Cameroun");   // Cameroun
printf("Adresse : %p\n", &variable);   // 0x7ffd...
printf("Pourcent : %%\n");             // % (il faut doubler le %)
\end{lstlisting}
\end{exemplebox}

\begin{exoresolu}[Calcul de la moyenne d'un élève]
\textbf{Énoncé.} Pour préparer les bulletins du collège de Ngaoundéré, on veut un programme qui demande les notes de mathématiques et de physique d'un élève (réels), calcule leur moyenne et l'affiche avec deux décimales. Écrire ce programme complet.
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
\item \textbf{Analyse.} Il y a des saisies (\texttt{scanf}), un calcul et un affichage (\texttt{printf}) : la bibliothèque \texttt{stdio.h} suffit. On ajoute \texttt{conio.h} pour la pause finale.
\item \textbf{Choix des types.} Les notes sont des réels : type \texttt{float}. La moyenne est aussi un réel.
\item \textbf{Formule.} $\text{moyenne} = \dfrac{\text{note1} + \text{note2}}{2}$.
\item \textbf{Rédaction.} Pour \texttt{scanf}, on écrit \texttt{\&note1} car \texttt{note1} est une variable simple. Pour l'affichage à deux décimales, on utilise le format \texttt{\%.2f}.
\end{enumerate}
\begin{lstlisting}[language=C]
#include <stdio.h>
#include <conio.h>

int main(void)
{
    float note1, note2, moyenne;

    printf("Note de mathematiques : ");
    scanf("%f", &note1);          /* & = adresse de la variable */
    printf("Note de physique : ");
    scanf("%f", &note2);

    moyenne = (note1 + note2) / 2.0;  /* 2.0 force la division reelle */

    printf("Moyenne = %.2f\n", moyenne);
    getch();                      /* pause : la console reste ouverte */
    return 0;
}
\end{lstlisting}
\textbf{Vérification.} Avec note1 $= 12$ et note2 $= 15$ : moyenne $= \dfrac{12+15}{2} = 13{,}5$, affiché \texttt{13.50}. Le format \texttt{\%.2f} arrondit bien à deux décimales.
\textbf{Conclusion.} Le programme lit deux réels grâce à \texttt{scanf} avec l'opérateur d'adresse \texttt{\&}, calcule la moyenne et l'affiche formatée : il répond exactement au cahier des charges.
\end{exoresolu}

\courssub{Variables, types et mode d'adressage}

\begin{definition}[Variable en C]
Une \cle{variable} est une zone de mémoire nommée, de taille fixe selon son \cle{type}, dont le contenu peut varier pendant l'exécution. Elle est caractérisée par :
\begin{itemize}
\item un \textbf{nom} (identificateur) : lettres, chiffres, \texttt{\_}, commence par une lettre, pas d'accent, pas de mot réservé ;
\item un \textbf{type} : \texttt{int}, \texttt{float}, \texttt{double}, \texttt{char} (et dérivés \texttt{short}, \texttt{long}, \texttt{unsigned}) ;
\item une \textbf{valeur} stockée à une \textbf{adresse} mémoire (ex. \texttt{0x7ffd3a1c}).
\end{itemize}
\end{definition}

\begin{methode}[Déclarer des variables et comprendre l'adressage]
\begin{enumerate}
\item \textbf{Choisir le type} selon la nature de la donnée : \texttt{int} (entier, ex. un âge, un compteur), \texttt{float} ou \texttt{double} (réel, ex. un prix, une note), \texttt{char} (caractère, ex. une mention 'A').
\item \textbf{Déclarer avant d'utiliser} : toute variable doit être déclarée (type + nom) avant sa première utilisation, en début de bloc (norme C90 exigée au Probatoire). Ex. \texttt{int age = 17;}.
\item \textbf{Nommer correctement} : lettres, chiffres et \texttt{\_}, en commençant par une lettre ; pas d'accent, pas d'espace, pas de mot réservé (\texttt{int}, \texttt{for}, \texttt{while}...).
\item \textbf{Comprendre le mode d'adressage} : chaque variable occupe une case mémoire identifiée par une \textbf{adresse}. L'opérateur \texttt{\&} (esperluette) donne l'adresse d'une variable : c'est le \emph{passage par adresse} qui permet à une fonction comme \texttt{scanf} de modifier la variable. Sans \texttt{\&}, on transmet seulement la \emph{valeur} (passage par valeur) et la fonction ne peut pas modifier l'originale.
\item \textbf{Initialiser} systématiquement les variables (surtout les compteurs et accumulateurs : \texttt{somme = 0;}) pour éviter les valeurs aléatoires (\emph{garbage values}).
\end{enumerate}
\end{methode}

\begin{exoresolu}[Échange de deux variables et adresses]
\textbf{Énoncé.} On considère le programme suivant :
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    int a = 5, b = 9, temp;
    temp = a;
    a = b;
    b = temp;
    printf("a = %d et b = %d\n", a, b);
    printf("adresse de a : %p\n", (void*)&a);
    return 0;
}
\end{lstlisting}
1) Donner l'affichage produit par la première ligne \texttt{printf}. 2) Expliquer le rôle du caractère \texttt{\&} dans la deuxième ligne. 3) Que se passerait-il si l'on supprimait la variable \texttt{temp} en écrivant \texttt{a = b; b = a;} ?
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
\item \textbf{Trace d'exécution.} On suit les valeurs pas à pas :
\begin{center}
\begin{tabular}{|l|c|c|c|}
\hline
\rowcolor{popblueL} \textbf{Instruction} & \textbf{a} & \textbf{b} & \textbf{temp} \\
\hline
Initialisation & 5 & 9 & ? \\
\hline
\texttt{temp = a;} & 5 & 9 & 5 \\
\hline
\texttt{a = b;} & 9 & 9 & 5 \\
\hline
\texttt{b = temp;} & 9 & 5 & 5 \\
\hline
\end{tabular}
\end{center}
L'affichage est donc : \texttt{a = 9 et b = 5}. L'échange est réussi grâce à la variable intermédiaire.
\item \textbf{Rôle de \texttt{\&}.} Le caractère \texttt{\&} est l'opérateur \textbf{adresse de} : \texttt{\&a} désigne l'adresse mémoire de la variable \texttt{a} (mode d'adressage direct). Le format \texttt{\%p} permet d'afficher cette adresse (en hexadécimal, par exemple \texttt{0x7ffd...}). Le cast \texttt{(void*)} est recommandé pour \texttt{\%p}. C'est ce même opérateur qui permet à \texttt{scanf} de savoir \emph{où} ranger la valeur saisie.
\item \textbf{Sans variable temporaire.} Avec \texttt{a = b;} puis \texttt{b = a;} : après la première instruction, \texttt{a} vaut 9 et la valeur 5 est \textbf{définitivement perdue} ; la deuxième instruction recopie donc 9 dans \texttt{b}. Résultat : \texttt{a = 9 et b = 9}. L'échange échoue.
\end{enumerate}
\textbf{Conclusion.} L'affichage est \texttt{a = 9 et b = 5} ; \texttt{\&} donne l'adresse d'une variable ; l'échange de deux variables exige obligatoirement une troisième variable temporaire.
\end{exoresolu}

\courssub{Les structures répétitives : for, while et do...while}

\begin{propriete}[Syntaxe des boucles en C]
\begin{center}
\begin{tabularx}{\linewidth}{|l|X|}
\hline
\rowcolor{popblueL} \textbf{Boucle} & \textbf{Syntaxe} \\
\hline
\texttt{for} & \texttt{for (init ; cond ; incr) \{ instr ; \}} \\
\hline
\texttt{while} & \texttt{while (cond) \{ instr ; \}} \\
\hline
\texttt{do...while} & \texttt{do \{ instr ; \} while (cond) ;} \quad \textit{(point-virgule final obligatoire)} \\
\hline
\end{tabularx}
\end{center}
Dans les trois cas, \texttt{instr} peut être une instruction simple ou un bloc \texttt{\{ ... \}}. Les accolades sont \textbf{obligatoires} si plusieurs instructions forment le corps de la boucle.
\end{propriete}

\begin{methode}[Choisir et rédiger une boucle en C]
\begin{enumerate}
\item \textbf{Choisir la boucle} selon le contexte :
\begin{itemize}
\item nombre d'itérations \textbf{connu à l'avance} $\Rightarrow$ \texttt{for} ;
\item répétition \textbf{sous condition}, avec éventuellement zéro passage $\Rightarrow$ \texttt{while} ;
\item corps exécuté \textbf{au moins une fois} (menu, saisie contrôlée) $\Rightarrow$ \texttt{do...while}.
\end{itemize}
\item \textbf{Respecter les trois éléments} de toute boucle : initialisation du compteur, condition d'arrêt, modification du compteur dans le corps (sinon boucle infinie).
\item \textbf{Initialiser les accumulateurs} (\texttt{somme = 0;}, \texttt{produit = 1;}) \emph{avant} la boucle, jamais dedans.
\item \textbf{Vérifier} la boucle sur un petit cas (par exemple $n = 3$) avec un tableau de trace.
\end{enumerate}
\end{methode}

\begin{exoresolu}[Somme des n premiers entiers — trois versions]
\textbf{Énoncé.} Une coopérative de quartier à Douala veut calculer la somme $S = 1 + 2 + \cdots + n$ pour un entier $n$ saisi au clavier. 1) Écrire le programme avec une boucle \texttt{for}. 2) Réécrire la boucle en \texttt{while}. 3) Donner la valeur affichée pour $n = 4$ en détaillant la trace.
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
\item \textbf{Version \texttt{for}.} Le nombre d'itérations ($n$) est connu à l'avance : la boucle \texttt{for} est la plus naturelle. L'accumulateur \texttt{s} est initialisé à 0 avant la boucle.
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    int n, i, s = 0;
    printf("Entrer n : ");
    scanf("%d", &n);
    for (i = 1 ; i <= n ; i++) {
        s = s + i;
    }
    printf("S = %d\n", s);
    return 0;
}
\end{lstlisting}
\item \textbf{Version \texttt{while}.} On sort l'initialisation et l'incrément de l'en-tête :
\begin{lstlisting}[language=C]
    i = 1;                       /* Initialisation */
    while (i <= n) {             /* Condition */
        s = s + i;               /* Corps */
        i = i + 1;               /* Incrément : OBLIGATOIRE */
    }
\end{lstlisting}
\item \textbf{Trace pour $n = 4$.}
\begin{center}
\begin{tabular}{|c|c|c|c|}
\hline
\rowcolor{popblueL} \textbf{Tour} & \textbf{i} & \textbf{Condition $i \le 4$} & \textbf{s} \\
\hline
avant boucle & 1 & --- & 0 \\
\hline
1 & 1 & vraie & $0+1=1$ \\
\hline
2 & 2 & vraie & $1+2=3$ \\
\hline
3 & 3 & vraie & $3+3=6$ \\
\hline
4 & 4 & vraie & $6+4=10$ \\
\hline
sortie & 5 & fausse & 10 \\
\hline
\end{tabular}
\end{center}
Le programme affiche \texttt{S = 10}. Contrôle par la formule : $S = \dfrac{n(n+1)}{2} = \dfrac{4 \times 5}{2} = 10$. Les deux résultats concordent.
\end{enumerate}
\textbf{Conclusion.} Les boucles \texttt{for} et \texttt{while} donnent le même résultat ; pour $n = 4$, le programme affiche $S = 10$, conforme à la formule $\frac{n(n+1)}{2}$.
\end{exoresolu}

\begin{exoresolu}[Saisie contrôlée avec do...while]
\textbf{Énoncé.} Pour un logiciel de cantine scolaire, on veut obliger l'utilisateur à saisir une note comprise entre 0 et 20 : tant que la valeur est hors de cet intervalle, la question est reposée. Écrire le fragment de programme correspondant et justifier le choix de la boucle.
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
\item \textbf{Choix de la boucle.} La question doit être posée \textbf{au moins une fois} (on ne peut pas tester la note avant de l'avoir saisie) : c'est le cas typique du \texttt{do...while}, dont le corps s'exécute avant le test. Un \texttt{while} simple exigerait une initialisation artificielle de la note.
\item \textbf{Condition de poursuite.} On recommence \emph{tant que} la saisie est invalide, c'est-à-dire tant que $\text{note} < 0$ \textbf{ou} $\text{note} > 20$ (opérateur logique \texttt{||}).
\end{enumerate}
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    float note;
    do {
        printf("Entrer une note entre 0 et 20 : ");
        scanf("%f", &note);
    } while (note < 0 || note > 20);   /* ; obligatoire ici */

    printf("Note validee : %.2f\n", note);
    return 0;
}
\end{lstlisting}
\textbf{Vérification.} Si l'utilisateur tape $25$ puis $-3$ puis $14{,}5$ : les deux premières valeurs sont rejetées (condition vraie), la troisième est acceptée (condition fausse) et le programme affiche \texttt{Note validee : 14.50}.
\textbf{Conclusion.} Le \texttt{do...while} garantit au moins une saisie et ne laisse passer que les notes de l'intervalle $[0\,;\,20]$ : c'est la structure adaptée à toute saisie contrôlée.
\end{exoresolu}

\courssub{Déclarer et exploiter un tableau à une dimension}

\begin{definition}[Tableau à une dimension]
Un \cle{tableau} est une collection ordonnée de variables de \textbf{même type}, stockées en mémoire de manière \textbf{contiguë}, accessibles par un \cle{indice} (entier) commençant à \textbf{0}.
\begin{itemize}
\item Déclaration : \texttt{type nom[taille];} (ex. \texttt{float notes[30];}).
\item Accès : \texttt{nom[indice]} (ex. \texttt{notes[0]} première note, \texttt{notes[29]} dernière).
\item Taille fixe à la compilation (allocation statique).
\end{itemize}
\end{definition}

\begin{methode}[Manipuler un tableau en C]
\begin{enumerate}
\item \textbf{Déclarer} le tableau avec son type, son nom et sa taille entre crochets : \texttt{float notes[30];} (30 cases pour les notes d'une classe).
\item \textbf{Se souvenir que les indices commencent à 0} : un tableau de taille $n$ a des cases numérotées de \texttt{0} à \texttt{n-1}. La case \texttt{notes[n]} n'existe pas : y accéder est une erreur classique (\emph{buffer overflow}).
\item \textbf{Remplir} le tableau avec une boucle \texttt{for} de 0 à $n-1$ : \texttt{scanf("\%f", \&tab[i]);} (le \texttt{\&} reste nécessaire car \texttt{tab[i]} est une variable simple).
\item \textbf{Traiter} (somme, moyenne, maximum, minimum) avec une deuxième boucle, en initialisant les accumulateurs avant la boucle ; pour un maximum/minimum, initialiser avec \texttt{tab[0]}.
\item \textbf{Initialiser à la déclaration} si les valeurs sont connues : \texttt{int t[5] = \{4, 7, 1, 9, 3\};}
\end{enumerate}
\end{methode}

\begin{exoresolu}[Notes d'une classe : moyenne et maximum]
\textbf{Énoncé.} Le professeur d'informatique du lycée de Maroua saisit les notes de 5 élèves dans un tableau. Écrire un programme C qui : remplit le tableau, calcule et affiche la moyenne de la classe, puis affiche la note maximale. Donner le résultat pour les notes $\{12\,;\,8\,;\,15\,;\,10\,;\,14\}$.
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
\item \textbf{Analyse.} Tableau de 5 réels : \texttt{float notes[5];}, indices de 0 à 4. Trois phases : remplissage, somme puis moyenne, recherche du maximum.
\item \textbf{Initialisations.} \texttt{somme = 0} avant la boucle de calcul ; \texttt{max = notes[0]} avant la recherche (initialiser le maximum à 0 serait faux si toutes les notes étaient négatives, et dangereux en général).
\end{enumerate}
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    float notes[5], somme = 0, moyenne, max;
    int i;

    for (i = 0 ; i < 5 ; i++) {          /* remplissage */
        printf("Note de l'eleve %d : ", i + 1);
        scanf("%f", &notes[i]);
    }

    for (i = 0 ; i < 5 ; i++) {          /* somme */
        somme = somme + notes[i];
    }
    moyenne = somme / 5.0;

    max = notes[0];                      /* recherche du maximum */
    for (i = 1 ; i < 5 ; i++) {
        if (notes[i] > max) {
            max = notes[i];
        }
    }

    printf("Moyenne = %.2f\n", moyenne);
    printf("Note maximale = %.2f\n", max);
    return 0;
}
\end{lstlisting}
\textbf{Vérification numérique.} Avec $\{12\,;\,8\,;\,15\,;\,10\,;\,14\}$ :
\[ \text{somme} = 12 + 8 + 15 + 10 + 14 = 59, \qquad \text{moyenne} = \dfrac{59}{5} = 11{,}8. \]
Recherche du maximum : max $= 12$, puis $8 < 12$, puis $15 > 12$ donc max $= 15$, puis $10$ et $14$ ne changent rien. Le programme affiche donc \texttt{Moyenne = 11.80} et \texttt{Note maximale = 15.00}.
\textbf{Conclusion.} Le programme remplit le tableau avec des indices de 0 à 4, calcule une moyenne de $11{,}80$ et trouve un maximum de $15$ : les résultats manuels et automatiques concordent.
\end{exoresolu}

\begin{methode}[Tester et déboguer un programme C]

\begin{exoresolu}[Chasse aux erreurs]
\textbf{Énoncé.} Un élève a écrit le programme suivant, censé afficher si un entier est pair ou impair. Le compilateur signale plusieurs erreurs. Identifier chaque erreur, la corriger et donner l'affichage obtenu pour la saisie $n = 7$.
\begin{lstlisting}[language=C]
#include <stdio.h>

int main()
{
    int n
    printf("Entrer un entier : ");
    scanf("%d", n);
    if (n % 2 = 0)
        printf("pair\n");
    else
        printf("impair\n");
    return 0;
}
\end{lstlisting}
\tcblower
\textbf{Solution détaillée.}
\begin{enumerate}
\item \textbf{Erreur 1 — ligne 4.} Il manque le point-virgule après la déclaration : \texttt{int n;} (message typique : \emph{expected ';' before 'printf'}).
\item \textbf{Erreur 2 — ligne 6.} Il manque l'opérateur d'adresse dans \texttt{scanf} : il faut \texttt{scanf("\%d", \&n);}. Sans \texttt{\&}, \texttt{scanf} reçoit la valeur de \texttt{n} au lieu de son adresse : comportement imprévisible (souvent un plantage \emph{segmentation fault}).
\item \textbf{Erreur 3 — ligne 7.} \texttt{=} est l'affectation, pas la comparaison : il faut \texttt{if (n \% 2 == 0)}. Avec \texttt{=}, l'expression \texttt{n \% 2 = 0} est d'ailleurs invalide car on ne peut pas affecter à une expression (lvalue required).
\end{enumerate}
Programme corrigé :
\begin{lstlisting}[language=C]
#include <stdio.h>

int main(void)
{
    int n;
    printf("Entrer un entier : ");
    scanf("%d", &n);
    if (n % 2 == 0)
        printf("pair\n");
    else
        printf("impair\n");
    return 0;
}
\end{lstlisting}
\textbf{Test pour $n = 7$.} L'opérateur \texttt{\%} donne le reste de la division euclidienne : $7 = 2 \times 3 + 1$, donc $7 \,\%\, 2 = 1 \neq 0$. La condition est fausse, le programme affiche \texttt{impair}, ce qui est correct.
\textbf{Conclusion.} Trois erreurs corrigées (point-virgule, \texttt{\&} dans \texttt{scanf}, \texttt{==} dans le test) ; pour $n = 7$ le programme affiche \texttt{impair}, conforme au calcul $7 \bmod 2 = 1$.
\end{exoresolu}

\begin{attention}[Les 5 erreurs qui coûtent des points au Probatoire]
\begin{enumerate}
\item \textbf{Oublier le \texttt{\&} dans \texttt{scanf}.} Sans esperluette, la saisie ne modifie pas la variable et le programme plante ou donne des résultats absurdes. Seule exception : les chaînes de caractères (tableaux), qui s'écrivent sans \texttt{\&} (ex. \texttt{scanf("\%s", nom);}).
\item \textbf{Confondre \texttt{=} et \texttt{==}.} \texttt{if (a = 5)} \emph{affecte} 5 à \texttt{a} et la condition est toujours vraie (valeur 5 non nulle) : le test est faussé silencieusement. La comparaison s'écrit toujours \texttt{==}.
\item \textbf{Indices de tableau hors limites.} Un tableau de taille $n$ s'indice de \texttt{0} à \texttt{n-1}. Écrire \texttt{for (i = 1 ; i <= n ; i++)} sur un tableau de taille $n$ provoque un débordement (\emph{buffer overflow}) : la boucle correcte est \texttt{for (i = 0 ; i < n ; i++)}.
\item \textbf{Oublier d'initialiser un accumulateur ou le réinitialiser dans la boucle.} \texttt{somme = 0;} se place \emph{avant} la boucle ; placé dedans, la somme ne contient que la dernière valeur. De même, oublier l'incrément dans un \texttt{while} crée une boucle infinie.
\item \textbf{Négliger la syntaxe de fin d'instruction et des bibliothèques.} Point-virgule manquant (y compris le \texttt{;} après le \texttt{while} d'un \texttt{do...while}), bibliothèque non incluse (\texttt{math.h} pour \texttt{sqrt}, \texttt{conio.h} pour \texttt{getch}) ou division entière non maîtrisée (\texttt{5 / 2} vaut $2$, pas $2{,}5$ : écrire \texttt{5.0 / 2} ou utiliser des variables \texttt{float}).
\end{enumerate}
\end{attention}

\courssub{Corrigés — Je vérifie mes connaissances}

\begin{corrige}[Exercice 1 — QCM : à chaque question, une seule bonne réponse]
\begin{enumerate}
\item \textbf{Réponse b.} Un IDE (\emph{Integrated Development Environment}, environnement de développement intégré) est un logiciel qui regroupe dans une même interface un \cle{éditeur} de code, un \cle{compilateur} et un \cle{débogueur} (exemples : Code::Blocks, Dev-C++, CodeLite). Ce n'est ni un langage ni un système d'exploitation.
\item \textbf{Réponse c.} Les fonctions \texttt{printf} et \texttt{scanf} sont déclarées dans la bibliothèque \texttt{stdio.h} (\emph{standard input/output}). On écrit donc \texttt{\#include <stdio.h>}.
\item \textbf{Réponse a.} Le caractère \texttt{\&} est l'opérateur d'\cle{adressage} : \texttt{\&n} désigne l'\textbf{adresse mémoire} de la variable \texttt{n}. \texttt{scanf} a besoin de cette adresse pour savoir \emph{où} ranger la valeur saisie (passage par adresse).
\item \textbf{Réponse b.} En C, un tableau se déclare avec des \textbf{crochets} : \texttt{int notes[10];}. Les parenthèses servent aux fonctions, et le mot \texttt{tableau} n'existe pas en C.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 2 — Vrai ou faux ?]
\begin{enumerate}
\item \textbf{Vrai.} Dans une boucle \texttt{do...while}, le test de la condition est effectué \emph{après} l'exécution du corps : le corps est donc exécuté \textbf{au moins une fois}, même si la condition est fausse dès le départ. C'est ce qui la distingue de la boucle \texttt{while}.
\item \textbf{Faux.} En C, les indices d'un tableau commencent à \textbf{0}. Pour \texttt{int t[5];}, le premier élément est \texttt{t[0]} et le dernier est \texttt{t[4]}. Accéder à \texttt{t[5]} est une erreur (dépassement de tableau).
\item \textbf{Vrai.} La fonction \texttt{sqrt} (ainsi que \texttt{pow}, \texttt{fabs}, etc.) est déclarée dans la bibliothèque \texttt{math.h}. Sans la directive \texttt{\#include <math.h>}, le compilateur signale une erreur.
\item \textbf{Faux.} Le format \texttt{\%f} est réservé aux nombres réels (\texttt{float} ou \texttt{double}). Pour un entier de type \texttt{int}, on utilise \texttt{\%d}. Utiliser \texttt{\%f} avec un \texttt{int} produit un affichage erroné.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 3 — Définitions]
\begin{enumerate}
\item \textbf{Bibliothèque} : ensemble de fonctions prédéfinies, regroupées dans un fichier d'en-tête (\texttt{.h}), que l'on rend disponibles dans un programme grâce à la directive \texttt{\#include}. \emph{Exemple} : \texttt{\#include <math.h>} permet d'utiliser \texttt{sqrt(x)} et \texttt{pow(a, b)}.
\item \textbf{Paramètre} : information transmise à une fonction lors de son appel, placée entre parenthèses, qui précise ce sur quoi la fonction travaille. \emph{Exemple} : dans \texttt{printf("\%d", age);}, les paramètres sont la chaîne de format \texttt{"\%d"} et la variable \texttt{age} ; dans \texttt{scanf("\%f", \&x);}, les paramètres sont \texttt{"\%f"} et \texttt{\&x}.
\item \textbf{Mode d'adressage} : manière dont une valeur est transmise à une fonction. Dans le \textbf{passage par valeur}, la fonction reçoit une \emph{copie} de la valeur (ex. \texttt{printf("\%d", n);} : \texttt{printf} reçoit la valeur de \texttt{n}). Dans le \textbf{passage par adresse}, la fonction reçoit l'\emph{adresse mémoire} de la variable et peut donc la modifier (ex. \texttt{scanf("\%d", \&n);} : \texttt{scanf} écrit directement dans \texttt{n}).
\item \textbf{IDE} : environnement de développement intégré, logiciel regroupant un éditeur de code source, un compilateur et un débogueur, qui permet d'écrire, de compiler, d'exécuter et de tester un programme. \emph{Exemple} : Code::Blocks, dans lequel on écrit un fichier \texttt{main.c} puis on lance la compilation avec \texttt{F9}.
\end{enumerate}
\end{corrige}

\begin{corrige}[Exercice 4 — Trace d'exécution]
\begin{enumerate}

\begin{corrige}[Exercice 5 — Somme des $n$ premiers entiers]
\begin{lstlisting}[language=C]
#include <stdio.h>

int main() {
    int n, i, sommeFor = 0, sommeWhile = 0;

    /* Saisie controlee : on recommence tant que n <= 0 */
    do {
        printf("Saisir un entier strictement positif : ");
        scanf("%d", &n);
    } while (n <= 0);

    /* a) Calcul avec la boucle for */
    for (i = 1; i <= n; i++) {
        sommeFor = sommeFor + i;
    }
    printf("Avec for   : 1 + ... + %d = %d\n", n, sommeFor);

    /* b) Calcul avec la boucle while */
    i = 1;                       /* reinitialisation du compteur */
    while (i <= n) {
        sommeWhile = sommeWhile + i;
        i++;
    }
    printf("Avec while : 1 + ... + %d = %d\n", n, sommeWhile);

    return 0;
}
\end{lstlisting}
\emph{Remarques.} Le contrôle de saisie utilise naturellement un \texttt{do...while} car la saisie doit avoir lieu au moins une fois. Il ne faut pas oublier de remettre \texttt{i} à 1 avant la boucle \texttt{while}, sinon le second calcul part de \texttt{i = n + 1} et donne 0. Vérification : pour $n = 4$, on obtient $1+2+3+4 = 10$, ce qui correspond à la formule $\dfrac{n(n+1)}{2} = \dfrac{4 \times 5}{2} = 10$.
\end{corrige}

#include <stdio.h>

\begin{corrige}[Exercice 8 — Chasse aux erreurs]
Les \textbf{cinq erreurs} sont :
\begin{enumerate}

    prixTTC = prixHT * 1.1925;
    printf("Prix TTC = %.2f FCFA\n", prixTTC);   /* erreur 4 corrigee : %.2f pour l'affichage monetaire */
    return 0;
}                                         /* erreur 5 corrigee */
\end{lstlisting}

\end{corrige}

\begin{corrige}[Exercice 9 — Type Probatoire : moyenne des notes d'une classe]
\begin{enumerate}
\item Programme complété :
\begin{lstlisting}[language=C]
#include <stdio.h>            // (1) directive d'inclusion

int main() {
    float notes[10];          // (2) tableau de 10 reels
    float somme = 0, moyenne;
    int i;
    for (i = 0; i < 10; i++) {
        printf("Note de l'eleve %d : ", i + 1);
        scanf("%f", &notes[i]);   // (3) format %f  (4) symbole &
        somme = somme + notes[i];
    }
    moyenne = somme / 10;
    printf("Moyenne = %.2f\n", moyenne);   // (5) format %f (%.2f pour 2 decimales)
    return 0;
}
\end{lstlisting}
\item Le caractère \texttt{\&} donne à \texttt{scanf} l'\textbf{adresse mémoire} de la case \texttt{notes[i]} : c'est un passage par adresse, qui permet à \texttt{scanf} d'\emph{écrire} la valeur saisie directement dans le tableau. Si on l'oublie, \texttt{scanf} reçoit la \emph{valeur} contenue dans la case (un nombre quelconque) et l'interprète comme une adresse : le comportement est imprévisible, en général le \textbf{programme plante} (erreur d'exécution) ou écrit n'importe où en mémoire.
\item On ajoute une variable \texttt{max} initialisée à \texttt{notes[0]} après la saisie, puis un parcours comparatif :
\begin{lstlisting}[language=C]
#include <stdio.h>

int main() {
    float notes[10];
    float somme = 0, moyenne, max;
    int i;
    for (i = 0; i < 10; i++) {
        printf("Note de l'eleve %d : ", i + 1);
        scanf("%f", &notes[i]);
        somme = somme + notes[i];
    }
    moyenne = somme / 10;

    max = notes[0];                 /* initialisation au premier element */
    for (i = 1; i < 10; i++) {
        if (notes[i] > max) {
            max = notes[i];
        }
    }

    printf("Moyenne = %.2f\n", moyenne);
    printf("Meilleure note = %.2f\n", max);
    return 0;
}
\end{lstlisting}
\item Contrôle de saisie avec \texttt{do...while} (la saisie est faite au moins une fois, puis recommencée tant qu'elle est invalide) :
\begin{lstlisting}[language=C]
    for (i = 0; i < 10; i++) {
        do {
            printf("Note de l'eleve %d (0 a 20) : ", i + 1);
            scanf("%f", &notes[i]);
        } while (notes[i] < 0 || notes[i] > 20);
        somme = somme + notes[i];
    }
\end{lstlisting}
\end{enumerate}
\textbf{Barème indicatif (sur 10)} : directives et structure du programme 2 pts ; formats \texttt{\%f} et \texttt{\&} correctement justifiés 2 pts ; calcul de la moyenne 2 pts ; recherche du maximum (initialisation + parcours) 2 pts ; contrôle de saisie 2 pts.\\
\textbf{Points de vigilance} : citer le rôle du passage par adresse pour \texttt{scanf} ; initialiser \texttt{max} avec \texttt{notes[0]} et non avec 0 ; justifier le choix du \texttt{do...while} (au moins une saisie obligatoire).
\end{corrige}

\begin{corrige}[Exercice 10 — Type Probatoire : caisse d'une boutique]

    float remise = 0, net;

        remise = total * 0.05;

#include <stdio.h>

int main() {
    float prix[50];        /* tableau de 50 cases maximum */
    float total = 0;

    printf("Prix de l'article (0 pour terminer) : ");

\courssub{Méthodes express}

\begin{methode}[Écrire et tester un programme C complet]
\begin{enumerate}
    \item \textbf{Ouvrir l'IDE} (Code::Blocks) $\rightarrow$ \texttt{File > New > Empty File} $\rightarrow$ Sauver \texttt{.c}.
    \item \textbf{Écrire les includes} nécessaires (\texttt{stdio.h} minimum).
    \item \textbf{Écrire \texttt{int main() \{\ ... return 0;\}}}.
    \item \textbf{Déclarer les variables} en haut du bloc (ancien standard C89) ou au plus près (C99).
    \item \textbf{Coder l'algorithme} : \texttt{printf} pour guider, \texttt{scanf(\%... \&var)} pour lire, boucles pour répéter, tableaux pour stocker.
    \item \textbf{Compiler} : \texttt{F9} (Build) ou \texttt{Ctrl+F9} (Build \& Run). Lire les \texttt{errors} (rouge) et \texttt{warnings} (jaune) dans le log bas.
    \item \textbf{Corriger} : erreur de syntaxe (point-virgule, accolade), erreur de format (\%d vs \%f), \texttt{\&} oublié.
    \item \textbf{Tester} : valeurs normales, valeurs limites (0, négatif, grand nombre), entrée invalide (lettre au lieu de nombre).
\end{enumerate}
\end{methode}

\begin{methode}[Parcourir un tableau pour calcul (somme, max, recherche)]
\begin{enumerate}
    \item Initialiser l'accumulateur (\texttt{sum=0}, \texttt{max=T[0]}, \texttt{trouve=0}).
    \item Boucle \texttt{for(int i=0; i<N; i++)}.
    \item À l'intérieur : mise à jour (\texttt{sum += T[i];} ou \texttt{if(T[i]>max) max=T[i];}).
    \item Après la boucle : résultat dans la variable.
\end{enumerate}
\end{methode}

\begin{aretenir}[Checklist avant le Bac -- Leçon N10 : Programmation C]
\begin{itemize}
    \item $\square$ Je sais installer et lancer Code::Blocks (ou Dev-C++) et créer un fichier \texttt{.c}.
    \item $\square$ J'écris la structure de base \texttt{\#include <stdio.h> / int main() \{ ... return 0;\}} sans regarder.
    \item $\square$ Je distingue \texttt{printf} (affichage, pas de \texttt{\&}) et \texttt{scanf} (saisie, \textbf{\texttt{\&} obligatoire} sur variables simples).
    \item $\square$ Je choisis le bon spécificateur : \texttt{\%d} (int), \texttt{\%f} (float), \texttt{\%lf} (double), \texttt{\%c} (char), \texttt{\%s} (chaîne).
    \item $\square$ J'écris correctement les trois boucles : \texttt{for}, \texttt{while}, \texttt{do...while} (attention au \texttt{;} final du do-while).
    \item $\square$ Je déclare un tableau : \texttt{type Tab[Taille];} et j'accède aux éléments par \texttt{Tab[i]} avec \texttt{i} de \texttt{0} à \texttt{Taille-1}.
    \item $\square$ Je sais parcourir un tableau avec une boucle \texttt{for} pour faire une somme, une recherche, un tri simple ou un affichage.
    \item $\square$ J'inclus \texttt{math.h} pour \texttt{sqrt, pow} et \texttt{conio.h} pour \texttt{getch()} si besoin de pause console.
    \item $\square$ Je compile avec \texttt{F9}, je lis les erreurs (ligne, type : \textit{syntax error, format mismatch, undeclared variable}) et je corrige.
    \item $\square$ Je teste mon programme avec des cas limites : boucle qui ne tourne pas (\texttt{while(0)}), saisie négative, tableau vide, division par zéro évitée.
    \item $\square$ Je connais le rôle du préprocesseur (\texttt{\#include, \#define}), du compilateur (C $\rightarrow$ .o), de l'éditeur de liens (.o + lib $\rightarrow$ .exe).
    \item $\square$ Je gère les entrées invalides : vérifier le retour de \texttt{scanf} (nombre d'éléments lus) pour éviter les boucles infinies.
\end{itemize}
\end{aretenir}
